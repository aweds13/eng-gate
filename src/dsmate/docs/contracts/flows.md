# flows.md — 多操作动线（触发 → 传导 → 落点）

> 单操作走通 ≠ 整条链走通。每条动线必须写清**中间有几步、每步失败会怎样**。
> 判据：走完这条动线，用户能不能说「这事成了」。

---

## FL-1 一本书，从拍到能唤

```
拍第一张 → 建书（起名）→ 编页码 → 继续拍 → 打完 → 会话绑定这本书 → 打 #p12 验证
```

| 段 | 做什么 | 失败会怎样 | 落点 |
|---|---|---|---|
| ① 建书 | 首次拍摄时弹「给这本书起个名」 | 取消 → 照片进「未归类」，可后补 | 书出现在书库，带封面（第一页缩略图） |
| ② 编页码 | 每张/每批给页码；默认「接着上一页」 | 页码撞车 → 拒绝入库并高亮冲突的两张 | 页记录带 `bookId + pageNo + 图路径` |
| ③ 补拍 | 漏页可插队（第 12 页后补一张 12b） | 一页多图允许，顺序按录入时间 | 同页多图有序 |
| ④ 绑会话 | 会话创建/设置里绑定这本书 | 一个会话只能绑一本（N7） | 顶部常驻书名 |
| ⑤ 验证 | 打 `#p12` → 胶囊出现 → 发送 → 模型收到该页图像 | 页码不存在 → 当场提示并可拍 | **这一步成了，FL-1 才算成** |

**验收**：第二天重开 App，旧会话里打 `#p12` 仍能唤出同一张图。

## FL-2 一道题，分三支比完回主干

```
主干发题 → 答案1 → 从题后分叉 A（提示：用换元）→ 答案A
                    ↘ 分叉 B（提示：用分部积分）→ 答案B
                    ↘ 分叉 C（直接问）→ 答案C
        → 对比视图看三支 → 选一支的结论 → 回主干继续问下一步
```

| 段 | 传导 | 失败会怎样 | 落点 |
|---|---|---|---|
| 分叉 | 分支记录 `(branchFromMirId, parentBranchId)`；**不复制消息体** | 循环引用 → 拒绝 | 版本切换器「第 2 支 / 共 3 支」 |
| 隔离 | A 分支的追加只影响 A | — | B、C 无变化 |
| 对比 | 同一分叉点下 ≥2 支可并排 | 某一支还在流式中 → 该支显示「生成中」 | 三列并排，每列可单独核验 |
| 回主干 | 记「离开时的那条消息 id」，回来滚动到它 | 主干被删 → 提示并落到最近存在的祖先 | **用户能在主干接着问，且不丢三支** |

**验收**：分三支问完，回主干继续问，三支的历史都还在、能再点进去。

## FL-3 联网 → 引用 → 核验

```
开「联网」→ 发问 → 客户端搜（或模型给意图→确认）→ 结果进上下文 → 模型回答带引用 → 点引用看原文 → 点核验条验式子
```

| 段 | 传导 | 失败会怎样 | 落点 |
|---|---|---|---|
| 搜索 | `POST /v1/tools/search`，`count` 默认 10 | 端点失败 → 「没搜到」+原因，对话继续 | 结果条列表 |
| 取正文 | 需要时 `POST /v1/tools/fetch`（不是每篇都 fetch） | 单篇失败 → 那篇标「取不到正文」 | Markdown 进上下文 |
| 引用 | 回答里的 `[n]` 可点 | 引用与结果对不上 → 显示原始 URL 让用户自己判 | 点开见标题+域名+原文 |
| 计费 | 每次搜索计一次 | 余额不足 → 提前拦 | 「本次 N 次，约 $X」 |
| 核验 | 回答里的式子可核验 | 见 IX-4 | 并排对比 |

**验收**：问一个需要最新信息的问题，能拿到带引用的答案，且引用可点开。

## FL-4 换机恢复

```
旧机导出归档 → 传到新机 → 新机导入 → 校验 → 打 #p12 验证 → 接着聊
```

| 段 | 传导 | 失败会怎样 | 落点 |
|---|---|---|---|
| 导出 | 含 DB + 图片 + `manifest.json`（版本、计数） | 空间不足 → 说清需要多少 | 单个归档文件 |
| 导入 | 校验版本 → 合并 | 版本高 → 拒绝并说明；同 id 冲突 → 保留双方并提示（不静默覆盖） | 书、页、图、树、分支全在 |
| 验证 | 打 `#p12` | 图缺失 → 明确指出缺哪几张，可重导 | **能继续用，才算成** |

**边界**：默认不导出密钥（C10）⇒ 新机需重新填 key。

## FL-5 模型改名后的降级

```
用户发消息 → 400 model not found → 自动刷清单 → 保留会话 → 提示重选 → 用户点一个 → 重发成功
```

| 段 | 传导 | 失败会怎样 | 落点 |
|---|---|---|---|
| 报错 | 识别 400 且错误体指向模型名 | 无法识别 → 归为通用失败，给「重试/换模型」 | 不丢消息（C12） |
| 刷清单 | 重拉 `list-models` | 拉不到 → 允许手填 | 新清单 |
| 推荐 | 名字相似 / 同系列优先 | 无候选 → 全列出来 | 用户点一个 |
| 恢复 | 重发原消息 | 仍失败 → 保留错误详情 | 会话继续 |

**验收**：故意把模型名改错，走完这条链能在一个屏幕上恢复。

## FL-6 核验发现模型算错了

```
模型答“= 5√2” → 点核验 → SymPy 得 “√50 未化简/或得 7.071…” → 橙条：不一致 → 展开三方 → 用户重问或让模型解释
```

| 段 | 传导 | 落点 |
|---|---|---|
| 抽取 | 从回答里抽出 `5√2` 与 `√50` 两个表达式 | 待验列表 |
| 计算 | SymPy `simplify(5*sqrt(2) - sqrt(50)) == 0` | 一致（这两个其实相等） |
| 三态 | 绿/橙/灰 | 橙时展开：模型写的 / SymPy 算的 / 数值代入 |
| 追问 | 一键把三方对比塞进输入框（用户可改）再问 | 不自动发 |

**关键**：这条动线的价值是**发现「看起来对其实错」**，而不是证明模型对。
