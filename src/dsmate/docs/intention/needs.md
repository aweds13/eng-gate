# needs.md — 需求清单（intention 层）

> 一页看懂：**一个只跑在手机上、只连官方 API、专门为「一手教材 + 一手分支」定制的 DeepSeek 聊天客户端**。
> 它不替你做 Agent，它替你把「一本书 + 一道题的多条思路」管住。

## 用户原话（需求的第一手来源）

> 「我希望获得我去自由调用 DeepSeek App 或者是网页端使用的接口端口 API，作用是进行简单的 chat 不涉及把它接入 Agent 使用仅是像 App 上的 Chat 一样，只不过对它的使用进行一些个性化的调整。」

> 「我实际上接的是网页端……抓取我问答的那个内容下来……再进行一个排版……通过脚本实现比较自由的 fork 操作」
> —— **此条已于 2026-10-23 被用户本人撤回**，见 `decisions.md` / T1。

> 「我希望我的对话是能像 GPT 或者是其他的已有的那样，可以轻松的复刻，就是一种树形网状的，因为我有时候会揪着某知识点问很远，然后想要回答回到主线任务的学习上。」

---

## 一、核心定位

| 维度 | 需求 |
|---|---|
| 使用者 | 我本人（大学生），数学 / 教材学习为主 |
| 运行环境 | **安卓手机**，单机；电脑端不做（D1） |
| 联网 | 只在调 API 时联网，其余全离线（SR-NF1） |
| 形态 | 装一次；之后**热更新**，不重装（D2） |
| 定位 | 聊天客户端，**不是 Agent 平台**（D3） |

## 二、需求条目

### A. 用起来

- **N1 手机上就能用，装一次不用再折腾**
  - *为什么*：用户明确「必须要能在手机上用。不然的话，我也不会叫你定制了」，且不懂 adb、没有日常 USB 调试条件。
  - *衍生*：更新路径必须不依赖重装 APK（→ D13 的 WebView bundle 方案，`SR-NF5`）。

- **N2 就是个 Chat，别搞成 Agent**
  - *为什么*：「它并不是一个全部的 Chat，先暂定这些」。
  - *衍生*：不做插件系统、不做自动工具编排；工具只保留「搜索」与「核验」，**都由用户显式触发**。

- **N3 自己的钥匙开自己的门**
  - *为什么*：要 BYOK（D10），要能自由调 API（原始诉求）。
  - *衍生*：key / baseURL / 模型名三者可填；官方只是默认值，不是唯一。

- **N4 模型我自己挑**
  - *为什么*：「你只要把清单拉过来，然后我自由选择什么模型点一下就行。」（否决「快/强」档）
  - *衍生*：型号会改名、会退役 ⇒ **绝不写死型号名**；`GET /api/list-models` 每次刷新（`SR-F4`）。

### B. 追思路

- **N5 对话要能分叉，也要能回来**
  - *为什么*：「可以轻松的复刻，就是一种树形网状的，因为我有时候会揪着某知识点问很远，然后想要回答回到主线任务的学习上。」
  - *衍生*：消息级分叉；分支**只存自己新增的消息**，祖先链在渲染时拼接（Explore 的 `Ag()` 做法，见 `evidence.md`）；必须能一眼看到「我在第几支、主干在哪」。

- **N6 一道题分几支，比着看**
  - *为什么*：数学用途第 ④ 类「要能一道题分多支对比」。
  - *衍生*：分叉时可选择「沿用前缀 / 只带题目」；分支之间要有横向对比视图（`SR-F2`）。

### C. 啃一本书

- **N7 一个窗口管一本书**
  - *为什么*：「我大概率不会在同个窗口问不同的书……先开发一个对话窗口对应一本书。」
  - *衍生*：会话 → 教材 一对一绑定；顶部常驻书名；换书要显式动作。

- **N8 图片用页码叫出来，不用反复发**
  - *为什么*：「我不希望我一直反复地发……通过编对图片的编号，我直接通过编号就能唤出你自动调用那个编号的图片。」
  - *衍生*：编号形态 = **页码**；输入框打 `#p12` 即唤出第 12 页（`SR-F5`）；发送前本地解析成图像块，模型侧只看到图（D7）。

- **N9 教材图必须留在自己手里**
  - *为什么*：用户质疑「啥叫存在服务器上会怎么样？真的合理吗？」；且官方 App 自己就提示文件会过期（`invalid_file_ref_toast` = "The file has expired. Please re-upload."）。
  - *衍生*：教材图**本机存**，只在发消息那一刻随请求送出去；不长期托管（`SR-F8`）。

### D. 算得准

- **N10 数学要看得清**
  - *为什么*：数学用途第 ① 类「问数学题要公式/推导看得清」。
  - *衍生*：KaTeX 渲染 + 公式原文可复制（取 LaTeX 源，不从渲染后的文字猜）；代码高亮、表格、Mermaid（`SR-F3`）。

- **N11 算错了要能当场发现**
  - *为什么*：「我觉得 AI 算的有点不靠谱……有个代码会让我安心一点。」
  - *衍生*：核验条；SymPy 独立算；**三方不一致要如实摆**（D8、`SR-F6`）。

- **N12 要能联网查**
  - *为什么*：「联网搜索功能呢。这个还是要有的。」
  - *衍生*：官方 Search/Fetch API；结果要带引用、要能点开原文、要显示花了多少钱（D12、`SR-F7`）。

### E. 用着顺手

- **N13 界面要能按自己喜好调**
  - *为什么*：原始诉求「对它的使用进行一些个性化的调整，以实现更加定制化的 App 使用体验」。
  - *衍生*：主题、字号、代码/公式样式、提示词预设、快捷键位（`SR-F9`）。

- **N14 数据要能带走**
  - *为什么*：只存本机（D5）⇒ 换机必须能搬。
  - *衍生*：一键导出（含书、页、图、对话树、分支）与导入恢复（`SR-F8`）。

## 三、参考对象（学什么、不学什么）

| 来源 | 学 | 不学 |
|---|---|---|
| **DeepSeek 官方 App 2.5.3** | 双档模型文案思路、思考折叠、Edit to branch（分叉入口）、Circle an area to ask | 数美验证码 / hCaptcha / FlyVerify / 字节 APM 埋点 / 未成年模式 / 设备风控 |
| **Explore（`ai.explore.poker/chat`）** | 卡片=线程、三种边语义、分支卡动态拼接、BYOK 三槽、IndexedDB 附件范式、历史分级总结 | butler/sage 双模型编排、把图片塞进 Markdown、提示词两端各持一半 |
| **big-AGI** | 分支树数据结构的写法（MIT） | 整套 Next 前端（要服务端） |

## 四、非目标（明确不做）

- 不做 Agent / 插件 / MCP 接入。
- 不做网页端抓取、不做 PoW 求解、不绕过任何风控（`conventions.md` 红线）。
- 不做账号体系、不做云同步。
- 不做语音 / TTS / 分享成图 / PDF 自动切页（第一版，D15）。
- 不追求「比官方 App 功能全」，只追求「啃教材 + 追分支比官方 App 顺」。

## 五、成功的判据（一句话）

> **一道题分三支比完，能一键回到主干继续问；翻到书上第 12 页拍下来，第二天打 `#p12` 就能把那一页再拿出来问，而模型答的每个关键式子我都能一键验一遍。**
