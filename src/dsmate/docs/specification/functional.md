# functional.md — 功能规格（SR-F）

> 每条规格 = **必须做到什么**。做到没做到由 `ACCEPTANCE.md` 与门禁判，不靠口头。
> 上游需求编号见 `../intention/needs.md`；不许违反 `conventions.md`。

---

## SR-F1 对话内核

**覆盖需求**：N1 N2 N3 N4

**必须做到**

1. 以 OpenAI 兼容格式调 `POST {baseURL}/chat/completions`，`stream: true`，逐块渲染。
2. **思考开关**：`thinking: {type: "enabled"|"disabled"}`；开启时思考内容进 `reasoning_content`，UI 里折叠展示，默认收起，可展开；显示「思考了 X 秒」（从首块到 `reasoning_content` 结束计时）。
3. **停止**：本地断开流，已收到的内容保留并标记「已停止」。
4. **重生成**：对最后一条 assistant 消息重跑；重生成产出的旧版本**不删**，进该消息的版本列表（与 SR-F2 共用）。
5. **编辑用户消息**：编辑后可从该处重新分支（对应官方 App 的 `Edit to branch`）。
6. **失败不丢消息**：网络错 / 4xx / 5xx 时，消息留在原处、标错误、可重试（C12）。
7. `usage` 里的 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` / `reasoning_tokens` 要落库，设置页可看累计。

**边界**

- 上下文超限时不自动截断，**必须**让用户选（「丢最早的 N 条」/「换成摘要」/「取消」）。
- `deepseek-v4-pro` 不收图：选它时附着图片要当场拦（不是发出去等 400）。

## SR-F2 树形分支与对比

**覆盖需求**：N5 N6

**必须做到**

1. 任意一条消息可以「**从这里分叉**」。分叉产生一个**新分支**，记录 `(branchFromMessageId, parentBranchId)`。
2. **分支只存自己新增的消息**；展示时递归拉平祖先链、拼到分叉点前面。
   （Explore 的 `Ag()` 做法，见 `evidence.md` §3。）
3. 每条 assistant 消息的**版本切换器**显示「第 i / n 版」（对应官方 App 的 `branch_switcher_description` = "Message %d of %d"）。
4. **回主干**：任何位置一键回到主干当前位置，回来时滚动到离开的那条消息。
5. **树视图**：能看到所有分支的骨架（节点=消息，边=分支关系），点节点跳转。
6. **对比视图**：同一分叉点下 ≥2 个分支可并排看（一道题分三支比答案）。
7. 删除分支：默认「折叠」不删数据；硬删必须二次确认并说明「子分支会一起消失」。

**边界**

- 分支不复制消息体（省空间、也避免改了 A 分支 B 分支跟着变）。
- 循环引用在写入时就拒绝（`parentId` 不能指向自己或后代）。

## SR-F3 渲染

**覆盖需求**：N10

**必须做到**

1. **公式**：KaTeX 渲染；`$...$` / `$$...$$` / `\(...\)` / `\[...\]` 都识别；渲染失败降级为等宽原文并给「显示源码」。
2. **公式可复制**：复制得到 **LaTeX 源**（C6），不是渲染后的文字。
3. **代码**：Shiki 高亮（离线 bundle，不联网取主题）；带语言标签与一键复制。
4. **表格**：Markdown 表格渲染；宽表可横向滚动，不撑破气泡。
5. **Mermaid**：` ```mermaid ` 代码块渲染成图；渲染失败降级为源码。
6. **流式增量**：边收边渲染，已渲染部分不因新块整段重排（避免闪）。
7. **长文**：超过 N 行默认折叠，给「展开全文」。

**边界**

- 不做「自研 markdown 方言词法器」（官方 App 的 `_DSFMLexer` 是为极致性能，我们不需要；用 `markdown-it` 的插件体系）。
- 渲染层不许发起任何网络请求（离线 bundle、无 CDN）。

## SR-F4 模型清单与凭据（BYOK）

**覆盖需求**：N3 N4

**必须做到**

1. 启动时拉 `GET {baseURL}/api/list-models`，把清单**原样列出**（id + 可用状态），用户点选。
   **不做**「快/强」语义档位映射（D9 / T3）。
2. 模型选择持久化到当前会话配置；新会话沿用上次选择。
3. **失效降级**：调用返回 `model not found` / 400 时，自动刷新清单、**保留会话**、提示「模型清单变了，重选一个」，并列出最接近的候选（名字相似 / 同系列）。
4. **能力探测**：vision / thinking 是否支持，以**实测**为准（发极小的探测请求），结果缓存到本机；探测失败时按「不支持」处理并在 UI 说明。
5. **BYOK 三槽**：`chat` / `utility`（标题生成、摘要等）/ `vision`，各自可配 `{apiKey, baseURL, model}`；视觉槽未配置时回落到对话槽。
6. 余额：可选调用 `GET /api/get-user-balance` 显示（失败不影响主流程）。

**边界**

- 清单接口不可用（离线 / 老 baseURL 无此端点）时，允许用户手填模型名，并在 UI 标「手动指定」。
- 密钥存储见 `conventions.md` C10。

## SR-F5 教材库与页码唤图

**覆盖需求**：N7 N8 N9

**必须做到**

1. **一窗一书**：会话创建时可绑定一本教材；绑定后顶部常驻书名；换书是显式动作（要确认）。
2. **录入**：拍照 / 相册多选 → 归入当前书 → **手动或半自动给页码**（页码是唯一编号，C13）。
3. **编号识别**：输入框里 `#p12`（也接受 `#12`、`#第12页`）→ 发送前解析为「第 12 页的图像块」。
4. **解析规则**：文字原样保留在消息里（用户能看到自己写了什么），图作为 user 消息的图像块随请求送出（C5）。
5. **缺页处理**：页码不存在时**不发请求**，当场提示「这本书没有第 12 页，要不要现在拍？」
6. **一页多图**：一页可以有多张（分段拍），一起送。
7. **书内检索**：按页码/关键词找已录入的页（本地，离线）。

**边界**

- 第一版**不做** PDF 自动切页、不做 OCR 抽文本层（D14）。
- 教材图不长期托管（C7）。

## SR-F6 计算核验

**覆盖需求**：N11

**必须做到**

1. 含公式的 assistant 消息下方有**核验条**：「核验这条推导」。
2. 点击后：从回答里**抽取关键式子**（等号/不等号两侧、积分、求和、矩阵）→ 转 SymPy 表达式 → 计算 → 返回结果。
3. **并排展示**：左「模型写的」，右「SymPy 算的」；一致 / 不一致 / 无法解析，三态用不同样式。
4. **三方视角**（不一致时展开）：模型结论 / SymPy 结果 / 数值代入抽样验证。
5. **文案红线**：不许出现「已验证正确」（C8）。
6. **懒加载**：SymPy 运行时按需加载，未点击不占内存、不拖慢启动。
7. **超时与取消**：单次核验有超时（默认 20s）与取消；超时如实说「算不完」，不许假装通过。

**边界**

- 抽式子失败时，允许用户**手动框选**一段式子再核验。
- 只做「验算」与「化简」，不做「自动解题」。

## SR-F7 联网搜索

**覆盖需求**：N12

**必须做到**

1. 触发方式：① 输入框开关「联网」② 模型自己产出搜索意图时给用户确认后执行。**两种都要用户可见**。
2. 调 `POST {baseURL}/v1/tools/search`（`query` / `count` / `need_content`），拿 `results[]`。
3. 展示：`snippet` 给 UI；`summary` 喂模型；`rerank_score` < 1.5 的默认折叠。
4. 需要正文时调 `POST {baseURL}/v1/tools/fetch` 取 Markdown，**按需**（不是每篇都 fetch）。
5. **引用**：回答里引用的网页必须可点开，且能看到原文标题与域名。
6. **计次与花费**：显示本次会话用了多少次搜索、估算花费（C11）。
7. 搜索失败不阻断对话（降级为「没搜到」并说明原因）。
8. **工具源可插拔**（D16 定案 C+D）：搜索不是写死在 UI 里的一个函数，而是一个 `ToolSource` 接口的默认实现。第一版只实现 `OfficialSearchSource`；`McpSearchSource` 只留适配位与注册点，**不实现具体 MCP 连接**。判据：换源不改 UI 代码，只改注册表一行。

**边界**

- 「搜外网」与「搜我的资料」是**两个独立工具**，UI 上不能混成一个按钮（D12）。
- 搜索走的是官方 API（待确认 D12）；若用户选自建，本条整体替换。

## SR-F8 存储与备份

**覆盖需求**：N9 N14

**必须做到**

1. 本机数据库（SQLite）存：教材、页、图索引、会话、消息、分支、版本、usage。
2. 图片本体存 App 私有目录，DB 只存相对路径与哈希。
3. **导出**：一键导出为单个归档（含 DB + 图片 + 元数据版本号），可直接分享到文件/网盘。
4. **导入**：选归档 → 校验版本 → 合并（同 id 冲突时保留两边并提示，不静默覆盖）。
5. 首次启动有示例数据开关（避免空屏）。
6. 存储占用可见，可按书清理。

**边界**

- 不做云同步、不做账号（D5）。
- 默认导出不含 API key（C10）。

## SR-F9 设置与个性化

**覆盖需求**：N13 N1（热更新）

**必须做到**

1. 主题（浅/深/跟随系统）、字号（含预览）、代码字号、气泡宽度。
2. 提示词预设：可保存多条「系统提示」并一键套用（这是「个性化」的主要落点）。
3. 搜索默认参数（count、是否 need_content）、核验默认开关。
4. 关于页：版本号、前端 bundle 版本、模型清单最后刷新时间。
5. **热更新**：前端 bundle 可被替换（见 `implementation/architecture.md`），替换后提示「已更新到 vX，重启生效」。

**边界**

- 不做「分享成图」「TTS」「语音输入」（D15）。
