# 功能规格（SR-F）— 系统「必须做到什么」

> 每条 = 一件系统必须做到的可验证事实。**必须**句式。末尾标注满足的 `N` 与「可验证性」。**[一版]**/[二版]见 README 约定。

## SR-F1 · 任务管理（N6–N11、N45）

- **SR-F1.1 My Day 语义**（N6，一版）～ 系统**必须**支持「My Day = 今天要做的集合」；昨日未完成的任务**必须**自动移入**逾期栏**（除非用户手动移除）；My Day 内排序**必须**按 `截止时间 → 优先级 → 手动拖拽`。
  > 验证：次日打开，昨日未完成的 My Day 任务出现在逾期栏；拖拽后顺序保持。
- **SR-F1.2 筛选视图**（N7，一版）～ 系统**必须**提供视图：My Day / Important / Planned / Flagged / **逾期栏**；**必须**显示全局总任务数；**不得**提供 Assigned to me（个人不适用）。
- **SR-F1.3 自定义分组**（N8，一版）～ 系统**必须**支持按项目/领域自定义分组（如主线任务 / 数学视频自媒体 / 财务），显示**分组计数**；**任务可归多个分组**（打多领域标签）。
- **SR-F1.4 任务详情与状态机**（N9，一版）～ 任务**必须**支持：子步骤 / 备注 / 加入 My Day / 截止日 / 提醒 / 重复(Repeat) / 附件；状态**必须**可在`未开始 / 进行中 / 完成 / 逾期 / 取消 / 归档`间流转。
- **SR-F1.5 Repeat 规则**（N9，一版）～ 重复任务**必须**到点按上次完成时间自动生成下一次；其节奏**必须**可用时间热力图管理。
- **SR-F1.6 子任务**（N10，一版）～ **必须**支持大任务拆成小任务；**子任务全完成父任务才自动完成**（用户可手动提前勾）；以任务树/折叠呈现、不臃肿。
- **SR-F1.7 任务存档**（N11，一版）～ **必须**支持记录任务当前状态 + 过去做过的尝试（简版）；任务**必须**可关联「笔记名 / 链接」，提供存档视图；Obsidian 深联动后置（见 SR-F8）。
- **SR-F1.8 逾期处理**（N45，一版）～ 逾期任务**必须**留在 My Day 并标红；展开**必须**可「推到明天 / 改 ddl / 标逾期 / 取消」；**学校硬考核逾期 → 强提醒**，普通任务逾期 → 温和提示。
- **SR-F1.9 学校硬考核分类**（N45，一版）～ 系统**必须**区分三类：①**有指标类**（进产出账、可重规划）；②**逾期不候·作业/考核**（负向、逾期扣分 → 强债务、**不可重组清零**）；③**逾期不候·竞赛/活动**（正向、不扣分 → 弱债务/机会损失）。

## SR-F2 · 债务记账 B 系统（N3 + 记账规则；N4/N5 后置）

- **SR-F2.1 两轴记账**（N3，一版）～ **必须**记两轴：**投入轴**（以**专注时长**为主、习惯保持；完成任务按**完成情况**记、**不硬估耗时**）与**产出轴**（学校 KPI / 知识资产增加）；**必须**把「逾期任务=债务、专注投入=储蓄、完成悬赏=收益、复习逾期=轻债务」如实记入。
- **SR-F2.2 复习两笔**（N3，一版）～ 复习完成**必须**记**投入（维持）**；若**温故知新**（新理解/笔记/灵感）**必须**可额外记一笔**产出**（可选）。
- **SR-F2.3 债务口径**（N3，一版）～ 债务**必须**以「逾期清单 + 逾期天数 / 程度（轻度≤3天 / 中度≤7天 / 重度>7天）」呈现，**不得**折算成精确时间；**有时标任务**按逾期天数对应，**灵活并行任务**只标「逾期中/天数」、看是否在做/完成。
- **SR-F2.4 产出两类分开**（N3，一版）～ 学校 KPI（成绩/综测）与个人知识资产增加**必须**独立记账、分开展示；学校任务中写作业/备考=投入、成绩/综测达标=产出、逾期=债务。
- **SR-F2.5 结算与稳定产出**（N3，一版）～ **必须**以**周为主**结算；**不设「目标」实体**（目标=任务分组，伪需求）、**不硬对标**（如实记账 + 趋势自判断，**不用算法推荐**）；**必须**衡量「单位时间（周/月/季）产出稳定性」，提供**均衡度指标**（投入波动/空档），**温和呈现、不告警、不施压**。
- **SR-F2.6 记账规则**（记账规则1–5/8，一版）～ 默认**必须**：未绑定专注也计投入（轻量）；团队分配出去的任务不计个人投入（记协调/分配+AI回报）；债务生命周期（完成→当天清零 / 取消→按已过天数计完即止 / 推到→随天数累计）；跨端同 id 去重（来源标记，LWW 覆盖）。
- **SR-F2.7 可视化**（N3，一版）～ **必须**用**曲线 + 时间热力图**呈现债务/储蓄；**必须**可按任务分组（领域）查看投入/产出分布；顶部**必须**给轻量摘要（今日/本周债务项数 + 投入时长）。
- **SR-F2.8 重新规划 / 债务重组**（N4/N5，二版）～ 后置：**重新规划**=账本失真时按真实能力重校指标（双向）；**债务重组**=债务压垮人时的逃生通道（承认失败→吸取教训→重组），**必须**保留教训记录；学校硬考核逾期**不可**通过重组清零。

## SR-F3 · 计时与专注（N15–N17）

- **SR-F3.1 计时器**（N15，一版）～ **必须**支持**番茄钟**与**普通计时**；**必须**可**绑定任务**（绑定则时长自动计入该任务 + 每日反馈 + B 投入）。
- **SR-F3.2 专注中断**（N15，一版）～ 专注被打断，**必须**提供「暂停 / 放弃 / 记中断」三选。
- **SR-F3.3 白名单与勿扰**（N16，一版）～ **必须**支持专注白名单（软件/网站），**默认「阻止非白名单」**；**必须**支持专注时段勿扰；桌面端/移动端**分别配置**。
- **SR-F3.4 多设备同步专注**（N17，一版）～ 电脑或手机任一开启专注，**其他设备必须**同步进入专注计时/勿扰。

## SR-F4 · 习惯 / 反馈 / 自检（N12–N14）

- **SR-F4.1 每日反馈**（N12，一版）～ **必须**支持每日复盘录入，反映「计划 vs 执行」差距；**专注时长（绑定任务）自动计入**。
- **SR-F4.2 习惯热力图**（N13，一版）～ **必须**支持习惯打卡，以**时间热力图**呈现，且**纳入 B 系统**同一套可视化。
- **SR-F4.3 定期自检**（N14，一版）～ **必须**支持定期自检（任务臃肿 / 注意力基线下滑 / 方向重校）；自检**必须**消费 B 账本数据（投入/产出/债务趋势）。

## SR-F5 · 学业追踪（N18–N20）

- **SR-F5.1 GPA/学分**（N18，一版）～ **必须**支持 GPA 与学分追踪，**期末/成绩出来后手动录入**；与自学时间线对照。
- **SR-F5.2 课程档案**（N19，一版）～ **必须**支持按课程建档（学分 / 考核方式 / 任课），并按课追踪与提醒（来自学校办公网），防漏考/漏交。
- **SR-F5.3 学校任务 KPI 单**（N20，一版）～ **必须**支持学校考试/课程任务的**完成要求备注**，并**跳转到本地文件 / 网站**看清要求。
- **SR-F5.4 同构合流**（N18–N20，一版）～ 学校任务**必须**与普通任务**同构**（进 My Day/列表、可勾选/排序/拆步骤），多带「课程标签 + 硬约束元数据」；课程价值用**重要性/优先级**（不单独做价值标签）；录入**手动建档**为主。

## SR-F6 · 复习与间隔重复（N26–N29）

- **SR-F6.1 FSRS 调度**（N26，一版）～ **必须**按 FSRS 做间隔重复调度（追踪 / 提醒 / 复习曲线）；第一版**必须**用现成 Python FSRS 库；数据按 FSRS 兼容字段设计（留扩展）。
- **SR-F6.2 复习任务创建**（N26，一版）～ **必须**可由「学习任务升级为复习任务」或手动建（作为特殊子栏目）。
- **SR-F6.3 到期排序**（N26，一版）～ 复习到期多时，**必须**按算法（重要度 + 最久未复习）排序，**优先**计入 My Day。
- **SR-F6.4 外部 app 场景**（N27，一版）～ 对「不背单词」等外部 app，工具**只做调度中枢**（提醒 + 记录），**用户手动点「完成」**；复习任务**必须**带「执行源」标签（外部 app / 内置）。
- **SR-F6.5 复习形式预留**（N29，一版）～ 复习任务**必须**预留「复习形式」字段（挖空 / 真题 / 问答卡）与扩展口子；具体工具方案后置。
- **SR-F6.6 反馈三态接口**（N29，一版）～ **必须**用 FSRS 反馈三态（记得 / 模糊 / 忘了）作为本软件与「复习工具」的联动接口。

## SR-F7 · 团队 / AI 协作（N46、N23）

- **SR-F7.1 管理者/执行者模式**（N46，一版）～ **必须**支持「管理者（建/分配任务）」与「执行者（接收/执行）」两视角，可切换；任务**必须**可标注「分配给我 / 我分配」；**跨端集成**（桌面 + 手机）。
- **SR-F7.2 团队原则**（N46，一版）～ **不强制执行者装本软件**；只需「我知道谁负责什么、进展到哪」；执行者状态**第一版手动为主 + AI 接口**；数据属「现实与 AI 记忆对齐」部分。
- **SR-F7.3 AI 接口**（N23，一版）～ **必须**为 AI 智能体（Hermes）提供读写任务的本地 API；**第一版只读 + 新增**（不改不删，避免和手动冲突）；写/改/删留后续；结合管理者模式。
- **SR-F7.4 团队任务记账归属**（N46，一版）～ 分配出去的任务**必须**不计个人投入；只记「协调 / 分配完成」+ AI 回报单独记。

## SR-F8 · 备忘录与知识资产（N24、N28、N11）

- **SR-F8.1 备忘录**（N24，一版）～ **必须**支持碎片化任务/想法**本地**随手记（含移动端快速记录）；**可顺手建成任务 + 加到期**。
- **SR-F8.2 知识资产引用句柄**（N24/N28，一版）～ 本软件**只存引用句柄**（Vault 相对路径 / `KB-...` 资源 ID）；**读写 Obsidian、PDF 库交给「知识资产项目」**（obsidian-vault-notes + manage-personal-knowledge），**本软件不直接碰 Vault 文件**；预留「知识资产句柄」契约（spec 层已定）。
- **SR-F8.3 复习联动知识资产**（N28，一版）～ 复习卡片/笔记**必须**可用引用句柄关联（Vault 路径 / KB ID），复习完标记并推进下一间隔；深联动后置到知识资产项目。
- **SR-F8.4 产出评价器接口**（记账规则9，一版）～ **必须**预留「**产出评价器**」接口：第一版**手动粗颗粒**入口；合同待知识管理项目对齐再定。

## SR-F9 · 存储 / 同步 / 数据（N25、N41）

- **SR-F9.1 本地优先存储**（N25，一版）～ **必须**本地优先（可 SQLite / 文件），数据不出本地；**必须**可跨端同步；**必须**可被 AI 读写；**必须**可扩展（习惯/专注/学业/备忘录多域）。
- **SR-F9.2 同步一致性**（N25，一版）～ 跨端同步**必须**用「修改时间戳 + version」做 **LWW（较新者胜）**，**不静默覆盖**（冲突给提示/日志）；**必须**同 id 去重（来源标记）。
- **SR-F9.3 数据迁移与备份**（N41，一版）～ **必须** schema 版本化 + 升级迁移；重要数据（任务/学业/复习历史）**必须**可备份、可回滚。

## SR-F10 · 学校通知监控接口（N21–N22，后置）

- **SR-F10.1 外部服务接口**（N21–N22，后置）～ 学校通知监测（网站/公众号/群聊/考试网站 → 抓取/集成/通知）**必须**以**独立脚本/软件**实现，主工具只提供**合作接口**（不让主软件膨胀）；接口契约后置定。
