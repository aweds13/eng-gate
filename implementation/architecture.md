# 总体架构分层与端到端数据流

## 一、分层架构（自外向内的抽象）
```
┌─────────────────────────────────────────────┐
│ ① 交互/壳   pywebview 桌面窗口 + Web 前端(HTML/CSS/JS) │
└───────────────┬─────────────────────────────┘
                │ HTTP (fetch /api/...)
┌───────────────▼─────────────────────────────┐
│ ② API 层     FastAPI (REST)                  │
│              - 给前端 / 给 AI(读+新增) / 给外部集成   │
└───────────────┬─────────────────────────────┘
                │ 调用（纯 Python 上下文）
┌───────────────▼─────────────────────────────┐
│ ③ 核心领域层  core/ (业务逻辑，模块化、错误隔离)        │
│   tasks·ledger·focus·feedback·academic·review ·team·memo │
└───────────────┬─────────────────────────────┘
                │ 读写（SQLAlchemy/raw SQL）
┌───────────────▼─────────────────────────────┐
│ ④ 存储层     storage/ (SQLite + schema迁移 + 同步LWW)  │
└───────────────┬─────────────────────────────┘
                │
┌───────────────▼─────────────────────────────┐
│ ⑤ 外部集成    getaways/ (知识资产句柄 / 学校通知接口)     │
└─────────────────────────────────────────────┘
```

## 二、端到端数据流（一套任务，从建到记账）
```
用户(桌面/手机) → 新建任务(带截止) → API → core/tasks 校验状态
   → storage 落库(SQLite, 带时间戳+version)
   → 到期/逾期 → core/ledger 记债务(逾期天数/程度)
   → 专注绑定任务 → core/focus 记投入(时长) → core/ledger 投入轴
   → 每日复盘 → core/feedback 记计划-执行差距
   → 顶部轻量摘要(债务项数+投入时长) 与 曲线/热力图 呈现
```

## 三、两条关键边界（设计取舍）
1. **业务与存储分离**：`core/` 只做领域逻辑，不碰 SQL；`storage/` 负责持久化与 schema 迁移——改存储不牵动业务（可维护，SR-NF6）。
2. **本软件与知识资产解耦**：知识/笔记**只存引用句柄**（Vault 路径 / KB-ID），读写交给「知识资产项目」，本软件不碰 Vault 文件——避免膨胀与耦合（SR-F8.2）。

## 四、模块目录对照
| 分层 | 目录 |
|---|---|
| 交互/壳 | `src/app/`（pywebview）+ `src/web/`（前端静态） |
| API | `src/api/` |
| 核心领域 | `src/core/`（tasks/ledger/focus/feedback/academic/review/team/memo） |
| 存储 | `src/storage/` |
| 外部集成 | `src/getaways/` |
| 配置 | `src/config.py` |
