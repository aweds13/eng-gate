# T-G41 · 习惯页的「今天」用了 UTC 日期（差一天，点一下还会把打卡取消掉）

> 2026-09-24。**发现路径**：改 T-G40 的 fixture 之后重采黄金，`habit` 那三份里
> 「已打卡（点此取消）」变成了「打卡」。这不是 fixture 的事 —— 查下去是**真缺陷**，
> 而且它只在**本地凌晨 0–8 点**显形（本机 UTC+8），所以它躲过了此前所有轮次的验证。

---

## 一、缺陷

`renderHabit`（`src/web/index.html`）：

```js
const today=new Date().toISOString().slice(0,10);   // ← UTC 日期，不是本地日期
const doneToday=(h.logs||[]).includes(today);
... ${doneToday?'已打卡（点此取消）':'打卡'}
```

`toISOString()` 给的是 **UTC**。本机在 UTC+8：

| 本地时刻 | `toISOString().slice(0,10)` | 后果 |
|---|---|---|
| 09-24 01:00 | `2026-09-23` | 今天已打卡 → 界面显示「打卡」（**说反了**） |
| 09-24 09:00 | `2026-09-24` | 正确 |

而后端按**本地日期**记打卡（`GET /api/habits` 当场返回 `logs: ["2026-09-24"]`）。

**不只是显示反了**：`toggleHabit()` 走的是 `POST /api/habits/{id}/toggle`（服务端按本地今天**翻转**），
`next` 只用来决定提示语。所以凌晨点那颗「打卡」= 把今天**已经打上的卡取消掉**，
而提示还写着「已打卡」。这是会**改数据**的那种错。

同一处写法还在 `heatmap()` 里（`const iso=d.toISOString().slice(0,10)`）：格子是按**本地**构造的
（`new Date(monday)` + `setDate`），再取 UTC 日期 → **整张热力图差一天**；更糟的是
"今天"那一格因为 `if(d>today)continue` 被跳过，于是**今天这次打卡根本画不出来**。

## 二、为什么以前没被发现

- 这个项目自己**早就写下了这条规矩**（`index.html` 第 160 行）：
  > 本机今天（日期默认值 / 「推到明天」用）；按本地时区拼，避免 toISOString 的 UTC 偏移

  也就是说 `todayISO()` 就在隔壁 —— 这两处是**漏用**，不是不知道。
- 渲染黄金看不见：热力图图元当时**整类没进黄金**（T-G40 发现 D）；
  按钮那颗字的对错又只在凌晨才翻。
- pytest / DOM 探针用的是假时钟或固定数据，碰不到"本地 vs UTC"这一层。

## 三、修法

```js
const today=todayISO();        // renderHabit：本机日期（本地时区）
const iso=todayISO(d);         // heatmap：格子日期同样按本地拼
```

旁边留了注释写清"为什么不能写 `toISOString()`"（免得下一个人再漏）。
**其余两处 `toISOString().slice(0,10)`（第 1964/1973 行）是对的** —— 它们先减了
`getTimezoneOffset()`，属于"已经做过时区换算"的那种，不动。

## 四、护栏（两层，写法不同、判的东西不同）

1. **全文件级**：`index.html` 里**不许出现** `new Date().toISOString()` 这个形状
   （裸写法就是 UTC 日期；要 UTC 必须先显式做时区换算）。这条能挡住"下一次又这么写"。
2. **函数级**：`renderHabit` / `heatmap` 里不许出现 `toISOString`，且必须用 `todayISO()`
   —— 挡住"改成另一种 UTC 写法绕过去"。

两条都在 `tests/test_web_frontend.py`，并各配一句为什么。

## 五、验证

| 项 | 结果 |
|---|---|
| 黄金（本地 01:0x = UTC 前一天） | habit 三份重新采到「已打卡（点此取消）」✅；修之前采到的是「打卡」 |
| 热力图 | 修后格子按本地日期排，今天的格子**画出来了**（黄金里能看到 `rect … YYYY-MM-DD 已打卡`） |
| 后端读数 | `/api/habits` → `logs:["2026-09-24"]`（本地今天），与界面现在一致 ✅ |
| 两个新护栏 | `tests/test_web_frontend.py` 两条，且**负样例**证明咬得住（见该文件） |

## 六、诚实边界

1. **黄金现在与"跑的时候是几点"无关了**，但这条修复本身是"凌晨才显形"的缺陷 ——
   也就是说：**我们的验证对"时间相关的分支"覆盖很薄**。T-G40 §六 第 1 条记的是同一件事的另一面。
2. 只修了发现的两处（`renderHabit` / `heatmap`）；**没有**做一次全仓的"日期取法"清点
   （`docs/`、`tools/`、其他 `.js`）。全文件级护栏只扫 `index.html`。
3. 热力图"今天那格"依赖 `logs` 里正好有本地今天 —— 现在的断言只保证"有就画得对"，
   不保证"任何数据下都不漏格"。
