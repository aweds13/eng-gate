# 接手旧项目的能力 · 方案（卡 A299 · T-AG413 的输入）

> 性质：方案咨询文档，给下一张实现卡当输入。不改任何技能、不写代码。
> 口径：每条结论带可观察证据（文件路径 / 命令输出形态）；显式区分「通用」与「本仓特有」。

## 一、分类：可接手的项目分四类

| 类 | 名字 | 判据（可观察的文件与命令） |
|---|---|---|
| A | 已有同款骨架 | 仓根存在骨架配置文件 pipeline.toml（框架骨架，落点表见 `skills/pipe-init/SKILL.md`）或 `harness.toml`（harness 复制体胶水）；跑命令 `python -X utf8 framework/cli/main.py --help` 能列出命令 ⇒ 直接按本仓流程接 |
| B | 有自己的 CI 与测试 | 存在 .github/workflows 目录、Makefile、pytest.ini 或 pyproject.toml、package.json（scripts 段有 test）之一；`git log --oneline -5` 有近三个月提交 ⇒ 有门可借，映射后接 |
| C | 只有代码没流程 | 有 `src/`（或等价源码目录）但无 CI、无测试目录；`git log --oneline -5` 仍在动 ⇒ 需要铺最小骨架（见 §4） |
| D | 只能只读观察 | `git remote -v` 不可写、介质只读、或用户明说「只许看」⇒ 只勘察，不落任何文件 |

判据全部落在「文件在不在 / 命令退什么码」上，不依赖人的口头描述。

## 二、映射：对方产物 → 我们的词

| 对方的产物 | 映射到 | 判据 |
|---|---|---|
| issue / 缺陷单 | **卡**（队列里的一条，进 backlog 文件） | 有标题、有验收 |
| CI job / 检查脚本 | **门**（一道能退出码判读的检查） | 能跑出 0 / 非 0 |
| 测试报告 / 覆盖率产物 | **证据**（台账条目里机器可求值的指针） | 文件路径能打开 |
| PR / 变更集 | **一笔提交**（落地单位） | 有 diff 边界 |
| 看板列（todo/doing/done） | **台账条目的 status** | 一列一值 |
| TODO 注释 / 未完事项 | 台账条目的 **gaps** | 写的是边界不是口号 |
| 口头约定、聊天记录、wiki 里「应该怎么改」 | **不映射** | 没有可求值形态，只能当背景写进复盘 |

★ 映射不上的显式写「不映射」，不硬塞 —— 硬塞出来的台账条目没有可求值证据，必然过不了对账。

## 三、安全边界：接手第一笔

**允许**（全部是只读或隔离内的动作）：

1. 只读勘察：`git log --oneline -5`、`git status --short`、读 README 与目录清单。
2. 跑对方现有的测试 / CI 命令（不改配置、不装依赖到系统级）。
3. 在隔离分支 / 隔离副本里铺骨架（§4），对方主干一个字不动。
4. 把勘察结论写进自己这边的复盘文件（本仓域内）。

**禁止**（可执行的限制清单，第一笔就生效）：

1. 禁止改对方的 CI 配置、门禁判据、测试断言 —— 红了是事实，不许调成绿。
2. 禁止重写历史（force push、rebase 已推送的分支、改已发布提交）。
3. 禁止删对方任何脚本 / 数据 / 备份目录，哪怕看着像死代码。
4. 禁止碰真实数据库与备份目录（本仓铁律原样适用）。
5. 禁止把骨架文件直接提交进对方主干 —— 骨架落在隔离层，集成由对方的人决定。
6. 禁止登记「没人验收的卡」：台账新条目必须带机器可求值证据，否则不许写 done。

## 四、最小骨架：补什么、不补什么

**必须补**（全是「只加文件」，参考 `skills/pipe-init/SKILL.md` 的落点表）：

| 文件 | 作用 |
|---|---|
| 骨架配置文件 pipeline.toml（或 `harness.toml`） | 门表与路径的唯一胶水；判据真源 |
| backlog 队列文件（如 `docs/workbacklog.toml` 这一形态） | 卡的家 |
| 台账壳（如 `docs/traceability.toml` 这一形态） | 条目追加的地方 |
| 至少一道真门（退出码判读） | 没有门 = 没接上 |

**坚决不补**（这些是运行态或本仓特有的产物，补了就是假成功）：

- 面板与面板桥（`tools/dsh_panel.py`、`tools/pipeline_view.py` 这类）—— 是本仓特例，见 §7。
- gates/diag 运行态目录 —— gitignored，各树自己生，不该进对方仓库。
- 渲染黄金、租约池、号池登记 —— 都是本仓并发体制的运行态。

**「只加文件」还是「允许改一行」**：默认只加文件。唯一允许「改一行」的两处：
对方 .gitignore 加一行运行态目录；对方 README 加一行指向骨架的说明。除此之外的改动都升级为卡。

## 五、第一步验收：从只读勘察到一笔落地

最小路径五步，每步给命令与产物：

1. **只读勘察**：`git log --oneline -5` + `git status --short` + 读仓根目录清单。
   产物：勘察笔记（分类判据逐条的读数）。
2. **定类**：按 §1 判据定 A/B/C/D；D 类到此为止，只交勘察笔记。
3. **铺骨架**（B/C 类）：`python -X utf8 framework/cli/main.py init --dir <隔离目录>`；
   产物：骨架配置 pipeline.toml + 台账壳 + 队列壳（退 0 且 count 与实铺文件数一致，
   自查口径见 `skills/pipe-init/SKILL.md`）。A 类跳过本步。
4. **一张卡 + 一道门**：队列里写一条最小卡（改一个文件、一条断言），
   跑一道门真出退出码 0。产物：门的输出日志 + 退码。
5. **一笔落地**：台账追加一条 `status=done`，证据用 `file:`/`test:` 这类
   机器可求值形态（本仓求值器是 `scripts/audit_progress.py`）；提交带
   `Task:/Refs:/Ledger:/Gates:` 四行 trailer。产物：提交 sha + 台账 diff。

验收口径：五步的产物全部存在且可重跑；第 5 步的台账证据换个窗口也能求值出同样结论。

## 六、失败模式：看起来接上了其实没接上

1. **门永远绿因为没真跑**：复用 / 缓存显示「通过」但本轮没执行。
   识破：本仓坑页已记 —— `gates/last.json` 的复用只说输入没变，自己动过的输入必须真跑一遍；
   接手侧同理：看门日志的时间戳与退出码，不看结论字段。
2. **卡登记了但没人派**：队列里有卡、没有任何租约占用、面板无读数。
   识破：查租约登记（本仓是 gates/diag 下的 pool-registry，gitignored 运行态），
   空 = 卡是死卡。
3. **证据指向不存在的路径**：台账写了 `file:` 证据但路径打不开。
   识破：`scripts/check_layers.py` 这类引用完整性检查；接手侧跑一遍「证据路径逐个存在」。
4. **台账 done 但证据不可求值**：证据写的是「已验证」「应该没问题」这类文字。
   识破：对每条 done 条目问「这条证据机器怎么判」；答不上来 = 假 done。
5. **骨架铺进了对方主干**：没走隔离层，直接污染对方仓库。
   识破：`git log` 里出现非对方作者的骨架提交；§3 禁止清单第 5 条就是挡这个。
6. **把本仓特有当通用**：把 `harness.toml` 的键、`gates/last.json` 的字段结构当成框架判据。
   识破：换第二个项目就对不上；判据的唯一落点是框架库与门（分工判据见 `skills/README.md` §1）。

## 七、反例：本仓哪些做法是特例，不能当通用能力

| 本仓做法 | 为什么是本仓特有 | 通用的那半是什么 |
|---|---|---|
| `tools/dsh_panel.py` 面板 | 本仓 DSH 环境的展示层 | 「状态要有一处真源」这条判据 |
| `tools/pipeline_view.py` 的工作台状态拼法 | 拼的是本仓 `harness.toml` 登记的键 | 「开工前能一眼看到谁在飞」这个需求 |
| gates/diag 运行态（gitignored） | 卡树里天然没有（本仓坑 25 记过） | 「勘察产物放哪」要显式定，不能假设目录在 |
| 证据前缀 `text:`/`route:`/`column:`/`ui:`/`test:`/`file:` 的求值 | 求值器在 `scripts/audit_progress.py`，本仓实现 | 「证据必须机器可求值」这条判据 |
| 派活切片的格式与 `tools/wb_dispatch.py` | harness 特有，属 `skills/GLUE-harness.md` 的域 | 「一卡一工人一白名单」这条纪律 |
| `gates/last.json` / `gates/reuse.json` 的字段结构 | 本仓 `scripts/run_gates.py` 的产物格式 | 「门禁结论落盘、可机读」这条判据 |

★ 通用判据与 harness 胶水的分界照 `skills/README.md` §1：判据进库 / 门，操作知识进技能，harness 特有值只进 GLUE 文件。
