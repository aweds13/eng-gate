# 主控复核器（T-G84）—— "这一笔提交算不算数"变成**一条命令**

> 一句话：外包之后主控每轮都要复核工人的提交。手工复核有五件事，每次现查既慢又容易漏 ——
> 而**漏一条**的代价是"把没验过的东西当验过了"。`tools/wb_review.py` 把五条判据一次过完。
> 2026-09-26；分支 `line/impl-v1`；台账 `T-G84`；**`src/` 一行没改**。

---

## §1 它判的五条（每条都对应本项目已写明的规矩）

| # | 判什么 | 依据 |
|---|---|---|
| ① | `scripts/audit_progress.py` 真跑一遍：退 0，且**豁免 0** | 用户约定：**audit 不过不许提交**、`[exceptions]` 保持 0 |
| ② | trailer：`Task:` **恰好一个**台账编号；`Ledger:`、`Gates:` 必须在 | 门禁⑧（T-G22 起的阻断项） |
| ③ | **门禁是不是为这一笔跑的**：`gates/last.json`（取这一笔里的那份）`ok=true`、`docs_sync_ok=true`、每道门 `exit_code=0`，且 `rev` **等于这一笔的父提交** | ★ 最要紧的一条：**一次门禁跑完提交两笔，第二笔就是"没验过"** |
| ④ | 改动越界没有：`--read-only`（只读卡一个被跟踪文件都不许改）或 `--allow <glob>` 白名单；**不给白名单就拒绝** | 外包卡的"只准改哪些文件"就写在这里 |
| ⑤ | 工作区干不干净（`-uno`） | 「一写一读」：工人不许留没提交的改动 |

用法与退出码：

```powershell
python -X utf8 tools/wb_review.py --rev HEAD --read-only          # 只读卡（报告卡用这个）
python -X utf8 tools/wb_review.py --rev <sha> --allow "src/**" --allow "tests/**"
# 0 全过 / 1 有不过的（逐条说为什么）/ 2 参数或 git 取不到
```

## §2 ★ 实测踩到的坑（这条值得单独记）

第一版直接 `git show --name-only`，于是**中文路径被 git 转义**成 `"\345\244\215\347\233\230/…"` ——
第 ④ 条的白名单**把中文路径全判成越界**（假红会让人去"修"一个没坏的东西）。
修法：所有 git 调用统一带 `-c core.quotepath=false`，并补一条测试
（`test_chinese_paths_are_not_escaped`：HEAD 的改动清单里**必须**原样出现 `复盘/…`）。
—— 同 T-G76/T-G79 那族：**判据自己要能证明它看得到东西**，否则"过了"可能只是"它没看见"。

## §3 边界（不假装）

- `gates/last.json` 的 **`tree` 字段故意不查**：它自己也在那棵树里（自指悖论），
  `scripts/run_gates.py` 里就写明"审计不看它"；这里只查 `rev`（父提交）与各门结论。
- 它**不判内容质量**（工人写的代码/报告对不对）—— 那是主控读一遍的事；
  它判的是"**流程**有没有走全"（证据/门禁/范围/痕迹）。
- 它依赖本项目的提交流程（`run_gates.py` 真跑 → `--seal` → 提交带 `gates/last.json`）。
  换个流程的仓库，第 ③ 条会直接红 —— 那是**故意的**。

## §4 一句话教训

> 复核这件事最怕"**每次现查**"：慢、漏、而且漏的那一条永远是你没想起的那条。
> 把它写成一个**会失败的判据**（12 条测试里大半是"该失败的输入"），
> 复核就从"我记得要查什么"变成"机器说这一笔算不算数"。
