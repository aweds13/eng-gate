# 封存指纹可核 · T-G179（卡 084）

> 一句话：`gates/last.json.tree` 曾是**一整列没人查、且每笔都错**的凭证 ——
> ① `scripts/run_gates.py:349` 把临时索引写死在 `ROOT/.git` 下，而 linked worktree 里 `.git` 是**文件**
> → `read-tree` 失败 → 回退成"底座提交的 tree"；② 就算不失败，`gates/last.json` 自己在那棵树里（自指）
> → 也永远追不上。本卡把回退修回（索引路径**由 git 自己给**），把指纹定义改成**「除 `gates/**` 外、
> 即将提交的内容」的 tree 哈希**（可复现的固定点），并让 `tools/wb_verify.py` 能**独立复算**它。
> 底座 `d8ed19c`（083 那笔提交）。门禁以 `gates/last.json` 为准（rev=父提交）。

## 一、病根（卡 §0 主控实测，照抄）

```
scripts/run_gates.py:349   tmp_index = ROOT / ".git" / "dsh_gates_index"     ← 写死 ".git" 是【目录】
而 linked worktree 里 `ROOT/.git` 是【文件】（git-dir = <主树>/.git/worktrees/<名>）
→ GIT_INDEX_FILE 指向一个"在文件底下"的路径 → `git read-tree HEAD` 失败
→ :359 回退 `git rev-parse HEAD^{tree}` = 【底座提交的 tree】（不是"即将提交的那棵树"）
```

**本树现算坐实**（`d:/文档/jelly_ware/program/engineering/.wt/gatefp`，`.git` 是文件）：

| 读数 | 值 |
|---|---|
| `test -d .git` | `FILE` |
| 提交在 `d8ed19c` 的 `gates/last.json.tree` | `c5047aa46bcb…` |
| `git rev-parse d8ed19c^{tree}`（本提交的 tree） | `bfa8abcc3bf4…`（≠） |
| `git rev-parse d8ed19c^^{tree}`（**父**提交的 tree） | `c5047aa46bcb…`（**= 旧 last.tree**） |

**结论**：旧 `last.json.tree` 记的是**父提交（=门禁跑时的 HEAD）那棵树**，不是"即将提交的那棵树" ——
与卡 §0 的判断一致（5 棵树无一例外）。而 `scripts/audit_progress.py:515-516` 与 `tools/wb_verify.py:32`
都**明写故意不查这个字段**（自指悖论 → 永远不相等）→ 这个洞一直没人补。

## 二、修法（四件）

1. **§1.1 索引路径由 git 给**：`scripts/run_gates.py::_git_index_path()` 用
   `git rev-parse --git-path dsh_gates_index`（拿不到再退 `--absolute-git-dir` 自己拼），
   **不再**手拼 `ROOT / ".git"`；两个都拿不到 → 打一行警告 + 回退（**不静默**）。
2. **§1.2 摘掉门禁产物 → 固定点**：`tree_without_gates(repo, rev, *, include_worktree, exclude_gates)`
   是**唯一实现**：临时索引 → `read-tree <rev>`（`include_worktree=True` 时再 `add -A`）→
   `git rm -r --cached --ignore-unmatch gates` → `write-tree`。`staged_tree()` 调它算指纹。
   docstring 写清：**是什么**（除 `gates/**` 外即将提交内容的 tree 哈希 / 可复现固定点）、
   **不是什么**（不是完整提交的 tree、不含门禁产物 —— 含了就自指）、**为什么之前会骗人**、**现在它已被检查**。
3. **§1.3 可独立复算**：`tools/wb_verify.py::check_fingerprint()` 新增一行，**import 门禁自己那份实现**
   （`<tree>/scripts/run_gates.py::tree_without_gates`）复算并比对 —— **不在此手写第二套切法**
   （080 那个假护栏的病根就是"手写第二套切法"）。旧笔（无 `tree_scope`）记 `INFO … 按旧口径不核`。
4. **§1.4 口径自述位**：`gates/last.json` 新增 `"tree_scope": "worktree-minus-gates"`
   （写在 `payload`（`:1026` 一带）与 `seal()` 两处），供 §1.3 分辨新旧笔。

（对比完整树 `bfa44b9e…` 的 gates 条目 = **49**）。

## 四、固定点（连续取指纹）

| 次数 | 操作 | 指纹 |
|---|---|---|
| ① | 不动任何文件 | `5d2f45dc4bc6…` |
| ② | 再取一次 | `5d2f45dc4bc6…` |
| ③ | **把 `gates/last.json` 改一个字节** | `5d2f45dc4bc6…` |

怎么写都追得上、不自指。

## 八、自指悖论：**削弱到哪一步**（如实，别吹）

- **解决了什么**：把"记的是底座树"（回退 bug）修对；把指纹定义成**不含 `gates/**` 的固定点**，
  于是 `last.json.tree` 可以被 `wb_verify` **独立复算** —— 同一份算法、两处共用一份实现。
  **现在能核到**：一笔提交"除 `gates/**` 外的内容"是不是它自称的那棵树（= 提交后复算必相等）。
- **没解决什么**（不许说"彻底解决"）：
  - 指纹**不含 `gates/**`** ⇒ 它**证明不了门禁产物本身**（`gates/last.json` 的内容、门数、ok）
    与提交一致 —— 那部分仍由 `wb_verify`/`audit` 的别几条（读 `HEAD:gates/last.json` 的字段）管，
    且**仍有"门禁产物自己在那棵树里"的自指**，只是被挪到别处、没被消除。
  - 它**不证明"门禁真在脏树上跑过"**：指纹只说明"提交时那块内容长这样"，
    不说明"门禁是拿这块内容跑出来的"（门禁结论仍只能靠 `last.json` 自述）。
  - 旧笔（无 `tree_scope`）**核不了**，只能标 INFO。
- **RI10（「无法脱离凭证独立证明门禁是在脏树上跑」）被削弱了多少**：从"这一列**每笔都错、且完全没人查**"
  变成"**新笔每笔都能被独立复算**（能查、且查得出对错）；旧笔如实标'不核'"。
  即：**把"门禁产物与提交内容对不上"这一类谎话，从"查不了"降成"查得到"**；
  但"门禁确实跑过脏树"这件事**仍未脱离凭证**，RI10 只是**缩小**、**未被消除**。
