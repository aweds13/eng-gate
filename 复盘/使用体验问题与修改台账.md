> 怎么验证、在哪一行。与**技术复盘**分开：技术复盘讲"为什么这么设计"（见 `前端现状评估与接缝重构方案.md`、

> 建立时间：2026-09-18（R3 三栏落地后，用户第一次真机看界面并连续反馈）
> 记录范围：2026-09-18 第 11 步之后的所有**用户提出**的体验问题；此前的反馈（并发卡顿、GPA 制式切换、

## 二、逐条记录（问题 → 根因 → 改动 → 验证）

### U-01 · 「帮我打开」

- **背景**：代码改完，但用户还没看到过界面。此前所有前端工作都靠真机自测 + 字符串护栏，**没人真点过**。
- **做了**：`python -X utf8 tools/serve.py`（起服务前自动备份库、只绑回环 127.0.0.1、默认 8520）跑在后台作业
  `pwsh-3`；验证 `/` 200、`/api/health` ok、页面含三栏骨架与真实数据（库里 5 条任务）；用系统默认浏览器打开。
- **结果**：用户看到界面 → 提出 U-02/U-03/U-04。**"能跑就实测"这条铁律再次被验证**：
  这三个问题全是**只有真看界面才会发现**的（护栏当时全绿：pytest 268 + 前端自检 12 项都通过）。

### U-02 · 「添加」按钮被遮盖 / 太挤（真 bug，不是审美问题）

- **用户原话**：「宽屏今日。状态下，那个今日栏，今天要做什么？回车添加，添加被遮盖了，感觉太挤了」
- **根因（查代码确认，非猜测）**：`.new input{flex:1}`（无最小宽度上限、可被无限压缩）配
  `input[type=date]` 与 `button` **都不收缩** —— 一行内容总宽超出容器时，flex 不会自动换行，
  超出部分直接**溢出被裁**，于是按钮"被遮住"。
- **改动**（`src/web/app.css`）：
  ```css
  .new { flex-wrap: wrap; gap:10px; align-items:center }
  .new input          { flex:1 1 220px; min-width:0 }
  .new input[type=number] { flex:0 0 100px }     /* 数字框不抢整行 */
  .new input[type=date]   { flex:0 0 auto; min-width:150px }
  .new button         { flex:none }              /* 按钮永不被压缩 */
  ```
  规则对**所有**新增行生效（今日/全部任务/习惯/备忘录/复习/产出/手动投入），不只修欢迎页那一个。
- **验证**：护栏 `test_inputs_cannot_cover_submit_buttons`（断言换行、最小宽度、`min-width:0`、`flex:none` 都在）；
  真机自检「挤压修复样式在位」。**视觉仍需人工确认**。
- **顺带**：`<label>` 内联样式收进 CSS（`.new label`），少一处内联。

### U-03 · 「每一行都挤，学业那部分尤其挤」

- **根因**：学业页的"添加考核项"是**一行塞 5 个控件**（课程下拉 + 名称 + 截止日 + 权重 + 按钮），
  "录入成绩"是一行 3 个；`.grid` 里的卡片在 641–1023px 之间仍保持两列，进一步压窄。
- **改动**：
  - 新增 `.form/.field` **表单块**（标签在上、输入在下、自动换行的多列网格，`.field.narrow` 给数字/日期收窄）；
  - 学业页「添加考核项」改 4 个带标签字段 + 独立按钮行；「录入成绩」改 成绩 + 学分 + 按钮；
  - 补「课程」分节标题，让页面有节奏；卡片用 `.card.panel-card`（块级）承载表单，避免被 flex 行挤。
- **验证**：护栏断言 `.form`/`.field` 存在；真机自检「挤压修复样式在位」。
- **诚实说明**：**"不再挤"是主观判断，需要用户再看一眼**。如果还挤，下一步可调的旋钮：
  `.field` 的 `flex-basis`（200px）、`.form` 的 `gap`（12/14px）、641–1023px 区间 `.grid` 是否也折成一列。

### U-04 · 「有些功能的调整可以统一放在一个设置界面里吧。加入一个设置的界面」

- **背景（代码事实）**：本来**有**一个 `renderSetting`，但它只是"移动端简版合并页"，
  且**宽屏左栏没有入口** —— 用鼠标在桌面端根本进不去设置。用户的印象"没有设置界面"是准确的。
- **改动**：
  - 宽屏左栏导航末尾补「设置」入口（移动端底部 Tab 原本就有）；
  - 把设置页写成正式页面，分节收拢：
    **常用**（一键跳到下面各节）/ **外观**（主题、强调色）/ **学业**（GPA 制式 + 去学业页）/
    **数据与同步**（在线状态、冲突条数、跨端未实现如实标注）/ **入口**（各域页面）；
  - 学业页原地的 4.0/5.0 制按钮**保留**（就近可改，两处写法一致，都走 `view(current)` 刷新）。
- **验证**：护栏 `test_settings_page_is_unified_and_reachable`（左栏入口 + 四个收拢项 + 动作全部已注册）；
  真机自检「左栏有设置入口」。
- **明确没做（避免自动扩范围）**：把各页面自己的录入表单（习惯打卡、手动投入、产出）搬进设置 ——
  那些是**日常干活的地方**，搬进设置反而绕；设置只收"配置项与状态"。

### U-05 · 主题可调（U-04 的连带：把外观调整收进设置）

- **性质**：这本来是非功能规格 `SR-NF1`（亮/暗双主题）的既定要求，此前**从未落地**，
  在计划里正是"前端 R4"。因为用户要求"调整统一放设置里"，主题开关自然落在设置页 —— 于是**顺带把 R4 做完**。
- **改动**：
  - `<html data-theme="dark|light">` + `localStorage('tf_theme')` + `matchMedia` **跟随系统**（三选）；
  - 暗色令牌 `[data-theme="dark"]` 在 R1 就写好了，本轮只接线；
  - 强调色：预设色板写进 `app.css` 令牌区（`--accent-1..6`），**JS 用 `getComputedStyle` 读**
    —— 第一版把色值写在脚本里，被 R1 护栏"index.html 不许有硬编码颜色"当场抓住，按规矩搬回 CSS；
  - **修一个真 bug**：`render()` 每次都用 `config.accent_color` 覆盖 `--accent`，
    导致用户选的强调色在下次刷新被打回默认；现在本机选过就以本机为准，配置值只作为默认。
- **验证**：护栏 `test_theme_is_selectable_and_wired`、`test_accent_palette_lives_in_css_not_js`；
  真机自检「暗色令牌可取到」「色板令牌」。
- **文档同步**：`docs/specification/nonfunctional.md` 的 SR-NF1 后补了"落地"说明（**未改它的要求**）；
  覆盖矩阵、changelog、交接文档同步。

## 五、将来提反馈的写法（让处理更快）

- **尽量带上三个要素**：① 哪个页面（今日 / 学业 / 设置…）；② 点哪里出的问题；③ **期望看到什么**。
  - 例：「宽屏 · 今日 · 输入框那行 → 期望按钮永远完整可见」（U-02 就是这么定位到真 bug 的）
- **说"挤/乱/找不到"也完全够用** —— 那类描述反而最能暴露布局与信息架构的真问题（U-02/U-03/U-04 都是）。
- 提完我会：查这份台账 → 定位根因（**不猜，先看代码/实测**）→ 改 → 加护栏防回退 → 回填本表 §一/§二。
- **一件事一件事来**：一次只做一步、保持测试全绿（`复盘/长任务执行协议.md` §三）。
