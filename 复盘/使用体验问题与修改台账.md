# 台账 · 使用体验问题与修改（用户反馈 → 代码改动）

> **这份文档装什么**：用户**在实际使用界面时**提出的问题、要求、感受，以及针对每一条做了什么、
> 怎么验证、在哪一行。与**技术复盘**分开：技术复盘讲"为什么这么设计"（见 `前端现状评估与接缝重构方案.md`、
> `第6-10步工作线复盘.md` 等），这份只讲**"用起来哪里不对劲 → 改了什么"**。
>
> **怎么用**：① 用户提问题时，先来这份查是否提过、是否已改；② 每修一条，在 §二 追加一行，
> 在 §一 回填处理状态；③ 状态用「待处理 / 处理中 / 已改·待人工确认 / 已确认 / 不采纳（写明原因）」。
>
> **口径**：本台账**不改任何产品规则**。涉及产品决策（比如"软删除还是彻底删"）的记录仍在
> `缺口处理与假设台账.md`（A-xxx）；本台账只记录体验层的问题与处置。
>
> 建立时间：2026-09-18（R3 三栏落地后，用户第一次真机看界面并连续反馈）
> 记录范围：2026-09-18 第 11 步之后的所有**用户提出**的体验问题；此前的反馈（并发卡顿、GPA 制式切换、
> 加权平均成绩）已由用户决定并落地，见 §三「已闭环的历史反馈」。

## 二、逐条记录（问题 → 根因 → 改动 → 验证）

### U-01 · 「帮我打开」

- **背景**：代码改完，但用户还没看到过界面。此前所有前端工作都靠真机自测 + 字符串护栏，**没人真点过**。
- **做了**：`python -X utf8 tools/serve.py`（起服务前自动备份库、只绑回环 127.0.0.1、默认 8520）跑在后台作业
  `pwsh-3`；验证 `/` 200、`/api/health` ok、页面含三栏骨架与真实数据（库里 5 条任务）；用系统默认浏览器打开。
- **结果**：用户看到界面 → 提出 U-02/U-03/U-04。**"能跑就实测"这条铁律再次被验证**：
  这三个问题全是**只有真看界面才会发现**的（护栏当时全绿：pytest 268 + 前端自检 12 项都通过）。

### U-02 · 「添加」按钮被遮盖 / 太挤（真 bug，不是审美问题）

- **用户原话**：「宽屏今日。状态下，那个今日栏，今天要做什么？回车添加，添加被遮盖了，感觉太挤了」
- **根因（查代码确认，非猜测）**：`.new input{flex:1}`（无最小宽度上限、可被无限压缩）配
  `input[type=date]` 与 `button` **都不收缩** —— 一行内容总宽超出容器时，flex 不会自动换行，
  超出部分直接**溢出被裁**，于是按钮"被遮住"。
- **改动**（`src/web/app.css`）：
  ```css
  .new { flex-wrap: wrap; gap:10px; align-items:center }
  .new input          { flex:1 1 220px; min-width:0 }
  .new input[type=number] { flex:0 0 100px }     /* 数字框不抢整行 */
  .new input[type=date]   { flex:0 0 auto; min-width:150px }
  .new button         { flex:none }              /* 按钮永不被压缩 */
  ```
  规则对**所有**新增行生效（今日/全部任务/习惯/备忘录/复习/产出/手动投入），不只修欢迎页那一个。
- **验证**：护栏 `test_inputs_cannot_cover_submit_buttons`（断言换行、最小宽度、`min-width:0`、`flex:none` 都在）；
  真机自检「挤压修复样式在位」。**视觉仍需人工确认**。
- **顺带**：`<label>` 内联样式收进 CSS（`.new label`），少一处内联。

### U-03 · 「每一行都挤，学业那部分尤其挤」

- **根因**：学业页的"添加考核项"是**一行塞 5 个控件**（课程下拉 + 名称 + 截止日 + 权重 + 按钮），
  "录入成绩"是一行 3 个；`.grid` 里的卡片在 641–1023px 之间仍保持两列，进一步压窄。
- **改动**：
  - 新增 `.form/.field` **表单块**（标签在上、输入在下、自动换行的多列网格，`.field.narrow` 给数字/日期收窄）；
  - 学业页「添加考核项」改 4 个带标签字段 + 独立按钮行；「录入成绩」改 成绩 + 学分 + 按钮；
  - 补「课程」分节标题，让页面有节奏；卡片用 `.card.panel-card`（块级）承载表单，避免被 flex 行挤。
- **验证**：护栏断言 `.form`/`.field` 存在；真机自检「挤压修复样式在位」。
- **诚实说明**：**"不再挤"是主观判断，需要用户再看一眼**。如果还挤，下一步可调的旋钮：
  `.field` 的 `flex-basis`（200px）、`.form` 的 `gap`（12/14px）、641–1023px 区间 `.grid` 是否也折成一列。

### U-04 · 「有些功能的调整可以统一放在一个设置界面里吧。加入一个设置的界面」

- **背景（代码事实）**：本来**有**一个 `renderSetting`，但它只是"移动端简版合并页"，
  且**宽屏左栏没有入口** —— 用鼠标在桌面端根本进不去设置。用户的印象"没有设置界面"是准确的。
- **改动**：
  - 宽屏左栏导航末尾补「设置」入口（移动端底部 Tab 原本就有）；
  - 把设置页写成正式页面，分节收拢：
    **常用**（一键跳到下面各节）/ **外观**（主题、强调色）/ **学业**（GPA 制式 + 去学业页）/
    **数据与同步**（在线状态、冲突条数、跨端未实现如实标注）/ **入口**（各域页面）；
  - 学业页原地的 4.0/5.0 制按钮**保留**（就近可改，两处写法一致，都走 `view(current)` 刷新）。
- **验证**：护栏 `test_settings_page_is_unified_and_reachable`（左栏入口 + 四个收拢项 + 动作全部已注册）；
  真机自检「左栏有设置入口」。
- **明确没做（避免自动扩范围）**：把各页面自己的录入表单（习惯打卡、手动投入、产出）搬进设置 ——
  那些是**日常干活的地方**，搬进设置反而绕；设置只收"配置项与状态"。

### U-05 · 主题可调（U-04 的连带：把外观调整收进设置）

- **性质**：这本来是非功能规格 `SR-NF1`（亮/暗双主题）的既定要求，此前**从未落地**，
  在计划里正是"前端 R4"。因为用户要求"调整统一放设置里"，主题开关自然落在设置页 —— 于是**顺带把 R4 做完**。
- **改动**：
  - `<html data-theme="dark|light">` + `localStorage('tf_theme')` + `matchMedia` **跟随系统**（三选）；
  - 暗色令牌 `[data-theme="dark"]` 在 R1 就写好了，本轮只接线；
  - 强调色：预设色板写进 `app.css` 令牌区（`--accent-1..6`），**JS 用 `getComputedStyle` 读**
    —— 第一版把色值写在脚本里，被 R1 护栏"index.html 不许有硬编码颜色"当场抓住，按规矩搬回 CSS；
  - **修一个真 bug**：`render()` 每次都用 `config.accent_color` 覆盖 `--accent`，
    导致用户选的强调色在下次刷新被打回默认；现在本机选过就以本机为准，配置值只作为默认。
- **验证**：护栏 `test_theme_is_selectable_and_wired`、`test_accent_palette_lives_in_css_not_js`；
  真机自检「暗色令牌可取到」「色板令牌」。
- **文档同步**：`docs/specification/nonfunctional.md` 的 SR-NF1 后补了"落地"说明（**未改它的要求**）；
  覆盖矩阵、changelog、交接文档同步。

### U-06 · 「全屏时列表应该放在左边框，而不是上边框」

- **用户原话**：「8521 在全屏的时候，他的列表应该放在左边框，而不是上边框吧？没有原版本的好看。」
- **根因（两个，都是真 bug）**：
  1. 断点定得太高：原来只有 **≥1024px** 才是三栏，用户在未最大化的窗口（900~1000px）看到的是
     "左栏变成主区上方一行横向导航"，也就是"列表跑到上面"；而 R3 之前的单列版顶部本来就有横向导航，
     所以旧版反而"看起来正常"。
  2. **两个断点重叠**：三栏块写 `min-width:1024px`、单列块写 `max-width:1023px` —— 我改成 980 之后忘了
     同步另一侧，980~1023 之间两套规则同时命中，rail 同时吃到"固定 168px 列"和"横向 banner 内边距"，
     出现半栏半横幅的错乱。
- **改动**（`src/web/app.css`）：三栏门槛降到 **≥980px**、单列块改 `max-width:979px`（**互斥**）；
  三栏从 grid 换 **flex**（`rail 168px` / `main ≤820px` / `sidebar 300px` + `justify-content:center`）——
  顺带解掉"媒体块规则被后面的基础规则覆盖"这个坑（grid 那版 `main` 的 padding 就被盖掉过）。
- **验证**：护栏 `test_three_column_shell_exists`（断言 980/979 两个断点与宽度约束）、
  真机自检「宽屏三栏是弹性布局」「断点互斥(980/979)」。

### U-07 · 日期框默认今天

- **用户原话**：「添加任务中……那个应该默认是今天，是你显示的时候是 yyyy mm dd 一个日字，但我希望直接默认今天，
  然后再点进去选具体日期。」
- **改动**：新增 `todayISO()`（**用本地时区拼串**，不用 `toISOString()` —— 那会给 UTC 日期，东八区晚上会差一天）
  与 `defaultDateFields()`；今日页 `#newDue`、全部任务页 `#allDue` 渲染后默认填今天，
  输入框 title 说明「截止日（默认今天，可改）」。顺带把「推到明天」也改成同一套本地日期算法。
- **验证**：护栏 `test_date_fields_default_to_today`。

### U-08 · 「加入今天」那句说明

- **用户原话**：「『今日』的界面，那个加入今天就没有必要再添加这句说明了吧。」
- **处理**：**说明去掉，勾选保留**。理由（必须说清，否则会造成新困惑）：
  `due_date`（截止日）与 `is_myday`（是否进今天清单）是**两个维度** —— 日期默认今天 ≠ 自动进今天
  （例如"下周一交的作业，今天先记下来但不放进今天的清单"）。勾选文案改为「也放进今天的清单」，
  比原来的「加入今天」更不容易和日期混淆。
- **验证**：护栏 `test_date_fields_default_to_today` 明确断言 `newMyDay` 仍在。

### U-09 · 回收站要能彻底删除 / 清空

- **用户原话**：「回收站应该设置可以清空或者硬删除的能力吧，纯软删除的话数据会越积越多。」
- **后端**：`purge_task()` 由"无校验的物理删除"改为**只接受回收站里的任务**（活动任务 → `ValueError` → 400，
  必须先软删除；任务不存在则幂等返回）；新增 `purge_deleted_tasks()`（清空回收站，返回条数，幂等）。
  API：`DELETE /api/tasks/{id}/purge`、`POST /api/tasks/purge-deleted`
  （后者必须声明在 `/{task_id}` **之前**，否则 `purge-deleted` 会被当成 task_id —— 已用测试钉住顺序）。
- **前端**：回收站每项加「彻底删除」，底部加「清空回收站（N 项，不可恢复）」；两处**二次确认**
  （清空是两道），并显示「删除于 某年某月某日 某时」。
- **验证**：`tests/test_task_delete.py` 新增 5 项（只删已删/幂等/清空只清已删/不留孤儿分组关联/API 400 与路由顺序）。
- **契约影响**：`docs/contracts/domains/F1-tasks.md` OP-6 原写「彻底删除不在界面暴露」，本轮按用户要求改为**暴露**，
  并保留"只能删回收站里的"这条安全边界。

### U-10 · 任务详情：看得到"完成时间"和这个任务的历史

- **用户原话**：「按那个记录按钮后，会显示类似于『完成09-18T17:31』这样的文字，我希望改成『完成于』某年某月某日某时」；
  「点击我具体的任务后，应该显示任务的详细……你现在是看不到详细的，完成的那些任务还没完成的。我要求点击进去就能看得到，点一下那个任务卡。」
- **改动**：
  - 新增 `humanTime()`：`2026-09-18T17:31` → `2026年09月18日 17:31`；事实流水、「建于/更新于」都用它。
  - 任务卡片：完成的任务显示**「完成于 2026年09月18日 17:31」**（绿标），未完成的显示**「未完成」**（中性标），
    点卡片上的「详情」在右栏看全部字段（状态/截止/分组/重复/负责人/时间）+ 最近 12 条事实流水。
  - **选中态**：正在右栏查看的那张卡加一圈强调色描边（否则"在看的到底是哪个"说不清）。
  - 「详情」按钮保留在卡片上；用户说的"点一下任务卡"我**没有整卡可点** —— 因为卡片上的勾选/按钮都是点击目标，
    整卡可点会误触；改为按钮 + 选中描边（如果你确实要整卡可点，我再加，那就得把勾选和按钮的点击隔离）。
- **验证**：护栏 `test_task_card_shows_completion_state`、`test_task_detail_panel_shows_readable_history`；
  「记录」按钮的旧提示条（ISO 串）也换成了同样的可读格式。

  "只存引用句柄"是**备忘录**（F8/`memos.ref_handle`）的能力，任务没有。要做得先定规格（见 §四-2 的 GAP-01）。

### U-11 · 完成圈要正圆

## 五、将来提反馈的写法（让处理更快）

- **尽量带上三个要素**：① 哪个页面（今日 / 学业 / 设置…）；② 点哪里出的问题；③ **期望看到什么**。
  - 例：「宽屏 · 今日 · 输入框那行 → 期望按钮永远完整可见」（U-02 就是这么定位到真 bug 的）
- **说"挤/乱/找不到"也完全够用** —— 那类描述反而最能暴露布局与信息架构的真问题（U-02/U-03/U-04 都是）。
- 提完我会：查这份台账 → 定位根因（**不猜，先看代码/实测**）→ 改 → 加护栏防回退 → 回填本表 §一/§二。
- **一件事一件事来**：一次只做一步、保持测试全绿（`复盘/长任务执行协议.md` §三）。
