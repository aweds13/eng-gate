# 功能验收机器化 —— 行为流层（T-G34）

> 一句话：**「待人工确认 28 项」里功能性的那些，从今天起归机器** —— 真浏览器、真点击、真按键，
> 每一条流都声明它替掉哪一条人工项；建成当天就抓到一族真缺陷（界面里字面的星号）。
> 2026-09-23；分支 `line/impl-v1`。工具：`tools/ui_flow_check.mjs` + `tools/tf_browser.mjs`。

---

## §1 为什么还要一层：三层各管一段，中间那段一直空着

T-G32 做完渲染层之后，台面上是这样分工的：

| 层 | 判什么 | 不判什么 |
|---|---|---|
| `tools/ui_dom_probe.mjs`（假 DOM） | 模板渲染**抛不抛错**、动作有没有注册、空不空 | 真浏览器里长什么样、点了会不会动 |
| `tools/web_live_check.py`（真 HTTP） | **接口**对不对、状态码、原话 | 界面里按钮点不点得着 |
| `tools/render_check.mjs`（T-G32 真浏览器） | 渲染**变了没有**（几何清单逐字节比黄金） | 点了会怎样 —— **它一个东西都不点** |
| ★ `tools/ui_flow_check.mjs`（本层） | **点下去会怎样**：能点开吗、关掉还来吗、非法值拦得住吗、二次确认是站内弹窗吗 | 好不好看、这句话说得对不对 |

**「先后顺序」这件事本身就是缺陷**：T-G32 那三类缺陷（卡片正文被挤成一列一个字、
复选框被画成文本框、离线页说明卡永远挂着）都是"渲染出来才看得见"。
还有另一类同样看不见的：**按钮点了没反应、报错指错对象、取消之后数据被改了** ——
它们在假 DOM 里"渲染成功"，在接口层"200 OK"，在几何黄金里"一个像素都没变"。
这一层补的就是这一段。

**它搬的是什么**：`复盘/交接-重构进度.md` §二「待人工确认 28 项」。
搬的判据只有一条：**这一项能不能写成"点一下、看一个事实"**。
能写的搬走；剩下的是**口味与选择**（喜不喜欢、这句话说得对不对）—— 那不叫验证，叫决策。

## §2 它怎么做的（以及为什么每个动作都要"真"）

### 真点击 = 命中测试 + 真鼠标事件，不是 `el.click()`

`el.click()` **会绕过命中测试**：一个被浮层盖住、被挤出视口、或者 `pointer-events:none` 的按钮，
`.click()` 照样"成功"。而用户点不到就是点不到。所以每次点击都走三步：

1. `scrollIntoView({block:'center'})` 先滚进视口（真实用户也得先看到它）；
2. **`document.elementFromPoint(中心点)` 做命中测试** —— 那个坐标上真正会被点到的是谁？
   不是它也不是它的子孙 → **当场判失败**，并说出"那个点上其实是 `<div class="modal">`"；
3. `Input.dispatchMouseEvent`（mouseMoved → mousePressed → mouseReleased）真按下去。

### 真按键 = `Input.dispatchKeyEvent` 逐字符，不是 `value = '…'`

直接改 `value` 会绕过 `keydown` / `keypress` / `input` 事件。而这个界面里
**回车提交**走的是 `data-enter` 那条键盘通路（`index.html:866`），
**输入校验**也只在真打字时才经过。所以 §3 里的「勿扰时段」那条流是：
真打字 `25:00-07:00` → 真按回车 → 等后端回话 → 读提示条 —— 全程没有一个 `value =`。

### 每条流都声明「我替掉哪条人工项」

登记时必填 `item`（如 `前端批次③ ⑦ 今日页新手引导卡片`），`--list` 会打出来，
`tests/test_ui_flow_check.py` 还会**逐条回查交接文档里那个编号还在不在**。
为什么不省这一步：这一层存在的**全部意义**就是把人工项搬给机器 ——
"搬走了哪几条"如果只剩一句口头说法，那就退化成了"我说我搬了"。

### 一段 HTML 里不带任何 `data-*` 值当路标

页面上有一批路标是数据 id 拼的（`asTarget-<uuid>`），还有"第几个"会随排序变。
所以找元素走 `mark()`：按选择器（可再加"它自己文字里含…"/"它所在的那张卡里含…"）挑一个**可见**的，
打一个临时 `data-tfprobe="hit"`，再照那个标记去点。标记只活在这一次页面里，刷新即消。

### 底座是共用的（并且这件事本身被证明了）

`render_check.mjs` 里那套"起临时库 / 起真浏览器 / 把渲染环境钉成确定的"（滚动条、随机设备号、
固定导出目录……每一条都是踩出来的）被抽到 `tools/tf_browser.mjs`，两个工具共用。
**抽完怎么证明没抽坏**：跑渲染层 —— **42 份黄金逐字节一致 + 确定性自检通过**（实测 91.7s）。
另外 `tests/test_ui_flow_check.py` 里有一条测试专门拦"谁又抄一份底座"
（渲染层里不许再出现 `function startServer` / `class Cdp` / `EDGE_CANDIDATES`）。

### 每轮跑两遍（这是"不会漂"的那一条）

跟渲染层同一个道理：**第一遍与第二遍各自起新库、新浏览器**，
两遍的**断言指纹**（每条流 × 每项断言 × 通过与否）必须逐字一样 ——
不一样就是**这个工具自己不可信**（退出码 4），不当成"界面坏了"。
`--once` 只给调试用，且会明确打印"这一轮**没有**做确定性自检"。

## §4 ★ 建成当天抓到的那一族：界面里字面的星号（6 处 → 10 个渲染口）

第一次跑，㉑ 直接红：`setting` 视图里扫出 **18 个 `**`**（= 9 组「重点」标记，每组两个星号）。

**根因**：后端那些 `describe()` 的「口径说明」文字里用 `**重点**` 标重点（这是**约定**，
`index.html:130` 有个 `noteHTML()` 专门把 `**x**` 转成 `<b>x</b>`，**先转义再只认 `**`**，防注入那条路不松）。
但**有些渲染口用的是 `esc()`** —— 那些说明在界面上就被原样画出星号：

| 后端在哪写的 | 界面原来怎么画的 |
|---|---|
| `core/focus/guard.py`（勿扰口径） | `${esc(guard.note)}` |
| `core/behavior.py`（口径与回退：`note` + `switch_note` + 每条 `current_note`） | `${esc(...)}` |
| `vocab.py`（词表说明） | `${esc(vb.note)}`、`${esc(t.note)}` |
| `core/ai.py`（AI 动作清单 `surface[].what`） | `${esc(s.what)}` |
| 学校通知的字段/路由说明 | `${esc(f.what)}` / `${esc(s.what)}` |
| 备份与恢复说明（`app.py`） | `${esc(bk.note)}` |

**为什么以前那两层护栏都没拦住**（T-G11 建的护栏是"两层"，见 `复盘/界面字面星号缺陷-T-G11.md`）：
① 第一层扫的是 `index.html` **脚本里的字符串字面量** —— 这些星号在**后端 Python** 里，它看不见；
② 第二层扫**渲染结果**，但用的是探针的**桩数据** —— 桩数据里没有这些 note，
于是那些分支根本没被渲染到。T-G11 的复盘把这条边界如实写在 §五了（"第二层只覆盖桩数据能渲染到的分支"），
**本层正好就是补这个缝的**：真后端、真数据、真渲染。

**改了什么**：把这 10 个渲染口改成 `noteHTML()`（**一个字都没改**，只是让"重点"真的变成粗体、
不再画出星号），并在 `noteHTML` 的定义处把规矩写死：

> · **后端 `describe()` 那类"讲口径"的说明文字** → `noteHTML()`；
> · **用户自己写的内容**（任务备注 / 考核要求 / 备忘 / 产出说明）→ 一律 `esc()` ——
>   用户写的 `**` 就是两个星号，不是重点；
> · **属性里**（`title=` 这类）只能 `esc()`：属性里塞不进 `<b>`。

**黄金层当场证明了改动范围**：只动黄金 = **3 份**（`desktop/narrow/phone × setting`），
每份 `-7 +16` 行（`**x**` 那行拆成 容器 + `<b>` 子元素，字重 400 → 700），
其余 **39 份逐字节不变** —— 也就是说"这次只碰了设置页那些说明文字"是**机器确认**的，不是我说的。
理由已落 `gates/render/LAST_UPDATE.md`。

## §5 建层时踩到的坑（4 个，其中 3 个是我自己写错的断言）

| 坑 | 真因 | 教训（已固化在哪） |
|---|---|---|
| ⑦ 断言"叫回来之后站的是今日页"永远失败 | 我拿**输入框的 placeholder 文案**（「今天要做什么？回车添加…」）去 `innerText` 里找 —— **placeholder 不是 innerText**，它压根不在文本里 | 断言要盯"用户真正看得到的"（改成看 `[data-view="today"].active`）。**拿看不到的东西当判据 = 假红/假绿** |
| ⑩ 断言标题 `=== 「删除分组「高数」」` 失败 | 实际标题是一整句（写清后果：「…？任务会保留，只是不再归到这个分组。」）。**界面是对的，断言太紧** | 文案**本来就允许更长**时用"包含"；但**故意用等号**的地方要保留等号（确定按钮上的动作名就该**恰好**是「删除分组」） |
| ⑨ "合法时段加不上" | **不是界面缺陷**：打完第一次的非法值后没清空输入框，光标落在中间 → 值变成 `25:00-07:0022:00-07:00` → 后端照旧拒绝 | 重填输入框**必须先全选**。修在底座里（`Cdp.selectAll()`），不是修在那条流里 —— 否则下一条流还会踩 |
| ⑥ 三条断言全落在隔壁那张卡上 | 路标挑了 `未绑定任务的专注`：**两张卡里都有这句话**，`mark` 抓了第一个 | 路标要挑"**这句话没了它就说不通**"的那种（原话在 T-G31 已经写过一次）。这次幸亏隔壁卡**碰巧**没有我要的那几句，要是碰巧有，就是**假通过** |

**另外补掉一个假绿灯**：`--only 打错字` 原本会"0 条流 → 通过 ✅ 0 条流"。
**空集永远满足"所有流都通过"** —— 这种绿灯比红灯更坏（红灯你会去看，假绿灯你不会）。
现在 `--only` 没匹配到任何流 → **起浏览器之前就报错退出**，并把现有流列出来。

## §6 这一层**不**假装能做到的事（边界如实写）

1. **判不了"好不好看"，也判不了"这句话说得对不对"**。它判的是"点下去发生了什么"。
2. **物理场景仍在人工那一栏**：两台设备 / 手机连热点 / 校园网隔离 / Windows 计划任务 /
   真桌面窗口 —— 这一层动不了那些。
   （`㉖ 手机直接上传`、`⑲⑳ 局域网与校园网`、`⑫ 桌面窗口`、`㉘ 跨端专注镜像` 的**双窗口**版都还留在人工栏；
   `㉘` 的单机版将来可以在这一层里开**两个 CDP 页面**验，还没做。）
3. **它是"我写的断言"**：断言写错 → 它给我一个**错的绿灯**。§5 那四条里有三条正是这类。
   所以它证的是"我关心的那些点都对"，不是"界面一定对"。
4. **扫文本那条流用了更弱的等待**（`settle()`：`#main` 连续 3 拍不变，≈0.6s，而不是"整页安静"）——
   代价是**更晚才到的东西会漏**。取 3 拍而不是 1 拍就是这个原因；真验行为的流一律用强等待。
5. **流会改数据**（建复习卡、加勿扰时段……）：所以每遍都是**新库**，
   且能自己收拾干净的流自己收拾（⑨ 加完就删）。
6. **它不替代 pytest**：值算得对不对仍归 pytest（这一层只看"界面上发生了什么"）。

## §9 与前两层的关系（一句话各自站位）

> **假 DOM 层**证明"模板不会崩"；**接口层**证明"后端说的是真话"；
> **渲染层**证明"画面没变"；**行为流层**证明"点下去真的会发生说好的那件事"。
> 四层都不管"好不好看" —— 那是人的事，而人只该在有意的视觉改动时看一眼 diff 图。
