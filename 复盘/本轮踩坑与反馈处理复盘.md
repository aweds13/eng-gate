## 二、踩的坑（按类型，逐条：现象 → 根因 → 修法 → 防复发）

### A. 工具/环境坑（4 类，都可复现）

#### A-1 用 PowerShell 的 `Get-Content -replace | Set-Content` 改中文文档，把文件写成非 UTF-8
- **现象**：改完 `复盘/交接-重构进度.md` 后，读取报 `invalid UTF-8 text`；控制台里中文全是 `锟斤拷`。
- **根因**：Windows PowerShell 的 `Set-Content` 默认编码不是 UTF-8；中文文档被按 ANSI 写回。
- **修法**：立刻 `git checkout -- <文件>` 回到已提交版本，**改用文件编辑工具逐条重做**（10 处编辑），
  重做后用 `UTF8Encoding(false, true)` 严格解码逐个校验通过。
- **防复发**（已写进 `新窗口交接卡.md` §五禁止事项）：
  **中文文档一律用编辑工具改，禁止 shell 重定向/`Set-Content` 写文件。**
- **代价**：约 15 分钟返工；没有丢内容（因为上一版已提交）。

#### A-2 `Out-File -Encoding utf8` 给提交信息写了 BOM，污染 commit subject
- **现象**：`git log --oneline` 看到 subject 前面多一个不可见字符（` fix(web): ...`）。
- **根因**：Windows PowerShell 5.1 的 `-Encoding utf8` 会写 BOM；git 把 BOM 当正文第一字节。
- **修法**：改用 Python 以 `encoding="utf-8", newline="\n"` 写消息文件，再用 `git commit --amend -F`；
  并加了一行自检（打印头 4 字节应为 `b'fix('`）。
- **防复发**：**提交信息也用编辑工具/Python 写**，不用 PowerShell 的 `Out-File`；或直接 `git commit -m`（单行时）。
- **附带教训**：我一度**误判**"BOM 还在"——因为控制台显示 `????`。实际那不是 BOM，是控制台编码显示问题。
  **结论：判断文件字节要用 `Format-Hex`/Python `read_bytes()`，别信控制台里看到的字符。**

#### A-3 PowerShell here-string `@"..."@` 静默吞掉 `$` 和引号，生成"看起来对、其实是坏的"脚本
- **现象**：用 `python -X utf8 -c @"..."@` 写审计脚本，`Path(__file__)` 的括号被吃掉、
  `re.search(r'...')` 变成 `re.search(r...)`。文件在编辑工具里显示正常，**执行结果却是错的**。
- **根因**：PowerShell 的 here-string 会做变量插值（`$`）且对引号有特殊处理；嵌套引号层层转义后失真。
- **修法**：**改用 write/edit 工具写脚本文件**，不再用 shell 里嵌 Python 源码。
- **防复发**：需要临时脚本 → 一律落成文件再执行（`.debug-ui/*.py`，已 gitignore）。

#### A-4 无头浏览器在沙箱里跑不起来（浪费了两轮尝试）
- **现象**：`msedge --headless=new --screenshot` 与 `--dump-dom` 都**卡住不退出**（需手动杀进程）；
  `stderr` 显示 `mojo ... platform_channel.cc: Check failed: Access denied (0x5)`。
- **根因**：沙箱禁止程序创建**命名管道**（`\\.\pipe\...`），而 Chromium 的多进程 IPC 就靠管道。
  这和「node 不能 `spawnSync` 子进程（EPERM）」是同一类边界。
- **修法**：放弃截图路线，改用**静态结构对比 + 假 DOM 跑脚本 + 问用户看到什么**；
  并给用户提供了 `tools/ui_ab.py`（并排跑旧/新前端）由**人眼**判断。
- **防复发**：**别在"能不能跑浏览器"上连续试两次以上**——确认是沙箱边界就立刻换路线（我试了两次，第二次才认）。

#### A-5 ⚠️ 我杀掉了**所有** msedge 进程（最该道歉的一条）
- **现象**：为了清理卡住的无头实例，执行了 `Get-Process msedge | Stop-Process -Force`。
- **后果**：**用户当时开着的所有 Edge 窗口可能被一起关掉**（我事后才发现这个问题）。
- **修法**：向用户明确道歉；此后只用 `Start-Process -PassThru` + `WaitForExit(ms)` + 只杀**那一个 PID**。
- **防复发**：**杀进程前必须按 PID 收敛范围**；涉及用户可见程序（浏览器/编辑器/终端）时，
  **宁可不清理，也不要连带杀**。

### B. 方法与流程坑（3 类，代价最大）

#### B-1 交付了 3 个阶段（R3/R4 + 修复轮）却**从没亲眼看过界面**
- **现象**：用户第一次打开界面就报「添加被遮盖」「学业太挤」「列表跑到上面」——**全是只有看了才知道的问题**；
  更严重的是「宽屏中列被拉满、上边距被清」这个布局回归，在 `pytest 268 passed` 下**完全没被拦住**。
- **根因**：把"结构断言 + 脚本语法检查"当成了"界面验证"；`tools/web_live_check.py` 只能证明
  "页面能取到、脚本能解析、容器在"，**证明不了渲染出来是什么样**。
- **修法**：① 立刻补 `tools/ui_ab.py`（旧版前端 + 现后端并排跑）请用户并排看；
  ② 把复盘里"**需人工确认**"的措辞写实（不再写"已闭环"）；
  ③ 新增布局不变量护栏（中列宽度上限/上边距/断点互斥）。
- **防复发**：**动布局的改动，必须请用户看一眼才算完成**；交付时明确说"我无法验证视觉"。

#### B-2 CSS 媒体块写在基础规则之前 → 同属性被覆盖（真 bug）
- **现象**：宽屏下 `main` 的 `padding` 变成 `0 24px 90px`（上边距被清），
  且失去 `max-width:820px` → 卡片在宽屏被拉到 1500px+，看着像"崩了"。
- **根因**：`@media (min-width:1024px){ main{...} }` 写在基础 `main{...}` **之前**；
  **同特异性下后者胜**，所以媒体块里的 padding 被基础规则覆盖。
- **修法**：媒体块里的 `main` 写全属性（`max-width` + `padding` + `margin`）；
  后来整体把三栏从 **grid 换 flex**，从根本上避开"基础规则覆盖媒体块"这类坑。
- **防复发**：**媒体块里的规则要写全属性**；布局改动后加"不变量护栏"
  （`test_main_stays_bounded_and_padded_on_wide_screens`）。

#### B-3 改断点时**只改了一侧**，两个断点重叠
- **现象**：三栏门槛从 1024 改成 980，单列块还是 `max-width:1023px` → 980~1023 之间**两套规则同时命中**，
  左栏变成"半固定栏 + 半横向 banner"的怪样子。
- **根因**：断点是**一对**（`min-width` / `max-width`），我只动了其中一半。
- **修法**：单列块改 `max-width:979px`（**互斥**），并加护栏断言两个断点同时存在。
- **防复发**：**凡是有媒体查询对（A/B）的，改动必须成对改**；护栏断言"两个断点恰好互补"。

#### B-4 审计脚本自己给出 3 个假结论（"机械化核对"也会骗人）
| # | 假结论 | 根因 | 修法 |
|---|---|---|---|
| 1 | SR-NF6「隔离机制没做」（**实际做了**） | 判定引用了 `facts/store.py`，而隔离逻辑在 `facts/bus.py`；`has()` 拿空串匹配 | 改引用 `bus.py`；**并加防呆：任一源文件读不到就报错退出** |
| 2 | SR-F1.4「任务字段齐全」（**实际缺 4 个**） | 判定条件太松（只要 `due_date` 在就算齐全） | 改成逐字段集合比较，缺口必须点名 |
| 3 | SR-NF8「shadow 机制有了」（**实际没有**） | `shadow` 命中的是 CSS 的 `--shadow` 令牌 | 改成 `shadow_mode|回退开关|shadow 对比` 精确匹配，并在注释里写明"CSS 令牌不算证据" |

- **防复发**：审计/护栏脚本必须有**防呆断言**（输入非空、文件存在、命中要打印证据），
  否则"脚本说没做"和"脚本说做了"一样不可信。

## 四、这一轮暴露的"系统性"问题（比单个 bug 更值得记）

1. **"闭环"这个词被用滥了。** 契约写了 OP-9「入口：任务详情面板」，而详情面板**当时根本不存在**，
   但测试全绿、自查表全 ✅ —— **契约的"入口"没人核对**。→ 审计报告已把它列为契约层最危险的模式，
   `任务重规划-剩余工作.md` 里也留了改进项（入口存在性纳入检查）。
2. **文档"未实现清单"本身会过期。** `modules.md` 说习惯不能增删（早已实现）、
   `traceability.md` 说周结算/可视化未实现（早已实现）。→ **未实现清单必须由审计产出，不能靠人工维护**。
3. **护栏只能守住"写下来过的东西"。** 布局回归能溜过去，是因为当时**没有**布局不变量护栏；
   补上之后同类问题会被拦住。→ **每修一个真 bug，就补一条护栏**（本轮新增 11 条）。
4. **我的"自我复核"有盲区。** 三处假判定、两处重复定义、一处死代码，都是**自查或工具**抓出来的，
   不是"再想一遍"想出来的。→ 结论：**复核要靠工具和清单，不靠再读一遍代码**。
