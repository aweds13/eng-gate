# 门禁锁租约改大并支持续租 —— 长门禁卡不再自己把自己变成陈旧锁（卡 067 · `T-G161`）

> 底座 `393fe84`（卡 065 那一笔，`gates/diag/gate_lock.py` 就是那一笔入库的）。
> 树 `.wt/lease1`；端口段 `TF_GATE_PORT_BASE=8901`；pytest 并发 `TF_PYTEST_WORKERS=2`。

## §1 为什么有这张卡（063 实测事故）

`gates/diag/gate_lock.py` 是「跨树一把」的门禁串行锁（铁律 25/27 的机械化）。063 那张反证卡
**在自己还持锁跑门禁时**被判成陈旧锁、被卡 066 拿走。事实时间线（063 的 log + 主控复核一致）：

```
11:10:08  063 拿到锁（租约默认 1800s）
11:16–11:41  它连跑三趟全量门禁（反证 A / B / C）—— 持锁 31 分钟
11:40:08  ★ 租约满，而它还在跑
11:40:18  066 按规则判它「陈旧」，直接把锁拿走
11:41:12  063 最后一趟门禁才结束 → 两趟真机门重叠约 1 分钟
```

**根因两条**：

1. `DEFAULT_STALE_AFTER = 1800`（30 分钟）**小于「一张卡持锁的常见时长」** —— 全量门禁 ≈ 6–7 分钟，
   而**三趟**（先绿后红那类反证卡）就是 **30 分钟**，正好把租约用光。
2. 租约是「**从 `acquire` 那一刻起算的静态计时**」—— 跑门禁期间**锁文件没人动**，
   于是「已 N 秒未动」一路涨到过期，**续跑中的卡会自己把自己变成「陈旧锁」**。

这次没红的唯一原因是 062 的端口隔离（063 默认段、066 用了 8841）；两张都用默认段就是一次假红。
这条与铁律 25 是一对：**25 说「别用 pid 判活 → 改用租约」；本卡说「租约是静态的 → 长活得续租」。**

## §2 改了什么

### §2.1 默认租约改大 + 印出到期时刻（`gates/diag/gate_lock.py`）
- `DEFAULT_STALE_AFTER`：`1800` → **`10800`（3 小时）**；模块 docstring 与 `--stale-after` 的 help 同步
  （help 用的是 f-string，自动显示 10800）。
- `acquire` 成功时**多印一行**租约到期时刻（本地时间）+「到期前记得 release，或让它自己续租」。
  ★ 只**加**这一行，**没有改**既有那几行的措辞（`pin_check --literal` 查过：既有措辞无钉子命中）。
- 改既有打印措辞之前先 `pin_check`：命中 2 处**叙述**（`gates/diag/gate_lock.py:17` 与
  `复盘/外包-卡表与规矩.md:713`），**钉子 0** → 安全。★ 那份协议文档 §24.7 仍写「默认 1800s」，
  它在**本卡禁区**（白名单外），**一个字没动**，见 §5 边界。

### §2.2 ★ 续租（本卡的正事）：选 **A（外部续租子命令）**
新增 `gate_lock.py renew --card <卡号>`：持有者（或它的看护）定期调用即 `os.utime` 刷新锁文件 mtime，
「多久没动」重新从 0 起算。**只有当前持有者 `--card` 名字相同才允许续** —— 别人续不了（退 **5**，且**不动**原锁）。

**为什么选 A 不选 B**：工人是**每次以子进程调用** `gate_lock.py`（`acquire` / `run_gates` / `seal` /
`release` 各是独立进程）—— 实现 B 的**进程级守护线程只在「同一进程里 acquire 后就地跑门禁」时才有效**，
跨进程场景**不生效**，而真实工人恰恰全是跨进程。A 的 `renew` 子命令**在跨进程下就生效**，
且判据干净（只刷 mtime）、可单独真机验证。B 的边界写在卡 §7.4 里，本卡不选它（也不实现它）。

★ 两条硬口径一点没松：**判据仍是锁文件 mtime（不引入 pid 判活）**；
**串行性没放松**（`renew` 不改「谁能拿锁」，只刷 mtime，且只有同卡号能续）。

## §3 先红后绿（`tests/test_gate_lock_lease.py`，5 条）

测试按路径 `importlib` 加载 `gates/diag/gate_lock.py`（`gates/diag/` 不是包），
每个用例把 `lock_path` **monkeypatch 到 tmp** —— **绝不碰跨树共享的真锁** `gates/diag/gates.lock`。
「多久没动」靠 **`os.utime` 拨 mtime** 造，不靠长时间 sleep（满负载下 sleep 会漂成假红）。

**先红**（旧实现 `git show 393fe84:gates/diag/gate_lock.py`，用环境变量 `GATE_LOCK_UNDER_TEST` 指过去）：


另两条（陈旧判定 / 串行同抢）**在旧实现上本来就是绿的** —— 那正是「这两条行为没被本卡改动」的对照。

## §4 续租 / 不许别人续 / 串行没松（真机 CLI 读数）

在**本卡自己持锁**（`--card 067`）期间，用真 CLI 验：

- **续租生效**：`renew --card 067` → 退出 0；`status` 的「已 Ns」从续租前的大数**回落**到 0 附近，
  报告为「租约内」；`renew --card 999`（别人的卡）→ 退出 **5**，且锁文件 mtime 前后**完全相同**。
- **串行没松**：`acquire --card A` 成功后，另一个卡 `acquire` 只能等/退 3 —— 逐字读数见回报。

（本节的具体数字在 §5 报告里以命令原始输出为准，不复述。）

## §5 边界（如实写，没做到的部分）

- **没动 `复盘/外包-卡表与规矩.md`**（禁区）：它的 §24.7 仍写「锁按租约判陈旧（默认 1800s 没动才算陈旧）」
  —— 与本卡的 10800 已不一致。★ 那是另一份文档，在禁区；建议主控后续按「只加日期注、不删不改原句」补一条。
- **没选/没实现实现 B**（自动续租线程）：理由见 §2.2（跨进程不生效）。B 的适用边界只在卡 §7.4 有记录。
- **`renew` 不自动**：它是个要人（或看护）**主动调用**的子命令；本卡只提供能力 + 把默认租约抬到 3 小时
  覆盖绝大多数场景，**没有**做「跑门禁时自动续租」的编排（那要有东西在门禁跑期间另起调用，超出本卡范围）。
- **`gates/diag/gate_lock.py` 的 4 处 ruff E501/UP009 是既有问题**（行 2 / 159 / 191 / 262），
  本卡**未引入新问题**（新加的 f-string 都在 100 列内）；且门禁的 ruff 档**不扫 `gates/`**
  （命令是 `ruff check src/ tests/ scripts/ tools/ examples/`），故不动它们（动了是本卡越界）。
- **没动**：`src/**`、`scripts/**`（含 `run_gates.py`）、其余 `tools/**`、`gates/diag/` 里除
  `gate_lock.py` 之外的一切、`data/`、真实库/备份、`.wt/**`、主树外来未跟踪文件。
