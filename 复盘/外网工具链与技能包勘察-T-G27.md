# 外网工具链与仓库里那份 UI/UX 技能包 · T-G27

> 起因两件：① 用户问「**怎么下载那么慢呢？**」；② 用户说「我仓库里还有一份 UI UX 的技能包，你找一找」。
> 这一份把两件事一起记下来：**这台机器上哪条外网路能走、哪条走不通**（省得下次再探一遍），
> 以及**仓库里那份第三方技能包到底是什么、跟我们已装的两个什么关系**。

---

## 1. 一句话结论

**慢的不是字节数（总共只下了约 1.3 MB），是"三条路里两条是死的"**：
`git`/`curl` 在这台机器上因为 TLS 凭证问题直接失败、`npm` 因为**缓存目录在工作区外被沙箱挡**而失败，
只剩 Node 自己的 `fetch` 能走。两条修法都实测过了（§3）。
**仓库里那份是 `UI UX Pro Max` v2.13.0**（7 个 skill / 260 文件 / 10 MB，自带 Python 搜索引擎）——
其中 **1 个跟我们直接对冲**（`ui-styling` = shadcn+Tailwind，与本项目"前端零依赖"相反），
**2 个值得用**（`ui-ux-pro-max` 的可搜索知识库、`design-system` 的令牌架构），其余 4 个是品牌/营销/演示方向。

## 2. 下载慢的三层原因（都实测过）

### ① `git` / `curl` 直接失败 —— TLS 凭证拿不到

```
git ls-remote https://github.com/...   → schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS
curl.exe https://registry.npmjs.org/…  → curl: (35) schannel: … SEC_E_NO_CREDENTIALS
```

`schannel` 是 Windows 自带的 TLS 后端 —— 它拿不到客户端凭证（校园网/公司网里那种中间设备很典型）。
**结果：0 字节，还要等超时。** `git clone` / `curl` 这类路在这台机器上不用试了。

### ② `npm` / `npx` 失败 —— 不是网络，是**缓存目录被沙箱挡**

```
npm error code EPERM
npm error path C:/Users/example\AppData\Local\npm-cache\_cacache\tmp\***
```

npm 的缓存目录在 `C:/Users/example\AppData\Local\npm-cache`，**在工作区之外**，
DSH 文件沙箱（workspace-write）不允许写那里 —— npm 连元数据都存不下，于是 `view` / `npx` 全废。
**注意这个错看起来像网络问题（"Invalid response body while trying to fetch …"），其实不是。**

### ③ 唯一能走的路是 Node 自己的 `fetch`，而它的**选源**很要紧

Node 的 `fetch` 用自带的 CA，不走 schannel，所以能通。实测同一份元数据：

| 请求 | 耗时 | 大小 |
|---|---|---|
| `registry.npmmirror.com` 的 sheleg 元数据 | **2715 ms** | 283 KB |
| `registry.npmjs.org` 同一份 | **427 ms** | 271 KB |
| `registry.npmmirror.com` 的 dwa 元数据 | 137 ms | 6.6 KB |
| `registry.npmjs.org` 同一份 | 64 ms | 6.4 KB |
| `raw.githubusercontent.com` | **FAIL（fetch failed）** | — |
| `cdn.jsdelivr.net` / `ghfast.top` / `gh-proxy.com`（三个 GitHub 代理） | 1439 / 810 / 395 ms | 3.6 KB |
| `api.github.com` | 546 ms | 6.2 KB |

**这台机器默认配的就是 `registry.npmmirror.com`（`npm config get registry` 实测），
而它比官方源慢 6 倍。** 另外真正花时间的其实是"**探哪条路能走**"——那次我试了 10 个候选地址。

下载量本身（两个包的 tarball）：`sheleg-design-skill` **1,212,670 B** + `dsh-web-artifact-designer` **20,456 B**
≈ **1.3 MB**。这一点点量不该让人觉得慢 —— 慢的是探路、以及两次"把 149 / 100 个文件全路径打出来"
（输出被落盘截断，看起来就像卡住）。

## 3. 两条修法（都实测过）

```powershell
# ① 把 npm 的缓存指到可写目录 —— 这条一改，npm/npx 系整个活了
$env:npm_config_cache = "$env:TEMP\npm-cache"
npm.cmd view sheleg-design-skill version     # → 1.61.0   ✅（默认 cache 下同一条命令 EPERM）

# ② 能用官方源就官方源（这台机器上快 6 倍）；Node fetch 兜底
#    git/curl 在这台机器上不要指望，直接走 Node。
```

注意 PowerShell 里 **`npm`（= npm.ps1）会被执行策略挡掉**，要用 `npm.cmd`。

## 4. 仓库里那份 UI/UX 技能包是什么

**位置**：`.uiux-skill-probe/`（在 `.gitignore` 里，**自带一个 `.git`** —— 是一份第三方仓库的克隆，
不是本仓库的内容）。**本次没有动它，也没有装它。**

**身份**：

| 项 | 值 |
|---|---|
| 名字 | **UI UX Pro Max** v2.13.0（`skill.json`） |
| 作者 / 许可 | NextLevelBuilder / MIT |
| 仓库 / 主页 | `github.com/nextlevelbuilder/ui-ux-pro-max-skill` / `uupm.cc` |
| 自称规模 | 79 UI 风格 · 192 调色板 · 74 字体搭配 · 119 UX 准则 · 25 图表类型 · 22 技术栈 |
| 安装方式（它自己的） | `npx ui-ux-pro-max-cli init --ai <platform>` |

**7 个 skill**（`.claude/skills/`，每个目录**自带 `scripts/` 与 `data/`**，是自包含的）：

| skill | 文件 / 字节 | 干什么 | 跟我们 |
|---|---|---|---|
| **`ui-ux-pro-max`** | 73 / **3.64 MB** | 主技能：可搜索知识库 + 设计系统生成 | ★ **值得要** |
| **`design-system`** | 27 / 0.19 MB | 三层令牌（primitive→semantic→component）、令牌校验脚本、幻灯片 | ★ 令牌架构部分有用 |
| `ui-styling` | 98 / **5.76 MB** | **shadcn/ui + Tailwind** 组件与 canvas 设计 | ⚠️ **与我们直接对冲**（见 §6） |
| `design` | 36 / 0.27 MB | 品牌识别 + logo 生成（调外部 AI 接口）+ CIP 物料 | 不是我们这条线 |
| `brand` | 18 / 0.09 MB | 品牌语气 / 视觉识别 / 资产校验 | 不是我们这条线 |
| `banner-design` | 2 / 0.01 MB | 社媒/广告 banner | 不是我们这条线 |
| `slides` | 6 / 0.02 MB | HTML 演示文稿 | 不是我们这条线 |
| **合计** | **260 / 9.99 MB** | | |

**它的引擎是真能跑的**（Python，本项目正好也是 Python）：

```powershell
python -X utf8 .uiux-skill-probe/src/ui-ux-pro-max/scripts/search.py "<query>" -d <domain>
# domain：style / color / chart / landing / product / ux / typography / icons / gsap / react / web / google-fonts
# 还有 --design-system（成套推荐）与 --variance/--motion/--density 三个 1–10 的旋钮
```

知识库规模（`data/`）：`styles.csv` 149 KB · `colors.csv` 38 KB · `typography.csv` 50 KB ·
`ux-guidelines.csv` 28 KB · `charts.csv` 23 KB · `icons.csv` 58 KB · `google-fonts.csv` 747 KB ·
`ui-reasoning.csv` 77 KB · `products.csv` 76 KB · `motion.csv` 15 KB …
（**22 个技术栈的 CSV 里没有"纯 HTML/CSS"** —— 最接近的是 `html-tailwind`，所以栈相关的建议对不上我们。）

**实测两条**（真跑出来的，不是读文档）：

1. `-d ux "text contrast accessibility"` → 第一条就是
   「**Color Contrast**：Minimum 4.5:1 ratio for normal text / 好例子 `#333` on white (7:1) / 坏例子 `#999` on white (2.8:1)」——
   跟我们刚做的对比度门是同一把尺子（互相印证）。
2. `-d chart "heatmap calendar"` → 给了几条**正好能用在我们 `SR-F1.5b` 上**的硬约束：
   「**calendar heatmap: 365 cells max per SVG**」「**不要只靠颜色**，格子里要印数值或符号 + 用纹理/标签」
   「少于 20 个格子就别画热力图（用柱子）」「键盘：聚焦露出格子数值」。
   —— 这几条和 workbench 的"状态不许只靠颜色"是同一条规矩的两种说法。

## 5. 三个"审美来源"现在的关系（别混用）

| | **workbench**（T-G26 装的） | **web-artifact-designer**（T-G26 装的） | **UI UX Pro Max**（仓库里这份） |
|---|---|---|---|
| 形态 | 39 个**锁死的**风格包之一 + token CSS | 反模式清单 + 质量清单 | **可搜索**的知识库（79 风格/192 色板） |
| 给的是 | **一个登记好的视觉体系**（值已定） | **别做成 AI 味**的判据 | **候选与理由**（要挑） |
| 用它做决定 | 本项目**已钉它当判据**（T-G26） | 写任何界面时的自查 | 查"这种情况业界怎么做" |
| 风险 | 它是 core-contract 包，组件状态要自己定 | 它的产出是"自包含 HTML 设计稿"，不是我们的多文件 app | **它会一次给 79 种风格 —— 选不好就变成"每块一个风格"** |

**一句话**：**workbench 定调、Pro Max 查证、web-artifact-designer 自查**。
Pro Max 是**参考书**，不是**风格决定器** —— 决定仍然由 workbench 判据 + 已登记的令牌表来做
（否则就会犯它自己警告的"默认三件套"和"每块不一样"的毛病）。

## 6. ⚠️ `ui-styling` 与本项目**直接对冲**

`ui-styling` 教的是 **shadcn/ui + Tailwind**（`scripts/shadcn_add.py` / `tailwind_config_gen.py`）。
而 T-G26 刚刚**记录在案**地答复过"要不要引 shadcn/ui"这个问题：**不引** ——
本项目「前端零依赖、无构建步骤」是既有约定（`docs/EXTENDING.md`），
`app.css` + `emptyState()/toast()/card` 已经是我们的组件层。

所以：**装 `ui-styling` 等于给自己留一个"下次写界面顺手用 Tailwind class"的入口** ——
那不是"多一个参考"，那是**方向相反的建议**。如果哪天要它，得先做一个产品决定（换前端技术栈）。

## 7. 三条可选路线 + 我的建议（**等你点头，本次一条都没做**）

| 路线 | 做什么 | 代价 / 风险 |
|---|---|---|
| **A. 不装，按需读** | 保持现状：`.uiux-skill-probe/` 已在仓库里（gitignored），要查时我直接跑它的 `search.py` | 零代价；但"我下次会不会想起来用它"没有保障（skill 没进目录就不会被自动加载） |
| **B. 只装 1–2 个**（推荐） | 把 `ui-ux-pro-max`（+可选 `design-system`）复制进 `~/.dsh/skills/`，**不装 `ui-styling`** 与 4 个品牌/演示类 | 3.6 MB / 73 文件；它自带的 `scripts/` 会一起进（自包含），但文档里写的 `${CLAUDE_PLUGIN_ROOT}` 路径在 DSH 下无效，要用"相对 SKILL.md 的 scripts/ 路径"那套说法 |
| **C. 跑它自己的安装器** | `npx ui-ux-pro-max-cli init --ai claude`（缓存修好后能跑） | 它会往**当前项目**写 `.claude/`（本仓库没忽略 `.claude/`）→ 会污染 `git status`；且它按 Claude Code 的目录约定，不是 DSH 的 |

**我的建议是 B 里的 `ui-ux-pro-max` 一个**，理由：它是这次三份材料里唯一**能查证**的
（"这种数据该用什么图、什么颜色对色盲不友好"），而 workbench 已经解决了"调子"的问题。
`design-system` 可以不要 —— 它的有用部分（三层令牌）我们已经在做，且它的校验脚本是 Node 写的，
把外部脚本接进门禁会引入一个**我们无法固定版本**的依赖（见 §8）。

## 8. 一条硬约束：**门禁不许依赖 `.uiux-skill-probe/`**

那份东西是：**gitignored**（不进仓库）、**自带 `.git`**（版本是它自己的）、**没有 pin**。
所以它的任何脚本（比如 `design-system/scripts/validate-tokens.cjs`、
`html-token-validator.py`）**只能当参考读**，不能接进 `run_gates.py` ——
否则换台机器、或者谁 gitignore 生效删了它，门禁就变成一个"在别人机器上不存在"的检查。

这正是本卡**自己写** `tools/contrast_audit.py` 而不是复用它的原因。
（如果以后真要用它的某个校验器，正确做法是**先把那份代码 pin 下来进仓库**，再说接门禁。）

```powershell
git ls-remote https://github.com/xulelenlp/dsh-web-artifact-designer   # → schannel SEC_E_NO_CREDENTIALS
curl.exe -sS https://registry.npmjs.org/sheleg-design-skill            # → curl (35) schannel …

# 仓库里那份技能包
Get-Content .uiux-skill-probe/skill.json -Raw
Get-ChildItem .uiux-skill-probe/.claude/skills -Directory | ForEach-Object {
  $f = Get-ChildItem $_.FullName -Recurse -File
  "{0,-16} {1,5} 文件 {2,10} 字节" -f $_.Name, $f.Count, ($f | Measure-Object Length -Sum).Sum }

# 它的搜索引擎（真能跑）

python -X utf8 .uiux-skill-probe/src/ui-ux-pro-max/scripts/search.py "heatmap calendar" -d chart -n 2
```
