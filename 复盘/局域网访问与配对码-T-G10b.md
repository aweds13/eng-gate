## 一、这一版做了什么

| 做的东西 | 落在哪 |
|---|---|
| **开关**：默认关；`python tools/serve.py --lan` 或 `config.toml` 的 `[net] allow_lan = true` | `tools/serve.py`、`src/timeflow/app/main.py`（窗口模式也认）、`config.py` 的 `NetConfig` |
| **门**：非本机请求必须带 `X-Timeflow-Pair`，否则 401 + 原话；本机（回环）免检 | `src/timeflow/core/lan.py`（判定是**纯函数**）+ `api/app.py` 的 `lan_gate` 中间件 |
| **配对码**：6 位数字，存本机库（重启不变、可换一个）；★ **只在本机响应里出现** | `core/lan.py` + `GET/PUT /api/settings/lan` + `POST /api/lan/pair` |
| **界面**：没配对时是**整页的配对墙**（说清"码在哪、为什么看不到"）+ 设置页一节 | `src/web/index.html`（配对墙 / `askPair` / 设置页「局域网访问」） |
| **起服务时当面说清代价**：地址 + 配对码 + "同一 WiFi 下别的设备也可能访问到" | `core/lan.banner()`（一处措辞） |

**电脑侧的老行为一个都没动**：默认关时中间件是**空操作**（有专门的用例钉住"关着 = 与以前一模一样"）。

## 二、四个设计选择（都是被"诚实"逼出来的）

### 1. 为什么是**启动期**开关，而不是设置页里的一个按钮

"开着局域网" = 服务绑 `0.0.0.0`。而**绑哪个地址是进程起来那一刻定下来的**，运行期改不了。
放一个能点的按钮就会出现"点了、看起来开了、其实没开"——那比没有更糟。
所以开关只有两个：`--lan`（临时开一次）或 `config.toml`（长期开），改完**重启**。
设置页照实说这件事（`how_to_change`），并把"配置里写的"和"这台服务实际"分成两个字段报 ——
所以 `allow_lan=true` 但你用 `uvicorn` 手起在回环上时，页面会如实显示"这台服务没开"。

### 2. 为什么"配对过 = 当作本机页面"

原来有一道 `require_local_origin`（跨站来源 403），防的是"随便一个网页让本机去开文件/改设置"。
现在多了一类合法来源：**你在同一 WiFi 下的手机**。判据不该是"来源地址是不是回环"，
而是"**你是不是本人**"—— 而配对码已经回答了这个问题（跨站页面发不出配对码：它拿不到 localStorage 里的码）。
所以：**配对过 → 当作本机页面**（`request.state.paired`）；没配对 → 401（门）/ 403（守卫），
两种提示措辞不同（一个说去配对，一个说只允许本机）。

### 3. ★ 为什么配对码**只在本机显示**

这是这道门的底线：**局域网设备能读数据，读不到"钥匙"本身**。
要是 `GET /api/settings/lan` 把码发给手机，那"配一次"就能把码传出去，门等于没有。
所以 `status()` 里 `code` 只在回环请求里非空（`code_visible` 同步说明），
`PUT`（换码）也只允许回环 —— 两条都有用例钉住，包括"包里/别处都不许漏"。

### 4. 为什么静态壳免检 + 6 位数字 + 失败节流

- **静态壳免检**：手机第一次打开必须先能拿到页面，否则连"输入配对码"这一页都打不开（自己把自己锁外面）。
  代价是"页面代码本身在同一 WiFi 下可见"—— 那里面没有你的数据，可接受。
- **6 位数字**：手机上敲得动（配对是**手敲一次**的操作，不是每天用的）。
  代价是空间只有 100 万种，所以配 **失败节流**（连续错 20 次锁 5 分钟，按来源锁，不是整台服务瘫掉）。
- 比较用 `hmac.compare_digest`：只是别让耗时泄漏信息，不是"加密"。

## 三、诚实边界（界面上、横幅里、代码里都写着）

- **只在同一个 WiFi 里管用**，不涉及公网（原文把"出门实时"列为后置）。
- **配对码不是加密**：这条路上是明文 HTTP，同 WiFi 能抓包的人抓得到码 —— 这个方案防的是
  **"同一 WiFi 下别人随手扫到你的地址"**，不是防"同网段的攻击者"。要防那个得 HTTPS + 证书，
  对一个单机个人工具不划算（也不是这一版的范围）。
- **没有账号体系**（N16 本地优先、隐私最小）：配对码就是这道门的全部，所以"别念给别人"。
- **防火墙**：真实机器上第一次绑非回环地址，Windows 大概率弹一次防火墙允许框 ——
  那是系统在问"允许别人连进来吗"，**允许**才能用（这条只能在你的机器上遇到，我这边环境没有这个交互）。

## 四、怎么验的（这次是**真的从局域网地址访问**）

本环境没有第二台设备，但有一个更好的办法：**拿"本机局域网 IP"当"别人"** ——
服务看到的来源地址就不是回环了，走的就是手机那条路。

**单元/接口测试**（`tests/test_lan_pairing_line.py`，20 条）：

- **默认关 = 与以前一模一样**（配置默认 false、服务不装门、局域网设备照样能读）；
- 门是**真值表**：回环免检 / 静态壳 + `/api/lan/pair` 免检 / 其余要码 / 错码 401 / 锁着时连对码也拒；
- **配对码只在本机响应里出现**（局域网设备拿到的是空串，且 `code_visible=false`；
  `/api/health`、`/api/config` 里也搜不到那个码）；
- 只有那台电脑能换码（手机调 → 403 带原话；换完**旧码立刻失效**）；
- 配对过的设备能改那些"本机设置"接口（`PUT /api/settings/ai` 演示），**没配对的先 401**；
- 默认关时跨站来源仍旧 403（老行为没被改掉）；
- `tools/serve.py --lan` **真的**绑 `0.0.0.0` 且那个 app **真的**装了门（把 `uvicorn.run` 换掉验的，
  不是"看它打印了什么"）；`--host 0.0.0.0` 不带 `--lan` 会被拒（不许绕过开关）。

**假 DOM 探针**「setting·局域网配对 1/1」：设置页那一节真渲染；
再把 fetch 换成"一律回 401 说没配对"→ 整页**真的变成配对墙**；换回来 → 墙**自己撤了**；
最后把"非本机看不到码"那一版喂进去 → 码不显示、`换一个` 按钮也不出现（反证）。

**真机自检**（`tools/web_live_check.py`，新增 7 条，共 **56** 条）：真起一个绑 `0.0.0.0` 的服务，
从**本机局域网地址**（这次是 `172.18.179.162:8531`）访问它 ——
静态壳 200 / 没配对 401 带原话 / 错码 401 / 对码 200 / 配对后能读数据 / **配对码没通过局域网漏出去** /
本机自己不受影响。连不上自己的局域网地址时**明确跳过**（打印 `[SKIP]` + 原因），不谎报通过。

**做不到的**：真手机（浏览器实现、触屏输入、iOS 的 PWA 限制）、真机防火墙弹框、
以及"同 WiFi 下别人的设备能不能连"（那要第二台设备）。

## 五、请你点一次（三类机器上各一遍）

1. **电脑上**：`python tools/serve.py --lan` → 应当看到 `[局域网]` 那几行（地址 + 配对码 + 代价），
   浏览器打开 `http://127.0.0.1:8520` 照旧能用；设置页「数据与同步 → 局域网访问」里应当能看到
   地址与**配对码**、能「换一个」。
2. **同一个 WiFi 下的手机**：用手机浏览器打开电脑上打印的那个地址（`http://192.168.x.y:8520`）→
   应当**先弹出/显示配对墙**（而不是一片空白）→ 输入电脑上的配对码 → 成功后整个应用可用。
   手机上再打开设置页：「局域网访问」那一节应当**看不到配对码**（写着"这是故意的"）、也没有「换一个」。
3. **关掉**：去掉 `--lan` 再起一次 → 手机上那个地址应当连不上（本机一切照旧）。

> 提醒：手机连的是**明文 HTTP**，别在公共 WiFi 上开这个开关。

## 七、校园网场景（T-G10c，用户 2026-09-23 说"我用的是校园网"）

**这一条改变了 ② 的前提**，所以单开一节（并落成一张卡 `T-G10c`）。

### 问题

1. **校园网 / 公共 WiFi 常开「客户端隔离」（AP isolation）**：看着连的是同一个 WiFi，
   但**设备之间互相不通** → 手机根本打不到电脑的地址。这是网络策略，不是软件 bug。
2. **风险也更大**：校园网常常是一个大子网（几千台设备），"同一网段别人也能扫到这个地址"
   从"室友"变成"整栋楼"；而且这条路上是明文 HTTP。**校园网按公共网络对待。**

### 做了什么（三件，都不改默认行为）

1. **把话说在明处**：`status().note`（设置页显示）、`banner()`（起服务时打印）、
   合约与规格里都主动提**校园网 / 客户端隔离**，并给"按公共网络对待：要用才开、用完就关"。
   之前只写"只在同一个 WiFi 里管用"——**在校园网里这句话是会误导人的**（同一个 WiFi 也可能不通）。
2. **排查顺序改成热点优先**（`selfcheck().hint`）：
   ① 电脑开「移动热点」让手机连它（地址通常 `192.168.137.1`；自己开的小网、没有隔离，最省事）；
   ② 手机开热点 / USB 共享，电脑连它（纯本地流量，不花流量费）；
   ③ 都不方便就用**「离线记」**（手机记 → 导文件 → 电脑导入，不需要两台设备互相看见）。
3. **本机自检**（`POST /api/lan/selfcheck` + 设置页一颗按钮）：把"手机为什么连不上"里
   **能在电脑上查的那一半**查出来 —— 这台服务开没开局域网、有哪些局域网地址、
   **从这台机器自己能不能经那些地址访问自己**（能 ≈ 地址在、绑定对、防火墙至少没拦本机自连）。
   结果连同**它能证明什么、不能证明什么**（`caveat`）一起显示，不自己编结论。

### 诚实边界（这一节的重点）

- **客户端隔离查不出来**：那是"手机 → 电脑"的事，在电脑上无论怎么试都试不出来 ——
  所以自检**不假装能判**，只给排查顺序。这是"报事实、不报结论"那条规矩的又一处应用。
- **自检的"可达"是必要条件、不是充分条件**：它只证明这台机器经局域网地址访问自己通了；
  真机上防火墙也可能"允许本机自连、拦别的机器"（那种情况自检会说 OK 但手机还是连不上）。
  所以 `caveat` 写在返回里、也显示在界面上。
- **校园网下推荐热点**，不是因为热点"更好"，而是因为**它是唯一能自己保证"两台设备真的互通"的做法**。

### 验证

- 单测 +4（`tests/test_lan_pairing_line.py` 共 24 条）：自检的三种口径（通了 / 不通 / 没开 --lan）、
  排查顺序里**热点排在校园网前面**、接口形状齐全、设置页那段边界主动提校园网；
- 探针「setting·局域网配对」加断言：排查顺序与自检按钮真渲染出来；
- 真机自检 +2（共 **58** 条）：在**真的绑了 0.0.0.0** 的服务上，自检必须报
  `self_reachable = true` 且地址非空，并把校园网/热点写进排查顺序。

### 你那边可以马上试的（不用等什么）

1. 电脑：设置 → 网络和 Internet → **移动热点** → 打开；手机连它。
2. 电脑：`python tools/serve.py --lan` → 记下打印的 `[局域网]` 地址（热点下通常是 `192.168.137.1`）。
3. 手机浏览器打开 `http://192.168.137.1:8520` → 出现配对墙 → 输入电脑上的配对码。
4. 连不上就看设置页那颗**「网络自检」**：它至少能告诉你"是电脑这边（防火墙/没开 --lan）"
   还是"网络那边（校园网隔离）"。前者能修，后者换热点。**防火墙**：Windows 把校园网当"公用网络"，
   有时**不弹允许框、直接拦** —— 去「允许应用通过防火墙」把 Python 的**公用**那一列也勾上。
