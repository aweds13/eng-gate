# 卡 A302 —— 谱系树：从 git 历史重建「谁接着谁」，按功能区切

任务号 T-AG416。树 `.wt/A302`，分支 `card/A302`。

## 为什么

用户要的是「从零开始建起来的前置逻辑」，并明确：**前置就是 git** ——
每张卡收口是一笔提交，父提交就是上一张卡，所以推进顺序本来就记在提交链里，
不需要往台账里补猜 `depends`。

实测：近 400 笔提交里 **134 笔**能通过任务号（`T-AG…`/`T-G…`）对到卡池；
其余 238 笔的任务号不在卡池（老账没登记成卡）—— 这类必须**如实显示 task 号或
subject 摘要**，不许猜成卡。

## 要交付什么

1. **`tools/wb_tree.py`（只读，标准库）**
   - 输入：`git log --format=%h%x09%p%x09%ad%x09%s --date=short` + `docs/workbacklog.toml`。
   - 节点 = 提交；`card` = 用 subject 里的 `T-[A-Z]+\d+` 查卡池 `task` 得到，
     查不到就 `card=null`（显示 task 号），**不推断**。
   - 边：`parent`（真实 git 父链）+ `depends`（卡池里的显式前置，跨链，标 `explicit`）。
   - `area`：按该提交改动文件的前缀归类（`git show --name-only`），映射表写文件头：
     面板 / 号池 / 技能 / 台账 / 复盘 / 门禁 / 服务 / 其它。
   - 输出 `--json`：`{nodes:[{sha,card,task,title,date,area,parents,children}], areas:[{name,count,roots}], orphans:[{sha,task,why}]}`。
   - 文本模式：`--area 面板 --limit 50`，缩进树，深度 >6 打 `…`；`--since 2026-10-01`。
   - 环/断链：父提交不在窗口内 ⇒ 记 `cut` 边界（不递归爆栈），并在尾部报「窗口截断 N 处」。
2. **面板**：只读路由 `/dsh-panel/card-tree`（转 `wb_tree.py --json`），工具箱加「谱系」页：
   按功能区折叠，每区先给「N 笔 / 起点 M」，展开才列（渐进披露）；点节点看
   `sha + 卡号 + 标题 + 改动文件数`；`card=null` 的节点标「未登记」。
3. **测试** `tests/test_wb_tree.py`：父链正确、任务号映射到卡、未登记如实为空、
   区映射、`--area` 过滤、窗口截断计数、JSON 形状；钉子：删 `orphans` 必红。

## 验收命令

```
python -X utf8 tools/wb_tree.py --area 面板 --limit 20
python -X utf8 tools/wb_tree.py --json | head -20
pytest tests/test_wb_tree.py -q
ruff check tools/wb_tree.py tests/test_wb_tree.py tools/dsh_panel.py
python -X utf8 tools/dsh_panel.py --check
```
