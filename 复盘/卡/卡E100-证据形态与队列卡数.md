## 要解决的问题（两件，都不是「再补一个 if」）

1. **证据指针的形态没人管，红在离现场很远的地方**。`tools/pool/stage_card.py` 的
   `~_as_assertion()` 只做一件事：带七种种类前缀就原样保留、否则补 `file:`。
   于是 `--evidence 'test:tests/test_pool_limits.py::test_pin_24…'` 这种**手顺**写法
   会原样进台账，而读侧 `scripts/audit_progress.py` 的 `test:` 分支是
   `p = ROOT / "tests" / fname`（**前缀由审计补**）⇒ 去找 tests/tests/test_pool_limits.py（前缀叠了两层），
   必红；`tools/evidence_map.py:69-75` 的倒排索引也是同一条 `"tests/" + fname`。
   实测（主树 `gates/diag/_e100_probe.py`）：`test:tests/test_pool_limits.py::test_pin_24…`
   求值回 `(False, '测试文件 tests/test_pool_limits.py')`，写成裸文件名才回 `True`。
   ⇒ 两种正确形态并存、坏形态**写得进去**、红要在落地链 ③″ 或审计时才炸。
2. **立卡那一笔是唯一不重算派生文档的台账写入**。`tools/pool/ledger.py` 的
   `~_commit_backlog()` 只 `git add` 台账那一份。E98 立卡（`36eb59f3`）就是这么来的
   ⇒ `docs/subsystems/pool/README.md` 的「队列卡数 | 345 张」慢一拍 ⇒ 下一张卡落地的腿②
   当场报红（`[FAIL] 第 87 行：应为 '| 队列卡数 | 346 张（333 done / 13 pending） |'`），
   只好单开一笔 `796ea840 fix(docs): 队列卡数跟上 E98 立卡` 补上。
   E99 立卡是**手工**补的（`39f4506f` 的正文自己写着「立卡笔顺手重算…」）——
   手工补等于没修。

## 判据（5 条）

1. **写侧归一 `test:` 的形态**（`tools/pool/stage_card.py`）：
   `~_as_assertion()` 对 `test:` 指针必须把文件名归成审计要的那一份 ——
   剥前导 `.`/`、剥 `tests/` 前缀、反斜杠换正斜杠；幂等（归一两次与一次同字节）。
   **别的六种种类一个字节都不许动**（`file:` / `text:` 原样）。
   钉子（`tests/test_stage_card_evidence_shape.py`）：四种坏形态归一成同一个结果；
   file:tests/x.py 与 text:tools/x.py::图案例 原样（这两串是**种类**示例，不指向真文件）。
2. **写盘之前就判死**（同一文件）：新给的 `test:` 指针在写任何文件之前求值 ——
   测试文件不在这棵树里、或用例名不在那份文件里 ⇒ **停手退 4**，逐条点名
   「`test:{fname} ⇒ tests/{fname} 不存在`」/「`用例 {bare} 不在 {fname} 里`」，
   一个字节都不写。判据复用 `tools/wb_invariants.py` 的 `case_name` / `defines_case`
   （那是「用例级存在性判据的唯一真源」）—— **不许**在 stage_card 里写第二份 `def\s+` 正则。
   钉子：缺文件退 4 且台账/片段都没写；缺用例退 4 且点名那个用例；
   `test:x.py::case[param]` 参数化形态放行；源文件里必须出现 `wb_invariants` 且没有第二份正则。
3. **carried 指针只归一、不判死**：台账里**已经记着**的证据（片段模式合并进来的那份）
   可能指向这批卡域之外的文件 —— 归一形态，但**不**因为它在当前树里找不到就让立卡失败。
   钉子：台账里先写一条带 `tests/` 前缀的 test 指针 ⇒ 新片段里是
   `test:whatever.py::test_x`，且退出码 0（不是 4）。
4. **立卡那一笔顺手把队列卡数跟上**（`tools/pool/ledger.py`）：`add_card(commit=True)`
   在**锁里**、写台账之后、提交之前，若这棵树里既有 `scripts/gen_pool_readme.py` 又有
   `docs/subsystems/pool/README.md` ⇒ 写模式跑一次生成器、再跑一次 `
--check` 自检，
   两份**同笔提交**；提交信息多一行 `Docs:`（读 log 不用猜）。
   四条「不带」的口径，每条都要**打出来**：
   (a) 没有生成器 / 没有 README（最小树、假仓）⇒ 只提交台账；
   (b) README **本来就**有未提交改动 ⇒ 不重算、不带上（那是别人验到一半的改动，
       替他提交等于替他签字）；
   (c) 生成器失败 ⇒ 台账**照提交**（卡不能丢），README 还原原字节，并点名退码；
   (d) 写完 `--check` 判不一致 ⇒ 不提交这份结果、还原原字节。
   不带 ``--commit`` 时**一次都不叫**生成器，只提示提交时记得重算。
   钉子（`tests/test_ledger_queue_counts.py`，12 条）：同笔提交 / 卡数已变且是写完台账之后的树 /
   生成器被叫两次（write 然后 check）/ 无生成器只提交台账且点名两个路径 / 无 README 同理 /
   别人的脏 README 既不重算也不带上且说明原因 / 生成器坏 ⇒ 卡仍在台账里且 README 不变 /
   自检红 ⇒ README 还原 / 不带 --commit ⇒ 生成器零调用 / 提交信息点名 README。
5. **反向变异 ≥4 条**（`gates/diag/_rev_E100.py`，落在主树、逐条真改真跑真还原并记 sha256）：
   A 去掉 `tests/` 归一（把 `_bare_test_file` 改成恒等）/ B 去掉写盘前判死（恒回 []）/
   C 立卡笔不叫生成器 / D 立卡笔把 README 不带进提交（返回 None）/
   E 「别人脏 README」也照重算并带上。每条必须让对应钉子红；还原后 sha256 与基线一致。
