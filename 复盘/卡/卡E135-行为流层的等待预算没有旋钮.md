## 判据（6 条，逐条可执行）

### 判据 1 · 预算旋钮只乘在等待预算上，不改任何断言

新增一个**独立可测**的模块 tools/tf_wait_budget.mjs（计划建）（纯函数、无副作用、不碰浏览器），导出：
- `WAIT_SCALE_ENV = 'TF_UI_FLOW_WAIT_SCALE'`；
- `parseWaitScale(raw)`：`raw` 为空 / 坏值 / `NaN` / 负数 / `0` ⇒ 回 `1`；合法区间 **`[1, 10]`**，超出上界**封顶到 10**（不许「等于永不超时」）；
- `waitScale()`：读 env 后转 `parseWaitScale()`；
- `scaleMs(ms, scale)`：回 `Math.round(ms * scale)`。

`tools/ui_flow_check.mjs` 只在三个原语里用它：`waitToast` / `waitToastWhere` / `waitFor` 的 `ms` 在函数头上乘一次（**调用点一个都不改**）。

### 判据 2 · 默认值一个都不许动

不设 env 时 `waitScale() === 1`，三个原语的默认仍是 12000 / 12000 / 5000（逐字不变）⇒ 本机行为与现在**完全一致**。

### 判据 3 · 仍然是「等到就绪就返回」的轮询，不是固定 sleep

这三个原语的主体**不许**引入新的固定等待：`while (Date.now() - t0 < ms)` 的循环结构、`sleep(100)` / `sleep(step)` 的轮询粒度、`ok: true` 就立刻返回 —— 全部照旧。卡 092 的两条钉子（`test_wait_primitives_poll_instead_of_asserting_once` 与 `test_toast_assertions_wait_for_the_whole_predicate`）**逐字不动且必须绿**。

### 判据 4 · 生效的预算必须自报，不许悄悄变宽

当 `waitScale() !== 1` 时，`main()` 在开跑前打一行：`[note] 等待预算 ×{scale}（TF_UI_FLOW_WAIT_SCALE）—— 判据强度不变，只是等得更久`。**不设 env 时一个字都不打**（默认输出零变化，否则黄金层 / 指纹类判据会被这行噪声碰）。
