# 卡 G1 —— 技能-工具对账机器化：133 处命令引用，没有一处被机器核过

> 台账号 T-AG456 · 分区 G（软工技能）· 来源：主控 2026-10-24 巡检

## 现在疼在哪（实测）

`tests/test_check_skills.py` 只查**结构**：`SKILL.md` ≤120 行、流程级 `###` ≤3、
结果项指针指向存在的脚本、`NOTES.md` 三段、frontmatter、目录名。

它**不查**技能正文里那些命令还在不在。实测：`skills/**/*.md` 里共有 **133 处**
`python -X utf8 tools/<x>.py …` 引用，涉及 **28 个工具**，无一处被机器核过。
参数随工具演进改名/退役时，技能照旧写着旧写法 —— 只有人照着敲、被 argparse 拒单才发现。

## 目标

技能里的命令与参数**能被机器对账**：工具不存在、参数不存在 ⇒ 点名 `文件:行`；
判不出来（比如动态拼的命令）⇒ 报 `not verified`，**不许猜成通过**。

## 判据

1. **扫描口径**：只扫 `skills/**/*.md` 的围栏代码块与行内反引号里的
   `python -X utf8 tools/<x>.py <args>`；`<x>` 必须落在 `tools/` 下。
2. **两项核对**：① `tools/<x>.py` 存在；② 每个 `--flag`（含 `--flag=value` 取等号前）
   在该工具源码里以 `add_argument("--flag"` 或 `"--flag"` 出现。
3. **判不出来要明说**：一行里出现 `<卡>`、`$VAR`、`|`、`>` 这类占位/重定向时，
   只核能核的部分，其余记 `not verified` 并计入汇总（不许静默丢弃）。
4. **豁免要写理由**：需要放行的条目放 `tools/check_skills_claims.py` 顶部的
   `EXEMPT` 表（`"路径:行" -> 理由`），空理由算红。
5. **退出码**：`--check` 有对不上 ⇒ 退 1 并逐条打印；全绿退 0 打印一行计数。
6. **钉子**（新建 `tests/test_check_skills_claims.py`，≥4 条）：好树全绿 /
   工具不存在点名 / 参数不存在点名 / 占位记 not verified 不算绿 / 豁免空理由算红。
7. **接进 pytest**（pytest 那道门会带它跑），不改门表、不改档位。

## 交付

`tools/check_skills_claims.py`（CLI：`--check` / `--json`）、`tests/test_check_skills_claims.py`。
验收：`python -X utf8 tools/check_skills_claims.py --check` 在**当前主树**上给出
真实清单（对不上的逐条点名，能核的全绿），并把两条计数写进回话。

## 不许做

- 不许为了让门变绿去改技能正文（那是卡 G2 的活）；本卡**只造尺子**。
- 不许把「判不出来」当通过；不许自动豁免。
