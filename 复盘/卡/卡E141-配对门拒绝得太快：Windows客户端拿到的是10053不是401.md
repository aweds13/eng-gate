# 卡 E141 · 配对门拒绝得太快：Windows 客户端拿到的是 10053，不是 401

> 台账号 T-AG650｜分区 E（门禁与可信度）｜树 .wt/E141｜层 判据层｜基准 63572c7a｜depends 无
> 依据：GitHub Actions 上 engineering 全量门禁 v12（head `d2ccf596`）只有两道门红，其中 `web_live` 的红原文是 `[FAIL] 局域网：有一步没等到（POST http://10.1.0.8:51323/api/sync/import）★ 等了 60 秒没等到（ConnectionAbortedError: [WinError 10053] An established connection was aborted by the software in your host machine）`，而同一刻服务端日志记的是 `"path":"/api/sync/import","status":401` —— 服务端**回了 401**，客户端**没读到**。
> 行号按 2026-11-19 主树 `63572c7a` 现场复核：`src/timeflow/api/app.py` 中间件在 `:302-323`，`src/timeflow/core/lan.py` 的 `def gate(` 在 `:196`、`def check_pair(` 在 `:228`。

## 要解决的问题（逐条实测，不是推测）

### 问题 1 · 配对门在拒绝前不读请求体，直接回 401 并让连接关掉
`src/timeflow/api/app.py:303` 的 `@app.middleware("http") async def lan_gate(request: Request, call_next: Any) -> Any:` 里，拒绝分支原文：

```text
            if not decision["ok"]:
                return JSONResponse(
                    {"detail": str(decision.get("detail") or "")},
                    status_code=int(decision["status"]),
                )
```

它**没有** `await request.body()`（`grep -n 'body()' -r src/timeflow` 在中间件里零命中）。放行分支紧接着一句 `return await call_next(request)`（`:323`），路由层才去读 body。

### 问题 2 · 这就是 10053 的成因（规范依据 + 本机四组探针）
HTTP/1.1 规范 [RFC 9112](https://www.rfc-editor.org/rfc/rfc9112.html)（连接管理）原文：`If a server performs an immediate close of a TCP connection, there is a significant risk that the client will not be able to read the last HTTP response. … the reset packet might erase the client's unacknowledged input buffers before they can be read and interpreted by the client's HTTP parser.` 同段给的解法是「先半关写端，再继续读到对端关」。
本机四组读数（脚本全在 `gates/diag/` 下，不进提交面）：

| 探针 | 场景 | 读数 |
|---|---|---|
| `gates/diag/_tmp/_probe_drain_vs_rst.py` | 最小 Starlette app，handler 不读 body 就回 401 | `0.003MB -> HTTP 401` / `1MB -> HTTP 401` / `8MB -> EXC ConnectionAbortedError: [WinError 10053]` / `16MB -> 同 EXC`（阈值在 1–8 MB 之间） |
| 同上 `drain` 模式 | handler 先 `await request.body()` 再回 401 | 四档全 `HTTP 401`（8MB 0.01s / 16MB 0.02s） |
| `gates/diag/_tmp/_probe_bindlan_10053.py` | **真 app**（`create_app(..., allow_lan=True)`）+ 裸 socket **bind 到本机局域网地址**再连 + 每 200 B 一包慢慢发 | `drain=False -> EXC ConnectionAbortedError: [WinError 10053]`；`drain=True -> HTTP/1.1 401 Unauthorized`；两次服务端都记 `status 401` |
| `gates/diag/_tmp/_probe_asgi_drain.py` | 不起真服务，`httpx.ASGITransport(app=app, client=PHONE)` + 生成器 body（10 块，每块记账） | `drain=False -> status=401 chunks_eaten=0`；`drain=True -> status=401 chunks_eaten=10` |

⇒ 判定：**只要客户端在服务端关闭连接时还没把 body 发完，Windows 客户端就拿到 10053 而不是 401**；把 body 读完（哪怕是分块丢弃、不缓存）就恢复 `401 Unauthorized`。

### 问题 3 · 回环地址复现不出来，必须绑局域网地址
`gates/diag/_tmp/_probe_loopback_10053.py`：打 `127.0.0.1` 时 `drain=False -> HTTP/1.1 422 Unprocessable Content` —— 因为 `src/timeflow/core/lan.py:65 def is_loopback(host)` 把回环放行，请求进了路由层，FastAPI 自己把 body 读完，两端行为一致。**判据不能写在回环上**。

### 问题 4 · 这不是「包体太大」
真手机包体实测 `body bytes 2917`（`gates/diag/_tmp/_probe_pack_size.py`，`phone-lan.json` 3181 B）；且真 app 对 8 MB / 16 MB 一次性发送都正常回 401。⇒ runner 上那次是**发送节奏被挤慢**（同一台机器上 22 道门并行），不是尺寸。

### 问题 5 · 卡 E85 只修了客户端侧的措辞，服务端这条路还在
`tests/test_web_live_read_failure_is_not_401.py` 文件头原文写着「现场那一趟的真正成因没有复现出来……本文件只保证『下次发生时门说的是实话』」，并且明文不许改 `src/timeflow/`。那张卡把「没读到响应」与「服务端没回 401」分开了；**本卡要修的是服务端自己**（E85 判据一条不动）。

## 判据（7 条，逐条可执行）

### 判据 1 · 拒绝之前先分块读完请求体，有界、不缓存
`lan_gate` 的拒绝分支（`if not decision["ok"]:` 之内、`return JSONResponse(...)` 之前）加一段：只对 `POST` / `PUT` / `PATCH` / `DELETE` 生效；用 `async for _ in request.stream(): pass` **分块丢弃**（不许 `await request.body()` 把整块收进内存 —— 服务端没有 body 上限）；整段包在 `asyncio.wait_for(..., 上限秒数)` 里，任何异常都吞掉后继续走原来的 `return`。上限写成模块级常量（建议 `LAN_DRAIN_SECONDS = 2.0`），并与 `lan.py` 的既有常量分开命名。

### 判据 2 · 判定一个字不改
`src/timeflow/core/lan.py:196 def gate(...)` 的五个分支（loopback 放行 / `is_static(path) or path == PAIR_PATH` 放行 / 锁定 ⇒ 429 / 配对通过 ⇒ paired / 否则 401）**一行不动**；401 的 `detail` 原文（`这台设备还没和电脑配对：请在那台电脑的「设置 → 局域网访问」里看配对码…`）与 429 的 `detail` 一字不改；状态码不变。drain 失败（超时 / 客户端半路断开）**不许**改变任何判定，也不许新增响应字段。

### 判据 3 · 放行分支不许 drain
放行（`decision["ok"]` 为真）时直接 `return await call_next(request)`，路由层自己去读 body —— 提前 drain 会把 body 吃掉，`POST /api/sync/import` 会变成空 payload。判据要能咬住这一点（见判据 4 第 2 条）。

### 判据 4 · 新文件 `tests/test_lan_gate_drains_before_refusing.py`（E85 那份一个字不改）
至少四条 `def test_`：
1. `test_unpaired_upload_refuses_only_after_the_body_is_read` —— `httpx.ASGITransport(app=create_app(tmpdb, allow_lan=True), client=("192.168.1.50", 51234))` + 生成器 body（10 块 × 300 B，每块记一笔）；`POST /api/sync/import` ⇒ `status_code == 401` **且** 记账条数 == 10（改前是 0，见问题 2 表最后一行）。
2. `test_paired_upload_still_receives_the_whole_body` —— 同一夹具，带正确配对码（`X-Timeflow-Pair`）`POST /api/sync/import` ⇒ 不是 401，且服务端确实拿到了 payload（断言合并/入库的既有行为，不许只断言「不是 401」）。
3. `test_locked_device_is_still_429_and_still_drained` —— 连错到锁定后仍回 429、`detail` 不出现新字段，且 body 已被读完（同第 1 条的量法）。

## 不许做

- 不许改 `src/timeflow/core/lan.py` 的任何判定（`gate` / `check_pair` / `locked` / `verify` / 常量）—— 那是纯函数真值表，改它等于改判据。

- 不许用 `await request.body()` 把整块收进内存再丢（判据 1）；不许无界等待。
- 不许改 `tests/test_web_live_read_failure_is_not_401.py` 的 8 条断言（只准改第 9 行描述的时态）。
