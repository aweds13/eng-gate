# 卡 E53 —— 文档门禁的基线在卡树采、在主树判（两侧不对称）

> 台账号：**T-AG503** ｜ 树：`.wt/E53` ｜ 层：门禁层 ｜ 风险：低（改判据扫描口径，不改数字）

## 1. 症状（实测，不是推测）

同一 HEAD、同一份基线，换棵树结论相反：

| 树 | `scripts/check_docs.py` 读数 | 结论 |
|---|---|---|
| 主树 | 死指针 **363**（基线 343，+20）、superseded **6**（基线 5，+1） | `CHECK_DOCS: 死指针 … +20` ⇒ **红** |
| `.wt/E49` | superseded 5（+0）、无 ratchet 抱怨 | **绿** |

今天早先落地的 E44 / E45 / E48 都能过全量门禁 ⇒ 那时两侧读数还一致。现在不一致了，
且主树红会挡住**在主树跑的门禁**（落地链在卡树跑，暂时不受影响）。

## 2. 真因（已定位到机制）

1. `docs/doc-debt-baseline.toml` 头部写着 `生成时间：2026-10-25 15:07:51` / `task = "T-AG493"`
   —— 那是卡 E39 落地时写的，判据当时跑在**卡树** `.wt/E39`。
2. `scripts/check_docs.py` 扫 `.md` 用 `base.rglob("*.md")`（`scripts/check_docs.py:231`），
   **不问 git 是否跟踪**；而**目标**侧有 `git check-ignore` 把 gitignored 产物记 `skip`
   （`scripts/check_docs.py:444` 的 `ignored()`、`:523` 的调用点）。
3. 主树 `复盘/` 下有**没入库的速查文档**（例：`复盘/DSH插件-点名仓深读-dsh-web.md`，
   26142 字节，`git log` 无记录、`git ls-files` 不认）。
   ★ **实测纠正**：它们**不是 gitignored** —— `git check-ignore -q -- 复盘/DSH插件-点名仓深读-dsh-web.md`
   退 **1**（真被忽略会退 0）。所以「照着目标侧那套 `ignored()` 抄」**修不好**本卡：
   问错问题的判据只会得到空集。差别的真身是「**入库 / 未入库**」：
   `git worktree add` 只铺入库文件 ⇒ 卡树里没有它们，主树盘上有 ⇒ 两侧源集合天然不同。
4. ⇒ 主树读数天然比卡树高，而基线采自卡树 ⇒ **主树永远红**，多红取决于本地盘上躺了多少 ignored 文档。

## 3. 判定

不是「债涨了」，是**两侧不对称**：目标侧 gitignored ⇒ skip（对）；源侧 gitignored ⇒ 照样扫、照样计入（错位）。

`docs/doc-debt-baseline.toml` 头部第 ④ 条：「只许跟着真还债下调，不许为了让门变绿往上调」
⇒ **不许**用 `--write-baseline` 盖掉（那是把判据改软，且换棵树又红）。

## 4. 修法（择一，选 A）

- **A（本卡采用）源侧对称 skip，但问的是「入库没有」**：扫源文件时把 `git ls-files -z`
  （入库集合）与 `git check-ignore --stdin -z`（忽略集合）**都**问一遍，两种情况的 `.md` 一律记 `skip`
  （理由分开记，明细里点名），不参与 ratchet。理由：判据管的是**仓库里的文档**，不是本地笔记本。
  ★ 只抄 `ignored()` 是不够的（实测见 §2.3）：**未跟踪**才是常态，gitignored 只是其中一部分。
- **B 基线按树记**（否决）：基线是「债」，债不该随树变；且 `--seal` 之后两套数会漂。

## 5. 判据

1. 造一个 gitignored 的探针文档（`复盘/探针-断链.md`，正文一条指向不存在文件的引用），
   主树 `--mode report` 的**死指针读数不变**，且 `--json` 的 `skip` 明细里能点名它。
2. **判据 2 原话（「主树与任一卡树对同一 HEAD 读数一致」）经实测不可达，改为下面两条可证伪的形态**
   —— 未跟踪文件在两侧本来就不同（主树盘上有、`git worktree add` 不铺），要求逐字相等只能靠
   `git clean -xdff` 之类的破坏性动作，或者把真债也 masked 掉：
   - 2a **源侧对称**：造合成仓（真 `git init` + 提交）两条钉子 —— 未跟踪的 `.md`、gitignored 的 `.md`
     都不进 `dead_refs`，且 `skip` 明细里点名（理由分开：`未入库文档（未跟踪…）` / `gitignored 文档（…）`）；
     把同一个文件 `git add` 进库后，它**立刻回到判据里**（证明不是「凡某目录都放过」）。
   - 2b **真树单调**：主树读数必须是干净树（`git worktree add <tmp> HEAD --detach`，无未跟踪文件）的
     **子集**，差集全部是「引用指向未入库文件」这一种真债。
   ★ 实测（本轮，HEAD `ad162da`）：主树 `dead_refs 327 / superseded 5 / drift 429`；
   干净树 `346 / 5 / 429`；**主树独有 0 条**，干净树独有 19 条，逐条都是
   `→ 复盘/DSH插件-点名仓深读-dsh-web.md`、`→ tools/replay_worker_edits.py` 这类**未入库**目标。
3. `docs/doc-debt-baseline.toml` 的 `dead_refs` / `superseded` 数字**本轮不许动**；
   `--write-baseline` 连跑两次字节一致（幂等）已有钉子，不许退化。
4. 反向验证：把源侧的入库判定摘掉（`iter_docs_split` 退回 `iter_docs`）⇒ 判据 2a 的两条钉子必红
   （取到红样，贴进卡）。
5. `--doctor` 仍能列出被 skip 的 ignored 文档（让「本地速查」可见，不被静默吞掉）。

## 6. 不许做

- 不许调高 `[baseline]` 的 `dead_refs` / `superseded`。
- 不许把 ignored 文档直接从扫描范围里**静默**丢掉 —— 必须进 `skip` 明细（判据 5）。
- 不许改 `gates/diag/**` 产物的 skip 口径（那是上一张卡钉过的）。

## 7. 证据（写卡时已核实）

- `python -X utf8 scripts/check_docs.py --root .wt/E49 --mode report` → `superseded 5（基线 5，+0）`。
- `git ls-files --error-unmatch "复盘/DSH插件-点名仓深读-dsh-web.md"` → `did not match any file(s) known to git`。
- 该文件按来源聚合的死指针条数 = 26（`--json` 分组）。
