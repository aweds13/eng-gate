# 卡 A275 —— 面板路由 404 真因：inject 里声明 webServer + 直接 ctx.webServer.register

## 现象
`GET http://127.0.0.1:<GUI 端口>/dsh-panel/stack-status`（以及 `/dsh-panel/skills`、
`/dsh-panel/workbench-board`）一直 **404（空响应）**；客户端面板却在（说明浏览器半加载了）。

## 对照（本机已装、真在跑的 `dsh-panel-wenyou`）
```js
export const inject = ["webServer"];
export function apply(ctx) {
  ctx.effect(() => ctx.webServer.register({ kind: "prefix", path: "/wenyou", handler: ... }), "…");
}
```
它把 `webServer` 写在 **`inject` 声明里**，apply 里**直接用 `ctx.webServer`**。

## 本插件原来的写法（不回）
```js
export const inject = ["tools"];
ctx.inject(["webServer"], (webCtx) => { webCtx.effect(() => webCtx.webServer.register({...})); });
```
桌面版里 `ctx.inject([...], cb)` 不保证被调用（服务未就绪时静默不跑）⇒ 路由一条都没挂，
而且没有任何可见日志（profile `logs/*.log` 全是 0 字节）。

## 改法
1. `export const inject = ["tools", "webServer"];`
2. apply 里改成
   ```js
   ctx.effect(() => ctx.webServer.register({
     kind: "prefix", path: SEAM_PREFIX, handler: serveSeam,
   }), "dsh-panel: read-only seam");
   ```
3. 自检加两条回归钉子：
   - `inject` 里必须有 `"webServer"`；
   - 路由必须用 `ctx.webServer.register`（不是 `ctx.inject([...])` 里挂）。

## 判据
- `python tools/dsh_panel.py --check` 绿；
- 反例：把 `inject` 里的 `"webServer"` 去掉 ⇒ 自检红（`[宿主半] inject 里没声明 webServer`）；
- `pytest tests/test_dsh_panel.py -q --no-cov` 全绿；
- `node --check` 生成的 `lib/index.js` OK。
- **真机判据（重启后）**：`GET /dsh-panel/stack-status` 返回 `{"ok":true,…}`，不再是 404。
