## 要解决的问题

「谁为什么被选中」在 pool 今天**只落在人话里**：`tools/pool/trae_dispatch.py:155 _verdict_text(...)` 的七段判决正文（docstring 明写「不另发明格式」）与 `tools/pool/jobs.py::scan_jobs` 的 `why`。想回答「这一轮到底按什么顺序试过哪几个模型、最后是谁答的」，只能人肉翻 `gates/diag/wb-usage.jsonl` 的「模型/轮次」两列再脑补顺序 —— 而 `wb_dispatch.py` 的 429 三拍（`next_whitelist_model` + `rotation_chain_for`）真的会换模型，**真实尝试顺序**是一条只有它自己知道的信息。

magpie 的解法不是「事后读日志重算」，而是**在做决定的地方、用做决定时的那几个值**记一条，事后不重算。本卡搬的就是这一句。

## 判据（9 条，逐条可执行）

1. **一行一轮**：每次派活落**恰好一条**结构化记录（不是零、不是两条）。断言：跑一次派活 ⇒ `read_routes(card)` 长度恰好 1。
2. **不含正文与凭据**：记录里没有 prompt / 回复正文 / 任何凭据。断言：拿一份正文含哨兵串 `<SECRET-2f9a>` 的 spec 跑一遍，落盘 JSON 里 `grep -c 'SECRET-2f9a'` 为 0。
3. **`tried` 是真实顺序**：不是事后按白名单重算。断言：构造「第 2 个模型失败、第 3 个成功」⇒ `tried == [{"model": m1, "fail": ""}, {"model": m2, "fail": "…"}, {"model": m3, "fail": ""}]`，且 `served == m3`。
4. **`served` 说的是真答的那个**：全挂时 `served` 为空串且 `status` 是终态（`all_failed`）。
5. **记录发生在做决定的地方**（★ 唯一需要「构造出重算必然算不出」的钉子）：喂一个与 `wb-usage.jsonl` 里**互相矛盾**的 `tried`（比如 usage 里只记了 `m1`，但 `tried` 传的是 `[m1, m2]`），记录里的值必须跟着**传进来的**走。若实现是「事后读 usage 重算」，这条会红。
6. **读回只读且幂等**：同一份文件读两次，结构完全相等；且读不写盘（断言 `mtime` 不变）。
7. **空表是合法读数**：文件不在 ⇒ `[]`，**不是错误**（照 `tools/pipeline_view.py:458 _read_leases` 的体例）。
8. **坏行如实报坏**：坏 JSON 行跳过但**计数**，不许静默当空（照 `tools/pool/jobs.py:97` 的 `unknown += 1` 体例）。签名要能把「坏了几行」交出来。
9. **`status` 是闭集**：只允许 `served` / `all_failed` / `stopped` / `quota_blocked` 四个；第五个值必须抛。

## 不许做
