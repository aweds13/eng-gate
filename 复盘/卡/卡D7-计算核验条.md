# 卡 D7 · 计算核验条（懒加载 SymPy + 式子抽取 + 三方不一致如实摆）

- task: T-DG007
- tree: `.wt/D7`
- risk: mid
- depends: D3

## 问题

用户的诉求很精确：「我觉得 AI 算的有点不靠谱……有个代码会让我安心一点。」
研究结论（`intention/evidence.md` §2）说得很清楚：**让模型写代码再自己心算没用**（GSM-HARD 只有 23.2），
增益全来自真解释器；而**代数题上「只抽式子交 SymPy」比「让模型写算法程序」高 20 点**。
所以本卡的形态是「**抽式子 → 交 SymPy → 并排比**」，不是「让模型写个 Python 跑一遍」。

## 改法

1. `pyodide.ts`：按需加载 SymPy（首次点击才下载，缓存到本地）；超时 20s；可取消。
2. `extract.ts`：从 assistant 消息里抽候选式子（等号/不等号两侧、积分、求和、矩阵）；抽不出就
   让用户手动框选。
3. `VerifyBar.ts`：三态样式（一致 / 不一致 / 无法解析）；不一致时展开三方视角
   （模型写的 / SymPy 算的 / 数值代入抽样）；结果缓存，可手动重算。
4. **文案红线**：禁止「已验证正确」「答案无误」这类表述（conventions C8）；只能说「SymPy 得到同样的结果」。

## 判据

- 一条含 `∫x·sin(x²)dx` 的回答 → 点核验 → 显示 `-cos(x²)/2` 且判为一致。
- 构造一条模型算错（提示词诱导 2+2=5 或故意错的分式化简）→ 核验条**橙**并展开三方。
- 抽查语料：`grep -rn "已验证正确\|答案无误" src/dsmate/web/src` → **0 处**。
- 式子解析不了 → 灰态 + 「手动框选」入口可用。
- **未点击核验前**，内存里没有 Pyodide（抓内存/日志打点证明），首屏时间不受影响。
- 超时场景：塞一个 `simplify` 很慢的式子 → 20s 后显示「算不完」，**不是**通过。

## 证据

- 一致 / 不一致 / 无法解析 三张截图 + 三方视角展开图。
- 未点击时无 Pyodide 的打点日志。
- 超时用例的耗时日志。

## 不做

- 不做自动解题、不做「帮你算出答案并替换模型输出」。
- 不做原生 CAS（安卓侧没有 SymPy 运行时）。
