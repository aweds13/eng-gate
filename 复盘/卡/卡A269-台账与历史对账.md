# 卡 A269 —— 台账状态与 git 历史对账

## 为什么
2026-10-17 这一轮，队列**连续撒谎**：252/260/262 其实早已落地（`1d94b56` / `fd02cad` / `f507aa3`），
台账却还写 `pending`，于是又白跑了三趟全量门禁（每趟约 8 分钟）。反过来，我自己的收工脚本在派活前
就把状态乐观翻成 `done`，落地失败也不回滚。而 `scripts/audit_progress.py` 只查「`done` 有没有证据」，
**不查「`pending` 到底有没有提交」** ⇒ 这种漂移永远不会变红，只能靠人去 `git log --grep` 猜。

## 做什么
新增 `tools/wb_reconcile.py`（只标准库，只读）：
- **stale-pending（红）**：状态不是 `done` 但 `git log --grep <任务号>` 已有提交 ⇒ 退出码 1，点名卡号/任务号/提交号；
- **stale-done（黄，只报不拒）**：状态 `done` 但找不到提交 ⇒ 只列出来（本仓历史上有 15 张这种老卡，不能当红）；
- `--json` 机器读；台账有分片（`docs/backlog/*.toml`）时**只读分片**（与 `wb_task.py` 同口径）。

## 真读数（实测）
- `pytest tests/test_wb_reconcile.py` → **3 passed**（红/黄/绿三条，含真 git 仓）✓。
- 真机跑 `python -X utf8 tools/wb_reconcile.py` → 立刻点名 `[红] 卡 146（T-G246，状态 failed）已有提交 1005569` ✓，其余 15 条 `[黄]` 老账 ✓。
- `ruff check tools/wb_reconcile.py` → `All checks passed!` ✓。

## 边界
- **只读**：不写台账、不改 git、不动门禁；`--fix` 目前只报「未实现写回」（写回要走落地链）✓。
- **不冒充审计**：它不替代 `audit_progress.py`，只补「队列 ↔ 历史」这一条此前完全没人看的口径 ✓。
