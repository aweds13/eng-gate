## 前情

magpie 的 `accounts import` 是「把别家 coding 工具已经登录好的凭据文件，登记成自己这边的账号」：`magpie accounts import <codex|claude|antigravity|factory> <file>... [--yes]`（`_ext/magpie-main/internal/cli/main.go:97`、`internal/cli/accounts_cli.go:33` 与 `:532` 的 `importUsage`）。
它认的不是「一个平台一种 token」，而是**同一个工具导出的好几种文件形状**：CLIProxyAPI 的 `{type:"codex", id_token, access_token, refresh_token, account_id, email,…}` 与 `{type:"claude", …}`、Codex CLI 的 `auth.json`（`{tokens:{…}}`）、Claude Code 的 `.credentials.json`（`{claudeAiOauth:{…}}`）、Sub2API 的 `{accounts:[{platform, type:"oauth", credentials:{…}}]}`、codexbar 的 `~/.codexbar/config.json`，以及**裸 refresh token 一行一个**（`internal/provider/login_import.go:3-20` 的文件头把这些格式逐条列了出来）。

仓里今天**一个都没有**：

- `grep -rn 'def import_' tools/ scripts/` —— 零命中
- `grep -rn '\-\-import' tools/ scripts/` —— 零命中
- `grep -rln 'import_accounts\|accounts_import' tools/ scripts/ tests/` —— 零命中
- `tools/pool_accounts.py:1917` 的 `build_parser()` 只有 `list / show / discover / checkin / probe / due` 六个子命令，没有 import

所以 F30 的落点是**新增**，不是补一个漏掉的分支。

## 缺口（逐条带现场）

### 缺口 1：账本写入今天只有两条窄路，导入这条路不存在

`tools/pool_accounts.py:2-7` 的文件头写着：本模块回答三个问题，「一个动作都不许写（本卡是纯只读面）」，其中第三问明写「**只 stat，绝不读内容**」。`:19-21` 紧接着列了两条写入例外（原文先说「只有一处例外」，同一段又补了 `probe`）：`saved_refresh_failed()`（卡 A335 —— 供应商拒绝刷新才打吊销标记）与 `probe`（**也写**，只写 `[account.health]` 的 `state` / `consecutive_failures` / `last_probe` 三键，卡 E121）。

而导入天生要**读凭据文件内容**（不读就不知道该登记谁）、又要**写账本**（新行）。这两件事都越过了上面这条边界 ⇒ 必须新开一个模块承接，不许塞进 `discover`，也不许塞进 `checkin.py`（后者文件头 `:1-16` 明写「写动作只在这个模块里」，指的是签到这一种写）。

### 缺口 2：`platforms.toml` 是平台能力表，不是源格式表

`tools/pool/platforms.toml`（246 行）每段的键是 `label/supported/auth_kind/probe/verified/base_urls/chat_urls/token_env/source/local_archive/claim_flow/quota_flow/pitfalls`，一个平台一个 token 名/位点；全文**只有 meoo 一条 file 型**（`:216` `token_file = "~/.meoo/credentials.json"`、`:217` `token_key = "accessToken"`、`:214` `amount_path = "data.account.availableBalance"`），codearts 是 `:41` 的多值 `token_env`，codebuddy `:239` 与 opencode `:193` 干脆是 `token_env = ""`。

导入要认的是**同一个工具导出的多种文件形状**（见上面引的 `login_import.go:3-20`）—— 这是另一个维度，塞不进 `platforms.toml`。这张表自己的文件头 `:1-20` 还写了「绝不放任何凭据、cookie、token」，所以源格式表也只能放**形状**，不能放样本真值。

### 缺口 3：账本今天写不进去 —— 三行行首注释挡住了 `save_ledger`

`tools/pool_accounts.py:334` 的 `save_ledger()` 在 `:344-350` 有一道硬判据：账本里只要有**行首注释**，`_dump_toml` 整份重生成会把它抹掉 ⇒ 直接抛 `LedgerError`，原文「先把注释挪走或删掉再写；**一个字节都没写**」。`ledger_would_lose_comments()`（`:315`）就是算这个的。

实测：仓外账本 `D:/repo/infra/pool/accounts.toml`（128 行、5 个 `[[account]]`）的**第 126/127/128 行是三行 `# touched` 行首注释**，`pa.ledger_would_lose_comments(<该账本>)` 回 `[126, 127, 128]`。

⇒ **今天任何导入写路径都是死路**：哪怕解析全对，写账本那一步必抛。这不是本卡要修的东西（清注释是人或另一张卡的事），但**本卡必须把它变成一条判据**：写之前先问、问出来就停、并且停的时候一个字节都不写、把行号念出来。

### 缺口 4：id 的形状没有约束，导进来可能解析不出人

`tools/pool/account_id.py:81` 的 `resolve_account_id(profile, rows)` 三步走：① 账本行的 `profile` 键 ② 稳定 id 直给 ③ `credential.locator` 末段，且**第 ③ 步只对 `kind == "dir"`**（注释说得很清楚：file 是「一个文件可能许多号共用」，末段是存储名不是号名，属范畴错误）。`:59` 的 `AccountMapError` 明写歧义必须响亮，不许取第一条。

⇒ 导入若给 file 型凭据生成一个靠末段猜出来的 id，导进来的号在派活时会直接解析失败或不稳。本卡必须**把 id 的生成规则钉死**，并用 A344 的解析器反过来验。

## 判据

每条都写清「怎么证明」，证明物一律是 tests/test_pool_accounts_import.py（计划建） 里的一个测试（钉子）。判据只认退出码与产物，不认「我看了觉得对」。

**J1 有入口，且形状与 magpie 同构**
`python -X utf8 tools/pool_accounts.py import --help` 退 0，列出 `--agent`（取值 codex/claude/antigravity，`factory` 明确拒绝并指向 `accounts add`）、至少一个文件位置参数、`--dry-run`、`--yes`、`--ledger`。
证明方式：跑上面那条命令看退出码 + 关键字；再跑 `... import --agent factory x.json` 断言退 2 且 stderr 里有指向 `accounts add` 的话。钉子：tests/test_pool_accounts_import.py（计划建）::test_cli_import_help。

**J2 源文件只读，一个字节都不改**
导入前后对每个源文件取 `sha256` 与 `st_size`，必须完全相同（含失败路径）。
证明方式：测试里先算 hash，跑完 import 再算，逐文件比对。钉子：`::test_source_files_untouched`。

**J3 读不懂的点名交出来，不许静默跳过（本卡最核心的一条）**
结果是一张表，每行至少 `where`（文件 + 第几条 / JSON 路径）、`status`（`added|exists|skipped|failed`）、`reason`。硬判据：`len(added) + len(exists) + len(skipped) + len(failed) == 输入条目总数`，且 `skipped` 每条都非空 `reason`；`where` 不许是空串或 `?`。
证明方式：喂一份「三好一坏」的样本（三条合法 refresh token + 一条 `{"foo":"bar"}`），断言坏那条进 `skipped` 且 `reason` 里含 `not an account`（沿用 magpie 原话 `internal/provider/login_import.go` 的 `err: "not an account"`），并断言四类计数之和等于 4。钉子：`::test_unparsed_entries_are_named`。

**J4 空文件与整体认不出，必须响亮**
空文件 ⇒ `nothing to import`；有内容但一条都认不出 ⇒ `no accounts in it`；两者都退非 0，**都不许**当成「导入了 0 个，成功」。多个文件里某一个空 ⇒ 不中止整次，但必须在结果里留一行 `skipped`（magpie 的原话："one file of several that holds none: said, not passed over"）。
证明方式：三个样本各跑一次，断言退出码与 stderr/结果表；多文件那个断言其余文件仍然被导入。钉子：`::test_empty_and_unknown_exports_fail_loudly`。

**J5 不许覆盖已有账号的凭据**
源里的凭据指纹（refresh token / access token 的 hash，**不落明文**）已在账本中 ⇒ 该条 `status = exists`，账本该行的所有字段（含 `added_at`、`approved_models`、`credential.locator`）**逐字节不变**。
证明方式：账本快照前后 diff；断言行数不变、目标行文本不变。钉子：`::test_existing_account_not_overwritten`。

**J6 导入不联网、不探测**
整个导入路径不许出现 `_get_json` / `urllib.request` / `socket`；`probe_account` 与 `_token_for` 不得被调用；账本的 `quota.observed_at`、`quota.samples`、`health.last_probe` 在导入后必须与导入前**完全相同**。
证明方式：① `grep -n '_get_json\|urllib\|socket' tools/pool/accounts_import.py` 必须零命中；② 测试里 monkeypatch `probe_account` / `_get_json` 成「一被调用就 assert False」的哨兵，跑完整导入；③ 账本 JSON 快照比对这三个键。钉子：`::test_import_makes_no_network_call`。

**J7 闸门与 discover/probe 同构**
`TF_NO_ACCOUNT_DISCOVERY=1`（同一个 `DISCOVERY_OFF_VALUES` 常量，`tools/pool_accounts.py:83` 与 `:86`）⇒ 导入直接拒绝、退非 0，并且**连账本都不读**（把 `--ledger` 指到一个不存在的路径，报的仍然是「闸关了」而不是「账本不存在」）。
证明方式：两条子测试，一条设 env + 真账本，一条设 env + 假路径，比对报错文本。钉子：`::test_import_respects_discovery_off`。

**J8 写账本前先过注释判据，过了才写；过不了就一个字节不写**
导入的写路径必须复用 `ledger_would_lose_comments()`（`:315`）+ `save_ledger()`（`:334`）这条既有闸，不许自己 `open(...,'w')`。有行首注释 ⇒ 抛 `LedgerError`、账本 sha256 不变、把行号念进 stderr。
证明方式：造一份带行首注释的临时账本，跑导入，断言退出码非 0、stderr 含行号、文件 sha256 不变；再造一份干净的，断言写成功。钉子：`::test_import_never_clobbers_comments`。

**J9 默认只算不写（dry-run 优先）**
不带 `--yes` ⇒ 只打印计划（`added` / `exists` / `skipped` 计数 + 每个将新增的 id），账本 `mtime` 与 `sha256` 都不变。`--yes` 才真写。
证明方式：两次跑，比对 mtime/sha256 与 stdout 里的计划表。钉子：`::test_dry_run_is_default`。

**J10 写进去的每一行都能过 `load_ledger(strict=True)`**
导入完成后立刻 `load_ledger(path, strict=True)`（`:285`）必须不抛：id 不重复、`platform` 在能力表里、`state` 是五值之一（`:66`）、`approved_models` 是数组、`credential.kind` 在 `CRED_KINDS`（`:73`）、`quota.source == "unknown"` 时**不带** `amount`（`:225-230` 的原话是「没探测过就不许填数」）。
证明方式：测试里直接调 `load_ledger(..., strict=True)`，异常即红。钉子：`::test_imported_rows_pass_check_account`。

**J11 导入出来的 id 能被 A344 的解析器认**
对每一条新导入的行，`resolve_account_id(<该行的 profile 或 locator>, rows)` 必须成功且指回这一行；file 型凭据**不许**靠 locator 末段猜 id（要么给 `profile`，要么给稳定 id），猜的路径必须报 `AccountMapError`。
证明方式：dir 型与 file 型各一条用例，断言返回值与预期 id 相等；再造一个同 file 两行的场景，断言抛 `AccountMapError` 而不是取第一条。钉子：`::test_imported_ids_resolve`。

**J12 账本里不许出现凭据明文**
导入后整份账本文本跑 `SECRET_RE`（`:74`）与「样本里的 token 原串」两个匹配，都必须零命中；另外断言 `credential.locator` 里不含 token 内容的任何 8 字符子串。
证明方式：测试用假 token（形如 `sk-TESTTOKEN...`）导入，读回账本全文做两次 grep 式断言。钉子：`::test_no_secret_in_ledger`。

**J13 单条失败不许把好的拖下水，但整体退出码要说话**
一条坏条目（认不出 / 同一个 token 在文件里出现两次）**不许**中止其余条目的处理：其余条目照常进 `added` 或 `exists`；整体退出码 = 0 当且仅当 `skipped` 与 `failed` 都为空，否则退 1（`EXIT_NEEDS_HUMAN`，`:76-78`），并在 stderr 头一行给「N 条未导入」。
证明方式：一份「三条好的 + 一条坏 JSON」的样本，断言 `len(added) == 3`、`len(skipped) == 1`、退出码 1；再喂一份「重复两次的同一个 token」，断言该重复条 `failed` 且 `reason` 含 `in the files twice`（抄 magpie 原话），另一条不被牵连。钉子：`::test_one_bad_entry_does_not_abort`。
判据条数合计 **13 条**。
