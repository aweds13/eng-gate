# 卡 E156 · 三仓适配层收进仓：fw / dsh / ura 也能用同一条构建器

> 台账号 `T-AG691`｜分区 E（门禁与可信度）｜树 .wt/E156｜层 代码层（骨架加两个键 + 三份适配器 + 三份 profile）｜
> depends E146（骨架 --repo 化）/ E151（号池桩缺件）/ E155（--allow 重复给）

## 要解决的问题

### 问题 1 · 三个镜像仓是「一次性构建器」推上去的，仓里没有它们的一份东西
`docs/subsystems/ci/GitHub-Actions-云门禁.md` §9 记着五个仓都在 GitHub 上跑，其中 fw-gate / dsh-gate / ura-gate
三仓的适配器与 profile **不在本仓**：`git ls-files -- scripts/cloud/gha` 只有
adapter.py / build_snapshot.py / conftest_shim.txt / gate_profile.py / profiles/engineering.toml / profiles/openmaic.toml 六件。
推它们的那套脚本写在 gates/diag/_ad/（一次性产物，被 .gitignore 挡在提交面外）。
后果：本机盘一没，这三个仓**再推不出来**；§9 那张表就变成「跑过，但没法重跑」。

### 问题 2 · 骨架的 conftest 垫片只认 tests/conftest.py
`scripts/cloud/gha/build_snapshot.py:400` 是 `cf = os.path.join(dst, "tests", "conftest.py")` —— 硬编码。
framework 与 UltraRAG 的垫片挂在**树根** conftest.py（framework 源仓自带；UltraRAG 源仓根本没有），
dsh-superagent-prototype 也没有根 conftest.py。⇒ 这条键对三个仓都用不了。

### 问题 3 · dsh 那份适配器的读数恒为 0（实测）
dsh-gate 那趟读数原文：`{"ok": false, ..., "passed": 0, "failed": 0, "skipped": 0, "files_failed": 0, "files_passed": 0}`。
两个叠加原因（本轮实测）：
1. `_run()` 只 `print(out.strip().splitlines()[-25:])` —— vitest 失败时末尾是一长行 `::error file=...` 的 GitHub annotation，
   把 `Tests` / `Test Files` 汇总行挤出 25 行窗口 ⇒ **作业日志里根本没有可解析的行**；
2. `_words()` 用 `s.startswith("Tests ")`，而 runner 上 vitest 输出带 ANSI（`\x1b[2m      Tests \x1b[22m …`）⇒ 永不命中。
⇒ 读数要么靠 JSON reporter，要么靠「剥 ANSI + 不截断」，不能靠 tail-25 猜。

## 判据（逐条可执行）

### 判据 1 · 骨架认「垫片挂在哪」
`scripts/cloud/gha/gate_profile.py` 的 `[adapter]` 段新增两个键：
`conftest_path`（默认 `"tests/conftest.py"`，engineering 逐字不变）与 `conftest_marker`（默认 `"pytest_addoption"`）。
`_cross_check` 加两条：`conftest_path` 不许绝对路径、不许含 `..`；`conftest_marker` 不许为空。
`scripts/cloud/gha/build_snapshot.py` 的 adapter 段改成读这两个键；目标文件**不存在时新建**
（UltraRAG 与 dsh 源仓都没有根 conftest.py），打一行 `conftest created: <rel> <N> B`；已存在则按老规矩 append。
幂等判据从写死的 `pytest_addoption` 改成 profile 给的 marker，命中仍 `CONFTEST_ALREADY_HAS_ADDOPTION` 退 5。

### 判据 2 · 三份适配器进仓，读数都落到同一个落点
新增 `scripts/cloud/gha/adapters/framework.py`、`adapters/dsh.py`、`adapters/ultrarag.py`，
三份都写 `<根>/.pipe/gha_reading.json`、都打 `=== GHA-GATE-READING-BEGIN/END ===`、都受 `GHA_GATE_ADAPTER` 防递归。
新增 `scripts/cloud/gha/conftest_reading.txt`：只有 `pytest_terminal_summary` 钩子（读上面那份 JSON、原样重打三行），
首行是 marker `# GHA-READING-HOOK`。
dsh 那一份**必须**用 `--reporter=json --outputFile` 取计数（本轮实测可用：`numPassedTests` / `numFailedTests` /
`numPendingTests` / `numTotalTests` / `numFailedTestSuites` / `numPassedTestSuites`），不许再靠 tail-25 解析。

### 判据 3 · 三份 profile，一条 engineering 专属键都不许有
新增 `scripts/cloud/gha/profiles/framework.toml`、`profiles/dsh.toml`、`profiles/ultrarag.toml`。
三份都：`task = ""`（这仨仓没有台账）、`pool.stub = false`、`ledger_exempt = []`、`evidence_files = []`、
`generators = []`、`from_remote_workflows = true`（workflow 在镜像仓上冻结，本 token 改不了）、`sync.mode = "tree"`。
正文禁 `TF_PROJECTS_TOML` / `models.whitelist.toml` / `line/impl-v1` / `T-AG526` / `gate: engineering`。

### 判据 4 · 三份 profile 都能在本机把 build + smoke 走通（不 push）
`--stage build` 各自 `BUILD_OK`；`--stage smoke` 各自 `SMOKE*_RC 0` 且没有 `SMOKE_FAILED`。
冒烟**不许**装依赖（framework 的 pytest 本机有；dsh 只跑 node 版本与 pnpm 版本；UltraRAG 只做静态读，
它那套 fastmcp / faiss 只能靠 runner）。

### 判据 5 · 钉子
`tests/test_gha_cloud_gate.py` 新增：①目录里每份 profile 都 load 且 `adapter.src` 文件真在盘上、在 git 里；
②三份新 profile 正文不含 engineering 五个字面；③`conftest_path` 绝对路径或含 `..` 时 `load` 抛 `ProfileError`
（正反两面）；④「目标 conftest 不存在就新建 + 幂等命中退 5」两条直接调 helper 断言，不真跑 `do_build`。
