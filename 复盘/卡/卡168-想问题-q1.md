## 你这一轮要产出什么（★ 不是找答案，是**问出问题**）

**只写一个文件**：`复盘/问题清单-组1.md`

你会被给到三样东西（都在仓里，**只读**）：
1. `复盘/架构索引-分层图.md` —— 这套系统的 **12 层实况**（每层的目录、规模、职责、**谁判它**）+ 一份补核；
2. `复盘/问题清单-分层.md` —— 主控的**初稿问题**（★ 当**种子**用，**别照抄**）；

你要负责的层：
- L0 意图层（人说了算 / 授权边界 / 停止条件）
- L1 规格与契约层（specification · contracts · commands.toml · ACCEPTANCE）
- L11 示例层（examples/ 可跑的文档）

## ★ 任务：替你负责的层**想出足够多、足够具体**的问题

**问题的口径（这决定成败）**：
- 每一问都要能落到「**谁的什么动作**」上 —— 不写「最佳实践是什么」这类问不出东西的；
- 优先问**这套系统真实咬过的地方**（能引就引现场：文件、读数、卡号、提交号）；
- 也问**还没咬但结构上一定会咬**的地方（从"谁判它"那一列找**没有机器判据**的层）。

**每条问题给四个字段**（缺一不写）：

```
### Q-<层>-<序号> <一句话把问题问清>
- 为什么它会咬人：<真实现场；没有现场就写「结构上必咬」，并说清结构>
- 该由谁回答：<人 / 机器判据 / 外部（论文·工具·社区）>
- 什么证据能把它了结：<一个可观察的东西：读数 / 判据 / 反例钉子 / 外部来源>
```

**末尾两行**：
- `统计：本组 N 条问题（按层分布：…）`
- `本组最狠的三条：Q-… / Q-… / Q-…（各一句为什么）`

## 铁律

- ★ **只读 + 只写那一个文件**；不改代码、不 `git add`、不 `commit`、**不跑全量门禁**（要 5 分钟且吃内存）。
- ★ **不写答案**。你要的是**问题**；给答案会污染后面 Kimi K3 的深化。
- ★ 命令要快：**不要递归扫 GB 级目录**（`~/.workbuddy`、`node_modules`、`.wt/**`）。
- ★ 中文用「」，不写 ASCII 双引号。**不确定就写不确定**，不许编现场。
- ★ 条数不是越多越好，但**每组至少 20 条**、**不许凑数**（同一件事换三种说法算一条）。
