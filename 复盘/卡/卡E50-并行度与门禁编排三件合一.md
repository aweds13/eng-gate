## 段 1 · 成员 E30 —— E30 —— 并行度自适应与分片策略：把 4 个 worker 的硬顶拆成按内存分档

原文：`复盘/卡/卡E30-并行度自适应与分片策略.md`

### 判据（原卡「判据」节逐字）

1. `pytest tests/test_run_gates_workers.py -q -o addopts=` 全绿，至少 8 条钉子：
   五个档口各一条 + `TF_PYTEST_WORKERS` 显式优先（给 2 就 2，不许被自适应覆盖）+
   `cpu_count=4` 时不许超过 4 + 读不到内存时退回兜底 + 「在跑多少就扣多少」。
2. **实测对照表**（写进申报，不是口号）：`-n 4` / `-n 8` / 三档 `--dist` 的 `pytest` 墙钟，
   同树同 commit。
3. **反向验证**：把 `workers_for()` 改回恒 `min(4, cpu)` ⇒ 档位相关钉子必须红；把
   「扣在跑」那步删掉 ⇒ 对应钉子必须红。两条红色原始输出进申报。
4. 全量门禁 `exit 0`、`pytest` 用例数与改动前一致（不许靠少跑用例变快）。

### 不许做（原卡逐字）

- 不许把 `TF_PYTEST_WORKERS` 的显式优先拆掉（A266 的约定）。
- 不许取消低内存保护（可用 < 2.5 GB ⇒ 串行）；这条是「不许换页」的安全网。
- 不许 `-n auto`（32 核会拉 32 个 worker，15.2 GB 内存必换页，卡 A266 已裁定）。
- 不许为了变快改 `-p no:cacheprovider`、`--tb=no`、`--maxfail` 之类「少跑 / 少说」的开关。

## 段 2 · 成员 E32 —— E32 —— 快慢分层：把 22 条「起真子进程跑落地链」的 e2e 移出默认 pytest 门

原文：`复盘/卡/卡E32-快慢分层.md`

### 判据（原卡「判据」节逐字）

1. **默认门 ≤ 150 s**（同 4 worker、同机器、不与其他门禁并行时测），`pytest_chain` 独立跑绿；
   两个数都进申报，并附 `gates/diag/bench-split-*.log`。
2. **覆盖面一条不丢**：`pytest --collect-only -q -m chain` 与 `-m "not chain"` 的用例数之和
   = 改前 3175；`pytest -m chain` 全绿、`pytest`（默认）全绿。
3. `pytest tests/test_gate_split.py -q -o addopts=`，至少 7 条钉子：`chain` marker 已注册 +
   默认门命令里有 `not chain` + `pytest_chain` 在 `GATES` 里 + `required_profiles()` 把它算进
   `lang` + 落地档包含它 + 只打链路的文件必然全在 chain 里（防漏打）+ 打标集合与清单一致
   （清单写死在钉子里，防悄悄少打）。
4. **反向验证**：把 `-m "not chain"` 从默认门去掉 ⇒ 「默认门命令」那条钉子必须红；
   把一条已打标的用例的 marker 删掉 ⇒ 「打标集合与清单一致」那条必须红。红色输出进申报。
5. 全量门禁（含新门）`exit 0`。

### 不许做（原卡逐字）

- **不许删用例、不许 `skip`、不许把 e2e 改成 `@pytest.mark.acceptance` 蒙混**（那是换名字不换成本）。
- 不许只加 marker 而不加门（那样 e2e 就永远不跑了，等于把安全网摘掉）。
- 不许让 `pytest_chain` 变成「可选门」：落地档必须包含它，否则落地可以绕开 e2e。
- 不许改 `tests/conftest.py` 的 `run_git` 语义（E14 的抖动重试在那儿，动它会把 55 条钉子搞红）。

## 段 3 · 成员 E33 —— E33 —— e2e 模板仓：把「每条用例自己建一遍仓」换成「复制一份」

原文：`复盘/卡/卡E33-e2e模板仓.md`

### 判据（原卡「判据」节逐字）

1. **同文件前后耗时对比表**（`tests/test_wb_land.py` + test_contract_audit.py 两文件，
   改前 / 改后各跑一遍，4 worker 亦可串行，只要两遍条件一致），目标 **−40%**；
   若实测不到 20%，本卡收口成「测过，收益不足，不改」并写清读数。
2. `pytest tests/test_wb_land.py tests/test_contract_audit.py -q -o addopts=` 全绿，
   用例数与改前一致。
3. `pytest tests/test_template_repo.py -q -o addopts=`，至少 5 条钉子：
   **全 session 只建一次**（计数器；注意 xdist 下 session fixture 每个 worker 会各跑一次，
   所以必须用 `worker_id` + 文件锁：gw0 建、其余等锁后复制，计数器断言的是「构建标志只被置一次」
   而不是「函数只被调用一次」）+ 两个 `copy_to` 互不可见（各自提交后看不到对方）+
   模板仓未被任何用例改动（跑完 `git status` 干净）+ `copy_to` 产物是**独立 git 仓**
   （`.git` 存在且 `rev-parse HEAD` 不同）+ 模板里骨架文件与真仓同名同判据。
4. **反向验证**：把 `copy_to` 改成「直接返回模板仓本尊（不复制）」⇒ 隔离那条钉子必须红；
   把文件锁去掉（每个 worker 各建一份）⇒ 「构建标志只置一次」那条必须红；
   在 `-n 4` 下重复跑三次，构建标志必须始终只有一次。红色输出进申报。
5. 全量门禁 `exit 0`。

### 不许做（原卡逐字）

- 不许改任何 e2e 的断言或子进程命令（这卡只换准备动作）。
- 不许让模板仓被用例写脏（`git status` 必须干净，脏了就是设计错了）。
- 不许把 e2e 改成「共享同一个工作树」来省时间 —— 那会让用例互相污染，且和 E32 的分层打架。
- 不许删 `run_git()` 的抖动重试；新 fixture 也走它。
