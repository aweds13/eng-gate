### 第二份：**进程契约纪律**（框架能不能"扔给别人用"就看这份）

1. **退出码表**：把我们现在的表写全（`0` 绿 · `1` 有门红 · `2` 用法错 · `3` 资源闸拒跑 · `124` 硬超时），
   并与外部惯例**逐个对照**：BSD `sysexits.h`（64/65/66/69/70/71/73/74/75/77/78 各是什么）· shell 保留码（**126/127/128+N 是 shell 发的，不是程序发的**）· `pytest`（**5 = 一个用例都没收集到**）· GNU `timeout`（**124 = 超时**）· 「非 0 但不算错」的例子（`grep`：1 = 没匹配；`diff`：1 = 有差异）。
   ★ 三个雷区要写进去：**POSIX 只保留低 8 位（>255 被截断）** · **Windows 是 32 位无符号（`-1` 会变成 4294967295）** · **别占用 126/127/128+N 的语义**。
2. **面向两类调用者的契约**：给程序/agent 调（**退出码 + `--json` + stdio**）· 给人调（**`--help` + 人话错误信息**）。
3. **泛用性的 7 条条件**（照抄并**逐条标出我们现在不满足的地方**，要举例到文件/行）：
   ① 退出码表公开稳定 ② `--json` 结构化输出 ③ **项目相关值全部外置**（不许硬编码路径/解释器）④ stdin/stdout 可管道 ⑤ 幂等/可中断/无隐藏全局状态 ⑥ 依赖声明清楚 ⑦ 跨平台（至少 Windows + Linux）。
4. **核心/薄壳分层**：★ **核心做成库（`import` 可用），外面套一层薄 CLI** —— CLI 给进程/agent 调，库给代码调；**别人"只调用"用 CLI，"要扩展"用库**。
5. **文档四象限（Diátaxis）**：`tutorial` 教程 / `how-to` 操作指南 / `reference` 参考 / `explanation` 解释 —— 标明我们的 **skills ≈ how-to**、**`--help`/手册 ≈ reference**、**`PIPELINE.md` ≈ explanation**。
