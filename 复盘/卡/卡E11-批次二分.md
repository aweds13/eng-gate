# 卡 E11 —— 批次二分：批红了要能自己指出是哪张卡

> 台账号：T-AG462 ｜ 树：`.wt/E11` ｜ 分区：E（CI 子系统）
> 依赖：E10（同改 `tools/wb_batch.py`）

## 现在疼在哪

攒批把「N 趟门禁」压成「1 趟」，代价是**失败定位变差**：批里任何一张卡的门禁红，整批落到 ⑤′ 停手，人只知道「批红了」，不知道是哪张卡。今天的处置办法是人工逐个重跑 —— 这正是 TFS11 原始算法要解决的问题：

> 一次构建带多个排队项；**失败则全部退回队列、逐个独立重跑**（[TFS11 Batching Gated Builds](https://learn.microsoft.com/pl-pl/archive/blogs/jpricket/tfs11-beta-batching-gated-builds)）。更省的版本是 [bors-ng](https://github.com/bors-ng/bors-ng) 的**对半二分**：批红 → 拆两半各自跑 → 只在红的那半继续拆。

我们仓里现在**连「批红了」这个事件都没落盘**：`gates/diag/land-<批号>.log` 里只有一行 `exit≠0`，没有「批里有哪几张卡」「哪一轮红的」。

## 要做成什么样

`wb_batch.py bisect <批号>`（或 `land` 加 `--bisect`）：

1. 批门禁红 ⇒ 自动把成员**对半拆**，各起一趟门禁（占两槽？不 —— 串行跑，同一把锁）；
2. 红的那半继续拆，直到定位到**单卡**；
3. 每轮把成员、结论、耗时写 `gates/diag/batch/<批号>.bisect.json`（`{"batch","rounds":[{"members":[…],"red":[…],"seconds":…}],"culprit":"<卡>"}`）；
4. 定位到的单卡，**原文引用**它自己那趟门禁的红行（`[ERR] <门名> exit=… <摘要>`），不 paraphrase；
5. 剩下的绿卡重新合成一批，给一条可执行命令（不自动跑）。

## 判据（可验收）

1. 批红**自动**触发二分（不靠人记得加参数）；绿批不触发，`bisect.json` 不产生。
2. 轮数 ≤ `ceil(log2(n)) + 1`，每轮成员是上一轮的真子集（不许原地重跑整批）。
3. 定位到单卡时 `culprit` 字段就是那张卡号；定位不到（全绿但批仍红 = 环境/非确定性）⇒ `culprit = null` 且**明说「未能定位」**，不许编一个。
4. 绿卡重新合批的命令里，成员是**这一轮实测绿**的那些，不是原来全批。
5. 台账写批次读数：`docs/changelog.d/<批号>.md` 的 changelog 段要有「批 N 张、二分 K 轮、多花 M 分钟」。
6. 验收 `python -X utf8 -m pytest tests/test_wb_batch_bisect.py -q`。

## 钉子（先红后绿）

1. 三张绿卡 ⇒ 批绿、无二分、无 `bisect.json`。
2. 三张里第二张必红（夹具注入一个必失败的测试文件）⇒ 二分定位到它，轮次 ≤3（3 张按 2+1 拆）。
3. 全绿但批红（注入一个只在批状态下失败的夹具）⇒ `culprit=None`，错误信息里有「未能定位」。
4. 二分期间不改卡树（只读分支比较），跑完 `git -C .wt/<卡> status --porcelain` 逐字相同。
5. 二分耗时记进 `bisect.json`，且总和与批次日志里的时长对得上（误差 ≤5%）。

## 不许做

- 不许对**审计红**二分：审计红是文书/台账问题（如今天 E2 的 `tia_map.py` 无证据指针），逐卡修比二分快。
- 不许自动重跑「绿的那一半」整批 —— 定位完成后由人决定合批。
- 不许在二分时改判据、放宽门禁、跳过某道门来「让它过」。

## 边界（如实写）

- 二分只在**同一把门禁锁**下串行跑，因此「多花的时间」≈ 轮数 × 单趟全量（今天 ≈19 min/趟）；这是定位的代价，要如实记，不美化。
- 二分不能定位**非确定性失败**（同一棵树两次跑结论不同）—— 那条路归 E5 合并队列的「每卡读数复用」。
- 与 E5 的分界：E5 管「排队与投机预检」，本卡只管「批红了怎么定位」。
