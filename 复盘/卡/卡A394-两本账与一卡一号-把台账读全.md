6. **`queued` 从 dict 改成 set 没有修掉任何一个 bug**：dict 的**键集合**与 set 完全相同（`{c.task for …}` 与 `{c.task: c for …}` 的键一样多，因为 task 号作键、重复只覆盖值）⇒ `mark in queued` 判孤儿的行为改前改后一致。改 set 只为**不让后来人以为 `queued[mark]` 能取到那张卡**（5 组共号时它取到的是最后一张）。判据 5 的测试守的是 `multi` 循环（它本来就走 `backlog.cards`，从来没被 dict 影响）—— 这一点在源码注释里也写明了，别把这条改动讲成「修了静默漏检」。
7. **「必须带 evidence」这一条今天没有挡下任何真孤儿**：evidence 为空的只有 `SR-F2.8` 与 `SR-F8.4b` 两条，两个号都不在 git 的 618 个 Task 号里。所以这条口径今天是**防线**而不是**修正**——它的价值要等一个「只有标题、没有证据」的条目被挂上 `Task:` 那天才兑现。

9. **3 张真·一卡两号没有定性**：`A289`/`T-AG403`、`E49`/`T-AG499`、`E54`/`T-AG505` 是「同一张卡两笔都改了代码」。本卡只保证它们**还红着**（判据 4 的反例），不替它们决定「是不是该拆卡 / 该补第二张卡号」——那要一张单独的卡，且得先问用户。
10. **这条判据不是门禁**：`scripts/` 与 `gates/defs/` 零命中 ⇒ 改它不会让门表变，也不会被全量门禁照到；唯一会咬它的是 `tests/` 里那三份。所以「门禁全绿」不等于「这条判据读全了」——只能靠本卡这三份测试。
