# 卡 E95 —— pool 打磨：把「不知道」和「知道」分开（选号 / 无价 / 静默空域）

> 台账号 `T-AG604` ｜ 分区 E（号池子系统）｜ 树 `.wt/E95` ｜ 层 gate
> 依据（用户 m92988）：「把 pool 的使用打磨好，不计代价与 token。」
> 勘察原件 `gates/diag/zero-callers-recon.md`（751 行，115 处 file:line 脚本校验 0 处越界）。

## 要解决的问题

1. **「不知道」被当成 0**：`tools/pool/route.py:157` `Seat.used: float = 0.0`，
   `smart_order`/`least_used` 只看 `used`。实测
   `smart_order([Seat(key='never', known=False), Seat(key='m95', used=95.0)]) == [0, 1]`
   —— 从没量过的号排在 95% 用尽的号**前面**；`Seat(known=False, used=99.0)` 时 `== [1, 0]`
   ⇒ `known=False` 完全不保护 `used`。接网关前不修，等于「把不知道当成 0% 已用」。
2. **无价被写成有价**：`tools/pool/ledger_spend.py::append()` 写死 9 键、**永不写 `priced`**，
   而读侧 `unpriced()` 对缺席键取 `True` ⇒ 恒回 0，「没有价目表」这个事实被读成「全都有价」。
3. **两处文档在说谎**：`docs/subsystems/pool/modules.toml` 与 README 说 `route` 被 `wb_dispatch` 调，
   实测 import 清单里没有它（已在本卡外修过一处，剩的见交付）。
4. **零调用方的两处该接的没接**：`route.apply_order`（纯护栏，三种坏输入全回恒等不抛）与
   `ledger_spend` 的「无价」状态。

## 判据（5 条）

1. **`Seat.used` 允许「没量过」**：类型改 `float | None = None`；
   `tier()` 收到 `None` ⇒ **不抛**，语义是「不知道」，且**不许静默当 0**；
   所有分桶函数对 `used is None` 的座给**明确的位次**（排在已知的后面，不是数字 0 的位次）。
   钉子：`smart_order([Seat(key='never', known=False), Seat(key='m95', used=95.0)])` 必须
   **把 m95 排前面**（当前是反的）；`least_used` / `by_pace` / `fastest` 同向。
2. **`known=False` 能保护 `used`**：`Seat(known=False, used=99.0)` 不许因为 `used` 大就排到
   已知 95% 的号后面（`known=False` 的含义是「这个数不可信」）。
3. **写侧记「无价」**：`ledger_spend.append(..., priced: bool | None = None)`，
   `None` ⇒ **不写这个键**（老行形状不变），`True/False` ⇒ 写字面值；
   `unpriced()` 对「写了 `priced=False`」的行计数 +1，对缺席键仍取 `True`。
   钉子：`append(priced=False)` 后 `unpriced(...) == 1`；`append()`（默认）后仍 0。
4. **文档与代码一致**：`docs/subsystems/pool/modules.toml` 与重算后的 README 里，
   `route.py` 的 `cli` 字段列出**真实调用方**（`pool.plan` 的 `reset_for`/`seconds_left`、
   `pool.sticky` 取 `USED_SHARE`），不再写 `wb_dispatch`。
5. **反向变异 ≥4 条**：`used` 默认改回 `0.0` / `tier(None)` 静默返 0 / `append` 写死 `priced=True` /
   `apply_order` 改成抛异常 —— 四处各自能让对应测试红。
