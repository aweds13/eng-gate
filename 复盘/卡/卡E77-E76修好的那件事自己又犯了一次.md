# 卡 E77 —— E76 修好的那件事，E76 自己落地时又犯了一次（T-AG580）

> 台账号 `T-AG580` ｜ 分区 E（门禁与可信度）｜ 树 `.wt/E77` ｜ 层 判据层
> 基准提交 `17c2e786`（主树 HEAD，E76 刚落）。

## 要解决的问题（已实测，不是推测）

E76（`T-AG579`）给落地链加了第 ⑤′.5 步「重算现算文档」，判据是「**落地链自己改的东西，自己验证**」。

**但 E76 自己落地那一笔没有走到那一步。** `gates/diag/land-E76.log` 原文：

```
=== ⑤′ 白名单 → 翻账 → 暂存 ===
  [队列] 卡 E76：pending → done（这一笔是它的落地）
  staged = [...]
```

翻账之后**直接** `staged`，**没有**「重算现算文档」那一行 —— 因为 `wb_land` 用的 `pool.landing` 是**它要提交的那份新代码之前**的版本（`--commit-only` 跳过 ①~④，但 ⑤′ 用的是**进程启动时加载**的 `landing.py`，而那份文件正在被这一笔改动）。于是 E76 落地后主树的 `docs/subsystems/pool/README.md` 又错了一次：

```
[FAIL] 第 83 行：应为 '| 队列卡数 | 313 张（302 done / 11 pending） | …'，
         实际 '| 队列卡数 | 313 张（301 done / 12 pending） | …'
```

实测：`python -X utf8 -m pytest tests/test_pool_readme_counts.py` 在主树 `17c2e786` 上 **`1 failed, 5 passed`**。重算后 `23 passed`。

**这是同一件事的第二次发生** —— 不是新缺陷，是「修它的那一笔自己没被它修好」。这正好把一条更硬的判据照出来了：**判据不能只靠「落地链在运行时重算」，因为落地链自己就是被改的对象。**

## 判据（5 条，逐条可执行）

1. **门禁必须能抓住它**：`tests/test_pool_readme_counts.py::test_real_readme_matches_recount` 在主树上**不许红**。修复后断言：真仓库跑这条 ⇒ 绿。
2. **不许靠「跑一次生成器」当修复**：光把 `README.md` 重算一遍再提交，**同一件事下一笔还会发生**（这是已实测的：E76 落地时就发生了）。所以修复必须让**门禁在提交前就抓住**，而不是靠人记得跑。
3. **落地链的自改自验要有第二条腿**：`pool.landing` 自己是被改对象时（`--commit-only` 路径、或这一笔改了 `tools/pool/landing.py`），E76 的 ⑤′.5 走不到 ⇒ 必须有一条**不依赖运行中被改的代码**的检查。由你判断实现（三个方向，任选或组合）：
   - (a) `run_gates.py` 在 ④ 之前（或 `--commit-only` 路径上）加一条**独立**的「现算文档一致性」子检查，它**自己**跑生成器，不经过 `landing.py`；
   - (b) `wb_land.py` 的壳层（不在 `pool.landing` 里）自己算一遍；
   - (c) 让 `gates/reuse.json` 的复用判据把「台账 status 变了但 README 没跟着变」判成**输入变了**（复用失效，必须重跑 pytest）。
   ★ **选哪个由你判断**，但必须写清理由，且不许变成「第二份判据」（现算口径仍只在 `scripts/gen_pool_readme.py`）。
4. **`--commit-only` 必须被覆盖**：E76 走的就是这条路。断言：一次 `--commit-only` 落地（改了台账 status）之后，README 与现算一致。
5. **不许削弱既有判据**：`tests/test_pool_readme_counts.py` 的两条钉子一个字不动；`scripts/gen_pool_readme.py` 的现算口径一个字节不动。

## 缺口（如实写在卡里）

1. `docs/INDEX.md` 是**完全同构**的缺口（E76 已实测记录：落地链每笔自动新增 `docs/changelog.d/{task}.md`，而 INDEX 篇数含它）—— 本卡**不碰**，另开卡。
2. 本卡治的是「现算文档」这一类；别的「落地链自己改、自己又没验证」的派生件本卡**不普查**。
3. 只在本机 win32 验过。
4. **`.git/hooks/` 只有 `*.sample`**（`core.hooksPath` 未设 ⇒ git hooks 没装），而 `复盘/不变量台账.toml:27` 明写「工人绕过收口链自己 `git commit` 时，机器拦在复核/审计侧（事后咬），不是 pre-commit 硬拦」⇒ 本卡的修复只能挂在**落地链**上，拦不住绕开落地链的手工提交。这也正是方向 (c)（复用判据）没选的原因之一。
5. **（2026-11-01 更正 · 卡 E79/T-AG582）本缺口原来写着「`landing.py` ⑦ 的 `audit_progress.py` 子进程没查退出码」—— 那句话**是假的，已实测推翻**。**实测**：`tools/pool/landing.py:201` 的 `def run(cmd, cwd, check: bool = True)` 在 `r.returncode != 0` 时打 `★ 命令失败（N）` 并 **`sys.exit(2)`**；`:2656` 的 `audit = run([... scripts/audit_progress.py], cwd=wt)` **没传 `check=False`** ⇒ 审计一红，落地链当场停手。复现：`python -X utf8 -c "import sys,pathlib;sys.path.insert(0,'tools');from pool import landing;landing.run([sys.executable,'-c','raise SystemExit(7)'],pathlib.Path('.'))"` ⇒ 打 `★ 命令失败（7）` 后 `SystemExit 2`。同一条缺口里的另一半是对的：`.git/hooks/` 实测只有 `*.sample`（`ls .git/hooks/ | grep -vc sample` = **0**）、`git config core.hooksPath` **未设**。⇒ 「in-band 修不动一笔同时改多条宿主的提交」这个**结论不变**，但支柱要换成 E77 已实测的那条（三条腿都走子进程读磁盘当前代码 ⇒ 改动前的代码即被加载），**不许**再拿这条假事实当旁证。
6. **结构边界（可证，不是疏漏）**：修复是三条腿 —— 前置腿（`wb_land.main()` 里、`_landing.main()` 之前、只读、不一致退 3）、腿①（`pool.landing` ⑤′.5）、腿②（`wb_land` 壳层里、提交**之后**、复核+就地修回+退 4）。**若一笔提交同时改`tools/wb_land.py` 与 `tools/pool/landing.py`，三条腿跑的都是改动前的代码 ⇒ 覆盖不到**。这不是漏写，是「判据宿主自己就是被改对象」的必然结果。工程上的缓解：这种笔落地后主树会留下一处未提交的 README 改动 + 退 4，人重落一条命令即可。
7. 腿② 的**代价**（如实）：它就地把 README 修回一致，改的是**工作区**，与「落地后主树 `git status --porcelain -uno` = 0 行」这条纪律**冲突**。这是拿「静默的错文档」换「可见的脏工作区」，不是免费 —— 前置腿是它的补丁，两者必须同时存在。
