## 要解决的问题

magpie 把每次读到的额度留成一条时间序列，从而能回答「这个号是在回血还是在掉血」「上次续期是什么时候」。本仓 pool **没有任何时间序列**：

- `grep -rniE "curve|曲线|quota_history|QuotaPoint" tools/ scripts/` ⇒ 零命中（`history` 的 18 条命中全在 `tools/pool/task.py`，是任务状态不是额度）。
- 账本 `[account.quota]` 里只有 `observed_at` / `samples` / `source` / `unit` / `amount`；`samples` 各 1 条且形状是 `{"at": <iso>, "kind": <六结论码之一>}` —— **只有结论码，没有数量，没有窗口起止**。
- `tools/pool/holds.py:98-122` 的 `Window(model/span_s/used/resets_at/reset_secs/aside/unlimited/pool/family)` 与 `estimate()`（`:217`，算式 `scale = 100/used`）**分母恒缺**：`used_percent` 全仓**零写方**（只有 `tools/pool_accounts.py:194` 的读与 `:198/:203` 两条越界文案）。

⇒ 今天 pool 只能回答「这个号现在能不能派」，回答不了「它在变好还是变坏」。本卡把 magpie 的**容器与判据**搬过来（历史点、回血检测、剪枝），数据源那一半如实留缺口。

## 判据（8 条，逐条可执行）

1. **新建 `tools/pool/quota_history.py`**（纯判据模块，禁 `print(` / `subprocess` / `os.environ` 之外的副作用；读盘只经 `root` 参数与 `ENV_HISTORY`）。必须有且仅有这些公开名字：
   - 常量：`HISTORY_REL = ("gates", "diag", "quota-history.json")` / `ENV_HISTORY = "TF_POOL_QUOTA_HISTORY"` / `KEPT_DAYS = 45` / `MAX_POINTS = 6000` / `GAP_S = 300` / `SAME_S = 30` / `SLACK_S = 300` / `REFILL_PCT = 5.0`。
   - `@dataclass(frozen=True, slots=True) class QuotaPoint`：`at: int`（unix 秒）/ `left: float`（剩余百分比 0–100）/ `start: int | None = None` / `resets_at: int | None = None`。
   - `def new_cycle(a: QuotaPoint, b: QuotaPoint) -> bool` —— 六支，**顺序即优先级**：
     ① `a.resets_at is None and b.resets_at is None` ⇒ `b.left > a.left + REFILL_PCT`
     ② 只有一个有 `resets_at` ⇒ `True`
     ③ `a.resets_at is not None and a.resets_at <= b.at` ⇒ `True`
     ④ `rolling = moved > 0 and abs(moved - (b.at - a.at)) <= SLACK_S`
     ⑤ `not rolling and abs(moved) <= SLACK_S and b.left > a.left + REFILL_PCT` ⇒ `True`
     ⑥ 兜底 `moved > (b.at - a.at + SLACK_S) or moved < -SLACK_S`
     其中 `moved = b.resets_at - a.resets_at`（两者都有 `resets_at` 时才走到 ④⑤⑥；magpie 里 `moved` 是 `b.ResetsAt.Sub(a.ResetsAt).Seconds()`，**只在两个都有 deadline 时有意义**，本条按此实现并在 docstring 写清）。
   - `def add_point(points: Sequence[QuotaPoint], point: QuotaPoint) -> list[QuotaPoint]` —— 照 `addPoint` 三步：不比最后一个新（`point.at <= last.at` 且 `point.left == last.left`）⇒ 原样返回；`k >= 2` 且相邻都不新周期且 `flat`（相邻两点 `left` 差 `< 0.05`）或 `point.at - p1.at < GAP_S` ⇒ 替换最后一个；`k >= 1` 且 `point.at - last.at < SAME_S` 且 `not new_cycle(last, point)` ⇒ 也替换最后一个；否则追加。**不许原地改入参**。
   - `def prune(points: Sequence[QuotaPoint], *, now: int) -> list[QuotaPoint]` —— `cut = now - KEPT_DAYS*86400`，丢 `at < cut` 的，再取尾部 `MAX_POINTS` 条。
   - `def hist_key(scope: str, account: str) -> str` —— `f"{scope}|{account.lower()}"`（magpie `quotaHistKey` 的小写口径）。
   - `def point_of(window: Mapping[str, object], *, at: int) -> QuotaPoint | None` —— 跳过 `unlimited` / `aside and not pool` / `family` 非空 / `name` 空 / `used` 非数的窗口；`left = round(max(0.0, min(100.0, 100.0 - used)), 2)`；`resets_at`/`start` 有才写（`start` 只在 `span > 0` 时写）。
   - `def load_history(*, root: Path | str | None = None) -> dict[str, list[QuotaPoint]]`（读不出/坏 ⇒ `{}`，**fail-open 不抛**）与 `def save_history(hist: Mapping[str, Sequence[QuotaPoint]], *, root: Path | str | None = None) -> Path`（走 `tools/pool/lastgood.py:98 write_atomic()`，**禁 `Path.write_text`**）。
2. **`REFILL_PCT` 必须是有名字的常量**：magpie 源码里 `5` 是字面量散在三处，本模块给一处名字，反向验证要能把 5.0 改成 0.0 并让钉子红。
3. **一份新判据只写一次**：`new_cycle` / `add_point` / `prune` / `point_of` 的判据**只许活在本模块**。`tools/pool/holds.py` 的 `estimate()` **一个字节不许动**（它是另一个口径：整窗推算，不是历史）。

## 缺口（如实说，不许当成已解决）

1. **今天产出空曲线**：`used_percent` 全仓零写方，四个真账号的 `[account.quota]` 也没有窗口起止 ⇒ 本卡落地后 `gates/diag/quota-history.json` **不会生成**。验的是**判据的判别力**（16 钉子 + 6 变异），不是「曲线真的画出来了」。真正的数据源在探测层（magpie 读的是厂商返回的窗口百分比，pool 的 `_extract_amount` 只拿绝对余额），那是另一张卡。
2. `holds.estimate()` 的分母仍然缺 —— 本卡只提供「历史点」这个容器，**不**替 `holds` 造数。接线是后续卡。
3. 不做 magpie 的 `mergeQuotaHist`（跨机合并）：pool 没有多机共用一份曲线的场景。
4. 不做 `SubscriptionQuota` / `QuotaWindow` / `LineName()` 那一层展示，也不把 `quota-state.json` 并进曲线（那是「现在」不是「历史」）。
5. `point_of()` 的入参形状（`name` / `used` / `family` / `aside` / `pool` / `unlimited` / `span` / `resets_at`）照 magpie 的 `QuotaWindow` 命名，**本仓今天没有任何东西产出这个形状**；本卡只保证「形状对了就能算对」。
