## 判据（六条，逐条给「怎么证明」）

### 判据 1 · 先把「窗口选择」做成一个纯函数，签名固定

新增（或扩充 `tools/pool/holds.py`，**不另立模块**）：

```python
def applies(window: Window, model: str) -> bool
def pick(windows: Sequence[Window], model: str, *, now: datetime) -> Window | None
```

- `applies` 逐字对应 `routing.go:294-296`：`model == ""` ⇒ 全计；否则**子串匹配**（`strings.Contains` 是**子串**，不是前缀、不是 glob —— 不许自己发明匹配规则）。
- `pick` 对应 `Allowance.For`（`routing.go:302-314`）：只在 `applies` 为真的窗口里挑，`used = max(...)`；**`aside` 窗不参与账号级判定**（`account_caps.go:349`）。
- **怎么证明**：`tests/test_holds_window.py` 加钉子 —— ① `model=""` 的窗口对任何模型都 `applies`；② `model="opus"` 对 `claude-opus-4` 为真、对 `claude-sonnet-4` 为假；③ `aside=True` 的窗口在账号级 cap 判定里被跳过（照 `account_caps.go:349` 的三条件逐个断言）；④ **反向**：把子串改成前缀匹配，`model="opus"` 对 `xopus-1` 的断言必须红。

### 判据 2 · 排序侧不许被不相关的窗口抬高

「Opus 的周额度用满不影响 Sonnet」在 pool 侧唯一能落地的地方是**选号/排序**：`tools/pool/gateway.py:431-435` `_order()` → `tools/pool/route.py:669-670` `apply_strategy(name, seats, *, pool, state=None)`。

- **怎么证明**：`tests/test_pool_route.py` 加一条构造用例：两个 `Seat`，一个 `used=100`（来自只计 opus 的窗口），当前请求模型是 `sonnet` ⇒ 该座**不许**被判成 tier 2（用尽）。断言走 `route.usage_tier()`（`tools/pool/route.py:210`）而不是比较排序结果 —— 排序是派生量。
- 若本卡选择**只在选号阶段**做（不扩 `quota-state.json`），这条就是主判据，且必须附一句「数据从哪来」的事实说明（今天：账本 `[account.quota]` 里没有 per-window 段 ⇒ 本判据在真数据上**恒放行**，只能在构造用例上验证）。

### 判据 3 · 未记录 ⇒ 不猜（既有口径一条不许放宽）
