# 卡 E68 —— 白名单里的串必须有产出方：一条死话术把整道 pytest 门判红

> 台账号 `T-AG529` ｜ 分区 E（CI 子系统）｜ 树 `.wt/E68` ｜ 层 判据层
> 依据：2026-10-30 现读主树 HEAD `3bfabad5`（别人那笔 T-BG001）——
> `python -X utf8 -m pytest tests/test_pytest_select.py::test_replay_last_20_commits_has_no_missed_pointer`
> ⇒ `1 failed in 2.25s`；`python -X utf8 tools/pytest_select.py --replay 20 --json` ⇒ `ok=False`，
> 3 笔 fallback 里唯一「原因不认识」的是 `3bfabad5`：
> `闸一：['DSH-技能与插件开发参考.md'] 的条目没有 test: 指针 ⇒ 选集为空 ⇒ 全量`。

## 要解决的问题

1. **白名单是手抄的，产出方是 f-string，两者早就脱节**。
   `tools/pytest_select.py:73`：
   ```python
   KNOWN_FALLBACK_MARKS = (JUDGE_BODY_MARK, "台账里没有任何 test: 指针", "没有登记")
   ```
   而真正会生成这句话的是 `:355`：
   ```python
   f"闸一：{empty_entry[:5]} 的条目没有 test: 指针 ⇒ 选集为空 ⇒ 全量"
   ```
   `台账里没有任何 test: 指针` 与 `的条目没有 test: 指针` 是**两个不同的串**。
   `git log -S'台账里没有任何 test: 指针' -- tools/pytest_select.py` 只有卡 E52 那一笔
   （`dc1ba702`）⇒ 这个串**从写下那天起就没有任何产出方**。`没有登记` 同样是死串
   （`grep` 的其余命中全在 `tools/contrast_audit.py` / `tools/wb_plan.py` 的无关注释里）。
2. **后果不是「少认一种」，而是正常欠账被判成判据失灵**。`replay()` 的 `ok` 里有一条
   `not unknown`（`:466-469`）：只要有一笔 fallback 的原因不在表里，整道门就红。
   T-BG001 那笔是**真的没有 `test:` 指针**（它改的是 `DSH-技能与插件开发参考.md`，
   `tests/` 下零命中覆盖），属于闸一 `empty_entry` 的正常欠账 —— 却被读成「判据自己不认识」。
   于是 E67 的全量门禁 22 门里唯一红的就是 pytest，而病灶不在 E67 的域内。
3. **这个病会随台账增长反复复发**：只要有新的「无 `test:` 指针」条目落进最近 20 笔，
   门就再红一次，而每次都会有人想去改白名单 —— 手抄法天生会再脱节。

## 判据（6 条）

1. **白名单与产出方同源**：`KNOWN_FALLBACK_MARKS` 里除 `JUDGE_BODY_MARK` 外的每个串，
   都必须定义为**常量**，并由 `select()` 的 f-string **直接引用**该常量拼接产出话术；
   产出方里不许再出现与常量字面不同的手抄串。
2. **表里不许有死串**：对 `KNOWN_FALLBACK_MARKS` 的每个串，都能用**真实 `select()` 分支**
   （不是正则、不是手抄）产出含该串的 `reason`。缺场景或多场景 ⇒ 判红。
3. **这次的病灶必须被认**：`replay(20, root=ROOT)` 的**每一笔**真 fallback
   都满足 `_known_fallback_reason(...)`，且 `result.ok` 为真。
4. **反向判据不许被削弱**：卡 E52 的死串 `台账里没有任何 test: 指针` 不许再被认成「认识的原因」；
   没见过的原因（`闸九：…`）仍必须使 `ok` 为假。
5. **行为不变**：`exit_code` / 闸序 / `payload()` 的 JSON 键 / `REPLAY_MAX_FALLBACK = 3`
   一一不动；既有钉子 `tests/test_pytest_select.py:189`（`"test: 指针" in sel.reason`）
   与 `:412`（反向钉子）继续绿。
6. **不许靠改台账蒙过**：不许给 T-BG001 补一条指向不存在用例的 `test:` 证据
   （`tests/` 下没有覆盖那份文档的用例，补就是造假）。
