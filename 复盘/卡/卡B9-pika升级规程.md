# 卡 B9 · 把 pika 升级经验收成一份可复用规程，并让 L3 运行手册层第一次落地

**task**：T-BG011　**risk**：mid　**tree**：主树（纯文档）　**状态**：已完成

## 为什么

pika 2.1.7 那一轮（卡 B1–B8）踩出来的东西散在五处：`复盘/pika迁移-回填方案.md`（操作步骤）、
`复盘/pika迁移-新旧比对.md`（比对读数）、`D:/repo/_tools/pika-迁移/对应表.md`（路径映射）、
同目录的 `宿主与环境变量.md`（环境变量与宿主张力）、以及只在会话里说过、**一次也没落纸**的十几条坑。
结果下一次拿到新 zip 的人得重读 1400 行复盘才能拼出「先做什么、什么顺序不能反」。

用户说（m29171 / m29187 / m29188，paraphrased）：把这套经验总结成**可复用规程**，并把**冲突的旧方案去掉**。

第二个问题：`docs/文档架构.md:71`/`:86` 两处把 `docs/runbooks/` 列为 L3「怎么起、怎么巡检、怎么落地」，
但**这个目录从来没存在过**（`git ls-files docs/runbooks` 空，全仓除那两行外零引用）。
目标布局里有一格是空的，而这次要写的东西正好是那一格的内容。

## 判据（怎么算做完）

1. 规程覆盖「拿到新 zip 之后从零到验收」的完整路径：前置检查 → 三方比对 → 个性化行回填 → 技能替换 → 残留清理 → 验收读数 → 回滚，每步给了命令形状与判据。
2. **每一条坑都带现场**：症状原文（报错/读数）+ 为什么 + 正确做法。不接受「注意 X」这种没有症状的描述。
3. **「不知道」单列一节**，写清是哪一条证据没拿到，不许用推断填空。
4. 附录给旧文档的**逐条去留判定**（保留 / 合并进本规程 / 标记过时），并指出旧文档里与实测矛盾的具体行。
5. 新目录 `docs/runbooks/` 建成后：`scripts/check_layers.py` 末行 `LAYER CHECKS: PASS ✅`；
   `scripts/gen_doc_index.py --check` 退 0；`python -X utf8 tools/wb_plan.py check` 绿。
6. 旧的两份复盘文档**不删**（它们是当时的证据），只在头部加一行指向新规程的注记，写明「操作部分已接管、正文保留为证据」。
7. 规程里不写自己的行数与字节数——自指的量一改就错。

## 不做什么

- 不执行任何迁移动作：本卡只出规程，不比对、不删除、不覆盖任何文件。
- 不改 `tools/pika_migrate.py` 的行为（它仍是 dry-run 脚本，接进规程的 8 步是后续卡）。
- 不动 `D:/repo/知识库/` 与 `C:/Users/example/.dsh/skills/`。
- 不在规程里写会漂的读数（篇数、字节数）当常量；要写就写「带日期的读数 + 算它的命令」。

## 做了什么

- 新建 `docs/runbooks/pika-升级规程.md`（L3 运行手册层的第一篇），九节 + 两个附录。
- 新建 `docs/runbooks/` 目录，`docs/文档架构.md` 里那个 ★ 格第一次有内容。
- `复盘/pika迁移-回填方案.md`、`复盘/pika迁移-新旧比对.md` 头部各加一行注记，指向新规程。
- `docs/workbacklog.toml` 加 B9 块；台账 / changelog / 交接三份片段各一。

操作规程属于 L3（动手时读），不属于 L4（复盘只收事后）；把它放进这个仓里长期空着的
`docs/runbooks/`，比塞进 `skills/` 或留在 `docs/research/` 都更符合本仓自己写的分层。
