# 卡 A311 · 接手判据严格化：判不出就停手（T-AG425）

## 现象

`wb_takeover.py` 的 `kind` 永远有值：没信号就兜底成 C（裸仓）。
于是「真的是裸仓」和「什么线索都没读到」看起来一模一样，agent 很容易照着 C 往下铺骨架，
把「不知道」伪装成「已判明」。用户问「会不会选错路径」——这就是选错路径的入口。

## 做法

1. `tools/wb_takeover.py` 新增 `--strict`：
   - 每个类别必须有一条**正证据**（A：管线文件/三件套；B：测试或 CI；D：别家框架标记；C：目录里真有内容）；
   - 不满足 ⇒ 逐条点名缺什么，退出码 **2**；`--json` 时多给 `strict_ok` / `strict_problems`。
2. `skills/pipe-takeover/SKILL.md` 第一步改成必须带 `--strict`，并写明「退 2 ⇒ 停手，先补读数」。
3. 仓库 `AGENTS.md` 路由表加一行：接手/新起项目 → 先跑 `wb_takeover.py --strict`。

## 验收

- `pytest tests/test_wb_takeover.py` 13 passed（新增 3 条：空目录退 2 / 有 tests 退 0 / JSON 带 strict 字段）；
- 空目录 `--strict` → 退 2 并报「缺：源码 / 测试 / CI / 管线任一信号」；
- 本仓 `--strict` → 类别 A、退 0；
- `scripts/check_layers.py` PASS。
