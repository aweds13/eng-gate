## 要解决的问题

`tools/pool/sink.py` 是按 magpie 的 sink 沉底逐字移植的（卡 A331 · `T-AG533`，已落地），但它自己的文件头**逐字写着**：

> 本模块**不接线**任何派活流程：`tools/wb_dispatch.py` 一行不改（那是另一张卡）；

也就是说，今天全仓**没有一个生产调用方**：`grep -rn "sink_order\|sunk_at\|should_sink" tools/ --include=*.py` 在 `tools/pool/sink.py` 之外零命中，只有 `tests/test_pool_sink.py` 在钉它。判据在、牙也在，但**派活器从来不看它**。

实际后果：`tools/wb_dispatch.py:3989` 的 `nxt = next_whitelist_model(model, pool)` 走的是**静态链序** —— 它不知道谁刚被 429 沉过。于是同一个刚撞过限流的模型，只要链序轮到它，就还会被再挑一次；而 `sink_order()` 已经会算的那个「先沉的排后面」的稳定序，没有任何人用。

## 判据（7 条，逐条可执行）

1. **沉与不沉的分界线只有一条：`sink.should_sink(kind, routing)`**。`tools/wb_dispatch.py` 里判定「这一次要不要沉」必须**只调**它，不许自己再写一遍 `kind == "限流"`；`kind` 取 `quota_error()` 的 `quota.get("kind")`（`"限流"` / `"余额耗尽"`）。`余额耗尽` 走不通是因为 `should_sink()` 内部就把它排除了（`sinks(on, routing) and kind == KIND_RATE`），**不许**在调用侧另加旁路。

2. **`routing` 的真实取值**：本仓今天**没有** `routing` 配置项（magpie 的 `rotate / weighted / manual` 在 pool 里零命中）。所以调用侧一律传**常量 `"order"`**（= magpie `Ordered`，`sinks()` 对它的判定是 `True`），并且必须在 `tools/wb_dispatch.py` 的那一段里**用一个具名模块级常量**写下它（例如 `SINK_ROUTING = "order"`），注释写明「本仓没有可配的 routing，将来有人真加配置时改这一个常量」。**不许**把它写成内联字面量散在判据里。

3. **沉的位置**：在 `tools/wb_dispatch.py:3978` 那行 `probe_ok, probe_why = quota_probe_ok(node, cli, model)` **之后**、`:3989` `nxt = next_whitelist_model(model, pool)` **之前**，且只在 `if not probe_ok:` 这个分支里。理由逐字照设计原件：探针通了说明「已经好了」，不该沉；探针仍挂才说明「这个 key 现在真的不能用」。**不许**沉在 `:3958 if attempts > args.retry:` 之前（那一支是硬轮次，与沉底无关）。

4. **沉谁**：`key` 必须写成 `sink.sunk_at()` 认的两段式形状 `<account>/<model>` —— 账号级用主循环的 `account_id`（`tools/wb_dispatch.py:3318` 的稳定 id，**不是** `--account` 收到的 profile 名）；`account_id` 为空时（没给 `--account`）用**空账号**那一档的可读 key（见判据 5），**不许**退回 profile 名或 `""`（`""` 会让 `_lookup` 的 `"/"` 分支猜错）。取下一个模型时要认**同一套 key**：`sink.sunk_at(key_of(m))` 对每个候选 `m` 都要能查。

5. **`account_id` 为空时的行为**：仍然沉，key 用 `f"/{model}"`（账号段为空、带斜杠 ⇒ `sunk_at()` 会先查 `"/<model>"`（模型级原文）、再按 `"/"` 分割取 `""` 查账号级 —— 两条都能查到）。这一档必须有一条钉子证明「没给 `--account` 时沉了也能被 `sunk_at()` 读回来」，**不许**因为账号为空就整个静默跳过（那会让「不接线」换个形状继续存在）。

6. **「全沉了就停」必须走**已有的停路，不许新开退出码。判定放在 `nxt` 算出来之后：把 `rotation_chain_for(pool)` 从 `nxt` 开始到末尾的**整个尾巴**（含 `nxt` 自己）逐个查 `sink.sunk_at(key_of(m))`，**全都非 None** ⇒ 把 `nxt` 置 `None`，然后落进 `:3990 if nxt is None:` 那条既有的停路（退出码 7、`release_tree("额度全挂 → 任务停下")`）。尾巴里只要有一个没沉过，就照旧换过去。**不许**只查 `nxt` 一个 —— 那只会在链尾逐个试错，正是「同一个刚撞限流的模型被再挑一次」的成因。

7. **`tools/pool/sink.py` 的行为一个字不改**：本卡只改它的**文件头那段「不接线」的说明**（改成「已接线到 `tools/wb_dispatch.py`，见卡 A351」+ 保留「『有配额却 429』是本仓证明不了的假定」这句**逐字保留**），以及 `SINK_REL` 之后按需加一个 `key_of(account, model) -> str` 的纯函数（若调用侧需要；不需要就不加）。`sink() / sunk_at() / unsink() / unsink_all() / sink_order() / sink_last() / sinks() / should_sink()` 八个函数的**签名与行为一字不动**，`tests/test_pool_sink.py` 21 条钉子必须照旧全绿。
