实测三档（tools/pytest_select.py::replay，主树）：

| 窗口 | fallback 笔数 | 说明 |
|---|---|---|
| 20 / 30 / 40 / 50 / 60 | 0 | 最近 60 笔全是立卡与台账记账提交 |

最近一笔判据本体提交 = b8545049，git rev-list --count b8545049..HEAD = **62**。

## 2. 病灶：窗口按「总提交数」计数，而 fallback 是事件

replay() 的 fallback 只有两种来源（tools/pytest_select.py:59-82 的 JUDGE_BODY_FILES / JUDGE_BODY_PREFIXES 与两个台账特征串）：

1. 这一笔碰了判据本体 ⇒ 必须全量（设计如此，不是欠账）；
2. 这一笔的台账条目没有 test: 指针 ⇒ 覆盖率欠账。

两者都不是「每笔提交都有」。所以「最近 N 笔里有几笔 fallback」这个口径，只要历史里连续 N 笔都是记账提交，就必然量到 0 —— 而这几笔记账提交的存在与判据本身无关。卡 E68 的修法（20 → 逐档放大到 60）只是把空转周期拉长，**没有改口径**。这在 2026-11-17 再次发生：62 笔连续记账提交（E100–E126 的立卡与落地笔）把 60 撑破。

## 3. 为什么上次不敢把窗口放大

因为贵：replay() 每笔起**两次**子进程（git show --name-only + git log -1 --format=trailers）。Windows 上每次约 0.086 s ⇒

| 窗口 | 旧实现耗时 |
|---|---|
| 20 | 5.4 s |
| 100 | 17.7 s |
| 300 | 49.7 s |

⇒ 卡 E68 只能用「20→60 的折中」。**放大窗口的前提是先把取数变便宜**。

## 4. 判据

### 判据 1：批量取数只许是加速，不许是第二真相源

tools/pytest_select.py 新增纯函数：

```python
def log_batch(count: int, root: Path | None = None) -> dict[str, tuple[str, tuple[str, ...]]]:
```

一次 git log -z -<count> --name-only --format=… 取回「每笔的 Task trailer + 改动文件」，按 rev 建索引。解析不出来的记录**不进**返回值（调用方按「缺的那笔回落逐笔读」处理）。

钉子 test_log_batch_agrees_with_the_per_commit_reads：取最近 5 笔，逐笔断言 batch[rev][1] == git_changed(rev) 且 batch[rev][0] == git_task(rev)。

### 判据 2：replay() 真走批量，且保留逐笔回落

replay() 里 git_changed / git_task 只在「批量里查不到这一笔」时才调。
钉子：monkeypatch 包一层计数，跑 replay(5) 断言 log_batch 被调 1 次、git_changed 被调 0 次。

### 判据 3：窗口上界放大到能覆盖真历史

tests/test_pytest_select.py 的 REPLAY_PROBE_STEPS 从 (20, 30, 40, 50, 60) 改成 (20, 40, 60, 80, 120, 200, 300)。实测（批量版）replay(20) 0.12 s / (60) 0.22 s / (100) 0.37 s / (300) 0.42 s；七档阶梯在真历史上停在 80，全档 ok=True。

### 判据 4：把「上界够不够」变成被检查的事实，而不是运气

新增钉子 test_the_probe_upper_bound_still_reaches_a_judge_body_commit：用一次 git log（限 JUDGE_BODY_FILES + JUDGE_BODY_PREFIXES）算出最近一笔判据本体提交到 HEAD 的距离 behind，断言 `behind < max(REPLAY_PROBE_STEPS)`，红时原文要念出 behind 与上界。

理由：空转的病根是「上界与历史长度赛跑」。这条钉子把赛跑结果变成一次断言 —— 上界不够时它**先红**，而不是等 assert seen 用「最近 60 笔一笔 fallback 都没有」这种看不出原因的话红。它也不贵（一次 git log，约 0.1 s）。

### 判据 5：反向变异 ≥4（每条真改真跑真还原，记 sha256）

| # | 变异 | 必须咬住 |
|---|---|---|
| A | replay() 改回逐笔 git_changed + git_task（批量只留着不用） | 判据 2 的计数钉子 |
| B | REPLAY_PROBE_STEPS 上界改回 60 | 判据 4 的上界钉子（今天 62 > 60） |
| C | log_batch 解析时吞掉 NUL 分出来的文件（回空列表） | 判据 1 的逐笔比对钉子 |
| D | 判据 4 的距离改常量 0（自欺） | 判据 4 的上界钉子 |
| C1 | 只改注释（安静对照） | 不许红 |

读数落 gates/diag/_rev_E127_result.txt，脚本放**主树** gates/diag/_rev_E127.py（ROOT = __file__.parent.parent.parent）。
