# 卡 E41 —— 号池判决不许把 429 读成「正常收工」（T-AG506）

## 1 疼点（实测，不是推断）

`tools/wb_watch.py` 的 CodeBuddy 一路是**只看文件非空就算收工**：

```python
if verdicts:
    text = verdict.read_text(...)
    if text.strip():
        line, code, dur = _parse_verdict(text)
        return CardSignal(card, FINISHED, "codebuddy", line, code, dur, ...)
```

于是「工人其实被 429 挡住、回话为空、退出码 0」这一趟只要落了判决文件，看守就把它判成
**FINISHED**（假绿）——主控以为这张卡跑完了，人去读日志才发现模型一句没吐。

`tools/wb_dispatch.py:1472` 早就有判据（卡 029 / 045）：`quota_error(lines)` 里那道
**候选闸门**只让 `subtype == "error_during_execution"` / `is_error` 为真 / 回话为空的
`result` 事件进入额度判定。**问题不是没判据，是判据没被看守复用**——
`wb_watch` 压根没导入它，只看「文件非空」。

## 2 要做成什么样

1. **单一真源**：`wb_watch` 判 CodeBuddy 的收工时，必须调 `wb_dispatch` 那一份判据
   （`quota_error` + `_parse_verdict`），不许另写一套「非空即完成」。
2. **判决文案 → 三态**：`wb-<卡>.verdict.txt` 的内容按三类归：
   · 正常收工（无 429 痕迹，且有非空回话证据）⇒ `FINISHED`
   · 额度类（限流 / 余额耗尽，文案由 `quota_error` 的 `why` 点名）⇒ `DEAD`，`detail` 带
     「额度：<why>」，并写 `state:"quota"` 事件进 `notifications.jsonl`
   · 判不出（空文件 / 半截写 / 只有退出码）⇒ `RUNNING` 或 `DEAD` 按 `classify_job_state`
     的静默时长判，**不许**判 FINISHED
3. **退出码永不作为依据**（既有口径）：日志里那句「退出码 0」只写进 detail，不参与判定。
4. **码道池同源**：`_probe_codearts` 的 `finished=true` 也要过同一道额度判据——
   meta 里 `errors`/`verdict` 命中额度类 ⇒ `DEAD` 而不是 FINISHED。

## 3 判据（每条要钉子）

1. 造一个「429 判决文件」⇒ `probe_card` 返回 `DEAD`，`detail` 含「额度」；反向：把判据
   改回「非空即完成」⇒ 该钉子红（写清红样）。
2. 造一个「正常收工判决」⇒ 仍 `FINISHED`（不许把好卡判死）。
3. 空判决文件 ⇒ 不判 FINISHED（既有反例钉子不许动，往里加这条）。
4. 码道池：meta `finished=true` 但 `verdict` 含「额度」⇒ `DEAD`。
5. `tests/test_wb_watch.py` 里 `FINISHED` 的断言必须同时断言「没有额度痕迹」——
   防止以后有人只改文案不改判据。
6. 判据唯一性钉子：`wb_watch.py` **不许**出现第二份额度 needle 列表（AST 扫字符串常量，
   额度类短语只能在 `wb_dispatch` 里）。

## 4 不许做

- 不许把「退出码 0 就算成功」写回来（卡 029 已经踩过）。
- 不许在 `wb_watch` 里复制一份 needle 列表 —— 那就是第二套判据。
- 不许把额度失败算成 `FAILED`（`FAILED` 是「卡做错了」，额度是「这趟没跑」，处置不同）。
- 不许改 `wb_dispatch.quota_error` 的两道闸门（卡 045 的判据）。

- 假绿现场：`tools/wb_watch.py` 的 `_probe_codebuddy`（非空即 FINISHED）。
- 号池台账：`docs/subsystems/pool/事后判据清单.md`（判决口径一节要跟着改）。
