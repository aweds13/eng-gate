## 现场（2026-10-03 09:57 实拍：主控落一笔**纯文档**提交，被全量门禁拦下）

```
FAILED tests/test_wb_dispatch.py::test_model_gate_refuses_an_unknown_model_with_zero_side_effects
```

用例把「表外模型」**写死**成 `kimi-k3-1`（`tests/test_wb_dispatch.py:1672`）。而用户 **2026-10-03 在开关文件里把 `kimi-k3-1` 打开了**
（`infra/pool/model-switches.toml`，原话「默认关闭，这是开启」）⇒ 它**不再是表外模型**。

**主控复核（原样命令、两条对照，都做过）**：

```
python -X utf8 tools/wb_dispatch.py --card 000 --model hy4-preview --execute
  ⇒ [FAIL] 未授权模型，已拒绝派活：hy4-preview（真表外，行为对）
python -X utf8 tools/wb_dispatch.py --card 000 --model kimi-k3-1 --execute
  ⇒ 直接走到「派活得给 --spec」⇒ **模型闸放行了它**
```

⇒ **红与那笔提交无关**，它是「**数据一开，判据就变红**」；**单跑该用例也复现**（与 worker 数无关，已排除 `TF_PYTEST_WORKERS=1` 的干扰）。

## 真因（两条，都要治）

1. **用例把样本写死成「可被数据打开」的名字** ⇒ 用户改**仓外**一份数据，门禁就红，而红得**对不上任何一次改动**。
2. **沙箱管不住仓外的开关文件**：开关文件在 `infra/`（**本仓外**），用例的 `sandbox` fixture 隔离不到它
   ⇒ 用例读的是**真机那份** ⇒ **门禁结果依赖机器状态**（换台机器、换个用户设置，结果就变）。

## 要做的（★ 只动用例；产品逻辑只许在报备后动）

1. **用例自己控制输入面**（两种都要）：
   - 从**有效允许集**里算出一个「**确实表外**」的名字（名单常量 + 开关集之后再挑），**不许**再写死某个具体名字；
   - 把开关**读取**打到夹具上（`monkeypatch` 开关路径或其读取函数），夹具写在 `tmp_path` 里 ⇒ **沙箱真的封闭**。
2. **补正向钉子**（现在的用例只钉了「表外被拒」，缺另一半）：
   - 「开关里写 `X = true` ⇒ `X` **必须被放行**」（证明开关真的生效）；
   - 「开关文件**读不到 / 坏掉** ⇒ **默认拒绝不变**」（黑名单锁死那条令）。
3. **不许**：改 `infra/pool/model-switches.toml`（**用户地盘**）、放宽任何白名单、把内存闸阈值改成 `0`、删用例、跳过门禁。
4. **台账**：`复盘/不变量台账.toml` 加一条不变量（claim 大意：**门禁的判据必须自控输入面，不许依赖仓外可被用户改的数据**），
   `judge` 指本用例所在文件、`nail` 指你新加的钉子用例名；`status` 按实情（有判据 + 有钉子 ⇒ `covered`）。
   ★ 加完必须跑 `python -X utf8 tools/wb_invariants.py --check`，**要看到它核过你那一条**。
