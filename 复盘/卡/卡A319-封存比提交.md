# 卡 A319 —— 封存比对「比提交，不比字符串」（T-AG433）

**树**：`.wt/A319` ｜ **base**：`ef9d254` ｜ **风险**：mid

## 现象

补账务时全量门禁红一条：

```
FAILED tests/test_wb_review.py::test_current_head_passes_the_gate_evidence_check
  ["门禁不是为这一笔跑的：last.json 的 rev='94d343c'，而这一笔的父提交是 '94d343cc'"]
```

`94d343c` 与 `94d343cc` 是**同一笔提交**。判据拿字面量比短 sha，而 git 的 `--short`
长度随仓库变大而变（同一笔在一处给 7 位、另一处给 8 位），于是「同一笔」被判成「两笔」。
后果不是假绿，是**假红**：落地链卡死，且看起来像"有人跑完门禁提交了两笔"。

## 修法

`tools/wb_review.py`：

- 新增 `_resolve_commit(short)`：`git rev-parse --verify <short>^{commit}` 拿完整 sha，解析不出返回空串。
- `check_gate_evidence()`：先比字面量（合成 sha 的用例仍可用），不等则**比解析后的完整 sha**；
  两边都解析不出 ⇒ 仍判红。
- 这不是放宽：仍然要求「同一次提交」，只是不许拿字符串长度当判据。

## 钉子

`tests/test_wb_review.py::test_short_sha_length_does_not_break_the_evidence_check`：

- 拿 `parent[:7]` 对 8 位父提交 ⇒ **不许**报「门禁不是为这一笔跑的」。
- 拿 `HEAD~2` 对父提交 ⇒ **必须**报。

同时把 `test_current_head_passes_the_gate_evidence_check` 自己的字面量断言改成比提交。
