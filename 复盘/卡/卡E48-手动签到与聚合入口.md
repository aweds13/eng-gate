# 卡 E48 —— 手动签到与聚合入口（T-AG497）

> 形态已由用户定形（m11666）：「我让你签，你再统一签到」，并且要「有个聚合入口给我快速签完所有的到」。
> 所以本卡做**拉取式**：一条命令跑完所有平台，不做后台定时、不做自动重试。

## 1 为什么不做定时

定时签到是最容易踩平台风控的形态，参考实现也都把写动作关在双重闸门后面：

- `dsh-codearts-auth` 的领取探针要 **`DSH_CODEARTS_E2E=1` 且 `DSH_CODEARTS_CLAIM_E2E_CONFIRM=yes`** 同时成立，
  否则整体 skip、零网络调用（`tests/e2e/*-claim-probe.e2e.spec.ts` 四份都这样）；
- 它的 `codearts-credits-probe.e2e.spec.ts` 与 `codearts-credits-claim` 是**两个文件**，只读探针绝不领取；
- `dsh-credit-hub` 的错峰调度是为「多账号高频轮转」设计的，我们只有 ≤5 个号、每天一次，收益远小于风险。

结论：**用户不开口，一个领取请求都不发。**

## 2 命令与输出

```
python -X utf8 tools/pool_accounts.py checkin --all                 # 先探后签，一次跑完全部平台
python -X utf8 tools/pool_accounts.py checkin --all --probe          # 只探不签（今天领没领 / 还能不能领）
python -X utf8 tools/pool_accounts.py checkin --platform codearts    # 只签一个平台
python -X utf8 tools/pool_accounts.py checkin --all --json           # 机器可读（给 MCP / 后续卡用）
```

一张表打屏 + 一份留档：

```
平台        账号         结论              详情
codearts    codearts-3   claimed           +100 积分（活动 2026-10）
workbuddy   wb-1         already-claimed   今天已领
trae        trae-1       not-supported     上游无签到接口
qoder       qoder-2      uncertain         凭据过期（未重放）
minimax     mm-1         inactive          非积分类账户
```

留档落 `gates/diag/checkin-<YYYYMMDD>.json`（gitignored），字段与 `--json` 同形，并回写账本的
`[account.quota].samples` 与 `[account.health]`。

代码分两处：`tools/pool_accounts.py` 只是入口（解析参数、打表、写留档），
各平台领取客户端统一放 `tools/pool/checkin.py`（**写动作只在这一个模块里**，判据 10 的静态扫描就扫它）。

## 3 结论码（六态，抄参考实现的 `ClaimOutcome`）

| 码 | 含义 | 算不算故障 |
|---|---|---|
| `claimed` | 刚领到，附 `+N <unit>` | 否 |
| `already-claimed` | 今天已领 | 否 |
| `inactive` | 账号不在活动范围（如 Token 计费账户、非积分类） | 否 |
| `not-supported` | 上游确实没有这个接口（HTTP 404 / 端点不存在） | 否 |
| `uncertain` | 凭据或网络不明，**结果未知 ⇒ 不重放** | 需人看 |
| `failed(code, msg)` | 上游明确报错 | 是 |

三条硬规矩：

1. **幂等**：先查状态/活动列表，已领直接返回 `already-claimed`，绝不重发领取请求。
   各平台判据不同，必须按能力表写死，不许「统一当成没有 Claimable 就领」：
   codearts 看活动 `claimable`/`status`；qoder 领取成功后列表**仍非空**；minimax 是 `is_today && status === 3`。
2. **一次一不重试**：串行、每号一次、平台之间 2 s 间隔；429/5xx 记 `uncertain` 就停，不连环打。
3. **每次动作留痕**：何时 / 哪个号 / 跑的是 `--probe` 还是真领 / 结论码，写进留档 JSON 与账本 `last_probe`。

## 4 实现顺序（逐个平台打穿，每步一条钉子）

1. **codearts**（第一个做，唯一有批准模型且端到端有参考实现）：
   签名（`SDK-HMAC-SHA256`，`X-Security-Token`）→ `statistics/plugin` 判 `is_credit_package`
   → `/v1/ops/delivery?channel=IDE` 取 `campaignId` → `/v1/ops/claim` → 若响应 `id !== null` 补 `/v1/ops/confirm`。
   钉子：用**假 fetcher** 回放四段真实响应形状，断言（a）非积分账户直接 `inactive` 不发 claim
   （b）`id !== null` 时 confirm 被调用（c）confirm 缺失路径必须失败（反向验证）。
2. **workbuddy**：`checkin-activity-status` 404 ⇒ `not-supported`（钉子钉这条）。
3. **trae**：`ug` 两步；额度单位是 credits。
4. **qoder**：`campaigns` → `claim`（空体）；**同一天第二次跑必须 `already-claimed`**（钉子模拟领取后列表仍非空的响应）。
5. **minimax**：`timezone_id` 必填；`base_resp.status_code != 0` 即使 HTTP 200 也判 `failed`（钉子）。
6. `lobsterai` / `opencode`：**只进能力表，不实现**（opencode 上游无签到；lobsterai 本机无账号）。

## 5 聚合入口（只读，两处）

- `tools/wb_daily.py` 的今日一页加一行：`今日签到：0/4 已领（跑 tools/pool_accounts.py checkin --all）`，
  数据只读 `gates/diag/checkin-<YYYYMMDD>.json`（当天没有就写「今天还没跑」）。
- MCP 只读工具 `checkin_status`（`tools/pool_mcp.py`）：参数 `date?`，返回当天留档摘要；
  **永不触发签到、永不联网**（只有 `checkin --apply` 那一处能写远端状态）。

## 6 判据（每条都要有钉子）

1. `checkin --all --probe` **一个领取请求都不发**：钉子用会抛异常的 claim 客户端 monkeypatch，断言全绿且结论码齐全。
2. 同一账号连跑两次：第二次结论是 `already-claimed`（五个平台各一条钉子）。
3. 六种结论码都能被造出来（表驱动钉子），且 `--json` 与打屏表同源。
4. 留档文件真的落盘，路径含本地日期，内容可被 `json.load` 读回；重复跑同一天**覆盖而不追加**。
5. `uncertain` 之后**不自动重试**：钉子断言同一进程内该号只出现一次请求。
6. 平台间隔 ≥2 s：钉子用假时钟断言两次平台调用之间的 `sleep` 参数（不看墙钟）。
7. 账本写回 `[account.quota].samples` 与 `[account.health]`；`claimed` 才追加样本，`uncertain` 只涨 `consecutive_failures`。
8. `wb_daily` 那行：当天无留档 ⇒ 打「今天还没跑」；有留档 ⇒ 打 `x/y 已领`；钉子用一个假留档目录。
9. MCP `checkin_status` 不联网、不写盘：monkeypatch 网络与 `open(..., "w")`，断言都没被调用。
10. 真领取的**入口唯一**：`grep -c "claim" tools/pool_accounts.py` 里所有写动作都在 `checkin_apply()` 之内，
    钉子断言「除 `checkin_apply` 外没有函数调用 claim 客户端」（静态 AST 扫）。
11. 反向验证：把 codearts 的 confirm 步骤注释掉 ⇒ 对应钉子必须红。
12. `pytest tests/test_pool_checkin.py tests/test_pool_accounts.py -q` 全绿；`ruff` 清；`check_layers` PASS。

## 7 不许做

- 不做定时任务、不做 `--auto`、不做「今天还没签就自动签」。
- 不并发（串行即可，5 个号 × 1 次）；不重试；不换号重放（换号是 E45/E41 的活）。
- 不伪造结论：探不出就 `uncertain`，上游没有就 `not-supported`，不许把 `inactive` 写成 `claimed`。
- 不把凭据、cookie、token 写进留档 JSON（只写 `id` 与结论码）。
- 不在云机上跑签到（凭据不出本机）。
