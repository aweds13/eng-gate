# 卡 E60 —— 两把尺子各自说各话：封存指纹的 `-f`、复核脚本的 `blocking`

> 台账号 T-AG518 · 分区 E（CI 子系统）· 树 `.wt/E60` · 风险 mid
> 依据：卡 B-20261052 落地（`5885f28f`）之后复核这一笔，`tools/wb_review.py` 报 3 条
> FAIL。逐条查下去，**两条是真缺陷**，而且都属同一类病：**同一件事有两把尺子，
> 两把尺子给出不同答案，没人钉住它们必须一致**。

## 要解决的问题

1. **`tree_without_gates()` 在 `rev != HEAD` 时静默退化，封存指纹变成整棵树的别名**。
   `scripts/run_gates.py:817` 的 `git rm -r --cached --ignore-unmatch --quiet gates`
   **缺 `-f`**。`read-tree <旧 rev>` 建出来的临时索引里，`gates/` 下的条目与工作区、
   HEAD 都不一致（`gates/last.json` 每趟都被改写），git 于是以
   `error: the following files have staged content different from both the file and the HEAD`
   **拒删并退 1**；而返回值**没人看** ⇒ `write-tree` 返回含 `gates/` 的**整棵树**。
   后果不是"少摘一个文件"，而是 `last.json.tree` 这条「摘掉 gates 的固定点」定义被
   悄悄换成「完整提交树」，自指解药失效。
   实测（14 笔）：不加 `-f` 时 **13/14 笔退 1**；加 `-f` 后 `gates/` 真被摘掉。
2. **`wb_review.py` 与门禁对「什么叫红」判得不一样**。
   `scripts/run_gates.py:1495 gates_ok()` 只数 `blocking` 门；
   `tools/wb_review.py:234` 却是 `bad = [g for g in payload.get("gates", []) if g.get("exit_code") != 0]`
   —— **无条件**把所有非零都当红。于是 `web_live exit_code=3 blocking=false status=NOT RUN`
   这一道「没验证」的门，门禁侧判绿、复核侧判红，同一份 `last.json` 两个结论。

## 追出来的另外三处（同一个病，修第 2 条时顺手全仓扫出来的）

把「按 `exit_code` 判红」的每一行扫了一遍，又挖出**三处同样的漏看 `blocking`**，
其中一处会让**云机根本起不来**：

| 处 | 病 | 后果 |
|---|---|---|
| `scripts/cloud/run_gate.sh` 播种判定（第 2/5 步） | 内联 python 只判 `exit_code not in (0,)` | **任何带 NOT RUN 门的真·全绿读数都被判「不绿」⇒ 云门禁起不来**。而 `gates/last.json` 长期带 `web_live exit_code=3 blocking=false` ⇒ 上云永久卡死 |
| `tools/wb_verify.py:204` `check_gates()` | `nonzero = [g for g in gates if g.get("exit_code") != 0]` | 独立复算器与门禁侧结论相反 |
| `framework/src/framework/review.py:133` `check_gate_evidence()` | 同上无条件判 | framework 侧同一判据，同病 |

**共性才是本卡真正的收获**：一份 `last.json` 被 5 个地方读，没有一处钉住
「必须说同一句话」。所以只把这 5 处改对**不够** —— 下一次还会有人写下第六处。

## 判据（六条）

1. **`-f` 在位，且旧 rev 一定摘得干净**：`git rm ... "--quiet", "-f", "gates"`；
   钉子 `tests/test_gate_fingerprint.py::test_old_rev_still_has_gates_stripped`
   用**上一笔提交**当 rev，断言 ①指纹 ≠ 完整树 ②指纹树里无任何 `gates/` 条目
   ③完整树 == 该 rev 的 tree。**反向验证过**：临时撤掉 `-f` ⇒ 该钉子红，
   报 `AssertionError: rev 不是 HEAD 时 gates/ 没被摘掉 —— 封存指纹变成完整树的别名`。
2. **两把尺子给出同一结论**：`wb_review.py` 的判据加 `and g.get("blocking", True)`
   （**缺字段按阻断算** —— 宁可多报，不许把老产物里的真红漏成绿）。
   钉子两条：`test_not_run_gate_is_not_red_but_a_real_red_still_is`（NOT RUN 不计红 /
   缺 `blocking` 字段按阻断 / 显式 `true` 照报）与
   `test_real_last_json_reads_the_same_way_on_both_sides`（读**真** `gates/last.json`，
   复核侧结论必须等于门禁侧 `gates_ok()`）。
3. **不许用「本轮无漂移」搪塞**：本卡不把 `5885f28f` 的 3 文件漂移洗白 ——
   那是**真漂移**（封存于 `50e9a6c8` 之后我又补证据并 amend），如实留档，
   待下一趟门禁重跑时自然对齐。
4. **云机播种判定与 `gates_ok()` 同口径**：`run_gate.sh` 的内联 python 改成
   `if g.get("blocking", True) and g.get("exit_code") not in (0,)`，并**点名**非阻断非零门。
   钉子 `test_seed_check_reads_the_same_way_as_the_gate`：真 `gates/last.json` 必须退 0，
   且必须点名 `web_live`（不许隐瞒）；把任一阻断门改红 ⇒ 必须退非零。
   **反向验证过**：撤掉 `blocking and` ⇒ 该钉子红。
5. **`wb_verify` 与 `framework/review` 同口径**：两处各加 `and g.get("blocking", True)`。
   钉子 `test_wb_verify_and_framework_really_run_their_own_ruler` 直接调**真函数**
   （不重抄判据、不 eval 源码片断），喂三份 payload（真读数 / 无 `blocking` 的老产物 /
   只有 NOT RUN），断言它们的结论必须等于 `gates_ok()`。**反向验证过**：撤任一处 ⇒ 红。
6. **不许再写下第六处（防复发）**：`test_no_exit_code_ruler_forgets_blocking` 全仓扫
   「按 `exit_code` 判红却没用 `blocking`」的可执行行，一处都不许有。扫出但**不是**判红的行
   必须进 `_NOT_A_RED_RULER` **并写明理由** —— 现在三条：`run_gates.py:1469`
   （"要不要印这段输出"）、`:1538`（docstring 里的说明文字）、`:2567`（"只有全绿的门才可复用"，
   比 `blocking` 更严）。`test_the_allow_list_is_not_stale_and_says_why` 钉住白名单自己：
   理由空 / 行号越界 / 那一行已经不是判据 ⇒ 红（不许悄悄膨胀成"什么都放行"）。

## 不许做

- 不许把 `-f` 换成 `--force` 之外的写法绕过（`--cached -f` 就是 git 给的正解）。
- 不许让 `blocking` **缺省按不阻断**：老产物没这个字段，那样会把真红漏成绿。
- 不许为了让复核绿灯而改 `gates/last.json` —— 那是门禁产物，不是给复核调色的。
- 不许把这条钉子的 `rev` 写成 `HEAD`：那就是原来那三条钉子，咬不到这个洞。
