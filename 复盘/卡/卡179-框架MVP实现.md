## 你要产出什么

**① 核心库**（能被 `import`，不 print、不 `sys.exit`、不读全局状态）
- 配置加载：读 `pipeline.toml`，**schema 校验**（照设计的字段），**缺键 / 拼错 / 未知键一律明确报错**，**不许静默兜底默认值**（这是本仓 `harness/manifest.py` 已经立过的口径，照搬）。
- 门（gate）执行器：按配置跑各道门，**并发**、**每门硬超时**、**每门记输入面**、**结果落盘**。
- ★ **三值判决**：每道门的结果只能是 **`pass` / `fail` / `inconclusive`**；★ **`inconclusive` 不许当成 `pass`**，也**不许**与「没跑（`not-run`）」混为一谈。集合为空（没有任何测试被收集到）必须是 **`inconclusive` 或 `fail`**，**绝不许绿灯**。
- 卡与屏障：卡的登记 / 认领 / 权威域 / 完成申报，照设计的字段与目录。
- 退出码：★ **严格照卡 177 的退出码表**（`0` 绿 / `1` 门红 / `2` 用法错 / `3` 资源闸拒跑 / `124` 硬超时），并写清哪些码是**我们发的**、哪些是 **shell 发的**（126 / 127 / 128+N 不是我们）。

**② 薄 CLI**（`pipe`）
- 只做**参数解析 + 调库 + 打印**；业务逻辑一律在库里（★ 判据：**把 CLI 删掉，库仍然可测**）。
- 命令面**照卡 178 的设计**（至少 `init` / `gate` / `doctor` / `card new` / `claim` / `land` / `ledger check`）。
- ★ **每条命令都要有 `--json`**：**人读的文案**与**机器读的结构**分开，且 **`--json` 的输出必须稳定**（字段名进 schema）。

**③ 模板仓**（`pipe init` 铺出来的骨架）
- 至少含：`pipeline.toml`（带注释）、`gates.d/`（或设计指定的形态）、一份**空的账本与不变量登记册**、`docs/` 的骨架、一份 `README`。
- ★ `pipe init` 必须**幂等**：同一个目录连跑两次，第二次**要么明确拒绝、要么结果逐字节相同**（不许悄悄覆盖用户改动）。

**④ 反例钉子（本仓的老规矩：判据随件走）**
- 每条**核心判据**都要自带**反例夹具**：★ 尤其是**三值判决**那一条 —— 必须有一个「**测试一条都没收集到**」的夹具，断言它是 `inconclusive` **而不是绿**。
- 钉子跑在**框架自己的**测试里（`framework/tests/`），**不接进 timeflow 的门禁**（那一步是卡 181 的自举）。
