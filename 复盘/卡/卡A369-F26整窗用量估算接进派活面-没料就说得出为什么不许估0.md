## 判据（六条，逐条给「怎么证明」）

### 判据 1 · 唯一判据源：整窗算式只许 `pool.holds.estimate`

新接线模块 / 新读数块**只准调** `holds.estimate()` 与 `holds.holds_bounds()`，不许抄 `scale = 100 / used`（`tools/pool/holds.py:254`）与五因顺序。理由同 `tools/pool/limits_check.py:8-9` 的「判据只许写这一份，不许各写一份 if」。

**怎么证明**：tests/test_holds_wiring.py（计划建）::test_only_one_scale —— 用 `ast` 扫新模块，断言源码里**没有** `100 /` 这种字面除法、且 `estimate`/`holds_bounds` 至少被调用一次；反向变异 M2 见判据 6。

### 判据 2 · 没有 `used_percent` 时不许估（本卡的核心判据）

- 生产路径上，账本 `[account.quota]` 缺键 / 是 `None` / 非有限数 ⇒ 该窗口读数必须是 `why == "-"` 且 `tokens == 0` 且**带上 `why_text`**；**不许**出现 `used=0.0`、`why == "low"`、或「`tokens=0` 但 `why==""`」（后者等于宣称「估出来了，整窗就是 0」）。
- 且 `0` 与 `None` 必须分得开：`0` 在账本层就被 `_check_used_percent()`（`tools/pool_accounts.py:259-263`）挡住（除以零），所以到 `holds` 手里只可能是 `None` 或 `>= 0` 的**真读数**；`holds_bounds()` 对 `None` 与 `NaN` 都回 `"-"`（`:200-202`）。
- **怎么证明**：三条钉子 ——
  ① `test_missing_used_is_dash_not_zero`：造一个没有 `used_percent` 的账本（`tmp_path` + `TF_ACCOUNTS_TOML`），读数行的 `why == "-"`、`tokens == 0`、`why_text` 非空，且**断言 `why != "low"`**（体例照 `tests/test_holds_window.py:144`）；
  ② `test_zero_used_is_refused_at_the_ledger`：`used_percent = 0` 写账本 ⇒ `LedgerError`（复用 `_check_used_percent`，不另写判据）；
  ③ `test_real_ledger_all_dash_today`：拿**真账本**跑一遍，五个号**全部** `why == "-"` —— 这条不许被「造一份假数据让它变绿」绕过（见判据 6 的 M3）。

### 判据 3 · 读数面：整窗读数进「一份读数」，缺料时把因念出来
