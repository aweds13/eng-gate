## 要做什么（就一件，落在**派活前置检查**里）

在 `tools/wb_dispatch.py` 的前置检查（`preflight`）里**加一条**：

> **卡树的基点之后，主树有没有改过这张卡要碰的文件？**
> - 取卡树 HEAD = `A`（`git -C <cwd> rev-parse HEAD`）、主树 HEAD = `B`；
> - 若 `A == B` ⇒ 放行；
> - 否则算 `git diff --name-only A..B -- <本卡的域（队列 `files` / `--allow`）>`：
>   - **结果为空**（基点之后主树只改了别的文件）⇒ **放行**（别误伤：多批并行时这很常见）；
>   - **结果非空** ⇒ **拒**，并**点名**：那些文件 + 涉及的提交（`git log --oneline A..B -- <files>` 的原文），
>     以及**修法**：「这张卡的树建早了 ⇒ 把树 rebase/重置到主树 HEAD 再派（`git -C <树> reset --hard <B>`
>     会丢未提交改动，**先 `git status` 看清楚**），或重建一棵树」。
> - ★ 域从哪来：与**既有守卫同源**（队列里该卡的 `files`）—— 查不到域时**沿用既有口径**（既有守卫已经会拒），
>   本卡**不许**另造一份域来源。

## 硬要求

- ★ **不许放宽任何既有前置**（内存 / 登录 / 模型白名单 / 日志 / 树 / 域 / 锁 / 项目 —— 哪一条都不许动）。
- ★ 这条判据**只拒不猜**：算不出 `A`/`B`（不在 git 树里等）⇒ **如实说"算不出基点，跳过这条判据"并继续**
  （★ 别把"算不出"当"过期" —— 那会把好卡全拒了）。
- ★ 复用现成的 git 调用风格与错误输出风格（照同文件里既有的前置检查写）。
