# 卡 E62 —— 一条都没挑中的时候不许说全绿：`--only` 空真与三道门的不对称

> 台账号 T-AG520 · 分区 E（CI 子系统）· 树 `.wt/E62` · 风险 low
> 依据：product 档 11 道门的自证（T-AG515 卡的 subagent 交付
> `gates/gate-selfproof-product.toml`）记下一条「盲区」，本卡把它坐实。
> 主控 2026-10-28 亲自复现（不是转述），原文见下面 §1。

## 要解决的问题

1. **`render_check.mjs --only` 匹配不到任何视图时退 0，还打一句自相矛盾的 OK。**
   现场复现（HEAD `ab66da19`，`node tools/render_check.mjs --only 根本没有这个视图`）：
   ```
   [OK ] 0 份清单与黄金逐字节一致（3 档宽度 × 14 个视图 + 1 个浮层）
   渲染验证层通过 ✅
   退出码=0
   ```
   同一行里既说「0 份」又说「14 个视图」，然后判通过。
   病灶：`tools/render_check.mjs:335` 的过滤
   ```js
   if (ARGS.only && ARGS.only !== view) continue
   ```
   把 15 个视图全部 `continue` 掉 ⇒ `pass1` 空 ⇒ 落到 `:532` 的
   `if (changed.length || gone.length)` 判据（0 与 0 ⇒ 不进入）⇒ `:558` 打印
   `pass1.size` = 0 的 OK 行 ⇒ `result.code = 0`。
   上游还有一层**先被空真喂饱**的：`:487` 的
   `[OK ] 确定性自检：${pass1.size} 份清单各采两遍，逐字节一致` 在 `pass1` 为空时
   同样打 `0 份…逐字节一致` —— 两遍空集合当然一致。所以复现输出里**有两行 OK**，
   不是一行（现场原文见 §1）。修判据 1 时这两行都要一起管。
   **`--only` 是给人调试用的**（`:505-507` 注释写明），但它的**拼错代价是「这条门等于没跑，
   却报通过」** —— 与卡 E60/E61 同一个病：判不出来的时候当没事。

2. **同一族的两道门判据不对称。** `tools/ui_flow_check.mjs:2068` 对同样的情形是退 1：
   ```js
   if (ARGS.only && selectedFlows().length === 0) {
     console.log(`❌ --only「${ARGS.only}」一条流都没匹配上。现有这些：`)
     ... 列出全部流名 ...
     return { ...result, code: 1, notes: ['--only 没匹配到任何流'] }
   }
   ```
   一道门（ui_flow）说「一条都没挑中就红」，另一道门（render）说「挑中 0 个就绿」。
   **没有任何一处钉住这两道门对同一件事说同一句话。**

3. **门禁表里两道门都是「可复用 + 允许 not_run」的同一档。**
   `scripts/run_gates.py:484` `REUSABLE = ("render", "ui_flow", "lf1_live", "web_live", "ui_dom_probe")`。
   所以「`--only` 拼错」这件事在门禁里表现为**绿**而不是 `not_run`，比 `not_run` 更坏 ——
   `not_run` 至少会被 `gates_ok()` 与播种校验看见（卡 E60 刚把这条修对）。

4. **同类空真还有一处要一起查。** `render_check.mjs` 的 `--seed-only` 是「起服务就停」，
   按设计不判；但 `--only` 与 `--update` 合用时（`:123` 已禁止，除非 `--force`），
   `--force --only <拼错> --update` 会走到 `:514 if (ARGS.update)` 分支：
   `changed` 与 `gone` 都是空（`--only` 时 `gone` 被 `:508` 跳过），于是
   `:524` 往 `gates/render/LAST_UPDATE.md` **追加一条「0 份改动」的假记录**并退 0。
   这条要一并钉住。

## 判据（四条）

1. **零匹配必须红。** `render_check.mjs` 在 `--only` 生效且「这次挑中的视图数 == 0」时
   必须退非零（用 `1`，与 `ui_flow_check.mjs` 一致），并把**现有全部视图名**打出来
   （照 `ui_flow_check.mjs:2069` 的体例），一行 `❌ --only「<原样参数>」一个视图都没匹配上。现有这些：`
   + 逐行列出。钉子 `test_render_only_with_no_match_exits_nonzero`：真跑 node 脚本
   （注入一个必然不匹配的 `--only`），断言退出码 != 0 且 stdout 含那句原文与至少
   一个真实视图名。**不许只断言「有报错」** —— 必须点名。

2. **匹配到就必须真的采到。** `--only <真实视图名>` 时 `pass1.size` 必须 > 0；
   若 `--only` 匹配上了但采集为空（例如视图已从界面移除、`collectView` 抛错被吞），
   也不许退 0。钉子 `test_render_only_with_a_real_view_captures_at_least_one`：
   `--only today` ⇒ `pass1` 至少 1 份（3 档宽度 ⇒ 3 份），且退出码 0。
   这条与判据 1 配对：**「红」和「绿」两侧都要有真读数**，否则撤掉判据 1 时
   判据 2 靠 `--only today` 的旧行为也能过（空真钉子自己也会空真，见卡 E61 的教训）。

3. **两道门的判据必须写在一处、被一条钉子钉住一致。** 新增
   `tests/test_only_selector_parity.py`：静态读 `tools/render_check.mjs` 与
   `tools/ui_flow_check.mjs` 的源码，断言两边**都有**「`--only` 零匹配 ⇒ 返回 code 1」的分支，
   并且两边的退出码取值相同（都 `1`）。做法照卡 E60 判据 6 的 `_NOT_A_RED_RULER` 体例：
   白名单为空且是对的 —— AST/正则扫出但**不是**这条语义的行必须进白名单并写明理由。
   钉子 `test_the_allow_list_says_why` 钉住白名单自己（理由空 / 行号越界 ⇒ 红）。

4. **`--update` 不许写出空记录。** `--force --update --only <零匹配>` 时：
   不许写 `gates/render/LAST_UPDATE.md`、不许退 0。判据 = 零匹配在**写之前**就拦下
   （判据 1 的检查位置必须在 `:514 if (ARGS.update)` 分支之前）。
   钉子 `test_force_update_with_zero_match_writes_nothing`：沙箱里跑，断言
   `gates/render/LAST_UPDATE.md` 的字节一字不变且退出码非零。

## 交付

- `tools/render_check.mjs`（零匹配检查 + 报错文案 + 检查位置在 `--update` 分支之前）
- `tests/test_only_selector_parity.py`（新文件：四条判据的钉子 + 白名单自证）

  从「未修」改成「已修 + 卡号」，并把三条盲区里仍然成立的两条留着）

## 反向验证（四条，逐条实测）

把每处判据**临时撤掉**再跑新钉子，必须咬住：

| 撤掉什么 | 咬到哪条钉子 | 判据 |
|---|---|---|
| 零匹配检查那一段 | `test_render_only_with_no_match_exits_nonzero` | 退出码变 0 + OK 行回来 |
| 把检查挪到 `if (ARGS.update)` 之后 | `test_force_update_with_zero_match_writes_nothing` | 先写了空记录再红 |
| `ui_flow_check.mjs` 的零匹配分支（改成退 0） | `test_only_selector_parity.py` | 两侧不对称 ⇒ 红 |
| 全仓扫描钉子本身（造一处假写法） | `test_the_allow_list_says_why` | 白名单自证红 |

★★ 反向验证的写法要求（照卡 E61 的教训）：**「退非零」必须配一份「不撤回就退 0」的对照**。
`render_check.mjs` 里还有别的 `return` 早退路径（node 不在、假时钟没钉住、
确定性自检失败都抛异常），单独断言「退出码 != 0」可能被**邻近的别的守卫**喂饱。
所以每条反向验证都要先记录「撤回前 `--only today` 是 0、`--only 乱写` 也还是 0」这个
**基线读数**，撤回后再看它翻成非零 —— 两次读数都写进卡里。

## 不许做

- 不许把 `--only` 直接删掉（它是 `:505-507` 注释写明的调试入口，删了会逼人去手改黄金）。
- 不许让 `--only` 零匹配时退 3（NOT RUN）—— `not_run` 在这一档门里会被
  `REUSABLE` 与播种校验当成「不算红」，那正是本卡要消灭的静默。
- 不许顺手改 `--update --only --force` 的既有语义（它是明确要求 `--force`
  的危险用法；本卡只要求零匹配时**不写**）。
- 不许只改 `render` 不管 `ui_flow` 的对称性 —— 判据 3 就是为这条写的。
