## 前情：原件为什么收 415，又为什么那条禁令在 E94 之后必须重判（逐字证据）

★ 本节出现的 magpie 侧文件一律相对仓外 _ext/magpie-main/（普通文字，不进反引号）。

- 原件同时做三件事：**认 Content-Encoding**、**解码**、**对解码后的长度归责**。request_bounds.go:99-116 逐字（节录）：

```go
switch enc := strings.ToLower(strings.TrimSpace(r.Header.Get("Content-Encoding"))); enc {
case "", "identity":
	// 原样
case "zstd":
case "gzip", "x-gzip":
default:
	return nil, fmt.Errorf("%w: magpie can't read a %q body; send it as identity, gzip or zstd", errBodyEncoding, enc)
}
```

  拒到调用方那一刻是 415：request_bounds.go:198-201 逐字 `if errors.Is(err, errBodyEncoding) {` ⇒ `reject(http.StatusUnsupportedMediaType, err)`。注意它把 `Content-Encoding` **从请求头上删掉**（:118 `r.Header.Del("Content-Encoding")`）—— 因为解压之后它就不再是「已编码」了。
- 413 那半是**解码后**的长度，且文案明确指向「这是网关的限制，不是 provider 的」：request_bounds.go:267-273 注释逐字「says a body is over magpie's own limit, and that it is magpie's, not the provider's: an agent shows the message as it comes, and a bare "Payload Too Large" read as the model's or the vendor's (#1422)」。512 MB 的取值理由在 :21-27 逐字「The limit is on the decoded body. … a long session that read many images went past 128 MB decoded and got magpie's 413 on every retry, while the same turn is a fraction of that on the wire (NeoPengZhile, #1422). 512 MB leaves such a session room and still bounds what one request may hold in memory.」
- 解压的**真实调用方**是 Codex 那条路：codex_zstd.go:70 `func CodexCompressed(req *http.Request, body []byte) int`，:74-81 逐字 `if enc := req.Header.Get("Content-Encoding"); enc != "" && !strings.EqualFold(enc, "identity") {` / `return len(body) // already encoded: as Codex, never twice`。
- ⇒ **本卡只搬「认头 + 415」这半格，绝不搬解码。** 理由有三条，其中两条来自**本仓自己上一轮的禁令**（仓外 _port_design_wave5.md:669-675「#### 不许做什么」逐字节录）：「**不许**搬 `defaultBodyLimit = 512 << 20` 与 gzip/zstd。那是 HTTP 请求体，pool 的入站是 stdio 一行，倍的量级不同。抄 512 MB 当行上限等于没有上限。」「**不许**搬 415（媒体类型）：stdio 没有 `Content-Type`。」
- ★ 立论支点：那两条禁令的**理由句**是「stdio 一行」与「stdio 没有 Content-Type」。E94 之后，pool 多出四条**回环 HTTP 面**（`tools/pool/gateway.py:103-108` 的 `PATHS` 四键）—— 入站**不再是 stdio 一行**，也不再「没有 Content-Type 可言」。⇒ 判 PORT 不是忘掉禁令，是**按 HTTP 面重判**；这也是本卡**推翻同一编号上一轮的自己**，理由与保留意见写在前情与「诚实边界」第 4 条。

## 本仓现状（`e7d0dda0` 实读）

**一句话：入站根本没人看 `Content-Encoding`（任何值都被静默忽略），压缩体读进来只是普通字节、于是被报成「你的 JSON 坏了」—— 今天真正缺的是「明确地拒绝」，不是「解压」。**

1. **入站头今天只读四处，没有 `Content-Encoding`、也没有 `Content-Type`**：`Origin`（`tools/pool/gateway.py:1111`）、`Authorization`（:1115）、`Content-Length`（`_post` 开头）、`X-Pool-Caller`（`_post` 末段）。本卡实跑 `grep -n self.headers tools/pool/gateway.py` 复核，与这四处一致。

3. **413 的钉子已经咬着**：`tests/test_pool_gateway.py:721` `test_http_body_over_limit_is_413`（`start_server(stub, max_bytes=64)`，发 65 字节，断言 `response.status == 413` + `stub.calls == []`）。

## 判定

**PORT（窄口）—— 只落入站 `Content-Encoding` 的 415，零解压。**

落什么：入站带 `Content-Encoding`，且其值（`strip` + 大小写不敏感，照 request_bounds.go:99 的 `strings.ToLower(strings.TrimSpace(...))`）**既非空、也非 `identity`** ⇒ 回 **415**，文案说清「本网关不解压，请用 identity 重发」。判定在读体**之前**（头部足够判，读都别读），且在 `_gate` **之后**（鉴权先行）。

| F7 的块 | 本仓判定 | 理由（逐字证据） |
|---|---|---|
| 认 `Content-Encoding` 并拒掉认不出的编码（415） | **PORT（本卡做）** | 四条回环 HTTP 面真存在（`tools/pool/gateway.py:103-108`）；今天任何 CE 值都被**静默忽略**（见「本仓现状」第 1、5 条），压缩体被误诊成「JSON 坏了」。只判**头部字面值**，不解析任何自由文案。 |
| gzip / zstd **解码** | **不做（本卡明确拒绝）** | ①没有压体调用方（CE 与压缩库全 0 命中）；②接 zstd 要新依赖（`pyproject.toml:9` `requires-python = ">=3.10"`，标准库 `compression.zstd` 要 3.14）；③解压=给回环口加一个**内存放大面**（同机任意进程都能打；本仓纪律一路收窄：`tools/pool/gateway.py:86-87` 逐字「只认回环。**没有例外**：不给 0.0.0.0 开口子」、:88 独立 token）；④两个上限**不可换算**（magpie 512 MB 是**解码后**，本仓 32 MiB 是**线上**，:92 逐字「照 `pool_mcp.MAX_LINE_BYTES`（32 MiB）」）。 |
| 512 MB 上限与「解码后归责」 | **不做** | 同上第 ④ 点；`grep -c 512` 两份文件各 0，本卡**不许**让它变成非 0。 |
| 入站 `Content-Type` 校验 | **不做** | 今天也从不校验（本卡不新增这条语义）；415 只由 CE 触发。 |

**为什么不是 SKIP_BY_REDLINE**：不是协议互译（那是 `tools/pool/gateway.py:8-14` 第 1 条硬边界讲的东西）；**不解析自由文案**（只判头部的字面值，:23 / :199 讲的是**上游答复体**）；不是定时器、不是凭据发现、不复制门禁判据、不碰 `PATHS`、不写 agent 配置。**为什么不是 SKIP_NOT_APPLICABLE**：四条回环面真存在，`gates/diag/_magpie_scope.md:15` 也已把 F7 标成 PORT/partial，且起草时的活体探针复现了「压缩体被报成坏 JSON」。

**价值方向（写在这里，免得被当战功）**：网关今天**没有编排者** —— `tests/test_pool_gateway.py:1291` `test_f36_port_8766_is_declared_once_and_not_orchestrated` 逐字钉着 `source.count("8766") == 1`、`"gateway" not in stack`、`"8766" not in lock`，且 :1294 的 docstring 逐字「★ 「以为 stack.py 会起它」是空想：网关今天只能手工 `python tools/pool/gateway.py` 起。」⇒ 本卡修的是**诊断质量**（让误用得到准确的话），**不是线上故障**。

## 判据（6 条，每条都能用一条 pytest 或一条命令证明）

### 判据 1 · 415 落地：非 identity 的编码一律 415，identity / 空值照旧放行（**本卡新做**）

**怎么证明**：新增 `test_content_encoding_is_415`（真 socket）。正面：`_request(port, "POST", "/v1/chat/completions", body={"model": MODEL}, headers={"Content-Encoding": "gzip"})` ⇒ `status == 415`、`stub.calls == []`、响应体文本同时含 `Content-Encoding` 与 `identity`（文案把「请用 identity 重发」说清）。反面：`identity` / `Identity` / `""` 三值 ⇒ **`status != 415`** 且 `stub.calls == []`。边界：`" gzip "`（带首尾空白）、`"GZIP"`、`"br"` 三值 ⇒ **都必须 415**。

★ 反面那三值**只写「不是 415」**，不写死「等于 403」：今天走到后面会因为「号池没批这个模型」回 403（夹具现象，见「诚实边界」第 7 条），把 403 写进断言等于把夹具的偶然当契约。

### 判据 2 · 415 不扩 `_ERROR_KIND`，走 `api_error` 兜底（**一半是新做、一半是既有兜底的钉子**）

**怎么证明**：


★ 这一条是**有意的取舍**：给 415 单独一个 error type 会让「六键闭集」变成七键、并顺手扩了对外契约（那张表是**回话形状**，不是内部枚举）。落到 `api_error` 兜底既不改表、也不丢信息（`message` 里说清了是编码问题）。

### 判据 3 · 零解压：源码里没有压缩库、也没有解压动作（**本卡新写的断言**）

**怎么证明**：用既有的 `tests/test_pool_gateway.py:1158` `_gateway_source()` 与 :1164 `_string_constants(tree)`：

### 判据 4 · 上限与既有 413 一字不动，`512` 不许进源码（**既有行为的钉子**）

**怎么证明**：


### 判据 5 · 不校验入站 `Content-Type`（**既有事实，钉它别被顺手加进来**）

**怎么证明**：`_request(..., body={"model": MODEL}, headers={"Content-Type": "text/plain"})` ⇒ `status != 415` 且 `stub.calls == []`。

★ 为什么单独钉：添 Content-Type 校验看起来是「顺手做对的事」，但它会把「一个能被现有调用方使用的网关」变成「需要重新对表头的网关」，而且**没有任何原件依据**（magpie 那侧拒的是**编码**，不是媒体类型）；真正的媒体类型判据在 `_magpie_features.md` 的 MCP 面，与本卡无关（见「诚实边界」第 5 条）。

### 判据 6 · 顺序钉子：鉴权先于编码判定（无 Bearer + gzip ⇒ **401**，不是 415）

**怎么证明**：`_request(port, "POST", "/v1/chat/completions", body={"model": MODEL}, token=None, headers={"Content-Encoding": "gzip"})` ⇒ `status == 401` 且 `stub.calls == []`；再来一次合法 Bearer + `Content-Encoding: gzip` ⇒ `status == 415` 且 `stub.calls == []`。

★ 这一条**防的是「把 CE 检查挪到 `_gate` 之前」**：那样一个连令牌都没带的请求会先被告知「本网关不解压」—— 等于把网关的能力面白送给外部。今天的顺序是既有的（`tools/pool/gateway.py:1143` `_dispatch` 里 `if not self._gate(): return` 在 `self._post(...)` 之前），本卡只钉不改。
