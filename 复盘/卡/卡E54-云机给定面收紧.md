## 2. 判定

三条独立的**可移植性缺陷**，都长在"给云机喂什么"这一层：

1. **依赖面不同源**：本机靠 `pip install -e .[dev]`（pyproject 单一真源），云机靠 bootstrap 里手抄的清单 ⇒ 加一个 dev 依赖就两侧漂移。
2. **仓外配置过渡供给**：`scp *.toml *.json` 把本机**私有账本**与**私有模型开关**推上云机；这两样不是门禁判据需要的输入，却是若干用例的判据输入 ⇒ 云机结论被本机私有状态污染。
3. **树陈旧无人拦**：`run_gate.sh` 不在开跑前断言"远端 HEAD == 目标 commit"，于是拿旧树判新队列，还会把结论写回 `last.json` 的 `rev`（与目标不符时靠人肉看出来）。

## 3. 要做成什么样（判据）

1. `scripts/cloud/bootstrap.ps1` 装依赖**只走一个真源**：`pip install --no-deps -e .` + `pip install -e ".[dev]"`；不再保留手抄清单里与 extras 重复的项（pytest/ruff/mypy/httpx/psutil/fsrs/hypothesis 全部由 extras 供给）。钉版本仍留在 bootstrap（`TF_CLOUD_PIN=1` 时用 `==` 钉死），但**清单来自 `pyproject.toml`**。
2. `scripts/cloud/run_gate.sh` 的仓外配置供给改成**白名单**：
   - 只推 `projects.toml`（项目索引，由模板渲染）与 `models.whitelist.toml`（模型白名单，判据需要）；
   - **不推** `accounts.toml`、`model-switches.toml` 及任何其它文件；
   - 铺之前**清掉** `$pool_cfg_dst` 里的旧账（除白名单外全部删除），否则上一趟残留继续污染；
   - 本机缺 `models.whitelist.toml` 时**fail fast**（退 5）并说明"判据需要它"，不许静默少喂。
3. `scripts/cloud/run_gate.sh` 新增 **`0.2/5` 树一致性断言**：远端 `git rev-parse HEAD` 必须等于本次目标 commit（`git rev-parse $card_tree_HEAD`），不等就 fail fast（退 7）并打印两边的 sha 与"是否缺少 fetch/patch"。
4. `tests/test_cloud_sync.py` 加钉子（至少 5 条）：
   - bootstrap 里**不再出现**手抄依赖清单（扫源码：`pip install` 行必须含 `.[dev]`；出现 `pytest==` 这类硬编码行 ⇒ 红）；
   - `run_gate.sh` 的 scp 行**不含** `*.toml` 通配、且不出现 `accounts.toml` / `model-switches.toml`；
   - 白名单缺失时 `exit 5`；
   - 头一致性断言存在且 `exit 7`；
   - 清旧账那步在白名单之外的文件上生效（用临时目录模拟）。
5. 反向验证（各留红样进 `gates/diag/E54-*.log`）：
   - 把 `-e ".[dev]"` 改回手抄清单 ⇒ 判据 4 第一条红；
   - 把 scp 白名单改回 `*.toml` ⇒ 判据 4 第二条红。
6. 云机复跑（同一 commit）：`pytest` 与 `mypy` **双 exit 0**，`last.json` 的 `rev` == 该 commit；红单数 0（`test_replay_*` 那 1 条由 `dc1ba70` 已修，须一并消失）。

## 4. 不许做

- **不许**为了让云机变绿去改任何单元测试的断言（本卡只改"喂给云机什么"）。
- **不许**把 `accounts.toml` / `model-switches.toml` 也当"判据需要"推上去 —— 私账不进云。
- **不许**在 `run_gate.sh` 里加"树不一致就警告继续"的软档：必须 fail closed。
- **不许**把钉版本整段删掉（两侧仍要同版本，只是清单来源改成 extras）。
