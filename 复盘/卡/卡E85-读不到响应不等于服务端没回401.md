# 卡 E85 —— 「没读到响应」不许说成「服务端没回 401」（T-AG592）

> 台账号 `T-AG592` ｜ 分区 E（门禁与可信度）｜ 树 `.wt/E85` ｜ 层 判据层
> 基准提交 `bb6c6479`（主树 HEAD）。

## 要解决的问题（已实测，不是推测）

云门禁 E84 那趟（`gates/diag/cloud-e84-payload.json`）22 门只有 `web_live` 一门红：

```
name=web_live exit_code=1 seconds=24.3
summary="[FAIL] 手机直传：没配对传不进来（401）"
其余 19 条全 [OK ]（含「局域网：没配对读不到数据（401 + 原话）」「局域网：配对后能读数据」）
```

而**服务端那一刻确实回了 401**（云机 `.wt/E84/gates/logs/web_live.log`）：

```
{"ts":"2026-11-04T12:26:25", …, "path":"/api/sync/import", "status":401, "ms":0.7}
```

八个探针在云机 `C:/eng` 上跑过（脚本在 `gates/diag/`，scratch 不入库；逐条读数见
`gates/diag/_e84_weblive_probes.md`）：

- 真门禁入口 `web_live_check.main()` 连跑 6 轮 ⇒ 6 轮全绿，每次
  `POST /api/sync/import -> 401 (11~12ms, 无码)`；
- 8 个 CPU 压载进程 × 100 次、4 压载 × 40 次、12 线程 × 6 次 ⇒ 100% 拿到 401；
- 裸 socket 发完 body 后故意延迟 0/50/200/500/1000 ms 再读 ⇒ 五种延迟都读到
  `HTTP/1.1 401 Unauthorized`；
- 只有把 body 放大到 **3.2 MB** 才稳定复现「客户端拿不到状态码」：
  `3200035 B → ['0','0','ConnectionResetError']`。门里那份 body 只有 **2917 B**。

结论（区分事实与推测）：**机制确定存在** —— 服务端中间件 `src/timeflow/api/app.py:303`
在没读请求体的情况下就回 401 并关连接，客户端还在写大 body 时撞 `ConnectionResetError`；
`tools/web_live_check.py:851-852` 的 `except OSError: return 0, None` 把它洗成「连不上」，
判据 `nopair[0] == 401` 于是看到 0，门报出一句**指向错误方向**的话（「没配对传不进来（401）」
失败），实际是客户端根本没读到响应。**现场那一趟的真正成因没有复现出来**，本卡不猜测它，
只负责让下次发生时门说的是实话。

## 判据（7 条）

1. **三种失败必须分得开**：`_lan_json()` 只许在「请求根本没送到服务端」
   （`ConnectionRefusedError` / `socket.gaierror` / `ENETUNREACH` / `EHOSTUNREACH`）
   时返回 `(0, None)`。凡是「连上了但没读到响应状态行」（`ConnectionResetError`、
   `ConnectionAbortedError`、`BrokenPipeError`、`http.client.RemoteDisconnected`、
   以及 `HTTPError` 已拿到状态码但读 body 失败之外的其它 OS 层中断）
   **一律抛 `LiveCallError`**，`.kind` 保留原始异常类名。
2. **有界重试只给「一个字节都没读到」那一类**：只在**没有拿到状态行**时重试一次
   （`TF_WEB_LIVE_RETRY` 可置 0 关掉，缺省 1）；重试仍不成 ⇒ 抛 `LiveCallError`。
   已拿到状态码的调用**不许**重试（那会把「服务端回了 4xx/5xx」改成「再打一次」）。
   重试在本仓是安全的，理由写进代码注释：本函数打的都是幂等 GET 与
   `/api/sync/import`（后者由门里「同一份包再传一次是幂等的」那条判据守着）。
3. **判据本身一个字都不许放宽**：`tools/web_live_check.py` 里
   `checks["手机直传：没配对传不进来（401）"] = nopair[0] == 401` 这行**原样保留**；
   不许写成 `in (401, 0)`、不许 `or`、不许把 `LiveCallError` 提前吞掉。
4. **新增一份测试**（文件名在下面代码块里，主树尚不存在）：
   至少 5 条钉子，全部**真起服务或真造 sockets**，不用 monkeypatch 假装成功：

   ```
   tests/test_web_live_read_failure_is_not_401.py
   ```

   必须覆盖：①拒连 ⇒ `(0, None)` ②连接被重置 ⇒ `LiveCallError` 且 `.kind` 是原始异常名
   ③重置后重试成功 ⇒ 返回 401 且**只**重试了 1 次 ④`TF_WEB_LIVE_RETRY=0` ⇒ 不重试、
   直接抛 ⑤已拿到 401 时**不重试**（计数器证明只发了一次请求）。
5. **`live_lan_checks` 的收口不许退化**：某一步抛 `LiveCallError` 时，已经算出来的
   `checks` 一条都不许丢，并且要补一条点名 False（卡 E71 的既有行为）。新增一条钉子，
   断言「重试后仍读不到 ⇒ 结果里出现 `局域网：有一步没等到（POST …/api/sync/import）`
   这一条，且**不出现**把责任推给 401 的那条」。
6. **既有钉子一字不动全绿**：`tests/test_web_live_lan_timeout.py`（卡 E71，15 条）
   与 `tests/test_web_live_timeout.py`（卡 E67）原样通过，本卡**不修改**这两个文件。
7. **行尾与静态检查**：`tools/web_live_check.py` 改后仍是纯 CRLF
   （`bareLF == 0`）；`ruff check tools/ tests/` 全绿。

## 反向变异（≥5 条，每条都要真改坏 → 跑 → 咬住 → `finally` 还原 → sha 核对）

- **M1** 把「连上了但没读到」那一支改回 `return 0, None` ⇒ 判据 1 的钉子必红。
- **M2** 把重试次数从 1 改成 0（等于永不重试）⇒ 判据 2 的「重置后重试成功」钉子必红。
- **M3** 把重试次数改成 2 ⇒ 判据 2 的「只重试一次」钉子必红。
- **M4** 让「已拿到 401」也走重试 ⇒ 判据 2 的「不许重试已拿到状态码的调用」钉子必红。
- **M5** 把 `nopair[0] == 401` 放宽成 `in (401, 0)` ⇒ 判据 3 的钉子必红。
- **M6** 在 `live_lan_checks` 的 `except LiveCallError` 里把已算出的 `checks` 清空
  ⇒ 判据 5 的「一条都不许丢」钉子必红。
- **C1（对照）** 只改注释文字 ⇒ 按设计**不**咬住。
