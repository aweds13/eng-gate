# 卡 E13 · 批集成的成员匹配按卡号精确对齐（T-AG464）

## 现在疼在哪（实测）

1. 攒批第一例 T-AG460（成员 E8 / E9 / G1）落地时，批集成树 `.wt/batch460` 里**冒出了卡 F1 的三个文件**：
   `docs/migration-map.json`、`tools/migrate_docs.py`、`tests/test_migrate_docs.py`（`git -C .wt/batch460 status --porcelain` 实测）。
2. 根因在 `tools/pool/landing.py:1341-1344`（`_integrate_multi_tree`）：

   ```python
   key = re.sub(r"\D", "", cid_val)
   for mid in card_files_map:
       if mid == cid_val or (key and re.sub(r"\D", "", mid) == key):
   ```

   `G1` 的数字键是 `1`，backlog 里 `F1`（还有 `E1`、`B1`、`D1`）的数字键也是 `1` ⇒ 这些**不是成员**的卡被认成成员 G1，
   把 `.wt/F1` 的改动合进批树。后果：别人的活被夹进这笔批提交，且 ⑤′ 白名单必然判「计划外」。
   当时的绕开办法是 `git worktree move .wt/F1 .wt/F1.off`（临时把树移走让集成跳过），不是修复。
3. 同一函数的历史注释（`:1334-1340`）已经记过一次同族事故（`cfiles` 自己跟自己求交），说明**匹配口径反复出错**。

## 你要做的事

把「backlog 里的卡块 ↔ 批成员」的匹配改成**不猜**的口径，并补钉子。

## 判据（机器可判）

1. **精确优先**：`mid == cid_val` 命中即用，不做任何模糊匹配。
2. **数字回退必须唯一**：只有「恰好一个候选成员的数字键等于该卡的数字键」时才允许回退；候选多于一个 ⇒ 打印点名并**停手**（`return False`，不许猜、不许跳过静默继续）。
3. **成员树必须是它自己的树**：`tree_val` 必须等于 `f".wt/{mid}"`（或与该成员在栅栏里的树一致），否则打印「<卡> 声明的树是 X，但成员 <mid> 的树是 Y ⇒ 停手」并 `return False`。
4. **报行带证据**：集成时逐成员打印 `id / 树路径 / 基点 / 改动文件数`（现有格式保留），并新增一行汇总「参加集成的树：A、B、C」。
5. **不改** `--batch` 其它语义（成员翻账、⑤′ 白名单、冲突停手规则一律不动）。

## 钉子（`tests/test_wb_land.py`，≥3 条）

1. backlog 里同时有 `F1`（`.wt/F1`，有改动）与成员 `G1` ⇒ 集成**只**合 `.wt/G1`，断言 `.wt/F1` 的文件一个都没进批树。
2. 两个成员的数字键相同（如 `E1` 与 `G1` 同时在栅栏里，且都指向 `.wt/E1` / `.wt/G1`）⇒ 报行里必须出现「数字键撞车」，且函数返回 False。
3. 正常三成员（E8/E9/G1 各自 `.wt/<卡>`）⇒ 仍能合入、返回 True。

## 不许做

- 不许把「数字键撞车」降级成只打印继续（那样批里还是夹别人的活）。
- 不许为了绕过而改 `--allow` 或 ⑤′ 白名单（白名单是护栏）。
- 不许动 `flip_batch_member_statuses()`（成员翻账另有钉子）。
