# 卡 A289 · 首屏秒开：不拿「读数中…」挡首帧（T-AG403）

## 问题

- 客户端 `SourceShell` 在 `state.status === "loading"` 时**整块只画** `<p>读数中…</p>`，
  所以任何一次读数慢，用户先看到的就是一行字（实测桌面实例 59137）。
- 客户端**零缓存**：装好的 `lib/client.js` 里 `localStorage` / `cache` / `stale` 命中数为 **0**，
  每次切页都从零取数。
- 宿主读数实测：`/dsh-panel/stack-status` **2.15 s**（内部 spawn `tools/stack.py status` 探 5 个端口），
  `/dsh-panel/workbench-board` 0.44 s，`/dsh-panel/zentao-gantt` 0.18 s，`/dsh-panel/timeflow-inbox` 0.15 s。
- 对照：DSH 内置页首帧即有内容，因为它们不等 HTTP —— 差异在**渲染策略**，不在网络。

## 改法

1. **客户端 stale-while-revalidate**（`tools/dsh_panel.py` 的 `useSource` / `SourceShell`）：
   - 首帧同步读 `localStorage`（键含 route，带时间戳）→ 有旧值就直接渲染旧值 + 「上次读数 hh:mm」；
   - 同时后台 `fetch` 刷新，成功覆盖并回写；失败保留旧值 + 状态点变红 + 原话（HTTP 码/异常）；
   - 无缓存时才画**页面骨架**（标题 + 状态点 + 操作位），不得再出现「读数中…」独占整屏。
2. **宿主内存缓存**：`/dsh-panel/stack-status` 加进程内缓存 TTL 5 s，命中返回上次 JSON 并带 `cached: true`；
   过期同步重算，但单次响应不得 > 1.5 s。其它路由不缓存。
3. **首帧结构**：三个入口在无数据时也画骨架，不许整屏单行文字。

## 判据

- 首屏有内容 **< 150 ms**（缓存命中路径，Playwright 或人工计时皆可，需贴读数）。
- 冷启动首次读数 **< 1.2 s**；`stack-status` 二次请求 **< 50 ms**（`cached:true`）。
- 断服务时：保留上次读数 + 红点 + 原话，**不白屏**。
- `python -X utf8 tools/dsh_panel.py --check` ⇒ 绿；`pytest tests/test_dsh_panel.py -q --no-cov` ⇒ 全绿。
- 零颜色字面量（`COLOR_LITERAL_RE` 不咬）；面板仍只读（不新增写文件/起进程）。

## 证据

- 修前读数：`/dsh-panel/stack-status` 2.15 s、`/workbench-board` 0.44 s（本卡「问题」节，实测于桌面实例 59137）。
- 修后读数与用例：`gates/diag/_a289_timing.txt`（首屏/冷/热三档计时）+ `tests/test_dsh_panel.py` 新增用例。
