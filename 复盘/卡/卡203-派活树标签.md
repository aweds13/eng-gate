## 为什么有这张卡

主控 2026-10-13 连派三张卡（197 / 201 / 202）时**被同一个缺陷咬了三次**，两条症状一个根。

**症状 A —— 租约把「主树」登记成被占**（真读数，原样）：
```
[占树] 租约被拦（退 1），**不派活**：
  · 树被占：（主树） 上已有活租约（卡 197，owner=DEV-HOST:36696）
```
202 第一次派活、201 第一次派活，**都是这么被挡掉的**；197 自己那条租约也一直写着 `tree: ""`（=主树），
而它实际在 `.wt/queue` 里干活。

**症状 B —— 派活产物落错地方**：197 那一轮的 log / 派活日志落进了
`.wt/queue/gates/diag/`，而不是卡 103 明写的「主仓的 `gates/diag/`」。

**根因（两处，都在主树 HEAD 上现读）**：

1. `tools/wb_dispatch.py:2694` —— `worker_cwd = Path(args.cwd).expanduser().resolve() if args.cwd else None`；
   而 `worker_tree_label(None, main_root)` **一律返回 `""`**（=主树）⇒ **不给 `--cwd` 时，租约登记的树
   与工人真正干活的树分叉**（工人 cwd = 派活器的进程 cwd，在卡树里就是卡树）。
   现测（`worker_tree_label`，main_root = 主树）：

   | 给什么 | 租约登记树 |
   |---|---|
   | 不给 `--cwd`（`wb_plan` 印的那种） | `''` ← **错**（实际在卡树） |
   | `--cwd .wt/queue` | `.wt/queue` ← 对 |
   | `--cwd <主树>` | `''` ← 对 |

2. `tools/wb_plan.py:100 dispatch_argv()` + `:109 render_dispatch()` —— 印的是
   `pushd <树>; python -X utf8 tools/wb_dispatch.py --card … --spec … --detach --execute`：
   **既没 `--cwd`，又是从卡树里跑「树里那份」脚本**（`ROOT = Path(__file__).resolve().parents[1]`
   于是成了卡树）⇒ 症状 A 和 B 一起出来。★ 而这是本仓**推荐的派活方式**。

## 要做的事

### 1. `tools/wb_plan.py` —— 印的命令换成**对的形态**

- `dispatch_argv()`：加 `--cwd <该卡树的绝对路径>`；**不再用 `pushd`**（改成从主仓跑）。
  树是 `""`（主树）时：`--cwd` 给主仓根或干脆不给 —— 两种都行，但**印出来的命令必须是能直接跑对的那种**。
- `render_dispatch()` 相应改（别再 `pushd`）。
- ★ 只改「印什么」，不改排批逻辑与任何判据。

### 2. `tools/wb_dispatch.py` —— `--cwd` 不给时**兜底按进程 cwd 还原**

  从 `.wt/x` 里跑 ⇒ 标 `.wt/x`；从主仓跑 ⇒ 标 `''`。
- ★ **不许改**树/域/锁/日志/模型白名单/内存闸任何一条守卫的语义 —— 只改**标签怎么算**。
- ★ 另外加一条**人话提示**（不拒跑）：当 `ROOT != 主树根`（即跑的是树里那份）时，打一行
  「你在卡树里跑了树里那份派活器：派活产物会落卡树。正确跑法是从主仓跑 + `--cwd <树>`」。
  要拒跑还是只提示，你定 —— 但**必须给出理由**，并在回报里写明你选了哪个。
