## 要做什么（只加"发现漂"的判据；**绝不自动改名单**）

1. **`tools/pool/models.py`** 新增一个**纯函数**（吃数据、回问题，**不读文件、不联网、不 print** ——
   与 `pool/guards.py` 同一风格）：
   ```
   def compare_rosters(local_names, pool_models) -> list[str]
   ```
   - `local_names` = 本仓那份名单（例如 `wb_dispatch.MODEL_WHITELIST` + `ONE_OFF_MODELS`，**由调用方传进来**，
     ★ **不许**在 `models.py` 里 import `wb_dispatch`（那是 CLI 层，反过来依赖会成环/分层倒置））；
   - `pool_models` = `load_pool_models()` 的返回值（仓外那份批准集）；
   - 返回**人话问题列表**（空 = 没漂）：① 只在**本仓**有、② 只在**池**有、③ **两边都在但名字对不上**
     （★ 这是关键：两份名单**id 体系不同**，`deepseek-v4.1-flash`（裸名）与
     `huaweicloud-maas/GLM-5.2`（`provider/model`）**不能**硬对成同一件事 —— 你要**说明**这个差异，
      并给出"要合并的话得先定一套 id 口径"这句结论）。
2. **`tools/wb_state.py`**（那条"一条命令看全局"的面板）**加一行**：
   把两份名单**并排列出来** + 调用上面的对账函数，漂了就打印 `⚠ 白名单对账：…`，一致就打印 `✓ 白名单对账：一致`。
   ★ 面板是**只读**的，**不许**因为这条去改任何名单文件。
3. ★ **口径（写进注释）**：本卡**只报告**，**绝不自动改名单**（两条铁律：白名单**只有用户能改**；
   池里新增模型**只报告、不自动启用**）。合并成一处是**用户的决定**。
