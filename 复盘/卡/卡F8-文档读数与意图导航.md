# 卡 F8 —— 文档的读数与意图导航：三份总览的过期计数、一张「找不到文档时先看哪」的路由页

> 台账号 T-AG514 · 分区 F（文档治理）· 批号 B-20261052（与 G6、E59 同笔落地）
> 依据：goal round 7 实测 —— 全仓 `.md` 1142 份、`复盘/` 773 篇、`tests/` 225 个 .py，
> 而三份总览里的对应数字停在 769 / 2034 / 26 棵树；`AGENTS.md` 的路由表有六条，
> 但没有一条回答「我该读哪一份文档」。

## 要解决的问题

1. **三份总览的计数过期，且过期方式各不相同**。
   - `docs/归置地图.md` 写「769 篇」「26 棵工作树」，实测 **773 篇 / 28 棵**。
   - `docs/文档架构.md` 写「`复盘/` 769 篇」「`卡/` 280 篇」，实测 **773 / 283**。
   - `复盘/架构索引-分层图.md` 写「`tests/`（2034 个用例）」，实测 **225 个 .py / 3443 个用例**。
   这三处属于 `2601.20404` 说的「误设的前提错得安静」：读者把数字当真，
   而没有任何测试会因为它错了而红。
2. **`docs/文档架构.md` 的 P2 断言是错的**：「presets 是项目书」——
   实测 `docs/presets/softeng.patch.yml` 是 **DSH 预设配置**（persona 前缀），
   不是项目书。这条错误会让人去 `docs/presets/` 找项目背景。
3. **云门禁机的文档还写着失效的 IP**：`203.0.113.11` 已不通，
   当前是 `203.0.113.10`；且「换机」这个说法本身是错的 —— 实测 meta-data
   的 `instance-id` 同一个（`i-0123456789abcdef0`），是**变配**
   （`ecs.e-c1m2.xlarge` → `ecs.u1-c1m4.xlarge`）。文档把「变配」写成「换机」，
   会让人以为旧机还在、还想连回去。
4. **没有任何一份「按意图路由」的页**：全仓六份索引（`docs/INDEX.md` /
   `复盘/INDEX.md` / `skills/README.md` / `docs/文档架构.md` / `docs/归置地图.md` /
   `AGENTS.md`），各自解决不同问题，但没有一处说明**它们分别管什么、什么时候不该看**。
## 判据（五条）

1. **读数一律当场算，不写死可漂移的数字**。三份总览里凡「N 篇 / N 个用例 / N 棵树」
   这类会随提交漂的量，要么改写成当场算出来的值，要么改成「见 `docs/INDEX.md` /
   `复盘/INDEX.md`（机器生成）」这种指向真源的写法。验收时用
   `python -X utf8 scripts/gen_doc_index.py --check` 与实测数字交叉核对。
2. **P2 的 presets 断言改成实测成立的写法**，并写明它到底是什么
   （DSH 预设配置 / persona 前缀，不是项目书）。
3. **云门禁机文档的 IP 与「变配 vs 换机」全部改成实测值**：
   `203.0.113.10`、同一 `instance-id`、`ecs.e-c1m2.xlarge` → `ecs.u1-c1m4.xlarge`；
   历史 IP 链保留成一张「哪一段时期用哪个 IP」的表，不许把旧值直接删掉
   （旧日志里的 IP 还是对的，删了就对不上了）。
4. **有路由页且被 `AGENTS.md` 指到**：`docs/文档系统导航.md` 至少覆盖
   「改代码 / 查某张卡 / 门怎么判 / 规矩的来历 / 发新功能」五类意图，
   每类指到具体文件；并且明确写出**哪些地方不是权威**
   （`复盘/` 是证据层、`gates/diag/` 是产物层、`docs/changelog.d/` 是片段）。
   `AGENTS.md` 的路由表加一行指到它。
