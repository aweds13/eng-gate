## 要解决的问题

pool 没有「清空用量」这个概念（`grep` 零命中），但有一个**语义相反**的东西：`tools/pool/ledger_spend.py:196-223 forget()` —— 它**物理把行搬走**。

magpie 的选择完全不同，理由逐字写在 `cleared.go:12-20`：清空**永不写进日志**，日志保留每一次调用 —— 因为「一个 key 的花费限额、额度的窗口估算、网关自己的 `Visit`」都还要数那些被清掉的调用，而 agent 的 session 文件与其他机器共享的天数 magpie 改不了，所以它改的是**读法**。可核证据 `cleared_test.go:78-82`：同一份日志，页面数 **3** 条、`Visit` 数 **5** 条，**一个字节都不改**。

照抄 `forget()` 会破坏一个已被测试咬住的语义（`tests/test_pool_limits.py:256-279` 的 `test_pin_12_forget_archives_and_leaves_other_accounts_alone`），而且是**净损失**：让「不想看见」悄悄松开限额。

## 判据（14 条，逐条可执行）

**本卡的判据就是设计原件 §F44「判据逐条」那 14 条**，逐字照做：

1. `add_clear` 在 `account != "" and model == ""` 时抛 `ClearError`，消息**逐字** `f"清空 {account!r} 的用量要点名模型"`；此时**文件不得被创建**（先判后写）。
2. `add_clear` 在 `at` 是 naive 或 `at.timestamp() <= 0` 时抛 `ClearError("清空用量要一个时间")`。
3. `read_clears()` 文件不存在 ⇒ `[]`（**不是异常**）；文件是坏 JSON ⇒ `[]`（**不猜、不隐藏任何行** —— 判不出就显出全部，这是「隐藏」动作唯一安全的方向）。
4. `read_clears()` 读出来的 `Clear.at` 全是 **aware**（naive 字符串按本仓 `pool_accounts.TZ` 解释，与 `ledger_spend._local` 同口径）。
5. `hides()` 空标记 ⇒ `False`（对应 `cleared.go:77`）。
6. 全清标记 `at=T` ⇒ `hides(..., at=T)` 为 **True**（**闭区间上界**，对应 `!r.Time.After(c.all)`）；`at=T+1ms` 为 **False**。
7. 按模型标记 `(account="A", model="m", at=T)` ⇒ 对 `(A, m, T)` 隐藏、对 `(A, m, T+1ms)` 不隐藏、对 `(A, other, T)` 不隐藏、对 `(B, m, T)` 不隐藏（**四个方向都要咬**）。
8. `covers(c, o)` 逐字照 `settings.go:2043-2046`：`c.at >= o.at and (c.account == "" and c.model == "" or c.account == o.account and c.model == o.model)`。
9. `prune()` 丢掉被别的标记覆盖的旧标记，且**同一个标记的重复项只留第一个**（对应 `// of two the same, the first is kept`）。
10. `add_clear` **永不重写 `pool-spend.jsonl`**：调用前后该文件字节完全相同（sha256 相等）。
11. `sums(..., clears=None)` 数**全部**行（= magpie 的 `Visit` 面）；`sums(..., clears=marks)` 只少数出来的行（= magpie 的页面面）。
12. `_entry()` 保留 `model`；行里 `model` 缺席或不是字符串 ⇒ `model == ""` 且**该行仍可用**（不判坏行）。
13. `tools/` 全目录里 `sums(` 的调用点**没有任何一处**传 `clears=`（限额面不许过滤）。
14. `cleared.py` **不 import `ledger_spend` 的 `forget`**、也不调用它（源码级断言：模块里出现 `forget` 字样即红）。

**常量逐字**：`CLEARED_REL: tuple[str, ...] = ("gates", "diag", "usage-cleared.json")` / `ALL_ACCOUNT = ""` / `ALL_MODEL = ""` / `EXIT_OK = 0` / `EXIT_USAGE = 2`；两条错误文案见判据 1/2。

## 缺口的如实交代（进 changelog 的 gaps）

1. **pool 侧没有「页面」这个面**：`sums(clears=…)` 今天**没有任何调用方**（`sums()` 连不带 `clears` 都没人调）⇒ 本卡交出去的是**能力**，不是**可见效果**。真要看，得等一张把 `wb_dash` / `wb_status` 接上 `pool-spend.jsonl` 的卡 —— 本卡不做。
2. **轴不对等**：magpie 的轴是 `provider + model`（网关上游），pool 的轴是 `account + model`（号）。「同一个模型在三个号上」在 magpie 是一行、在 pool 是三行 —— 判据照抄了形状，但**语义不等价**，这一点移植消除不了。
3. **alias 无对应物**：magpie 的 `clearSet.alias` 让 `qwen3-32b-q4` 的用量归到 `qwen3:32b` 名下，于是清后者也清前者；pool 的模型名是字面量（`model_registry.py` 的 `alias` 是「逻辑名 → 每池 id」，与用量归并**无关**）⇒ 本卡**不支持**按别名清。
4. **`clearedSince()` 无对应物**（magpie 用它让热力图起点不早于全清时刻）；pool 的热力图面不存在，这一支不移植。
5. **只在合成夹具上验过**：真实 `gates/diag/pool-spend.jsonl` **今天不存在**，所以「对真账跑一遍」做不到。
6. **毫秒 vs 微秒判不出**：magpie 存 `At int64`（Unix **毫秒**），Python `datetime.isoformat()` 写 6 位小数；两边都自洽，但拿 magpie 的 `settings.json` 直接喂 pool 会差一个量级 —— 本卡不处理这种跨仓搬运，也不做那个承诺。
7. **假牙如实申报（两处）**：①钉子 13（`test_no_call_site_passes_clears_to_sums`）今天是因为「没人调用」而绿，它挡不住「将来有人接线时传了 `clears=` 却没人发现」以外的任何东西。②钉子 17 的 `ast` 版本仍咬不住「间接调用」（如 `getattr(ledger_spend, "for" + "get")`）—— 判据是白名单式而非证明式。
