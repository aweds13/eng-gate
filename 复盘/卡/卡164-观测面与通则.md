## 要做什么

1. **观测面统一到一个判据**（★本卡核心）：**「这张卡现在是什么状态」只许有一个实现** ——
   `tools/pool/jobs.py::classify_job_state` + `tools/wb_dash.py` 的阈值**都从 `tools/wb_dispatch.py` 取**
   （`STALL_SECONDS` / `inflight_tool()` / `stall_threshold_seconds()`），**不许各写一份口径**；
   并且**判决/摘要必须带轮次与开始时刻**，读的时候要能判「这是不是当前这一轮」；
   发现「判决比日志旧」要**显著提示**（今晚 146 就是这个现场）。
   ★ 先读 `tools/wb_dispatch.py::archive_stale_artifacts`：它本该在真开跑那一刻把旧判决改名 `.stale` —— 
   **查清 146 那次（`--force` 重派）为什么没生效**，再决定改法（带出处，查不到就写查不到）。
2. **`0 字节 ≠ 失败`**：判据只看**判决文件 + 日志 mtime 距今多久**（**不看大小**）；
   加钉子：0 字节 + 无判决 + 静默 ⇒ 判「可能卡死」而**不是**「收工」。
3. **桩必须带 `id` + `__timestamp`**（INV-36）：`_epoch` 的保守分支不许让断言恒真 ——
   加一条钉子：**缺字段的桩 ⇒ 判据必须红**（不是"悄悄跳过"）。
4. **INV-43/44**：`tools/run_bg.py` 加哨兵口径的钉子；输入预算加**单轮中途**的拦截（或如实写清为什么做不到，

5. **INV-61 通则**（★ 能做成扫描的就做）：写一个**只读扫描**（`tools/` 或 `scripts/` 下，

## ★★ 追加（主控 2026-10-03 16:2x —— **flaky 的第二例，现场**）

**现场**：卡 149 第 3 趟落地，`tests/test_wb_dispatch.py::test_retry_round_threshold_eats_only_its_own_log` 红。
它**真起两轮子进程**、`--poll-seconds 0.2` / `--stall-seconds 2`，断言「第 1 轮判决必须是**超时**」；实际拿到：

```
判决：卡死：0.0 分钟没有新事件（这一次的阈值 0.0 分钟；没有在飞的调用；历史最长一次调用：没有记录）
```

★ **真因推断**：**xdist 4 worker** + 机器有别的活 ⇒ **stub 的第一行还没落地，看门狗就已经开跑** ⇒ 阈值算成 0.0 ⇒ 判「卡死」。
★ 同一天另两趟（也是 4 worker / 串行单跑）**它都是绿的** ⇒ **典型计时 flake**。

★★ **它正是本卡要治的那一族**（「**状态判定不许把噪声当结论**」）—— **flaky 就是「判据把资源噪声当结论」**。
★ 文献站位：RAFT [arXiv:2310.12132] —— **46.5% 的 flaky 是资源敏感的**，`<1 core / <1 GiB` 时 flakiness 激增；
★ 加剧因素：149 新加的两条钉子**真起 `Popen`**，与这条计时测试**挤在同一个 worker** 上。

**本卡要收的活（加进 §上面那五条之外）**：
7. ★ **计时敏感的真进程测试要有"资源噪声"的显式处理**：要么**给足容差**（`poll`/`stall`/预算按最坏情况定），

   ★ 代价就是第 7 条那类 flake。⇒ 把这笔账写进跑法留痕（与卡 184 的「降级必须留痕」同族）。

## ★★ 追加二（主控 2026-10-03 16:5x —— **队列流量仪表：把"会不会收敛"变成读数**）

**背景**：用户问「**全部做完大概要多久？**」→ 主控先答「按现在的动态**永远不会空**」→ 用户追问
「**你确定到最后不会收敛吗？**」⇒ ★ **主控那条断言太强**（把「平台」说成了「发散」）。
⇒ **正确的做法不是争，是量**。本卡收下这个小工具。

**要产出的东西：`tools/wb_flow.py`（新，只读）**
每天/每次跑，输出四个数（`--json` 也要）：
1. **到达**：`docs/workbacklog.toml` 里**新增**的卡（按 id 或按 git 历史现算）；
2. **离开**：标成 `done`/`failed` 的卡数（同一窗口）；
3. **WIP**：`status == "pending"` 的卡数（**就是今天的"待派"**）；
4. ★ **流量分解**：新增卡按**来源**分类 —— `用户提问/裁定` · `文献/外部调研` · `审计/复核发现` · `坑（现场咬出来的）` · `结构性重构`。
   ★ 来源**从卡的 `why`/规格里现读**（读不到就标 `未标`，**不许猜**）。

**判据（这才是"会不会收敛"的机器判据，不许拍）**：
- **到达 < 离开** ⇒ 收敛中；**到达 ≈ 离开** ⇒ 平台；**到达 > 离开 连续 N 天** ⇒ **报警**；
- ★ 并且要能回答一个具体问题：**「今天的到达里，有几张是"坑长出来的"？几张是"外部输入/用户提问"？」**
  ⇒ 前者若**长期为 0**，说明**缺陷面在收敛**（那是**好**消息，也是"会收敛"的证据）。

**边界**：只读；不改队列；不判断「该不该立卡」（那是产品决定 —— 主控/用户的事）。
★ 判据要能**证明它看得到东西**（合成一份带新增卡与 `done` 卡的夹具 ⇒ 四个数必须对）。

## ★★ 主控追加（2026-10-03 21:4x，用户令「并进去呗」）：**"压缩文书"要变成会咬的判据**

**口径**（已写进 `复盘/外包-卡表与规矩.md` 的 §17，第 5~6 条）：

> **文书的读者是下一个干活的人**，不是证据档案；想看全量证据**从快照反推**。

★ **它在 §17 里只是"话"** —— 而本卡（观测面与通则）的活就是**把话变成判据**。要做三件：

1. ★★ **结构预算的判据**（落在收口读文书的那一步 —— `tools/pool/stage_card.py`，或 `scripts/audit_progress.py`；
   二选一，**在规格里说清选哪个、为什么**）：
   - 全文 **≤ 60 行**；`gaps` ≤ **6 条**（每条 ≤ 3 行）；`changelog` 用**每卡一行**的表；`老实说` ≤ **4 条**。
   - 超了 ⇒ **红**，并**指出超的是哪一节、超多少**（不许只说"太长"）。
   - ★ **反例钉子**：造一份超长的文书 ⇒ 必须红；一份合规的 ⇒ 必须绿。

   **快照 id / 日志路径 / 既有文档 / 提交 sha**（用现成的引用核对那一套验它**真的存在**）。
   - ★ 为什么：**压缩之所以安全，全靠"压掉的指得出来"**；没有这条，压缩就是**丢证据**。
   - ★ 反例钉子：一条**不带指针**的 gap ⇒ 红；指针**指到不存在的东西** ⇒ 红。
3. ★★ **"靠快照反推"的两个前提要写进本卡的通则**（当晚实测，见 §17 第 6 条）：
