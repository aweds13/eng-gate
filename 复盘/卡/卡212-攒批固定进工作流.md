# 卡 212 —— **把攒批收口固定进工作流**（不是写成文档，是装牙）（T-G323）

**树**：`.wt/batchflow` ｜ **base**：主控派活时的主树 HEAD ｜ **提交**：★ 不要 commit
**成员号**：任务 `B-20261014` 的 **M-1**。★ **干完必须交成送申请**：
`python -X utf8 tools/wb_task.py claim B-20261014 M-1 --claim success --why "…" --evidence "…"`。

## 为什么有这张卡

用户 2026-10-13 的令：**「尽量重活 codeart - 同学-我的这个优先级，然后大量并行，**攒批提交，一日一次**」**，
随后追问：**「这个机制为什么没有固定到工作流里」**。

主控当场查出来的事实（**证据是硬的，别重查**）：

1. `wb_land.py` 的 `--card` / `--batch` **必须恰好给一个** ⇒ 攒批收口**是现成的路**（一次门禁、一笔提交）；
2. 但**两条路平权** —— 没有任何东西偏向批，也没有任何东西在单张落地时提醒「这张卡属于一个批」；
3. ★ 栅栏状态机（`collecting → awaiting-commit → landed`）**只能靠人手工推**（`wb_task.py claim` / `landed`），
   而**没有任何判据比较「栅栏说的」与「git 里真落的」**。实测：
   ```
   B-DTREE    collecting 0/1   ← 它的卡 203 早在 e45267b 落地了
   B-DSHTIE   collecting 0/1   ← 它的卡 206 早在 64bd500 落地了
   （当天 7 个栅栏全部 collecting 0/1）
   ```
4. ⇒ 栅栏漂成**虚构**；而绕开它的是主控自己（当天 7 张卡全用 `--card` 逐张落，`claim` 一次没跑）——
   **不是机制失效，是没人咬。**

★ 这正是本仓反复记载的病：`wb_advcard.py` 建了零接线 · `tools/card_doc_budget.py` 零件没人用 ·
`tools/proxy_audit.py` 交了没接门禁。**教义一句话：没装牙的规矩 = 话。**

## 要做的事

### 1. 落地链**自己推栅栏**（人不该是状态机的一部分）

`tools/pool/landing.py`：提交成功之后，**自动**把本卡的成送申请推到位（`claim success` + `landed`），
`--batch` 时逐成员推。
- ★ 推送内容取自**这一笔的真实产物**（`--task`、`--card`/批号、提交 sha），**不许**填报喜不报忧的空话。
- ★ 读不到栅栏（没有对应的 `B-*.toml`、或卡不在任何栅栏里）⇒ **跳过并打印一句**（不崩、不猜、不新建栅栏）。
- ★ `landed` 必须记**这一笔的真实 sha**（`wb_task.py landed` 的现有口径照用，别另造一套）。

### 2. 单张落地时**警告**（默认该走批）

- 若 `--card` 那张卡**属于某个栅栏**，且该栅栏还有**别的成员**（同批该一起走）⇒ 打一行**醒目警告**，
  说清「它属于 `B-XXX`（还有 N 个成员）—— 攒批该走 `--batch`」。
- ★ **警告还是拒绝，你定**（拒绝要加 `--force-single` 之类的明示开关）—— 但**必须给出理由**并把选择写进回报。
  ★ 不许**静默**继续（那正是今天的毛病）。

### 3. ★★ 攒批收口要能吸收**多棵树**（用户追问逼出来的真缺口）

`tools/pool/landing.py:557` 是 `wt = ROOT / a.tree` —— **收口只落一棵树**。而一个批里的成员
今天是**各在各的卡树**里干活的（7 张卡 7 棵树）⇒ 「一笔提交收一批」**缺一个集成步骤**。

- 当年 `B-DOC1`（4 个成员一笔提交）不需要它，因为那些成员是在**同一棵树**里改不同文件。
- ⇒ 本卡加一条：`--batch` 收口时，若批成员的产物**不在同一棵树**里，必须能**把各棵树的改动合进
  一棵集成树**再落（`--tree` 指向集成树），并**打印清楚合了哪几棵、各自的基点**。
- ★ **冲突要当场咬**：两棵树改了**同一个文件**的同一处 ⇒ **停手并点名**（不许自动择一、不许静默覆盖）。
- ★ 合的方式与顺序**必须可复现**（同一批、同样的输入 ⇒ 同样的结果），且**不许**绕过任何既有判据。

### 4. ★★ 装牙：一条判据盯**真仓库的栅栏**（`tools/wb_plan.py` 或新增小工具 + 测试）

- 对每个 `gates/diag/batch/B-*.toml`：它的成员在**队列里的 status** 与**栅栏状态**必须一致。
  **「卡已 `done` 而栅栏还 `collecting`」⇒ 红并点名**（卡号 + 批号 + 两边各说什么）。
- ★ **反向保护**：不许把「还没派活的卡」或「缺席被显式豁免」的成员报成错；没有 git/没有栅栏文件时**优雅跳过**。
- ★ **先红后绿**：**今天就该红** —— 现仓库里 `B-DTREE` / `B-DSHTIE`（以及当天另外 5 个）都漂着。
  把这条判据跑出来的**第一次红**原样贴进回报。
