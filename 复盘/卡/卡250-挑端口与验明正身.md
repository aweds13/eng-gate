## 为什么有这张卡（依据：定点深读 §四.3，`复盘/DSH插件-定点深读.md`）

深读 `dsh-pilot` 源码得到一条**我们该照抄**的做法：挑本地端口**用"能不能 bind"判定**（`src/index.js` 的 `canBind` 一带，详见文档），而不是靠 HTTP 探测超时猜空闲 ✗；并且在接入一个**已有**服务前先取**身份指纹**确认"连的是谁"再发请求 ✓。
我们的现状（`tools/serve.py`）：挑端口/判活偏"HTTP 探一下"✗ —— 这会在两种情况下骗人：
- 端口被**非 HTTP** 的东西占着（裸 socket / 别的服务）⇒ HTTP 探测超时 ⇒ 误判"空闲"✗；
- 端口上**是别的 HTTP 服务** ⇒ 探测成功 ⇒ 误判"我们的服务活着"✗（这类误判我今天在别处已经咬过 ✗）。

## 要做的事（只改 `tools/serve.py` + 新增 `tests/test_serve_port.py`）

1. ★ **挑端口改成 bind 探测**：从候选端口起，`bind` 失败（含被占用、权限不足）⇒ **报忙并顺延**到下一个候选；全试完仍不行 ⇒ **非零退出**并把试过哪些端口原样打出来 ✓。
2. ★ **接入/判活加身份指纹**：在自己起的 HTTP 服务上提供一个小自述端点（例如 `/healthz` 或等价的现成端点 ✓），判活/接入时**先取指纹**：
   - 指纹**对**（是我们这个服务）⇒ 才算"活着"✓；
   - 指纹**不对**（是别的服务）⇒ 判"**验明失败**"并**拒绝接入**，错误信息里带上**下一步排查命令**（照 pilot 的"错误即修复指令"口径 ✓）；
   - 端口**根本没有响应** ⇒ 才判"没起"✓。
3. **判据（新增测试文件，先红后绿；★ 不许用真端口范围乱占，用临时端口 ✓）**：
   - a. **占用时的行为**：用一个**裸 socket**（`python -c` 起一个只 listen 不说话的）占住目标端口 ⇒ 挑端口逻辑必须**报忙并顺延**（★ 不许因为"HTTP 探测超时"把它当空闲 ✗）；反例：把 bind 探测换成 HTTP 探测 ⇒ 断言必须红 ✓；
   - b. **冒充者**：起一个**别的** HTTP 服务占住端口（返回 200 但指纹不对）⇒ 判活必须给"**验明失败**"（不是"活着"✗），且错误信息里含下一步排查命令 ✓；
   - c. **自己的服务**：正常起 ⇒ 判活"活着" + 指纹对 ✓；
   - d. **既有判据一条都不许删/降级**（若 `serve.py` 已有判据文件，一并保绿 ✓）。
4. **边界**：只碰上面两个文件；不许改桌面 `start-all.cmd`、不许改 `tools/stack.py`（那是卡 243 的域 ✗）；不许 commit/tag；不许跑全量门禁；零第三方依赖。
