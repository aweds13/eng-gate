# 卡 E91 —— 号池的签到与额度读数和真机对齐（T-AG599）

> 台账号 `T-AG599` ｜ 分区 E ｜ 层 判据层 ｜ 无独立卡树（用户 m89794 授权直接改、逐处自检）
> 依据：卡 E48（T-AG535，手动签到与聚合入口）的三条硬规矩；卡 E45（T-AG531，账号账本与只读探测）。

## 要解决的问题

三家平台的签到客户端**按猜的响应形状写**，对着参考实现的真实响应跑，三种错法各一次：

1. **qoder 读错根键**：`claim_qoder` 读 `data` / `items`，参考实现（`lib_vendor_qoder_qoder-credits.js:328`）
   的真根键是 `campaigns`；且没按 `actionType === "CLAIM_BENEFIT"` 过滤 —— 参考实现 `:310-317`
   明写 `VIEW_DETAILS` 也会带 `claimStatus:"CLAIMED"`，不先过滤就会在**从没领过的号上谎报已领**。
2. **workbuddy 缺 UA、缺包装层、缺幂等判据**：`copilot.tencent.com` 的网关认不出 UA 就回
   `code 10085（请求不合法）`（magpie `workbuddy.go:48-56` 逐请求设 `User-Agent: WorkBuddy/5.5.6`）；
   业务码在顶层 `code`、载荷在 `data`；重复领取是 **400 + code 10001**，即便 `!ok` 也要解析响应体
   （`lib_adapters_buddy.js:678`/`:1085`）。本仓 `_bearer()` 只给 `Authorization` 与 `Accept`。
3. **trae 把失败判成成功**：只读 HTTP 与 `data.claimed`，不读业务码 ⇒ `{"code":9004}` 被判
   `CLAIMED credit=0.0`。参考实现 `src_trae-credits.ts:120-130` 的 `readClaimCode` **兼容字符串**
   （后端会以 `"9074"` 返回），`:280` 只有 `code === 0` 才算成功，`:284-296` 明写 **claim 响应
   不含积分数**（实测完整响应是 `{"code":0,"message":"success"}`）⇒ 成功后必须补查 status 端点。

同一批还有两类与代码无关的**判据缺口**：

4. **`--probe` 会写坏当天签到判决**：`_record_checkin()` 无条件写 `last_checkin`，而卡 E48 判据 4
   （`:60`）只授权「写进留档 JSON 与账本 `last_probe`」⇒ 探一次就把当天机会判成「当日已定案」。
5. **能力表两处指错地方**：`[platform.trae] probe_url` 漏 `/trae` 前缀（同段 `quota_flow` 却带），
   实测回 404 ⇒ 把「路径打错」固化成「上游没这能力」；`[platform.codearts] token_env` 写
   `TF_CODEARTS_*`，而本机 `~/.codeartsdoer/pool.env` 实测只有 `CODEARTS_CLI_AK`/`CODEARTS_CLI_SK`
   ⇒ 已写好的读路径没人喂。

外加一件新能力：**秒悟（Meoo）接入**。它有额度接口（`GET /open/v1/cli-compat/account/points`，
实测 `availableBalance = 56958`）但没有签到入口（全量 grep 无 check-in 子命令），凭据是**文件型
OAuth**（`~/.meoo/credentials.json`），与现有「环境变量取 token」的形态不同。

## 判据（6 条，逐条可执行）

1. **三个客户端按真实形状判**：`tests/test_pool_checkin.py` 里 npm 的五条钉子全绿，且把实现换成
   改前的版本会红 —— 分别是 workbuddy 的 `10085`（缺 UA）、`400 + code 10001`（重复领取不算失败）、
   trae 的 `{"code":9004}`（业务失败不许报成功）与 `{"code":"9074"}`（字符串业务码要认），
   以及 `test_workbuddy_404_is_not_supported` 里那条 UA 断言。
2. **`--probe` 不碰判决位**：`test_probe_mode_never_touches_the_verdict_bits` 绿；把
   `_record_checkin()` 的 `if not apply: return` 删掉，该用例必须红。
3. **能力表指向真位置**：`trae.probe_url` 含 `/trae/api/v2/pay/`；`codearts.token_env` 以
   `CODEARTS_CLI_AK/` 开头；workbuddy 的 `claim_flow` 第一条是 `POST`（状态查询实测是 POST），
   `pitfalls` 写明 UA 版本、`code 10001` 幂等、`code`/`data` 包装层三件。
4. **Meoo 走自己的口径**：`_extract_amount()` 对 Meoo 的响应体**返回 None**（不许猜成
   `totalGranted` 61000），`_amount_at_path(..., "data.account.availableBalance")` 得 56958；
   真实能力表里 `amount_path` 是那一条；token 从凭据文件的 `accessToken` 读、说明里不回显值；
   **发现闸关着时一次都不许打开凭据文件**。
5. **账本多一个号且能真读**：仓外账本 `accounts.toml` 有 `meoo-1`（`kind = "file"`，指向
   `~/.meoo/credentials.json`，`last_checkin = "not-supported"`——它没有签到入口）；`probe` 真跑回
   `ok` 且额度是 `56958`，读数来源写明是哪个端点。其余四个号本机无凭据 ⇒ 如实 `uncertain`，
   **不许**写成成功。
6. **文档不再说谎**：`docs/subsystems/pool/modules.toml` 里 `route.py` 的调用方不再是
   `wb_dispatch`（实测 `grep` 为空），平台数改成九个；`tools/pool/sticky.py` 三处过期行号
   （`route.py:210` → `:627` 两处、`route.py:75` → `:101`）改对。
