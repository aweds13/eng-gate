# 卡 A287 · 队列补登记 8 张 + 巡检分报批成员（T-AG401）

## 问题

- **8 张已落卡不在队列里**：`259` / `260` / `261` / `262`（批 `B-20261046`…`B-20261049`）与 `A283` / `A284` / `A285` / `A286`（`T-AG397`…`T-AG400`）都已经落地、卡规格也已经进了 git，但 `docs/workbacklog.toml` 里**一条登记都没有**。后果不是"少个数字"：队列是 `wb_plan.py` / `wb_daily.py` / `audit_progress.py` 的唯一真源 —— 不在队列里 ⇒ 排批看不见它、巡检看不见它、翻 status 也翻不到它，**已落的卡在账面上等于不存在**。
- **巡检把批成员冒充成卡**：`tools/wb_daily.py` 的 `_render_stale` 把所有「已落但队列里没有」的名字一股脑塞进一行 `★ 另有 N 个已落批成员不在队列里：…`。而 `M-1`…`M-5` 是 `gates/diag/batch/` 里的**批成员标签**，从来就不是卡号 —— 它们**永远**不可能进队列，于是这一行 `★` 天天亮着，成了**噪音**。真卡号形态（`A123` / `261`）漏登记才是要报警的那件事，两者混在一行里 ⇒ 报警被自己的噪音稀释。

## 改法

1. **补登记 8 条 `[[cards]]`**（`docs/workbacklog.toml` 末尾）：`259` / `260` / `261` / `262` 挂 `B-20261046`…`B-20261049`，`A283` / `A284` / `A285` / `A286` 挂 `T-AG397`…`T-AG400`；每条都带 `tree` / `spec` / `files`，`status = "done"`，`risk = "low"`。★ 口径照既有条目，**不新造字段、不改 `depends` 语义**。
2. **顺带把 A287 自己也登记进队列**（同一文件末尾）：否则下一页 `wb_daily` 会报「找不到卡 A287 ⇒ 跳过翻 status」，且这笔自己就成了"已落没登记"的第 9 张。
3. **巡检分报**（`tools/wb_daily.py`）：新增 `CARD_ID_RE = re.compile(r"^(?:[A-Z]+\d+|\d+)$")`（`tools/wb_daily.py:357`）与 `_card_key()`（`tools/wb_daily.py:360`，批号 `M-1` 与队列 `M1` 归一），补 `import re`（`tools/wb_daily.py:35`）。`_render_stale` 里把 `unknown` 拆两拨：**卡号形态**仍报 `★ 另有 N 个已落批成员不在队列里`（`tools/wb_daily.py:378`），**无卡号形态**降为 `· 历史批成员 N 个（无卡号，不进队列）`（`tools/wb_daily.py:381`）。
4. **断言改新口径**（`tests/test_wb_daily.py:238`）：从 `assert "已落批成员不在队列" in out` 改成 `assert "历史批成员 1 个（无卡号，不进队列）：M-9" in out` —— 钉住"`M-9` 不进 `★` 那一行"这件事本身，而不只是"有个词出现"。
