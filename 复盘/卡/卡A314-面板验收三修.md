# 卡 A314 —— 面板验收三修（真机验收抓到的行为缺陷）

> 真源：2026-10-21 重启后对 `127.0.0.1:59514` 的验收。三条都不是「没生效」，是行为错。

## 1. `stack-status` 预算小于真实成本 → 假红

- 现读：`/dsh-panel/stack-status` 返回 `status.ok=false`、`error="stack.py 起不来：spawnSync python ETIMEDOUT"`。
- 实测：`python tools/stack.py status --json` 本机 **2.8s**（五次端口探测），宿主预算是 **1500ms**。
- 修法：`STACK_STATUS_BUDGET_MS` 1500 → 6000，注释写明实测成本与误报形态。

## 2. 通知混进脏卡号、且 `unread` 与 `items` 口径打架

- 现读：`unread=75` 但 `items` 只有 20；列表里出现 `000`（派活前置失败留下的脏号）与 `254.r2`（带重试后缀）。
- 修法：① 卡号归一（`254.r2` → `254`）；② 只认台账里登记过的卡号（`readDoneCards()` 兼收 `all` 集合）；③ 上限 50 条，超出用 `more` 明示。

## 3. 判据（钉子）

- `tests/test_dsh_panel.py` 新增三条：预算 ≥ 实测成本、只认台账卡号、截断必须显式。
- 行为复核：以假 ctx 直挂宿主半，对真仓跑两条路由 —— `unread=1 / items=1 / 含000=false / 含254.r2=false`、`stack-status status.ok=true 错误空`。
