# 卡 E25 · 落地翻账不许抹掉台账证据指针

## 为什么开这张卡

`tools/pool/stage_card.py` 的片段模式（`_fragments_mode`）会把
`docs/traceability.d/<台账号>.toml` **整份重写**，`evidence` 只取本次 `--evidence` 那几个文件：

```python
lines += [f"  {_toml_str('file:' + _unescape_git_quoted(e))}," for e in a.evidence]
lines += ["]", 'gaps = "' + quote_safe(gaps) + '"', ""]
frag2.write_text("\n".join(lines) + "\n", ...)     # ← 覆盖，不合并
```

而落地链 ② 正好会带着自己的 `--evidence`（常常只有「卡规格 + batch.toml」两条）再跑一次它。
结果：人手补过的 `file:tests/xxx.py`、`test:xxx.py::用例` 全被抹掉，紧接着审计 ⑫
「这一笔改了 X 但台账没有任何证据指针指到它」当场红。

真现场（本轮两趟白跑）：

- E24 落地，`gates/diag/land-E24.log` 240 s 后红在这条；
- 改成「把要声称的文件也塞进 `--evidence`」才绕过 —— 那是让每个落地的人**手工重复**一遍
  证据清单，只要漏一个文件就再红一次；
- F1/E22/E21 落地时同样被它咬过（`docs/traceability.d/T-AG451.toml` 从 7 条退回 2 条）。

## 判据（改后）

1. 片段里已有的 `evidence` 条目 **原样保留**（顺序不变），本次 `--evidence` 的新条目**追加在后**；
2. 完全相同的条目**去重**（同一份 `--evidence` 连跑两次，条目数不许翻倍）；
3. `gaps` / `title` / `status` 仍按本次写入（翻账本来就要改 `status`）；
4. 已有条目里若有本次没提到的东西，**不删**（它不是「域外」，只是这次没再点名）。

钉子：`tests/test_stage_card_evidence_merge.py`
- `test_existing_fragment_evidence_survives_a_restage`：片段里先放 `file:tools/x.py` +
  `test:test_x.py::test_it`，再跑一次 stage_card ⇒ 两条都还在，且本次 `--evidence` 也进去了；
- `test_restage_does_not_duplicate_an_identical_pointer`：同一份 `--evidence` 连跑两次 ⇒ 条目数不变。

反空转：`git stash push -- tools/pool/stage_card.py` 后跑第一条 ⇒ 必红（`人手补的指针被覆盖了`）；
`stash pop` ⇒ 两条都绿。

## 不做什么

- 不动 `gaps` 的写法（仍是拼成一行的 TOML 基本串）。
- 不动非片段模式那段（那段是「已有就跳过」，本来就不覆盖）。
- 不给 `--evidence` 加校验（不查文件是否存在）—— 那是另一条口径，本卡只管「不许抹掉」。
