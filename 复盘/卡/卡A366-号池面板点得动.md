# 卡 A366 —— 号池面板 P0：把「点了没反应」改成能点、能等、能如实报

> 台账号 `T-AG588` ｜ 分区 A（工作台 / 面板）｜ 树 `.wt/A366` ｜ 层 工具层
> 依据：用户 2026-11-03 13:07 派卡「把已有的 DSH 面板插件做成『人真的能点得动』的号池操作面」，
> 指定设计 `gates/diag/_design_pool_panel.md`（441 行）为判据唯一来源，并列出 P0 五项与七条验收（m00001）。
> 现读事实（全部实测）：
> ① 现「派活」按钮调 `tools/pool/trae_dispatch.py start`，该子命令自述**不起任何子进程**，
> 只 `registry.reserve` + 写一条 init 日志 ⇒ 点了永远「成功」，工人从没起来。
> ② 更底层：宿主半 `runTool(argv)` 用 `path.join(root, ...argv)` 把**参数也 join 进脚本路径**，
> 于是 `trae_dispatch.py start --card D1` 变成 `…\trae_dispatch.py\start\--card\D1`，
> Python 报 `can't open file` 并以 2 退出 —— 派活 / 放租约在旧代码上**一次都没成功过**，
> 而且失败被 600 字截断 + 无提示吞掉。
> ③ 卡号正则 `/^\d{1,4}$/` 对台账 322 张卡只放行 **142** 张（脚本
> `gates/diag/_a366_regex_proof.py` 实测），D1–D8 / C1 / C2 / E81 这些**待派卡**全被 400。
> ④ 面板只有 `workbench-board` 一条读源（台账状态），没有「在飞 / 卡住 / 门禁 / 锁 / 待派」
> 的读数；三个新读工具的 JSON 出口有两个还不存在：`wb_status.py` 没有 `--jobs`，
> `gate_lock.py status` 只有人读文本。
> ⑤ 已装副本 `~/.dsh/profiles/desktop/node_modules/dsh-client-ui-workbench-panel/`
> 是**真实目录、不是 link**，`lib/index.js` 是旧构建 ⇒ 运行中的 GUI 不可能有新路由；
> 本卡用「emit 到临时目录 + node 桩服务器」做运行时证据，**不碰 `~/.dsh`、不重启 DSH**。

## 要解决的问题

1. **按钮点了没用，而且假成功**。旧链路 `runTool` 把参数拼进脚本路径 ⇒ 每次都 exit 2；
   即使路径对了，`trae_dispatch.py start` 也只是登记租约、不起工人。人看到的是
   「点了一下，什么都没发生」，日志里没有任何一行能解释为什么。
2. **待派卡根本点不了**。卡号正则只认纯数字：`D1`、`C1`、`E81` 这类卡在派活 / 放租约
   两个动作上一律 400 `卡号不合法`，而它们在台账 322 张里占 180 张。
3. **第一屏没有可恢复动作的读数**。「在飞 / 卡住（静默 > 480s）/ 门禁 / 锁 / 待派」
   分别住在 `tools/pool/jobs.py`、`gates/diag/gate_lock.py`、`tools/wb_daily.py` 里，
   面板一条都没接；人要看现场必须切终端。
4. **失败不可解释**。旧客户端把 `text` 静默截到 600 字、把列表静默截到 60 行，
   页脚不写「共多少」，人不知道还有多少没看到。
5. **确认模型不对**。旧代码用 `window.confirm` 弹系统框：不可撤销的动作（release 只是
   删登记、可逆）与不可逆动作（派活）用同一种对话框，且没有「3 秒内二次确认」的语义。

## 判据（9 条）

1. **卡号正则对台账全量放行**。`/^[A-Za-z]{0,3}-?\d{1,4}$/` 对 `docs/workbacklog.toml`
   的 322 张卡命中 322（旧 142），且仍拒绝 `bad card`、`../etc`、`A366/x`。
2. **三条只读路由可用且字段齐**。`/dsh-panel/pool-daily` 回 `{ok,route,reading}`、
   `reading` 含 `to_dispatch`/`leases`/`gates`/`checkin`；`/dsh-panel/pool-jobs` 的
   `reading.jobs` 是数组；`/dsh-panel/pool-locks` 的 `reading.locks` 是数组，且
   `reading.note` 原样含「★ 别看 pid 判活」。
3. **读面只 GET、只转发、只缓存**。三条路由都挂在 `serveSeam` 的 GET 闸门之后；
   每条各自 TTL（daily 5000 / jobs 3000 / locks 3000 ms），命中回 `cached: true`；
   宿主半不解析这些工具的人类文本（全部 `--json`）。
4. **派活走 run_bg + 一层 shim**。`dispatch` 的 argv 是
   `run_bg.py run --log gates/diag/wb-<卡>.dispatch.log -- python -X utf8 tools/pool/dispatch_shim.py`
   ⇒ 面板**立刻**回 `pid=`/`rc_file=`，不 await 工人；shim 只转发、不复制守卫，
   真派活器仍是既有那一个，宿主半不再出现它的名字。
5. **失败三态如实报**。「起不来」给 `done.error` 原话；「非零退出」给退出码 + 尾部 600 字；
   读面失败给 502 `{ok:false,route,error}`，不把失败洗成空对象。
6. **两段式确认替代 window.confirm**。派活第一下只「武装」，按钮变成
   「确认派活 <卡> → .wt/<卡>（3 秒后自动收起）」；第二下才发请求；3 秒一次性
   `setTimeout` 收起，**不引入 setInterval**，客户端全文不含 `window.confirm` 字面。
7. **不再静默截断**。在飞 / 待派列表页脚写「显示 M / 共 N」+「再多看 60 行」，
   `data-wb-more` 可被测试与探针读到；单条错误文本仍是工具原话。
8. **宿主半仍然只读**。`FORBIDDEN_WRITE_TOKENS` 一个都不出现（`_check_read_only("宿主半")`
   绿）；新路由的字面判据（常量名、`servePool*` 函数名、TTL、`run_bg.py`/`dispatch_shim.py`）
   都进了 `_check_host`，`--check` 仍 `[OK ]`。
9. **判据仍只有一份**。`gate_lock.py status --json` 与 `wb_status.py --jobs --json`
   都是**同一份读数换输出格式**：`gate_lock` 的人读文本改前改后逐字相同，
   `wb_status` 的 `--jobs` 只计数、不重算 480s 阈值。

## 不许做

- 面板里不放「落地」按钮（8 步任一步错不可逆）；不放门禁执行按钮（宿主半同步跑门禁
  会撞 HTTP 超时 + 孤儿进程）。
- 宿主半不许解析人类文本（缺 `--json` 就去工具里加，不在 JS 里 grep 字符串）。
- 不引入 `setInterval`；不用 `window.confirm`；不做 5 秒常驻轮询刷 226 KB。
- 宿主半不写文件（留痕只能 python 侧写 `gates/diag/pool-actions.log`）。
- 面板不重算「卡住」阈值 / 冲突域 / 额度四态 —— 一律转发既有工具的读数。
- 不从客户端收 `files` 参数；不把本地包伪装成 `link:`；不改 `~/.dsh` 配置。
- 不碰主树、不 `git commit` / `rebase` / `reset`、不跑落地链。

## 直做

不需要再问；按上面 9 条判据做，反向变异 3 条**全部**真跑一遍并把输出贴进交接。

**铁律**：多行 Python 一律 `write` 落盘再跑；源文件纯 CRLF
