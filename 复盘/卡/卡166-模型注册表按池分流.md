# 卡 166 —— 模型注册表：**一层统一，按池分流**（取代卡 146 的朴素合并）（T-G266）

**树**：`.wt/modelregistry` ｜ **提交**：★ **不要 commit** ｜ **模型**：默认
**成员号**：任务 `B-MODELREGISTRY` 的 **M-1**

## 来路（用户 2026-10-03 的裁定 + 一句话问到了根上）

用户问：**「为什么白名单会变成……就是那两个部分会有不同的、不能用的 id 体系是吗？你可以把它做成一个同一层，然后分流到不同层吗？」**

**现场（卡 146 踩坏的地方，有实证）**：卡 146 把 `tools/wb_dispatch.py` 的硬编码白名单**删掉、改读**
`infra/pool/models.whitelist.toml`。而那份"唯一权威"**只描述华为码道池**：

```
[[approved]]  pool = "codearts-cli"   model = "huaweicloud-maas/GLM-5.2"
（注释里还写着：deepseek-v4.1-flash / glm-5.3-flash 在码道侧**服务端不可用**）
```

而派活器在用的是 **CodeBuddy 池**，id 是**裸名**（`deepseek-v4.1-flash` / `glm-5.3-flash`）。
⇒ 合并后裸名全被拒、`--model` 默认值取到"首项" = 一个 **CodeBuddy CLI 不认**的名字 ⇒ **不带 `--model` 的派活全挂**。
**两个池连 id 体系都不同**，所以"挑一份当真源"这条路本身是错的。

## 要做什么（★ 一层注册表 + 每池一个适配器）

1. **一层注册表（唯一真源）**：每条记录声明
   `逻辑名(别名) / pool / 该池内的真实 id / 是否该池默认 / 备注`。
   ★ 现有的两份（`tools/wb_dispatch.py` 的常量、`infra/pool/models.whitelist.toml`）**都要从它派生或指向它**，
   **不许再有第二份可写名单**（「多份真源」是本仓台账里的一条老坑）。
2. **默认值按池声明**：`--model` 缺省时，按**当前池**取该池的默认项。
   ★ **绝对不许"取注册表首项"** —— 那正是 146 踩的雷（跨池串了默认值）。
3. **按池分流**：派活时拿逻辑名 → 查出 `(pool, per-pool id)` → 交给**该池的适配器**。
   - `codebuddy` 适配器：起 CLI，`--model <per-pool id>`（**今天的行为一字不变**）；
   - `codearts` 适配器：**本卡只留接口 + 响亮拒绝**（「这个池的调用还没接」），
     ★ **不许静默回落到别的池**，也不许拿裸名去试。
4. **id 不许跨池串用**：把码道形式的 id（含 `/`）给 CodeBuddy 池、把裸名给码道池 ⇒ **当场拒并说清**。
5. **开关文件（`model-switches.toml`）也要按池**：现在的 `"glm-5.3" = true` 只对 CodeBuddy 池有意义。

## 判据（每条都要有反例钉子）

- ① **单层**：全仓只有一份**可写**的模型名单；`wb_dispatch` 的常量要么删掉、要么是"读出来的结果"
  （PEP 562 现读，照卡 146 已落的那套写法）。
- ② **默认不跨池**：注册表里码道项排在第一 ⇒ `--model` 缺省**仍必须是 CodeBuddy 池的默认**。
- ③ **跨池串用被拒**：`--model huaweicloud-maas/GLM-5.2` 在 CodeBuddy 池 ⇒ 拒（点名"这是 codearts 池的 id"）；
  `--model deepseek-v4.1-flash` 在 codearts 池 ⇒ 拒。
- ④ **未知池**：注册表里出现 `pool = "某个没接的池"` ⇒ 派活前**响亮拒绝**，不静默降级。
- ⑤ **找不到注册表 / 注册表坏掉** ⇒ 退 2、零副作用、点名（照卡 146 已落的两条路）。
- ⑥ ★ **本笔不许改变今天 CodeBuddy 池的行为**：裸名照旧、允许集照旧、429 轮换链照旧。

## 边界（如实写）
