## 要解决的问题

`pool.accounts_scope.ledger_path()` **自己重写了一遍锚点查找**，没走
`pool_accounts.find_ledger()` —— 于是它认不出 `TF_ACCOUNTS_TOML`：

```
$ TF_ACCOUNTS_TOML=<沙箱账本> python -X utf8 gates/diag/_probe_ledger_env.py
pool_accounts.find_ledger()      -> <沙箱>/accounts.toml
  认 env？True
accounts_scope.ledger_path()     -> D:/repo\infra\pool\accounts.toml
  认 env？False
```

两条后果，都只在**宿主目录形状不同**时暴露：

1. **云机 → 13 条红**：云机仓在 `C:/eng`，从那里向上没有 `infra/pool/accounts.toml`
   （卡 E54 明令**不许**把私有账本推上云机）⇒ `ledger_path()` 抛 `ScopeError` ⇒
   `wb_dispatch` 的第 ① 条闸「账号白名单读不了 ⇒ 不派活」把所有带 `--account` 的用例一律退 2。
   这些用例**本来已经**用 `_use_ledger()` 把 `TF_ACCOUNTS_TOML` 钉到沙箱账本 —— 只要
   `ledger_path()` 走 `find_ledger()` 就全绿，判据一个字都不用改。
2. **本机 → 静默读错账本**：本机从仓根向上**恰好**能找到 `D:/repo/infra/pool/accounts.toml`
   （仓的祖父目录），于是 `default_path()` 返回那份**真**账本的兄弟文件
   `account-scopes.toml`。今天那个文件不存在 ⇒ `load_scopes()` 回 `{}` ⇒ 看起来「不收窄、一切正常」；
   一旦有人在真账本旁边放了白名单，**测试就会读到宿主的私有策略**，而不是夹具造的那份。
   这是 `tests/test_wb_dispatch.py` 里那批用例「本机绿、云机红」的同一根因的另一面。

★ 判据的纪律已在卡 E49 立过：「锚点从**仓库根**向上找，不跟 cwd 走」。
`ledger_path()` 把这条抄成了「自己再写一遍向上找」，而**唯一实现**已经有
（`pool_accounts.find_ledger()`，它先看显式参数、再看 `TF_ACCOUNTS_TOML`、最后才向上找）。
两份实现 = 第二份真源，正是本仓最不想要的形状。

## 判据（六条）

1. **`ledger_path()` 必须是 `pool_accounts.find_ledger()` 的一层皮**，不许自己写循环。
   判据可执行化：`accounts_scope.ledger_path()` 与 `pool_accounts.find_ledger()` 在
   ① 显式 `path` ② `TF_ACCOUNTS_TOML` ③ 都没有（向上找）三种情形下**回同一个路径**；
   三处都对不上 ⇒ 红。**不许**用 `monkeypatch.setattr(pool_accounts, "find_ledger", ...)` 冒充
   「同一个实现」—— 钉子必须证明**源码里真的调了它**（见判据 5）。
2. **`TF_ACCOUNTS_TOML` 指向的账本，`default_path()` 必须跟着走**：把它指到 `<tmp>/accounts.toml`
   ⇒ `default_path() == <tmp>/account-scopes.toml`。这是判据 1 的可观察后果，也是最容易被
   改回「自己找」的那一处。
3. **`ledger_path()` 抛的错必须仍是 `ScopeError`**（不是 `LedgerError` 漏出来）：账本找不到时
   调用方 `wb_dispatch` 只捕 `ScopeError`；换成 `LedgerError` 会变成裸 traceback 而不是
   「响亮拒绝」。且文案里必须仍能读出「往哪放账本」。
4. **云上那 13 条必须真变绿**，且**不许改判据**：这 13 条用例一个字都不改（含它们的
   `TF_ACCOUNTS_TOML` 钉法与断言），只改 `accounts_scope.py`。反向自证：把 `ledger_path()`
   改回自己向上找 ⇒ 这些用例**本机也红**（用 `TF_ACCOUNTS_TOML=<沙箱>` + 一个不存在的
   宿主锚点模拟云机形状，见判据 6）。
5. **钉子不许只测行为，要测接线**：静默地把 `find_ledger` 换成一个「行为相同但独立实现」的
   桩，必须让接线钉子红。做法照本仓先例（卡 A342 的教训「别用子串钉接线」）：
   用 `dis.un` 读 `ledger_path` 的字节码，断言它的 `LOAD_*` 里出现 `find_ledger` 这个名字，
   **不是**断言源码文本里有这个子串。
6. **反向验证 ≥4 条，每条真改真跑真复原**（sha256 自证），必须包含：
   - M1 把 `ledger_path()` 改回「自己从 `TOOL_ROOT` 向上找」⇒ 判据 1/2/4 的钉子变红；
   - M2 把 `find_ledger()` 的 `TF_ACCOUNTS_TOML` 分支从 `ledger_path()` 的路径上摘掉
     （例如传 `explicit=None` 之外再多传一个空串）⇒ 判据 2 变红；
   - M3 把 `ScopeError` 换成 `LedgerError` ⇒ 判据 3 变红；
   - M4 把 `default_path()` 从 `ledger_path().with_name(...)` 改成「按 `TOOL_ROOT` 拼」
     ⇒ 判据 2 变红。
