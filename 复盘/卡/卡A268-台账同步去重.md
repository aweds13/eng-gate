# 卡 A268 —— 台账同步去重：同名条目重放时原地替换

## 为什么（今天撞了三次）
`tools/sync_docs.py::_merge_traceability` 以前只做「末尾追加」。同一张卡的片段一旦**重放**
（⓪ 回退后重跑、或上一趟已写进汇总又重来），`docs/traceability.toml` 里就会出现两个
`[entries."X"]`，TOML 直接报 `Cannot declare ('entries', 'X') twice`，把整笔落地拦在写后自检。
260 与 262 的重试都是撞在这一条上（见 `gates/diag/_land_260.log`、`_land_262.log`）。

## 做什么
1. `tools/sync_docs.py`：新增 `_TRACE_KEY_RE` / `_trace_key()`；`_merge_traceability` 改成
   **有同名键就原地替换（到下一个 `[entries.` 或文件尾），没有才追加**。
2. `tests/test_docs_fragments.py`：新增 `test_traceability_merge_replaces_duplicate_key`
   —— 同一片段合并两次，断言只有一个同名条目且 TOML 可解析、旧条目不被吞。

## 真读数（实测，2026-10-17）
- 合并一次 → 计数 1；再合并 → 仍是 1；`tomllib.loads` 通过，键集合 `{T-G900, T-G999}` ✓。
- `pytest tests/test_docs_fragments.py -q -k "replaces_duplicate_key or idempotent"` → 2 passed ✓。
- `python -X utf8 tools/sync_docs.py --check` → `[OK ] 片段 ↔ 汇总一致（changelog.d=123, traceability.d=123, 交接.d=123）` ✓。

## 边界
- 只动「台账汇总」的合并策略，不动片段格式、不动锚点、不动改动清单 ✓。
- 汇总里**老条目**（同名）若内容不同：以**新片段**为准（同一张卡重放时新片段是权威）✓。
