# 卡 E136：状态钉子拿「死秒数」当判据，机器一忙就红，挡的是别人的落地

> 台账号 T-AG645｜分区 E（门禁与可信度）｜树 `.wt/E136`｜层 判据层｜基准 `216fb64e`｜
> 依据：用户 m92988「把 pool 的使用打磨好，不计代价与 token」；m93503「之前的任务记得做完」。

## 要解决的问题（实测，不是推测）

### 问题 1 · 断言写死了「锁刚造出来 0~1 秒」

`tests/test_gate_lock.py:261` 原文（卡 E16 的钉子 ⑦）：

```python
    assert "已 0s" in out or "已 1s" in out, out       # 已持有秒数
```

这条断言拿**墙钟秒数**当判据。锁文件由夹具 `_write_lock()` 刚写出来，
`gates/diag/gate_lock.py:604` 的 `age_seconds` 是「现在 − 锁文件 mtime」，
`:634` 打印成 `（已 {age_seconds}s / 租约剩 {remain_seconds}s；…）`。
机器不忙时 age 是 0~1 秒；机器一忙（xdist 多 worker + 落地链并行）夹具与断言之间
隔了 4 秒，`age_seconds` 就是 4 ⇒ 断言红。钉子本来的意思只是「状态里必须有已持有秒数」，
它从来没打算判「这个数是多少」。

### 问题 2 · 它挡的不是一张卡：全量门禁里 1 passed 之外所有卡都跟着红

现场（卡 E125 / `T-AG634` 第三次落地，`gates/diag/land-E125e.log`，exit 1）：

```text
[FAIL] pytest                 exit=1  1408.38s  1 failed, 4993 passed, 1 skipped, 1506 warnings in 1405.22s (0:23:25)
       ↳ 红单归并（全量输出在 gates/logs/pytest.log）：
         × 1  [AssertionError] [锁] 段 base=9471 文件=gates-9471.lock: card=LIVEOWNER pid=21900 起于 2026-10-25T0…  ← tests/test_gate_lock.py::test_status_names_the_holder
★★ 门禁退出码 = 1（124 = 硬超时掐的）【全量】
★ 不绿 ⇒ 不提交
```

同一趟门禁 22 道门里其余 21 道全绿（含 pytest_chain 695.65s 22 passed）。
⇒ 一张与锁无关的卡（E125）烧了 23 分钟全量，红在一条**只判机器闲不闲**的钉子上。
隔离跑同一条是绿的：

```text
$ python -X utf8 -m pytest tests/test_gate_lock.py -o addopts= -q --no-cov -p no:xdist
9 passed in 27.79s
```

⇒ 不是代码坏，是**负载敏感**：判据依赖「夹具与断言之间不超过 1 秒」。

### 问题 3 · 这类「死数字」没有机器拦着，会长回来

卡 E126（`T-AG635`）修的是同一类病的另一处（`--days 0` 只在验证当天绿），
做法是「删掉随运行日变化的断言 + 加一条 ast 钉子拦住同类」。本卡照同一体例：
把随**运行时刻**变化的断言改成形状判据，并用一枚 ast 钉子拦住「拿死秒数当判据」的写法。

## 判据

### 判据 1 · 把那条断言改成形状判据，理由写进注释

- `tests/test_gate_lock.py::test_status_names_the_holder` 的秒数断言改成
  `assert re.search(r"已 \d+s", out), out`（`import re` 加到文件头部 import 段）；
- 注释必须写清「为什么不用死数」并指向本卡号，别只写「改成正则」；
- **不许**顺手删掉这条断言、也不许放宽成只看 `已` 一个字：钉子要保住的语义是
  「状态输出里有『已持有 N 秒』这个读数」，形状 `已 \d+s` 正好是它。

### 判据 2 · 加一枚机器钉子拦住同类写法

- 新建 tests/test_wall_clock_assertions.py（计划建）；
- 判据：ast 扫全仓 `tests/**/*.py`（现读，不写死清单），凡是**字符串常量**里出现
  `已 Ns` / `剩 Ns` / `age Ns` 这类「秒数」形状（正则 `[已剩] \d+s` 与 `\d+s 前` 两种），
  且该常量被用在 `assert` 表达式里的 `in` / `==` 比较上 ⇒ 红并点名 `文件:行号`；
- 允许的写法：正则匹配（`re.search` / `re.match` / `re.fullmatch`）或读结构化读数
  （`_status_payload` 的 `age_seconds`）再比较区间；
- 钉子自己必须有一条**负样例**（在临时合成小树上造一段坏代码 ⇒ 必须报出来），
  否则「扫不到」和「没有坏样本」分不开。

### 判据 3 · 反向变异 ≥3（每条真改真跑真还原，记 sha256）

- M-A：把判据 1 的正则改回死数字 `"已 0s"` ⇒ 判据 2 的钉子必须红；
- M-B：把判据 2 的钉子改成恒 `assert True` ⇒ 判据 2 的负样例必须红；
- M-C：把判据 2 的扫描范围从 `tests/**/*.py` 收窄到单个文件 ⇒ 负样例必须红；
- E1（安静对照）：只改注释、不动判据 ⇒ 一条都不许红。

### 判据 4 · 不许削弱既有钉子

- 卡 E16 的七条钉子（死主清理 / 活主不清 / 无 pid 不清 / `--grace 0` / release 点名 / status 点名）
  一条都不许删、不许改成恒真；
- `gates/diag/gate_lock.py` 一个字节不改（本卡只动测试）；
- 不许改 `tests/test_run_gates_proxy.py` 里卡 E126 那条 ast 钉子。
