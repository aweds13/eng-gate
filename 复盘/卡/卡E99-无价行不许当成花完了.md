# 卡 E99 —— pool 打磨：无价的行不许当成「花完了」

> 台账号 `T-AG608` ｜ 分区 E（号池子系统）｜ 树 `.wt/E99` ｜ 层 gate
> 依据（用户 m92988）：「把 pool 的使用打磨好（零调用方接线…），不计代价与 token。」
> 前情：E95（T-AG604）把「无价」的**写侧与读侧**都做出来了（`append(priced=...)` / `unpriced()`），
> 但**生产一个调用方都没接**：`tools/wb_dispatch.py:4020` 不传 `priced`，`unpriced()` 零读者。

## 要解决的问题（两个，同一条链）

1. **「不知道」被写成「知道」**：`tools/wb_dispatch.py:4020-4028` 写账时 `cost=0.0` 且不传
   `priced` ⇒ 每一行都被读成「有价」。于是 `unpriced()` 恒回 0 —— 仓里没有任何一处
   说得出「这些行没有价」。
2. **按钱限额是假绿**：`tools/pool/limits_check.py:98`
   `cost_over = limit.cost > 0 and used_cost + inflight_cost >= limit.cost`，
   而 `used_cost` 恒 0.0（同上）⇒ 写 `cost = 1.5` 的限额**永远不拦**，
   看上去「有判据」，实际一个都拦不住。同文件 :8-9 的纪律写明判据只许有这一份 ——
   所以修法**必须在 `limits_check.check()` 里**，不许在 `wb_dispatch` 里另写一个 `if`。

★ 为什么不是「补一个价目表」：`tools/pool/pricing.py:3` 与 `tools/pool/ledger_spend.py:7`
  都立过「不许内置价目表」，`复盘/卡/卡A338-限额要在派活之前拦.md:105` 逐字抄了这条。
  价目表是判据问题（谁维护、何时失效、涨价谁负责），不是接线问题。
  ⇒ 本卡只做一件事：**把「判不了」说出来，并在派活之前停下**（fail-closed，与
  「限额策略读不懂 ⇒ 拒派、不许当成没设限额」同型，见 `tools/wb_dispatch.py:3593-3596`）。

## 判据（5 条）

1. **写侧记「无价」**：`tools/wb_dispatch.py` 那段用量落账必须传 `priced=False`
   （`cost` 仍 `0.0`、仍走 `ledger_spend.append()`、不另写 JSONL）。
   钉子：跑一轮 ⇒ 账本那一行 `row["priced"] is False`、`cost == 0.0`、
   `ledger_spend.unpriced(account, start, end) == 1`；空账号仍**一行都不写**。
2. **判据加在唯一真源里**：`limits_check.check()` 增可选参数
   `unpriced: Mapping[int, int] | None = None`（第 i 条 limit 窗口里无价行的条数）。
   当某条 `limit.cost > 0` 且该条 `unpriced[i] > 0` ⇒ **拒绝**，`why` 点名
   「按钱那一支判不了：窗口里 N 行没有价」。`Verdict` 字段不增不减。
   钉子：`check([Limit(period="day", cost=1.5)], spent={0:(0,0.0)}, unpriced={0:3}, now=…)`
   ⇒ `allowed is False` 且 `"按钱" in why` 且 `retry_after_s >= 1`。
3. **不误伤**（这是本卡最容易做错的地方）：
   - `unpriced=None`（缺省）⇒ 行为与今天**逐字节相同**（`tests/test_pool_limits.py` 32 条 pin 一条都不许改）；
   - `limit.cost == 0` 的纯 tokens 限额 + `unpriced={0:99}` ⇒ 仍按 tokens 判，不因「有行无价」拒；
   - `limit.cost > 0` 且窗口里 `unpriced[i] == 0`（老的有价行）⇒ 仍按 `used_cost >= limit.cost` 判；
   - 已花完（`over` 非空）与「判不了」同时在 ⇒ 仍按既有次序报「已花完」那条（不许把确定的结论降级成不确定）。
   钉子：四条各一条，都直接调 `check()`。
4. **派活之前，同一条出口**：`tools/wb_dispatch.py` 的限额闸把 `unpriced` 算出来传进去
   （与 `sums()` **同一个 now、同一个窗口**），拒的时候并进既有的 `problems`：
   `[FAIL] 不派活 —— 前置检查没过：` 出口、**不新开退出码**、**不占树**。
   钉子（走 `tests/test_pool_limits_wiring.py` 的真派活路径）：
   写 `[[codebuddy-demo.limit]]\nperiod = "day"\ncost = 1.5` + 账本里先有一行无价
   ⇒ 退出码 2、stderr 有「按钱」、`reserve` 没被调、没有 `pool-registry.json`。
5. **反向变异 ≥4 条**（`gates/diag/_rev_E99.py` 本卡新建，落在主树、逐条真改真跑真还原并记 sha256）：
   A 写侧去掉 `priced=False` / B `check()` 把 `unpriced` 恒当空 / C 有金额限额且无价行时只打印不拒 /
   D 把「已花完」让位给「判不了」（次序反过来）。四条各自必须让对应钉子红，还原后 sha256 与基线一致。
