## 来路（用户问的就是这一条）

用户问：*「为什么你总是能发现后门呢？是不是缺乏一个**审核**以及**需求架构的整理**？…后面为什么总是有？」*
主控的诊断（写进了当晚复盘）：**需求与架构文档不缺**（`外包工具-需求与架构` / `架构审议` / `口径坑` / `门禁改进清单`），
**缺的是"不变量台账"** —— 没有任何一份东西说清「这套系统的**安全主张**有几条 → 每条由**哪段代码**判 →
**反例钉子**在哪 → 现在**覆盖到没覆盖**」。于是每加一个能力，安全主张就多一条，而**没人知道它还没被判**。
★ 立的规矩（本卡要把它变成可执行的）：**新能力没进这张表，就不算做完。**

## 要做什么（两个新文件）

1. **`复盘/不变量台账.toml`（新，进 git）** —— 一行一条，字段：
   `id` · `claim`（一句人话，说清"什么不许发生"）· `judge`（**判据在哪**：`路径::符号` 或 `路径` + 一句命令）·
   `nail`（**反例钉子**：`tests/<文件>::<用例名>`）· `status`（`covered` / `partial` / `missing`）· `note`（诚实说明）。
   ★ **初版必须把今晚这些真的写进去**（**一条都不许编**：写之前先去看代码，找不到判据就老实写 `missing`）：
   ① 门禁全绿才能提交；② 收口**只有一个写者**（+ 门禁锁）；③ 提交必须带 `Task:/Refs:/Gates:` 且 `Gates:` 是**真的**；
   ④ 收批**集齐申请才放行**（按申请、不按数量）；⑤ **树/域/锁三条守卫**；⑥ 记忆层三条（没登记不许派活 / 树必须落在
   该项目 `tree_prefixes` 里 / 反查不到拒）；⑦ MCP 写面「**存在性即授权** + `confirm` 等于卡号」；
   ⑧ 模型**默认拒绝**（名单是下限）；⑨ **只增不减**（凭据快照 / 白名单 / 账号快照）；
   ⑩ ★ **假绿家族**（这一族**至少两条要老实标 `missing` 或 `partial`**）：ff 失败仍打印"合流完成" ·
   退出码 0 其实没跑完 · 豁免当通过 · `Gates:` trailer 只查存在性 · ★ **门数≠17 冒充全量门禁**
   （`wb_verify` 查、**`wb_review` 不查** —— 这是卡 140 自己发现的后门）· 片段"单向缺失"查不出来。
2. **`tools/wb_invariants.py`（新）**：
   - `--check`：逐条核 **`judge` 与 `nail` 真的存在**（路径在不在 / 测试文件里有没有那个用例名；
     命令只核**路径**、**不真跑**门禁）—— ★ **有一行对不上 ⇒ 非零退出并点名**（台账**不许烂掉**）；
   - `--missing`：**只列** `missing` / `partial` 的条目（★ 这就是那份"**待验台账**"：每条该有人去关）；
   - `--list`：按 `status` 分组打印（人读）。
   - ★ `missing` 是**状态**、**不是错误** ⇒ `--check` 对"有 missing 条目"的台账**仍然通过**（别把"诚实"判成失败）。
