# 卡 D4 · 模型清单与凭据（list-models 原样列出 + BYOK 三槽 + 改名降级）

- task: T-DG004
- tree: `.wt/D4`
- risk: mid
- depends: D1

## 问题

用户明确否决「快/强」语义档位：「你只要把清单拉过来，然后我自由选择什么模型点一下就行。」
同时用户担心「模型会更新，不同的前缀名字会有不同」。所以本卡的核心不是界面，是
**清单的唯一真源 + 改名后的降级不死**（conventions C4、flows FL-5）。

## 改法

1. `ModelCatalog.kt`：`GET {baseURL}/api/list-models`；**兼容解析**（`data[]` / `models[]` / 顶层数组都认，
   因为返回结构未验证）；缓存 + 手动刷新；拉不到时退回上次清单 + 允许手填模型名。
2. `KeyVault.kt`：Android Keystore 加密；三槽 `chat` / `utility` / `vision`，各存 `{apiKey, baseURL, model}`；
   `vision` 未配则回落 `chat`。日志里 key 一律 `sk-****`。
3. `Catalog.ts`：顶部模型名 → 弹清单 → 点选；**不做任何语义档位**。
4. 失效降级：识别 400 / 错误体指向模型名 → 刷新清单 → 保留会话 → 给候选（名字相似 / 同系列）→ 重发。

## 判据

- 清单里 ≥2 个模型，名字来自接口（改接口返回的假数据，界面跟着变，证明没写死）。
- 把模型名改成 `no-such-model` 发消息 → 出现「清单变了，重选一个」+ 候选列表，**消息不丢**，
  选一个候选后重发成功。
- 三槽分别填不同 baseURL/key → 各自生效；视觉槽留空时走对话槽。
- `adb shell run-as <pkg> ls files/` 与 `grep -r "sk-"` → **看不到明文 key**。
- 选 `deepseek-v4-pro` 时附图片 → 本地当场拦（不发出去等 400）。

## 证据

- 一次「改名 → 降级 → 恢复」的完整录屏。
- Keystore 加密后目录清单（无明文）。
- 清单接口原始返回（打码 key）。

## 不做

- 不做「推荐模型」算法（用户自己会挑）。
- 不做多账号切换（一个 key 就够；以后再说）。
