## 2.5 逐条实证（pass2 的原文，别再猜）

- **B 类不是「设 env 就能过」**：好几条钉子**自己 `monkeypatch.delenv("TF_PROJECTS_TOML")`**
  （`tests/test_pool_guards.py:244` 就是），所以导出环境变量对它们无效。
  正解是让「从 cwd 逐级向上找 `infra/pool/*.toml`」在云机上也能命中 ⇒ 把仓外配置放到
  `C:/infra/pool/`（云机仓库在 `C:\eng`，上一级就是 `C:\`），与 `run_gate.sh` 里
  `TF_PROJECTS_TOML` fail fast 并存（两条路都要能走）。
- **`test_pool_lib` 三条的真因是「判据依赖 gitignored 目录」**：`validate()` 要求
  「声称属于 B-INVGATE 的卡，预声明 `gates/diag/batch/B-INVGATE.toml` 必须存在」，
  而 `gates/diag/batch/` 是 gitignored、云机 `git clean -xfdq` 之后整个目录没了 ⇒ 红。
  本机绿是因为那个目录里恰好有文件。处置：要么钉子自己造预声明文件，要么 `validate()`
  区分「未登记」与「宣称了不存在的批号」。
- **`test_pool_accounts` 两条**：`find_ledger()` 报「没找到账号账本」——
  账本本体在仓外 `D:/repo/infra/pool/accounts.toml`，云机没有；
  fixture 只 patch 了路径常量、没设 `TF_ACCOUNTS_TOML`/`--ledger` ⇒ 同上，配置落 `C:/infra/pool/`。
- **`test_concurrency` 的 `assert 5 == 8` 是判据自身的假红**：它拿 `id(conn)` 去重，
  而 CPython 会复用已回收对象的地址，且 `ThreadPoolExecutor(max_workers=8)` 在慢机上
  不一定真起 8 条线程 ⇒ 必须改成「线程 ident → 连接」而不是「连接 id 去重」。
- **`test_contract_audit`**：`judge_red=1`（本机 `judge_ok=10 / no_judge=3`）——
  说明有一条契约的判据本身在云机跑红，得靠 `--json` 逐条读出是哪一条（本卡第一步就做这个）。
- **`test_wb_land::preflight`**：期望文案 `缺文档件 … _text_TG999.md`，
  云机实际多了一条 `本树没有可用的 gates/diag/gate_lock.py ⇒ 锁状态 not verified` ⇒
  钉子钉的是「第一条」，环境少了锁文件就换了一条 ⇒ 同类 `gitignored` 依赖。

## 2.6 实际处置（与草稿不同的三处，逐条写清「为什么不是草稿那个改法」）
\n
1. **B 类的真因不是「没导出 env」，是「索引里的 root 是开发机路径」。** 草稿写的是「导出
   `TF_PROJECTS_TOML` 就绿」；实测不是 —— 仓外 `projects.toml` 里
   `[project.engineering].root = "D:/repo/engineering"`，原样搬上云，
   那个目录**不存在**，项目守卫按「宁拒不许猜」拒掉：
   `项目索引读不了（项目守卫判不了）：项目 engineering 的 `root` 不存在：D:/docs/…`。
   所以导出 env 只是把「找不到文件」换成「找到了但根不对」，红不消失。
   处置改成**渲染**：仓内新增 `scripts/cloud/pool-config/projects.toml.tmpl`（`root = "__REPO_ROOT__"`），
   `run_gate.sh` 的 0.45/5 步把占位符换成云机仓库目录，写进 `C:/infra/pool/projects.toml`
   —— 那正是 `tools/pool/*.py` 从 cwd 逐级向上找 `infra/pool/` 会命中的位置。
2. **E 类不做「not-run」，做「探测 + 大声失败」。** 草稿说「探不到 bash 就如实报 not-run」；
   实际判据更强：`test_cloud_sync.py` 的 `_find_bash()` 先 `shutil.which`、再试
   `C:/Program Files/Git/bin/bash.exe` 等三处；**都找不到就 `pytest.fail`**，理由写
   「Git for Windows 是云机装配必装项」——因为 `run_gate.sh` 本身就要 bash，缺了它门禁根本
   跑不起来，此时报 not-run 反而掩盖装配缺失。
3. **新增 F 类（草稿里没有）：判据自己读不回子进程输出。**
   `skills/nails/check_commands.py` 用 `subprocess.run(..., text=True, encoding="utf-8")` 读
   `pipe --help`，云机中文控制台按 GBK 输出 ⇒ `UnicodeDecodeError: 'utf-8' codec can't decode
   byte 0xc3 in position 57` ⇒ 崩掉 ⇒ 命令集空 ⇒ 假红「`pipe init` 不存在的命令」。
   同一颗钉子还有第二个坑：找不到 CLI 时 `raise SystemExit(...)`，对账器把非 0 一律当红。
   处置：①解码兜底 UTF-8 → GBK → `errors="replace"`；②**缺前置 ⇒ 退出码 3 = 「未验证」**，
   `tools/contract_audit.py` 把 judge `rc==3` 映射成 `no_judge`（如实计入，不算绿也不算红）。
   实测云机上 CX-02 现在 `judge_ok`（10/3），本机无 CLI 的机器走 9/4。
\n
4. **「删掉 last.json 再断言没有」是错的，正解是「显式播种上一趟读数」。**
   `gates/last.json` / `gates/reuse.json` 是**入库文件**（`git ls-files` 在云机上确认）：
   `git clean -xfdq` 只清未跟踪/被忽略的文件，清不掉它们；`checkout -f` 又会把提交里那份
   **陈旧基线**恢复回来，于是自指钉子（`test_false_success_pins`）把上一笔的读数当成「上一轮」。
   反过来删掉也不行：审计 ⑫ 有两条台账 evidence 引着这两份产物（`T-00`、`T-G47`），
   删了审计立刻判「断言不成立」⇒ CX-10 判据连带红、`test_docs_fragments` 也跟着红。
   处置：`TF_LAST_SEED`（默认 `.wt/<卡>/gates`）从**本机** scp 一份绿的上去覆盖，第二步据此断言。
5. **云机的 `Set-Content -Encoding UTF8` 会写 BOM**，`tomllib` 直接 `Invalid statement (at line 1, column 1)`
   —— 这一颗就把 `test_mem_guard`(2) / `test_pool_guards`(2) / `test_pool_lib` / `test_pool_projects` /
   `test_pool_registry`(2) / `test_pool_task` / `test_wb_dispatch` / `test_wb_land::preflight` 一串全咬红。
   处置：`[IO.File]::WriteAllText($path, $c, (New-Object System.Text.UTF8Encoding($false)))`。
6. **`TF_MODEL_WHITELIST` 不注入 ⇒ 码道池整池消失**：`tools/pool/model_registry.py` 的
   `CODEARTS_SOURCE_ENV = "TF_MODEL_WHITELIST"` 是码道条目的**唯一**来源，云机上只剩 codebuddy 池，
   `test_model_registry` 三条（跨池串用 / CLI 退 2 / 要有 codearts 条目）必红。处置：`envset` 里一并注入。
7. **3.12 的 `TOMLDecodeError` 没有 `.lineno` 属性**（3.13+ 才有）⇒ 「点名第几行」的判据在云机退化成没有行号。
   处置：`tools/pool/models.py` 新增 `_line_of(exc)`（先取属性，再从 `at line N` 里抓），已用 uv 的
   cpython-3.12.14 实测：属性 `None`、`_line_of` 返 `2`。

## 3 判据（每条要钉子）

1. A 类钉子改成显式期望集后，**在 3.12 与 3.14 上都绿**（用 uv 的 cpython-3.12.14 跑一遍，把读数写进卡）。
2. B 类：`run_gate.sh` 导出三个 env 后，云机上 `pytest -k "pool_projects or pool_lib or pool_guards"` 转绿；
   本机不设 env 时仍绿（不许把本机拖红）。
3. C 类：`bootstrap.ps1` 装 `pywebview` 后云机 `mypy` exit 0；`pyproject.toml` 的 dev extras 与 bootstrap 的
   版本清单**逐字一致**（钉子：读两个文件比对集合）。
4. D 类：每条都要写清「是判据太贴本机 / 还是真依赖」，并给出**改前红、改后绿**两段读数。
5. E 类：钉子在探测不到 bash 时输出 `not-run` 理由，门禁把它算**未跑**（不是通过）。
6. 收官判据：云机第三趟（`cloud-verify-E35.sh 3`）`pytest` 与 `mypy` 双双 exit 0 ⇒
   E35 台账 `partial → done`、删 `[exceptions]` 里那条 T-AG489、另起账务提交。
