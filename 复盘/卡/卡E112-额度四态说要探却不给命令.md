## 要解决的问题（逐条实测，不是推测）

### 问题 1 · 三态都说「要探」，读者拿不到那条命令

实测（主树 `dd0b1267`，`python -X utf8 tools/pool_quota.py status --card A318 --model kimi-k3-1 --now 2026-11-16T12:00:00+08:00`）：

```text
[额度] 卡 A318 · 模型 kimi-k3-1 —— 已过期，需重新探测
  过期 564:34:11（记录重置时间 2026-10-23T23:25:49+08:00；现在 2026-11-16T12:00:00+08:00）
  ★ 过期 ≠ 可用，要探
  判据：reset_at <= now（过期 2032451 秒）—— 过期 ≠ 可用，要探
```

四行里「要探」出现两次，**没有一处是可执行的命令**。另两态同病：`余额耗尽` 打「不自动等，只能探」，
`未记录` 打「不猜（★ 不许默认当可用）」—— 三态都把最后一步留给读者自己猜。

真人可跑的只有一条，藏在 `tools/pool_accounts.py` 的 docstring 里（`:13`）：
`python -X utf8 tools/pool_accounts.py probe [--json] [--offline] [--platform X]`。
实测 `probe --offline` 退 0、输出 5 个号的结论（`skipped=4 · uncertain=1`）；`probe --offline --platform codebuddy` 只留 codebuddy 一行。

模块内两处指针也只到「在哪个文件」为止：`tools/pool_quota.py:849` 与 `:875` 都写「探测在 tools/pool_accounts.py」。
MCP 面（`tools/pool_mcp.py:1414-1416`）把 `status()` 原样当 payload、把 `render()` 原样当人话段 ⇒ 缺口一路透到机器读者。

### 问题 2 · can_dispatch 四态恒 False —— 「不知道」被写成「不能派」

`tools/pool_quota.py:477` 是全文唯一一处赋值：`"can_dispatch": False`；四态分支没有一个把它翻成 True 或 None。
实测四态 `status(...)["can_dispatch"]` **全 False**（限流中 / 已过期 / 余额耗尽 / 未记录）。

而四态里**只有「限流中」是确定的不能派**（`reset_at > now`，有钟表读数）；其余三态的判词自己就是「要探」「不猜」。
给机器读者一个恒定 False，等于把「不知道」说成「确定不能派」—— 这正是本仓反复咬的那条
（`tools/pool/cleared.py:27` 与 `docs/subsystems/pool/模型与号池.md` 的「未记录不当可用」同一族）。

消费者盘点（子 agent 已逐条核过）：生产代码**只有 MCP payload 与 CLI 人话**读它；`tools/pool/quota_line.py` 的
`one_line()` 只读 state/card/model/recorded_at/remaining_seconds，不读 can_dispatch；面板与前端 0 命中。
⇒ 改它不牵动派活分派（分派走 `wb_dispatch.quota_error` + `pool.route.reset_for`），代价小、收益是读面不再撒谎。

## 判据

### 判据 1 · 探的命令只有一份实现，三态都把它念出来

`tools/pool_quota.py` 新增（模块级，供 CLI / render / MCP 三处共用）：

- `PROBE_SCRIPT = "tools/pool_accounts.py"`、`PROBE_ARGS = ("probe",)`；
- `probe_command(platform: str | None = None) -> str`：返回**逐字可跑**的一条，形如
  `python -X utf8 tools/pool_accounts.py probe --platform codebuddy`；
  给了平台才带 `--platform`，`platform` 为 None 时**不带**（跑全量），**不许**编一个平台名；
- `probe_hint(platform: str | None = None) -> str`：一句话 —— 给命令，并**明说它不改四态读数**：
  「要探就跑：<cmd>（它会写仓外账本的观测时刻；`gates/diag/quota-state.json` 只由 429 派生，探完四态未必变）」。

`render(st)`（`:519`）在 `限流中` 之外的三态各追加一行 `  要探就跑：<cmd>`；平台取 `st["probe"]["platform"]`。

**钉子**（`tests/test_quota_clock.py`）：

- `test_every_needs_probe_state_hands_out_the_command`：三态（已过期 / 余额耗尽 / 未记录）的 `render()` 人话段里
  必须出现 `tools/pool_accounts.py probe` 这一串，且**逐字**等于 `pool_quota.probe_command(...)`；`限流中` 不许出现它
  （确定不能派时不该叫人去探）。
- `test_probe_hint_says_what_it_does_not_do`：`probe_hint()` 必须同时含 `quota-state.json` 与「未必变」两个意思
  （用「不许承诺」的反向断言：hint 里**不许**出现「探完就会变」「即可派活」这类承诺 —— 断言 `"就会" not in hint`）。

### 判据 2 · can_dispatch：确定不能派才是 False，其余是 None

`status()` 四态里：`限流中` ⇒ `can_dispatch=False`；`已过期，需重新探测` / `余额耗尽` / `未记录` ⇒ `can_dispatch=None`。
新增 `can_dispatch_reason`（一句话）：False 那态写「reset_at 还在未来 ⇒ 确定不能派」，None 三态写「不知道 —— 要探」。

**钉子**：

- 四态那条既有钉子（`tests/test_quota_clock.py:38/52/71/84`）的 can_dispatch 断言**按新语义改**：
  `限流中` 仍 `is False`，其余三条改 `is None`（这是本卡的语义变更，不是削弱 —— 同时新增下面两条）。
- `test_can_dispatch_none_is_not_false`：`None is not False` 且 `bool(None) is False` —— 钉住「Python 里假值不等于判词」，
  并断言 `can_dispatch_reason` 在 None 三态里都含「不知道」，False 那态**不含**「不知道」。
- `test_mcp_payload_keeps_unknown_as_null`（`tests/test_pool_mcp.py`）：`quota_status` 的机器块里，未记录态的
  `can_dispatch` 在 JSON 里是 `null`（不是 `false`）；解析 `_fence()` 后的 JSON 块断言 `data["can_dispatch"] is None`。

### 判据 3 · 平台取记录里的 pool 名，取不到就明说取不到

`status()` 新增 `probe` 键：`{"command": str, "hint": str, "platform": str | None}`。
`platform` 取记录的 `pool` 字段（真数据里今天只有 `codebuddy`）；`未记录` 态没有记录 ⇒ `platform=None`，
`hint` 明确说「不知道是哪个号池 ⇒ 命令不带 `--platform`（跑全量）」。

**钉子**：

- `test_probe_command_carries_the_recorded_pool`：合成记录 `pool="codebuddy"` ⇒ `probe_command("codebuddy")` 含
  `--platform codebuddy`；`probe_command(None)` **不含** `--platform`。
- `test_unrecorded_state_does_not_invent_a_platform`：`status(card="nope", model="nope")` 的 `probe["platform"] is None`，
  且 `probe["hint"]` 含「不带 `--platform`」。
