## 要做的事

### 1. `tools/pool/landing.py` 第 ⑥ 步 —— **只在这张卡自己的落地时**翻 status

**插入点（现读，行号以你拿到的树为准）**：`=== ⑥ 白名单 → add → commit ===` 那段里，
`allow += list(DOCS) + list(GATES)` **之后**、`staged, extra = staged_and_extra(wt, allow)` **之前**。

**判据（这就是安全边界，别改）**：**当且仅当** `--task` 等于队列 `docs/workbacklog.toml` 里
`--card` 那张卡的 `task` 字段时 ⇒ 这是**这张卡自己的落地** ⇒ 把它的 `status` 翻成 `done`，
并把 `docs/workbacklog.toml` 加进 `allow`（于是**随这一笔进提交**）。

★ **为什么不能只看 `--card`**：本仓的**登记/收尾提交**也用 `--card <号>`（现场：登记卡 203 那笔用的是
`--card 203 --task T-G307`，而卡的号是 `T-G308`）⇒ 只看 `--card` 会把**还没干的卡标成 done**。
`--task == 卡的 task` 这条把两者天然分开。

- `--batch`：**逐个成员**用同一判据。
- 翻的时候**如实打印一行**：`[队列] 卡 203：pending → done（这一笔是它的落地）`。
- **找不到卡 / 找不到 `status` 行 / 那行已经是 `done`** ⇒ 打印一句并**跳过**（不许崩、不许猜、不许新建卡）。
- ★ **写文件要 CRLF 感知**（那份文件是纯 CRLF；用 `\n` 匹配会静默不生效 —— 主控本轮真踩过）。
- ★ **顺序**：这一翻必须在 `staged_and_extra` **之前**完成，否则它会被当成"计划外暂存"而停手。

### 2. `tools/wb_plan.py` 加一条判据 —— 「已落却仍 pending」

- 对队列里**每一条** `status = pending` 的卡：若它的 `task` 号出现在 `git log` 的 `Task:` trailer 里
  ⇒ 报 **`已落却仍 pending`**，**点名卡号 + 那笔提交的短 sha**。
- ★ 前提写进它的 docstring/`--help`：**一卡一号**（登记/收尾提交必须用自己的簿记号；本仓已在这么做）。
- ★ **反向保护（三条都要）**：① 不许把 `done` 的卡报成错；② 不许把**队列里没有条目**的已落卡
  （现场：193/194/195/196）牵进来；③ 没有 `git` 时**优雅跳过**（不许崩、不许当通过）。
- 入口自定（并进 `check` 或独立开关都行）—— 但**必须机器可跑、可测**。

### 3. 测试（`tests/test_wb_land.py` + `tests/test_wb_plan.py`，先红后绿）

- **正向**：一笔 `--task == 卡.task` 的落地 ⇒ 提交里那张卡的 `status` 是 `done`（一条端到端）；
- ★★ **反例（最重要）**：一笔 `--task != 卡.task` 的（登记型）⇒ 那张卡的 `status` **一字不动**；
- 判据红：造一张 `pending` 卡 + 找到它 `task` 号的提交 ⇒ **红并点名**；翻成 `done` ⇒ 绿；
- 反过来：**没有**对应提交的 pending 卡 ⇒ **不许报红**（这条错了会天天误伤）。
