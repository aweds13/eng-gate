# 卡 A300 · 接管旧项目：`pipe-takeover` 技能 + 只读勘察器

## 背景
`复盘/接手能力-方案.md`（A299，K3 稿）给了八节：四类项目、映射表、六条限制、最小骨架、
C 类五步验收、六种假成功、本仓特例、下一张卡的五步。本卡只落**第 1–3 步**（勘察器、
映射表、限制清单），第 4–5 步留给下一张卡（端到端验证 + 失败模式钉子）。

## 交付（全在卡树内）
1. `skills/pipe-takeover/SKILL.md`（≤120 行）：接手旧项目的**顺序**——分四类 →
   出映射表 → 套限制清单 → 最小骨架 → 第一步验收。只写操作顺序与前置检查，
   判据放工具里（与 `skills/README.md` 的分工一致）。
2. `skills/pipe-takeover/references/classify.md`：四类判据（A 已有完整管线 /
   B 有测试无门禁 / C 裸仓 / D 别人的框架），每类给「怎么认」的可执行读数。
3. `skills/pipe-takeover/references/mapping.md`：自然语言约定 → 机器表；「不映射」
   是一等值（写 `none`，不是省略）。
4. `skills/pipe-takeover/references/limits.md`：六条禁止（不改对方主干、不装依赖、
   不动 CI、不覆盖已有测试、不引入新语言运行时、不删对方文件）。
5. `tools/wb_takeover.py`：**只读**勘察器，`--root <目录> --json`，输出
   `{ok, kind: "A"|"B"|"C"|"D", readings: [...], mapping_hints: [...]}`；
   零写盘、零网络、非零退出只在「目录不存在」时用。
6. `tests/test_wb_takeover.py`：用临时目录造 A/B/C/D 四种形态，逐类断言；
   再断言对不存在目录返回 `ok:false` 且退出码非 0。
7. `skills/README.md` 的目录表补一行 `pipe-takeover`（只加一行，不动别的）。

## 判据（门会咬）
- `python -X utf8 tools/wb_takeover.py --root . --json` 在**本仓**应判 `A`（有
  `docs/workbacklog.toml` + `gates/last.json` + `tools/wb_*.py`）。
- `ruff check .` 干净；`python -m pytest tests/test_wb_takeover.py -q` 全绿。

  仍全绿（新技能要能被三处登记看到）。
- 技能行数：`SKILL.md` ≤120 行；`skills-ref validate skills/pipe-takeover` 通过。
