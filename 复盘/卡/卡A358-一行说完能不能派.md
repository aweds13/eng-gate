## 要解决的问题

pool 没有「一行说完」这个东西（`grep` 零命中）。近似物是 `tools/pool_quota.py:519-535 render(st)` —— 它**多行**、每行都在念判据。那是对的（「把判据念出来」），但**不是**「一眼能看完、不占屏」那种。

magpie 的 statusline 解决的是同一件事：Claude Code 只在那条命令结束时显示一行，所以多一个字都是噪音。它有三个硬决定值得照抄：
- **问不到就打空行**（`statusline_cli.go:67` 返回 `""`），**不是** `"?"` —— 空行 = 「这行不说话」，而 `"?"` 会被读成「有一个不知道的额度」，那是**多说了**。
- 只有**最新那条**带星号（`freshest()`），而且星号**紧贴名字、前面不加空格**（`:149`）。
- `>= 1 小时` 时**不带秒**（`:151` 的五对替换 + `:168` 只到整数）—— 这是「一行」的硬约束。

## 判据（15 条，逐条可执行）

**本卡的判据就是设计原件 §F92「判据逐条」那 15 条**，逐字照做：

1. `one_line([])` 返回 `""`（不是 `"?"`、不是 `"（无）"`）。
2. `one_line` 在**所有** `state == "未记录"` 且 `only` 为空时返回 `""`（`未记录` 这一态在 `pick()` 里被丢掉）。
3. `pick()` 丢掉 `state == "未记录"` 的条目、丢掉 `recorded_at` 为 `None` 的条目，**其余全留**（四个态里的另外三个都留）。
4. `pick()` 在 **`only` 非空**时按 `matches()` 过滤，且**「最近答过话的优先」不生效**（对应 `:122` 的 `len(only) == 0 &&`）。
5. `pick()` 在 `only` 为空且存在多条**按 `recorded_at` 同一天**的条目时，**只留最晚那一批**；同一天 = 同一个 `recorded_at[:10]`。
6. `matches()` 比**且只比**三个字符串：`st["card"]`、`st["model"]`、`f"{st['card']}/{st['model']}"`；**空串不参与**；比较**大小写不敏感**（`.casefold()`）。
7. `freshest()` 返回 `recorded_at` 字典序最大的那条的 `f"{card}/{model}"`；`recorded_at` 全 `None` ⇒ `""`；**并列取第一条**。
8. `one_line` 里 **`*` 只加在 `freshest()` 那一条**上，位置是**名字末尾、前面不加空格**（`"A318*"` 不是 `"A318 *"`）。
9. 一格的拼法逐字：`f"{card}/{model}"` + （`*` 若 freshest）+ `CELL_SEP` + `short_state`；`限流中` 的 `short_state` 是 `short_hms(st["remaining_seconds"])`（**不是** `_hms` 的 `HH:MM:SS`）。
10. `short_hms(6024) == "1h40m"`；`short_hms(59) == "0m59s"`；`short_hms(3600) == "1h0m"`；`short_hms(None) == "?"`；`short_hms(-1) == "?"`（**负数当没有**）。
11. `short_hms` 当 `>= 3600` 时**不许带秒**（`6024 → "1h40m"` 而非 `"1h40m24s"`）。
12. 段间**只用 `SEP`**（`" | "`），格间**只用 `CELL_SEP`**（`" "`）；返回串里**不许出现 `"\n"`**、**不许出现 `"  "`（两个连续空格）**。
13. 输入**顺序即输出顺序**（不排序、不按卡聚合）—— 排序归调用方，本函数只渲染。
14. 对**不认识的 `state`** 抛 `KeyError`（照 `tools/pool/holds.py:145-147 why_text` 的口径：只认那一小撮原串，别的直接 `KeyError`，不编话兜底）。
15. `one_line` **零 IO**：模块 import 后 `sys.modules` 里不出现 `tools/pool/lastgood`、`pool_accounts`、`socket`、`urllib`、`http`（源码级断言）。

**常量逐字**：`SEP = " | "` / `CELL_SEP = " "` / `STAR = "*"` / `SHORT = {"限流中": "", "已过期，需重新探测": "过期", "余额耗尽": "耗尽", "未记录": "未记录"}` / `UNKNOWN_HMS = "?"` / `HOUR_MIN = 3600` / `MINUTE_S = 60` / `NO_DATA = ""` / `MAX_ONLY = 32`。

★ **`MAX_ONLY = 32` 没有 magpie 出处**（magpie 的 `only` 是人打的、无上限；pool 是为了防将来被脚本调用时 O(n·m) 扫描才加的护栏）。**注释里必须如实标这句话**，不许把它写进「照 magpie 移植」的话里。

## 缺口的如实交代（进 changelog 的 gaps）

1. **pool 画不出百分比**：magpie 的 `w.Used`（`quotas.go:128`）在 pool 侧**零来源** —— 真 `gates/diag/quota-state.json` 18 条记录没有 `used`；仓外 `D:/repo/infra/pool/accounts.toml` 4 个号的 `[account.quota].used_percent` **全是 `None`**；`tools/pool/quota_history.py:16` 自己写着「`used_percent` 全仓零写方」。⇒ 一格只能是一个态标记 + 倒计时。**这不是取舍，是没料。**
2. **`LastServedAt` / `Last` 无对应物**：magpie 的 `*` 咬的是「这个号上次**答过话**」（`served.go:24` 30 天窗口），pool 只有 `recorded_at`（上次**读到额度**的时刻）。两者不是一回事（一个号可以「昨天答过话、今天没读到额度」）⇒ 本设计用 `recorded_at` 顶替，**语义已经漂了** —— 星号在 pool 里该读作「最新读到的」，不是「最近答话的」。想真对齐得先有「谁答过话」这本账（今天没有）。
3. **`windows` 多窗结构无对应物**：magpie 一个号带多个窗（`QuotaSpan`），pool 一个 (卡,模型) 只有一个 `reset_at` ⇒ magpie 的六级 switch（`Unlimited`/`Balance`/`Text`/`ResetsAt`/default）**一支都用不上**。`holds.Window` 与 `quota_history.QuotaPoint` 是形状对得上的两个候选，但两者都「由调用方转过来」，今天没东西产出那个形状。
4. **`alias` / `user` / `provider` 三个可比值无对应物**：magpie 比五个串，pool 只有 `card`/`model` 两个真值 ⇒ 等比缩到三个串。`model_registry.ModelEntry.alias` 是「逻辑名 → 每池 id」，与这里无关。
5. **`MAX_ONLY = 32` 是本设计新加的护栏，没有 magpie 出处**。
6. **只在合成读数上验过**：真 `quota-state.json` 里 18 条记录的 `kind` 只有 `"余额耗尽"`（17 条）与 `"限流"`（1 条），而 `status()` 产出的是四个**中文**字面量 —— **`kind`（账本字段）与 `state`（`status()` 产出）是两套字面量**（`"限流"` ≠ `"限流中"`）。本设计只认 `status()` 的产出，不认 `kind`；这一点没有真实数据能验，只能靠夹具。
