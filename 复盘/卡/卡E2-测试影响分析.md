# 卡 E2 —— 测试影响分析（TIA）：按覆盖映射选测

> 台账号 T-AG444 · 分区 E · 依赖 E1

## 目标

pytest 从「全量 2955 条 / 427 s」变成「改动面相关子集 / ≤90 s」，且**宁可多跑不许漏跑**。

## 判据

1. 映射生成器 `tools/tia.py --build`：逐测试跑一遍并采覆盖率（`coverage run --context=<nodeid>`），
   产出 `gates/tia.json` = `{test_nodeid: [被覆盖的源文件…], generated_at, rev}`（gitignored）。
2. 选测 `tools/tia.py --select <改动文件…>`：返回该跑的测试清单 + 三类 **pinned 兜底**：
   上次失败过的、本卡新增/改过的测试文件、判据钉子（`tests/test_wb_review.py`、`test_check_layers.py`、
   `test_card_specs_tracked.py`、`test_check_skills.py`、`test_run_gates_profiles.py`）。
3. 映射过期即失效：`gates/tia.json` 的 `rev` 不是当前 HEAD 的祖先 ⇒ 打印「映射过期，退回全量」并跑全量（fail closed）。
4. `scripts/run_gates.py --fast`/pytest 门支持 `TF_TIA=1` 选测；选测结果写进 `last.json`（`tests_run` / `tests_total`）。
5. 必测集保真：被选中的集合必须满足「任何被改文件至少有一个测试覆盖它」；判不出 ⇒ 全量。

## 交付

- `tools/tia.py`（生成 / 选测 / 自检）+ `tests/test_tia.py`（映射格式、pinned 兜底、过期失效、fail-closed）。
- `scripts/run_gates.py` pytest 门接 `TF_TIA`，并在 payload 里记 `tests_run`/`tests_total`。
- `docs/subsystems/ci/README.md` 补度量读数（改前 / 改后）。

## 验收

- `pytest tests/test_tia.py -q` 全绿。
- 实跑一趟：改 `tools/wb_session.py` ⇒ 选测条数 < 全量 30%，且 `tests/test_wb_session.py` 在清单里。
- 故意改一个没人覆盖的文件 ⇒ 工具打印「判不出 ⇒ 全量」并真的全量。

## 不许做

- 不许按目录猜（必须来自覆盖映射）。
- 不许为了让数字好看而缩小 pinned 集。
