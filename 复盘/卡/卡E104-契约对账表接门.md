## 要解决的问题（逐条实测，不是推测）

`tools/contract_audit.py --check-doc` 是 E101（`a94af526`）给 `复盘/契约-判据对账.md` 装的那把尺子：
逐格核**源行号 / 原句子串 / 判据标签 / 段标题条数**，0.15 s 跑完，不跑判据。
它现在**不在任何一档门禁里**：

```text
$ python -X utf8 -c "import sys;sys.path.insert(0,'.');from gates.defs import domains;print(domains.required_profiles(['复盘/契约-判据对账.md']))"
frozenset({'audit'})
$ grep -rn 'contract_audit' gates/defs/ scripts/run_gates.py
```

而 audit 档是 `gates/defs/contract.py` 的五道（`audit` / `invariants` / `audit_titles` / `docs` / `skills_claims`），
**没有一道读那张表**。于是：

1. **只改这张表的卡，落地时 pytest 根本不跑。** 落地链 ④ 用 `--profiles auto` 按提交面算档，
   `复盘/契约-判据对账.md` ⇒ 只有 `audit` 档 ⇒ 21 条钉子（`tests/test_contract_doc_table.py`）
   一条都不执行。表漂了没人当场拦，只有「下一次恰好跑到 pytest」才会红。
2. **E101 装的那把尺子只在人手工跑的时候存在。** 这正是 E101 想消灭的形态（表替工具撒谎）。
3. **代价几乎为零**：0.15 s（本段实测 `python -X utf8 tools/contract_audit.py --check-doc` ⇒ rc=0）。

## 判据（四条）

### 判据 1 · 第 23 道门 `contract_doc_table` 进 audit 档

`gates/defs/contract.py` 的 `GATES` 尾部 append
`("contract_doc_table", [PY, "-X", "utf8", "tools/contract_audit.py", "--check-doc"])`，
并按该文件体例写上注释（判什么 / 为什么不跑判据 / 反向用例在哪）。
`scripts/run_gates.py` 的 `GATE_PROFILES["audit"]` 是 `tuple(n for n, _ in contract.GATES)` ⇒ 自动跟上，**不动它**。

**不进 `FAST`**：fast 档挑的是「改一行代码就能犯的噪声」，而这张表只有在改它自己时才可能漂；
`--profiles auto` 已经把那种改动路由到 audit 档，放 fast 里只是把「十几秒」的口径搞乱。

**钉子**（`tests/test_contract_doc_table_gate.py`，本卡新建）：

- `::test_contract_doc_table_is_registered_in_the_audit_profile` —— 从 `contract.GATES` 读那一条
  （名字 + argv **逐字**）、`"contract_doc_table" in rg.GATE_PROFILES["audit"]`、
  `dict(rg.build_jobs(False, False))` 里有它、`"contract_doc_table" not in rg.FAST`；
- `::test_the_registered_command_is_green_on_the_real_table` —— 直接跑**注册的那条 argv**，
  rc == 0（真表此刻不漂；表一漂，门当场红）。

### 判据 2 · 这道门真会咬（喂一张坏表给**注册的那条命令**）

把真表复制到 `tmp_path`，把段标题的条数改坏（`### 有判据的（10 条` → `（11 条`），
在**注册 argv** 后面追加 `--doc <坏表>`，断言 rc == 1 且 stdout 点名条数不符。
★ 证明的是「门表里那一条命令」会咬 —— 不是另一个工具的另一个开关。

**钉子**：`::test_the_registered_command_bites_on_a_drifted_table`。
