## 来路（**卡 146 是好卡，但它把两口锅并成了一口**）

卡 146 已把 `tools/wb_dispatch.py` 改成**读真源** `infra/pool/models.whitelist.toml`（找不到就拒、坏掉点名）
—— **这一步本身是对的**（消灭「两份白名单、两套 id 体系」）。★ 但真源**现在的内容**是：


⇒ **落下去会立刻出事**（三条，都是必然、不是可能）：

2. `--model` 的**默认值 = 真源首项** ⇒ 变成 `huaweicloud-maas/GLM-5.2`（**CodeBuddy CLI 服务不了的名字**）；
3. ⇒ ★ **所有「不带 `--model`」的派活全挂**（而这是最常见的用法）。

★ 备注：`infra/pool/model-switches.toml` 那条**只做加法**（它把模型**额外打开**），
**救不了默认值**（默认值取的是真源首项）—— 别以为「打开开关就行」。

## 决策（**用户拍板，二选一或都不选**）

### 候选 ①：把 CodeBuddy 池的裸名**按同格式补进真源**

```
# infra/pool/models.whitelist.toml 追加
[[approved]]
pool  = "codebuddy-cli"
model = "deepseek-v4.1-flash"
by    = "用户"
at    = "<拍板日>"
note  = "CodeBuddy 池（与 codearts-cli 同一个文件、不同 pool 段）"
```
- **好处**：真源**真的**变成唯一真源；`--model` 默认值回到 `deepseek-v4.1-flash`；其它工具（`pool_models`）也一致。
- **代价**：这份文件的头部写着「**只有用户能改**」——所以**必须用户点头**；且要**想清楚 pool 字段的含义**
  （现在是「哪个号池」，两个池共用一份文件是否合意？）。

### 候选 ②：在 `model-switches.toml` 里把裸名全部打开 + **规定永远显式给 `--model`**

- **好处**：不动那份「只有用户能改」的名单。
- **代价**：★ **默认值仍然是坏的** ⇒ 必须**同时**改派活器（默认值不许取「真源首项」，改成
  「**必须在真源里、且显式给或按白名单兜底**」）+ **所有派活命令都得带 `--model`**（人不带就挂）。
  ⇒ 这是**把成本转嫁给每一次派活**，而且**「必须记得带」就是靠人记得**（本仓今晚栽过 9 次的那种）。
