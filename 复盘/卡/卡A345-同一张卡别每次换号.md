## 要解决的问题

同一张卡第二次派活时，`wb_dispatch` 会**重新挑号**：上一次是谁答的、在哪棵树上答的、
会话号是多少，全仓没有任何一处记着。后果是三笔真金白银的浪费 ——
① 工人要**把整段卡规格与上下文重发一遍**；② 上一个号缓存在 vendor 侧的
上下文**用不上了**（pool 不转发协议请求，没有 prompt cache 可命中，能省的只是重发 token
与重新理解卡的时间）；③ 人从判决里**看不出**「为什么这次换了号」。

magpie 的 `affinity` 就是治这个的，但它有四个输入 pool 侧根本没有（见「不许做」）。
所以本卡只搬两层：**粘性**（谁答过）与 **`Why`**（为什么留 / 为什么走）。

## 判据（11 条，逐条可执行）

1. **新模块只读纯函数化**：新增 `tools/pool/sticky.py`，模块级标识符逐字为
   `STICKY_REL: tuple[str, ...] = ("gates", "diag", "pool-sticky.json")`、
   `ENV_STICKY = "TF_POOL_STICKY"`、`STICK_KEEP_S = 24 * 3600`、`STICKS_KEPT = 512`。
   `STICK_KEEP_S` 与 `STICKS_KEPT` 逐字抄 magpie `affinity.go:71` / `:73`，**不许改数**，
   并在注释里点名来处。
2. **`Why` 是有限枚举且两组不相交**：`WHY_SESSION = "session"` / `WHY_CARD = "card"` /
   `WHY_FIRST = "first"` 属 `REASONS_KEEP`；`WHY_OFF = "off"` / `WHY_GONE = "gone"` /
   `WHY_SPENT = "spent"` / `WHY_COLD = "cold"` 属 `REASONS_LEAVE`。
   `set(REASONS_KEEP) & set(REASONS_LEAVE) == set()`，且两组并集**等于**模块里全部 `WHY_*` 常量。
   `WHY_FIRST` 归「保留」是因为 magpie 的 `Kept=false/"first"` 就是「第一次，没人答过」——
   这条语义要写进 docstring，免得后来人以为分错了。
3. **`Stick` 的字段**：`@dataclass` 七个字段逐字
   `card: str` / `account: str = ""` / `tree: str = ""` / `session: str = ""` /
   `model: str = ""` / `at: float = 0.0` / `why: str = WHY_FIRST`。
   `at` 是 epoch 秒（照 `savedStick.At`）。**不许多塞字段**。
4. **`stick_for(card, *, now=None, root=None) -> Stick | None` 必须 fail-open**：
   - 命中且未过期 ⇒ 回 `Stick`；
   - `time.time() - at > STICK_KEEP_S` ⇒ 回 `None`，且**不抛**；
   - 文件不存在 / JSON 坏 / 形状不对 / `account == ""` ⇒ 一律回 `None`，**绝不抛**。
   理由照 `tools/pool/route.py:210 apply_order()` 的同一条纪律：粘性是省钱的优化，
   判不了就当没有，**不许**因此拦派活。
5. **`note(stick, *, root=None) -> Path` 走原子写**：写盘必须调用
   `tools/pool/lastgood.py:98 write_atomic()`（**不许**自己 `Path.write_text`），
   落盘位址由 `STICKY_REL` 与 `ENV_STICKY` 决定（`root` 缺省取 `TOOL_ROOT`）。
   修剪照 magpie `affinity.go:287 saveSticks`：按 `at` **倒序**取前 `STICKS_KEPT` 条。
   **不许**按卡号字典序剪 —— 要的是「最近」，不是「最小」。
6. **`--sticky` 默认关，关掉时行为逐字不变**：`tools/wb_dispatch.py` 新增
   `parser.add_argument("--sticky", action="store_true", help=...)`，默认 `False`。
   不给 `--sticky` 时，`reserve()` 的入参、`lease_note` 的字符串、判决文案与今天**逐字相等**
   （钉子 `test_sticky_off_by_default`）。
7. **粘性只在没显式给 `--account` 时生效**：接入点 1 放在 `tools/wb_dispatch.py` 的
   **占树之前**（`reserve()` 与 `lease_note` 之前），逻辑逐字：
   `if args.sticky and not args.account:` ⇒ 读 `stick_for(args.card)`；
   命中且 `why` 属 `REASONS_KEEP` 且该号仍在账本、仍 active、`used_percent < USED_SHARE`
   ⇒ 用记录里的号；否则记下走开理由（`gone` / `spent` / `cold`）并**回落正常挑号**（不拦派活）。
   `USED_SHARE` 必须从 `tools/pool/route.py:75` 取（**不许**硬编码 98，更不许抄 magpie 的
   `SpentShareOf()` 口径）。
8. **接入点 2 与用量落账同一处**：`append_usage_line(...)` 之后**同一个 try 块内**调
   `note(Stick(card=args.card, account=<本轮实际用的号> or "", tree=reserve_tree,
   session=sid or "", model=model, at=time.time(), why=<WHY_CARD 或 WHY_FIRST>))`。
   **不许**分散到两个 try 块，也不许在 dry-run 路径上写（`--execute` 之前那一段一个字节不碰）。
9. **粘性不许覆盖任何闸**：粘性命中后，`guards.lane_guard` / `guards.domain_guard` /
   模型白名单 / rpm 闸**照旧全部生效**；任何一条咬住 ⇒ 放弃粘性、走原有失败路径。
   **不许**为了让粘性成立在 `tools/pool/guards.py` 里开口子（钉子
   `test_sticky_never_overrides_lane_guard`）。
10. **`--sticky` 写进 `tools/pool_mcp.py` 的干跑与 schema**：`pool_dispatch` 的 `_dispatch_argv()`
    若 A344 之后已有 `account` 透传，本卡照同一位置加 `sticky`（布尔开关，`False` 不透传，
    保持既有 argv 逐字不变）。
11. **判决里看得见 `why`**：粘性生效或走开时，往 stderr 打一行人类可读的话，形如
    `[粘 ] 卡 <卡> 上次在号 <号> 上答过（why=card，<龄>）⇒ 这次还用它` /
    `[粘 ] 卡 <卡> 上次的号 <号> 已 <gone|spent|cold> ⇒ 正常挑号`。
    **不许**改判决文件（`wb-<卡>.verdict.txt`）的既有格式。

## 缺口（如实说，不许当成已解决）

1. **收益比 magpie 小一个量级**：magpie 的 affinity 是为了**命中 vendor 的前缀缓存**（真金白银），
   pool 不转发协议请求、没有缓存可命中；这里省的只是「重发整段卡规格」的 token 与人的一点时间。
   `cacheWorth = 1024` 这道闸门**明确不搬**（pool 侧没有 `cache_read + cache_write` 这个派活前证据，
   `gates/diag/wb-usage.jsonl` 里的 `cache_read` 是**事后**数）。
2. **不搬四个路由态**：`strict` / `resting` / `spent` / `main` 读的是 `planned.order[i].Rest`、
   `Order[i].Fallback`、`SpentShareOf(p.Routing)` —— pool 的 `apply_order()` 是另一个形状，
   硬接会把两套语义搅在一起。本卡只有自己的 `spent`（= `used_percent >= USED_SHARE`）。
3. **`account` 从哪来取决于 A344 落地**：若 `.wt/A344` 尚未落地，`args.account` 是 profile 名，
   粘性记录里存的就是 profile 名；A344 落地后记录里是稳定 id ⇒ **旧记录里的名字会 `why == "gone"`**
   （账本查不到）⇒ 首次派活重建一次。这是可接受的降级，但**要写在 changelog 里**，不许当没发生。
4. **不做跨机同步**：magpie 有 davsync 合并，pool 只治单机（`tools/pool/task.py` 文件头已立过这条）。
5. **`session` 的真实来源未验**：接入点 2 用的 `sid` 是本轮 `run_worker` 回来的会话号；
   续跑（`--resume`）时它是 `resume_sid`。**本卡不保证**「同一张卡的第二次派活会沿用同一会话」，
   只保证「记录里写了当时用的是哪个会话」。要不要据此自动 `--resume` 是**另一张卡**。
6. **`gates/diag/pool-sticky.json` 是 gitignored 的运行状态**，不进 `docs/`、不进台账；
   测试一律用 `tmp_path` 当 `root`，**不许**写到真仓。
