# 卡 E73 —— 两条门抢同一个端口：并行跑门时 fixture 互相踩（T-AG564）

> 台账号 `T-AG564` ｜ 分区 E（门禁/判据）｜ 树 `.wt/E73` ｜ 层 判据层
> 依据：2026-10-31 实测复现（`node tools/render_check.mjs --only today` 同时起两个，第二个 exit 2）。
> 基准提交 `a6100b68`（主树 HEAD，E72 刚落）。
> 与在飞卡的关系：本卡只碰 `tools/render_check.mjs` / `tools/ui_flow_check.mjs`（端口取法）+ `tests/` 里那处不起眼的默认端口 + 新增 `tests/test_gate_port_isolation.py`。**不许碰** `scripts/run_gates.py`（`port_base()` 已是对的）。

## 要解决的问题

`scripts/run_gates.py:271 port_base()` 早就支持 `TF_GATE_PORT_BASE` 整段平移（`:268 DEFAULT_PORT_BASE = 8531`），门禁起跑时也会把它透传给 `render_check.mjs --port`（`:624`）与 `ui_flow_check.mjs --port`（`:634`）。**问题不在门禁那一侧**。

问题在**门禁之外的调用方**：`tests/test_only_selector_parity.py` 的 `run_render()` 调 `node tools/render_check.mjs --only today` 时**一个 `--port` 都不传** ⇒ 落到 `tools/render_check.mjs:97` 的默认 `port: 8531`。于是：

1. 全量门禁用 `pytest-xdist -n 2`（`scripts/run_gates.py` 的并行跑法）时，两个 worker 里只要**同时**有一条用例起 render 服务，就撞在 8531；
2. 后起的那个实例 `waitHealth()` 立刻通（前一个已经把服务拉起来了）⇒ 它以为「服务就绪」，直接 `seedFixture()`；
3. fixture 是 `POST /api/groups {name:'高数'}` —— 前一个已经造过了 ⇒ `400 {"detail":"分组「高数」已存在"}` ⇒ `problems` 非空 ⇒ **`result.code = 2`**，报 `❌ fixture（种子数据）没造全`。

实测复现（`.wt/F12`，2026-10-31）：

```
$ (node tools/render_check.mjs --only today &) ; node tools/render_check.mjs --only today
# 后起的那个：❌ fixture（种子数据）没造全 … POST /api/groups → 400 {"detail":"分组「高数」已存在"}  [耗时] 2.3s
```

这与 2026-10-30 夜那趟 F12 门禁的红单一字不差：`[AssertionError] 挑中真视图必须退 0：… 分组「高数」已存在` ⇒ 这是**假红**，但红得像真的。

## 判据（5 条，逐条可执行）

1. **`render_check.mjs` 与 `ui_flow_check.mjs` 的默认端口不再写死 8531/8541，而是跟着 `TF_GATE_PORT_BASE` 走**：`port_base()` 的同一口径（不设 ⇒ 8531，设了 ⇒ 那个值；`+10` 是 ui_flow 的偏移）。实现上**不许**读 `scripts/run_gates.py`（那是 python，node 不许跨语言 import）—— 在 `tools/tf_browser.mjs` 里加一个 `export function portBase()`（纯函数，读 `process.env.TF_GATE_PORT_BASE`，非整数 ⇒ 退 8531 并**在 stderr 说一句**），`render_check.mjs` / `ui_flow_check.mjs` 两处默认值改成调它；两个工具里**再不许出现字面量 8531 / 8541**（头注释里的示例命令可以留，但必须改成示例形态，不许是可被执行到的默认值）。

2. **`--port` 显式给了就赢**：`portBase()` 只影响**默认值**，`--port N` 仍然逐字覆盖（现有 `:106 else if (k === '--port') a.port = Number(argv[++i])` 一字不改）。

3. **端口被别人占着时不许当「服务就绪」**：`waitHealth(port)` 现在只问 `/api/health` 通不通 —— 通不通**分不清**「我刚起的服务」与「别人早就跑着的服务」。必须加一条：起服务后先**等到自己这个子进程真的在听**（或更简单：`startServer()` 之后**先确认端口在起之前是空的**，空不了就**退出并点名** `端口 N 已被占用（可能是并行的另一条门）`，退非零，**不许**去 seed 别人的服务）。判据：端口被占时，进程必须以「点名端口 + 非零退出码」结束，**且一次 `POST /api/groups` 都不发**（测试用假 HTTP 服务或占位 socket 钉住）。

4. **`tests/test_only_selector_parity.py::run_render()` 必须传 `--port`**：端口取 `int(os.environ.get("TF_GATE_PORT_BASE", "8531")) + 200`（与门禁用到的 8531..8551 段错开，也与其他树的 BASE 段错开），并且这个取法要**写成一个模块级函数**（例如 `_test_port()`）以便钉子直接调。`ui_flow_check` 在测试里的调用同样处理（若存在）。

5. **一条钉子把「并行也不会踩」钉住**：新 `tests/test_gate_port_isolation.py`（≥ 6 条）必须包含 ——
   - `test_default_port_follows_gate_base_env`（设 `TF_GATE_PORT_BASE=9111` ⇒ `portBase()` 回 9111；不设 ⇒ 8531）
   - `test_bad_port_base_env_warns_and_falls_back`（`TF_GATE_PORT_BASE=abc` ⇒ 8531 + stderr 有话说）
   - `test_no_hardcoded_default_port_left`（`render_check.mjs` / `ui_flow_check.mjs` 里**没有** `port: 8531` / `port: 8541` 这种可执行的默认字面量；头注释里的示例不算，但判据用「去掉注释行后扫」）
   - `test_busy_port_is_refused_not_seeded`（判据 3：占住端口 ⇒ 非零退出 + 点名）
   - `test_parity_test_passes_an_explicit_port`（读 `tests/test_only_selector_parity.py` 源码，`run_render` 的命令行里必须含 `"--port"`）
   - `test_two_runs_at_once_do_not_collide`（真起两条，各自 `--port` 不同 ⇒ 两条都退 0；这条是**反证**：它必须能证明「同一个端口会红」——即先跑一次 `--port` 相同场景断言红）

## 交付

- `tools/tf_browser.mjs`：加 `export function portBase()`。
- `tools/render_check.mjs` / `tools/ui_flow_check.mjs`：默认端口改成 `portBase()`（ui_flow `+10`）；`startServer()` 之后加判据 3 的占位检查。
- `tests/test_only_selector_parity.py`：`_test_port()` + `run_render()` 传 `--port`。
- `tests/test_gate_port_isolation.py`（新）：判据 5 的六条。
- `gates/diag/_rev_E73.py`（新）：≥ 5 条变异（至少含「默认端口退回写死 8531」与「端口被占还照旧 seed」两条），每条证明某条钉子变红，收尾绿。
