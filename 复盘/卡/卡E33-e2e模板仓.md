# 卡 E33 —— e2e 模板仓：把「每条用例自己建一遍仓」换成「复制一份」

> 台账号 T-AG487 ｜ 树：`.wt/E33` ｜ 分区：E（CI 子系统）
> 依据：2026-10-25 实测（`tests/test_wb_land.py` 7 条 e2e 合计 121.4 s；单条 15–22 s）

## 现在疼在哪（都是实测）

1. **每条 e2e 都在 `tmp_path` 里从零造仓**：`git init` → 逐文件 `write_text` → `git add` →
   `git commit` → 再起子进程跑 `wb_land`。`tests/test_wb_land.py` 7 条 e2e 合计 **121.4 s**，
   平均每条 **17 s**，而其中真正「跑落地链」的时间占比没人量过。
2. **同样的准备动作重复 20 多遍**：最慢清单里 22 条里有 12 条在 `test_wb_land` / `test_contract_audit` /
   `test_evidence_map` / `test_card_specs_tracked` —— 它们都要一份「像真仓的树」。
3. **没有共享 fixture**：`tests/conftest.py` 只有 `run_git()`（E14 加的抖动重试）与少数小工具，
   没有「一次建好、多次复制」的模板仓。于是每加一条 e2e，就多付一次造仓成本。

## 要做成什么样

1. **加一个 session 级 `template_repo` fixture**（落在 `tests/conftest.py`，与 `run_git` 并列）：
   在 tmp 下建一个最小可信仓（`pipeline.toml`、`gates.d/`、`docs/workbacklog.toml` 等骨架文件
   与真仓同构，内容以现有 e2e 里那份为准），`git init` + 首批提交**只做一次**；
   对外提供 `template_repo.copy_to(tmp_path) -> Path`（建议 `shutil.copytree` 或
   `git clone --shared`，二选一按实测选，读数进申报）。
2. **改写 12 条 e2e 的准备工作**：把「逐文件造仓」换成 `template_repo.copy_to(tmp_path)`；
   **断言与子进程命令一个字都不许改**（只换准备动作）。
3. **隔离性必须是钉住的**：两条 e2e 不许看到对方的提交 / 分支 / `gates/diag` 残留。

## 判据

1. **同文件前后耗时对比表**（`tests/test_wb_land.py` + `test_contract_audit.py` 两文件，
   改前 / 改后各跑一遍，4 worker 亦可串行，只要两遍条件一致），目标 **−40%**；
   若实测不到 20%，本卡收口成「测过，收益不足，不改」并写清读数。
2. `pytest tests/test_wb_land.py tests/test_contract_audit.py -q -o addopts=` 全绿，
   用例数与改前一致。
3. `pytest tests/test_template_repo.py -q -o addopts=`，至少 5 条钉子：
   **全 session 只建一次**（计数器；注意 xdist 下 session fixture 每个 worker 会各跑一次，
   所以必须用 `worker_id` + 文件锁：gw0 建、其余等锁后复制，计数器断言的是「构建标志只被置一次」
   而不是「函数只被调用一次」）+ 两个 `copy_to` 互不可见（各自提交后看不到对方）+
   模板仓未被任何用例改动（跑完 `git status` 干净）+ `copy_to` 产物是**独立 git 仓**
   （`.git` 存在且 `rev-parse HEAD` 不同）+ 模板里骨架文件与真仓同名同判据。
4. **反向验证**：把 `copy_to` 改成「直接返回模板仓本尊（不复制）」⇒ 隔离那条钉子必须红；
   把文件锁去掉（每个 worker 各建一份）⇒ 「构建标志只置一次」那条必须红；
   在 `-n 4` 下重复跑三次，构建标志必须始终只有一次。红色输出进申报。
5. 全量门禁 `exit 0`。

## 不许做

- 不许改任何 e2e 的断言或子进程命令（这卡只换准备动作）。
- 不许让模板仓被用例写脏（`git status` 必须干净，脏了就是设计错了）。
- 不许把 e2e 改成「共享同一个工作树」来省时间 —— 那会让用例互相污染，且和 E32 的分层打架。
- 不许删 `run_git()` 的抖动重试；新 fixture 也走它。

## 证据

- 两个文件的改前 / 改后耗时表（附 `gates/diag/bench-template-before.log` / `-after.log`）。
- `pytest tests/test_template_repo.py -q -o addopts=` 原始输出。
- 两条反向验证的红色原始输出。
- 改后 `tests/test_wb_land.py` 跑完模板仓所在目录的 `git status --porcelain`（应为空）。

## 检索证据（2026-10-25 回灌）

- **这个杠杆在文献里没有量化先例**：arXiv 语料里找不到「模板仓 fixture 复用」的测量；
  相邻证据只有测试坏味道研究（`General Fixtures` 冗余准备与更高开销正相关，arXiv:2310.14548）。
  ⇒ 本卡的收益必须自己量，别引用别人的百分比。
- **一条会直接改判据的机制事实**（`pytest-xdist` 文档 + 实践文章）：`scope="session"` 的 fixture
  在 xdist 下**每个 worker 各执行一次**，不是每 session 一次。所以「只建一次」不能靠 `session` scope，
  必须靠 `worker_id` + 文件锁（`filelock` 或 `O_EXCL` 自旋）——判据 3 已按这条改写。
- 参考实现套路：`worker_id == "master"`（`-n 0`）或 `gw0` 先建并置构建标志，其余 worker
  轮询等锁后直接 `copy_to`（cnblogs《Pytest - xdist 保证多进程共享 session 级别 fixture》、Yorgos
  Katsaros《Setup your tests once per session while using pytest and xdist》）。
