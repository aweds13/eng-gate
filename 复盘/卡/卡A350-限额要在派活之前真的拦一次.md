## 要解决的问题

限额判据要真的拦住派活，缺三样东西，且**缺一不可**：

1. **喂料**：`ledger_spend.sums()` 要能读到这个号在这个窗口里已经花了多少 —— 而账本
   `gates/diag/pool-spend.jsonl` 今天一行都没有，因为没人写。
2. **问一次**：派活之前要拿 `limits_check.check()` 问「还有余量吗」，不够就拒，并说清
   卡在第几条、什么时候续上、等多久。
3. **写回**：这一轮跑完（无论成败）要按真实用量追加一行，否则下一轮问的还是空的。

★ **三样必须同时做**：只做 1+2 ⇒ 账本永远空 ⇒ 每次都有余量 ⇒ 闸是摆设（比没有更坏：
它让人觉得「已经拦过了」）。只做 2+3 ⇒ 第一轮之后才有料，但第一轮就已经该拦。
**这就是本卡把三样放进同一张卡的唯一理由。**

## 判据（七条）

1. **写回**：每轮跑完按真实用量追加一行到 `gates/diag/pool-spend.jsonl`，字段与
   `ledger_spend.append()` 既定形状**一致**（`at` / `account` / `card` / `model` /
   `input_tokens` / `output_tokens` / `cache_write` / `cache_read` / `cost`），走
   `ledger_spend.append()`（**不许自己再写一份 JSONL**——那是第二份真源）。
   - 数从 `result_usage()` 拿（`tools/wb_dispatch.py:1562`，CLI 自报，**不许自己估**）。
   - `cost` 今天**算不出来**（vendor 不报金额，`append_usage_line()` 的 docstring 明写「金额恒 0.0」）
     ⇒ **必须写 `0.0` 并在一处说实话**，不许编一个乘数假装能算。这一条是本卡的**已知缺口**，
     changelog 里要写明「cost 轴今天恒 0 ⇒ 只按 tokens 判」。
   - `account` 用**稳定 id**（`account_id`，与租约、RPM 闸、lanes 闸同一个键）。
   - ★ **空账号不许写**：没给 `--account` 时 `account_id` 是空串，那一行**不写**（否则账本里
     全是空账号的行，`sums()` 按账号求和永远读不到它，纯粹污染）。
2. **问一次**：派活**之前**（`pool_registry.reserve()` 之前）问一次 `limits_check.check()`：
   - `limits` 从 `limits_policy.load_limits()` 拿，键是**稳定 id**；
   - `spent[i]` 用 `limits_policy.window(limits[i], now)` 算窗口、`ledger_spend.sums()` 求和
     —— 两边**必须用同一个 `now`**（`check()` 的 docstring 逐字要求）；
   - `cache_reads` 跟 `limit.cache_reads` 走（`Limit` 有这个字段，别自己定）。
3. **拒的方式**：`check().allowed` 为假 ⇒ 走**既有** `if problems:` 出口
   （打印 `[FAIL] 不派活 —— 前置检查没过：` + 逐条 `  · …` + 退 2），文案必须含
   `reset_at`（什么时候续上）与 `retry_after_s`（等多久）。**不许新开退出码**。
4. **文件不存在 / 没声明限额 ⇒ 零行为变化**：`limits.toml` 不存在 ⇒ `load_limits()` 回 `{}`
   ⇒ `check()` 回 `allowed=True` ⇒ 派活路径与今天**逐字节相同**。这条要有钉子正面钉住
   （「没有策略文件时，`--execute` 的完整 argv 与改动前一字不差」）。
5. **坏策略要响**：`limits.toml` 存在但读不懂 ⇒ `LimitError` ⇒ **拒派**并说清是哪一段坏了
   （不许吞成「没设限额」——那是悄悄松开判据，与 `load_limits()` 的既定口径一致）。
6. **两份 `load_limits` 不许合并**：`tools/pool/limits.py:78` 与
   `tools/pool/limits_policy.py:249` 是两套语义（前者读不出来一律 `{}` 不抛，服务 F34 的
   `[accounts.<id>].models`；后者坏 TOML 必抛，服务本卡的限额判据）。**本卡只调后者**，
   不许为了「统一」去改前者。
7. **反向验证 ≥6 条**，每条真改真跑真复原（sha256 自证），必须含：
   - M1 写回那行删掉（只问不记）⇒ 判据 1 的钉子红；
   - M2 `cache_reads` 恒 False（无视 `limit.cache_reads`）⇒ 判据 2 的钉子红；
   - M3 `check()` 的 `allowed` 反着判 ⇒ 判据 3 的钉子红；
   - M4 `limits` 用 `args.account`（profile 名）当键 ⇒ 判据 2 的钉子红（喂真账本 + profile 名派活）；
   - M5 `LimitError` 吞成 `{}` ⇒ 判据 5 的钉子红；
   - M6 两个 `now` 不同源（一个 `datetime.now()`、一个传进来的 `now`）⇒ 窗口边界钉子红。
