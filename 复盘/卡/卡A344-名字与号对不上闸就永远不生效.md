# 卡 A344 —— 名字与号对不上，闸就永远不生效：profile 名 ↔ 账本稳定 id 映射 + 把 account 真传进占树

> 台账号 **T-AG546** ｜ 分区 A（magpie 移植）｜ 树 `.wt/A344` ｜ 层 判据层
> 依据：第二波设计 `_ext/_port_design_gates_keys.md` §0「pool 的『账号』不是在途对象，而是一次性环境变量注入」；
> magpie 源把 `who` 当**稳定标识**用（`internal/gateway/rpm.go:122-138` 的 `reserve` 键、
> `internal/concurrency/concurrency.go` 的账号并发键），而本仓 `--account` 收的是**profile 名**。
> 基准提交 `17f29c7f`（主树 HEAD）。

## 要解决的问题

A339（lane 闸）与 A340（每分钟闸）都落了判据，但**两条闸今天一次也不会拦**，因为它们查表用的键和表里的键不是一套：

1. **`--account` 收的是 profile 名，不是账本 id。** `tools/wb_dispatch.py:577 account_env(name)`
   跑仓外 `codebuddy_accounts.py profile env <名>` —— 实测 `profile list` 只有 `tongxue3`；
   而 `infra/pool/accounts.toml` 里的稳定 id 是 `codebuddy-tongxue3`。仓内**零映射代码**
   （只有 `credential.locator` 末段 `~/codebuddy-accounts/tongxue3` 恰好末段相同，且**只对 codebuddy 成立**：
   `codearts-1` 的末段是 `pool.env`、`workbuddy-1` 是 `.workbuddy`、`trae-1` 是 `.trae`）。
2. **每分钟闸按 profile 名查表**：`tools/wb_dispatch.py:3475` `rpm_limit = pool_rpm.load_rpm().get(args.account, 0)`
   ⇒ `rpm.toml` 的键是稳定 id ⇒ `.get("tongxue3", 0)` 恒 0 ⇒ 恒放行（A340 的 `rpm.toml` 因此被裁定成空表，
   并如实写了「填上真号也只落 0，看着配了实际谁也不拦」）。
3. **并发闸的入参根本没有来源**：`tools/pool/registry.py:306 reserve(..., account="")` 的 `account` 默认空，
   而生产代码**一处都不传**（`tools/wb_dispatch.py:3546` 只传 `tree/files/project/model/log/note/lock_body`；
   `tools/wb_lease.py` / `tools/wb_registry.py` / `tools/pool/trae_dispatch.py` / `tools/pool_mcp.py` 同样不传）
   ⇒ `tools/pool/guards.py:336 lane_guard("", ...)` 立即回 `[]` ⇒ `lanes.toml` 配了也白配。
4. **A341 的模型白名单也踩同一个坑**：`tools/wb_dispatch.py:3185` `caller_model_rejected(args.model, pool, args.account)`
   ⇒ `caller_model_patterns()` 读 `limits.toml` 的 `[accounts."<id>"].models`，键同样对不上。

⇒ 本卡只做一件事：**让「人给的名字」能稳定地变成「账本里的那个号」，然后把这个 id 送到三条闸手里**。
不新造第二份身份真源，也不许把「对不上」悄悄当「对上了」。

## 判据

1. **新增只读映射模块** `tools/pool/account_id.py`（纯函数 + 一个薄壳，判据只有一份）：

   ```python
   class AccountMapError(ValueError): ...

   def resolve_account_id(
       profile: str,
       rows: Sequence[dict],
   ) -> tuple[str, str]:   # (稳定 id, 依据说明；依据为空串 = 精确命中账本的 profile 键)
   ```

   - 三步、顺序固定：
     ① **`profile` 键优先**：找 `rows` 里 `str(row.get("profile") or "").strip() == profile` 的那一条。
     ② **稳定 id 直给**：`profile` 恰好等于某条 `id` ⇒ 返回它（允许人直接写 id）。
     ③ **`credential.locator` 末段**：`Path(str(cred["locator"])).name == profile` 的那一条
        （`cred = row["credential"]`，`kind == "none"` 或无 locator ⇒ 跳过）。
   - ①/②/③ 各自命中**多于一条** ⇒ 抛 `AccountMapError`（点名是哪几条、为什么歧义）——
     **歧义必须响亮**，不许取第一条（取第一条 = 悄悄挑一个号）。
   - 三步都不命中 ⇒ 返回 `(profile, "账本里没有这个 profile 的稳定 id")`，**不抛**：
     这是「今天本来就是这样」的诚实回落，派活不许因此断掉。
   - 必须是**纯函数**：不读文件、不读环境、不碰网络；`rows` 由调用方给。
   - 薄壳 `load_account_ids()`（读账本、吞掉 `LedgerError` 回空列表）**只**给 `--account` 之外的只读展示用，
     判据本身不接受「读不到账本」这个输入。

2. **`account` 的解析只在一处发生**：`tools/wb_dispatch.py` 里新增

   ```python
   def resolve_account(arg: str | None) -> tuple[str, str]:
   ```

   `arg` 空 ⇒ `("", "")`（逐字保持今天的行为）。否则读一次账本（`pool_accounts.find_ledger()` +
   `pool_accounts.load_ledger()`），**账本读不到 / 解析抛 `AccountMapError` ⇒ 退 2 拒派并点名**
   （不许「解析不了就按原名派」——那正是本卡要消灭的静默失效）。解析成功但依据非空 ⇒
   往 stderr 打一行事实：`[账号] profile「<名字>」在账本里没有稳定 id ⇒ 三条闸按这个名字查表（今天等于不生效）`。

3. **占树带上 id**：`tools/wb_dispatch.py:3546` 的 `pool_registry.reserve(...)` 必须多传
   `account=<解析后的 id>`；`tools/pool/registry.py` 的签名与 `:332`/`:336`/`:356` 三行**一字不改**
   （它已经支持了，改它就等于重写 A339）。

4. **每分钟闸按 id 查表**：`tools/wb_dispatch.py:3475` / `:3477` / `:3494`（`give_back_stamp`）
   三处一律用解析后的 id，不许再用 `args.account`。`args.account` 仍要出现在
   `lease_note`（`:3544`，那是给人看的留痕）和 `account_env()`（`:3235`，那是给工人取环境的）里
   —— **两件事不许混**：给人看的是名字，查闸用 id。

5. **模型白名单按 id 查表**：`tools/wb_dispatch.py:3185` 改成把解析后的 id 传进
   `caller_model_rejected()`；`tools/pool_mcp.py` 的干跑路径（A341 落的第 ⑥b 步）同样改成
   先解析再判 —— 两处判据只有一份（`caller_model_rejected()` 本体不动）。

6. **`lanes.toml` / `rpm.toml` 的注释改口径**：两份文件头现在都写着「键对不上、填了也只落 0」，
   本卡落地后这句话就过期了 ⇒ 改成「键 = 账本稳定 id；`--account` 给的名字经
   `tools/pool/account_id.py::resolve_account_id()` 解析后再查表」。**表的正文保持空**（限额是人的策略，
   本卡不许替人开闸）。

7. **仓外账本一个字节都不动**：本卡只读 `infra/pool/accounts.toml`，不写 `profile` 键
   （写了就等于替人宣布身份）。判据 1 的 ③ 步保证「不加这个键也能用」；
   `profile` 键是留给将来精确口径的**优先**来源，卡规格与 docstring 都照实这么写。

8. **不许造第二份身份真源**：不得新增 `infra/pool/*.map.toml` 之类的映射表，也不得把 profile 名单
   抄进本仓（`tests/test_wb_dispatch.py:3335` 已有钉子钉住「不许本地抄一份清单」，本卡不许把它放宽）。

## 缺口（如实说，不许当成已解决）

- **`profile` 键今天一条都没有**：所以 ③ 步（locator 末段）就是今天**唯一**能让 codebuddy 对上的路径；
  其余三个平台（`codearts`/`workbuddy`/`trae`）今天对不上 ⇒ 判据 2 会打那行实话，三条闸对它们仍不生效。
  要真生效得人工在账本里加 `profile = "<名>"`（本卡不许动）。
- **`wb_lease.py` / `wb_registry.py` / `trae_dispatch.py` / `pool_mcp.py` 的 `reserve()` 调用仍不传 `account=`**
  （只有派活主路径接了）⇒ 从那些入口占的树，`account` 仍是空、并发闸仍不管它们。
- **`lanes.toml` / `rpm.toml` 仍是空表**：本卡只让「键能对上」，不替人开闸 ⇒ 落地当天两条闸依然不拦任何派活，
  验证靠钉子而不是真拦。
- **`account_env()` 仍只认 codebuddy 的 `codebuddy_accounts.py`**；跨平台取环境是另一件事，不在本卡。
- **既有 `--account demo` 的用例**（`tests/test_wb_dispatch.py` 里那一串）用的是沙箱账本吗？
  如果它们跑真账本，`demo` 会走「三步不中 ⇒ 回落原名」，行为不变；这一点必须在回执里**给出实测**，
  不许假定。
