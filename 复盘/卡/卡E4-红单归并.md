# 卡 E4 —— 红单归并：同 traceback 只打一次

> 台账号 T-AG446 · 分区 E · 依赖 E1

## 目标

门禁报告从「788 KB 日志 + 34 条并列」变成「≤3 行：同因归并 + 计数 + 一条示例」。

## 判据

1. 新增 `tools/failure_group.py`：从 pytest 输出抽 FAILED 行 + 每条的首个异常行（`E   …` /
   `ModuleNotFoundError` / `AssertionError` 首句），按「异常类型 + 首句 + 首个仓内文件」归并。
2. 门禁报告：每类打一行 `× N  [异常] 首句  ← 代表用例 nodeid`；超过 3 类才追加「…另有 K 类见日志」。
3. 原始日志不删：全量输出仍落 `gates/logs/pytest.log`（当前行为），归并只作用于**屏幕报告与 trailer 摘要**。
4. 归并结果同时写进 `last.json` 的 `pytest_failure_groups`（列表明细，供 `wb_review` 与面板读）。
5. 单测：用今天的真实 34 红文本做固定样例（3 类），断言归并后 3 行、计数正确。

## 交付

- `tools/failure_group.py` + `tests/test_failure_group.py` + `tests/fixtures/pytest-34fail.txt`（脱敏样例）。
- `scripts/run_gates.py` 的 pytest 门收尾处调用归并打印。

## 验收

- `pytest tests/test_failure_group.py -q` 全绿。
- 拿样例跑一遍：输出恰好 3 行 + 每行有计数。

## 不许做

- 不许丢原始输出（屏幕可以不打全，日志必须全）。
- 不许按测试文件名归并（必须按异常）。
