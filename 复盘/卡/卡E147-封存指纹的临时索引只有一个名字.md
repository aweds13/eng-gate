# 卡 E147 · 封存指纹的临时索引只有一个名字：并发读者互相锁死，封存指纹静默退化成 None

> 台账号 `T-G385`｜分区 E（门禁与可信度）｜树 `.wt/E146`｜层 判据层（并发正确性；不改封存口径）｜基准 `e7d0dda0`（立卡时主树 HEAD，2026-11-20 21:2x 实读）｜depends 无（与今天 21 张活跃卡零相交，`scripts/run_gates.py` 不在任何 pending 卡的 files 里）

## 0. 一句话

`scripts/run_gates.py` 算「封存指纹」时要建一个临时索引，名字是**每棵树固定的**一个文件（`.git/dsh_gates_index`，linked worktree 里是 `.git/worktrees/<名>/dsh_gates_index`）。同一个工作树里**两个读者同时算**就会撞 git 自己的 `<名字>.lock`，先到的那步 `read-tree` 失败，函数打印一行警告并**返回 None**。落地链的门禁用 `-n 2 --dist worksteal` 跑全量 pytest，于是这件事每天都在发生，只是**大多数时候没被测到**——一旦那条钉子抽到这种顺序，整趟落地就白烧 19 分钟。

## 1. 现场（照抄，不是推测）

### 1.1 一次真实的落地失败

`gates/diag/land-A383.log`（2026-11-20 20:33 起跑，20:52 判红）：

```
× 1  [TypeError] expected str, bytes or os.PathLike object, not NoneType  ← tests/test_two_rulers.py::test_old_rev_still_has_gates_stripped
★★ 门禁退出码 = 1
1 failed, 5343 passed, 1 skipped, 1 xfailed, 1508 warnings in 1132.35s
```

同一次门禁里 pytest 的 `Captured stderr call`（`.wt/A383/gates/logs/pytest.log:132`）原文：

```
[警告] read-tree 90fad05e 失败（fatal: Unable to create 'D:/repo/engineering\.git\worktrees\A383\dsh_gates_index.lock': File exists.

Another git process seems to be running in this repository, e.g.

are terminated then try again. If it still fails, a git process
may have crashed in this repository earlier:
remove the file manually to continue.
）→ 封存指纹回退
```

`tree_without_gates()` 返回 None ⇒ 钉子里的 `_tree_entries(None)` 把 None 传给 `subprocess.run` ⇒ `TypeError`。**这不是那张卡的代码问题**：同一棵树里单跑 `pytest tests/test_two_rulers.py -o addopts= -q --no-cov -p no:xdist` 是 `11 passed, 1 skipped in 1.02s`。

### 1.2 病灶在哪（源码位置，逐行）

- `scripts/run_gates.py:995`：`INDEX_NAME = "dsh_gates_index"`
- `scripts/run_gates.py:1000 def _git_index_path(repo: Path) -> Path | None`：用 `git rev-parse --git-path dsh_gates_index`（拿不到再退 `--absolute-git-dir`）拼出绝对路径 —— **这个名字对同一棵树是常量**。
- `scripts/run_gates.py:1028 def tree_without_gates(repo, rev, *, include_worktree=False, exclude_gates=True) -> str | None`：`index_path.unlink(missing_ok)` → 设 `GIT_INDEX_FILE` → `git read-tree <rev>`（可叠 `add -A`）→ `git rm -r --cached --ignore-unmatch --quiet -f gates` → `git write-tree` → 再 unlink。任一步失败就 `print(f"[警告] ...")` 并 `return None`。
- 读它的地方：`scripts/run_gates.py:1106`（seal 自用）、`tools/gate_base.py:338`、`tools/wb_review.py:559`、`tools/wb_verify.py:198`；测试里 `tests/test_gate_fingerprint.py`、`tests/test_two_rulers.py`、`tests/test_wb_land.py`、`tests/test_wb_review.py` 都会走到它。
- 门禁的 pytest 命令带 `-n 2 --dist worksteal` ⇒ **两个 worker 进程同时算同一棵树的封存指纹**，共用同一个索引文件名。

### 1.3 我写的并发探针（可复现，已跑）

`gates/diag/_race_probe.py`（本卡不入库的临时脚本，体例见 §4 判据 2 要求把它变成钉子）：N 个进程各连调 6 次 `tree_without_gates(ROOT, "HEAD")`，数返回空串的次数。主树实跑：

```
$ python -X utf8 gates/diag/_race_probe.py 4
[警告] read-tree HEAD 失败（fatal: Unable to create '...\\.git\\dsh_gates_index.lock': File exists. ...）→ 封存指纹回退
进程数=4 调用=24 回退(None)=14
  p0: ['', '', '', '', 'ca3e07b1', '4b825dc6']
  p1: ['ca3e07b1', '', '', '', '', '']
  p2: ['', '', '', '4b825dc6', '4b825dc6', 'ca3e07b1']
  p3: ['', 'ca3e07b1', '', 'ca3e07b1', 'ca3e07b1', '4b825dc6']
```

⇒ **24 次里 14 次拿不到指纹（58%）**。注意还有第二个症状：拿到的值里既有 `ca3e07b1…` 也有 `4b825dc6…`（后者是 `git write-tree` 的空树），说明并发下连「成功」的那些也不都是同一棵树 —— 这就是为什么单跑永远绿、门禁偶尔红。

## 2. 为什么它不是「另一张卡的锅」也不该靠重跑糊过去

- 这条 flake 的代价按整趟落地算：一次全量门禁 ~19 分钟（本例 1132.35s），失败的卡要重排、重等合并队列、重算派生文档。
- 它**骗人**：函数失败时只打一行警告并返回 None，调用方（`tools/gate_base.py:338`）拿 `or ""` 吞成空串 ⇒ 封存指纹变成空 ⇒ 复核/审计里出现「封存树与提交树不一致」这类**看起来像别人伪造**的红字（同类现象见卡 E137 的基点漂移）。
- 它**不可判定**：读者无法从产物反推「这次失败是因为并发」，只能翻 pytest 的 captured stderr。

## 3. 改法（最小形态：把临时索引变成**每次调用唯一**的路径）

唯一改动点 `scripts/run_gates.py::_git_index_path(repo)`：在 `git rev-parse --git-path dsh_gates_index` 给出的路径上追加**调用唯一**的后缀（进程 id + 进程内计数器，例如 `dsh_gates_index.<pid>.<seq>`），拿不到 git 路径的两条退路同样加后缀。**不许**改成进程固定后缀（同一进程内两个线程/两次调用仍会撞），**不许**换成 `tempfile.mkdtemp()` 放在仓外（`GIT_INDEX_FILE` 必须在同一 git dir 里才共享对象库语义）。

失败路径必须**删干净**：现有实现里 `read-tree` 失败会 `unlink` 再返回 None，改成唯一名字后这一步照旧但必须真的删（否则每跑一次门禁就在 `.git` 里堆一个孤儿索引）。

## 4. 判据

### 判据 1 · 路径唯一（静态可判）

`_git_index_path(repo)` 连续调 3 次返回**三个不同**路径，且都位于 `git rev-parse --absolute-git-dir` 之下、文件名都以 `dsh_gates_index` 开头。钉子放在新建的 tests/test_gate_index_path.py（本卡新建）：

- 断言三次返回值互不相等；
- 断言三者 `path.parent == Path(git_dir)`；
- 断言 `path.name.startswith("dsh_gates_index")`（保留可 grep 的前缀，便于排查与清理）。

### 判据 2 · 并发不再回退（本卡的钉子本体）

新建的钉子**真起多进程**（`multiprocessing.get_context("spawn")`，Windows 也必须能跑）：4 个进程 × 每人连调 5 次 `thanks tree_without_gates(ROOT, "HEAD")`，断言：

- 20 次全部非空（`fp` 非空字符串、长度是 40 或 64 的十六进制 —— 用 `re.fullmatch(r"[0-9a-f]{40}([0-9a-f]{24})?", fp)`）；
- 20 次结果**一致**（同一棵树必须给出同一个指纹；这是 §1.3 里 `ca3e07b1` vs `4b825dc6` 那个症状的反向钉子）；
- 子进程退出码全 0，且 stderr 里**没有** `[警告]`（失败必须响亮，成功不许带警告）。

★ 反向证明（本判据必须能红）：把 `_git_index_path` 改回固定名字，这条钉子必须红；红单要能看到 `回退(None)=N` 那行（≥1）。实测基线见 §1.3（14/24）。

### 判据 3 · 不留垃圾

任何路径（成功 / `read-tree` 失败 / `write-tree` 失败）跑完，`Path(git_dir).glob("dsh_gates_index*")` 都必须为空。钉子：在临时仓里跑一次成功的 `tree_without_gates`，再人为造一次失败（把 `GIT_INDEX_FILE` 指到不可写位置或直接 monkeypatch 内部 git 调用返回非零），两次之后都断言 glob 为空。

### 判据 4 · 既有判据一条不许放宽

`tests/test_two_rulers.py`（含 `test_old_rev_still_has_gates_stripped`）、`tests/test_gate_fingerprint.py`、`tests/test_wb_land.py`、`tests/test_wb_review.py` 里所有涉及封存指纹的断言**一个字不放宽**；`scripts/run_gates.py` 里 `-f` 那个 `rm` 参数、`INDEX_NAME` 前缀、以及「拿不到 git 路径就打印警告并回退」的行为都不许删。

### 判据 5 · 反向变异 ≥3 条，逐条真改真跑

脚本落在主树 `gates/diag/_rev_146.py`（不入库），每条 try/finally 还原并核对 `sha256[:16]`，结果写 `gates/diag/_rev_146_result.txt`，末行「结论：N/N 条全部咬住，收尾绿。」：

- **M-A**：`_git_index_path` 改回固定名字（去掉唯一后缀）⇒ 判据 2 红；
- **M-B**：唯一后缀只加 pid、不加进程内序号 ⇒ 判据 1 红（同进程连调三次同值）；
- **M-C**：删掉失败路径上的 `unlink` ⇒ 判据 3 红；
- **M-D**：唯一路径改到仓外临时目录（`tempfile.mkdtemp()`）⇒ 判据 2 或判据 4 红（说明「必须同一 git dir」这条不是摆设）；
- **Q**：只改一行注释 ⇒ 零新红（安静对照）。

## 7. 不许做

- 不许「给钉子加 retry」或「把 `-n 2` 改成 `-n 0`」—— 那是把并发问题藏起来，不是修它。
- 不许把 `tree_without_gates` 的失败回退从「打印警告 + None」改成「静默重试 N 次」—— 重试只会把 58% 的概率乘小，仍然不可判。
- 不许顺手动封存口径（`include_worktree` / `exclude_gates` / `rm -f gates`）。
- 不许碰六份受保护共享文件（`docs/traceability.toml`、`docs/changelog.md`、`复盘/交接-重构进度.md`、`复盘/新窗口交接卡.md`、`gates/last.json`、`gates/reuse.json`）。
