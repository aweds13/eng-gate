# 卡 E71 —— 局域网客户端自己那份 3 秒窗，把超时吞成了「连不上」（T-AG554）

> 台账号 **T-AG554** ｜ 分区 **E**（CI / 门禁可信度）｜ 树 `.wt/E71` ｜ 层 **判据层**

## 引用块

依据是本机探针 `gates/diag/_probe_lan_timeout.py`（本卡新建，gitignored）的实测输出：

```
[设置] 服务端 http://127.0.0.1:49863 收 POST 后睡 5s 再回 401
[设置] _lan_json 的默认 timeout = 3（int）
[读数] _lan_json 返回 code=0 body=None 耗时=3.03s
[读数] 调用点判据 `nopair[0] == 401` ⇒ False
[结论] 已证：服务端回了 401，客户端却看到 0 ——
       `TimeoutError` 被 `except (URLError, OSError)` 吞成「连不上」。
```

以及云机 pass14 的那条真红（`gates/diag/cloud-gate-A328.log:37`）：

```
[FAIL] 手机直传：没配对传不进来（401）
```

同批这两条却是绿的 —— 说明服务端确实回了 401：

```
[OK ] 局域网：没配对读不到数据（401 + 原话）
[OK ] 手机直传：配对后能把包传上来并合并
```

本机异常谱系实测：

```
TimeoutError is OSError: True
socket.timeout is TimeoutError: True
URLError is OSError: True
URLError wrapping timeout is OSError: True
```

## 要解决的问题

`tools/web_live_check.py:_lan_json()`（`:804`）是**独立的一份 HTTP 客户端**：

- 它自己的 `build_opener(ProxyHandler({}))`；
- 它自己的 `timeout: int = 3` —— **不认** `call_timeout()`，也不认 env `TF_WEB_LIVE_TIMEOUT`；
- 结尾 `except (urllib.error.URLError, OSError): return 0, None`，注释写的是
  「连不上（防火墙 / 没有局域网地址）」。

卡 E67 只修了 `_json_call`（`:173` 已改成 `except OSError as e: raise LiveCallError(...)`），
**没修同病灶的第二份客户端**。而 `TimeoutError` 是 `OSError` 的子类 ⇒ 超时被静默降级成
「连不上」⇒ 调用点 `nopair[0] == 401` 判 False ⇒ 门报「没配对传不进来（401）」失败。

**判据没错，诊断错了**：真因是「客户端 3 秒没等够」。云机 2 物理核、内存紧，这条
`POST /api/sync/import` 带整包体，打得比 3 秒慢是常态。

十一个 `_lan_json` 调用点（`:869/:879/:880/:881/:882/:884/:885/:898/:899/:900`）
全部只取 `[0]` 或 `[1]`，**没有一处**区分「超时」与「连不上」。

## 判据（六条，缺一不可）

1. **`_lan_json` 的等待窗必须与 `_json_call` 同源**：签名改成
   `timeout: float | None = None`，`None` ⇒ `call_timeout()`（同一 env、同一默认值）。
   不许再写死 `3`。
2. **超时必须是可判定的第三态，不许再混进「连不上」**：
   `except (TimeoutError, socket.timeout)` 与
   `except urllib.error.URLError as e: if isinstance(e.reason, (TimeoutError, socket.timeout))`
   两条 ⇒ `raise LiveCallError(method, url, wait, e)`（点名 endpoint + 等了几秒 + 原始异常类型）。
   其它 `OSError`（连接被拒 / 无路由）**保持现状** `(0, None)`。
3. **探针现场必须转绿**：服务端睡 5 秒再回 401，`TF_WEB_LIVE_TIMEOUT` 不设（默认 10 秒）
   时 `_lan_json(...)[0] == 401`。这条要写成真起本地 HTTP 服务的用例，不是桩。
4. **一个地址等不到不许杀死整组检查**：地址探测循环（`:868-871`）里单个地址抛
   `LiveCallError` ⇒ 打 `[提示] <地址> 等不到（<秒数>），换下一个` 并继续；
   全部等不到 ⇒ 仍走既有的 `[SKIP]`。`live_lan_checks()` 主体里其它位置抛
   `LiveCallError` ⇒ **已算出的 checks 全部保留**，再补一条
   `"局域网：有一步没等到（<点名>）": False` 后返回（不许整组丢掉变一条笼统 FAIL）。
5. **不许洗成通过**：任何「等不到」都不许落成 `True`，也不许 `return 0, None` 了事。
6. **`_json_call` 与 `call_timeout()` 一个字节不动**（E67 已定的东西，本卡只补第二份客户端）。

## 已知缺口（如实写进 gaps，不许粉饰）

1. **没在真云机复核转绿** —— 只在本地用「服务端故意慢 5 秒」复现与验证。
2. `_lan_json` 的调用点共 10 个，其中 8 个只取状态码；本卡只保证「超时不再被吞」，
   **不保证**每次慢请求都被等到（默认 10 秒，云机若真的 >10 秒仍会红 —— 但那时报的会是
   「等不到」，而不是谎称 401 不成立）。
3. 地址探测循环里「所有地址都超时」与「所有地址都拒连」今天走到同一个 `[SKIP]`，
   本卡只加打印不加分支。
4. `live_*` 那 13 组真机检查按 `tests/test_gate_selfproof.py` 的登记仍是盲区，
   本卡只覆盖 `live_lan_checks` 这一组。

## 不许做

- 不许改 `_json_call`、`call_timeout()`、`LiveCallError`、`mark_live_error()` 的任何行为。
- 不许把 `timeout` 默认值调到 30 秒以上（云门禁已由 `scripts/cloud/run_gate.sh` 注入
  `TF_WEB_LIVE_TIMEOUT=30`，本卡只让它**生效**，不是替代它）。
- 不许把「等不到」洗成 `[SKIP]`（那是 E59 留给「造不出手机包」这类**未验证**的口径，
  超时是**已知的失败**）。
- 不许动六份 `PROTECTED_FILES`、三份片段、`gates/last.json`、`gates/reuse.json`。
- 不许写 `# noqa` 蒙 lint。
- 不许引用仓外路径（`_ext/**` 等）。
