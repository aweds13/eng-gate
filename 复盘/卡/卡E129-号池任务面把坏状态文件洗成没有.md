## 判据

### 判据 1 · 坏状态文件是读数：进 payload 的 broken 列表，人话段点名文件与原因，且与「没有文件」不同形

- 断言：`_load_tasks` 返回 `(states, broken)`，`broken` 是 `[{"file": "<名>.json", "error": "<原因>"}]`；`tool_task_list` 的 payload 恒带 `broken`（无坏文件时是空列表），人话段每个坏文件一行「★ 读不了：<名> —— <原因>」。两类**非** BatchError 的坏法（目录冒充、非 UTF-8）也必须进 broken，不许冒泡。
- 什么情况下红：坏文件存在而 `broken == []`；或人话段不含文件名；或 `tool_task_list` / `tool_task_status` 抛 PermissionError / UnicodeDecodeError。
- 钉子（tests/test_pool_mcp_task.py）新增四条：

  - `test_task_list_names_broken_state_file` —— 两个好任务，把 T-2.json 写成 `{"id": "T-2", "declared": [`，断言 `is_error is False`、`[b["file"] for b in data["broken"]] == ["T-2.json"]`、`"Expecting value"` 在 `data["broken"][0]["error"]` 里、人话含 `T-2.json` 与「读不了」；
  - `test_task_list_broken_is_not_batch_error_only` —— T-8.json 建成目录、T-9.json 写 `b"\xff\xfe\x00bad"`，断言调用不抛、`is_error is False`、`len(data["broken"]) == 2`、两条 error 里分别含 `Permission denied` 与 `utf-8`；
  - `test_task_list_broken_differs_from_no_files` —— 同一 tmp 拍两次：先空目录（`(tmp_path/"batch").mkdir()`）取一次，再放一个坏文件取一次。断言空的那次 `broken == []` 且人话含「一个任务都没有」；坏的那次 `broken` 非空且人话**不含**「一个任务都没有」（两份人话逐字不相等）；
  - `test_task_list_description_mentions_unreadable` —— 从 tools/list 取 task_list 的 description，断言含「读不了」（现在只有 tools/pool_mcp.py:552-555 那两句，没有这个口径）。
- 失败分支：为了「不改接口」把坏文件塞进 `tasks` 的行里（假装它是任务）⇒ 红（`data["tasks"]` 里出现读不出来的 id）。

- 先红实证（2026-11-17，打在 HEAD b5a703cf 的树上：临时批目录，唯一的 T-1.json 写成坏 JSON，单文件 python 脚本，未入库）：五条断言里除 `is_error is False` 外**四条全红** —— payload 键是 `[batch_dir, count, tasks]`、`count = 0`、人话只有「（一个任务都没有）」。这就是「先写钉子会红」的读数；改完转绿的读数见判据 6 的变异记录。

### 判据 2 · 老形状（没有 waived 键、或 waived 为 null）当空集合处理，不许 KeyError

- 断言：tools/pool/task.py 里 waived 的 13 行读取点（`:668`、`:743`、`:747`、`:759`、`:765`、`:827`、`:843-844`、`:951`、`:969`、`:1018`、`:1117`、`:1149`）一律读 `(state.get("waived") or [])`；写回那处（`:765` 的 cmd_waive）在缺键时先补一个列表再 append。`_required` 读的是 declared（不是 waived），它的修法在判据 3。
- 什么情况下红：老形状下任一面抛 KeyError / TypeError；或 `waived=None` 时抛 `'NoneType' object is not iterable`；或把 `_missing` 改成吞异常返回空串（那是撒谎）。
- 钉子新增三条：

  - `test_task_list_tolerates_state_without_waived`（tests/test_pool_mcp_task.py）—— 用 `_seed` 真注册 T-1，再 `json.loads` 后 `pop("waived")` 写回（老形状照 `:162-168` 的造法），断言 `tool_task_list({})` 不抛、`is_error is False`、`data["tasks"][0]["id"] == "T-1"`、`data["tasks"][0]["waived"] == []`、人话含 `T-1` 与「还缺：卡A」（与完整形状的那一行逐字相同）；
  - `test_task_status_tolerates_state_without_waived` —— 同一 fixture，断言 `tool_task_status({"task": "T-1"})` 不抛、`is_error is False`、`data["waived"] == []`、`data["missing"] == "卡A"`、人话含「豁免 0」；
  - `test_helpers_tolerate_state_without_waived`（tests/test_pool_task.py）—— 老形状 dict 直接喂 `task._missing` / `task._bad` / `task._required` / `task._report`：断言 `_missing(st) == "卡A"`、`_bad(st_with_failed) == []`（st_with_failed = 老形状 + `"claims": {"卡A": "failed"}`）、`_required(st) == ["卡A"]`、`_report(st)` 返回 0 且打印行含「豁免 0」；再把 `waived` 设成 `None` 重跑一遍，断言四者同样不抛（`.get` 单独不够，必须 `or []`）。
- 失败分支：只把 `_missing` 改掉（`_bad` / `_report` 留着）⇒ 第一、二条绿、第三条红（说明必须成组改）。

### 判据 3 · 缺 declared 不许当空名单，也不许静默丢：点名「结构不对」

- 断言：状态文件缺 `declared`（或不是 list）时 —— task_list 把它放进 `broken`，error 逐字含「结构不对」与「declared」；task_status 回 `is_error=True` 并点名该文件（走 tools/pool/task.py 抛 `BatchError("结构不对：缺 declared 列表（不猜成空名单）")`，由 tools/pool_mcp.py:1977-1985 兜住）；`task._required` 对老形状抛同一条 BatchError，不许回空列表。
- 什么情况下红：缺 declared 的任务被当成「0 张卡 / 齐了」；或 `_required` 返回 `[]`；或 task_status 回 `missing == ""`。
- 钉子新增两条：

  - `test_task_list_missing_declared_is_named_not_dropped` —— 好任务一份 + 缺 declared 的一份，断言 `count == 1`、`broken` 只有那条、error 含「结构不对」与「declared」、人话含该文件名；
  - `test_task_status_refuses_state_without_declared` —— 断言 `is_error is True`、`found is True`、人话含文件名与「declared」，且**不含**「（齐了）」。

### 判据 4 · 计数口径自洽：count + broken 数 = 盘上状态文件数，「一个任务都没有」只留给真的零文件
