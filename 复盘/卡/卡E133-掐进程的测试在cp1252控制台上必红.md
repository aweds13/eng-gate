## 要解决的问题（逐条实测，不是推测）

判据只有一条：**「控制台编码」是这台机器的属性，不是全世界的属性**。测试要验的是「生产代码按系统编码写人话、按系统编码解坏字节」，不是「这台机器能编中文」。

### 问题 1 · `human` 硬编码中文 ⇒ cp1252 上在准备阶段就炸

`tests/test_pool_mcp_write.py:418-424`：

```text
418	def _expected_console_encoding() -> str:
419	    """这台机器的控制台编码 —— 被测代码就是按它写盘的。"""
420	    try:
421	        import locale
422	        return locale.getencoding() or "utf-8"
423	    except Exception:
424	        return "utf-8"
```

Python 文档 https://docs.python.org/3/library/locale.html 原文：**On Windows, return the ANSI code page**；且 **this function ignores the Python UTF-8 Mode** ⇒ `PYTHONUTF8` / `PYTHONIOENCODING` / `-X utf8` 全都改不动它（本机四种写法实测都回 cp936，见下方「直做」）。

GHA 的 `windows-latest` 是 **cp1252**，于是 `:452-457` 的两行在准备阶段就抛：

```text
452	    human = "成功: 已终止 PID 1（映像 python.exe）"
455	    system_enc = _expected_console_encoding()
456	    good_bytes = human.encode(system_enc)
```

实测原文（GHA job 日志 `gates/enggate-logs/win-133805837526.log`）：

```text
E   UnicodeEncodeError: 'charmap' codec can't encode characters in position 0-1: character maps to <undefined>
C:\hostedtoolcache\windows\Python\3.12.10\x64\Lib\encodings\cp1252.py:12: UnicodeEncodeError
1 failed, 4951 passed, 5 skipped in 1168.36s (0:19:28)
```

### 问题 2 · `b"\xff\xfe\xff"` 在 cp1252 下是合法三字母，不是坏字节

同一测试的坏字节那半把 `b"\xff\xfe\xff"` 当成「连系统编码都解不开」的样例。cp1252 把 0xFF/0xFE 都映射成字母 ⇒ 实测 `AssertionError: assert '\ufffd' in 'ÿþÿ'`。cp1252 真正未定义的字节是 **0x81 / 0x8d / 0x8f / 0x90 / 0x9d**。

两条都不是被测代码坏 —— 是测试把「本机成立」当成了「跨环境成立」。

## 判据（4 条，逐条可执行）

### 判据 1 · 样例按编码现造

新增 `_human_sample_that_survives(encoding: str) -> tuple[str, str]`：编码能编中文 ⇒ 用原中文串 `"成功: 已终止 PID 1（映像 python.exe）"` 并回探针 `"成功"`；编不了 ⇒ 退到「这个编码能编、utf-8 解必坏」的一个字母（cp1252 取 `é` U+00E9，候选还有 `Ω` U+03A9），回 `(改造过的人话, 探针)`。

### 判据 2 · 坏字节按编码现造

新增 `_undecodable_bytes(encoding: str) -> bytes`：候选 `b"\xff\xfe\xff"` / `b"\x81"` / `b"\x80\xff"` / `b"\x90"` / `b"\xff"`，取第一个在**这个编码**下 `decode(encoding, errors="replace")` 出现替换字符的。

### 判据 3 · 判据强度不变

`assert probe in detail` 取代 `assert "成功" in detail and "已终止" in detail`；坏字节那半改成 `bad_bytes = _undecodable_bytes(system_enc)` + `_Done(bad_bytes.decode(kwargs["encoding"], errors=kwargs["errors"]))`。两条钉子**一条都不许软化**：
- 「该用系统编码却用了 utf-8 ⇒ 人话变 U+FFFD」——仍在；
- 「坏字节只许 replace 不许抛」——仍在。

### 判据 4 · 反向变异咬得住

把 `tools/pool_mcp.py` 里**两处** `encoding=_console_encoding(),` 改成 `encoding="utf-8",`，测试必须红：cp1252 模拟下 `2 failed`、本机 cp936 下也 `2 failed`；还原后 `tools/pool_mcp.py` 的 sha256 必须回到 `bfce26b54ce685f8`。
