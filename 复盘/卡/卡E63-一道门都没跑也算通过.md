# 卡 E63 —— 一道门都没跑也算通过：`gates_ok([])` 空真与三把尺子

> 台账号 T-AG521 · 分区 E（CI 子系统）· 树 `.wt/E63` · 风险 mid
> 依据：主控 2026-10-28 用真探针逼出来的读数，原始证据
> `gates/diag/_probe_vacuous.txt`（2498 B）与 `gates/diag/_probe_zero_door.txt`。
> 本卡的病灶与 E60（两把尺子）、E61（判不出来说没事）、E62（零匹配说全绿）**同一条病根**：
> **「没有证据」被当成了「证据说没事」。**

## 要解决的问题

1. **`gates_ok([])` 返回 `True`，这是 `all()` 对空集的数学性质，不是笔误。**
   `scripts/run_gates.py:1498` 的实现：
   ```python
   def gates_ok(results: list[dict[str, object]]) -> bool:
       blocking = [r for r in results if r.get("blocking", True)]
       return all(int(str(r["exit_code"])) == 0 for r in blocking)
   ```
   实测（本机真跑 `import run_gates`）：
   ```
   gates_ok([])                                      = True
   gates_ok([{'name':'render','exit_code':3,'blocking':False}]) = True
   gates_ok([{'name':'render','exit_code':3,'blocking':True}])  = False
   ```
   ⇒ **零道门通过**，**全部 NOT RUN 也通过**。

2. **它在本地路径上能被真实触发，不是理论问题。**
   `--only render` 点一道纯 node 门，本机没有 node：
   ```
   resolve_cmd('render') = None   ← 记 not_run，不进 results
   results（进判据的门）= []
   not_run = ['render']
   gates_ok(results) = True  ⇒  整趟 ok = True  ⇒  run_gates.py 返回 0
   ```
   而**同一份 payload** 里 `not_run = ['render']` —— 产物自己写着「未验证，不算通过」，
   `ok` 却写「通过」，还退 0。

3. **本仓对同一份产物有三把尺子，三把说法不同。**
   | 位置 | 判「零门 + not_run 非空」 | 判据原文 |
   |---|---|---|
   | `scripts/run_gates.py:2371` 本地整趟 | **过**（退 0） | `ok = gates_ok(results)` |
   | `tools/gate_pool.py:446`/`:452` 云机复核 | **红** | `if sorted(got) != sorted(want):` / `problems.append(f"② 有门 not_run（未验证 ≠ 通过）：{not_run}")` |
   | `tools/wb_verify.py:240` 落地后复核 | **红** | `problems.append(f"有门没跑：{not_run}")` |
   三把里两把说红、一把说过。落地链本地路径（`tools/pool/landing.py:2325 if rc != 0: return rc`）
   信的是**第三把**（退出码）⇒ 本地能过、云机必红。

4. **还有第三类「没验证」没被任何一把挡住**：进了 `gates` 数组但 `exit_code == 3`。
   `scripts/run_gates.py:1424-1427` 把 exit 3 一律标成 `blocking=False` + `status="NOT RUN"`。
   于是「跑了但没验证」的门（`web_live` 在没 node 的机器上、`check_docs` 的 skip 档）
   在 `results` 里、`blocking=False` ⇒ 不计进 `ok` ⇒ **整趟仍可能 ok=True**。
   这与 `not_run`（压根没启动）是**两回事**，但后果一样：都不该算通过。

## 判据（六条）

1. **零门必须红。** `gates_ok([])` 必须返回 `False`。钉子
   `test_gates_ok_of_an_empty_list_is_false`：直接断言 `gates_ok([]) is False`，
   并配一条**绿对照** `gates_ok([{exit_code:0}]) is True` —— 只证明「空集红」不够，
   还要证明「非空且全 0 仍然绿」，否则把函数写成 `return False` 也能过。

2. **「零门」在真路径上必须退非零。** 沙箱里造 `--only render` + 无 node 的真实场景
   （`PATH` 里摘掉 node，或 `monkeypatch` `NODE_CMD['render']` 返回 `None`），
   断言 `scripts/run_gates.py` 退出码 != 0，且 stdout/stderr 里**点名**了
   「没有一道门真的跑过」这类原文（不许只说「失败」）。
   钉子 `test_only_a_node_door_without_node_exits_nonzero`。
   **这一条是本卡的主判据** —— 判据 1 是它的最小值，判据 2 才是用户真正会遇到的场景。

3. **三把尺子必须说同一句话。** 把「整趟算不算通过」抽成**一处**判据
   （`gates_ok` 或其继任者），`scripts/run_gates.py`、`tools/gate_pool.py`、
   `tools/wb_verify.py` 三处**都调它**，或至少被一条钉子钉住三者对同一份
   payload 结论相同。钉子 `test_three_rulers_agree_on_a_zero_door_payload`：
   构造一份 `{"ok": true, "gates": [], "not_run": ["render"]}` 的 payload，
   断言三处的判定函数都判红。做法照卡 E60 判据 6 的 `_NOT_A_RED_RULER` 体例：
   白名单为空且是对的 —— 扫出但**不是**这条语义的行必须进白名单并写明理由。

4. **`exit_code == 3`（跑了但没验证）不许静默。**
   ★ **这一条已经在现网真数据上发生了，不是假想。** 实测最后一趟云门禁
   `gates/last.json`（`ok=True`、`host=gates-runner-host`、22 门、`not_run=[]`）里：
   ```
   name = 'web_live'
   exit_code = 3
   blocking = False
   status = 'NOT RUN'
   note = '这一层**没有验证**，不算通过'
   summary = '[OK ] 局域网：自检把校园网/热点写进排查顺序'
   ```
   它自己的 `note` 写着「**没有验证，不算通过**」，而整趟 `ok=True`、`not_run=[]`，
   于是 `tools/gate_pool.py:452` 的 `if not_run:` **看不见它**（`not_run` 是空的），
   `tools/wb_verify.py:240` 的 `if not_run:` 也看不见它。
   ⇒ **三个复核口全都放行了一道自己声明「没验证」的门。**
   根因：`scripts/run_gates.py:1424-1427` 把 exit 3 的门留在 `gates` 数组里、
   只把 `blocking` 设 False，而「有没有验证」这件事被**两个不同字段**
   （`not_run` 与 `gates[].status`）各记一半。

   判据：一趟里只要有一道门的 `status == "NOT RUN"` 或 `exit_code == 3`，
   整趟就**不许** `ok=True`，除非调用方显式给了「允许未验证的档位」开关
   （第一版可以不做这个开关，直接判红）。
   钉子 `test_a_single_not_run_door_is_not_a_pass` + 一条绿对照
   （22 门全 exit=0 且无 NOT RUN ⇒ 仍 `ok=True`）。
   **交付里必须同时说明**：云机为什么跑不了 `web_live`（是没 node？没服务？
   还是这门本来就要真 uvicorn？），以及怎么让它在那台机器上真能跑 ——
   **不许把这条降级成「已知盲区」了事**，因为它现在是以 `ok=True` 的名义放行的。

5. **金样本绑机器，换机不许说「红」也不许说「绿」。** `gates/render/*.txt` 这 45 份金样本
   是**某台机器的显示栈**渲出来的（Edge 版本 / 字体 / DPI 决定字形推进宽度）。实测云机跑
   同一份代码：45 份里 **39 份逐字节不同，差异全是文字度量、结构完全一致** —— 那不是回归。
   ⇒ 那种门记 `status="EXCLUDED"` + `excluded_reason`：**不跑、不说通过**，产物里必须能读到
   「为什么这台机器不跑」。采集主机记在 `gates/render/CAPTURED_ON.json`（`host` 字段），
   读不到 / 为空 ⇒ **按未验证处理**（返回理由，不许静默跳过）。
   钉子 `test_golden_host_reason_is_none_on_the_capture_host`（绿对照）+
   `test_golden_host_reason_names_the_other_host` +
   `test_a_declared_gate_excluded_with_a_reason_is_not_red`。

6. **排除是一条豁免，必须念给人听。** 只有 `GOLDEN_PINNED` 里声明的门才许 `EXCLUDED`；
   且 `excluded_reason` 不许空。没有这一条，任何门都能自报 `EXCLUDED` 把红洗成绿 ——
   那正是本卡要消灭的那种话。钉子 `test_an_undeclared_gate_may_not_be_excluded` +
   `test_excluded_without_a_reason_is_red`。

## 反向验证（四条，逐条实测）

每条都要：把产品代码改成错的 → 跑钉子 → 断言红 → **从内存还原** → 断言逐字节回原样。

| # | 把什么改坏 | 哪条钉子必须红 | 期望的指名原文 |
|---|---|---|---|
| 1 | `gates_ok` 恢复 `all(...)` 原实现 | `test_gates_ok_of_an_empty_list_is_false` | 断言 `True is not False` |
| 2 | 删掉零门退非零那段 | `test_only_a_node_door_without_node_exits_nonzero` | 退出码 0 ≠ 期望非零 |
| 3 | 只改本地那把尺子、不改云机 | `test_three_rulers_agree_on_a_zero_door_payload` | 三处结论不一致，点名哪一处说绿 |
| 4 | 去掉 exit 3 判红 | `test_a_single_not_run_door_is_not_a_pass` | `ok=True` ≠ 期望 False |
| 5 | `golden_host_reason` 对任何机器都返回 `None`（当成「本机就是采集机」） | `test_golden_host_reason_names_the_other_host` | 期望有理由，实际 `None` |
| 6 | 判据 6 整段删掉 | `test_an_undeclared_gate_may_not_be_excluded` | 期望判红，实际 `(True, [])` |

**★ 必须遵守的纪律（E62 踩过的坑）**：变异体造出**语法错/运行时错**时，
那叫 **invalid mutant**（业界叫 stillborn mutant），**不算「咬住」**。
每次改完必须①先跑一遍基线拿到读数，②再改坏跑一遍，③逐条 diff 两份输出，
确认红的**恰好**是表里那一条、原文匹配。照 Stryker 八态的口径：语法不过的变异体
必须**丢弃**，既不算 killed 也不算 survived。断言「出错了」是不够的。

## 不许做

- 不许把 `not_run` / `exit_code==3` 直接从产物里删掉 —— 它们是**诚实的读数**，
  本卡改的是「怎么用它判」，不是「不记它」。
- 不许为了让云机继续全绿就把 `web_live` 从门表里摘掉。要么那台机器补 node，
  要么把这条如实记成卡里的「已知代价」并另开卡，不许在本卡里悄悄放宽。
- 不许只改本地 `scripts/run_gates.py` 就收工 —— 判据 3 就是为这条写的：
  三把尺子只改一把，等于把「两把尺子」变成「两把尺子 + 一把新尺子」。
- 不许把 `--only` / `--quick` / `--fast` 的既有语义一起改掉（它们本来就只跑一部分门，
  本卡要拦的是「跑零道门还说过」和「跑了没验证还说过」，不是「跑了少于 22 道」）。
- 不许在没跑云门禁的情况下落地 —— 本卡改的是通过判据本身。
- 不许用 `EXCLUDED` 给「跑不动」找退路：它只给**判据本身在别的机器上不成立**的那类门
  （目前只有 `render` 一道，理由是金样本与显示栈绑定）。「机器缺 node / 缺服务 / 太慢」
  仍然是 `not_run` 或红，不许改记成 `EXCLUDED`。
