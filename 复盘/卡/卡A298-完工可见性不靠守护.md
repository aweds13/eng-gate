# 卡 A298 · 完工可见性不靠守护进程（T-AG412）

## 问题

A297 的回推通道靠常驻 `wb_notify.py --daemon` 写 `gates/diag/notifications.jsonl`。
**关机重启后守护不会自己回来** ⇒ 那之后收工的卡不会进 JSONL，面板就看不见。
不能把「看得见」押在一个需要人来启动的进程上。

## 目标

把「已收工未收口」变成**读的时候当场算出来**的状态，不依赖任何常驻进程。

## 设计

1. 面板宿主路由 `GET /dsh-panel/notifications` **实时计算**（只读、不写文件）：
   - 扫 `gates/diag/wb-<卡>.verdict.txt`（取 mtime + 「判决：」行）；
   - 读 `docs/workbacklog.toml`，`status == "done"` 的卡剔除；
   - 结果 `{"ok":true,"unread":N,"items":[{card,verdict,at}],"source":"live"}`，最多 20 条，按时间倒序；
   - 若 JSONL（A297 的留痕）存在，合并去重，`source` 标 `live+history`。
2. **左栏常驻（用户 m12198 要求）**：客户端在 `sidebar.panellist` 的「工程工具箱」这一行上显示待收口数量
   （形如 `工程工具箱 · 3 待收口`，零未读时不加后缀）；数据来自上面那条只读路由，
   挂载时取一次 + 每 60 秒刷新一次；**不许弹窗、不许阻塞渲染**（拿不到就按 0 处理，不报错）。
   这样跨对话、重开 DSH 都看得见——它跟着插件走，不跟着某个会话走。
3. 工具箱「总览」页顶部同一行状态：`已收工未收口 N（最近：A289 20:14）`，点击展开列表；零未读不显示。
4. `tools/wb_daily.py` 增加一行「已收工未收口：N 张（最近 A289 20:14）」，零张时不显示。
5. daemon 变成**可选加速器**：`wb_notify.py --once` 仍可用；没有它，面板与巡检照样看得见。
6. 移除「必须起守护」的措辞（`tools/wb_dispatch.py` 的提示与技能文档同步改）。

## 验收

- 停掉 `wb_notify` 进程后，`curl /dsh-panel/notifications` 仍返回非空（只要有已收工未落地的卡）。
- 把某张 done 卡的 verdict 临时改名，`unread` 相应变化（测试用临时目录，不动真产物）。
- `pytest tests/test_dsh_panel.py tests/test_wb_daily.py -q --no-cov` 绿。
- `python -X utf8 tools/dsh_panel.py --check` OK（左栏行文案变化后自检仍绿）。
- 左栏行在零未读时**不带后缀**、有未读时带 `· N 待收口`（测试钉住两种形态）。
- `ruff check` 干净。

## 不做

- 不装开机自启、不改注册表、不加 Windows 计划任务。
- 不写 `gates/diag/`（面板宿主半只读是硬约束）。
