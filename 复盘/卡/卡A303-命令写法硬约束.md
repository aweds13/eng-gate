# 卡 A303 —— 命令写法硬约束：拦住管道截断与 sleep 硬等

## 1. 背景（为什么要这张卡）

用户原话（m13275 / m13322 / m13331）：

> 「就是不能后台返信息给你吗」「一定要wait或者sleep吗」「可以禁掉这些偷懒的东西吗，强制禁止掉」

两次落地都因为命令写成了 `wb_land.py … | tail -3`，管道要等进程结束才吐输出，
后台作业中途一个字都读不到，用户看到的就是「50 分钟一直卡着」。
另有一次用 `sleep 120` 硬等，同样是把时间当信息用。

这不是语气问题，是**工具用法问题**：长任务必须让输出**边跑边可读**，
等待必须靠**完成通知**而不是睡眠。

## 2. 要交付什么

1. `tools/run_logged.py`：跑命令并把子进程输出逐行落盘，每 `--every` 秒在自己的
   stdout 打一行心跳（含最后一行的前 120 字），结束时回放最后 `--tail` 行，
   退出码原样透传。
2. `tools/cmd_guard.py`：按 `--cmd` 检查命令原文，命中下面两类就退 1 并给改法：
   - `| tail` / `| head` / `| cut`（管道截断）；
   - `sleep N`（硬等）。
3. `tests/test_cmd_guard.py`：6 条钉子（管道截断、head/cut、sleep、合规写法、
   `main` 的 0/1 两种退出码与提示文字）。
4. `AGENTS.md`：写清「禁止管道截断 / 禁止 sleep 硬等 / 长命令一律
   `run_logged.py` 套起来」三条，并把 `cmd_guard.py` 定为跑前强制检查。
5. `skills/pipe-land/references/land-steps.md`：落地跑法一节，指向 `run_logged.py`。

## 3. 验收

- `python -X utf8 -m pytest tests/test_cmd_guard.py -q --no-cov` → 6 passed。
- `python -X utf8 tools/cmd_guard.py --cmd '… | tail -3'` → 退 1 且打印 `run_logged`。
- `python -X utf8 tools/cmd_guard.py --cmd 'python tools/run_logged.py --log env.log -- python tools/wb_land.py …'` → 退 0。
- `python -X utf8 -m ruff check tools/cmd_guard.py tools/run_logged.py tests/test_cmd_guard.py` → 全绿。
- 真机证据：用 `run_logged.py` 跑一次落地，日志里能看到「[心跳] 20s | …」增量行。
