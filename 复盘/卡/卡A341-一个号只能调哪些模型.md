## 要解决的问题

pool 的白名单是**按池**的，不是**按 caller**（账号 / 卡）的；而且它的立场与 magpie **方向相反**。

1. 允许集只有一处算得出：`tools/pool/model_registry.py:345 effective_allowed_for(pool, entries=None)`
   —— 「注册表该池条目 ∪ 开关文件里该池打开的」，注释写明「开关只做**加法**（注册表是下限）」。
   `tools/wb_dispatch.py:400 effective_allowed_models(pool)` 再加一次性授权（仅 codebuddy）。
2. 判据只有一份、且在 `tools/wb_dispatch.py:415 model_rejected(model, pool="codebuddy")`：**逐字**比较，
   不在集合里就回一段拒单文案。文案逐字「默认拒绝：既不在名单、也没在开关文件里打开的模型一律调不动」。
3. `grep -rniE "caller|api_key|per-key" tools/pool/ --include=*.py` ⇒ **0 行**；
   `max_models|最多.*模型` ⇒ **0 行**。⇒ 今天**没有任何**「这个号只能调哪些模型」的对象，也没有条数上限。
4. ★ **方向相反的铁证**：`tools/pool/plan.py:64 WILDCARD_CHARS = ("*", "?", "[")` 是「`files` 里**不许**
   出现通配」的拒单口径（`:284` 实际拒），理由是通配会让冲突域「静默绕过」。而 magpie 的 `*` 是**规则**、
   是**允许**。⇒ 两者管的是**不同字段**，不许把任一边的口径搬去另一边。

## 判据

1. **新增只收窄的纯函数**（`tools/pool/model_registry.py`，放在 `effective_allowed_for()` 之后）：

   ```python
   def narrow_for_caller(pool: str, allowed: Sequence[str], patterns: Sequence[str]) -> tuple[str, ...]:
   ```

   - `not patterns` ⇒ **原样返回** `tuple(allowed)`（逐字对应 magpie `Restricted()` `:37` 的「空 = 不受限」）。
   - 每条 `p`：与 `id` **大小写不敏感**逐字相等 ⇒ 命中；或 `p` 含 `*` 且 glob 编译后命中 ⇒ 命中。
   - **结果 ⊆ `allowed`**（不新增任何允许）—— 这是本函数的**全部意义**。
   - 必须是**纯函数**：不读文件、不读环境、不碰网络。

2. **`*` 跨斜杠**：`compileGlob` 逐字是 `(?is)^` + `strings.Join(parts, ".*")` + `$` ⇒
   `patterns=("codebuddy/*",)` 必须命中 `codebuddy/a/b`，`("*",)` 命中一切（但不新增）。

3. **大小写口径两层不同，且必须有意**：`narrow_for_caller()` 大小写不敏感（照 magpie `EqualFold`）；
   `model_rejected()` 保持**逐字**。两层不同口径要写进 docstring，不许被当成 bug「统一」掉。

4. **清洗函数与上限**（`tools/pool/model_registry.py`）：

   ```python
   MAX_CALLER_PATTERNS = 500      # magpie access/models.go:31 "A key can list at most 500 models"
   MAX_PATTERN_CHARS = 300        # magpie access/models.go:15 的长度上限

   def clean_caller_patterns(raw: Sequence[str]) -> tuple[str, ...]:
   ```

   trim、去重（不区分大小写）、必须含 `/` 且不以 `/` 开头或结尾、长度 ≤ 300、最多 500 条；
   越界 ⇒ 抛本模块已有的 `ModelRegistryError`，**不许**静默丢掉越界那条（丢一条 = 悄悄放宽一条）。

5. **`clean_caller_patterns` 的 docstring 必须显式写出与 `approved_models` 的分歧**：
   `tools/pool_accounts.py:147-151` 里 `approved_models = []` 的语义是「这个号不许派活」；
   而本卡的 `patterns = []` 按 magpie 口径是「不收窄」。两处空列表含义相反，照实写清，不许沉默。

6. **接入点顺序固定三步，不许调换**（调换会让某一步的拒单文案被吞掉）：
   ①`resolve_model(model, pool)`（跨池，`PoolMismatchError`）→ ②`model_rejected(model, pool)`（池内白名单）
   → ③`narrow_for_caller(...)` 的收窄判。第 ③ 步只许在 `tools/wb_dispatch.py` 的派活主路径与
   `tools/pool_mcp.py` 的干跑路径各接一处，且**必须调同一个函数**（`tools/pool/__init__.py:1-25` 逐字
   「它只 import 本包、不在这里重写判据」）。

7. **patterns 从哪来**：挂到仓外 `D:/repo/infra/pool/limits.toml` 的账号段
   （`[accounts."<稳定 id>"]` 的 `models = [...]`），键用 `accounts.toml` 的 **id** 不是 email。
   读不到 / 段不存在 ⇒ 空 ⇒ 不收窄。读表函数写成本卡自己在 `wb_dispatch.py` 里的一个小函数即可，
   **不新建文件**（`limits.toml` 是数据，不是判据）。

8. **反向钉子 `test_reverse_narrow_cannot_widen`**：把 `narrow_for_caller` 改成「命不中就**保留**」
   （白名单翻成黑名单）⇒ 必须变红。现场：`allowed=("a/x","b/z")`、`patterns=("a/*",)`，
   断言结果 `== ("a/x",)` 且**不含** `b/z`。

9. **★ 裁定 (c)：池前缀可省 —— 不放宽清洗，只改匹配口径**（2026-10-30 追加）。

   现场冲突：`codebuddy` 池的注册表别名是**裸名**（`deepseek-v4.1-flash` / `glm-5.3-flash` /
   `glm-5.3` / `kimi-k3-1` / `glm-5.2`，全部不含 `/`），`codearts` 池的别名自带 provider
   （`huaweicloud-maas/GLM-5.2` / `huaweicloud-maas/deepseek-v4.1-flash`）。而本条判据 4 照
   magpie `CleanModels` 要求每条 pattern **必须含 `/`** ⇒ 照原样匹配时两者相交为空，
   给 `codebuddy` 账号配 `models` 等于**全禁**。

   - `clean_caller_patterns()` 的 `/` 规则 **一字不动**（那是合规边界）。
   - `narrow_for_caller(pool, allowed, patterns)` 里除按 pattern 原样匹配之外，**若 pattern 以
     `f"{pool}/"` 开头（两边 `.lower()` 比，大小写不敏感），再拿剥掉这段前缀的剩余部分匹配一次**；
     两次命中任一即算命中。
   - ★ **只剥当前池自己的前缀**：`codearts/x` 写在 `codebuddy` 账号下**匹配不上**（结果等同不命中，
     **不是**放宽）；任意前缀都剥 = 放宽 ⇒ 必须被钉子咬住。
   - ★ 剥完是空串（pattern 就是 `"codebuddy/"`）按**不命中**处理，**不许**退化成「全命中」。
   - 结果仍 ⊆ `allowed`、保持 `allowed` 原序、仍是纯函数。
   - ★ 后果照实钉住：`codebuddy/*` 剥成裸 `*` 后 `*` 跨斜杠 ⇒ 它会命中**任何**形状的别名
     （含 `other/a/b`）。这是裁定的直接后果、不是放宽（结果仍 ⊆ `allowed`）。要只命中裸名就写
     `codebuddy/glm-*` 这类更具体的。
