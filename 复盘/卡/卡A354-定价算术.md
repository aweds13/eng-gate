## 要解决的问题

pool 全仓**没有一处**把 token 数换算成钱 —— 这是**有意的**，不是漏的：`tools/pool/ledger_spend.py:7-10` 的模块 docstring 逐字写着「★ **不内置价目表**：价格是外部事实，内置一份就等于在仓里埋一个会过期的常量。`cost` 一律由调用方给……本模块只做**记账与求和**，不做估算」。`cost` 的三处来源全是调用方给的浮点数（`ledger_spend.py:119 append(..., cost: float, ...)` / `limits_check.py:56-57` 只做比值 / `holds.py:221`+`:256` 只做缩放）。

结果是：调用方要自己算钱时**没有任何算术可用**，而这件事有几个必须精确的地方 —— 十进制位移（`0.3 USD/百万` 必须是 `"0.0000003"` 而不是 `"2.9999999999999997e-07"`）、分档是**严格大于**（等号不算）、整单按档（不是累进）、1 小时缓存写是 2×。

★ 本卡的边界是：**搬算术，不搬数据**。`pricing.py` 里不许出现任何厂商单价（`ledger_spend.py:7` 已经立过这条纪律，本卡只是把同一条纪律用在算术模块上）。

**另有一处顺手要记的探针结论（写进 changelog，不改代码）**：`tools/pool/ledger_spend.py:8` 引用的「`tools/wb_dispatch.py:1430-1454 append_usage_line()`」行号已过时，实测真行号是 `:1586`。

## 判据（13 条，逐条可执行）

**本卡的判据就是设计原件 §F42「判据逐条」那 13 条**，逐字照做：

1. `per_token(0.3) == "0.0000003"`，**不是** `"2.9999999999999997e-07"`，也**不是** `"0.00000030000000000000004"`（用十进制字符串位移，**不许**浮点除法）。
2. `per_token(20) == "0.00002"`；`per_token(0) == "0"`；`per_token(-5) == "0"`（`max(perMillion, 0)`）。
3. `per_token(1.25) == "0.00000125"`（小数位要跟着 `frac` 一起位移，不许截断）。
4. `at(price, 200_000 + 72_000)` **不**触发 272,000 档（**等号不算**）；`at(price, 272_001)` **触发**。两条必须成对。
5. `at(price, 300_000)` 在有 272,000 与 500,000 两档时，取 **272,000 那档**（「超过的最高一档」）。
6. `cost(...)` 传给 `at()` 的 prompt 数是 **`input + cache_read + cache_write`** 三项之和，**不是** `input` 一项。
7. `cost(...)` 里 `cache_write_1h` 先夹到 `[0, cache_write]`：`cache_write_1h=999, cache_write=10` ⇒ 按 10 计 1 小时价 + 0 按 5 分钟价；`cache_write_1h=-5` ⇒ 按 0 计。
8. `one_hour(price)`：有 `cache_write_1h` 用它，否则**退回 `cache_write`**（不是 0、不是抛）。
9. `one_hour_for("claude-opus-5-5", price)` 把 `cache_write_1h` 设成 `2 * input`，**分档里每一档也各自设一遍**（`2 * tier.input`）；对非 claude 的 id 原样返回。
10. `one_hour_for` 在 `cache_write <= 0` 或 `cache_write_1h > 0` 时**不改**（幂等、不覆盖已有价）。
11. `openrouter_pricing`：`prompt`/`completion` **键永远在**（价 0 也在），`input_cache_read`/`input_cache_write` **只在 > 0 时在** —— **绝不给 0**。
12. `unpriced_calls(rows)` 对**没有价**的调用计数，返回 `int`；`0` 时调用方**不许**打印 `"0 calls unpriced"`。
13. **没有价目表**：模块里**不许**出现任何具体厂商的单价常量。钉子级判据：`grep -c "gpt-\|claude-opus-5\|gemini-" tools/pool/pricing.py == 0`。

**常量逐字**：`COST_SCALE = 1_000_000` / `DISPLACE_DIGITS = 6` / `ONE_HOUR_FACTOR = 2.0` / `CLAUDE_HINT = "claude"`。

## 缺口的如实交代（进 changelog 的 gaps）

1. **`1.25` 这个 5 分钟缓存写系数没有源码常量**（只有 `catalog.go:196-200` 的注释）⇒ 本条**不把 1.25 写成常量**，`cache_write` 的价一律由调用方给。标「仅文档」。
2. **有效价五级优先级只有仅文档证据**，且条目清单里给的路径 `internal/provider/pricing*.go` **不存在** ⇒ 本条不移植。这是本篇**唯一一处「条目清单与实测不符」的路径引用**。
3. **`/v1/models` 的 `pricing` 键、`magpie model price` CLI、`--tier 272k` 语法**都是 HTTP/CLI 面，pool 没有对应面。`openrouter_pricing()` 只搬**输出形状**，今天**没有消费者**。
4. **`unpriced_calls` 的输入形状判不出**：原件在 `usage.Record` 上判（`Price` 为 nil 或零值），pool 的 `wb-usage.jsonl` 没有 `price` 字段、也没有「这次调用有没有价」的标记 ⇒ 本函数只能定义在**调用方传入的 dict 序列**上，与真实账本**还没有接线**。
5. **`cost()` 从未与 magpie 的真实输出对账**（没跑 `go test`）⇒ 正确性证据只有 `internal/catalog/price_tiers_test.go:29-44` 的**边界断言**，没有端到端数字比对。标「只在合成数据上验过」。
6. **判不出**：`PerToken` 对整数（`20`）与带小数（`1.25`）两种输入的行为是按 `FormatFloat(-1, 64)` + 字符串位移**推的**，没跑 Go 确认 ⇒ `1.25 → "0.00000125"` 标「按算法推，未跑」。
