# 卡 A299 · 接手旧项目的能力：方案咨询（T-AG413）

## 背景

现有七个技能（`skills/pipe-*` + `skills/softeng-manage`）**全部默认「这就是本仓」**：
已经有 `docs/workbacklog.toml`、`gates/last.json`、`tools/wb_*.py`、`gates/diag/` 产物。
拿它们去接一个**旧项目 / 别人写的 / 半途而废的项目**，第一步就卡：不知道它的卡在哪、门在哪、台账长什么样。

## 本卡要的产物

**一份方案文档**：`复盘/接手能力-方案.md`（≤200 行，中文），给下一张实现卡当输入。不要改任何技能、不要写代码。

必须回答这七件事：

1. **分类**：把「可接手的项目」分成几类（例如：已有同款骨架 / 有自己的 CI 与测试 / 只有代码没流程 / 只能只读观察），每类的判据是什么（可观察的文件与命令）。
2. **映射**：对方已有的产物（issue、PR、测试报告、TODO、看板）分别对应我们的「卡 / 门 / 证据 / 台账」哪一样；映射不上的，明确写「不映射」。
3. **安全边界**：接手第一笔允许做什么、禁止做什么（例：禁止改 CI 配置、禁止重写历史、禁止删脚本）。给出可执行的限制清单。
4. **最小骨架**：哪几样必须补（`harness.toml`、队列文件、门表…），哪几样坚决不补；补的时候是「只加文件」还是「允许改一行」。
5. **第一步验收**：从「只读勘察」到「一张卡 + 一道门 + 一笔落地」的最小路径，每步给命令与产物。
6. **失败模式**：至少 5 种「看起来接上了其实没接上」的假成功（例：门永远绿因为没真跑；卡登记了但没人派；证据指向不存在的路径），以及怎么识破。
7. **反例**：本仓自己哪些做法是**特例**、不能当通用能力（例如 `tools/dsh_panel.py` 的面板、`gates/diag/` 的运行态）。

## 硬要求

- 每条结论要有**可观察的证据**（文件路径 / 命令输出形态），不许写「应该」「建议考虑」这种空话。
- 必须区分「本仓特有」与「通用」；把本仓特有当成通用的地方要显式标出。
- 不许发明新概念名词；用本仓已有的词（卡 / 门 / 台账 / 证据 / 封存 / 租约）。
- 文档末尾给一节「下一张卡该做什么」，用 5 条以内说清实现顺序。

## 验收

- `复盘/接手能力-方案.md` 存在，七节齐全，≤200 行。
- `scripts/check_layers.py` PASS（文档里反引号只包真路径）。
- 不改 `skills/`、`tools/`、`tests/`、`docs/workbacklog.toml`。

## 不做

- 不实现技能本体（那是下一张卡）。
- 不碰任何现有项目目录（只读本仓与文档）。
