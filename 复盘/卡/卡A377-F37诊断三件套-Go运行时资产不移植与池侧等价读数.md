## 前情

F37 在 magpie 里是三个**Go runtime 专属**的只读端点：`/v1/magpie/heap`（gzip 过的 pprof heap protobuf，带 `X-Magpie-Heap-Stats` 头）、`/v1/magpie/cpu`（记 N 秒 CPU profile，N 限 5–120、默认 30、同时只允许一个，第二个 409）、`/v1/magpie/goroutines`（文本栈转储，且**先于**中间件链执行 —— 锁卡住时仍能答）。

原件逐字（`_ext/magpie-main/internal/gateway/gateway.go:788-798` 那三条 `mux.HandleFunc`）旁边每条都写着「(loopback only)」；`goroutines.go` 的注释给出的理由是「lanGuard's allow list reads settings.json under settings' file lock … goroutinesRefused and goroutineDump read only the request, the environment and the runtime, so the dump answers while any of those is stuck」。

**这三件都是 Go runtime 的资产**：`pprof.Lookup("goroutine").WriteTo(&buf, 2)`、`runtime.NumGoroutine()`、Go 的 CPU profiler。Python 侧没有对应物，本仓也没有管理面。
