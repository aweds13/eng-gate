# 卡 E88 —— 台账合并必须先做到无损，才谈得上启用分片（T-AG595）

> 台账号 **T-AG595** ｜ 分区 E（门禁与可信度）｜ 树 `.wt/E88` ｜ 层 判据层
> 基准提交 `3925f6e2`（E87 落地笔）

## 要解决的问题（已实测，不是推测）

目标①「多主控共用卡池的写入隔离」剩最后半步：把台账拆成 `docs/backlog/<分区>.toml`，
各分区各写自己的片，落地时用 `tools/wb_plan.py merge --execute` 合并成**只读总表**。
锁（卡 E81 `87f95ba5`）与分片读取（`load_sharded_backlog`，先分片后总表）都已经在了。

**但是合并本身会把总表弄坏。** 三个缺陷，全部在 `.tmp/` 沙箱里用真件复现过：

### 缺陷 1：没有覆盖性守卫，merge 会静默吃掉整本台账

`.tmp/_probe_merge_guard.py` —— 复制真总表进沙箱，只放一片 `E.toml`（1 张卡），
再跑 `wb_plan.py merge --execute`：

```
真总表：158788 B / 332 张卡
merge rc = 0
stdout: [写 ] 合并 1 张卡 → …e88_sandbox\docs\workbacklog.toml
merge 之后：175 B / 1 张卡
```

**331 张卡被吃掉，退出码 0，一句警告都没有。** `cmd_merge` 只问「分片能不能读出来」，
从不问「分片是不是把总表里的卡都覆盖了」。

### 缺陷 2：块序、表头、块内注释全漂

`.tmp/_probe_split_merge.py` —— 把真实 332 张卡按前缀拆成 7 片
（A226/B8/C2/D8/E68/F12/G8，各片 `render_merged_toml`），再 merge 回来：

```
合并 332 张卡，rc=0；卡数 332（没丢卡）
字节：真 158788 → merge 后 124888；逐字节相同 = False
同位置逐块相同 50/332；集合口径相同块 88/332；换位置的卡 188/330
unified diff 行数 5708
```

`.tmp/_probe_merge_losses.py` 逐个量出了漂掉的东西：

| 漂掉的 | 真件里的量 |
|---|---|
| 表头（`[base]` 段 + 29 行口径注释） | **2158 B** |
| 块内注释行 | **192 行，分布在 47/333 个块里** |
| 块顺序（真件是「A 与 LEGACY 交错 45 段」） | 前缀序列切换 **43 次**，重排后 188/330 张换位 |

根因在 `tools/wb_plan.py:781 render_merged_toml()` 的 docstring 里写得很坦白：
「只渲染本仓队列用到的字段…总表是**生成物**，手写注释不保留（注释留在各分片里）」。
问题是**分片里也留不住** —— 它渲染的是解析后的 `Backlog` 对象，
`Card` 只有九个字段，注释在解析那一步就已经没了。
所以「注释留在各分片里」这句承诺今天是不成立的。

### 缺陷 3：写出来的行尾是裸 LF，违反台账自己的纯 CRLF 规矩

`cmd_merge` 落盘用 `out.write_text(text, encoding="utf-8", newline="\n")`。
沙箱里 merge 出来的文件：`175 B / crlf 0 / bareLF 13`。
而 `tools/pool/ledger.py:308 non_crlf_lines()` 是台账的硬规矩（卡 E81 判据 3），
`add_card` 每次写之前都要验它：「纯 CRLF 时必须是 0」。
真件工作区是 `158788 B / crlf 5338 / bareLF 0`（纯 CRLF，`core.autocrlf=true`
把入库的 LF blob 检出成 CRLF）。**merge 一落盘，台账就不再是合法台账。**

### 为什么必须先修这个再启用分片

三件事加起来意味着：今天只要一启用分片、一跑 merge，总表就会
**丢掉 2158 B 口径注释、192 行卡片备注、整本卡片的既有顺序，并且行尾变成裸 LF**。
分片是「让并发写入不打架」的手段，不是「让台账变差」的理由。
**先把合并做成无损，再启用分片** —— 本卡只做前半，启用留给下一张。

外部实践同向：把手工维护的共享账本变成**生成物**、并让合并对「没变的部分」字节稳定，
是冲突抗性文件流的通用做法
（[BE-0043](https://raw.githubusercontent.com/bajutsu-e2e/bajutsu/refs/heads/main/roadmaps/BE-0043-conflict-resistant-file-flow/BE-0043-conflict-resistant-file-flow.md#1)、
[psaab/xpf@ba18839](https://github.com/psaab/xpf/ba18839b1303e56d5053497ca16e810a6d7e0b4e)）。

## 判据（6 条）

1. **覆盖性守卫：少一张就拒写。** `merge --execute` 之前必须比一次卡号集合 ——
   总表里有、而所有分片加起来没有的卡号非空 ⇒ **不写盘**、逐个点名缺哪些卡号、
   `return` 非零（不许是 0）。判据是可测的：沙箱里「总表 332 张 + 分片 1 张」必须被拒，
   且拒完之后总表字节**一字未变**。

2. **无变化就零 diff。** 拿真总表拆出的分片（内容与总表完全一致、只是换了存放位置）
   去 merge ⇒ 落盘结果与 merge 前的总表**逐字节相同**（`read_bytes()` 相等）。
   这一条同时钉住块序、表头与块内注释三件事：任何一件漂了都过不了。

3. **块级搬运，注释不许在解析里蒸发。** 合并不是「解析成 `Card` 再重新渲染」——
   每张卡的块字节必须**原样取自它所在的那一片**（含块内 `#` 注释行）。
   判据：造一片含注释的卡，merge 之后总表里那些注释行**逐字还在**。

4. **新卡只往后长，不许挤位。** 分片里有、总表里没有的卡号 ⇒ 追加在总表**末尾**，
   既有卡的相对顺序一律不动。

5. **落盘必须是纯 CRLF。** merge 写出的文件 `non_crlf_lines(raw) == 0`，
   且 `ledger.non_crlf_lines()` 能直接吃（不抛、不为正）。

6. **既有行为一字不变。** 没有分片 ⇒ 仍然 `[OK ] 没有台账分片（…）—— 总表不变`、退 0；
   分片里卡号重复 ⇒ 仍然 `[FAIL] 卡号重复：<号>（分片 <名>）`、退 2；
   不加 `--execute` ⇒ 仍然只打印不落盘。`tests/test_partitions.py` 既有条目全绿。
