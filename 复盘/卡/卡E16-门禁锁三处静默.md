# 卡 E16 · 门禁锁的三处静默：等锁没进度、死主不释放、要人肉 --force（T-AG467）

## 现在疼在哪（实测）

1. **等锁时落地日志一片空白**。`tools/pool/landing.py` 调 `gates/diag/gate_lock.py acquire` 时用了
   `subprocess.run(..., capture_output=True)`，而 `gate_lock.py` 每 60 秒会打印
   `[锁] 等门禁锁 Ns… 本段锁被占：card=… pid=…（已 Ns）` —— 这些行全被吞进返回值，
   于是 `gates/diag/land-batch460.log` 从 19:49:42 到 20:18 只有一行「起跑」，
   看起来就是「卡死」（我因此白等了 28 分钟才发现它在等锁）。
2. **被杀掉的落地把锁留在磁盘上**。19:47:33 那趟批落地（`--batch T-AG460`，pid 44680）被我 `job_kill` 杀掉，
   `gates/diag/gates-9361.lock` 留了下来；19:49:42 起的那趟只能 `acquire --wait 5400` 干等，
   而租约是 **10800 s**（3 小时）—— 没有任何机制看「持有者 pid 还活着吗」。
3. **只能人肉判断 + `--force`**。我最后是 `cat` 锁文件、比对 `Get-CimInstance Win32_Process` 里没有 44680，
   再 `TF_GATE_PORT_BASE=9361 python -X utf8 gates/diag/gate_lock.py release --card T-AG460 --force`。
   这一步没有任何判据支撑，纯靠人看。

## 你要做的事

三处各修一处，都**不许放松**租约语义（T-G169：陈旧判定以持有者写进锁文件的租约为准）：

1. **等锁有进度**：`tools/pool/landing.py` 里拿锁那一步改成**流式**（`Popen` + 逐行读到自己的输出/日志），
   `gate_lock.py` 打印的每一行都要出现在落地日志里。
2. **死主自动清**：`gate_lock.py acquire` 拿到 `FileExistsError` 时，除了看租约，再看持有者
   **进程是否还活着**（同一台机器：`os.kill(pid, 0)` / `tasklist` 之一，Windows 下要能跨权限失败不算死）；
   判定「同机 + pid 不存在 + 租约未过期」时，**再等一个宽限期 `grace`（默认 60 s，防 pid 复用）**，
   仍不存在就清掉并打印 `[锁] 清掉死主的锁（card=… pid=… 进程已不存在）`。跨机/判不了身份时**保持原样等待**。
3. **体检先说锁**：`wb_land.py --preflight` 加一条 —— 打印本端口段（以及全局）当前锁的
   `card / pid / 已持有秒数 / 持有者进程是否还活着 / 剩余租约`，判断不了就明说 `not verified`。

## 判据（机器可判）

1. 造一个「持有者 pid 不存在」的锁文件 + 把租约写成很大 ⇒ `acquire` 在 grace 后拿到锁，并打印清锁行。
2. 造一个「持有者 pid 存在（用当前进程 pid 冒充）」的锁 ⇒ 宽限期内**不许**清，等锁超时退 3。
3. 判不了身份（锁文件里没有 pid 字段）⇒ **不许**清，等锁超时退 3，并打印「判不了持有者身份」。
4. 宽限期可用 `--grace 0` 关掉（回到今天的行为），默认 60。
5. `--force` 语义不变（人工兜底）。
6. 落地日志里能看见等锁进度：造一个假锁 + 起一趟真落地（或直接调 landing 的取锁函数），
   3 分钟内日志里必须出现 ≥1 行 `[锁] 等门禁锁`。

## 钉子（≥4 条）

1. 死主锁 ⇒ 清掉 + 拿到（退出码 0 + 打印清锁行）。
2. 活主锁（pid = 当前进程）⇒ 宽限期后仍等（不许清），超时退 3。
3. 无 pid 字段的锁 ⇒ 不清，超时退 3，报行含「判不了持有者身份」。
4. `--grace 0` ⇒ 不清死主锁（回到旧行为）。

## 不许做

- 不许改 `_lease_of()` 的租约语义（T-G169 的原意：别人的活锁不能被短租约清走）。
- 不许在跨机/判不了身份时清锁。
- 不许把 `--wait` 默认值改小（那是超时，不是判据）。
