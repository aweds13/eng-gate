# 卡 D5 · 教材库与页码唤图（一窗一书 + #p12 发送前本地解析成图像块）

- task: T-DG005
- tree: `.wt/D5`
- risk: mid
- depends: D1, D2

## 问题

用户要的是「拍下来，以后打编号就能叫出来」，而不是每次重发图。官方 App 只会「发过的文件挂在
原消息上」且会过期（`The file has expired. Please re-upload.`）。本项目的差异点就在**页码编号 +
本地解析**（needs N7/N8/N9、decisions D6/D7）。最关键的判据是：**模型收到的必须是图，不是
`#p12` 这串字**。

## 改法

1. `Books.kt`：`book(id, name, createdAt)` / `page(bookId, pageNo, images[], createdAt)`；页码由用户给，
   默认「接着上一页」；撞号拒绝并高亮冲突项。
2. `Camera.kt` / `Compressor.kt`：拍照、相册多选；入库前压缩长边 ≤2048（vision 每图只算 1024 token，
   更大只是浪费流量）；图存 App 私有目录，DB 只存相对路径 + hash。
3. `PageRef.ts`：输入框识别 `#p12` / `#12` / `#第12页` → 变成胶囊（可点预览）；**发送前**由前端调
   `store` 取该页图 → 转 base64 → 作为 **user 消息的图像块**随请求送出（C5：图只能在 user 消息）。
4. 缺页/未绑定书 → **不发请求**，当场提示并可拍照补录。

## 判据

- 拍 3 张 → 建书起名 → 页码 1/2/3 → 书库可见（第一页缩略图当封面）。
- 会话绑书 → 顶部常驻书名；未绑书时输入 `#p2` 给出「先绑定一本书」的提示而不是静默失败。
- 打 `#p2` 发送 → 抓包可见请求体里是 `image_url`（base64），**没有** `#p2` 字面串当唯一内容；
  模型回答能描述该页内容。
- 打 `#p99`（不存在）→ **无网络请求**，出现「这本书没有第 99 页，现在拍？」+ 拍照入口。
- 一页拍两张 → 一起送出，顺序按录入时间。
- 关 App 重开 → 旧会话里 `#p2` 仍唤出同一张图（比对 hash）。
- 抓包确认：**没有**调用 `/api/v0/file/upload_file` 或 Files API 长期托管（C7）。

## 证据

- 抓包截图（请求体含 image、无 #p2 字面串）。
- 缺页时的界面截图（含「无请求」的抓包证据）。
- 重开 App 后唤图的 hash 比对输出。

## 不做

- 不做 PDF 导入/自动切页/OCR（第二版，decisions D14）。
- 不做「按文件名字母序自动编号」（页码是用户说了算，C13）。
