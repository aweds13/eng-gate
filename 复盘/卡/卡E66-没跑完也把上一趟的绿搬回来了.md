# 卡 E66 —— 没跑完也把上一趟的绿搬回来了（T-AG526）

> 台账号 `T-AG526` ｜ 分区 E（工具面 / 门禁机制）｜ 树 `.wt/E66` ｜ 层 框架
> 依据：m12391「门禁必须上云」+ 本仓铁律「判不出来的时候不许说没事」（E61/E63/E64/E65 同一族）。
> 实测现场：2026-10-29 03:00 云机被定时任务关掉，`run_gate.sh E65 9448` 的 4/5 中途断线。

## 要解决的问题

`scripts/cloud/run_gate.sh` 的第 5/5 步**无条件**把云机上的 `gates/last.json` 搬回
`.wt/<卡>/gates/last.json`，不看这一趟到底跑成没跑成：

```bash
ssh ... "cd $cloud_dir && ... scripts/run_gates.py && ... run_gates.py --seal" > "$TMP/gate.out" 2>&1
rc=$?
echo "门禁退出码=$rc 用时=...s"
echo "=== 5/5 回传 gates/last.json 与日志 ==="
scp ... "$HOST:$cloud_dir/gates/last.json" ".wt/$card/gates/last.json"
```

而第 2/5 步刚把一份**绿的上一趟**播种进云机的 `gates/last.json`（`gates/diag/seed-<卡>/`）。
于是「机器在 4/5 被关机」这种最常见的失败，产出的是：**一份绿的、`host` 为云机、
`rev` 也对得上的产物** —— 它不是这一趟跑出来的，但落地链的三道自检
（`ok` / `host` / `tree` 复算）**全都过得去**，因为它就是上一趟的真读数。

这是「把没跑出来的东西说成跑出来了」的又一个变种，比 E60 的两把尺子更隐蔽：
E60 是**判据不统一**，这里是**产物来源不分辨** —— 播种源与真产物共用同一个路径，
谁最后写谁说了算，而断线时最后写的是播种。

## 判据（5 条）

1. **产物必须自证是这一趟写的**：新增纯函数
   `tools/gate_pool.py::product_is_from_this_run(payload, *, started_at, shipped_text="", seed_text="") -> tuple[bool, str]`，
   两条独立证据，任一不过即不新鲜：
   - ① `payload["at"]` 不早于本趟 4/5 起跑时刻（`at` 由 `scripts/run_gates.py` 在写盘时打，
     是本仓既有字段，不新造）；
   - ③ 产物与播种源（`gates/diag/seed-<卡>/last.json`）**不许逐字相同** ——
     这条不依赖任何时钟（R12 已登记「两台都是裸本地钟」，时钟只能当辅助证据）。
   判不出（缺 `at` / 解不出时间）⇒ **算不新鲜**（fail closed）。
2. **不新鲜就不许留下**：`5/5` 回传后立刻核验；不新鲜 ⇒ 删掉刚搬回来的
   `last.json`（避免后续任何工具读到它）、打印「这趟没产出读数，`.wt/<卡>/gates/last.json`
   上那份是上一趟的」、**退 9**。日志照常回传（排障要用）。
3. **`rc == 0` 但产物不新鲜 ⇒ 同样退 9**：不信退出码，只信产物自证。
4. **反向验证**：把播种那份原样当产物 ⇒ 必须拒（`stale`）；把 `at` 改到起跑之后 ⇒ 必须收
   （`fresh`）；缺 `at` / `at` 不可解 ⇒ 必须拒不收；`at` 恰好等于起跑时刻 ⇒ 收（边界算新鲜）；
   朴素 `at` 与带偏移的起跑时刻按同一墙上时钟比。**两个变异必须都咬住**
   （`gates/diag/_rev_E66.py`）：M1 把 ③ 换回 `return True, ""`、M2 把 `run_gate.sh` 的核验段换成
   `if false; then`。
5. **不许放宽既有判据**：`host` 非空那条、`ok` 那条、`tree` 复算那条一个字都不动。

## 交付

- `tools/gate_pool.py::product_is_from_this_run()` + 一个只做这件事的小 CLI 入口
  （`python -X utf8 tools/gate_pool.py check-product-fresh <last.json> --started-at <ISO> --seed <seed.json>`
  —— 子命令形态而不是 `--flag`：`gate_pool.py` 的 CLI 本来就是 `status` / `slots` 两个子命令），
  让 bash 侧不必再写一套时间比较。
- `scripts/cloud/run_gate.sh`：4/5 前记 `started_at`（`date -Iseconds` 走云机时钟不可靠，
  用**本机**时钟记起跑，再与产物 `at` 比；两者时区都带偏移，按绝对时刻比）。
- `tests/test_cloud_product_freshness.py`：判据 1/3/4 的单元钉子（含四个反向用例）。
- `docs/subsystems/ci/云门禁机.md`：第 5/5 步的行为写清楚「断线 ⇒ 不留产物、退 9」。
- `docs/subsystems/ci/云门禁-可复现性清单.md`：加一行（R17），与既有 R1–R16 同格式。

## 不许做

- 不许把 `seed-<卡>/` 的判定改成「只要有 host 就当新鲜」——那正是本卡的病灶。
- 不许改 `tools/gate_pool.py::validate_cloud_return` 的三条（③host 非空）语义。
- 不许在 `run_gate.sh` 里用云机时钟算新鲜度（云机 RTC 与本地有偏移，且断电重启后更不可信）。
- 不许为了让门变绿而给 `product_is_from_this_run` 加「宽容窗口」（例如 ±10 分钟）：
  `at` 是跑完写盘的时刻，只会晚于起跑，不需要窗口。
