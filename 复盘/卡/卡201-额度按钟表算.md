# 卡 201 —— **额度状态按钟表算**：429 不许凭记忆，一律「记录时间 vs 现实时间」（T-G303）

## 为什么有这张卡

用户 2026-10-12 原话：

> 「还有 pool 要有个功能，就是你 429 了，**不要凭记忆确定是否 429**，要根据**记录时间和现实时间对比**。」

主控实测**三个缺陷**（都在主树 HEAD 上现读，行号以你拿到的树为准）：

1. **那个重置时间从头到尾没被当成时间。** `tools/wb_dispatch.py::quota_error()` 从日志里抠出
   「将在 <时间> 重置」，但只当**字符串**返回：`{"kind": …, "reset": hit.group(1), "why": …}`。
   这个字符串只进两处 —— 判决文本（`429 限流（额度重置时间：…）`）与进程内的字典 `quota_seen[model]`。
   **全仓没有一处把它解析成时间戳。**
2. **等待是写死的。** `DEFAULT_QUOTA_WAIT = 300` 且 `time.sleep(args.quota_wait)` ——
   记录写的是 5 分钟后还是 5 小时后，它都睡 300 秒。
3. **MCP 面根本不报额度。** `tools/pool_mcp.py` 里 grep `重置时间` / `reset` **零命中** ⇒
   会话里问「现在能不能派活」得到的是**人的记忆**，不是读数。

★ 真现场（这条卡自己就是证据）：记录写着 `额度重置时间：2026-10-12 16:52:45 UTC+8`，
主控 23:28 现探 —— **两个模型都通**。「过期」根本不是「可用」，**只有探测才是证据**。

## 要做的事

### 1. 新 `tools/pool_quota.py`

- `record`：把一次 429 落成**一条记录** ——
  `{card, model, pool, kind, reset_raw, reset_at, recorded_at, source_log, source_line}`，
  写进 `gates/diag/quota-state.json`（**派生、可重建、gitignored**；已存在同卡同模型的记录就覆盖）。
  `reset_at` 用 ISO-8601；**解析不出来就写 `null` 并保留 `reset_raw`**（不许拿别的数冒充）。
- `status`：**每次现算**，读记录 + 读「现在」，输出**四态**（每一态都要打印**判据**）：
  | 态 | 条件 | 打印什么 |
  |---|---|---|
  | `限流中` | `reset_at > now` | **剩余** HH:MM:SS + 记录时间 + 现在 |
  | `已过期，需重新探测` | `reset_at <= now` | 过期多久 + **一句「过期 ≠ 可用，要探」** |
  | `余额耗尽` | 无 `reset_at` | 「没有重置时间 ⇒ **不自动等**，只能探」 |
  | `未记录` | 没有这条记录 | 「没记录 ⇒ **不猜**」（★ 不许默认当可用） |
- `--now <ISO>`：注入「现在」（**测试不许靠真实钟表**）。

### 2. 改 `tools/wb_dispatch.py`（**只加，不改判据**）

- `quota_error()` 的返回值**加一个 `reset_at`**（ISO 或 `None`），原有 `kind` / `reset` / `why`
  一个都不许动。
- ★ **卡 045 那两道判别闸门一个字不许改**（候选闸门 + 结构化字段优先）—— 那是真撞出来的。
- 等待由固定值改成**按记录算**：`wait = clamp(reset_at - now, 0, 上限)`；
  `reset_at` 解析不出来才退回现在的固定 `--quota-wait`。
- 撞到 429 时调 `pool_quota.record`（判据只许一份真源，**不许在 wb_dispatch 里重写解析**）。

### 3. 新 `tests/test_quota_clock.py`（≥4 条）
