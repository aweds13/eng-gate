## 要解决的问题

pool 今天**没有「钱包」这一层**：一个号一个月烧掉多少 token、多少钱，仓里没有任何地方能回答。
`gates/diag/wb-usage.jsonl` 有 token 数但**没有账号维、没有金额**（行键实测 11 个：
`卡/模型/轮次/开始/结束/用时分钟/input_tokens/output_tokens/cache_read/退出码/判决`），
写方 `tools/wb_dispatch.py:1430-1454 append_usage_line()` 的 docstring 明写「只数 token，不做金额换算」。
于是「这个号这个月还剩多少」只能靠人记 —— 这正是 magpie 用 `Limit` + `Reserve` 挡住的那类事故。

★ 本卡与既有 `--input-budget` 的**语义差别必须写进代码注释**：magpie 的限额保护**钱包**
（一把外部 key 在烧我的钱，派之前就拒）；`--input-budget` 保护**一次任务的时长/成本失控**
（跑起来才 `break`）。同一个 token 数，一个是预算授权、一个是熔断。**把 `input_budget` 改名当限额 = 假限额。**

★ 本卡只立**判据面与记账面**，不改 `tools/wb_dispatch.py` 的派活流程（接线是下一张卡）：
接线点已勘明在 `tools/wb_dispatch.py` 占树之前（约 `:3280`）与 `append_usage_line(...)` 之后（约 `:3402`），
但一改就会与在飞的 `A335`（同文件）撞车，且「派之前拒」需要先有真策略文件与真价目表才谈得上。

## 判据

1. **`tools/pool/limits_policy.py`（新）读策略，只读不写、不联网、不看钟**：
   `MAX_LIMITS = 5`、`MAX_DAYS = 3650`、`MAX_HOURS = 8760`、`PERIODS = ("day","week","month","days","hours")`、
   `COST_ROUND = 4`；`class LimitError(ValueError)`；`@dataclass(frozen=True, slots=True) class Limit`
   （`period/days/hours/tokens/cost/cache_reads/since`）；`Limit.limited()` **逐字对应** `limit.go:113`
   的 `Tokens > 0 || Cost > 0`；`parse_limit(raw)` 校验 + 归一；`window(limit, now) -> (start, reset)`；
   `load_limits(path=None) -> dict[str, tuple[Limit, ...]]`（文件不存在 ⇒ `{}`，坏文件/越界/超 5 条 ⇒ `LimitError`）。
2. **`window()` 逐字对应 `limit.go:187-222`**：`week` 从**周一 00:00**（`now.isoweekday()` 回退）、
   `month` 从**1 号 00:00**（`now.replace(day=1)`）、`day` 从**当天 00:00**；`days`/`hours` 从 `since` 起算，
   **`since is None` ⇒ `LimitError`**（不许默认「从现在起算」—— 那等于每次重启重置窗口）。
   一律用 `tools/pool_accounts.TZ`，**不许新造时区**。
3. **`parse_limit()` 校验文案里的数字从常量拼出来**（同 `tools/wb_dispatch.py:2907-2908` 的纪律）：
   `days` 超出 ⇒ 文案含 `1` 与 `3650` 两个字面数值；`hours` 超出 ⇒ 含 `1` 与 `8760`；
   未知 `period` ⇒ 文案含五个周期名；负值 ⇒ 文案含「不能为负」；第 6 条 ⇒ 文案含 `5`。
4. **`cost` 精度**：`parse_limit({"cost": 20.00005})` ⇒ `.cost == 20.0001`（照 `math.Round(v*1e4)/1e4`）。
   `tokens=0` 且 `cost=0` ⇒ `limited()` 为假 ⇒ 该条**被忽略**（对应 magpie `limitsOf` 只收 `Limited()` 的）。
5. **`tools/pool/ledger_spend.py`（新）记账**：`SPEND_REL = ("gates", "diag", "pool-spend.jsonl")`；
   `append(account, card, model, *, input_tokens, output_tokens, cache_read, cost, at, root=None)` **追加写、永不覆盖**；
   `sums(account, start, end, *, cache_reads=False, root=None) -> tuple[int, float, int]` 只统计 `start <= at < end`
   （**左闭右开**），token 口径逐字抄 `budget.go:69-75`（`input+output+cache_write`，`cache_reads` 真才 `+cache_read`）；
   `forget(account, before, *, root=None) -> int` 把早于某刻的行**另存并删**，**只在人显式 `reset` 时调**。
   ★ **本模块不内置价目表**：价格是外部事实，内置一份就等于在仓里埋一个会过期的常量。
6. **`tools/pool/limits_check.py`（新）判据面纯函数**：`@dataclass(frozen=True, slots=True) class Verdict`
   （`allowed/binding/reset_at/retry_after_s/why`）；`check(limits, *, spent, now, inflight_tokens=0, inflight_cost=0) -> Verdict`：
   ①`limits` 空 ⇒ `allowed=True`（逐字对应 `:341` `len(ls) == 0 ⇒ 永不过问`）；②**每一条 limit 都要有余量**，
   任一条不够就拒；③在飞预留要算（`spent[i] + inflight >= limit`）；④`retry_after_s >= 1`（照 `:318-320`
   `max(int(...+0.999), 1)`）；⑤`binding` 按 `Binding()` 三段优先级选：**已花完的优先** → **续期最晚的** →
   `share()`（用量/上限）最大的。
   ★ **判据只许写这一份**，注释里明写「`wb_dispatch` / `pool_mcp` 将来都调它，不许各写一份 if」。
7. **`check()` 用 `>=` 不是 `>`**（照 `budget.go:204-219` 的 `st.Tokens >= l.Tokens`）：`tokens=100`、`spent=(100,0.0)`
   ⇒ **不许放行**。差一个 token 就放行是只在边界出现、人工测不出来的偏差。
8. **零值方向**：`load_limits()` 读不出文件 ⇒ `{}`（= 没设限额 = 今天的行为），**不许**回落到「无限」
   也**不许**抛；但 `parse_limit` 遇到坏数据**必须抛 `LimitError`**（不许跳过坏条目继续用剩下的 ——
   跳过 = 悄悄松开判据）。
