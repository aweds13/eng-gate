# 卡 A339 —— 一个号同时只能派几张（T-AG541）

> 台账号 `T-AG541` ｜ 分区 A（历史线 / 号池 pool）｜ 树 `.wt/A339` ｜ 层 判据层
> 依据：magpie 的**每账号并发闸** —— 三条上限 `MaxLimit = 1000`（同时在途）/ `MaxQueueLimit = 10000`（每 lane 排队）/
> `MaxQueueWait = 3600`（排队最多等几秒）在 `internal/provider/concurrency.go:41-47`；
> 拿槽入口 `lanes.take(ctx, who, limit, queue, wait)` 在 `internal/gateway/concurrency.go:82`，三支判定 `:82-150`：
> `limit <= 0` ⇒ **不限**（只计数）、有空位且无排队 ⇒ 立刻拿、`queue > 0 && len(queue) >= queue` ⇒ `errQueueFull`、
> 否则入队后 `select` 三路（拿到 / `ctx.Done()` / 超时 `errQueueWait`）；两条具名错误 `:63-66` 逐字
> `errQueueFull = errors.New("queue full")` / `errQueueWait = errors.New("waited too long")`；
> 放槽 `grant()` `:218-224` 是 `for len(ln.queue) > 0 && (ln.limit <= 0 || ln.busy < ln.limit)` —— **先来先服务**；
> 文件头 `:14-27` 定义了这个词的边界：「Waiting is not failing: a request queued is never passed to a fallback
> for want of a free slot, and the key or account it waits for doesn't rest.」
> 实测现场（2026-10-30，主树 `e3641bb9`）：租约 `entry` 的**全部 12 个键**（`tools/pool/registry.py:312-325`）
> 是 `card/task/tree/files/project/pool/model/log/owner/at/ttl_seconds/note` —— **没有 `account`**；
> `grep -rniE "queue_limit" tools/ --include=*.py` ⇒ **0**；`queue_wait` ⇒ **1**，唯一命中是
> `tools/pool/landing.py:1930` 的落地合并队列（同名不同物）；`lanes.limit` / `MaxConcurrency` ⇒ 0。
> 与在飞卡的关系：本卡改 `tools/pool/registry.py` 与 `tools/pool/guards.py` ⇒ 必须等 A333/A334/A335
> 三张改 `tools/pool_accounts.py` 的卡落地后再开树（本卡不碰 `pool_accounts.py`）。

## 要解决的问题

一个号被同时派几张卡，今天**没有任何判据**：`tools/wb_dispatch.py:2817-2854` 的 `dispatch_batch()` 是串行
（一张跑完再下一张），但只要两个**不同的**批/两个人各起一次派活，同一个号就会同时出现在两棵树上。
`registry.reserve()` 的四条守卫里，`tree_guard` 管树、`domain_guard` 管冲突域、`lock_guard` 管门禁锁、
`log_guard` 管日志不许覆盖 —— **没有一条看「这个号现在在跑几张」**。

`account` 今天只是一段塞进 `note` 的显示文本（`tools/wb_dispatch.py:3323` 的 `f"｜account={args.account}"`）。
从显示文本反推判据是本仓明令禁止的：`tools/pool/registry.py:21-26` 拒绝用 pid 判活、`tools/pool/jobs.py:204-214`
拒绝用宽 glob 抠卡号。所以本卡第一步是**给租约一个可判的键**。

★ 说清语义差别，不许靠改常量糊过去：magpie 的并发闸保护的是 **vendor 的限流**（同一个 key/账号被自己打太多会 429）；
pool 的并发若不设限，保护的是**这台机器的内存与端口**（`gates/diag/gate_lock.py:4` 原文「真正的瓶颈是内存：
一趟 17 门要 15–30 个无头 Edge」）。同一个词，两个被保护对象 —— 移植的是**形状与判据**，不是它的理由。

## 判据（8 条，逐条可执行）

1. `tools/pool/registry.py` 的 `reserve()` 加一个**纯加法**关键字参数 `account: str = ""`，`entry` 里加一行
   `"account": str(account),`。既有 12 个键的名字与语义**一个都不许改**；`tests/test_pool_lease.py:138`
   钉着 `("owner", "at", "ttl_seconds")`，那三条必须照旧。
2. 新增纯函数 `guards.lane_guard(account: object, reservations: Iterable[dict], *, limit: int, queue: int = 0,
   now: float | None = None) -> list[str]`：
   - `limit <= 0` ⇒ **永远返回 `[]`**（照抄 magpie `concurrency.go:82` 的 `limit <= 0` 分支 —— `0` 是「关掉闸」，
     **不是**「一个都不许」）；
   - `account` 为空 / 不是字符串 ⇒ 返回 `[]`（没点名账号 = 没闸，与 magpie「无 key 的请求永不过问」同方向，
     见 `internal/gwbudget/gwbudget.go:101-124`）；
   - 数的是入参里 `res.get("account") == account` 的条数，**`>= limit`**（不是 `>`）⇒ 回 1 条问题；
     否则 `[]`。入参必须是调用方已过 `registry.is_dead()` 的 `live`（死租约不许算在途）。
   - 文案逐字含三样：账号 id、`同时在跑 N 张`、`上限 M`。
3. `queue` 的语义必须**在 docstring 里说实话**：magpie 的 `QueueLimit` 是真队列，pool **没有「在等」这个状态**
   （派活是同步的）⇒ `queue` 在本仓只能表达「**允许多少个派活进程在闸门口等**」，`queue == 0` 就是「不排队、直接拒」。
   本卡**不实现等待**（`wait` 留给下一张卡），`queue > 0` 时 `lane_guard` 的判据与 `queue == 0` 相同（都按
   `limit` 判），只在文案里多一句「队列上限 q 张」。**不许**把「等待」写成 `while True: sleep`。
4. 新增 `tools/pool/lanes.py`（数据面，~120 行）：`LANES_REL = "tools/pool/lanes.toml"`、
   `MAX_LIMIT = 1000` / `MAX_QUEUE_LIMIT = 10000` / `MAX_QUEUE_WAIT = 3600`（逐字照抄 `concurrency.go:41-47`）、
   `class LanesError(ValueError)`、`@dataclass(frozen=True, slots=True) class Lane`（`limit=0` / `queue=0` / `wait=0`）、
   `load_lanes(path=None) -> dict[str, Lane]`、`lane_for(account, lanes) -> Lane`。
   - 文件**不存在** ⇒ `{}`（= 一条闸都没开，与今天行为逐字相同）；
   - 文件坏 / 值越界（`limit > MAX_LIMIT` 等）/ 某段不是整数 ⇒ `LanesError`，**绝不静默当 0**
     （0 等于关掉闸 = 悄悄松开判据）。
   - 本模块**不判活、不写文件、不起进程、不联网**。
5. 新增 `tools/pool/lanes.toml`（随仓走、由人改），`[default]` 段 + `[accounts."<稳定 id>"]` 段；
   键是 `accounts.toml` 的**稳定 id**（`tools/pool_accounts.py:315-334` 的 `list_rows` 排序键是 `(platform, id)`），
   **不是 email / user**。文件里必须有一行注释说「0 = 不限」。
6. `reserve()` 的 `problems` 列表里**新增一条**（位置在 `domain_guard` 之后、`lock_guard` 之前）：
   ```python
   *guards.lane_guard(account, live, limit=lane.limit, queue=lane.queue, now=stamp),
   ```
   `lane` 由 `lanes.lane_for(account, lanes.load_lanes())` 得来；`load_lanes()` 抛 `LanesError` ⇒ 让它冒到
   `reserve()` 外面（**不许** catch 之后当空）。`reserve()` 既有四条守卫的**顺序与文案**不许变。
7. `guards.py` 文件头 `:1-40` 逐字「**不写文件、不 print、不起进程**」⇒ `lane_guard` 不许 `open(` / `Path(` /
   `print(` / `subprocess` / `os.environ`。`lanes.toml` 的读取只能在 `pool.lanes`，调用方把 `limit/queue`
   作为**整数**传进来。
8. 反向钉子必须有判别力：把 `reserve()` 里的 `live` 换成 `rows`（不清死租约）⇒
   `test_reverse_lane_guard_counts_dead_leases` 必须变红（否则「死租约也算在途」会静默把号锁死）。
   做法：造 3 条 `ttl_seconds=1`、`now` 推后 100 秒的租约 + `limit=2`，断言**不**报「并发已满」。
