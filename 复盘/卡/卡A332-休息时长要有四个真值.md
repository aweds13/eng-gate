## 要解决的问题

「429 之后该歇多久」现在没有真值，只有两个数：`wait_seconds()` 拿 `reset_at` 算剩余，
算不出就拿调用方的 `DEFAULT_QUOTA_WAIT = 300`（`tools/wb_dispatch.py:218`）睡死 5 分钟。
于是「欠费」和「每分钟限流」和「月度额度用光」拿到的休息时长一模一样 —— 前者该歇 30 分钟、
后者该歇到续期时间、再后面那个该歇 8 天，全都退化成 5 分钟瞎猜。

`record()` 只收一个 `kind` 字符串，没有把「为什么失败」落下来（HEAD `:161-186`）：

```python
def record(*, card: str, model: str, pool: str, kind: str,
           reset_raw: str, source_log: str | None = None, source_line: int | None = None,
           root: Path = ROOT) -> dict[str, Any]:
    reset_dt = parse_reset(reset_raw)
    reset_at = reset_dt.isoformat() if reset_dt is not None else None
    rec: dict[str, Any] = {
        "card": card,
        "model": model,
        "pool": pool,
        "kind": kind,
        ...
```

常量块里也只有等待口径，没有任何 `REST` 常量（HEAD `:61-66`）：

```python
WAIT_MIN_S = 60          # magpie quotaWaitMin = time.Minute
WAIT_MAX_S = 600         # magpie quotaWaitMax = 10 * time.Minute
WAIT_MARGIN_S = 30       # magpie quotaWaitMargin = 30 * time.Second
REFRESH_GAP_S = 30       # magpie quotaRefreshGap = 30 * time.Second
```

## 判据（9 条）

1. **credit 是 30 分钟，不是 15 分钟**：`classify()` 判出 `"credit"` ⇒
   `reason.seconds == CREDIT_REST_S == 1800`、`by == "credit"`
   （`routing.go:1094-1095` `d, r.By, guessed = creditRest, "credit", true`；
   `quotaRest` 的 900 **不许**串到这里）。
2. **quota 有续期时间 ⇒ 按续期算**：`why == "quota"` 且 `reset_at` 能解析 ⇒
   `by == "resets"`、`seconds == max(0, reset_at - now)`（`:1126-1127`）。
3. **quota 没有续期时间 ⇒ 15 分钟且自认是猜的**：`why == "quota"` 且 `reset_at` 为 `None`/解析不出 ⇒
   `seconds == QUOTA_REST_S == 900`、`by == "quota"`、`capped == True`
   （`:1143` `guessed = r.By == "quota" && own <= 0`）。
4. **上限按窗口换**：quota 走 `resets` 时，命中月窗口（`full_until` 未过期）上限换
   `LONGEST_MONTHLY_S = 35 * 24 * 3600`，否则 `LONGEST_QUOTA_S = 8 * 24 * 3600`
   （`:1145-1148`）；`reset_at - now < 0` ⇒ `seconds == 0` / `by == "resets"` / `capped == False`，
   **不许**当成「立刻可用」。
5. **rate 是指数退避**：`why == "rate"` ⇒ `seconds == min(COOLDOWN_S << min(n-1, 10), cap)`；
   `n=1..7` 依次 `60, 120, 240, 480, 960, 1800, 1800`；`failures > 1` ⇒ `by == "backoff"`，
   否则 `"cooldown"`（`:1436-1439`）。供应商 `retry_after`（这里用 `reset_at` 喂）更长且
   `>= seconds` 时才采用，且它**先被** `LONGEST_WAIT_S = 3600` 压过（`:1592-1619`）⇒
   `by == "retry-after"`。
6. **`rest-cap off` 只挡「无因失败」**：`why == "other"` 且 `rest_cap_s == REST_CAP_OFF` ⇒
   `seconds == 0` / `by == "off"`（`:1182` 守卫）；但 `status in (401, 403)` **必须挡在 off 之外**
   （守卫里的 `status != 401 && status != 403`），且 `quota` / `credit` / `rate` 三类
   **完全不受 off 影响**（quota 仍 900、rate 仍退避）。
7. **other 其余是 10 分钟上限的退避**：`seconds == min(COOLDOWN_S << min(n-1, 10), cap)`、
   `cap = rest_cap_s or LONGEST_RETRY_S`、`by == "backoff"`（`:1221`）；`auth` 同理
   （magpie 的 `restAfterMarked` switch 没有 `case failAuth`，落到 default）。
8. **不认就喊，不许静默**：`why` 不在五个枚举
   （`"credit" / "quota" / "rate" / "other" / "auth"`）里 ⇒
   `raise ValueError(f"不认的失败分类：{why!r}")`；`rest_cap_s < -1` 或
   `> MAX_QUOTA_REST_MIN * 60`（= 8 天）⇒ `raise ValueError`，**不 clamp**。
9. **`status()` 只加两个键、且仍然零网络零等待**：四态名字与 `why` 文案**一个字都不许改**，
   只多 `rest_until` / `rest_by`（`未记录` 那支两者都 `None`）；`inspect.getsource(status)`
   里不许出现 `urllib` / `requests` / `httpx` / `socket` / `urlopen` / `http.client` /
   `time.sleep`（反向钉子 `test_status_has_no_network_or_sleep` 守着）。
