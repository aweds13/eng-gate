# 卡 E35 —— 云机确定性：让「换一台机器跑门禁」从 37 红变成 0 红

> 台账号 T-AG489 ｜ 树：`.wt/E35` ｜ 分区：E（CI 子系统）
> 依据：2026-10-25 受控 A/B（同 commit `d37cb06`、依赖齐、各 4 worker）

## 现在疼在哪（都是实测）

同 commit、同 worker 数、依赖都装齐，两侧读数：

- 本机：`pytest 403.46 s / 3079 passed / 0 failed`
- 云机（`gc.e-c1m2.xlarge`，4 vCPU / 15.5 GiB，Windows Server 2022）：`pytest 684.27 s /
  3008 passed / 37 failed / 34 skipped`

1. **37 条红分两类，都不是「云机不行」：
   - **A 类（约 22 条，装配能解决）**：`pool.projects.ProjectsError: 找不到项目索引（从 C:\eng
     及上层都没有 infra/pool/projects.toml，用 TF_PROJECTS_TOML 指定）` ⇒ `test_pool_projects` 2 /
     `test_pool_registry` 2 / `test_pool_guards` 2 / `test_pool_lib` 3 / `test_pool_task` 1 /
     `test_contract_audit` 1；索引真身在仓外 `D:/repo/infra/pool/projects.toml`。
     模型库文件读不到 ⇒ `test_model_registry` 3。`ruff` 云机 0.17.2 vs 本机 0.16.6
     （`I001` 结果不同）⇒ `test_wb_land` 4 条 `test_preflight_*`。内存阈值按机器断言 ⇒ `test_mem_guard` 2。
   - **B 类（约 15 条，得改测试或显式声明）**：`test_gates_reuse_line` 10 条
     （`assert 'e3b0c44298fc1c14' != 'e3b0c44298fc1c14'`，`e3b0c442…` = sha256("")，即
     `rg.input_hash(('src/**', …))` 在云机扫不到文件；云机 `C:\eng` 下确实有 `src`，**根因未定位**）、
     `test_run_gates_timeout` 4 条（进程树击杀语义）、`test_concurrency` 1 条（线程本地性）。
2. **装配脚本根本不在库里**：`gates/diag/cloud_bootstrap.ps1` 被 `.gitignore:76 gates/diag/*` 忽略，
   `git ls-files` 为空 —— 也就是说「云机怎么装」这件事只存在我这台机器的磁盘上。
   而且它装的是 `fastapi uvicorn pydantic pytest pytest-cov pytest-xdist mypy ruff`，
   **没有 `httpx` / `fsrs` / `psutil`**，`ruff` 不钉版本。
3. **同步脚本留残留**：`gates/diag/cloud_run_gate.sh` 里是 `git clean -fdq`（不删被忽略文件），
   于是云机上趟的 `gates/last.json`（`rev=e3b19de`、`branch=card/E14`）会被下一趟读到，
   自指钉子（`test_false_success_pins` / `test_gates_reuse_line`）必红。我今天手工换成
   `git clean -xfdq` 才干净重跑。
4. **一次 ssh 断了整趟白跑**：`Start-Process` 起后台门禁会被 ssh 会话退出掐掉（踩过），
   也没有断点续跑、没有完成通知。

## 要做成什么样

1. **装配入库**：把装配脚本搬到 `scripts/cloud/bootstrap.ps1`，把同步脚本搬到
   `scripts/cloud/run_gate.sh`（都入库、可 review），`gates/diag/` 里只留「这台机的路径配置」（gitignored）。装配清单补齐
   `httpx` / `fsrs` / `psutil` **并钉版本**（与本机 `pip freeze` 一致的 pin），`ruff` 钉到
   与本机同版本（否则 `I001` 类判据两个环境给两个答案）。
2. **清残留**：`cloud_run_gate.sh` 的 `git clean -fdq` 改 `-xfdq`，并在跑之前断言
   `gates/last.json` 不存在（存在就报错，不静默沿用）。
3. **仓外配置显式注入**：`TF_PROJECTS_TOML` / `TF_MODELS_TOML` 之类由脚本参数传入，
   缺了就**先报错再跑**（fail fast），不许「跑一半发现没配」。为 CI 造一份最小 fixture 亦可，
   但必须在申报里写明「这份 fixture 与真索引的差异」。
4. **B 类 15 条逐条处置**：要么改成环境无关（首选），要么在测试里显式声明
   `known-env-red: <原因>` 且**点名列出**（`pytest.ini` 的 marker 或仓内 `docs/subsystems/ci/`
   清单），不许静默 `skip`。
5. **两趟连续跑读数一致**（确定性判据）：连续两次 `exit 0`，用例数一致。

## 判据

1. **云机全量门禁 `exit 0`**（不是「只剩已知红」），连续两趟，`pytest` 用例数相同。
2. A 类 22 条在云机**真绿**（不是 skip）：申报里给出云机 `pytest -k` 对应子集的原始输出。
3. B 类 15 条：要么绿，要么在 `docs/subsystems/ci/云门禁机.md` 里逐条列出「为什么这台机器上
   判不了」并附判据路径；`git grep known-env-red` 能查到声明处。
4. `scripts/cloud/bootstrap.ps1` **与** `scripts/cloud/run_gate.sh` 都在 `git ls-files` 里；
   `gates/diag/` 下不再有这两个脚本（机器本地配置除外）。
5. `pytest tests/test_cloud_sync.py -q -o addopts=`，至少 6 条钉子：`-xfdq` 在脚本里 +
   跑前断言 `last.json` 不存在 + 依赖清单含三个包且带版本 + 缺 `TF_PROJECTS_TOML` 时 fail fast +
   装配脚本路径在库内 + `known-env-red` 名单与测试实际跳过集合一致（防悄悄扩大）。
6. **反向验证**：把 `-xfdq` 改回 `-fdq` ⇒ 残留断言那条钉子必须红；把 `ruff` 版本钉去掉 ⇒
   版本一致那条必须红。红色输出进申报。

## 不许做

- 不许把「云机红」解释成「云不行」（用户已判过这句话错，见 2026-10-25 对话）。
- 不许用 `skip` 掩盖 A 类：能配就配，配不上要写清为什么。
- 不许把装配脚本继续留在 `gates/diag/`（那里 gitignored，等于没有）。
- 不许为了绿而放宽判据（`--cov-fail-under`、`known-env-red` 名单只许收缩不许扩大）。
- 本卡不负责「把门禁搬到云机当日常」（那是 E34 池化的事），只负责「云机上的判据是确定的」。

## 证据

- 云机连续两趟全量门禁的 `exit` 与 `pytest` 汇总（原始输出 + `last.json`）。
- A 类子集在云机真绿的 `pytest -k` 输出。
- `git ls-files scripts/cloud/` 与 `.gitignore` 相关行的原文。
- 两条反向验证的红色原始输出。
