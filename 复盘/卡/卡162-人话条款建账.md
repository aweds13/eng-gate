## 来路（台账里 5 条同族的缝：**只有一句人话**）

★ 用户最恨的一类。实读：六条硬规矩里只有「门禁落盘 / 审计不过不许提交 / 文档同提交」三条有机器判据；
其余**全是人话**，于是「**没人知道它已经不可能发生，还是根本没人管**」。

## 要做什么（★ 不是「给每条人话写一个检查」，而是**建账**）

1. **新建 `复盘/条款台账.toml`**（照 `复盘/不变量台账.toml` 的形状）：
   每条人话条款一行，字段：`id`（`CL-nn`）· `clause`（原话/出处 §）· `judge`（判据落点 `路径::符号`）·
   `nail`（反例钉子 `tests/…::用例名`）· `status`（`covered` / `partial` / **`unjudgeable`**）·
   `note`（**为什么机器判不了** —— 这一栏是 `unjudgeable` 的必备项，空的要红）。
   ★ **`unjudgeable` 是诚实态，不是失败**；但它**必须带理由**，否则就是"用一句人话糊过去"。
2. **核查器**：`tools/wb_invariants.py` 加 `--clauses`（或让它同时核这份台账）—— 只核**指针存在性**，
   并且**必须咬**「`status = unjudgeable` 但 `note` 为空」这一种（★ 这是本卡最关键的一条判据）。
3. **能变成判据的，就地变**（本卡只挑两条最该变的）：
   - **INV-71 悬停**：在 `tools/style_audit.py` 加一条 `check_hover_motion` —— 扫 CSS 的 `:hover` 规则，
     只许出现 `background` / `border*` / `color` / `opacity` 这类**不改变几何**的属性；
     出现 `transform` / `translate` / `margin` / `padding` / `height` / `flex` / `display` 等 ⇒ 红。配反例钉子。
   - **INV-70 视觉改动人工过目**：在协议 §四 的停止条件里**加一条**，并在 `复盘/外包-卡表与规矩.md`
     写清「哪些改动必须交用户过目」；**同时**在卡规格模板里加一行「本卡是否属视觉/布局类」（选"是" ⇒
     报告里必须写明"已交用户过目/待过目"）。★ 这条**判不了**的部分（好不好看）**如实标 `unjudgeable` + 理由**。
4. **INV-74 / INV-75**：先**如实标 `unjudgeable` 或 `partial`**（写清为什么：gaps 是自由文本、
   状态句是自然语言），**不许**为了"变绿"去编一个只能查子串的假判据。

## 判据与钉子

- 台账核查器：`unjudgeable` 无 `note` ⇒ **红**；`covered` 无 `nail` ⇒ **红**；指针指向不存在的路径/用例名 ⇒ **红**。
- `check_hover_motion`：合成一段带 `transform` 的 `:hover` ⇒ **红**；真实样式表 ⇒ 绿（若真实样式表本来就有 ⇒ **如实报**，别改样式去迁就判据）。
- ★ 每条判据配反例钉子，**先红后绿**。
