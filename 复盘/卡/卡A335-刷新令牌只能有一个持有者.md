## 要解决的问题

**一、刷新这件事在 pool 里根本不存在 —— 不是坏的，是没有。** 全仓两条串都零命中（**已核**）。
`renew` 这个词在 `tools/` 下只出现在门禁锁续租，与 token 无关：

```
tools/pool/landing.py:637: def _renewer_loop(lock_label, wt, env, stop) -> None:
```

⇒ 没有锁、没有「到期前 N 分钟才刷」、没有吊销判定、没有「标记存 hash」的落盘口径。

**二、401 与 403 被说成同一句话，而这正是要分开的那件事。** 原文
（`tools/pool_accounts.py:477-482`，**已核**）：

```python
    if status in (401, 403):
        return {
            **base,
            "kind": "failed",
            "detail": f"HTTP {status}：凭据无效或过期（刷新后改账本的 locator，别改这里）",
        }
```

magpie 的口径是：**只有 400 / 401 才算「这个 refresh token 死了」**，403 / 5xx / 网络错一律只是
「这一次没成」（`internal/provider/account.go:867-872`）。pool 现在把 403 和 401 混成一个结论，
于是一次权限不足会被当成凭据过期 —— 而「当成过期」的下一步就是**去花掉一个本来还活着的 refresh token**。

**三、没有锁，就没有「只能用一次」这件事。** 供应商的 refresh token 是**轮换**的：第二次用旧的去刷，
要么失败、要么把第一次刚拿到的新 token 作废。`tools/pool_accounts.py` 现在既没有进程内互斥、
也没有跨进程锁（`threading` / `contextlib` / `O_EXCL` 三个词全零命中，**已核**），
两个工人同时对同一个号动手时没有任何东西拦得住。

**四、本仓已经有一份写对的「按时间判陈旧」实现，必须照抄。** `tools/pool/task.py`

```python
@contextlib.contextmanager
def spin_lock(target: Path, timeout: float | None = None):
```

（`tools/pool/task.py:242-291`）的 docstring 逐字：「照抄 `gates/diag/gate_lock.py` 的口径：
**按时间判陈旧，绝不按 pid 判活**（pid 会重用、跨机不可信；`acquire` 与真正的写往往不是同一个进程）」
与「★ `yield` **必须在取到锁之后、循环之外**」。要点：`os.open(lock, os.O_CREAT | os.O_EXCL | os.O_WRONLY)`
（`:263`）→ `except FileExistsError` 后用 `_lock_age()`（`:220`，**优先锁内 ISO 时间 `at`，退化 mtime**）
→ `age > ttl` 才接管（`:264-`）→ 超时抛 `BatchError` → 循环尾 `time.sleep(0.05)`；
payload 是 `{"owner": whoami(), "pid": os.getpid(), "task": target.stem, "at": now_iso()}`（`:283`）。

**五、pid 判活在本仓是硬禁令，不是建议。** `tools/pool/registry.py:18-30` 逐字：
「★ 本模块**不登记 pid**，判活只用「租约 + 日志」。」「★★ **绝对不许用 `os.kill(pid, 0)` 探活**：
Windows 上 CPython 的 `os.kill` 走 `TerminateProcess` —— 那不是探活，那是**把真在跑的进程杀掉**。」

⇒ 本卡是**新增能力**，不是修 bug。最有价值的是先把第二、三、四条落成**纯判定函数**（可测、无网络），
再把锁接上去。

## 判据（8 条）

1. **只差 5 分钟才刷**：`tools/pool_accounts.py::needs_renew(access_token: str | None, *, force: bool = False,
   now: float | None = None, margin_s: int = RENEW_MARGIN_S) -> bool` —— `force` 恒 `True`；
   `jwt_exp()` 读不出 `exp`（`None` / 0）恒 `True`；否则 `(exp - now) <= margin_s` 为 `True`。
   常量 `RENEW_MARGIN_S: int = 5 * 60`（照 `logins_on.go:275`）、`SIWC_MARGIN_S: int = 3 * 60`
   （照 `chatgpt_api.go:68`）、`LOCK_WAIT_S: float = 10.0`（照 `filelock.go:20`）。
   `now + 299` ⇒ `True`、`now + 301` ⇒ `False`。
2. **读不出来的 JWT 一律当该刷，且不许抛**：`jwt_exp(token: str) -> float | None` —— 非三段式、
   base64 解不开、没有 `exp`、`exp` 不是数，全部回 `None`（不抛异常、不打印 token 片段）；
   `needs_renew()` 见到 `None` 回 `True`（宁可多刷一次，也别拿着过期 token 去撞供应商）。
3. **只有 400 / 401 算吊销**：`refresh_failed(status: int, agent: str, msg: str) -> Exception` ——
   `status in (400, 401)` 返回 `RefreshRefused(msg)`（`class RefreshRefused(Exception)`），
   其余（403、5xx、0/超时/连接错）返回普通 `RuntimeError(f"{agent} token refresh failed (HTTP {status})")`。
   判据标识：**只有** `RefreshRefused` 能让调用方去写吊销标记。
4. **没拿到答复就不许打标记**：吊销落盘走 `saved_refresh_failed(ledger_path: Path, *, account_id: str,
   agent: str, exc: Exception, now: datetime | None = None) -> bool` —— 只有 `isinstance(exc, RefreshRefused)`
   才写 `revoked` 标记并回 `True`；网络错 / 403 / 5xx 回 `False` 且**账本一个字节都不变**
   （照 `logins_on.go:318` 「A refresh that never got an answer marks nothing.」）。
5. **标记只存 hash，永不存明文**：`revoked_mark(reason: str, *, salt: str = "") -> str` 回
   `"revoked " + hashlib.sha256((salt + reason).encode()).hexdigest()[:16]`（前 8 字节 hex，
   照 `quota_last.go:52-55 keyTag()` 只存 sha256 前 8 字节）。写进账本的是这个串；
   **refresh token / access token 的明文不许出现在账本、日志、钉子树、任何 stderr 行里**。
   既有 `mask()`（`tools/pool_accounts.py:285`，`SECRET_RE.sub("***", value)`）只管 `sk-/ak-/ghp-/xoxb-`
   前缀，**管不到 JWT**，所以本卡另给 `mask_token(token: str) -> str`（三段式只留 `header.payload` 前 6 字符 +
   `…`，非三段式一律 `"<token>"`），日志出口一律走它。
6. **单持有者：进程内先互斥，再跨进程，拿到双锁后才重读账本**：
   `@contextlib.contextmanager def renew_lock(account_id: str, *, root: Path | None = None,
   wait_s: float = LOCK_WAIT_S) -> Iterator[bool]` —— 先进程内 `threading.Lock`（按账本路径取，
   模块级 `dict[str, threading.Lock]` + 一把保护锁），再跨进程 `os.open(<ledger>.renew.lock,
   O_CREAT | O_EXCL | O_WRONLY)`；锁内 JSON payload 照 `tools/pool/task.py:283` 的形状
   （`{"owner", "pid", "task", "at"}`，`at` 是 ISO），陈旧判定照 `_lock_age()`（`:220`）**只按时间**，
   TTL 用 `RENEW_LOCK_TTL_S: float = 120.0`。**`yield` 必须在取到锁之后、循环之外**（`task.py` docstring 原话）。
7. **拿不到锁是 fail-open，不是失败**：`wait_s` 内没拿到 ⇒ **不抛**，往 stderr 说一行
   「另一个持有者占了 {wait_s} 秒，无锁继续」，然后 `yield False`；拿到 ⇒ `yield True`。
   照 `filelock.go:57` 逐字口径「another magpie held it for %v; going on without it」。
   **关键**：`yield` 的 `held` 值必须让调用方能在「无锁」时做更保守的事（例如刷新前重读一次账本、
   或直接放弃本次刷新），而不是假装拿到过锁。锁整体**只锁一个账本文件**（与 magpie 的 `loginsPath()`
   同构）：按号加锁会让两个号并发刷新时互相覆盖 `save_ledger()` 的原子写。
8. **反向钉子**：把 `renew_lock()` 的超时分支从 `yield False` 改成 `raise TimeoutError` ⇒
   `tests/test_renew_lock.py::test_renew_lock_timeout_is_fail_open` 必须**变红**；
   把 `needs_renew()` 的 `exp is None` 分支改成 `False` ⇒
   `test_needs_renew_unreadable_jwt_is_true` 必须**变红**；
   把 `refresh_failed()` 的 403 也归进 `RefreshRefused` ⇒
   `test_refresh_failed_only_400_401_are_refused` 必须**变红**。三条都要在验收里手工跑一遍。

## 不许做

- 不许用 `os.kill(pid, 0)` 或任何形式的 pid 判活做陈旧判定 —— `tools/pool/registry.py:18-30` 是硬禁令
  （Windows 上 CPython 的 `os.kill` 走 `TerminateProcess`，那不是探活，是把真在跑的进程杀掉）；
  照 `tools/pool/task.py:242-291` 的 `spin_lock` / `_lock_age`（`:220`）**按时间判陈旧**。
- 不许在拿不到锁时抛错 —— `filelock.go:57` 的口径是打一行然后照样往下走（fail-open）；
  超时抛错会让一次可用的刷新变成一次硬失败。
- 不许把 403 / 5xx / 网络错当吊销（`internal/provider/account.go:867-872` 只认 400 / 401）；
  也不许在「没拿到答复」时打标记（`logins_on.go:318` 原话「A refresh that never got an answer marks nothing.」）。
- 不许把 refresh token / access token 的明文写进账本、日志、钉子树或 stderr —— 一律走 `mask_token()`；
  吊销标记只存 sha256 前 8 字节 hex。
- 不许在没有真实刷新路径时伪造「刷新成功」日志行（本卡第一步只有判定函数与锁，
