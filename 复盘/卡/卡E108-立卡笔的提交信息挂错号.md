# 卡 E108 · 立卡那一笔的 trailer 挂错号：`Task:` 写新台账号、`Refs:` 与 `Gates:` 都没有

> 台账号 `T-AG617`｜分区 E（门禁与可信度）｜树 `.wt/E108`｜层 判据层｜基准 `c97d0d11`｜
> 依据：用户 m92988「把 pool 的使用打磨好，不计代价与 token」；m93503「之前的任务记得做完」。

## 要解决的问题（逐条实测，不是推测）

### 问题 1 · 立卡笔把**新台账号**写进 `Task:`，而它在落地前还不在台账条目里

`tools/pool/ledger.py:556-557` 原文：

```python
msg = (f"chore(ledger): 立卡 {card_id}（{task}）\n\n"
       f"Task: {task}\nLedger: 新增 {task}（ENGINEERING/pending）\n")
```

`task` 是**新卡**的台账号（例：`T-AG616`）。审计 ⑧ 判「`Task:` 必须恰好一个**已登记**台账编号」，
而 `[entries]` 里只有落地后的号 —— 新号在落地前根本不存在。实测（E107 立卡笔 `6ecb5e09`）：

```text
[FAIL] 6ecb5e09 的 Task: 不是「恰好一个台账编号」：'T-AG616'（chore(ledger): 立卡 E107（T-AG616））
       —— 多余编号请写进 Refs:
```

这一笔是 `tools/wb_card.py add --commit` 生成的，逼得当场 `git reset --soft` + 手写消息 squash 成
`4d4de3ad` 才过 preflight 第 9 条。判据真源：`scripts/audit_progress.py:447` `parse_task_trailers()`
与 `:832-834`（`ids` = `docs/traceability.toml` 的 `[entries]` 键集合）。

### 问题 2 · 没有 `Gates:` 行

同一函数拼的 msg 里没有 `Gates:`。`scripts/audit_progress.py:794-795`：单条模式（`--rev` / 不带 `--all`）
见不到 `Gates:` trailer 就 FAIL「提交没有 `Gates:` trailer（没有门禁结果）」。

### 问题 3 · 没有 `Refs:` 行 —— 读 log 的人看不出这一笔为哪张卡而立

历史 34 笔 `chore(ledger): 立卡` 里 **33 笔**是同一体例（`Task: T-AG440` + `Refs: T-AG<新号>` +
`Gates: 沿用 <sha> 那趟全量绿 …`），只有 `_commit_backlog` 自动生成的那一笔不是 —— 函数自己另立了一套。

### 问题 4 · 这个洞只有「立卡笔」会踩，而它每次都踩

`_commit_backlog` 是 `add_card(..., commit=True)` 唯一的提交路径（`tools/pool/ledger.py:469`），
`tools/wb_card.py add --commit` 走它。卡规格的「直做」区明确要求每张卡都用它立卡 ⇒ 每个新窗口都要手工
squash 一次。

## 判据

### 判据 1 · `Task:` 必须是**账务条目**，新台账号写进 `Refs:`

`tools/pool/ledger.py` 组件级常量 `BOOKKEEPING_TASK = "T-AG440"`（docstring 写明：它是 `[entries]` 里
那条「dsmate 文档底座 + 分区 C/D 登记 + 历史 `Task:` 补记」的**账务条目**，不是卡）；msg 改成：

```text
chore(ledger): 立卡 {card_id}（{task}）

Task: T-AG440
Refs: {task}
Ledger: 新增 {task}（ENGINEERING/pending）
```

**钉子**（`tests/test_ledger_queue_counts.py`）：
- `test_the_ledger_commit_puts_the_bookkeeping_id_in_task`：`Task:` 行恰好是 `T-AG440`，
  且 `Task: T-AG900` 一个字都不出现（`T-AG900` 是夹具里那张新卡的台账号）。
- `test_the_bookkeeping_id_is_a_real_ledger_entry`：读**真仓** `docs/traceability.toml`（`tomllib`）⇒
  `T-AG440 in entries` 且 `status == "done"`（常量不是编的，也不许以后被改成一个不存在的号）。
- `test_the_ledger_commit_passes_the_audit_trailer_judge`：**复用真判据** —— `sys.path` 进 `scripts/`，
  把这一笔的 body 喂 `audit_progress.parse_task_trailers(record, ids)`（`ids` 只含 `T-AG440`，**不含**
  `T-AG900`）⇒ 回 `[]`。判据只有一份，不在这里另抄一遍正则。

### 判据 2 · `Refs:` 点名新台账号（恰好一行）

**钉子**：`test_the_ledger_commit_names_the_new_task_in_refs`：body 里 `Refs: T-AG900` 出现**恰好一次**，
且 `Refs:` 行只有一行（读 `git log -1 --format=%B` 逐行数）。

### 判据 3 · `Gates:` 必须如实（三态，不许一律写「绿」）

读 `base/gates/last.json`（`tools/pool/ledger.py` 里加常量 `GATES_REL = "gates/last.json"`）：

| 现场 | `Gates:` 行 |
|---|---|
| `ok is True` | `Gates: 沿用 <HEAD 短 sha> 那趟全量绿（gates/last.json ok=True at=<at>）；只立卡，不改源码` |
| 有文件但 `ok` 不是 `True` | `Gates: 没有可用门禁产物：gates/last.json ok=<值> at=<at>；只立卡，但这一笔**不**声称绿` |
| 文件不在 / 读不了 / 不是对象 | `Gates: 没有门禁产物（gates/last.json 不存在）；只立卡，不声称绿` |

**钉子**：`test_the_ledger_commit_reuses_the_last_gate_honestly`（三态参数化，夹具里写 `gates/last.json`）、
`test_the_gates_line_never_claims_green_when_the_gate_is_red`（`ok=False` ⇒ 含 `不`、不含 `全量绿`）。

### 判据 4 · 反向变异 ≥4（真改真跑真还原）

`gates/diag/_rev_E108.py`（新建，不入库）：
- **M-A** `Task: {task}` 写回去 ⇒ 咬判据 1 的三条钉子（尤其 `..._passes_the_audit_trailer_judge`）；
- **M-B** 删掉 `Refs:` 行 ⇒ 咬判据 2；
- **M-C** `Gates:` 行恒写「全量绿」（不看 `last.json`）⇒ 咬判据 3 的红灯那一半；
- **M-D** 整个 `Gates:` 行删掉 ⇒ 咬判据 3；
- **C1** 只改 docstring 一个字 ⇒ 应当安静（rc=0）。

每条记改前/改后 sha256，还原后必须与基线逐字节相同。

### 判据 5 · 既有钉子一条都不许**削弱**（唯一一处必须动，理由写在下面）

`tests/test_ledger_queue_counts.py` 现有 12 条钉子全部保留。**唯一必须动的一行**是
`test_the_commit_message_records_the_extra_doc`（:291）里的 `assert body.count("Task: T-AG900") == 1`：
判据 1 就是要让 `T-AG900` 不再出现在 `Task:` 行。改法是 `body.count("Refs: T-AG900") == 1` —— 这条钉子的
意图（「这一笔点名了新台账号」）一个字不变，同一条测试里的 `README_REL in body` 也不动。
