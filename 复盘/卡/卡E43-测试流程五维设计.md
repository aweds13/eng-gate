# 卡 E43 —— 测试流程五维设计：档位 / 域 / 选测 / 夜间 / 异机（T-AG495）

- 层：文档层
- 树：`.wt/E43`
- 分区：E
- 风险：mid（纯文档，但它决定「谁跑什么、什么时候跑、跑在哪」，写错会让人误判"绿"）

## 1. 疼在哪

1. **同一个词「跑门禁」今天至少有五种含义**：`--fast`（8 门 ~12 s）、
   `--quick`（~90 s）、全量 19 门（5–7 分钟）、A327 按域 `--profiles auto`
   （`tools/` 改动 ⇒ 8 门）、E36 台账选测（子集）。谁在什么时候该用哪一档，
   没有任何一处写全；结果是我今天多次「卡树跑全量 → 主树又前进 → 重 realign
   → 再跑一趟」（E10 跑了五趟、E39 两趟）。
2. **「绿」没有分层**：门禁 `last.json` 只给一个 `ok`。落地要的是
   「`rev == 父提交` + 全量 + 封存指纹一致」；而卡内自测要的是「我改的文件
   相关的测试绿」。两者混在一个 `ok` 里，就会用自测的绿去承诺落地的绿。
3. **谁跑在哪没有口径**：本机跑一次全量 = 工人少 0.6–1.0 GB 内存、两趟并行
   `pytest 341→506 s`；云机跑 = 慢 1.7× 但不占本机。今天全凭我临场判断。
4. **红门之后没有「只重跑那一道」的常规做法**：每次红都重跑 19 门（5–7 分钟
   × 若干次）。今天 E29/E39/E10 的重跑里有大量时间花在「别的 18 门本来就是绿的」。

## 2. 要做成什么样：一份文档 + 一棵决策树

新增 `docs/subsystems/ci/测试流程.md`（与 `云门禁机.md`、`pool/` 五篇同构），
必须含下面五维与三张表。

### 2.1 五维

| 维 | 取值 | 谁决定 | 落点 |
|---|---|---|---|
| 档位 | `--fast` / `--quick` / 全量 | 改动面 | `scripts/run_gates.py` 现成参数 |
| 域 | lang / audit / product（A327） | 改动路径 | `gates/defs/domains.py::required_profiles()` |
| 选测 | 台账驱动子集（E36） | 台账 `test:` 指针 | `tools/pytest_select.py` |
| 夜间 | 每天全量 + 红则通知 | 无人（cron/计划任务） | `tools/wb_nightly.py` |
| 异机 | 云机两趟全绿 | 里程碑前 | `scripts/cloud/run_gate.sh` / E42 门禁池 |

**每维都要写清「不满足时怎么办」**（fail closed 还是 fail open）：
选测不过三道闸 ⇒ 回全量；云机不可达 ⇒ 退 2 不回落；夜间没跑 ⇒ 落地前必须
补一趟全量（不能拿「昨天的绿」当今天的）。

### 2.2 决策树（文档里就写成这样，五步）

```
改了什么？
├─ 只改 docs/、skills/          → --fast（8 门）+ 审计；不必全量
├─ 只改 tools/、scripts/        → --profiles auto（lang+audit）+ 相关 pytest 子集
├─ 改判据本体（gates/**、run_gates.py、wb_land.py、pool/landing.py、pyproject.toml）
│                                → 全量，且必须在**云机**跑（E42）
└─ 要落地一张卡                 → 全量 19 门 + --seal + rev==父提交（云机）
```

### 2.3 三张表

1. **19 道门清单表**：门名 / 判什么 / 常态耗时 / 能不能复用（`gates/reuse.json`
   只有 5 道真机门可复用、`pytest` 永不复用）/ 谁能跑（本机/云机都行，或只本机）。
   数据从今天的 `gates/last.json` 与 bench 日志里抄，逐条带读数。
2. **红门处置表**：门名 → 最常见的 3 个原因 → 只重跑这一道的命令。
   实测 `scripts/run_gates.py --help` 今天**没有** `--only`（只有
   `--profile/--profiles/--fast/--affected/--changed-from`，而 `--affected`
   是按**路径**选门、不是按门名）⇒ 本卡要补 `--only`，见判据 4。
3. **时机表**：卡内自测（改完立刻）/ 提交前（`--fast` 或自动档）/ 落地前（全量，
   云）/ 每天 02:00（夜间全量）/ 里程碑前（云机两趟 + 异机）。

### 2.4 与技能的分工

- 判据留在工具里（`run_gates.py` / `domains.py` / `wb_verify.py`），文档只写
  「什么时候用哪一档」。
- `skills/pipe-gate/SKILL.md` 加一行指向本文档；**不要**把五维表抄进技能
  （技能只放操作知识，判据在库/门里 —— 全局约定）。

## 3. 判据

1. `docs/subsystems/ci/测试流程.md` 存在，含上表全部五维 + 决策树 + 三张表，
   且**每条耗时/读数都标来源**（`gates/last.json`、`gates/diag/*.log`），
   不许写没有出处的数字。
2. 文档里的命令都能直接复制执行：至少 6 条，逐条在卡树里实跑一次并贴输出。
3. `tests/test_ci_docs.py` 新增 ≥5 条钉子：19 道门名与 `gates/defs/*.py` 的
   `GATES` 逐字一致（防文档与门表漂移）、五维关键词都在、决策树里的档位名
   都是 `run_gates.py` 真认的参数、指向 `skills/pipe-gate/SKILL.md` 的链接存在。
4. `scripts/run_gates.py` 补 `--only <门名>`（逗号可多值，未知门名退 2 并列出
   可用名），并在日志首行写明「本次只跑了 X/Y 门」；`wb_verify` 看到
   `only` 跑出来的 `last.json` 必须判红（**不许拿半趟当全量**）。
5. 反向验证两条：把 `--only` 的名字写错 ⇒ 退 2 且列出可用门名；
   `tests/test_ci_docs.py` 里把某道门名改错一个字 ⇒ 钉子红。

## 4. 不许做

- 不许把「文档里写的档位」与「工具真认的参数」写成两套（判据 3 就是防这个）。
- 不许在文档里给出「跳过某门」的建议；只允许「这档本来就不含它」。
- 不许把五维表抄进 `skills/`（技能只放操作知识）。
- 不许新增门；本卡只描述与收口现有 19 道。
