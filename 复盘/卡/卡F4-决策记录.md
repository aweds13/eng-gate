## 要解决的问题

今天的决策散在三处：台账 `docs/traceability.toml`（可改，不算记录）、几十篇复盘正文、
以及我脑子里。改主意时没人知道原来为什么那么定，也没人知道当时有多大把握。

## 判据（五条）

1. 模板固定五段：`## 背景与问题` / `## 候选方案` / `## 决定`（含取舍）/ `## 把握程度`（high·medium·low + 一句为什么）/ 头信息 `Status: Proposed|Accepted|Superseded` + 可选 `Supersedes:` / `Superseded-by:`。
2. **只追加**：已 Accepted 的记录正文不许改（改主意 = 新写一条 + 双向链接）；`scripts/check_docs.py --decisions` 用 git 检查"Accepted 记录正文是否被改过"。
3. 编号连续（`0001` 起）、文件名 `NNNN-slug.md`、slug 只用小写字母数字连字符。
4. 回溯首批 8 条（今天定过的真决策）：D12 搜索走官方 / D16 MCP 只留扩展位 / C14 域红线 / 封存口径（比提交不比长度）/ 工具根与数据根切分 / 按域跑必需门 / 卡归窗口 / `复盘/` 不收项目书。
5. 每条都指回原始出处（台账条目号 / 卡号 / 复盘文件名），能顺着读回去。

## 交付

- `docs/decisions/README.md`（模板 + 什么时候该开一条）
- `docs/decisions/0001-*.md` … `0008-*.md`
- `scripts/check_docs.py --decisions`（编号连续 / status 合法 / supersedes 成对 / Accepted 正文未被改）

## 不许做

- 不许把台账条目直接导成 ADR（台账会改、ADR 不改，两者语义相反）。
- 不许把 ADR 写成设计指南（微软原文：decision 必须能独立成立，细节外链）。
- 不许为了"补全"编造当时的候选方案 —— 记不清就写"当时没有正式比较过"。
