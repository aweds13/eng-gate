## 要解决的问题

`tools/pool/route.py` 今天只有一种排法：`smart_order()`（= magpie 的 `Smart`）。magpie 的 `Builtin` 里**恰好七种**，pool 一种都没有（`grep -n "rotate\|weighted\|least_used\|pace\|free_first\|fastest\|ordered" tools/pool/route.py` 无结果）。

而且这个「一种排法」今天还没有派活链上的调用方（`route.smart_order()` / `apply_order()` 零生产调用方，唯一 import 它的 `tools/pool/plan.py:524` 只用 `reset_for` / `seconds_left`）。所以本卡是**纯追加判据**：把七种排法搬齐并逐条钉住，**不负责接线**（接线是另一张卡）。

## 判据（15 条，逐条可执行）

**本卡的判据就是设计原件 §F17「判据逐条」那 15 条**，逐字照做、不许自行增删：

1. `BUILTIN` 恰好 7 项且逐字等于 `("order","rotate","usage","pace","weight","free","fast")`。
2. `ordered(seats) == list(range(len(seats)))`，**任何** `Seat` 取值下都成立。
3. `rotate` 用「该 pool 的请求计数 `% n`」做起点；第二次调用是第一次的循环左移一位；`n == 0` ⇒ `[]` 不抛；计数按 pool 分开。
4. `least_used` 键序严格是 ①`tier` 的「2 与 2 之间比 `credits`」→ ②`used` 升 → ③`by_left` 组内位次 → ④`tokens` 升；排序必须**稳定**。
5. `by_pace` 分带：`pace` 从大到小，`k==0` 或 `p < PACE_BAND*top` 起新带；带号递增；`tier(used) != 0` 或缺 `pace` 的人不参与分带。
6. `by_pace` 里 `pace is None` **不许当 0**（`None` 是「不知道」，`0` 是「一点都不剩」，两者排位必须不同）。
7. `round_pick` 是平滑加权轮转：`weights=(3,1)` 连续四次得到 `0,0,1,0`；`total` 是**参与者**权重和（`rests[i]` 不计入），赢家减 `total`；全 `rests` ⇒ `-1`。
8. `weighted(seats) == first(round_pick(...), len(seats))`：赢家提到第 0 位，**其余保列出序**（不是旋转）。
9. `free_first` 只分两档：`free=True` 全在前、其余按列出序；**`free` 档内部不排序**。
10. `estimate(ttft, 0, mid)`：`tps<=0 ⇒ tps=mid`；`mid` 也是 0 ⇒ 只按 `ttft`；否则 `ttft + REF_TOKENS*1000/tps`。
11. `fastest` 四堆顺序是 `awake + resting + spent`，`awake = fast + unmeasured`；`Resting` 优先于「用完」、用完优先于「没量过」。
12. `fastest` 探测：`fast` 与 `unmeasured` 都非空时，每 `PROBE_EVERY` 次把 `unmeasured` 里下一轮那个提到 `awake` 最前，计数归零、轮次 +1（**顺序是判据的一部分**）。
13. `apply_strategy(name, ...)`：名字不在 `BUILTIN` ⇒ 返回 `identity(n)` **且不抛**；任何策略返回非置换 / 越界 / 重复 ⇒ 也返回 `identity(n)`，**不抛**。
14. `round_pick` 的 `keys` 换了一批之后，旧 key 的 `cur` 必须**被清掉**（否则新 key 继承上一个同位置 key 的欠账）。
15. 新增的三种要比余额的策略**必须复用** `_left_key`（`left_in is None` 与 `left_in` 相同才比的那条），不许各写一份「比余额」。

**常量逐字**（一个不许「顺手调」）：`FRESH_PACE = 100.0 / (7 * 24.0)` / `REF_TOKENS = 200` / `PROBE_EVERY = 5` / `ALIKE = 1.1` / `PACE_BAND = 0.9`。

## 不许做

- **不许另开一个策略模块**（例如把七种策略拆成 `strategies`）：`Seat` 是共享类型，复制一份就是两份真源。
- **不许改 `smart_order()` 一个字节**（它被 9 条既有钉子咬住）。
- **不许把 `rotate`/`weighted`/`fastest` 的计数状态持久化到磁盘**：原件是进程内 map，pool 一次一个进程；持久化会把「每进程重置」洗成「跨卡继承欠账」。状态一律由调用方按 pool 传进 `state=`，模块自己不落盘。
- **不许借 `tools/pool/plan.py:64` 的 `WILDCARD_CHARS`**（那是拒绝通配的字段校验，与路由无关）。
- **不许在 `apply_strategy` 里抛异常**（原件 `Apply` 的设计就是 fail-open）。
- **不许给 `pace`/`ttft`/`tps` 填「看起来合理」的默认值**：`pace` 用 `None`（不知道），`ttft`/`tps` 用 `0.0`（没量过）并在注释里写明。
- 不许碰 `tools/wb_dispatch.py` / `tools/pool_quota.py` / `tools/pool/sink.py`（各有在飞卡）。
- 不许碰六份 `PROTECTED_FILES`。

## 缺口的如实交代（进 changelog 的 gaps）

1. `Seat.Tokens` 的「1 小时半衰期衰减」在 magpie 源码里**零命中**（只有注释）⇒ 不搬衰减，`tokens` 只是「调用方给的已衰减值」。
2. `credits` 分支在 pool 侧**无输入**（号池没有「超出额度还能用赠金」这个概念）⇒ 字段在与判据在，但今天没人填、咬不住。
3. `free` 在 pool 侧**无来源**（`model_registry.ModelEntry` 没有 `free` 字段）⇒ `free_first` 只对调用方传入的 `free=` 生效；要真用起来得先在注册表加一列（另一张卡）。
4. `fastest` 的 `ttft`/`tps` 在 pool 侧**无测量面**（`append_usage_line` 不记首字节时间）⇒ 结构在、喂不饱。
5. `Pace` 的 `band` 在 `k == 0` 时落到哪个值，是按 Go map 零值语义**推的**，不是读到某一行断言 ⇒ 标「判不出」。
