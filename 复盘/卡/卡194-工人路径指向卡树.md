# 卡 194 —— **CodeBuddy 工人的白名单路径要指向卡树**（不是主仓）（T-G294）

**树**：`.wt/promptpath` ｜ **base**：主控派活时的主树 HEAD ｜ **提交**：★ **不要 commit**
**成员号**：任务 `B-PROMPTPATH` 的 **M-1**（干完要交成送申请，见最后）

## 现场（2026-10-03 晚，真发生）

派卡 151 到 CodeBuddy 池（`wb_dispatch.py --cwd .wt/verdict …`）。工人**报成功、交了申请**，
但：
- 它自己的卡树 `.wt/verdict` **报「干净」**；
- **主树**里却出现 `M tools/wb_dispatch.py`（+22/-5）与 `M tests/test_wb_dispatch.py`（+44/-0）——
  **逐字就是它自报的数**。

★ 同一时间的**码道**工人（166/183/185）**都写在自己的卡树里** ⇒ 问题只在这一条路。

## 根因（已读代码定位，不是猜）

`tools/wb_dispatch.py::prompt_path()`（T-G204 加的那段）把规格 / 切片路径**统一解析到 `ROOT`（主仓）**：

```python
return str(q if q.is_absolute() else (ROOT / q).resolve())
```

⇒ 于是工人的提示里，**它要改的白名单文件也指向主树**（而 `--cwd` 只管**进程起点**、管不住这个）
⇒ **它顺着绝对路径改到主树**。★ 码道那条路的提示不带主树绝对路径，所以没这个毛病。

## 危害（三条，都真的会发生）

1. 违反「**工人只在自己的卡树里干活**」；
2. **多个 CodeBuddy 工人可能互相覆盖**（同一文件、同一主树）；
3. **主树堆积未提交改动 ⇒ 挡住 ff 合流**（当晚真的挡了一次）。

## 要做的事

1. **让「工人要改的文件」在提示里指向卡树** —— 给了 `--cwd` 时，白名单 / 域里的**仓库相对路径**
   必须解析成 **`worker_cwd / <相对路径>` 的绝对路径**；★ **规格 / 切片**这类**只存在于主仓**的
   临时文件仍按主仓解析（它们不在卡树里，找不到工人会满盘找）。
   - ★ **判据**：同一个 `prompt_path()` 里区分「**工人要改的**」与「**只读的临时件**」两类，
     **不许一刀切**（一刀切到卡树 ⇒ 规格读不到；一刀切到主仓 ⇒ 就是今天这个 bug）。
2. **反例钉子**（每条要"故意坏掉会红"）：
   - ① 给了 `--cwd` ⇒ 白名单路径必须是**卡树绝对路径**（含 `--cwd` 的那棵树）；
   - ② 同一场景下，**规格/切片**路径必须仍指向**主仓**（读得到）；
   - ③ **不给 `--cwd`** ⇒ 行为**逐字不变**（向后兼容）；
   - ④ 反例（今天这个 bug）：白名单路径解析到主仓 ⇒ 必须**红**。
