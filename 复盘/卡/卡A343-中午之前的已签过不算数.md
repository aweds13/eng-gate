# 卡 A343 —— 中午之前的「已经签过了」不算数：magpie provisional 复查窗口移植进 pool（F29）

> 台账号 **T-AG545** ｜ 分区 A（magpie 移植）｜ 树 `.wt/A343` ｜ 层 判据层
> 依据：magpie `internal/provider/workbuddy_checkin.go`（`wbCheckinEvery` `:53`、
> `wbCheckinRetry` `:56`、`wbCheckinSoon` `:87`、`checkinSureHour` `:147` + `:140-147` 的来历注释、
> `provisional()` `:160-173`、`settled()` `:190-195`、`retryAfter()` `:201-206`、
> `tick()` `:596-628`）与 issue `#3326`。

## 要解决的问题

pool 的签到是**一次定案**：`tools/pool_accounts.py:1127 _record_checkin()` 把结论码直接写进
`health["last_checkin"]`，之后再没有人回头看它第二眼。magpie 那边有三条 pool 完全没有的东西，
而且其中一条是**实测事故换来的**：

1. **没有 `provisional` 这个概念**。北京 12 点之前的 `already-claimed` / `inactive`，vendor 很可能
   还在说**昨天**。magpie 的来历（`workbuddy_checkin.go:140-147` + issue `#3326`）：实测 00:00:28
   六家全回 "already in"、10:54 才真领到，**29 个号里 14 个中招**。这不是防御性编程，是事故修补。
2. **没有复查窗口**。magpie 的 `settled()` 判「当日已定案」，`tick()` 是「每北京日一次 + 30 分钟复查
   + 失败到期重问」的唯一实现。pool 侧 `health["last_checkin"]` **只写不读**（全仓 `last_checkin` 的
   读取点：0 处）。
3. **没有失败退避**。magpie `retryAfter()`：在线固定 30 分钟；离线
   `min(wbCheckinRetry, wbCheckinSoon << min(tries,5))` = 1/2/4/8/16 分钟、30 分钟封顶。

零命中实测（本树）：`provisional` **0** / `checkinSureHour|CHECKIN_SURE_HOUR` **0** /
`checkinEvery|checkin_every` **0** / `due_for_recheck` **0** / `retry_after_s` **0**。

### ★ 只移植判据，不移植触发方式

magpie 的「每分钟看钟」是**触发方式**（`keepCheckedIn` `:565-593`）；pool 的定形是「人开口一次」
（`tools/pool/checkin.py:1-16` 逐字「不给后台定时、不做自动重试，只有用户开口时跑一次」）。
⇒ 本卡**只加纯判据 + 一个只读查询 + 一个只读子命令**，`checkin` 子命令的行为**一个字不改**。
这样「一次一不重试」的既有钉子仍然成立：一次 `checkin` 调用对同一个号只发一次，
复查发生在**下一次人开口时**。

## 判据

1. **`tools/pool/checkin.py` 顶部常量区新增四个常量**（紧跟在 `TIMEOUT_S = 30.0` 之后）：

   ```python
   CHECKIN_SURE_HOUR = 12      # magpie workbuddy_checkin.go:147；来历见 :140-147 + issue #3326
   RECHECK_EVERY_S = 30 * 60   # magpie :53 wbCheckinEvery
   RETRY_AFTER_S = 30 * 60     # magpie :56 wbCheckinRetry
   RETRY_FLOOR_S = 60          # magpie :87 wbCheckinSoon

   RECHECK_PLATFORMS: frozenset[str] = frozenset({"qoder"})   # 只有活动类平台要复查
   ```

   **`CHECKIN_SURE_HOUR` 不许改成可配置**（magpie 侧是 `const`，值来自那次事故读数）。

2. **新纯函数 `provisional(outcome, *, at, now, timezone) -> bool`**，三步判据缺一不可：
   - `outcome.kind in (ALREADY_CLAIMED, INACTIVE)`；
   - `at.astimezone(timezone).date() == now.astimezone(timezone).date()`（**同一天**）；
   - `now.astimezone(timezone).hour < CHECKIN_SURE_HOUR`（**北京 12 点前**）。
   `NOT_SUPPORTED` / `CLAIMED` / `UNCERTAIN` / `FAILED` ⇒ `False`。
   `at` / `now` 都必须带时区（naive ⇒ `ValueError`，不许猜时区）。

3. **新纯函数 `retry_after_s(*, offline, tries) -> int`**：
   在线 ⇒ 恒 `RETRY_AFTER_S`（1800）；离线 ⇒ `min(RETRY_AFTER_S, RETRY_FLOOR_S << min(tries, 5))`
   ⇒ `tries=0..5` 得 `60, 120, 240, 480, 960, 1800`，`tries>=5` 恒 `1800`。
   `tries < 0` ⇒ `ValueError`。

4. **新纯函数 `due_for_recheck(last, *, at, now, timezone, platform, offline=False, tries=0) -> tuple[bool, str]`**
   —— 第二个元素是**给人看的理由**，按下表逐条判定，先命中先返回：

   | 条件 | 返回 |
   |---|---|
   | `last is None` | `(True, "从没问过")` |
   | `last.kind == NOT_SUPPORTED` | `(False, "平台不支持签到")` |
   | `at` 的北京日期 ≠ `now` 的北京日期 | `(True, "跨天了")` |
   | `last.kind == FAILED` 且距今 ≥ `retry_after_s(offline=offline, tries=tries)` | `(True, "失败到期重问")` |
   | `last.kind == UNCERTAIN` 且距今 ≥ `RETRY_AFTER_S` | `(True, "没定论，复查窗口到了")` |
   | `provisional(...)` 为真 且 距今 ≥ `RECHECK_EVERY_S` | `(True, "上午的「已签过」不可信，复查窗口到了")` |
   | `platform in RECHECK_PLATFORMS` 且距今 ≥ `RECHECK_EVERY_S` | `(True, "活动类平台复查窗口到了")` |
   | 其余 | `(False, "当日已定案")` |

   纯函数：不读钟、不读文件、不写文件、不联网。

5. **新只读查询 `tools/pool_accounts.py:recheck_rows(data, platforms, *, now=None, platform=None) -> list[dict]`**
   （放在 `:1127 _record_checkin` 之后）：逐号读 `health["last_checkin"]`（**历史形状兼容**：
   可能是结论码字符串，也可能是带秒/不带时区的 ISO 时刻；解不出 ⇒ 当作「从没问过」——
   这是本卡**唯一**的 fail-open，方向正确：复查签到是幂等动作，比「时间戳坏了就永远不复查」安全，
   **这条理由必须写进 docstring**），调 `ck.due_for_recheck(...)`，只收 `(要问, 为什么)` 为真的行。
   回 `[{"id", "platform", "why", "provisional"}]`，按 `(platform, id)` 稳定排序。
   **只读**：不签到、不写账本、不写留档。

6. **CLI 加只读子命令 `due`**（`tools/pool_accounts.py:1302` 的 `sub` 上，照 `checkin` 的写法）：
   `--now`（ISO-8601，注入「现在」）/ `--platform` / `--json`。**不加参数之外的任何东西**。
   退出码：有行 ⇒ `EXIT_OK`(0)；无行 ⇒ `EXIT_OK`(0)；参数坏 ⇒ `EXIT_USAGE`(2)。**不许**用 `EXIT_NEEDS_HUMAN`。

7. **时区只有一个真源**：`tools/pool_accounts.py:61 TZ = timezone(timedelta(hours=8))`。
   `checkin.py` **不许**自己造第二个 `+08:00` 常量（`provisional` / `due_for_recheck` 的 `timezone` 参数由调用方传 `TZ`）。
   `due` 子命令的 `--now` 解析照 `tools/pool_quota.py:213 _resolve_now` 的口径（None ⇒ 真实现在、str ⇒ `fromisoformat`）。

8. **反向钉子 `test_reverse_provisional_without_the_noon_line`**：把 `CHECKIN_SURE_HOUR` 从 **12 改成 0**
   （即「任何时候的 `already-claimed` 都可信」= 删掉 `#3326` 那次修补）—— 这条必须变红。
   现场：`ALREADY_CLAIMED @ 今天 00:30`、`now = 今天 00:31`，断言 `provisional(...) is True`；
   改成 0 后 `hour < 0` 永不成立 ⇒ `False` ⇒ 红。
