# 卡 A301 —— 落地前置检查 + 接管技能端到端验证

任务号 T-AG415。树 `.wt/A301`，分支 `card/A301`，基线 HEAD。

## 为什么开这张卡

`wb_land` 每次落地都要跑 19 道全量门（含全量 pytest，4–8 分钟）。A300 连红两轮，
两次都不是产物坏了，而是**文书里的裸文件名**被 `scripts/check_layers.py` 判成
引用断裂（`limits.md`、`NOTES.md`）。同类坑已经踩第 3 次，必须前移到秒级检查。

同时 `pipe-takeover` 只做了纸面校验，没有在一份真实样例上跑通「勘察 → 映射 →
限制 → 最小骨架 → 第一步验收」；六种假成功也只是文档条目，没有会咬的钉子。

## 要交付什么

1. **`tools/wb_land.py` 加前置快检**（在 ② 文书生成之后、③ 全量门禁之前）：
   - 检查本次新增的 `gates/diag/_text_<task>.md` 与它生成的
     `docs/changelog.d/<task>.md`：反引号里出现**裸文件名**（不含 `/` 或 `\`，
     以 `.md` / `.toml` / `.py` 结尾）⇒ 立即红，退出码非 0，不进全量门禁。
   - 只跑 `python scripts/check_layers.py` 与 `pytest tests/test_check_skills.py -q`
     两项，总耗时目标 <30s。
   - 红线：不许放宽既有判据，不许跳门；全量门禁仍照跑（快检只是早失败）。
2. **规则写进技能**：`skills/pipe-land/references/land-steps.md` 的坑清单补一条
   「文书只许写仓内全路径，裸文件名会被 check_layers 当路径」。
3. **接管技能端到端验证**：新增 `tests/test_takeover_e2e.py`，在 `tmp_path` 造
   四类样例目录（A 完整 / B 有卡无门 / C 只有代码 / D 空），逐类断言
   `tools/wb_takeover.py` 的 `kind`、`mapping_hints`，并至少对 C 类跑一次
   「铺最小骨架 → 第一步验收」的函数级路径（不写真实仓库）。
4. **六种假成功各一条钉子**：新增 `tests/test_false_success_pins.py`，每条都要能
   在本仓当前状态**变绿**，并在人为注入坏数据时**变红**（用 monkeypatch/临时目录）：
   门假绿、卡没人派、证据路径不存在、done 无证据、骨架污染主干、本仓特例当通用。

## 验收命令

```
python -X utf8 tools/wb_land.py --help | grep -q precheck   # 或者函数名可被直接调用
pytest tests/test_takeover_e2e.py tests/test_false_success_pins.py -q
pytest tests/test_wb_land.py -q
ruff check tools/wb_land.py tests/test_takeover_e2e.py tests/test_false_success_pins.py
```

- 不新增技能目录；规则进已有 `references/`。
- 不动 `gates/last.json` 的封存口径。
