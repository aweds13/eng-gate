### 问题 2 · `dispatch-rate` 的 metric 与 evidence 描述的是**不存在的东西**

原文（`docs/proxy-map.toml:56` 与 `:58`）：

```text
metric = "tools/wb_dispatch.py / 号池任务里派活是否真起出工人（.meta.json 落盘 + 工人出 result 事件才算成功）"
evidence = "工人留在 gates/diag/ 的原始读数（口径坑 12：落盘产物才是唯一证据源，工人的判决不是）"
```

实测三件事，三件都对不上：

- 仓内 `find . -name '*.meta.json' -not -path './.git/*' -not -path './.wt/*'` ⇒ **0 个**；
  真身在仓外 `D:/repo/infra/pool/logs`，**45 个**，生产者是仓外的 `infra/pool/dispatch.py:275`。
- `grep -c meta tools/wb_dispatch.py` ⇒ **0**：本仓派活器从不写 `.meta.json`。它写的是
  `gates/diag/wb-<卡>.jsonl`（codebuddy 池日志）、`gates/diag/wb-<卡>.done`、`gates/diag/notifications.jsonl`、`gates/diag/wb-usage.jsonl`。
- codearts 池的日志根本不在仓内：`tools/pool/model_registry.py` 的 `dispatch_log_dirs()` 写明
  codebuddy ⇒ `<root>/gates/diag/`、codearts ⇒ `<号池>/logs/card-<卡>.jsonl`（仓外）。

⇒ 读者按这条 metric 去找 `.meta.json`，在仓里找到 0 个，会以为自己看错了目录。这是**判据撒谎**，不是笔误。

### 问题 3 · 只把日期改成今天，会**新造一条红**

`tests/test_run_gates_proxy.py:124` 的 `test_days_zero_also_turns_the_gate_red` 拿**真登记表**跑
`--check --days 0`，断言 `rc != 0`。它的 docstring 写的是「真登记表（全部昨天验证）也必须红」——
前提是登记表比今天旧。日期一改成今天，`age = 0`、`overdue = 0 - 0 = 0`、`expired = overdue > 0 = False`
⇒ 门变绿 ⇒ 这条钉子必红。**重验和这条钉子必须同时改**。

### 问题 4 · 机器挡不住「只改日期」

子 agent 实测（`mktemp` 临时表，真表未动）：把五条 `last_verified` 全改成 `2026-11-16` ⇒
`--check` 退 0，`--days 0` 也退 0。`tools/proxy_audit.py` 只比日期，不读 `note` 里的读数。
⇒ 本卡必须**同时**加一条钉子，让「只改日期、note 里没有当天读数」这件事红掉。

## 判据

### 判据 1 · 五条 `last_verified` 填**真验证日**，且每条 `note` 追加当天的实测读数

- `last_verified` 全部 = `2026-11-16`（本卡实测日，不是登记日）。
- 每条 `note` **保留原文**（不许删旧案：`tests/test_proxy_audit.py` 断言 `doc-lines` 的 note 含
  「文书行数」「6 行」、`dispatch-rate` 的 note 含「16:52:45」），并在末尾追加
  `★ 2026-11-16 重验读数：…` + 具体数字。
- 钉子：`tests/test_proxy_audit.py` 新增 `test_every_note_carries_the_reverification_reading` ——
  逐条断言 note 含 `2026-11-16`、含至少一处数字、含 `重验读数`。

### 判据 2 · `dispatch-rate` 的 metric / evidence 改成**真源**

- metric 必须点名两头的真日志（codebuddy 的 `gates/diag/wb-<卡>.jsonl`、codearts 的
  `<号池>/logs/card-<卡>.jsonl`）与收工判据（`type=result` 事件）；
- metric **不许**再出现 `.meta.json`（那是仓外生产者的产物，不是本仓派活器的）；
- evidence 必须写清 `.meta.json` 的真实位置（仓外）与「仓内 0 个」，否则读者仍会去找。
- 钉子：新增 `test_dispatch_rate_metric_points_at_the_real_logs` —— 断言 metric 含 `wb-` / `card-` /
  `result`，且 `".meta.json" not in metric`；evidence 含 `infra/pool`。

### 判据 3 · `test_days_zero_also_turns_the_gate_red` 改成自造「昨天」表

- 不再拿真表跑 `--days 0`；改成在 `tmp_path` 里造一份「全部昨天验证」的表（复用同文件既有的
  `_map_with_first_entry_dated` 思路或新帮手），断言 `--days 0` 在那份表上退非零且点名 `过期`；
  真表在 `--days 0` 上**变绿**这件事本身要写成注释说明（今天是验证日）。
- 钉子：重验后再跑这条钉子必须绿；把实现改回「拿真表跑」⇒ 必红。

### 判据 4 · 反向变异 ≥4（真改、真跑、真还原，记 sha256）

- A：把 `dispatch-rate` 的 metric 改回「.meta.json 落盘」⇒ 判据 2 的钉子必红；
- B：把某一条 note 里的 `2026-11-16 重验读数` 删掉 ⇒ 判据 1 的钉子必红；
- C：把某一条 `last_verified` 改回 `2026-10-12` ⇒ `proxy_audit.py --check` 退非零、`tests/test_run_gates_proxy.py::test_real_map_makes_the_gate_green` 必红；
- D：把 `test_days_zero_also_turns_the_gate_red` 改回「拿真表跑 `--days 0`」⇒ 该钉子必红；
- C1（安静对照）：只改一句注释 ⇒ 全绿。
