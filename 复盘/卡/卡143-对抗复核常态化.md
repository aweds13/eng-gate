# 卡 143 —— **对抗复核常态化（提交之后 · 异步 · 不挡流水线）**（T-G242）

**树**：`.wt/advcard` ｜ **base**：主控派活时的主树 HEAD ｜ **提交**：★ **不要 commit** ｜ **模型**：默认
**成员号**：任务 `B-QUAL` 的 **M-2**（干完要交成送申请，见最后）

## 来路（用户的口径 + 今晚的实证）

用户先问 *「验收能不能外包出去？」*，紧接着给了**关键修正**：
> *「可不可以对抗复核，是在**提交之后**，然后呢，**继续推进任务**，这样子可以**加快任务推进**。就是**提高效率**。」*

★ 这一改**改对了性质**：对抗复核从"**闸**"（挡收口 ⇒ 每批都要等一轮）变成"**审计**"（提交后异步跑，
**与下一批并行** ⇒ **不挡流水线**）。今晚的实证支持这个方向：
**8 笔提交里对抗卡 = 0 张**；而唯一一次真对抗（GLM-5.3 审整套设施）一次抓出 **14 条 + 5 条判据漏洞**
（含自评"最狠"的那条：域检查吃**自报清单**）—— **方法有效，但那次是一次性的**。
★ 零件已经齐了 80%：只读卡的概念在协议里 · 申请必须带证据 · 指针索引让复核者的输入便宜。
**缺的是：按"审计"落位的机制 · 常态化规矩 · 对抗性开场白。**

## 要做什么（三件，别扩）

1. **栅栏支持"审计型只读成员"**（`tools/pool/task.py`）：
   - 预声明允许 `read_only = true` 的成员，**它的 `paths` 可为空**（`paths = []`）——语义：
     "这张卡**不改任何文件**，产物是**攻击记录**（读数 + 结论）"；
   - ★★ **它不挡收口**（这是本卡与"闸"的分水岭）：**放行判据里的"集齐"只数非只读成员**
     （`need` = 非只读成员数）；只读成员的申请**照样记进 `history`**、照样能看，但**不参与放行**；
     ⇒ 于是"提交之后才跑复核"不会让任务卡在 `collecting`；
   - ★ **判据别放松**：**没有** `read_only = true` 而 `paths` 为空 ⇒ **照今天一样拒**（原文保留）；
     只读成员**不许**声明"我改了文件"（`--files` 非空 ⇒ 拒）；
   - `status` 输出里把只读成员**标出来**（一列或前缀），让人一眼看得出"这不是闸，是审计"。
2. **新增 `tools/wb_advcard.py`（对抗开场白 + 指针索引生成器）**：吃 **`--task <任务号>`** 或 **`--commit <sha>`**
   （★ 因为现在是**提交之后**跑，`--commit` 是主形态），产出草稿到
   `gates/diag/batch/<任务或提交>.advcard.md`（**scratch、不进 git**），至少含：
   - ★ **这一笔/这一批新加了哪些能力**（从成员 `what` 与 claim `why` 抽）—— **每处新能力都可能是新的假绿路径**；
   - ★ **改动文件清单**（`git diff --name-only`）与**每处"谁判它"**（判据 + 反例钉子路径）——
     能复用**卡 142 的 `tools/wb_impact.py`** 就复用，**别另写一份**；
   - ★ **要它攻击的四问**（固定模板）：① 哪条**新能力**让"看着绿其实没查"变得可能？② 哪条判据只查**存在性**而非**真伪**？
     ③ 哪条**自报清单**还在被当判据？④ 哪条**退出码/产物**被当成了结论？
   - ★ **硬要求**：**只读**（不改任何文件）· 结论必须带**证据指针**（`路径:行` 或命令读数）·
     **找不到攻击点就说找不到**（不许编） · ★ **产出是"跟进卡清单"**：每条发现给出"该开哪张卡、治什么"。
3. **写进卡表规矩**（`复盘/外包-卡表与规矩.md`）新增一节「**对抗复核（外包验收）**」：
   - ★ **默认：提交之后、异步、与下一批并行**（**不挡**收口 —— 它是**审计**，不是闸）；
   - ★ **发现的问题 ⇒ 开跟进卡（fix-forward）**；主控裁定严重度；★ **必要时主控 `git revert`**（回退路径要写在规矩里）；
   - ★ **例外（仍要提交前复核）**：**不可逆 / 影响面大**的改动 —— 数据迁移、凭据与密钥、**删除**、
     门禁与收口工具自身 ⇒ **前置**复核，不许事后补；
   - ★ **复核者必须与实现者不同族**（同族共享盲点；今晚实现 `deepseek-v4.1-flash`／审查 `GLM-5.3` 是正例）；
   - ★ **输入用指针索引**（像今晚那份 90 行索引），**不许**让它漫读仓库（控成本）；
   - ★ **开场白必须对抗**：「找假绿路径 / 什么情况下它看着绿其实没查 / 攻击它」—— 写成「请检查是否通过」就退化成盖章；
   - ★ **诚实边界也写进去**：复核**降低**概率、**不归零**；复核者也会漏；**最终责任仍在主控**（唯一写者）。

## 验收（照这个报）

- ★ **反例钉子**（每条要"故意坏掉会红"）：
  ① ★★ **审计型成员不挡收口**：`read_only = true` + `paths = []` ⇒ 注册成功；★ 只读成员**没交申请**时，
     `need` **仍是**非只读成员数 ⇒ 任务**照样能进 `awaiting-commit`**（贴 status 原文）—— **这条是本卡的命门**；
  ② **不许放松**：**没有** `read_only` 而 `paths = []` ⇒ **照旧被拒**（贴原文）；
  ③ 只读成员**声明改了文件** ⇒ **拒**；
  ④ **生成器**：`--commit <某个真 sha>` ⇒ 产物里含**四问**、含**改动文件清单**、含"**只读 + 证据指针 + 找不到就说**"三项硬要求；
  ⑤ **它真的复用影响面**（桩掉 `tools/wb_impact.py` ⇒ 输出跟着变，或**明确降级**并说"拿不到影响面"——不许自己硬编一张门表）；
  ⑥ **规矩可查**：断言那一节含「**提交之后**」「**异步**」「**不挡**」「**不同族**」「**不可逆**」五个词。
- 贴：`python -X utf8 -m pytest tests/test_pool_task.py tests/test_wb_advcard.py --no-cov` 尾行；
  `ruff check tools tests` 尾行；★ 一条**真读数**：拿**今晚某个真任务**（如 `B-AFFECT`）跑一次生成器，贴**前三段原文**。
- ★ 不许跑全量门禁、不许 commit/tag、不许动主树与别的树；★ 不许改"申请必须带证据"这条既有判据。
