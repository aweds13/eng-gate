> `tests/test_gate_summary_truthful.py::test_detail_makes_the_suspect_shape_visible_again` 唯一失败，
> `detail` 原文是 `'[FAIL] û�ȵ���Ӧ������Լ 12 ��\nFAILED tests/test_live.py::test_x'`。
> 云机读数：`python -c "import sys;print(sys.stdout.encoding)"` ⇒ **`gbk`**；`locale.getpreferredencoding(False)` ⇒ **`cp936`**；
> 本机两者都是 `utf-8`。

## 要解决的问题

判据没错，是**编码把症状洗掉了**：

```python
# scripts/run_gates.py（修前）
def env() -> dict[str, str]:
    return tree_pythonpath(dict(os.environ))
```

```python
# scripts/run_gates.py:1516（读的一方）
proc = subprocess.Popen(
    cmd, cwd=ROOT, env=env(),
    stdout=subprocess.PIPE, stderr=subprocess.STDOUT,
    text=True, encoding="utf-8", errors="replace",   # ← 按 utf-8 解
)
```

读的一方钉死 utf-8，写的一方却**继承宿主 locale**。云机是 Windows Server、`cp936`，于是：

1. 门禁子进程把 `[FAIL] 没等到响应，等了约 12 秒` 按 **GBK** 写进管道；
2. `start_gate()` 按 **utf-8** 解 ⇒ 得到 `[FAIL] û�ȵ���Ӧ������Լ 12 ��`；
3. `mark_suspect_rows()` 拿 `SUSPECT_SHAPES`（`没等到` / `超时` / `timeout` / `timed out` / `等了约`）
   去匹配 ⇒ **一条都匹配不上** ⇒ 标不上 `SUSPECT`；
4. 于是 E67 落的判据 4（「`detail` 让他们看得见症状」）在云上**假红**：
   判据本身是对的，被编码骗了。

本机复现（同一机制，与平台无关）：把 `PYTHONIOENCODING=gbk` 注入环境，走旧 `env()` 起子进程 ⇒
子进程输出 GBK 字节 ⇒ 解出乱码 ⇒ 形状全部失明。探针读数见 `gates/diag/probe-A337.log`：

```
=== 修前（旧 env()：只走 tree_pythonpath） ===
首行 repr = '[FAIL] û�ȵ���Ӧ������Լ 12 ��'
[判] 中文乱码 = True（期望 True）

=== 修后（新 env()：+ PYTHONUTF8/PYTHONIOENCODING） ===
首行 repr = '[FAIL] 没等到响应，等了约 12 秒'
[判] 中文完好 = True（期望 True）
status = 'SUSPECT'（期望 'SUSPECT'）
```

副作用：这层缺口不只影响 `SUSPECT`，它让**所有**按中文形状做的判据在非 UTF-8 宿主上同时失明
（`FAIL_SHAPES` 里的 `超时`、`acceptance` 的中文摘要、`ui_text` 的中文断言都靠同一份解码）。

## 判据（6 条）

1. **`env()` 必须同时给出 `PYTHONUTF8=1` 与 `PYTHONIOENCODING=utf-8`**。只给前者不够：
   `PYTHONIOENCODING` 优先级**高于** UTF-8 模式，外部环境里已有的 `PYTHONIOENCODING=gbk` 仍会赢。
2. **必须是覆盖，不是 `setdefault`**：`monkeypatch.setenv("PYTHONIOENCODING", "gbk")` 后
   `env()["PYTHONIOENCODING"]` 仍须是 `utf-8`（要的是同一份读数，不许被一个环境变量悄悄换掉）。
3. **不许动 `PYTHONPATH` 那条既有约束**（INV-25）：本树 `src` 仍在首位。
4. **真路径上中文完好**：注入 `PYTHONIOENCODING=gbk` 后走真 `start_gate()` → `finish_gate()`，
   `summary`/`detail` 里 `没等到响应，等了约 12 秒` 必须逐字出现。
5. **`SUSPECT` 在 GBK 宿主上仍标得上**（云机那条红的正题）：
   同一条链喂 `mark_suspect_rows()` ⇒ `status == "SUSPECT"`，`suspect_reason` 里含命中的形状。
6. **反向自证**：把 `env()` 退回旧实现，同一现场**必须**乱码且形状全部失明 ——
   先断言前提成立（乱码真的发生），才谈得上「修好了」。

## 不许做

- 不许改 `start_gate()` 的 `encoding="utf-8"`（那会把问题从「解错」变成「两处都不确定」）。
- 不许只写 `PYTHONUTF8` 就算完（判据 2 咬的就是这个）。
- 不许用 `setdefault`（外部环境会赢 ⇒ 换台机器修不好）。
- 不许动 `scripts/run_gates.py` 的行尾（实测是 `\r\r\r\n` 三重 CR，2902 行；归一化会毁整份文件）。
- 不许放宽 `SUSPECT_SHAPES`（往表里加 `û` 之类的乱码形状 = 掩盖病灶）。
- 不许改六份 `PROTECTED_FILES`（`docs/traceability.toml` / `docs/changelog.md` / `复盘/交接-重构进度.md` /
  `复盘/新窗口交接卡.md` / `gates/last.json` / `gates/reuse.json`）。
- 不许在本卡顺手改 `web_live` 的 `nopair` 断言（那是另一条云红，根因未定论，另开卡）。
