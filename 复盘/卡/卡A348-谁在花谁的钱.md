## 要解决的问题

**今天分不清「谁在派活」，也撤不掉一个派活的人。**

`default_owner()` 给的是 `TF_WINDOW_ID` 或 `<hostname>:<pid>` —— 人给的号、可伪造、进程重启就变。
它回答的是「这条租约属于哪个窗口」（用来判死租约），**不是**「谁在花谁的配额」。

于是两件事做不了：

1. **归因**：一个号被三个窗口换来换去时，事后查不出是哪个人让它换的。
2. **撤**：想让某个窗口别再派活（它在跑偏、它在刷），今天唯一的办法是**关服务端写面**（
   `POOL_MCP_WRITE`）—— 那是把整台机器停掉，不是把一个人停掉。

magpie 用 `caller-keys.json` 解决这两件事：一把 key 一个名字、一个 `off` 开关、三条可选收窄。
本卡只搬**身份 + 撤销 + 收窄挂载点**，不搬凭据。

## 判据（9 条，逐条可执行）

1. **新增 `tools/pool/callers.py`，纯标准库（`os` / `tomllib` / `dataclasses` / `pathlib`），不改任何既有模块的判据。**
   文件头 docstring 如实写清三条边界：① 没有凭据（不生成 secret、不做常量时间比较、不写 `0600`）；
   ② `off` 是**唯一**可撤语义，撤 = 改 `off = true`，**不删行**；③ 本模块**只读**名册，写入由人改 TOML。
2. **常量与根推导逐字照 `tools/pool/limits.py:48 POOL_ANCHOR = ("infra", "pool")` 的形状**：
   `POOL_ANCHOR = ("infra", "pool")` / `CALLERS_NAME = "callers.toml"` / `ENV_CALLERS = "TF_POOL_CALLERS"` /
   `TOOL_ROOT = Path(__file__).resolve().parent.parent.parent`。
   `pool_dir(start=None)` 从**仓库根**逐级向上找含 `infra/pool/` 的目录（**不跟 cwd 走**，照
   `tools/pool_accounts.py:104-107` 卡 E49 的注释）；**源码里不许出现任何仓外绝对路径字面量**。
3. **`callers_path()` 三段：`TF_POOL_CALLERS` 覆盖 > 号池目录下 `callers.toml` > 仓根下同路径**
   （逐字照 `tools/pool/limits.py:67 limits_path`）。
4. **`@dataclass(frozen=True, slots=True) class Caller`** 五字段：`id: str` / `label: str = ""` /
   `off: bool = False` / `models: tuple[str, ...] = ()` / `accounts: tuple[str, ...] = ()`。
   **不许**有 `secret` / `masked` / `key` / `token` 任何一栏（见判据 9 的静态钉子）。
5. **`load_callers(path=None) -> dict[str, Caller]`：文件不存在 ⇒ `{}`；文件在但读不懂 ⇒ 抛 `CallersError`。**
   「读不懂」包括：不是合法 TOML、段名不是 `caller.<id>`、`id` 为空、`off` 不是布尔、`models`/`accounts`
   不是字符串数组。★ **坏文件绝不静默当空** —— 逐字照 `tools/pool/lanes.py:103 load_lanes` 的纪律
   （文件头注释原话：「绝不返回 `{}` —— 那就等于 配置文件坏了 ⇒ 悄悄松开判据」）。
6. **`models` / `accounts` 的方向照 magpie `access.go:111`：空/缺 = 全允许。**
   ★ 与本仓 `tools/pool/plan.py:64 WILDCARD_CHARS` 的「见通配就拒」**方向相反**，
   与 `tools/pool/guards.py::domain_guard` 的「空 = 全拒」**方向也相反** —— docstring 里必须把这两条
   对比写明，理由：这两处是**冲突域**判据，这里是**白名单**判据，两个「空」意思不同。
   `models = []`（显式空数组）与「没写这个键」**都是全允许**。
7. **`resolve(explicit="", *, env_window="") -> Caller` 三级：显式 `--caller` > `env_window` > `<hostname>:<pid>`。**
   前两级与 `tools/pool/registry.py:121 default_owner()` **同一口径**（不许另立一套；`env_window` 由调用方
   从 `TF_WINDOW_ID` 传入，本模块**自己不读环境**，只读 `ENV_CALLERS` 找文件）。
   名册里查不到 ⇒ 回一个只有 `id` 的 `Caller`（**不报错**）：名册是**加法**，没登记的人不该因此被拦。
8. **`is_off(caller) -> bool` + 接入 `tools/wb_dispatch.py` 一处**：在 `problems` 已建、占树（`reserve()`）
   **之前**追加一句判定 —— `off` 为真就 `problems.append(f"调用方 {id}（{label or '无名'}）已撤（off = true）—— 不许派活")`。
   复用既有 `problems` 出口（打印 + 退 2），**不许新开一种退出码**，**不许**改 `reserve()` 的签名。
9. **12 条钉子**（`tests/test_pool_callers.py`）：名字与断言见 §测试钉子表。其中两条是静态扫描：
   - `test_no_secret_field_anywhere`：`tools/pool/callers.py` 里 `compare_digest` / `Bearer` / `chmod` /
     `secret` / `masked` **全部零命中**；`Caller` 的字段集恰好是五字段。
   - `test_callers_path_derives_from_anchor`：`TF_POOL_CALLERS` 覆盖生效；源码里除锚点 `infra/pool` 外
     **不许有 `D:/` 或 `C:/` 字面量**。

## 缺口（如实说，不许当成已解决）

1. **名册文件今天不存在**（`infra/pool/callers.toml` 没有）⇒ `load_callers()` 回 `{}`、`resolve()` 恒走
   `<hostname>:<pid>` ⇒ **落地当天零行为变化**。本卡验的是判据的判别力，不是「真撤过一个人」。
2. **三条收窄只搬了挂载点，没有消费者**：`Caller.models` / `Caller.accounts` 今天**零读取方**。
   F34 的模型白名单接的是 `infra/pool/limits.toml` 的账号维度（卡 A341 已落地），F35 接的是
   `account-scopes.toml`（卡 A342），**都不是调用方维度**。要把 caller 维度接进那两条判据，是**另一张卡**。
3. **不做读面隔离**：magpie 有六个 403 按 key 收窄读面的，pool 的 MCP 读面是全机共享的只读面，
   收窄它只会让人看不到现场。**未落地，仅设计**（与卡 A342 的判断一致）。
4. **不做 `rotate` / `0600` / `ConstantTimeCompare`**：没有 secret 可轮换，也没有对手可防。
5. **不做 `limits`（F33 的按 key 限额）**：本卡 `Caller` 五字段里没有 `limits`，卡 A338 的 `limits_policy`
   已经按**账号**维度实现了 key 限额。要挂到调用方维度是另一张卡。
6. **`--caller` 是新增参数，不是替代 `--account`**：`--account` 回答「用哪个号」，`--caller` 回答
   「谁在用」。两者正交，`lease_note` 里 `account=` 与 `caller=` 并列出现，**不许**用一个顶另一个。

## 不许做

- 不许改 `POOL_MCP_WRITE` 的语义（`tools/pool_mcp.py:479`）：它是「服务端有没有这个 env」的**一位授权**，
  与「这次是谁」**正交**。用 caller 表去替 env，等于把「整台机器不许写」降级成「某个人不许写」，写面就此对全机敞开。
