## 要解决的问题

三页 CI 文档里各有一处**读者会当「现在的事实」用**的说法已经与现实不符（判据按
`skills/softeng-manage/references/doc-write.md` 的问题 2：会被当现状用的就地改，不会的加注）：

### 问题 1 · `docs/subsystems/ci/云门禁机.md` 描述的机器已经不存在

2026-11-25 实测：`203.0.113.10:22` 回的 banner 是 `SSH-2.0-OpenSSH_9.6p1 Ubuntu-3ubuntu13.20`
（Ubuntu 24.04 系），不是该页写的 Windows Server 2022；`administrator@` 与 `root@` 都是
`Permission denied (publickey,password)`（`id_ed25519_cloud` 不再被接受），3389 端口同时关闭。

⇒ 该页是**历史运维手册**（§1–§8 的装机、变配、A/B、37 红分类都是当时的现场记录，读数不改），
但页首没有一句话告诉读者这件事。后果：读者按它去 `--gate-on cloud`，会撞 fail-closed 退 2。

### 问题 2 · `docs/subsystems/ci/测试流程.md` 六处仍把云机当默认档位

五维表的「异机」维、决策树两处、时机表两处、§7 命令块一处，都写着「落地默认云机」。

### 问题 3 · `docs/subsystems/ci/门禁自证-product.md` 说「22 道门」

`gates/gate-selfproof.toml` 实测 **23 个 `[[gate]]`**（`schema = 1`，字段 `name` /
`reverse_case` / `why_no_case` / `since`，name 与门表逐字同）。该页 `:3` / `:4` 仍写 22。
无测试钉住这个数字，但它是读者会当现状用的计数。

### 问题 4 · `docs/文档系统导航.md` 零处指向 `docs/subsystems/`

`grep -rn "docs/subsystems" --include=*.md docs/ skills/ 复盘/ AGENTS.md`（排除 `docs/subsystems/` 自身）
⇒ 0 命中。子系统页（CI 七篇 + 号池六篇）是**实现层 / 契约层**的说明，
但它们从唯一的意图路由页上找不到入口。

### 问题 5 · `.gitignore` 缺 `gates/enggate-logs/`

`docs/subsystems/ci/GitHub-Actions-云门禁.md` 已声明「本机落盘在 gates/enggate-logs 下，不进仓」，
但 `git check-ignore -v gates/enggate-logs/x.log` ⇒ rc=1（未被忽略）⇒ 每读一次读数就多一堆
未跟踪 .log，`git status` 与 `check_docs.py` 结果都会跟着这台机器漂（与 `gates/review/` 同一类事故）。
