## 要解决的问题（已实测，不是推测）

卡 E77 的缺口第 5 条（落在 `复盘/卡/卡E77-E76修好的那件事自己又犯了一次.md:71`、`docs/traceability.d/T-AG580.toml:23`、`docs/traceability.toml:11159` 三处）逐字写着：

> `tools/pool/landing.py` ⑦ 的 `scripts/audit_progress.py` 子进程 **rc 没人查**（只 `print((audit.stdout or "").strip()[-260:])`）—— 本卡**不修**：改它会把「本来能落但审计有警告」的笔变成硬失败，属于另一件事。记在这里是为了说明「in-band 修不动」不是偷懒：落地链自己就有一条已经坏掉的 rc 检查。

**这条是假的。** 实测：

```python
# tools/pool/landing.py:201
def run(cmd, cwd, check: bool = True) -> subprocess.CompletedProcess[str]:
    r = subprocess.run(..., check=False)
    if check and r.returncode != 0:
        print(f"★ 命令失败（{r.returncode}）：{' '.join(cmd[:6])} …")
        ...
        sys.exit(2)          # ← 红了就停手

# tools/pool/landing.py:2656
audit = run([sys.executable, "-X", "utf8", "scripts/audit_progress.py"], cwd=wt)
#         ^ 没传 check=False ⇒ 用的是默认 True ⇒ 审计红 ⇒ sys.exit(2)
```

用 `landing.run([sys.executable, "-c", "raise SystemExit(7)"], pathlib.Path("."))` 直接探针实测：打 `★ 命令失败（7）：…` 并 **`SystemExit 2`** ⇒ **rc 是查的**。

⇒ 这条缺口**不是「不修」而是「本来就是好的」**。它留在库里有两重害处：
1. 下一个人会照着它去「修一个不存在的 bug」，改出真问题（把 `check=False` 加回去就真坏了）；
2. 它被用来支撑一个论证（「in-band 修不动不是偷懒」）—— 而那个论证的这根支柱是假的。

★ 注意区分：**E77 的结论本身没错**（一笔同时改多条宿主 ⇒ 三条腿都覆盖不到，这条已实测且是结构边界）；错的是它拿来当旁证的那条**事实**。
