# 卡 A342 —— 点了一个号的某个账号，它的其它账号就关上：magpie 每 caller 账号白名单移植进 pool（F35）



> 台账号 **T-AG544** ｜ 分区 A（magpie 移植）｜ 树 `.wt/A342` ｜ 层 判据层

> 依据：magpie `internal/access/accounts.go`（`AllowsAccount` `:63-83`、`CleanAccounts` `:21`、

> 「最多 500 条」`:58`、长度 ≤ 300 `:21`）与 `internal/gateway/key_models.go`（`accountHolds` `:51-54`、

> `onKeys` `:334-354`）。台账号/卡号由用户统一分配，本卡不改台账。



## 要解决的问题



pool 有「这个号不许派活」的终态，但**没有**「谁可以用哪些号」这个维；而且它连

「点名了一个 provider 的某个号 ⇒ 同 provider 的其它号全关」这条收窄语义都没有。



1. 现有「不许」判据只有一条，且是**账号自己**的属性：`tools/pool_accounts.py:164-172` 里

   `approved_models = []` ⇒ 抛 `LedgerError`，文案逐字「空数组的含义是「这个号不许派活」，不是「随便用」」。

   实测账本 `D:/repo/infra/pool/accounts.toml` 的 `codebuddy-tongxue3` 就是空数组。

2. 账号选择是「点名一个 profile」：`tools/wb_dispatch.py:2964` 的 `--account`，

   `:505-555` 的 `account_env(name)` 跑仓外 `codebuddy_accounts.py profile env <名>`，

   拿不到就抛错**绝不回空 dict**。⇒ 没有「从集合里挑」这个动作，也就没有「挑的时候过白名单」的位置。

3. 零 per-caller 判据：`grep -rniE "caller|api_key|per-key|held_key" tools/pool/*.py` ⇒ **0**。

4. 同族「只收紧不放宽」的纪律已经在跑，可抄方向：`tools/pool/review.py:24-36 outside_allow(paths, allow)`

   （`fnmatch`，docstring 逐字「空 `allow` = 全越界（调用方负责先判"没给白名单"）」）。

5. ★ **同名不同物**：`tools/pool/guards.py` 里的 `held` 是**门禁锁**（`lock_guard` 判「锁文件里写着谁」），

   与 magpie 的「key 被 hold」毫无关系。写文档、写注释时必须点明，否则下一个人会去改锁的代码。



### ★ 两个「空」是两种意思，不许统一



| | magpie | pool |

|---|---|---|

| 名单为空 | **全允许**（`AllowsAccount` 第 1 支） | **全拒**（`outside_allow` 空 allow = 全越界；`approved_models=[]` = 不许派活） |

| 名单非空 | 只**收窄**点名了的 provider | 只**放行**点名的条目 |

| 被拦后果 | 403 + 一个 code，只影响**读** | 拒派（退 2），影响**做** |



⇒ 本卡在 pool 侧的落地必须是「**没设 = 不收窄**」（否则今天所有派活全挂）+「**设了 = 只能收窄**」

（否则就是放松判据）。两句话都要逐字写进 `accounts_scope.py` 的文件头。



## 判据



1. **新模块 `tools/pool/accounts_scope.py`**（约 130 行，纯读 + 纯函数，零写零网络）：



   ```python

   MAX_SCOPES = 500          # magpie access/accounts.go:58 "A key can list at most 500 accounts"

   MAX_SCOPE_CHARS = 300     # magpie access/accounts.go:21 的长度上限



   class ScopeError(ValueError):

       """scopes 损坏 / 越界 —— 响亮拒绝，**绝不回落到「不收窄」**（回落 = 悄悄放宽）。"""



   @dataclass(frozen=True, slots=True)

   class Scope:

       caller_kind: str          # "card" / "project" / "pool"

       caller_id: str

       patterns: tuple[str, ...] # 形如 ("codebuddy/codebuddy-tongxue3", "codearts/*")



   def load_scopes(path: Path | str | None = None) -> dict[tuple[str, str], Scope]: ...



   def narrow(

       candidates: Sequence[str],

       patterns: Sequence[str],

       *,

       provider_of: Callable[[str], str],

   ) -> tuple[str, ...]: ...

   ```



2. **`narrow()` 的三支逐字照抄 `AllowsAccount`**：

   - `not patterns` ⇒ `tuple(candidates)`（**这一支保证今天的派活不会全挂**）；

   - 逐字命中（**大小写不敏感**，整串 `provider/id`）⇒ 保留；

   - 该候选的 provider 被 patterns **点名过**（有任意一条同 `provider/` 前缀）⇒ **删掉**；没被点名 ⇒ 保留。

   - 结果 ⊆ `candidates`，顺序 == `candidates` 原序（不重排，便于对账）。



3. **`provider_of` 必须注入，不许猜**：id 形状是 `<platform>-<n>`（`codearts-1`、`codebuddy-tongxue3`），

   不是 `platform/id`。实现侧读 `accounts.toml` 的 `platform` 字段。**不许**在 `narrow()` 里用

   「减号前面就是 platform」的启发式（`codearts-doer-1` 会猜错）。这条是设计原件点名的「最容易写错的一处」。



4. **只实现两种 pattern 形态**：`"provider/*"` 与 `"provider/exact-id"`。

   中间/结尾的 `*`（如 `codebuddy/tongxue*`）在 magpie 侧**不存在**（`AllowsAccount` 只有 `HasPrefix`），

   本卡**不许**引入 —— 也不许用 `fnmatch`（`*` 跨 `/`，会让 `codebuddy/*dh*` 意外生效）。

   非法形态 ⇒ `ScopeError`，不许静默跳过。



5. **`load_scopes()` 的读面**：默认读 `infra/pool/account-scopes.toml`（仓外，与 `accounts.toml` 同目录，

   路径复用 `tools/pool_accounts.py:60 ANCHOR = ("infra","pool","accounts.toml")` 的根推导）。

   文件不存在 ⇒ `{}`（= 一条都不收窄 = 今天的行为）；坏 TOML / 越界 / 超 `MAX_SCOPES` 条 / 单条超

   `MAX_SCOPE_CHARS` ⇒ `ScopeError`。**`accounts.toml` 读不到也 `ScopeError`**（不许当成「空名单」）。



6. **新守卫 `tools/pool/guards.py:account_guard`**（纯函数，与 tree/domain/lock/log 同类）：



   ```python

   def account_guard(

       account: object,

       scopes: Mapping[tuple[str, str], object],

       *,

       card: object = "",

       project: object = "",

       pool: object = "",

   ) -> list[str]: ...

   ```



   - 三级 caller 由**窄到宽**：`card > project > pool`。任一层的名单收窄了就按它判，都不收窄 ⇒ `[]`（放行）。

   - `account` 为空 ⇒ `[]`（没点名账号 = 今天的行为）。

   - **只删不增**。

   - `guards.py` 里**不许**出现 `open(` / `Path(` / `print(` / `subprocess` / `os.environ`

     （文件头 `:1-20` 逐字「不写文件、不 print、不起进程」，`tests/test_pool_guards.py:156` 有现成断言写法）。



7. **接入点（两处，必须调同一个函数）**：

   - `tools/wb_dispatch.py` 在**占树之前**（`pool_registry.reserve()` 之前）接一道：

     `if args.account:` → `load_scopes()` → `guards.account_guard(...)` → 非空则 stderr 逐条打印 + `return 2`（零副作用）。

   - `tools/pool_mcp.py` 的 `pool_dispatch` 干跑路径（模型干跑之后、`registry.reserve()` 之前）接**同一条判据**。

     不许另写一份 `if`（`tools/pool/__init__.py:1-25` 逐字「它只 import 本包、不在这里重写判据」）。



8. **反向钉子 `test_reverse_narrow_never_adds`**：把 `narrow()` 第 3 支从「被点名的 provider ⇒ 删」

   改成「⇒ 保留」（整条收窄失效）⇒ 必须变红。现场：`candidates=("codebuddy/a","codebuddy/b")`、

   `patterns=("codebuddy/a",)`，断言结果 `== ("codebuddy/a",)`；改坏后 `b` 留下 ⇒ 红。

## 不许做



- **不许**把名单实现成「白名单放行」（`if account in patterns: pass else: reject`）—— 会让**没写名单的

  caller 全拒**，今天所有派活立刻全挂。正确形态是 `not patterns ⇒ 原样放行`。

- **不许**复用 `tools/pool_accounts.py:164-172` 的 `approved_models = []` 语义当本卡的「空名单」。

  两个空、两种意思，各写一份、互相引用，**不许合并成一个函数**。

- **不许**改 `--account` 的既有语义（点名一个 profile；`account_env` 拿不到就抛错绝不回空 dict）。

  本卡是在它**之后**加一道判，不是把「点名」换成「挑选」。

- **不许**改 `tools/pool/guards.py` 里 `held` / `lock_guard` 的任何一行（同名不同物）。

- **不许**在 `narrow()` 用 `fnmatch`，也不许引入中间/结尾通配。

- **不许**读面隔离（对应 magpie 的 6 个 403）：pool 的 MCP 面没有 caller 身份，强行加「被 hold 就不给看」

  是比 F35 更大的一件事。**如实标「未落地，仅设计」**，不许假装做了。

- **不许**改租约的 12 键或 `reserve()` 的既有参数（`account` 键由卡 A339 统一加，本卡只消费）。

- **不许**碰六份 `PROTECTED_FILES` 与 `docs/workbacklog.toml` / `docs/INDEX.md` / 三个片段目录。

- **不许**动 `tools/pool/registry.py` / `lanes.py`（A339）、`tools/pool/rpm.py`（A340）、
