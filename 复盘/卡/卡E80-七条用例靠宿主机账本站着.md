# 卡 E80 —— 那七条账号用例，靠宿主机上那份仓外账本站着（T-AG583）

> 台账号 `T-AG583` ｜ 分区 E（门禁与可信度）｜ 树 `.wt/E80` ｜ 层 判据层
> 基准提交 `88c46b19`（主树 HEAD，E79 刚落）。

## 要解决的问题（已实测，不是推测）

云门禁 `A354` 那一趟（`gates/diag/cloud-A354c.log`）9 红里，有 **7 条**都在
`tests/test_wb_dispatch.py`，全是同一句：

```
[FAIL] 账号账本读不到，判不出「这个名字是哪个号」⇒ 拒派（不许按原名悄悄派活）：没找到账号账本。
账本本体在仓外：D:/repo/infra/pool/accounts.toml
```

云机上 `C:\infra\pool\accounts.toml` **不存在**（实测 `LEDGER-NO`），这七条就全红；
本机上它存在，所以本机全绿 —— **这七条用例是「靠宿主机上那份仓外账本站着」的**，
判据跟着宿主机的目录形状走，正是卡 E70 判据里那句「判据不许跟宿主目录形状绑定」。

**本机复现（隐藏账本即 7 红）**：

```
$ TF_ACCOUNTS_TOML="C:/nonexistent/accounts.toml" python -X utf8 -m pytest \
    tests/test_wb_dispatch.py -o addopts= -q --no-cov
7 failed, 279 passed, 1 skipped          ← 与云机那 7 条逐字同一批
```

**最小账本可解（已探针验证，`gates/diag/_probe_e80.py`）**：给一份只含
`[[account]]` / `[account.credential]` / `[account.quota]` / `[account.health]`
四段的最小账本、`TF_ACCOUNTS_TOML` 指过去 ⇒ `7 passed in 5.56s`。

★ **为什么不能照卡 E54 的办法「把本机账本推上云机」**：卡 E54 判据逐字（`scripts/cloud/run_gate.sh:121-126`）
写明账本是**私有**的，推上去会让云机的判据输入被本机私有状态污染，反而弄坏
`test_pool_accounts.py` 那两条「账本缺失要报错」。**判据必须自带它需要的输入**，
不是让环境去凑判据。

## 判据（5 条）

1. **七条用例各自把账本钉到自己的沙箱**：`TF_ACCOUNTS_TOML` 指向 `tmp_path` 下的账本
   （用 `monkeypatch.setenv`，自动还原），**不再回落**到 `find_ledger()` 的「向上找」那条。
   ★ 判据：把仓外账本藏起来（`TF_ACCOUNTS_TOML="C:/nonexistent/accounts.toml"`）后，
   这七条**仍全绿** —— 这是本卡唯一的验收口径。
2. **最小账本只有一份**：新增的账本夹具必须是**一个**共享 helper（照既有
   `_use_ledger(monkeypatch, ledger)` 与 `_ledger_with_profiles(...)` 的体例），
   七条用例都调它；**不许**在每条用例里各写一份 TOML 字面量。
3. **不许改产品的找账本逻辑**：`tools/pool_accounts.py:123 find_ledger()` 与
   `tools/wb_dispatch.py` 的 `_account_rows()` / `resolve_account()` **一个字节都不动** ——
   账本真缺失时「拒派并说明三种修法」是**正确行为**，本卡治的是用例，不是产品。
4. **负向用例仍然负向**：`test_missing_profile_refuses_and_names_it`（profile 不存在 ⇒ 退 2 点名）
   与 `tests/test_wb_dispatch.py:3933` 那条「账本读不到 ⇒ 退 2 拒派」**必须保持红/退 2 的形状**，
   不许为了让门绿而把它们改软。
5. **整文件仍全绿**：`tests/test_wb_dispatch.py` 全跑通过，且**在藏掉仓外账本时**也通过。

## 反向变异（≥4 条，每条都要真改坏 → 跑 → 咬住 → `finally` 还原 → sha 核对）
