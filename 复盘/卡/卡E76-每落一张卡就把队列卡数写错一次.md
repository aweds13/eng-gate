# 卡 E76 —— 每落一张卡就把「队列卡数」写错一次：落地链得自己重算它（T-AG579）

> 台账号 `T-AG579` ｜ 分区 E（门禁与可信度）｜ 树 `.wt/E76` ｜ 层 判据层
> 基准提交 `16561fa5`（主树 HEAD，A364 刚落）。

## 要解决的问题（云门禁 pass 实测，不是推测）

云门禁对主树 `16561fa5` 跑了一趟（`gates/diag/cloud-E76b.log`，`host=gates-runner-host`），`pytest` 门 **10 条红**，其中**两条**是同一件事：

```
FAILED tests/test_pool_readme_counts.py::test_real_readme_matches_recount
FAILED tests/test_pool_jobs.py::test_gen_pool_readme_check_is_green
```

原文：

```
[FAIL] 第 83 行：应为 '| 队列卡数 | 312 张（301 done / 11 pending） | …'，
         实际 '| 队列卡数 | 312 张（300 done / 12 pending） | …'
```

**根因**：`tools/pool/landing.py` 第 ⑤′ 步会 `flip_card_status()` 把卡从 `pending` 翻成 `done`、并把 `docs/workbacklog.toml` 加进这一笔 —— 于是**台账的 done/pending 分布变了**，而 `docs/subsystems/pool/README.md` 里那句「队列卡数 | N 张（X done / Y pending）」是 `scripts/gen_pool_readme.py` 从台账**现算**出来的。落地链**从不重算它**（`grep -n "gen_pool_readme\|gen_doc_index" tools/pool/landing.py gates/diag/_land_any.py` ⇒ **零命中**）。

⇒ **每落一张卡，主树的 README 就错一次。** 我在本机实测到同一处：`16561fa5` 落地后 `python -X utf8 scripts/gen_pool_readme.py --check` 报「1 行不一致」，重算后才绿（`301 done / 11 pending`）。今天之所以没红，是因为**本机那趟全量门禁跑在翻账之前**（门禁在 ④，翻账在 ⑤′）—— 也就是说：**判据只在「下一次有人跑门禁」时才说话，而那时已经错了**。

这不是「忘了重算」的一次性失误 —— 它是**顺序缺陷**：翻账（⑤′）在门禁（④）之后，而 README 的现算判据在门禁里。落地链自己改的东西，自己没验证。

## 判据（6 条，逐条可执行）

1. **落地链必须重算现算文档**：`landing.py` 在翻账之后、提交之前，跑 `scripts/gen_pool_readme.py`（不带 `--check`，真写盘）。断言：造一个「翻账会让 README 过期」的场景，跑落地链 ⇒ README 与现算一致。
   ★ 不许只跑 `--check` 然后失败：那是把活推给人。这一条要的是**自己修**。
2. **重算发生在翻账之后**：断言顺序（翻账 → 重算 → 暂存 → 提交）。反证：把重算挪到翻账之前 ⇒ 判据 1 必须红。
3. **`--check` 仍能抓到过期**：`scripts/gen_pool_readme.py --check` 遇到过期必须退非零（这是既有行为，本卡**不许**削弱它）。断言：手工把 README 改错一行 ⇒ `--check` 退非零并点名第几行。
4. **旧链不进提交的东西不许被顺手带进来**：重算只改 `docs/subsystems/pool/README.md` 与被它依赖的现算块；断言这一笔的暂存清单里**没有**意外多出来的文件。
5. **`--commit-only` 也要重算**：那条路从 ⑤′ 起跑、跳过门禁 —— 它**同样**会翻账。断言：`--commit-only` 路径下 README 也被重算。
6. **不许把 README 从门禁判据里摘掉**：`tests/test_pool_readme_counts.py` 的两条钉子一个字不动（反证：删钉子 ⇒ 本卡判据 3 失去意义）。
