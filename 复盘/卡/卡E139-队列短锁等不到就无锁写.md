## 缺口（逐条实测，不是推测）

### 缺口 1 · `tools/gate_pool.py:217-254` ‑ 锁等不到就无锁往下写

原文（:218-238，节选；注释 `←` 是立卡时加的）：

~~~python
@contextlib.contextmanager
def locked(self, timeout: float | None = None):
    """读改写期间的短锁（`<队列>.lock`，`O_CREAT|O_EXCL`）；超时照样往下写。

    与 `tools/pool/queue.py::_locked` 同一套语义：这把锁保护的是「读 → 改 → 写回」
    这几毫秒，**不是**门禁锁。
    """
    lock = self.path.with_suffix(self.path.suffix + ".lock")
    lock.parent.mkdir(parents=True, exist_ok=True)
    wait = self.timeout if timeout is None else float(timeout)
    t0 = time.time()
    fd = None
    while True:
        try:
            fd = os.open(str(lock), os.O_CREAT | os.O_EXCL | os.O_WRONLY)
            break
        except FileExistsError:
            if time.time() - t0 >= wait:
                break                      # ← 等满了：fd 仍是 None，照样往下走
            time.sleep(0.02)
    try:
        yield
    finally:
        if fd is not None:                 # ← fd 是 None 时 finally 什么也不做
            ...
~~~

调用方（:282-318 `submit`、:320-340 `promote`、:342-373 `mark_done`）一律是 `with self.locked():` → `state = self.load()` → 改 → `self.save(state)`。
`with` 正常退出 ⇒ 两个线程同时进了「读→改→写回」那段临界区 ⇒ 后写的把先写的整份覆盖。
这个类自己的 docstring（:181）写着「**原子替换**：每次读改写后 `tmp + os.replace`，别的进程读到的永远是完整的一份」—— 原子替换保证的是**文件不残缺**，不是**行不丢**；丢行是读改写竞态，不是撕裂。

实测（立卡前，`timeout=0.0`，12 线程 × 5 轮 = 60 次 `submit`）：队列里最后只有 **5 行**。

### 缺口 2 · `tools/gate_pool.py:231` ‑ `os.open(O_CREAT|O_EXCL)` 在 Windows 上抛的是 PermissionError，不是 FileExistsError

原文（:229-236）只 `except FileExistsError`：

~~~python
        except FileExistsError:
            if time.time() - t0 >= wait:
                break
            time.sleep(0.02)
~~~

但 Windows 上持有者正在 `lock.unlink()` 的那一瞬，`O_CREAT|O_EXCL` 抛的是 `PermissionError [WinError 5]`，异常直接冲出 `with`，整条 `submit` 失败。

实测（12 线程 × 5 轮，**默认 timeout=30.0**）：

~~~
A: timeout=30.0 提交 60 次 / 落在队列里 59 行
   ×1  PermissionError @ gate_pool.py:231 locked <- contextlib.py:141 __enter__
~~~

⇒ **这不是只有 timeout=0 才有的病**：默认 30 s 下同样丢行，只是概率低（这组 60 次丢 1 次）。这一条是用户现场清单里没有的第三个面，也是「负载相关 flake」最可能的真身。
概率也单独量过：3 条线程对锁文件 churn（建 → 立刻 unlink）3 秒，计数 `{'exists': 1974, 'perm': 56, 'ok': 250}` ⇒ 建锁尝试里约 **2.46%** 撞 PermissionError。
`tools/pool/ledger.py:37-40` 早把这条写进自己的纪律：「**PermissionError 也当「有人在写」**：Windows 上持有者正在 `unlink()` 的那一瞬，`O_CREAT|O_EXCL` 抛的是 `PermissionError [WinError 5]` 而不是 `FileExistsError`（实测 8 写者连跑第 2 轮就撞一次）」—— 两个队列实现都没抄这一条。

### 缺口 3 · `tools/pool/queue.py:141-170` ‑ 同族实现，同一个 break，同一处不响

原文（:142-170，节选；注释 `←` 是立卡时加的）：

~~~python

    ...

      调度饥饿打穿过，等满就无锁写、把行盖掉。

    lock = state_path(root).with_suffix(".lock")
    lock.parent.mkdir(parents=True, exist_ok=True)
    t0 = time.time()

            fd = os.open(str(lock), os.O_CREAT | os.O_EXCL | os.O_WRONLY)

            if time.time() - t0 >= timeout:
                break                      # ← 同款：等满了照样往下走
~~~

实测：`timeout=0.0` 下 10 轮 **10 轮丢行**；`timeout=30.0` 下 0/10。

## 判据

> 每条都可机器验证：给定命令、给定退出码、给定文案片段。「看起来对了」不算过。

### 判据 1 · 锁等不到 ⇒ 失败关闭（不许无锁写）

- **断言**：锁文件已被别人持有时，`PoolQueue(path, timeout=0.0).submit(...)` 必须抛一个**点名的**异常（建议 `class GatePoolBusy(GatePoolError)`，与 `:167 GatePoolUnreadable` 同族），**且队列文件字节不变**（`read_bytes()` 前后相等）。
- **文案三要素**（缺一即红）：
  1. 等了多久 —— 形如「等了 30s」，数值来自实参 `wait`，不许硬编码；
  2. 锁文件在哪 —— 完整路径；
  3. 谁可能还持着 —— 一句可操作的指认（建议把锁文件里写的 pid/host 读进消息；读不到就明说「读不到持有者」）。
- **钉子**：`tests/test_gate_pool.py::test_locked_timeout_fails_closed`（新建）。手造 `q.json.lock`（直接 `write_text`，或用既有 `_exclusive()` 夹具）⇒ `pytest.raises(gp.GatePoolBusy)` + 三条 `in str(err.value)` + `assert q.path.read_bytes() == before`。
- **什么情况下红**：任何一次「等满却写了」—— 包括 `finally` 里 `fd is None` 悄悄放过。
- **失败分支**：异常类型定义在 `gate_pool` 模块级（不许造在测试里），测试只 import。

### 判据 2 · os.open 的 PermissionError 与 FileExistsError 同路

- **断言**：`locked()` 建锁循环里 `except (FileExistsError, PermissionError)` 走**同一条**「等 → 到期 → 失败关闭」的路；PermissionError **不许**冲出 `with`。
- **钉子**：`tests/test_gate_pool.py::test_locked_permission_error_is_busy_not_crash`（新建）。`monkeypatch` `os.open` 头一次抛 `PermissionError(13, "Permission denied")`、之后成功 ⇒ 断言 `submit` 正常完成（不抛、行写进去了）；反向：一直抛 ⇒ 抛 `GatePoolBusy`，文案含锁路径。
- **什么情况下红**：`except FileExistsError` 单独一路（现状）⇒ 这条钉子直接红。
- **失败分支**：PermissionError 分支必须保留轮询间隔（`time.sleep(0.02)` 不许删），否则变成热转。

### 判据 3 · write_atomic 的两处 os.replace 都有界重试（:131 与 :300）

- **断言**：照抄 `tools/pool/ledger.py:335-358` 的口径 —— `tries: int = REPLACE_TRIES`（`:87 = 5`）、`base: float = REPLACE_BASE_S`（`:88 = 0.02`，第 n 次等 `base * (i + 1)`），**只对** `PermissionError` 重试、其它 `OSError` 立刻抛；`tries <= 1` 退化成单次尝试（`ledger.py:343` 原话「反向变异就靠这个参数把重试撤掉」—— 必须保留）；最终抛时消息含「原子写失败（N 次）」+ 路径 + 最后一次的 errno 名。
- **两处都咬**：`_copy_bytes_atomic`（:131，`.bak` 那一跳）与 `write_atomic`（:300）**各一条钉子**；只改一处不算过。
- **钉子**：`tests/test_pool_lastgood.py` 新增两条（照 `tests/test_ledger_lock.py:409-431` 的形状：monkeypatch `os.replace` 首调抛 ⇒ `calls == 2`）+ 一条放弃路径（`tries=3, base=0.001` ⇒ `pytest.raises(...)` 且 `list(tmp_path.glob(".*.tmp")) == []`，照 `tests/test_ledger_lock.py:434-447`）。
- **什么情况下红**：`os.replace` 一行 try 都没有 ⇒ 两条重试钉子红；只给 :300 加重试不给 :131 ⇒ `.bak` 那条红。
- **诚实边界（必须写进卡，不许含糊）**：重试只把「必抛」压成「少数仍抛」，**不是零**。实测 20000 B + 1 个并发读者：无重试 19/60 失败 → `tries=5/base=0.02` 后 3/60 失败；读者 2 个时 `tries=10/base=0.05` 仍 64/120 失败。**不许**在文案或注释里承诺「不再抛」。

### 判据 4 · 两条同族实现口径一致，一颗钉子同时咬两边

- **断言**：`gate_pool.PoolQueue.locked` 与 `pool/queue.py::_locked` 在「等不到」这件事上**同一种结局**（都抛、都失败关闭、都不写），且两边 `LOCK_WAIT_S` 仍同值（既有钉子 `test_queue_lock_wait_defaults_agree` 守着，不许削弱）。
- **钉子**：`tests/test_pool_queue.py::test_locked_timeout_fails_closed`（新建，与判据 1 的钉子**同形**）+ `test_two_families_agree_on_give_up`：参数化 `[(gp.PoolQueue, "locked"), (queue_mod, "_locked")]`，两边都用 `timeout=0.0` + 被占的锁文件，`pytest.raises` 同族异常，且两边异常消息**都**含锁路径。
- **什么情况下红**：只改一边 ⇒ 参数化里那一边红；两边异常类型不同族 ⇒ 判据 4 第二条红。
- **失败分支**：允许两模块各自定义异常（`GatePoolBusy` / `QueueBusy`），但**必须**都继承各自模块基类，钉子里用元组断言；不许为省事让 `tools/pool/queue.py` import `tools/gate_pool.py`（依赖方向不变）。

### 判据 5 · 并发不丢行，且异常被收集（既有钉子加强，不许削弱）

- **断言**：`tests/test_gate_pool.py:88-109` 保留 12 线程 + `threading.Barrier(n)` + `n_slots=6`，新增 worker 里的 `try/except BaseException as exc: errs.append(exc)`，末尾 `assert not errs, f"线程里抛了 {len(errs)} 次：{errs[:3]}"`，且 `assert len(commits) == n` 的原文案（`丢了行：只看到 …`）与 `assert len(running) == 6` 都保留。
- **稳定性要求**：该用例连跑 **30 次**必须 30 次全绿（命令见验收）。这是本卡唯一一条**统计性**判据 —— 它不证明「永不丢」，只证明「30 次没丢」；卡里要如实这么写。
- **什么情况下红**：任一线程抛异常（缺口 2 现状）⇒ `errs` 非空；任一行没写进去 ⇒ 原断言红。
- **失败分支**：`errs` 只收集异常对象，不许在 worker 里 `print` 了事；`Barrier` 与线程数一个都不许动（E55 :51 已明令）。
