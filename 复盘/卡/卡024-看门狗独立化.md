## §2 口径（要做什么）

### 2.1 ★★ 待主控定：走哪条架构（三选一）

- **A 双进程互盯**：`--detach` 时起**两个**进程（跑工人的 + 只盯看门狗的），互相探活，
  任一被杀另一个接管（掐工人 / 落判决 / 触发续跑）。
  代价：最稳，但 Windows 上"谁来盯盯人的"容易做成三体问题；探活间隔与判定要标定。
- **B 看门狗进程独立**：看门狗做成独立小进程（只读 log 文件 + 按 PID 文件掐树），
  派活进程死了它还在。
  代价：中等；必须定义"看门狗自己被杀"的发现机制与**孤儿看门狗的退出条件**
  （工人正常收工后它必须自己退 —— 否则留下永久后台进程 = 用一个新问题换一个旧问题）。
- **C 接受现状 + 兜底告警**：不做进程级独立，给 `--status` 加"心跳停滞超过 X 分钟 →
  打印醒目告警"，由主控/用户的定时调用兜底。
  代价：最便宜，但只是"看得见"，不是"有人管"。

### 2.2 无论选哪条

- **判据必须有牙**（突变检验）：改坏"看门狗活着 / 会掐"的那条接线 → 用例红
  （复核 1969b46 §2.2 的 M5/M6 假护栏教训就在这个文件：删掉接线 50 passed 全绿）。
- **真机证据必须含这一步**：杀掉"跑工人的那个进程" → 看门狗仍然掐掉工人/落判决
  （**按 PID** 杀，绝不按进程名 —— 卡表 §8-3：按名字会误杀用户自己的程序）。
- 不许动的：看门狗判据本体（`watchdog_verdict` / `inflight_tool` / `tool_durations` /
  `stall_threshold_seconds`，T-G94/T-G96 定的口径）、心跳与判决的落盘格式、
  `--status` 只读文件的原则。

## §7 已知的坑

1. ★ **Windows 进程常量**：自起的 `subprocess` 加 `CREATE_NO_WINDOW`、脱离的用
   `DETACHED_PROCESS | CREATE_NO_WINDOW`（T-G96-⑥ 的口径：不留空控制台窗口迷惑用户）。
2. ★ **掐树按 PID**（`kill_tree`，`:863`；整棵进程树），绝不按进程名 ——
   按名字会杀掉用户正在用的程序（卡表 §8-3，真踩过）。
3. **孤儿看门狗是新的坑**：没有退出条件的独立看门狗 = 永久后台进程 —— §5-③
   那一步不做，方案 B 就不完整。
4. **探针手法已有现成的**：T-G91 的 `spawn_detached` 真机探针（子进程活过父进程 +
   输出落盘）与 T-G94 的压缩阈值桩（`--stall-seconds 20` 如实记）都照抄，
   别另发明一套。
