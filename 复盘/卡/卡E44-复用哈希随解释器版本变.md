# 卡 E44 —— 复用哈希随 Python 版本变（`X/**` 在 3.12 里不匹文件）＋ 假门依赖 `sleep`

- 层：工具层
- 树：`.wt/E44`
- 分区：E
- 风险：high（改的是「门禁输入哈希」本体 —— 它对不上，复用结论就是注释）

## 1. 疼在哪（云机 pass1 实测，不是推测）

云机 `pytest` 33 红里最大一类（10 条）是 `tests/test_gates_reuse_line.py` 报
`AssertionError: assert 'e3b0c44298fc1c14' != 'e3b0c44298fc1c14'` —— `e3b0c44298fc1c14`
是 **sha256("")**。在云机上直接复现：

```
ROOT= C:\eng
hash= e3b0c44298fc1c14
hits= ['C:/Users/Administrator/AppData/Local/Temp/tmpvw_7xee9/src']   # 只有目录，没有 src/probe.py
```

**根因**：`scripts/run_gates.py:475` 的 `input_hash()` 用 `ROOT.glob(pattern)` 展开门输入。
`X/**` 的语义**随解释器版本变**：

| 解释器 | `Path.glob('src/**')` 返回 |
|---|---|
| 本机 3.14.6 | `src`（目录）+ `src/probe.py`（文件） |
| 云机 3.12.8 | 只有 `src`（目录） |

`input_hash` 里 `if p.is_file()` 把目录滤掉 ⇒ **3.12 上每一道门的输入哈希都等于
sha256("")**。后果不是红，而是**静默**：`skip_reused()` 拿常量与 `gates/reuse.json`
里的记录比，「一个字节都没变」恒成立 ⇒ 改了 `src/**` 也照样复用上一次的绿。
判据变成注释，而这正是 `tests/test_gates_reuse_line.py` 文件头点名要防的事。

同一趟里第二类（4 条 + 若干）：`AssertionError: 本机 PATH 里没有 sleep，假门造不出来` ——
`tests/test_run_gates_timeout.py` 的 `_sleep_cmd()` 用 `sleep <秒>` 造假门，Windows 上没有这个
可执行文件（本机有 Git Bash 的 `sleep`，云机只有裸 Windows）。

## 2. 要做成什么样

### 2.1 哈希口径与解释器解耦（主要工作）

`input_hash()` 不再依赖 `Path.glob("X/**")` 的版本语义，改成**自己展开**：

- 图案以 `/**` 结尾 ⇒ `(ROOT / 前缀).rglob("*")`（3.9+ 语义稳定），只收 `is_file()`；
- 其余图案（`gates/render/*.txt`、`tools/serve.py`、`src/web/**`）保持 `ROOT.glob()`，
  但同样先判 `/**` 后缀；
- 生成物过滤（`is_generated()`）与 CRLF 归一（`replace(b"\r\n", b"\n")`）**一行不改**；
- 排序键、`path.relative_to(ROOT).as_posix()`、`[:16]` 截断全部不变 ⇒ **哈希值对本机
  （3.14）逐字不变**，只把 3.12 拉回同一口径。

### 2.2 版本门槛写进判据（防再犯）

- `scripts/run_gates.py` 启动时断言 `sys.version_info >= (3, 11)`（仓库 `pyproject.toml`
  的 `requires-python` 同源），并在 `gates/last.json` 的 payload 里记
  `python: "3.12.8"` 一行 —— 让「这份绿是哪版解释器跑的」有据可查。
- `scripts/cloud/bootstrap.ps1` 的 Python 版本**钉到与本机同一条线**（3.13/3.14 之一），
  或在文件头注明「低版本会让 `input_hash` 退化成常量」并强制升。

### 2.3 假门换成跨平台

`tests/` 里所有「假门」用例改用 `python -c "import time; time.sleep(N)"`（或
`sys.executable`），不再依赖 PATH 上有 `sleep`。

## 3. 判据

1. `tests/test_gates_reuse_line.py` 新增 ≥3 条钉子：`X/**` 展开同时命中更深层文件
   （`src/a/b/c.py`）、`.rglob` 路径与旧 `glob` 路径**对 3.14 结果集逐字相同**（用固定假树比对）、
   生成物仍被排除。
2. `tests/test_run_gates_timeout.py` 在 **Windows 且 PATH 无 `sleep`** 的环境下全绿
   （用 `monkeypatch.setenv("PATH", 只剩系统目录)` 造该环境，不许靠「本机恰好有」）。
3. 反向验证：把 `input_hash` 改回 `ROOT.glob(pattern)` 单一路径 ⇒ 新增钉子①红；
   把假门改回 `sleep` ⇒ 钉子②红。两条都要贴红原文。
4. `gates/last.json` 的 payload 含 `python` 字段；`tests/test_run_gates_payload.py`
   （或同族）钉住它存在且形如 `\d+\.\d+\.\d+`。
5. 全量门禁 `exit 0`，且 `gates/reuse.json` 里 5 道可复用门记录在**同一份提交**上
   本机与云机**哈希一致**（拿 E42 的云机池跑一趟对比）。

## 4. 不许做

- 不许把 `X/**` 直接换成 `X/**/*` 了事（`rglob` 与 glob 的边界含隐藏目录、符号链接，
  会悄悄改变输入集合）。
- 不许为了让云机绿就把那 10 条钉子改成 `skipif` —— 它们抓的正是本卡要修的缺陷。
- 不许在 `input_hash` 里吞掉读文件异常（现在读不到就空，正是「静默」的来源）；
  读失败要抛，让门禁红。
- 不许改 CRLF 归一与生成物过滤（那是 T-G181 已定的口径，本卡不动）。

## 5. 证据

- 云机 pass1 `gates/diag/cloud-E35-pass1/logs/pytest.log`：33 条 `FAILED` 全清单
  （10 条 `e3b0c442…`、4 条 `没有 sleep`、~14 条池索引仓外、2 条 `test_mem_guard`、
  其余零散）。
- 云机复现片段（上文 `hits=` 那三行）与解释器版本 `Python 3.12.8`；本机 `Python 3.14.6`。
- `scripts/run_gates.py:447-482`（`input_hash` 全文，含 T-G181 的生成物过滤与换行归一）。
