## 要解决的问题

**不经过派活器的调用，今天完全不进账。** 有人直接拿 supply 的 key 调一次模型，那笔钱和那些 token
在 `gates/diag/wb-usage.jsonl` 里**一个字节都没有** —— 因为它只由 `append_usage_line()` 在派活收工时写。
于是「这个模型今天用掉多少」这个数在「有外部直连」的日子里系统性偏小，而它正是整窗估算的分子。

magpie 用 `POST /v1/magpie/usage/requests` 收这种记录（`source: "reported"`），并且**用七处分别排除**
保证「上报行一条都不放宽任何限额」—— 因为上报的可能是很久以前的补录，那些调用根本不是它路由的。

本卡把**判据层**整块搬过来（全有或全无 / `rid` 幂等 / 上报行单列 + 默认不计入），
只替换传输层（HTTP ⇒ CLI / 纯函数入参），如实标注传输层未移植。

3. **`parse_batch(text: str, *, now: datetime) -> list[dict]`：解析 + 全量校验，一条坏 ⇒ 整包拒。**
   抛 `IngestRefused(faults)`，`faults` 是 `list[Fault]`；`Fault` 是 `@dataclass(frozen=True)`
   带 `index` / `field` / `msg`，`error_text()` 逐字 `f"{field}: {msg}"`（`index < 0`）或
   `f"record {index}: {field}: {msg}"`（照 `usage_ingest.go` 的 `ingestFault.Error()`）。
   `[]` ⇒ `Fault(-1,"body","the array has no records")`；>5000 条 ⇒ `Fault(-1,"body",f"{n} records: send at most 5000 a post")`；
   不是 `[` 也不是 `{` 开头 ⇒ `"send a JSON record, or an array of them"`；字节数 > `MAX_BODY` ⇒ 一句带两个数字的文案。
4. **单条校验的判据逐条照 §「判据表」**（见下），顺序即优先级，**报错文案逐字英文照抄**（文案稳定是 magpie 的设计目标，
   `usage_ingest.go:210` 先 `slices.Sort(keys)` 就是为了「同一个坏 body 永远得到同一个 index/param」）。
   `err` 是唯一豁免 256 字符与控制字符的字段（照 `:225` / `:231` 的 `k != "err"`）。
5. **`ingest(text, *, now=None, root=None) -> dict`：全有或全无 + `rid` 幂等。**

   拒单时**目标文件的行数与 mtime 都不许变**。
   `_known_rids(path)` 从**日志本身**读回已报过的 rid（先 `if REPORTED_MARK not in line: continue` 再 parse，
   照 `reported.go:31` 的字节标记法）；同一批内重复的 `rid` 也跳过（照 `:108` 的 `batch[rid]`）。
   **不许**为 `rid` 另立索引文件（两个真源，删一份就让已报过的行复活）。

## 缺口（如实说，不许当成已解决）

1. **传输层未移植**：magpie 的 415（Content-Type 不对）/ 413（超 32 MiB）/ 403（浏览器页无 key / held key）三条判据属于 HTTP 层，
   pool 没有 HTTP 面 ⇒ **未落地，仅设计**。本卡只保留「字节数超 32 MiB」这一条与传输无关的量。
2. **读端没接线**：`merged_tokens()` 今天**零生产调用方** —— `usage_in()` 还没加 `include_reported` 参数（`tools/wb_dispatch.py`
   正被 A342/A344/A345 改）。下一张卡做接线。
3. **`cost` 只存不核**：pool 无价目表，上报方给的 `cost` 原样存，不重定价，也不参与任何判据。
4. **`wb-usage.jsonl` 与上报账是两本账**：任何「今天这个模型用掉多少」的既有读者（`usage_summary` / `usage_in`）
   看到的仍然只是派活器那本。这是**有意**的（单列），但也意味着「外部直连的账在界面上仍然看不见」。
5. **`_known_rids()` 每次全扫**：文件会长到几十万行，两段式（锁外一次 + 落盘前一次）照抄 magpie，
   但 pool 没有 magpie 的 `info`/`off` 增量位点（`reported.go:51`），本卡不做增量。
