### 2.5 ★★ 429 / 额度耗尽：等一会儿 → 按序换 → 全挂就**停**

⚠ 先记现场：429 **看起来像成功** —— CLI 给 `result.subtype = error_during_execution`、
**回复为空**、**退出码 0**。所以**不许**只看退出码。

- **认出它**：从 `result.errors` / `errors_info` 里认 `status == 429`（`code 6004` / `category quota`），
  或正文含 `额度已用尽` / `使用量已超出频率限制`。★ 两种要**分开记**：
  **限流**（带「将在 <时间> 重置」）vs **余额耗尽**（没有重置时间）。
- **不许 retry**：命中 429 → **不许**在这上面走 `--retry` 自动续跑（那是拿仅剩的额度空撞）。
- **先等一下**：`--quota-wait`（默认 **300 秒**）睡完**再探**（探 = 一次**极小代价**的可用性探测，
  ★ 别把整卡重跑一遍当探测）。
- **按序换**：还挂 → 取**白名单里的下一个**（顺序 = 清单顺序）重派。★ **不许**跳到表外模型。
- **全挂就停**：白名单里**每一个**都 429 → **把任务停下来**：写一份醒目判决
  （含**每个模型的**重置时间、这次一共烧了多少 token）、**退出码 7**，并且**不再自动重试**。
  ★ 用户原话：「都有问题的话，就直接把任务停下来」—— **不是**「换个模型接着干」。

### 2.10 ★ `--resume` 被「工作区干净」前置检查**卡死**（本轮真撞的，必须修）

**现场**：卡 022 把活干完后**故意没提交**（它撞到白名单外的红灯，按规矩**停手报主控**）→

```
  · 工作区不干净（4 个被跟踪文件有改动）→ 一写一读：先提交或收起它们
```

★ 而 `--force` **不管这个**（它只允许覆盖 log）→ 于是「**工人留下未提交改动、主控要续跑**」
这条**正常路径被堵死**，主控只能绕过派活器直接调 CLI（本轮就是这么办的）。

**要做的**：

- ★ **续跑时**（`--resume <id>` 或 `--resume auto` 拿到了 id）**不适用"工作区必须干净"** ——

- ★ 但**不能不看**：改成**打印 + 记录**：把 `git status --porcelain` 原文打出来，
  再加一行「★ 续跑：工作区带着 N 个未提交改动（上一轮的活），继续」→ **放行**；
- ★ **非续跑**（全新一轮）**保持原判据**（必须干净）—— 那是"一写一读"的护栏，**不许松**；
