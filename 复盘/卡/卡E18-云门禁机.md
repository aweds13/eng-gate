# 卡 E18 · 云门禁机：多会话共享的一台机器，口径与停机护栏（T-AG470）

> 分区 E（CI 子系统）· 无依赖（文档 + 体检脚本各一件，都不碰落地链判据）

## 现在疼在哪（实测）

1. **云机不是"我的电脑"，是共用 CI 资源**。今天这台本机已经说明问题：`gates/diag/gates-9361.lock`
   是一把**本地文件锁**，多会话/多 Agent 同时落地时谁先拿到谁跑，另一个只能干等 90 分钟——
   而 `tools/pool/landing.py` 调 `gate_lock.py acquire` 用的是 `capture_output=True`，
   **等锁进度全被吞掉**（今晚我误判成"卡死"白等 28 分钟，卡 E16 已立）。
   换到云机，问题变成：**别的窗口看不见这把锁，也不知道云机现在有没有人在跑门禁。**
2. **停机 = 死主锁**。按量付费 ECS 停机不收实例费（只收盘），所以"用完就停"是对的钱包选择；
   但一停，正在跑的落地就变成"死主留下锁"，租约 **10800 s（3 小时）**内谁都拿不到门禁（T-G169 的陈旧判定只看租约）。
3. **合流只有一条绳子**：落地 ⑦ 是 `--ff-only`，一次只能一个。今天两次同文件卡（E2/E4 同改
   `scripts/run_gates.py`、F3/F4 同建 `scripts/check_docs.py`）都要 realign 重放，跨机后会更容易撞。
4. **封存指纹是单机的**：`gates/last.json` 里 `rev` 必须是这一笔的父提交（`tools/wb_review.py:182`）。
   两台机器各跑一遍门禁、各自写 `last.json`，后写的会盖掉前写的 —— 没有一条"谁算数"的规矩。

## 你要做的事

写一份口径 + 一个体检脚本，**两件都不改落地链判据**：

1. **口径文档** `docs/subsystems/ci/云门禁机.md`，必须写清四件事，每条都要带"怎么验"：
   - **谁算数**：全量门禁与封存只认**跑门禁那一台**的 `gates/last.json`；另一台不许覆盖、不许自己 commit
     合流只走「云机 push → 本机 `ff-only`」（现在 `git remote -v` 为空，这是前提，不是建议）。
   - **谁在跑**：云机上同一时刻**只许一趟全量门禁**（本地锁 + `TF_GATE_MAX_CONCURRENT=2` 是上限不是目标）；
     另一个会话要么排队（`tools/wb_task.py register` 到 `awaiting-commit` 等）、要么去派活。
   - **什么时候能停**：停机前必须**没有**在跑的落地、没有未释放的门禁锁、没有 `awaiting-commit` 的任务；
     满足才允许 `shutdown`，否则拒绝并点名"谁在占"。
   - **开机做什么**：自启服务只做三件——`git fetch` + `ff-only` 拉主树、`gate_lock.py` 体检、起
     `tools/auto_land.py` 常驻收口器（卡 233 / T-G350，零 LLM，四态：无批 / 内存紧 / 门禁红 / 该落）。
2. **体检脚本** `scripts/check_cloud_box.py`（新文件，只读，`--check` 退 0/1，`--json` 给机器读）：
   - 打印：主机名/内核/CPU/内存/可用磁盘、`git` 版本、当前分支与 HEAD、`git remote -v` 是否为空、
     门禁锁（`gates/diag/gates-*.lock` 的 `card/pid/已持有秒数/持有者是否活着/剩余租约`）、
     `gates/last.json` 的 `ok` 与 `rev` 是否等于 `HEAD^`、有没有 `awaiting-commit` 的任务；
   - **判断不了就写 `not verified`，不许猜**（例：锁文件缺 `pid` 字段 ⇒ 写 `not verified`，退 1）；
   - 任一项不满足（例如有锁但持有者已死、`last.json.rev != HEAD^`）⇒ 退 1 并逐条点名。
3. **不用实现关机/开机**：本卡只交"口径 + 体检"，真关机脚本留给后面单独一张卡（避免一张卡跨两件事）。

## 判据（机器可判）

1. `python -X utf8 scripts/check_cloud_box.py --check` 在干净主树退 0；造一个"持有者 pid 不存在"的锁文件后退 1 并点名该锁。
2. 造 `gates/last.json` 里 `rev` 不等于 `HEAD^` ⇒ 退 1，报行含 `rev` 与 `HEAD^` 两个实际值。
3. 锁文件缺 `pid` 字段 ⇒ 报行含 `not verified`，**不许**判成"死主"。
4. `--json` 输出的键与本卡枚举一致（`host/os/cpu/mem/disk/git/head/remote/locks/seal/tasks`），缺来源的键给 `null` 并带 `why`。
5. 文档里四件事各有"怎么验"的命令（可被 G1 的尺子核住：命令与参数必须真存在）。

## 钉子（≥4 条，`tests/test_check_cloud_box.py`）

1. 干净仓 + 无锁 + 正确封存 ⇒ `--check` 退 0。
2. 假锁（pid 不存在）⇒ 退 1，退出信息里出现该 pid。
3. `rev` 不等于 `HEAD^` ⇒ 退 1。
4. 锁缺 `pid` ⇒ 出现 `not verified`，且**不**出现"清掉/死主"字样。
5. `--json` 是合法 JSON 且顶层键齐全。
