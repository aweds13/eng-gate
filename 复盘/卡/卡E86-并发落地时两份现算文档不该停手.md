# 卡 E86 —— 并发落地时两份现算文档不该让整笔停手（T-AG593）

> 台账号 `T-AG593` ｜ 分区 E（门禁与可信度）｜ 树 `.wt/E86` ｜ 层 判据层
> 基准提交 `1671a432`（主树 HEAD）。

## 要解决的问题（已实测，不是推测）

卡 E85 的第二次落地（`gates/diag/land-E85b.log`）走到了最后一步 ff 合流，因为主树在此期间被
**另一笔**推进过，落地链按判据先 rebase：

```
34:  rebase 冲突（并发两笔都动了共享文档 / 门禁产物）： docs/INDEX.md · docs/changelog.md ·
     docs/subsystems/pool/README.md · docs/traceability.toml · gates/last.json · 复盘/交接-重构进度.md
35:  ★★ 自动解决不了 ⇒ **停手**： ["冲突里有**非派生物**（必须人来判）：
     ['docs/INDEX.md', 'docs/subsystems/pool/README.md']"]
```

退出码 **3**。可这六份里**每一份**都是落地链自己会重算的：

| 冲突文件 | 谁生成 | 落地链哪一步重算它 |
|---|---|---|
| `docs/traceability.toml`、`docs/changelog.md`、`复盘/交接-重构进度.md` | `tools/sync_docs.py` | ② |
| `docs/subsystems/pool/README.md`、`docs/INDEX.md` | `scripts/check_derived_docs.py`（真写盘） | ⑤′.5 `recount_derived()` |
| `gates/last.json`、`gates/reuse.json` | 门禁自己 | ④ |

冲突的判定在 `tools/pool/landing.py:169 resolve_derived_conflicts(wt)`：

```python
79: DOCS = ("docs/traceability.toml", "docs/changelog.md", "复盘/交接-重构进度.md")
80: GATES = ("gates/last.json", "gates/reuse.json")
89: DERIVED = DOCS
90: GATE_ARTIFACTS = GATES
102: RECOUNT_DOCS = ("docs/subsystems/pool/README.md", "docs/INDEX.md")
182: extra = [x for x in conflicted if x not in DERIVED and x not in GATE_ARTIFACTS]
184: return False, [f"冲突里有**非派生物**（必须人来判）：{extra}"]
```

`RECOUNT_DOCS`（`:102`）与 `DERIVED`（`:89`）是**两张互不相交的表**，而前者同样是落地链
自己会重算的产物 ⇒ 只要主树动过这两份，并发落地就**必然**停手等人判。判据把「机器能重算的
投影」当成了「必须人来判的代码冲突」。

代价（实测）：E85 那次停手后，我手工做了 `git checkout --ours` × 5 + `--theirs` × 1、
`git add`、重跑三个生成器、`git rebase --continue` 共八条命令才走完 —— 每一步都是判据
已经知道答案的事。

★ 与本卡相邻但**不同**的两件事（不在本卡范围，别混进来）：
  · 卡 E85 落地暴露的「先 `sync_counts` 后翻账 ⇒ `复盘/交接-重构进度.md` 分布恒差一」
    —— 那是**计数时序**，与冲突判定无关；
  · 当前 `DERIVED` 那三份取的是 `--ours` 再 `sync_docs`，本卡新增的这两份**必须**走同一条
    路（取基线 + 重跑生成器），**不许**只取 `--ours` 就算解决（那会把本笔新增的
    `docs/changelog.d/*.md` 漏进索引，索引当场过期）。

## 判据（6 条）

1. **两张表合成一张「可重算」口径**：新增常量 `RESOLVABLE = (*DERIVED, *RECOUNT_DOCS)`，
   `resolve_derived_conflicts()` 的 `extra` 判定改用 `RESOLVABLE`（而不是 `DERIVED`）；
   `DERIVED` 与 `RECOUNT_DOCS` 两个名字**保持不变**（别处按名字引用它们）。
   ★ 判据是可测的：把 `docs/INDEX.md` 放进冲突集合，`extra` 必须为空。
2. **取基线 + 重算，不是只取基线**：对 `RECOUNT_DOCS` 里的每一份，先 `git checkout --ours`，
   再**真跑**一遍重算 —— 走 `DERIVED_CHECKER = "scripts/check_derived_docs.py"` 的**写模式**
   （不带 `--check`），以子进程方式、cwd = 卡树。
   ★ 不许在这个函数里另立现算口径（不数行数、不扫目录、不算篇数）—— 那套口径只有
     `scripts/gen_pool_readme.py` / `scripts/gen_doc_index.py` 有，重算判定必须与它们同源。
3. **重算后必须复核，失败要响亮**：紧接着跑 `scripts/check_derived_docs.py --check`，
   非零 ⇒ `return False, [...]` 并**点名是哪一步**（与人判停手同一条出口，不许吞成成功）。
4. **`git add` 的名单跟着变**：函数末尾 `add = [p for p in (*RESOLVABLE, *GATE_ARTIFACTS)
   if p in conflicted]` —— 新纳入的这两份必须进暂存，否则 `rebase --continue` 之后工作区
   仍有 `UU`（本卡实测：`checkout` 之后不加 `git add`，`git status --porcelain` 照样显示 `UU`）。
5. **冲突里有真代码时仍然停手**：把 `tools/pool/landing.py` 自己放进冲突集合 ⇒ 必须
   `return False`，且原因串里点名该文件。这条是**反向保护**：放宽的只能是「可重算的投影」，
   绝不外溢到源码。
6. **既有行为一字不变**：`DERIVED` / `GATE_ARTIFACTS` 的取法（`--ours` + `sync_docs` /
   `--theirs`）、失败文案、`sync_docs --check` 那一腿的判据全部不动；本卡只**扩**可重算集合。
