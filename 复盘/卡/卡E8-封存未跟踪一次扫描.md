# 卡 E8 —— 封存未跟踪检查：215 次 git 进程 → 1 次

> 台账号 T-AG454 · 分区 E（CI 子系统）· 来源：卡 E1 的边界如实报告

## 现在疼在哪（实测）

`scripts/audit_progress.py:588` 的 `_is_tracked()` 对**每个**路径起一次
`git ls-files --error-unmatch` 子进程；`check_seal_untracked()` 逐条调它。
实测 `gates/last.json.untracked` = **215 条** ⇒ 215 次进程。

- 主树实测：`python -X utf8 scripts/audit_progress.py --all` 用时 **25.2 s**（落地门禁并发时更慢，卡 E1 在卡树量到 12.6–15.3 s）。
- 对照：`git ls-files -z` **一次** = **0.10 s**。

后果：卡 E1 的 `--preflight`（判据前置）本来要给「10 秒内说完」，被这一步拖到 22 s；
每次落地链 ③ 与 `--preflight` 都要多花十几秒；这不是判据问题，是**取数方式**问题。

## 目标

把「这一批路径里哪些已被 git 跟踪」从 N 次进程变成 **1 次**，判据语义一字不改。

## 判据

1. **一次取全量**：`check_seal_untracked()` 只起 **1 次** git 子进程
   （`git ls-files -z`，`-c core.quotepath=false` 保持现状），命中集合在调用内建好再逐个比。
2. **语义不变**（逐条照旧实现，不许顺手改口径）：
   - 只查 `gates/last.json.untracked` 这份清单，不扩到「封存树 == 提交树」；
   - 文件**已不存在** ⇒ 不算缺；
   - 不在片段目录（`FRAGMENT_DIRS`）的未跟踪文件 ⇒ 只报一行、不计缺；
   - 老 `last.json` 没有 `untracked` 字段 ⇒ 优雅降级返回空、不红不崩。
3. **可观测**：路径清单为空时**不**去起 git 进程（省掉空跑）；有清单时打印一行
   `已用一次 ls-files 取到 N 条跟踪路径`（同一批多次调用不许重复取）。
4. **钉子**（`tests/test_seal_untracked.py` 补，不许删旧钉子）：
   - 单进程：用计数器/桩统计 `subprocess.run` 调用次数，215 条清单 ⇒ **1** 次；
   - 语义回归：缺片段仍点名、非片段不计、已删除不算缺、老产物降级；
   - 空清单 ⇒ 0 次进程、返回空。
5. **提速可测**：`python -X utf8 scripts/audit_progress.py --all` 在**同一台机器、同一仓况**下，
   从 25.2 s 降到 **≤5 s**（把两次实测数字写进回话，附命令）。

## 交付

- `scripts/audit_progress.py`：`_tracked_paths(repo)`（一次 `git ls-files -z` → set），
  `check_seal_untracked()` 改用它；`_is_tracked()` 若再无调用方则删（有调用方就保留并委托）。
- `tests/test_seal_untracked.py`：上述四类钉子。

## 验收

```bash
cd .wt/E8
python -X utf8 -m pytest tests/test_seal_untracked.py -q
python -X utf8 scripts/audit_progress.py --all   # 记下用时
```

## 不许做

- 不许把「未跟踪清单」的口径扩大或收窄（那是卡 115 / 118 的判据，改它要另开卡）。
- 不许缓存跨进程（每次调用重新取；缓存只活在这一次调用内）。
- 不许为了快而跳过「文件已不存在」的存在性判断（顺序：先查集合，再看是否还在盘上）。
