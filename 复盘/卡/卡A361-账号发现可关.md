## 要解决的问题

pool 今天**一道 fail-closed 闸都没有**：`discover()` 无条件下 stat `DECLARED_DIRS` 里 7 个位点，`_token_for()` 无条件读 `token_env`。也就是说，只要跑一次 `pool_accounts.py discover` 或 `probe`，这台机器上**别人**的凭据目录就被摸了 —— 摸的是「有没有」，但「有没有」本身就是信息。

magpie 的选择是**在最前面拦**，不是「读到了但不用」：`discoveryOff()` 是每个碰账号位点的动作的**第一句**，返回的是**同一个错误** `errAccountDiscoveryOff`。照抄成「读完再过滤」是净损失 —— 那种写法能通过「返回空列表」的断言，实际已经把 `stat` 发出去了。

闸必须是 **env**，不能是 `accounts.toml` 里的一个键：读 `accounts.toml` 本身就已经在发现账号了。

默认值必须是**不关**。今天那 7 个位点的 stat 是既有行为，把默认写成「关」等于让号池凭空消失 —— 「一条判据改坏一台机器」，比 magpie 那边严重得多（magpie 是 fresh install 先问用户，pool 没有那个前提）。

## 判据（7 条，逐条可执行）

1. 闸关（`TF_NO_ACCOUNT_DISCOVERY=1`）⇒ `discover([...], [...])` 返回 `[]`，且**一个位点都没被 stat**。咬法：把 `os.scandir` / `Path.exists` 换成会记录调用的桩，断言调用次数 = 0 —— 「返回空」不算过，那样「stat 了但过滤掉」也能过。
2. 闸关 ⇒ `_token_for(plat)` 返回 `("", "")` 且**没读 `os.environ`**里的 token 变量（同样用桩断言）。闸问在循环之前，不是循环里面。
3. 闸关 ⇒ `probe_account(...)` / `probe_all(...)` 每条都给 `skipped`（**不是** `uncertain`，**不是** `failed`）。三码差别是判据的一部分：`uncertain` 说「我有凭据但不敢发」，`skipped` 说「我根本不该看」。闸关时连平台能力表都不查 —— 不许给 `unknown-platform`（那是「查过了、表里没有」）。
4. 闸关 ⇒ 签到取凭据那一面也拿不到东西：`tools/pool/checkin.py` 的 `tokens_from_env(...)` 返回 `[]`。
5. 闸**默认缺席** ⇒ 照旧工作（`discover` 仍按位点数出行、`_token_for` 仍取第一个非空的、`tokens_from_env` 仍按 `/` 切、目录存在时仍数条目、没凭据仍是 `uncertain`）。这一条是回归保护，少了它「默认写成关」也能全绿。
6. 取值解析：`""` / `"0"` / `"false"` / `"no"` / `"off"` 与认不出来的值 ⇒ **开**（照旧发现）；`"1"` / `"true"` / `"yes"` / `"on"` ⇒ **关**。大小写与首尾空白无关；**空串等于没设**。
7. 错误/解释文案含 `account discovery is off`，且**不**泄露任何路径（不含 `/`、`\`、`~`、文件名），也不抄 magpie 的 `Settings → Privacy` 指引。

**常量逐字**：`ACCOUNT_DISCOVERY_ENV = "TF_NO_ACCOUNT_DISCOVERY"` / `DISCOVERY_OFF_VALUES: frozenset[str] = frozenset({"1", "true", "yes", "on"})` / `DISCOVERY_OFF_MESSAGE = "account discovery is off（TF_NO_ACCOUNT_DISCOVERY 取真值 ⇒ 不碰任何账号位点）"`。

## 缺口的如实交代（进 changelog 的 gaps）

1. **`noAccountDiscovery: true` 这个键名属「仅文档」**：magpie 源码读的是 `settings.AccountDiscoveryOff()`，配置键名只在条目清单里见过 —— 这一格**不算已核**。所以 pool 侧的闸落在 **env** 上，不是模拟那个键名。
2. **两侧的闸保护的不是同一件事**：magpie 的闸保护**隐私**（fresh install 先问用户）；pool **没有**「用户同意」这条路径，本卡的闸是**运维级**（env）。它保护的是「不许偷偷摸别人的机器」，不是「用户没点头就不读」。
3. **`probe_account` 的 `skipped` 今天没有任何调用方产生它**：六码里早有这一格，但今天没有一条路径会返回它。本卡让它**第一次真的被产生出来**（此前只有 `--offline` 与 `state=disabled/expired` 用 `skipped`）。
4. **签到侧只做到「取不到凭据」**：闸关时 `tokens_from_env` 返回 `[]`，签到会走到「账本只存指针，没有凭据可发」那条既有 `uncertain` 分支 —— 不是新加一个「不该看」的结论码。理由是 `tools/pool/checkin.py` 的结论码是 E48 的判据面，本卡不许扩。
5. **假牙如实申报**：`_rev_A361.py` 的「丙」那条（先 stat 再过滤）**只有调用计数桩抓得到** —— 已实测：把那条钉子退化成只断言 `assert rows == []` 时，同一条变异**是绿的**。脚本里「甲/丙」两条的锚点是整段函数体替换，不是单行替换，因为只删闸会返回非空行（那是另一种坏法）。
