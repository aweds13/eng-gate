## 要解决的问题

pool 今天**只有墙钟**（`gates/diag/wb-usage.jsonl` 的 `用时分钟` 与事件里的 `duration_ms`），**没有首字延迟、没有流转时长**（实测 242 份 `wb-*.jsonl`：`result` 事件键含 `duration_api_ms` / `duration_ms` / `total_cost_usd` / `num_turns` / `modelUsage` / `usage`，但**没有** `ttft_ms` / `first_text_ms` / `flow_ms`）。

于是「这条回复每秒写了多少 token」这件事在 pool 侧**今天根本算不出来**。而 magpie 那边有一整套判据回答的是**另一个问题**：「什么情况**不许**报速度」。那套判据是**纯算术**，可以逐字搬 —— 它闭的是一个真错：**拿墙钟冒充速度**。一条 5 秒的回复里有 4.5 秒是排队与首字延迟，用 `output_tokens / 总时长` 算出来的「速度」是假的，而且会系统性地偏低（把快的号看不出来）。

★ 本卡的边界与 F42 同型：**只搬判据、不搬数据面**。pool 今天零生产方（不产 `ttft` / `flow`），所以这个模块上线当天**一行也不被调用**；它交出去的是「将来有数时该怎么判」。**这一点必须写进模块 docstring 与 changelog，不许说成「已经能测速度了」。**

## 判据（14 条，逐条可执行）

**本卡的判据就是设计原件 §2.1「判据（每条能被一条 pytest 咬住）」那 13 条 + 一条接线禁令**：

1. `window(out=0, ms=1000, ttft=1) == 0`；`window(out=-1, ms=1000, ttft=1) == 0` —— 没写出来就没有速度。
2. `window(out=10, ms=1000, ttft=0) == 0` —— 首字时间未知 ⇒ 不可测（**这是 pool 侧的常态**，必须在 docstring 里点名）。
3. `window(out=10, ms=1000, ttft=950) == 0` —— `w = 50 < MIN_DECODE_MS(100)` ⇒ 不可测。
4. `MAX_DECODE_SPEED` 那条边界**成对**：`window(out=10000, ms=1001, ttft=1) == 1000`（`10000*1000 = 10,000,000 > 10000*1000` 为假 ⇒ 过）；`window(out=10001, ms=1001, ttft=1) == 0`（`10,001,000 > 10,000,000` 为真 ⇒ 回 0）。
5. `tells(out=200, reasoning=0, ms=5000, ttft=500, first_text=0, flow=0) == (200, 4500)` —— 正常一条。
6. `tells(out=200, reasoning=150, ms=5000, ttft=500, first_text=2000, flow=0) == (50, 3000)` —— 有推理且有首字 ⇒ **只算答案**（`out - reasoning`），窗口从 `first_text` 起。
7. `tells(out=200, reasoning=150, ms=5000, ttft=500, first_text=0, flow=0) == (0, 0)` —— 有推理、无首字、无 `first_reasoning` ⇒ 不可测（**不能拿推理的 token 冒充答案**）。
8. `tells(out=200, reasoning=150, ms=5000, ttft=500, first_text=0, flow=100, first_reasoning=[600]) == (50, 4400)` —— 走 `first_reasoning` 那一支：`start = 600`。
9. `tells(…, flow=100, first_text=2000)` 且 `flow * HELD_SHARE < w` ⇒ `(0, 0)`（`flow=100`、`w=3000` ⇒ `400 < 3000`）—— **末端爆发**那条。
10. `THINK_PACE` 那条**边界两侧各一条**：用能过的一侧与过不了一侧成对钉住（设计原件 §2.1 判据 10 给了构造思路：`50*(first_text-ttft) > 20*reasoning*w` 要真，得把 `reasoning`/`out` 的量级拉开）—— **这一条不许只测一侧**，否则空转。
11. `tells_record(reasoning_hidden=True, first_text=0) == (0, 0)`；`reasoning_hidden=True, first_text=2000` ⇒ **继续走** `tells`（不是无条件回 0）。
12. `codex_short` **两对边界**：`codex_short(w=999, n=100) is True` / `codex_short(w=1000, n=100) is False` / `codex_short(w=2000, n=99) is True` / `codex_short(w=2000, n=100) is False`。
13. 常量逐字：`MIN_DECODE_MS == 100` / `MAX_DECODE_SPEED == 10000` / `HELD_SHARE == 4` / `THINK_PACE == 20` / `CODEX_WINDOW_MS == 1000` / `CODEX_BODY_TOKENS == 100`。
14. **不接线**：`tools/` 全目录里**没有任何一处** import `pool.speed`（源码级断言，扫 `tools/**/*.py`）。理由：pool 今天不产 `ttft`/`flow`，接进去只能接假数 —— 那正是本卡要消灭的东西。将来有数了再开卡接（`append_usage_line` 的键集是唯一入口）。

## 不许做

- **不许接线**：`tools/` 里不许有任何一处 import `pool.speed`（判据 14）。接进去只能接假数。
- **不许改 `append_usage_line` 的键集**（那是将来接线时的事，本卡碰都不碰）。
- **不许把「不可测」写成 0 速度**：不可测的返回值是 `0`（窗口毫秒）与 `(0, 0)`（tokens, 窗口），**调用方因此不报速度**；不许为了让数好看而编一个。
- **不许用 `float` 做边界比较的中间量**：原件全是 `int64` 整数比较，Python 侧也全用 `int`（`out * 1000 > MAX_DECODE_SPEED * w` 这种写法）。
- **不许把 `first_reasoning` 做成 `int` 之外的形状**（原件是 `firstReasoning ...int64` 变参，pool 用 `Sequence[int] | None`，**空序列与 `None` 同义**）。
- 不许碰在飞的 `tools/wb_dispatch.py` / `tools/pool_quota.py` / `tools/pool/lastgood.py` / `tools/pool_accounts.py` / `tools/render_check.mjs` / `tools/ui_flow_check.mjs`（各有在飞卡）。
- 不许碰六份 `PROTECTED_FILES`。

## 缺口的如实交代（进 changelog 的 gaps）

1. **零生产方**：pool 今天不产 `ttft` / `first_text` / `flow`（242 份 `wb-*.jsonl` 实测无这三个键）⇒ 本模块上线当天**零调用**。判据在、数据面空。将来要真用，得先给 `append_usage_line` 加 `ttft_ms`/`first_text_ms`/`flow_ms` 三个键并让工人报 —— 那是另一张卡。
