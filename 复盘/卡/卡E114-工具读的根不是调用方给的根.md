`tools/pool/task.py:141-144`：

⇒ 卡 114 的旧卡（`复盘/卡/卡114-main_tree_root不许依赖cwd.md`）原文已经点破过同一类事故：

## 判据

### 判据 1 · `gates/diag` 单凭自己**不足以**判数据根；两份账本各自单独仍够

- `tools/pipe_root.py:20` 的 MARKER 里，`"gates/diag"` 不能单独成立：`_looks_like_data_root(P)` 为真 ⟺
  `P` 下存在 `docs/workbacklog.toml` **或** `docs/traceability.toml`。
- 反例必须机器化：`tmp_path` 里**只** `mkdir gates/diag`（不写任何账本）⇒ `_looks_like_data_root(tmp_path)` 必须 `False`，
  且 `data_root()`（清掉 `PIPE_DATA`/`PIPE_HOME`）必须回 `home_root()`，**不许**回 `tmp_path`。
- 正例不许受伤：`docs/workbacklog.toml` 单独存在 ⇒ 仍是数据根（`tests/test_pipe_root.py:55` 必须继续绿）；
  `docs/traceability.toml` 单独存在 ⇒ 仍是数据根（`tests/test_sync_counts_root.py:87` 必须继续绿 ——
  它造的树 `:28-39` **只有** traceability + 两份交接 md，没有 `gates/diag`，不会被这条波及）。
- 钉子：`tests/test_pipe_root.py` 新增 `test_a_lone_gates_diag_is_not_a_data_root` ——
  `:19-24` `_env()` 清环境、`monkeypatch.chdir(tmp_path)`、只造 `gates/diag`，
  断言 `_looks_like_data_root(tmp_path) is False` 且 `data_root() == pipe_root.home_root()`。
  **红法**：把 `"gates/diag"` 加回 MARKERS ⇒ 这条必红（模拟已证：only-gates-diag 由 False 翻 True）。

### 判据 2 · 五条只读面在任意 cwd 下读**同一个根**，且根由调用方/工具根决定

- 断言（三条，全部机器可检）：
  1. 任意「模块所住的树 × 进程 cwd」组合下，`task.main_tree_root()` **等于** `registry.main_tree_root()` ——
     后者已由卡 114/117 修好、并有钉子（`tests/test_pool_registry.py:86-97`）。
     **两维都要动**：模块住哪棵树（主树 / 真卡树）× 进程 cwd（主树 / 卡树 / 非仓目录），共 5 格
     （模块住主树×cwd=主树、×cwd=卡树、×cwd=非仓；模块住卡树×cwd=卡树、×cwd=非仓）。
     ★ 今天只有 2 格 DIFF（`_probe_E114k.py` 读数在问题 3），另外 3 格本来就 EQUAL ——
     **只跑「模块住卡树」会假绿**，这是本卡最容易写错的地方。
  2. `pool_mcp.tool_task_list({}, root=R)` 回话里 `tf-json` 的 `batch_dir` 必须等于 `R/gates/diag/batch`（`R` 为 tmp、未设 `TF_BATCH_DIR`）；
     **今天两次不同 root 回同一个 batch_dir**（`_probe_E114j.py` ②：`两次相同 = True` ⇒ root 被完全忽略）。
     `TF_BATCH_DIR=X` 设了时必须仍回 `X`（自证注入点不许坏，`tests/test_pool_mcp_task.py:147-154`）。
  3. `pool_mcp.tool_pool_plan({}, root=R)` 的判据根必须是 `R` 不是 cwd ——
     构造：cwd = 一棵「有 `gates/diag`、没有账本」的 tmp 树，`R` = 另一棵「有 `docs/workbacklog.toml` + 规格都在」的 tmp 树
     ⇒ 必须 `exit 0`。**今天必红**（`plan.ROOT` 走 cwd ⇒ 报 361 条或报 cwd 那棵树）。
- 根的顺序写死（不许第三条路）：**显式 `root` 参数 > `TF_BATCH_DIR`（仅任务目录）> `main_tree_root()` / 工具根**；
  cwd **一次都不许**参与。
- 钉子：`tests/test_pool_task.py` 新增 `test_main_tree_root_agrees_with_registry_in_every_cwd`（上 1）、
  `tests/test_pool_mcp_task.py` 新增 `test_task_faces_follow_the_root_they_are_given`（上 2）、
  `test_pool_plan_judges_with_the_root_it_was_given`（上 3）。
  **红法**：把 `task.py:143` 改回 `common = Path.cwd() / common` ⇒ 1 必红（**前提是钉子跑对格**：
  模块住主树 + cwd≠主树；跑成「模块住卡树」会假绿）；把 `_task_batch_dir()` 改回不收 root ⇒ 2 必红；
  把 `plan_report` 改回只读模块级 ROOT ⇒ 3 必红（三条都已在 `_probe_E114e/j` 里实测过方向）。
- 路径比较**必须先规范化**（`Path(x).resolve().as_posix()`）：mcp 回 `D:/`、task 回 `D:\`，
  直接比字符串会**假红**（`_probe_E114h.py` 第一版就是这么废的）。

### 判据 3 · `checkin_status` 的读端与写端指向**同一个文件**

- 断言：不 monkeypatch `DATA_ROOT`、**不设 `PIPE_DATA`** 的前提下，同一个 cwd 里
  `Path(pool_mcp.tool_checkin_status({"date": D})[1]["archive"]).resolve()`
  **等于** `pool_accounts._checkin_archive(D).resolve()`。
- 两个 cwd 都要测（子进程，`PIPE_DATA`/`PIPE_HOME` 都清掉，因为 `pa.DATA_ROOT` 是导入时求值）：
  ① cwd = 真数据根（tmp 里造 `docs/workbacklog.toml`）⇒ 两边都落在那棵树；
  ② cwd = 只有 `gates/diag` 的目录（profile 的迷你复刻）⇒ 两边都落回工具根，**都不许**落在那个目录。
- 钉子：`tests/test_pool_mcp_task.py` 新增 `test_checkin_read_side_lands_on_the_write_side`（两格参数化）。
  `tests/test_pool_mcp_task.py:831/:856/:877` 三条既有的 `root=tmp_path` 钉子**不许改形状**（它们钉的是「给我哪个根就读哪个根」）。
- ★ 口径边界：本判据只钉「读端 = 写端」。`PIPE_DATA` 设了的情形归判据 4 ——
  本卡**不要求** MCP 面也听 `PIPE_DATA`（若实现选 `pipe_root.data_root()`，它会自动听，也不算越界；两种都合格）。
- ★ 与判据 1 的咬合（这是本判据能绿的**前提**）：② 那一格要求「两边都落回工具根」，
  靠的正是判据 1 把 `gates/diag` 从 MARKERS 里拿掉 —— 拿掉之前 `pa.DATA_ROOT` 会等于那个只有 `gates/diag` 的目录。
  ⇒ 两条判据必须同一笔里改；只改一条，另一条的 ② 格会红（这不是钉子写错，是真的没治好）。
- **红法**：把 `:1507` 改回 `root / _CHECKIN_DIR`（即读端继续锚工具根）⇒ 第一条必红。
- ★ 与卡 E119 的分界（`复盘/卡/卡E119-checkin_status说读账本却没读.md:5`、`:50`、`:163`）：
  **账本读法 / payload 键名 / 三处文案**归 E119，本卡**只**钉「读端与写端同一个根」这一条。
  所以本判据**不**要求 description 里那句 `health.last_checkin` 变真（那是 E119 判据 5），
  也不许为了让本判据变绿去删那句文案 —— 删了 E119 必红。

### 判据 4 · `PIPE_DATA` 的显式优先级**一个字都不许坏**（那是给 ds mate 用的）

- 现状指名：`grep -rln pipe_root tools/ scripts/ --include=*.py | grep -v __pycache__ | wc -l` = **18** 个源文件
  （`scripts/run_gates.py`、`scripts/tia_map.py`、`tools/pipe_root.py` 自身，加 `pool/` 7 个、账本/通知/计划 9 个）；
  **`tools/pool_mcp.py` 与 `tools/pool/task.py` 不在其中**（`grep pipe_root` 两个文件 0 命中）。
  本卡**不要求**它们也听（那是新增语义，会动 18 个工具面）—— 但**已经听的，不许因为本卡的改动而退化**。
- 断言（四条，全部是既有钉子的原样复跑，不许改断言）：
  1. `PIPE_DATA` 设了 ⇒ `pipe_root.data_root()` == 它（`tests/test_pipe_root.py:38`）；
  2. `PIPE_DATA` 与「cwd 也像数据根」同时成立 ⇒ `PIPE_DATA` 赢（`tests/test_sync_counts_root.py:125`，断言文案「cwd 抢了 PIPE_DATA 的位置」）；
  3. 在卡树里跑不改主树（`tests/test_sync_counts_root.py:87`，E38 现场）；
  4. `data_root(explicit=…)` 仍**优先于** `PIPE_DATA`（`pipe_root.py:36-41` 的顺序）。
