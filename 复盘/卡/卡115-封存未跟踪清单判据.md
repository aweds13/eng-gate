## 来路（今晚真丢过一次的账，靠人眼才发现的）

2026-10-02：三笔提交（`T-G205` / `T-G206` / `T-G208`）的**片段文件根本没进提交** ——
`_stage_card.py` 在卡树里生成 `docs/changelog.d/<台账号>.md` 等三个片段（**未跟踪文件**），
集成时 `--allow` 只给了代码文件 ⇒ `git add` 没带上 ⇒ **提交里没有片段**（实测三笔的 `.d/` 文件数 = **0 / 0 / 0**）。

**为什么门禁没咬**：`run_gates.py --seal` 算的"封存树"是**工作树减 `gates/**`**（临时索引 `git add -A`）——
它**包含**了那些未跟踪的片段；可是**没人**拿它跟"提交树"比。而 `sync_docs.py --check` **只查**
"现有片段在不在汇总里"，**少文件它照样 PASS** ⇒ 这个缺口**零判据**。

★ 口径（主控定，别扩大）：
- 本卡**不要求**"封存树 == 提交树"（那三个**派生的共享文档** `docs/changelog.md` / `docs/traceability.toml` /
  `复盘/交接-重构进度.md` 允许在门禁之后按片段重汇总 —— 那是并行落地时**有意**的宽松）。
- 本卡要的是**同一件事的窄版**：**封存那一刻"未跟踪"的文件，提交之后必须已经被跟踪**（或者干脆不存在了）。

## 你要做的

1. `scripts/run_gates.py`：`--seal`（以及落 `gates/last.json` 那条路径）里，把**当时未跟踪的文件清单**
   记进 `gates/last.json` 的一个**新字段**（名字你定，例如 `untracked`；**已跟踪的不列**、
   `gates/**` 照旧不列）。★ **不许动既有字段的语义**（`tree` / `tree_scope` / `rev` … 都保持原样），
   新字段只**追加**；`gates/last.json` 的既有读法一个都不许坏。
2. `scripts/audit_progress.py`：新增**一条判据** —— 「封存时未跟踪的文件，现在必须已被 git 跟踪」：
   - 对 `gates/last.json` 里那份清单逐条 `git ls-files --error-unmatch <path>`；
   - 没被跟踪的**逐条点名**（路径 + 一句"生成了却没进提交 ⇒ 集成时 `--allow` 漏了它"）；
   - 有缺 ⇒ **判红**（退出码非 0，与这道审计既有的红一致）；清单为空 / 全被跟踪 ⇒ 绿、且**不打印噪音**。
   - ★ 老 `gates/last.json` **没有**这个新字段时要**优雅降级**（当"没有清单"，不报红、不崩）——
     因为仓库里就躺着历史版本。
3. 钉子（放 `tests/` 下你新建的文件，例如 `tests/test_seal_untracked.py`）：
   - ① **必须咬**：在临时仓库里造一个 `gates/last.json`（`untracked: ["docs/changelog.d/T-G999.md"]`）
     而该文件**没有被跟踪** ⇒ 审计报红并**点名那条路径**；
   - ② **不许误报**：同一个文件 `git add` 之后 ⇒ 绿；
   - ③ **优雅降级**：`last.json` 里**没有** `untracked` 字段 ⇒ 绿（不崩、不报红）；
   - ④ **`--seal` 真写清单**：跑一次 `--seal`（或直接调那个写 `last.json` 的函数），断言新字段里
     **恰好**是当时未跟踪的那些文件（已跟踪的不在、`gates/**` 不在）。
   - ★ 测试用**临时 git 仓库**（`tmp_path` + `git init`）或桩，**别**动真仓库的 `gates/last.json`。
4. ★ 顺手确认一件事并写进回报：这条判据**对今晚那三笔**（片段没进提交）**本来会不会咬**？ ——
