# 卡 118 —— ⑪ 判据口径收窄（不许把外来未跟踪文件当漏交）+ 审计失败路径补还门锁（T-G216）

## 来路（收 B-DOC1 那趟的现场，逐字）

```
=== ⑪ 封存未跟踪清单（封存时未跟踪的文件，提交后必须已被跟踪）===
  [FAIL] DSH-技能与插件开发参考.md：封存时未跟踪、现在仍未被 git 跟踪 —— 生成了却没进提交 ⇒ 集成时 `--allow` 漏了它
  [FAIL] DSH-窗口化方案.md：…      [FAIL] Hermes-数据位置.md：…      [FAIL] dsh-skill-docs-report.zh.md：…
→ 按用户约定：审计不通过不许提交
```
**这四条是误报**：它们是**用户自己的笔记**，一直躺在仓库根、**用户明确说过「留着」**、永远不该进提交。
⑪（卡 115 / `T-G212` 新加）拿 `gates/last.json.untracked`（**工作区所有**未跟踪文件）去比 `git ls-files`
⇒ 于是**任何主树收口都会被它们挡住**（用户的这 4 份是常态）。
★ 反面证据（判据本身有价值）：同一次里 `docs/*.d/T-G214.*` 三份片段**没被点名**，因为收口第 ⑥ 步已 `git add` 过
⇒ ⑪ 确实能抓"该带却没带"，只是**口径太宽**。

## ① 收窄 ⑪：只盯「本笔该带的」未跟踪文件

**口径（就按这个实现，别扩大）**：`scripts/audit_progress.py::check_seal_untracked` 只对**三类片段目录**下的
未跟踪文件咬：`docs/changelog.d/`、`docs/traceability.d/`、`复盘/交接.d/`（今晚真丢的三笔，丢的正是这三类）
—— **其它位置**的未跟踪文件（用户笔记、外来文档）**一律不算**，但要在输出里**列一行**说"另有 N 个无关未跟踪文件（不计）"，
免得"看不见"变成新的盲区。

**钉子（先红后绿，逐条给原样输出）**：
- ★ **不许咬**：工作区预先放一份外来未跟踪文件（如 `外来笔记.md`）⇒ 收口后审计 **exit=0**，且那行"不计"要出现。
- ★ **必须咬**：`docs/changelog.d/T-G999.md` 封存时未跟踪、提交后仍未跟踪 ⇒ **exit!=0** 且**点名该文件**。
- ★ **必须咬**：`复盘/交接.d/T-G999.md` 同上。
- **不许误伤**：受管文件（已跟踪）与 `git check-ignore` 命中的产物（gitignore）**都不算**。
- **优雅降级**：老 `gates/last.json` 没有 `untracked` 字段 ⇒ 不报错、不误判（已有钉子，别弄坏）。

## ② 顺手修：收口在**审计失败**那条路径上没还门禁锁

**现场**：B-DOC1 那趟审计失败后，`gate_lock.py status` 显示 `card=B-DOC1` 的锁**还挂着**（365s 未还），
是主控手工 `release` 的 —— 与"卡 106 白名单失败那次锁挂了 5 分钟"同一个毛病。
白名单失败那条早退路径**已经**有 release，审计失败这条**没有**。
**修**：`gates/diag/_integrate.py` 里所有 `return`/早退路径都要**先 release 再退**（最好收成一个 `finally`）。
★ 这是 **scratch 工具、没有门禁覆盖** ⇒ 修完要**当场真机复现**：造一次 audit 必红（临时把审计判据改坏或用一个必红的桩）
⇒ 确认锁被释放，再把改动复原。
