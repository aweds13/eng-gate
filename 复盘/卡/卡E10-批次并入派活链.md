派活器与排班器都**不认「落地批」**：`wb_dispatch.py` 只有 `--card`（单卡，`--help` 里没有任何批相关键）；`wb_plan.py plan` 的分批是**派活并发**用的 —— `tools/pool/plan.py:453 plan_batches()` 只取 `in_flight()`（pending/running）的卡，按 `topo_layers()`（`:387`）+ `greedy_pack()`（`:426`）打包，算的是「现在能同时起几个工人」，**不看卡树里有没有产物、也不生成预声明/文书/批次树**。⇒ 「哪些卡已经干完、能合成一批落地」这层仍然全靠人。于是机制白放着 —— 用户 m03288 的原话就是「把它并在我们的派活器啊整套系统里面，不然散开的话都不好调用」。

## 要做成什么样

一条链，三个入口，全部由工具算，不靠人记得：

| 入口 | 干什么 |
|---|---|
| `wb_batch.py plan` | 从队列取**待落**卡（`status` 为 pending 且卡树有产物 / 或申请已是 awaiting-commit），算候选批：成员 `files` 两两不相交、`depends` 已满足、同批 ≤4；打印每批的成员、文件、预计省时 |
| `wb_batch.py make <批号>` | 一条命令生成成员预声明 `gates/diag/batch/<批号>.toml` + 三方文书骨架 `_text_<批号>.md`（成员 gaps 合并、台账 evidence 取**并集**）+ 批次树 |
| `wb_batch.py land <批号>` | 一条命令走到 `wb_land.py --batch <批号>`，参数透传 `--port-base / --evidence / --allow` |

另加 `wb_dispatch.py --batch <批号>`：派活时就把成员登记进同一任务，不再事后手拼。

## 判据（可验收）

1. `tools/wb_batch.py` 三个子命令都可用，`--help` 写清三者关系（plan 只读、make 写盘、land 起门禁）。
2. `plan` 的可行性判据**复用** `tools/pool/plan.py` 的 `files_intersect`（`:169`）、`dependency_path`（`:232`）、`topo_layers`（`:387`）—— **不许另写一套相交/依赖逻辑**（两套判据迟早不一致）。
3. `make` 生成的预声明必须过 `pool.task._validate_manifest`（`tools/pool/task.py:357`）：`id` 与文件名一致、`why` 非空、`gate_cmd` 以 `python -X utf8 scripts/` 开头且不含 shell 元字符（`:329 validate_gate_cmd`）、`on_complete ⊆ {"gate","draft"}`、每个成员都有 `id / layer / paths`，且成员域**不得覆盖** `plan.PROTECTED_FILES`（`:383` 会当场拒）。
4. `make` 必须同时写台账证据并集：`docs/traceability.d/<批号>.toml` 的 `evidence` 覆盖**所有成员**的文件（审计 ⑫ 判据在 `scripts/audit_progress.py:295 _reverse_claimed_files`：本笔改的文件必须都被台账指针指到，只并 gaps 不并 evidence 必红）。
5. `make` 的批次树用 `git apply --3way` 合补丁（不 `cherry-pick`、不动卡树）；合不上就**退非零并点名是哪张卡**，不留半合状态。
6. 批大小上限 **4** 写进工具（不是文档）：超限拒单并打印依据（TFS11 用 5、[ACM TSE 2022](https://dl.acm.org/doi/10.1109/TSE.2021.3070269) 实测批 4 可免二分地最优、Shopify 用 8 但只允许同时 3 批在飞）。
7. `wb_dispatch.py --batch <批号>`：成员不在预声明里 ⇒ 响亮拒绝；批号已 landed ⇒ 拒绝并给现状。
8. 验收 `python -X utf8 -m pytest tests/test_wb_batch.py -q`，且真跑一次 `wb_batch.py plan` 能把今天这局面（E8/E9/G1 类）识别成一批。

## 钉子（先红后绿）

1. 三张**文件不相交**的待落卡 ⇒ `plan` 给出一批，成员齐全、顺序按队列序。
2. 两张卡**同改一个文件** ⇒ 不许同批（拿今天 E2/E4 同改 `scripts/run_gates.py` 的形状当夹具）。
3. 依赖未满足（B 依赖 A、A 还没落）⇒ B 不许进批，且理由里点名 A。
4. 成员 5 张 ⇒ 拒单，错误里带「上限 4」与依据。
5. `make` 出来的预声明能被 `wb_task.py register` 原样接受（用 `_validate_manifest` 真跑一遍）。
6. 批次树冲突（两卡树对同一文件各自改动）⇒ `make` 退非零，错误里点名冲突的卡与路径。

## 不许做

- 不许改 `tools/pool/landing.py` 的落地判据（那是 E1/E9 与落地链本体的事）；本卡只调它。
- 不许把「批」做成默认行为：**批仍然要人显式说**（`make` + `land`），派活侧只提供入口。
- 不许在卡树里跑 `git apply`（批次树是独立 `.wt/batch<号>`）。
- 不许为了让 `plan` 好看而放宽「文件不相交」—— 那是批的安全边界。

## 边界（如实写）

- 只治**单机**：门禁锁本来就全仓一把，跨机不做也不假装能做。
- 时间估算用实测均值（今天：一趟全量 ≈19 min，pytest 占 1024 s / 90%），不是「省 N 小时」的营销数。
- 批次失败目前只能人工逐个重跑；自动二分是卡 E11 的事，本卡不做。
