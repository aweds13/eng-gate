# 卡 G6 —— 判据自己也得有牙齿：docs 判据顺序、每道门的反向用例、技能对账接门

> 台账号 T-AG515 · 分区 G（软工技能）· 批号 B-20261052（与 F8、E59 同笔落地）
> 依据：卡 F6 把 `docs` 门接进 audit 档之后，goal round 7 的实测又挖出三层
> 「判据看着在跑、其实咬不到」：判据顺序错、门没有反向用例、对账脚本退 0。

## 要解决的问题

1. **`scripts/check_docs.py` 的判据顺序错，134 条真实存在的引用被白跳过**。
   `check_dead_refs()` 原来先做**扩展名猜测**（`ext_of(token) not in OWN_EXTS ⇒ skip「别仓类型」`），
   再问文件存不存在。于是引用了 `.ts` / `.php` / `.jsonl` 这类「本仓不跟踪的扩展名」、
   但**文件就在盘上**的 134 条，全被记成「别仓路径」skip。
   实测：把存在性提到类型猜测之前，skip 从 1274 降到 1115。
   存在性优先于类型猜测 —— `.ts` 真在仓里，它就是仓里的。
2. **`OWN_EXTS` 是手写集合，没人钉住它**。26 个扩展名里到底哪几个本仓真跟踪过、
   哪几个是"猜进去的"，没有判据。漏一个 = 把本仓文件误判成别仓；
   多一个 = 未来真写错时它不再是死指针。两半都要钉。
3. **没有一道门能证明自己会咬**。全仓 22 道门，`pytest` 绿只说明进程退 0。
   「一道从不红的门，等于没有门」—— 每道门都该有一条**故意造坏输入 ⇒ 断言它红**的
   反向用例，这件事本身要么是判据、要么会烂在原地。
4. **`tools/check_skills_claims.py --check` 报 `[FAIL]` 却退 0**，而且脚本
   **根本没有 `--mode` 参数** ⇒ 它接不进任何门（门只看退出码）。
   技能里写的 `python -X utf8 tools/<x>.py --flag` 与工具源码漂了，没有任何东西会红。

## 判据（四条）

1. **判据顺序就是判据，且有反向用例**：`check_dead_refs()` 的 docstring 逐条写出
   完整顺序（外链 → 绝对路径 → 模板占位 → 逃逸 → **存在性** → gitignored → 类型兜底），
   并有至少 5 条反向用例证明每一档都会咬；`skip` 总数从 1274 降到 1115 量级，
   且 `dead_refs` 不涨。
2. **`OWN_EXTS` 被钉在 `git ls-files` 上**（反了两个方向）：
   ① `git ls-files` 实测到的每个扩展名都必须在 `OWN_EXTS` 里；
   ② `OWN_EXTS` 里每个**没有跟踪样本**的成员，必须在
   `OWN_EXTS_UNTRACKED_REASONS` 里有一条非空理由，且理由表与跟踪样本**不相交**
   （某成员哪天被真跟踪了，测试就要求把理由删掉 —— 理由会腐烂，腐烂得被抓出来）。
3. **每道门都有自证行，且台账不许空转**：`gates/gate-selfproof.toml` 一行一道门
   （`name` / `reverse_case` / `why_no_case` / `since`），判据在
   `tests/test_gate_selfproof.py`：① 台账里的门都在真门表里 ①b 真门表里每道门都有行
   ② `reverse_case` 指的 nodeid **真的存在** ③ `none` 时 `why_no_case` 非空且够长
   ④ 每道门的命令非空 ⑤ 台账行序与真门表逐字同序。
   `reverse_case` 判的是**用例名在不在**（走真 `pytest --collect-only`），不是「文件在不在」。
4. **技能对账接进 audit 档且不再说谎**：`tools/check_skills_claims.py` 加
   `--mode report|block`；`block` 档「判不出」退 3、「真漂移」退 3；
   `report` 档只报不红。门表接
   `[PY, "-X", "utf8", "tools/check_skills_claims.py", "--check", "--mode", "report"]`
   （第一版 report：那 73 条 `<卡号>` / `...` 是占位符与通配名，压不到 0 条，
   block 会把每趟门禁染红 —— 与 `docs` 门同一个理由）。
   门表 21 → **22 道**。

## 不许做

- 不许为了让 `dead_refs` 好看而把「存在性优先」改回「类型优先」——
  那正是这张卡要修的那个错。
- 不许把 `reverse_case` 写成不存在的 nodeid 来凑满台账：判据 ② 会当场红。
- 不许把 `why_no_case` 写成「要真浏览器」这种一句话免责：判据 ③ 有最小字数。
- 不许把 `skills_claims` 门一上来就挂 `--mode block`：那 73 条占位符会把每趟门禁染红，
  这是刻意选择 report 档，理由写进门的注释。
- 不许改 `docs/doc-debt-baseline.toml` 的数字来让门绿（`PINNED_FLOOR` 钉子会咬）。
