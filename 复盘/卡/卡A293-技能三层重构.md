# 卡 A293 — 技能体系三层重构（7 个）

## 目标
按 Agent Skills 规范（`docs/reference/agent-skills-spec.md`）把 `skills/` 下 7 个技能
重构成三层：元数据（name/description）→ 正文（≤120 行，只留流程）→ `references/`（长表按需）。

## 实测现状（2026-10-19）
- `pipe-card` / `pipe-gate` / `pipe-land` / `pipe-init` / `pipe-forensics`：几乎不写 `wb_*` 真命令，
  `worktree` / `branch` 出现 0 次 —— 它们是 pipe CLI 时代的稿子。
- `pipe-workbench` 较新（6 处 `wb_*`、4 处 worktree）。
- `softeng-manage` 本轮新写（80 行），是路由技能。

## 要求
1. 每个 `SKILL.md` 压到 ≤120 行，只留：什么时候用 / 什么时候别用 / 前置检查 / 真命令 /
   怎么读结果 / 常见错与处置 / **自查**。
2. 长表（门清单、落地参数、批次围栏、状态机）下沉到该技能目录的 `references/`，正文给
   **相对链接**（只深一层）。
3. 命令一律写本仓真命令（`python -X utf8 tools/…`）；与 pipe CLI 的差异引用
   `skills/softeng-manage/references/mapping.md`。
4. **不许写判据**（阈值、字段、不变量在门与库里）；技能只写「怎么用才不出错」。
5. 保留并更新 `NOTES.md`（人类理解版：防哪类错、接口怎么改）。
6. 每个技能跑 `npx -y skills-ref@latest validate ./skills/<名>`，必须 `Valid skill`。
7. `python -X utf8 scripts/check_layers.py` 必须 PASS；`git status --porcelain -uno` 0 行。

## 验收（缺一不算完）
- 7 个 `Valid skill` 输出
- `check_layers.py` PASS
- 每篇 SKILL.md 行数读数
