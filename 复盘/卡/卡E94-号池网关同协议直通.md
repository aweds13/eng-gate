## 要解决的问题

1. **零推理客户端**：`grep -rn 'chat/completions' --include=*.py tools/` = 0 命中。
   号池能派活（起 CLI 工人），但没有任何程序能「拿这个号的额度打一次模型」。
2. **选号是死代码**：`tools/pool/route.py` 723 行、七种策略、`smart_order`/`apply_strategy`
   的 8 处引用**全在模块自身** ⇒ 从没在真流量上跑过；`apply_strategy` 还带 fail-open。
3. **失败不换号**：`tools/wb_dispatch.py:4040-4110` 的 429 段只改 `model`，`account_id` 从不重赋值。
4. **没有端点**：`tools/pool/platforms.toml` 九平台的 `base_urls` 全是额度/签到端点，
   一个 chat 端点都没有 ⇒ 网关缺「往哪发」这一列。

## 判据（6 条）

1. **失败分类只有一份**：gateway.py 里的 classify(status, body) -> Kind，
   七个 kind `rate / quota / auth / overflow / server / bad_request / other`。
   判据**只看 status 与结构化字段**（`insufficient_quota` 这类 error.type/code），
   **不解析自由文案**（含中文提示语）；`Retry-After: 0` 必须被当成合法值（判空写 `is not None`）。
2. **端点先立接口不编造**：`platforms.toml` 每平台加一列 `chat_urls = []`（九平台全空）。
   网关遇到 `chat_urls` 为空的平台 ⇒ 403 并**点名**「这个平台没登记 chat 端点」，
   不许退化成「随便试一个 base_url」、不许伪造成功。
3. **干跑能跑通且不出网**：`route_once()` 在 `forward` 是桩时可完整走完
   候选选择 → 沉底跳过 → RPM 跳过 → 收窄拒绝 → 循环尝试 → 落账。
   账落 `gates/diag/wb-route.jsonl`（复用 `tools/pool/route_log.py::append_route`，
   `card` 用 `gw:<caller>`）；**`tried` 为空则不落记录**（纪律由网关自己守，append_route 不拒）。
4. **HTTP 面只有四条且默认关**：`POST /v1/chat/completions`、`POST /v1/messages`、
   `GET /v1/models`、`GET /v1/pool/routes`。服务必须：只绑回环（非回环直接拒且文案照 mcp_http）、
   `TF_POOL_GATEWAY_TOKEN` 未设 ⇒ **退非零不起服务**（不为无鉴权留默认路径）、
   令牌比较走 `hmac.compare_digest`、Origin 白名单、请求体上限 32 MiB。
5. **只做同协议直通**：客户端说 Chat ⇒ 上游必须也是 Chat（`/v1/messages` 同理）；
   上游只流式而调用方要非流式 ⇒ **400 拒绝并说明**，不许自己攒流。
   SSE 逐字节转发、不解析、不改写。
6. **反向变异 ≥5 条**：每条判据至少一处变异能让对应测试红（分类表挪一项 / 空 chat_urls 放行 /
   有 token 才起服务改成无 token 也起 / 非回环放行 / 空 tried 也落账 / 非流式被攒流）。
