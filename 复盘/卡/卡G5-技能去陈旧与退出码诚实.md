# 卡 G5 —— 技能去陈旧：把「等卡 X」清干净，把判据指回真脚本

> 台账号 T-AG512 · 分区 G（软工技能）· 批号 F-20261027-1（与 F6、F7 同笔落地）
> 依据：`skills/nails/check_skills.py` 与 `check_commands.py` 都是绿的 —— 机器校验
> 只管行数、流程段数与命令能跑通，**管不到散文里说的话是不是还成立**。

## 要解决的问题

技能层有三类陈旧/冲突，机器校验一条都拦不住：

1. **散文里写着「等卡 X 落地」**，而那些卡早就落了：
   - `skills/pipe-gate/SKILL.md:33`「卡 E16 在修等锁没进度」—— E16 已并入 E28 落地。
   - `skills/README.md:41` 与 `skills/softeng-manage/references/commands.md:127-128`
     「等卡 E18 落地」—— E18 已 `done`（T-AG470）。
   - `commands.md:95`「在卡 E10」—— E10 已 `done`。
2. **`check_skills_claims.py` 自己判不干净却退 0**：`--check` 打
   `[FAIL] 引用 173 / 对得上 100 / 对不上 1 / 判不出 72`，**exit code 仍是 0**。
   「判不出」的 72 条既不算过也不算不过，而退出码把它们一起当成了过。
3. **三份参考里的证据命令指不到东西**：`skills/softeng-manage/references/` 下
   `commands.md` / `retired-settings.md` / `spec-checklist.md` 里若干命令行
   （`tools/check_mapping.py`、`tools/replay_worker_edits.py`、`tools/sync_worker_skills.py`
   等）在仓外或指向未入库文件。

根因是同一个：**技能的散文层没有任何「它说的话现在还算不算数」的判据**。
卡 209 的四条钉子（≤120 行 / 流程段 ≤3 / 口径指真脚本 / 有 NOTES.md 三节）
只约束形状，不约束真值。

## 判据（四条）

1. **「等卡 X」全部清掉**：`skills/**` 里任何一处「等卡 `<编号>`」都必须
   指向**实测仍是 pending/running** 的卡；拿 `docs/workbacklog.toml` 的
   `status` 逐条核，过期的一律改成既成事实（落了什么 / 结论是什么）。
2. **退出码诚实**：`check_skills_claims.py --check` 在「对不上 1 / 判不出 72」时
   **不许退 0**。要退 0，就得让「判不出」有明确归属（认了不算数、或写进豁免表），
   不能靠退出码把它们一起放过。
3. **每条命令都指得到真文件**：`check_commands.py` 覆盖的命令必须真能跑；
   指向未入库工具的，要么把工具入库，要么把命令改掉。
4. **口径指真脚本**（卡 209 第四条不许回退）：技能里说的「判据在 X」，
   X 必须是 `tools/` 或 `scripts/` 里真存在的脚本。

## 不许做

- 不许删技能或把它们合并掉来消除陈旧 —— 陈旧的是**断言**，不是技能本身。
- 不许把 `skills/` 里已经成立的口径（判据不进技能、删掉整个 `skills/` 框架仍可用）
  当成「多余描述」删掉：那是全仓立仓原则，`docs/reference/agent-skills-spec.md` §9 有据。
- 不许用「加注保留原文」的方式处理 reference/how-to 层的错断言 ——
  那一层错了就该改（只有 `复盘/` 的证据层只许加注）。
