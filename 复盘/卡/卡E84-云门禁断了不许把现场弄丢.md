# 卡 E84 —— 云门禁跑到一半断线，不许把 15 分钟的现场一起弄丢（T-AG591）

> 台账号 `T-AG591` ｜ 分区 E（门禁与可信度）｜ 树 `.wt/E84` ｜ 层 判据层
> 基准提交 `dbe3a71f`（主树 HEAD）。

## 要解决的问题（已实测，不是推测）

卡 A366 那趟云门禁（端口段 9520）**在云机上是跑完了的**，本机却收到 `rc=255`，
`scripts/cloud/run_gate.sh` 于是退 9，落地链判「云机不可达」。三份证据逐字如下。

① 本机日志 `gates/diag/cloud-e82-real2.log` 末段：

```
[FAIL] CloudUnreachable: 云门禁没跑成（run_gate.sh 退 9，卡在 === 5/5 回传 gates/last.json 与日志 ===）：
[stale] ① 产物 at=2026-11-04T02:50:38 早于本趟起跑 2026-11-04T04:38:27+08:00 ⇒ 这是上一趟留下的读数
★★ 回传的 last.json 不是这一趟跑出来的（rc=255，起跑 2026-11-04T04:38:27+08:00）⇒ 已删除卡树里那份。
```

② 本机抓到的那份「现场」只有 1026 字节，`gates/diag/cloud-gate-A366.log` 全文停在 4/5 的开头：

```
=== 内存闸：可用 13.1 GB ≥ 阈值 2.0 GB，放行 ===
=== ④ 文档与代码同提交（提交前检查）===
=== 本树 src = C:\eng\src（子进程 PYTHONPATH 首位，T-G157）===
=== ⑨ 开场清遗留（端口段 + 本树 cwd 双判据；BASE=9520：9520..9538）===
```

③ 同一时刻云机上的产物却是**完整**的，`C:/eng/gates/last.json` 实测：

```
ok False  rev 61ffa1206…  host gates-runner-host  at 2026-11-04T04:55:14  gates 22
```

云机侧 `C:/eng/gates/logs/` 21 份日志的时间戳也一路写到 `pytest.log 4:55:13`——
**门禁在云机上真跑完了 22 门，产物就在盘上，本机却当它没发生过。**

根因三条，全在 `scripts/cloud/run_gate.sh`：

- `:71` 的 `SSHOPTS` 只有 `StrictHostKeyChecking` / `UserKnownHostsFile` / `BatchMode`，
  **没有 ServerAliveInterval**。一趟门禁约 15 分钟，长连接空闲被中间设备剪断时
  本机只看到 `rc=255`，而云机上的进程照跑。
- `:312` 的 4/5 是裸 `ssh … "… run_gates.py && … --seal" > "$TMP/gate.out" 2>&1`：
  **没有超时**。云机挂死时本机就无限等（只有上层 `gate_pool` 的 3600 s 兜底）。
- 4/5 的输出**只落本机 `$TMP/gate.out`**，而写成 `gates/diag/cloud-gate-<卡>.log` 的
  `cp` 在 `:322`、`scp` 在 `:319-320` —— 都在 5/5。传输一断，云侧那 15 分钟的
  stdout 与 `last.json` 就没人去取了（本次就是）。

## 判据（7 条）

1. **SSH 必须保活**：`SSHOPTS` 里必须同时有 `ServerAliveInterval=30`、
   `ServerAliveCountMax=6`（或更大）、`TCPKeepAlive=yes`。三者缺一即判红。
2. **4/5 必须有硬超时**：用 `timeout` 包住那一条 `ssh`，秒数可由
   `TF_CLOUD_GATE_TIMEOUT` 覆盖、缺省 `3600`；超时单独可辨（`timeout` 的 124）。
3. **云侧也要落盘**：4/5 的 stdout 在云机上同时写一份文件
   （`C:/eng/gates/diag/cloud-4of5-<卡>.log`，`gates/diag/` 是 gitignored，不会入库），
   断线后这份文件仍在盘上。
4. **本机先抢现场**：`ssh` 一返回就**立刻**把本地捕获写成
   `gates/diag/cloud-gate-<卡>.log`（开头带上 `rc` 与用时两行），
   **必须早于** 5/5 的任何 `scp`（顺序要能被静态断言读到）。
5. **断线也要试着取回**：5/5 里对「云侧 4/5 日志」「`gates/last.json`」「`gates/logs/*.log`」
   三项各自 best effort 取回，**任何一项失败都不许中断后面两项**（也不许因为失败就 `exit`）。
6. **断线/超时要说人话**：`rc=255`（传输断）与 `rc=124`（超时）各给一句诊断，
   并写明「云机上的现场在哪个路径、怎么取回」。不许只说「退 9」。
7. **既有钉子一字不动全绿**：`tests/test_cloud_sync.py` 原有的 20 条静态钉子
   （`0.4/5` / `2/5` / `2.5/5` / `3/5` / `3.5/5` / `4/5` 步名与退码语义）
   必须原样通过；本卡只在文件末尾**追加**钉子。
   `scripts/cloud/run_gate.sh` 的其它步（0/5–3.5/5 与 `check-product-fresh`）一字不动。
