## 要解决的问题

1. **codearts 的额度读数今天根本走不到。** `tools/pool_accounts.py` 的 `probe_account()` 里
   `mode == "unsupported"` 一律回 `uncertain "读取也需 SDK-HMAC-SHA256 签名（E48 的 checkin
   一并实现），本卡不猜读数"` —— 可 E48 的签名器**已经实现并真跑通了**（`tools/pool/checkin.py`
   的 `sign_huawei` + `codearts_account`，2026-11-09 真机读回 46.5%）。这句话现在是**假话**。
2. **读回来了也没人解析。** `checkin.py` 的 `codearts_account()` 只把 `statistics/plugin` 的裸对象
   交出来，**不碰 `metrics[]`** ⇒ 已用比例（`package_credit_used / package_credit_amount`）
   一个字节都没进账本，`[account.quota].used_percent` 全仓零写方（`tools/pool/quota_history.py:16` 自己写着）。
3. **窗口边界仍然不可得（这条不许掩盖）。** `statistics/plugin` 不下发周期字段
   （`gates/diag/repos/ref/dsh-codearts-auth/src_codearts-credits.ts:416` 注释逐字；
   `:419-421` 的 `cycleStartTime` / `cycleEndTime` / `expiredTime` 全空串）。⇒ 接上 used 之后
   `holds.holds_bounds()` 仍会走 `HOLDS_NO_CLOCK`。**这是正确结果，不许拿 `reset_secs` 编一个。**
4. **分子恒 0：用量行的模型名与注册表对不上。** `tools/wb_dispatch.py` 的 `usage_in()` 按字面比
   `row.get("模型")`；真机用量行的模型集是 `glm-5.2` / `glm-5.3` / `glm-5.3-flash` /
   `deepseek-v4.1-flash` / `kimi-k3-1`，而注册表（和账本 `approved_models`）用的是
   `huaweicloud-maas/GLM-5.2` 这种 provider/model 写法。实测 2026-11-09：
   `usage_in("glm-5.2", 全年) = 143312742` 而 `usage_in("huaweicloud-maas/GLM-5.2", 全年) = 0`。

## 判据（5 条）

1. **解析只认一条 metric，且绝不把分类相加。** `tools/pool/checkin.py` 加纯函数
   `codearts_package_used(package) -> float | None`：只在 `metrics[]` 里找
   `name == CODEARTS_TOTAL_METRIC` 的那一条，取 `package_credit_used` 与 `package_credit_amount`；
   两者都是有限数、amount > 0、0 <= used <= amount 才算数，否则回 None（**不猜、不除零、不当 0**）。
   钉子：真机形状里 `usageBasicPackageCredit` / `usageBonusPackageCredit` 与 total **同值**
   （2026-11-09 实测 amount 9000.0 / used 4185.59 三者一致）⇒ 相加会算成 3 倍；
   一条断言钉死「结果等于 4185.59 / 9000 * 100 = 46.51，不是 138 或 0」。
2. **codearts 的 probe 走真读，不再用 unsupported 当挡箭牌。** `tools/pool_accounts.py` 的
   `probe_account()` 的 codearts 分支改成：从 `token_env` 取 AK/SK（沿用 `_token_for` 的闸），
   用 checkin 的 `CodeArtsCredential` + `http_fetch` 读一次 `statistics/plugin`；
   成功 ⇒ `kind="ok"`、带 `used_percent`（0~100，两位小数）与 amount（积分余额）；
   缺 AK/SK ⇒ 仍 `uncertain` 且点名 `token_env`；网络不明 ⇒ `uncertain`（**不重放**）；
   401/403 ⇒ `failed`；429 ⇒ `uncertain`。`tools/pool/platforms.toml` 里 codearts 的
   `probe = "unsupported"` 必须改成真读能识别的值（同时删掉或改写那句「本卡不猜读数」）。
   钉子：`tests/test_pool_accounts.py` 的 `test_codearts_probe_is_honest_uncertain` 要**改判据**
   （原来是「永远 uncertain」，现在改成「合成 fetcher 回真形状时 kind==ok 且 used_percent≈46.51；
   没凭据时才 uncertain」）—— 这条测试的**意图**不许丢：没料时必须说不知道。
3. **写回账本只写 used_percent，且只在真读到的那一轮写。**
   `record_probe_result()` 对 `kind=="ok"` 且带 `used_percent` 的行写
   `[account.quota].used_percent`；失败 / skipped / uncertain / 其它平台一律**不写、不删旧值**
   （缺键仍是「未观测」）。写之前必须过 `_check_account()` 的范围校验（0~100）。
   钉子：合成账本写一次后 `load_ledger()` 不炸且值等于 46.51；再跑一次不重复长键。
   ★ 本卡**不改仓外账本**（`D:/repo/infra/pool/accounts.toml`）：真机读数验证只读，
   落账由人跑 `pool_accounts.py probe` 决定。
4. **用量行的模型名按注册表归一。** `tools/wb_dispatch.py` 加纯函数
   `model_aliases(name) -> tuple[str, ...]`（复用 `tools/pool/model_registry.py` 的 `id_names` 三档口径，
   不另写一套），`usage_in()` 改成「任一别名命中即计入」；注册表读不到 ⇒ 退回今天的字面相等
   （fail-open，不许因为注册表坏了就一律回 0）。只在第一次调用时读盘。
   钉子（真机读数钉死）：`usage_in("huaweicloud-maas/GLM-5.2", 全年)` 与
   `usage_in("glm-5.2", 全年)` 必须回**同一个** tokens（2026-11-09 = 143312742，测试用合成 JSONL
   钉同一个关系，不钉这个绝对值）。
5. **文档不再说假话，且把「仍不知道」写清楚。** `docs/subsystems/pool/modules.toml` 的
   `checkin.py` / `pool_accounts.py` 两条 duty 写清新能力并重算 README；
   `tools/pool/quota_history.py` 与 `tools/pool/quota_line.py` 里「used_percent 全仓零写方 / 全 None」
   的缺口改写为「codearts 可写（唯一的写方），其它平台仍无；窗口边界仍缺 ⇒ holds 仍走 clock」。
