# 复盘 · 门禁锁改「按端口段分把 + 全局并发上限」（卡 075 · `T-G169`）

> 时间：2026-09-27 · 树：`.wt/locks1` · 底座：`b90c4e4`
> 用户原话：「**不能多几把跨树锁**」—— 卡规格：`gates/diag/卡075-门禁锁分把与并发上限.md`。

## 一、为什么有这张卡

`gate_lock.py` 原来是**跨树一把**全局锁，七张卡排队、最后一张可能等 40 分钟。
但 062（`T-G156`）已把端口按树隔离，并实测**两个端口段可以同时跑真机门**（四进程 rc 全 0）——
「同一时刻整机只许一趟门禁」这条已无必要。真正的必要条件是两条：

1. **同一个端口段**不许两趟门禁并行（撞端口 → 假红，铁律 13/25 的教训）；
2. **整机并行趟数**有上限 —— 瓶颈是**内存**（一趟 17 门要 15–30 个无头 Edge，机器 15.2 GB、常驻只剩 1–3 GB）。

## 二、改了什么（`gates/diag/gate_lock.py`，别的没动）

- **锁路径按段分把**：取段口径与 `scripts/run_gates.py` 的 `port_base()` 一致 ——
  **不设 `TF_GATE_PORT_BASE` → 仍是 `gates/diag/gates.lock`（路径逐字不变，向后兼容）**；
  设了 BASE → `gates/diag/gates-<BASE>.lock`；非法/越界 → WARN 退默认段（同 `run_gates.py`）。
  `acquire` / `release` / `renew` / `status` 全部认「我这一段」；别的卡调 `release --card X`
  不给段 = 默认段，与今天的口径一致。
- **全局并发上限**：新变量 `TF_GATE_MAX_CONCURRENT`，**默认 2**（=1 即退回全局串行旧行为）。
  实现 = 「先创建本段锁、再重扫全目录计数（含自己）」，超限就**自删退回等空位**并打印
  「当前 N 把在跑（上限 M）…等空位」；计数发生在创建之后 → 不会超卖。
  ★ 空位**随租约一起过期**：名额只数租约内的活锁，持有者死了/租约过期 → 名额自动回归。
  上限只保护内存，**不参与**门禁通过与否的判定。
- **锁文件新增两个字段**：`base`（段）与 `lease`（持有者的租约秒数）。
- **status 重写**：列出**每一段**的锁文件、持有者 card/pid/cwd、已占秒数与**租约剩余**、
  是否超过租约可被清；再报全局限额与当前租约内把数、本段端口占用。
- **顺手收紧一条既有语义（先红后绿测试抓出来的）**：同段 `acquire` 的陈旧判定原来用
  **等待者的** `--stale-after` —— 等的人拿个短 stale-after 就能把别人的**活锁**清走
  （063 现场被 066 拿走活锁正是这个机制）。现在改为以**持有者写进锁文件的租约**为准
  （旧格式锁没有 lease 字段才回退等待者值）。铁律 25/29 的保证是**收紧**，不是放松。
- **没动 `scripts/run_gates.py`**（062/063 定型）；禁区全部未碰。

## 三、五条反证读数（CLI 层在临时 git 仓库跑 —— 不在主仓锁目录留测试痕迹，也不受当时正持默认段锁的卡 072 干扰；门禁阶段照卡在真 9061 段拿锁）

1. **不同段同时拿**（默认上限 2）：`TF_GATE_PORT_BASE=9061` 与 `=9081` 各 `acquire --card 075`
   → 两边 rc=0，锁文件分别是 `gates/diag/gates-9061.lock` / `gates-9081.lock`，
   两行分别报「全局 1/2 把在跑」「全局 2/2 把在跑」。
2. **同段第二把等**：同 9061 段第二次 `acquire --card 075b --wait 2` → rc=3，
   报「★ 等超时（2s）——本段锁被占：card=075 pid=76224（已 19s）」。
3. **全局上限**：`TF_GATE_MAX_CONCURRENT=1` 时第二个段 rc=3，报
   「当前 2 把在跑（上限 1）：075(gates-9061.lock), 075b(gates-9081.lock)，等空位」，
   且 9081 的锁文件**已被自删**（名额没被占着）；`=2` 时两个段 rc 都 0（全局 2/2）。
4. **路径向后兼容**：`env -u TF_GATE_PORT_BASE` 下 `lock_path()` =
   `D:/repo/engineering\gates\diag\gates.lock`（只读路径，不 acquire）。
5. **租约/续租回归**：同卡 `renew` rc=0（age 刷回 0s）；别人 `renew --card 999` rc=5
   （原锁未动）；短租约 4s 睡过头后第三个卡 `acquire` **清掉陈旧锁**（已 7s 未动 > 租约 4s）
   拿到 rc=0 —— 空位回归，不泄漏。
   ★ 过程中抓出并修掉上面 §二 最后一条的语义不一致（第一版读数 rc=3 暴露）。

**先红后绿**：`tests/test_gate_lock_multi.py`（10 条）在旧实现 `b90c4e4:gates/diag/gate_lock.py`
（`GATE_LOCK_UNDER_TEST` 指过去）上 **8 failed / 2 passed** —— 红的正是新能力：
分段并发、全局上限、路径兼容、锁文件新字段、status 多段输出、默认上限。
新实现上 `tests/test_gate_lock_multi.py + tests/test_gate_lock_lease.py` 共 **15 passed**（lease 五条一字未动，仍全绿）。

## 四、测试设计要点

- `tests/test_gate_lock_multi.py` 新建：`importlib` 按路径加载（`gates/diag/` 不是包）；
  把 `main_root` monkeypatch 到 `tmp_path` —— **绝不碰主仓共享真锁**；
  fixture 先 `delenv`（跑测试的 shell 自带 `TF_GATE_PORT_BASE=9061`，不清会污染读数）；
  `_ports_busy` 关掉（互斥/名额断言不依赖它，还省时）；拨 mtime 造陈旧，不靠长 sleep。
- 旧实现兼容：旧 `lock_path()` 同样走 `main_root()`，monkeypatch 点一致 → 同一测试能同时跑两版实现。
- `all_lock_paths()` 从 `lock_path().parent` 派生而不是直接走 `main_root()` ——
  真踩过：lease 测试只 patch `lock_path`，第一版 status 扫了真目录，把 docsync1 树的锁行
  扫进了它的断言输出（当场红）。
