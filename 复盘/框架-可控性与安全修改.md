# 框架的可控性与安全修改（外部证据 + 落到我们管线上的机制）

> **问题（用户 2026-10-03 16:2x）**：「你这个框架、这个外包设施、整个管线**不可能十全十美**的。
> **如何做到这种可控性的维护？以及修改？**」
> 本文件是那次检索的结果（**带真实 arXiv 编号**），末尾给出**要折进框架的条目**。
> ★ **一句话结论**：文献不追求「完美」，要的是 **可控（control）**：**可执行约束 + 闭环 + 多样性匹配 + 显式债务记账 + 可逆迁移**；
> 而**「安全修改」的第一条是「先证明旧判据还活着，再改它」**。

## 一、总纲（文献给的五条，逐条对我们）

| # | 机制（官方词） | 文献依据 | 我们的现状 | 缺什么 |
|---|---|---|---|---|
| **C1** | **可执行约束 / 符合性检查（fitness function · conformance check）**：把「意图」写成**机器判据**，持续对齐「意图 vs 实际」 | [1909.05973] 运行时验证架构侵蚀 · [2401.16382] MAPE-K 符合性检查 · [2609.36148] 云原生架构符合性（**早期就能检出基础设施漂移**） | ★ 有：17 道门 + 台账 + 分层检查。**但**「结构性约束」**不成体系**（分层依赖、目录纪律、跨仓边界） | 把**架构级**约束也做成门（不只功能/文档级） |
| **C2** | **闭环（MAPE-K：Monitor-Analyze-Plan-Execute over shared Knowledge）** | [1508.01330] 设计模式（**强制 monitor 与 analyzer 职责分离**）· [2112.06198] **已验证的回路** + 在线更新管理器 · [1805.08678] 多回路可执行 megamodel · [2511.06352] ★ **不确定性一等公民**：决策从「只估收益」升级为**收益-成本-风险三元** | ★ 我们是**手工版**：门 → 台账 → 复盘 → 卡 → 门 | ①「复盘 → 卡」这条**没有机器判据**（靠主控记得）；② **monitor 与 analyzer 没分离**（同一个人既看又判）；③ 决策没有「成本/风险」栏 |
| **C3** | ★★ **必要多样性（Ashby's Law of Requisite Variety）**：**控制器的多样性必须 ≥ 被控环境的多样性** | [2206.04896] 多尺度版（**每个尺度**都要够，且存在尺度间的权衡）· [1812.00450] 无序系统面对结构化需求**内在不稳定** · [2507.04594] core/periphery | ★ 我们在做「增量 + 每日全量」——**这正是保持多样性** | ★★ **判据**：**不许以「更快」为名削减控制器多样性**（见下面那条实证） |
| **C4** | **技术债的显式记账（TAP / TD register）**：把欠债从隐性变成**可决策项** | [2204.09623] [2103.10317] TAP 框架（TD 工单 + 团队/管理层工作流）· [2205.13872] ★ 开发者**承认欠债但缺上下文排优先级** · [2101.01487] 激励（只有「鼓励」被普遍采用，**管理者感知与开发者体验显著错位**）· [2508.15570] 五步工作坊 + **backlog 提醒（复选框、重提日期）** | ★ 有：坑总账 / 经验教训登记册 / 队列（带 `risk`） | ① 债务**没有利息**（欠着不涨，所以永远排不上）；② 没有**提醒机制**（重提日期）；③ 「坑」与「卡」之间**没有机器连接** |
| **C5** | ★★ **可逆的渐进迁移（strangler fig + convertibility taxonomy）** | [2606.24598] ★★ **可逆迁移路径 + 可转换性分类**，把冻结的专家工作流拆成**可组合、可审计**的阶段，**零业务逻辑改动** · [2608.15135] dual-boot（一个二进制里跑两个变体）· [2103.09728] 迁移顺序用 learning-to-rank 学 · [2505.06885] 知识图谱增量分析定边界 | ★ 我们有：**缝层复制体**（复制不搬）+「原件 vs 复制体逐字节等价」判据 | 「**可转换性分类**」我们没有：**哪些部分可逆、哪些一次性**没有成表的判据 |

## 二、★★ 一条把「为了快而砍门」的代价量化了的实证

| 证据 | 读数 | 对我们的意思 |
|---|---|---|
| **The Cost of Downgrading Build Systems: A Case Study of Kubernetes** [arXiv:2510.20041] | 从 artifact-based（Bazel）降级到更简单的 Go Build：**全量构建慢 23–39%**、高并行度下**增量慢达 75%**；但 Bazel 内存高 81–351% ⇒ 降级使 **CI 资源成本上升最多 76%** | ★★ **「更简单的构建工具在规模化时并不高效」**（作者原话方向）= **Ashby 定律的工程实证**：**简化会削减控制器多样性，成本必然外溢** |
| 反面参照 [arXiv:2405.00796] | 383 个 Bazel 项目：并行构建中位加速 2.0–12.8×、增量 4.2–4.7×；但**只有 68.77% 的项目在 CI 里真用** | 「强工具」的收益是真的，**但要有人运营** |

⇒ **对我们的直接禁令**：**不许为了让门禁变快，就把门/判据/兜底砍掉**。
「增量 + 每日全量 + 三条强制全量」是**多样性**，不是冗余；**要提速就提并行度**（F1），**不是砍控制面**。

## 三、★★ 「安全修改」的六条（改判据之前必须做的）

| # | 机制 | 文献依据 | 我们 | 加强点 |
|---|---|---|---|---|
| **M1** | ★★ **改判据之前，先证明旧判据还活着**：**拒绝点变异测试**（refusal-site mutation）—— 把验证器的拒绝逻辑逐个删掉，看它还咬不咬 | [2608.26183] **Four Ways to Forge a Bundle…**（删拒绝点 ⇒ 暴露 **vacuous pass**；作者结论：**对验证器自身拒绝逻辑做活性测试，比对具体 bug 写回归测试有效得多**） | ★ 我们有「判据随件走 / 反例钉子」（同族） | 只覆盖**部分**判据；没有**系统性地**对拒绝点做活性扫描 |
| **M2** | **规则级差分测试**：同一类规则跨工具比 | [2109.02245] 2,728 项目 / **7,633 处不一致 / 46 个规则级 bug**（38 假阴性 + 8 假阳性，13 类模式） | ✗ 没有 | 我们的「静默失败三族」可以用差分法互相印证 |
| **M3** | ★★ **门禁控制层只信「新鲜、可验证的证据」**：**Don't trust the agent, trust the evidence** | [2607.14890] **Proof-or-Stop**：只在**新鲜且可验证**的证据满足 gate predicate 时才允许状态迁移；用认证完整性与源状态绑定**防止 agent 自报完成**；消融显示**隐藏失败显著减少** | ★★ 我们的「**成送申请 + 证据指针**」就是这个形状 | ① 证据**没绑「新鲜」**（旧判决冒充当前，我们咬过）；② 现在**允许工人自报成功**（`--claim success`） |
| **M4** | ★★ **配置层元验证**（检测「规则被删后仍变绿」） | ★ **文献里没有现成工具**（检索结论明说）；最接近的是 M1（拒绝点变异）与 M2（规则差分），**二者是方法不是插件** | ✗ 没有 | ★★ **这是我们能自研的差异化能力** —— 而且我们已经踩过一次（import-linter 缺「规则必须被覆盖」那一半） |
| **M5** | **假红与漏检必须分开度量** | [2302.10594] Chromium：flaky 预测器**精确率 99.2%**，却把 **76.2%** 的真回归误判成 flaky；改用**失败级特征** MCC 0.20→0.42 · [2401.15788] 分类器效果极不稳定 · [2607.09345] ★ **代码级 flaky 检测有根本上限**（flakiness 是运行时属性） | ⚠ 我们有「区分无关失败」的**意图**（F6），没有**读数** | 假红率 / 漏检率 / 重跑率**三个数分开报**，并**成对**给 |
| **M6** | **验证器自身的脆弱性**也要测 | [1805.03296] 语义等价变异体（重排独立声明）就能让 Boogie 改判 —— 135 个程序里 16 个 | ✗ 没有 | 我们的门会不会因为「语法无关的改动」而改判？（`check_layers` 的引用扫描就是这类） |

## 四、★ 明确的证据缺口（三条，照 F10 附检索面）

1. ★ **没有**把 CI 门禁可靠性写成 **SLO / error budget** 的论文（上面那些指标都是精确率/召回/MCC/重跑率等**代理**）。
2. ★ **没有**专门检测「质量门禁**被删/被削弱**后仍然变绿」的**配置级**工具论文（最接近的是 [2608.26183] 与 [2109.02245]，**都是方法、不是现成件**）。
3. ★ **没有**「变异测试当门禁」的工业**成本**数据（只有「开销是主要采用障碍」的定性结论 [2104.11767]）。

**检索面自述（F10 纪律）**：DeepXiv / arXiv，`categories=["cs.SE"]`（另有构建系统几篇散落在 cs.DC/cs.PL），
2 组问题各 top_k 10–15，逐条试过的词包括：`build system evolution maintainability` ·
`architecture erosion fitness function self-adaptive MAPE-K` · `requisite variety software` ·
`verification of the verifier CI gate` · `mutation testing gate strength` · `CI reliability false positive SLO`。
★ **所以：是「检索面内未见」，不是「没有」** —— 这类数据同样可能落在工业报告 / ICSE-SEIP / FSE-Industry。

## 五、★ 要折进框架的条目（C1~C5 · M1~M6）

| # | 条目 | 依据 | 硬判据 |
|---|---|---|---|
| **G1** | **架构级 fitness function 成体系**：把「结构性约束」也做成门（分层依赖不许倒流 · `framework/` 不许 import 项目代码 · 台账/证据不许指向不存在的路径 · 目录纪律） | C1 | 每条约束一条钉子 + 造错必红 |
| **G2** | ★ **闭环要可判**：「复盘 → 卡」要有机器判据（例如：每条**教训**必须挂到一张卡或写明「不挂 + 理由」；欠债必须有**重提日期**） | C2 · C4 | 教训无归属 ⇒ 红；债务到期未重提 ⇒ 红 |
| **G3** | ★★ **多样性不许被削减**（写进框架的**设计约束**）：任何「提速」改动，**不许**减少门数/兜底/证据面；要提速先提并行度 | C3 · [2510.20041] | 一笔改动若**减少**了门或兜底，必须在文书里**显式论证**并留 override 记录 |
| **G4** | ★ **债务带利息**：欠债进 `risk` 并**随轮次上涨**（时间越久越显眼） | C4 | 债务项的「年龄」在面板/产物里可见 |
| **G5** | ★ **可转换性分类**：每一样要搬的东西标「**可逆 / 一次性 / 不可逆**」，以及**回滚手段** | C5 · [2606.24598] | 迁移清单里每一行都有这三列之一 + 回滚手段 |
| **G6** | ★★ **证据要「新鲜」**：门禁控制层只认**新鲜且可验证**的证据（旧判决不许冒充当前） | M3 | 证据带 `at` + `rev`；不匹配当前 ⇒ 红 |
| **G7** | ★★ **配置层元验证**（拒绝点活性扫描）：**系统性地**对拒绝点做变异，找出 `vacuous pass` | M1 · M4 | 至少一条「删掉某个拒绝点 ⇒ 本该红却没红」的**现成读数** |
| **G8** | ★ **三个数分开报**：假红率 / 漏检率 / 重跑率（成对给），**不许**用一个「绿」代替 | M5 | 产物里三个字段齐全 |
| **G9** | ★ **验证器脆弱性自测**：语法无关的等价改动**不许**改变判定 | M6 | 一条钉子：等价重排后判定不变 |

★ **注**：G2/G4 与 **卡 160（台账接进门）· 卡 162（人话条款建账）** 同域；G6 与**卡 156（旧判决冒充当前）**同域；
G1/G7/G9 是新面（框架侧）。⇒ 落地时**别重复造**，先看那几张卡覆盖到哪。
