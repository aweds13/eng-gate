# 架构审议：外包 + 门禁这套的**三处结构性错配**（2026-10-02）

> 用户当面问「**架构是不是有问题？**」。这一页不是复盘某一张卡，而是**回头看整个架构** ——
> 它是从 T-G99 起、80+ 张卡一处一处补丁长出来的，**从没做过一次"如果重来会怎么设计"的审视**。
> **结论**：方向没错，但有三处**结构性错配**（粒度 / 单写者 / 权威位置），**每一处今晚都咬过我**。

## 一、现在的形状（一句话）

一张卡同时是**六样东西**：工作单 · 冲突域声明 · 验收判据 · 切片来源 · 台账条目来源 · 提交信息；
收口是一条 4 步链（迁树 → 写文书 → 17 道门 → 封存 → 白名单提交 → 审计 → ff）；**三份共享文档每笔都改**。

## 二、三处错配（每条都给今晚的实证）

| # | 错配 | 今晚的实证 | 代价 |
|---|---|---|---|
| ① | **粒度错配**：重量级流程用在轻量改动上 | 卡 113 实际改 **16 行**、卡 114 改 **9 行**，照样走"写卡 + 建树 + 切片 + 工人 + 17 道门 + 三段文书"全流程 | 固定开销 ≈ **10KB 文书 + 6 分钟门禁**，**与改动大小无关**；今晚光门禁就跑了 40+ 分钟 |
| ② | **单写者文书**：三份共享文档**每笔都改** | 今晚 **4 次** rebase 冲突（最惨一次四个文件全撞：changelog / 台账 / 交接 / `last.json`） | **并行度被文书结构锁死**；每次并行都要我手工收缝（片段化只把冲突缩小到"合成那一步"，**合成点仍唯一**） |
| ③ | **权威与工具位置错配** | 白名单**两份**（`wb_dispatch.py` 写死一份、`infra/pool/models.whitelist.toml` 一份）· 派活器**两份** · **收口工具在 gitignore 的 scratch 里** ⇒ 别的窗口拿不到 | 多项目必**漂**；"外包设施"**只能外包干活、不能外包收口**（用户在上一轮当面点出来的） |

## 三、方向对的部分（**别推倒重来**）

- **门禁 / 审计 / 台账是机器判的** ⇒ 今晚 **9 次漏细节、0 次错提交**（这一条最值钱）
- **片段化 + 封存指纹** ⇒ 并发在**提交**这一层可判（不是靠人眼）
- **卡的「禁区 + 回报格式」** ⇒ 工人 / 模型 / 池 / 厂商**可替换**（换 vendor 不动流程）
- **池（`infra/pool`）与项目分层** ⇒ 方向对，只是**权威没定**
- **MCP 暴露** ⇒ 别的窗口能查、能派活（方向对，收口尚未下放）

## 四、三处错配 → 三个结构性动作

| 动作 | 治 | 做法 | 关键判据（防呆） |
|---|---|---|---|
| **A. 分档通道** | ① | `微改`（单文件域、≤~50 行）→ 只跑**相关门** + **一条台账** + 极简卡；`常规` → 现状；`难题` → 大模型 + `brief` 问法 | 必须能回答"**哪几道门对这次改动敏感**"；**漏跑一道门比多跑更危险** ⇒ 要有反例钉子 |
| **B. 文书自动化** | ② | 台账 / changelog / CHECKPOINT 三段话，由机器从（`diff` + 工人报告 + 门禁读数 + 卡的元数据）**生成骨架**，人只写"为什么" | 生成的骨架**必须过 `audit_progress`**（格式判据不松） |
| **C. 权威与工具归位** | ③ | 白名单 / 路由 / 池适配器 → `infra/pool/`（只有用户能改）；**收口工具 + 卡规格 → git**；项目只留"项目特有的规矩" | 一条判据：**每一份白名单只有一处**（多一份就红） |

## 五、迁移代价与风险（如实写）

- **A 分档**：现在门禁**只有"全量"**，没有"哪个文件影响哪道门"的依赖图 ⇒ 中等工作量，
  且**判据方向是反的**（不是"多跑安全"，而是"漏跑危险"）⇒ 要先做一张**门 × 输入**的表。
- **B 文书自动化**：改变的是"**谁写**"（人 → 机器骨架 + 人补判断），台账**格式不动** ⇒ 迁移风险低。
- **C 工具归位**：跨仓（`infra` 是**独立 git 仓**）⇒ 两边各要一笔提交；`infra` 没有门禁，靠读数自证。

## 六、建议次序（按"先治最贵的"排）

**D 防呆收口**（今晚就能做，保护后面每一步）→ **A′ 索引 + 白名单 + 越界守卫**（用户已批）
→ **批次/板块（= ① 分档 + ② 文书自动化 合体，见 §七）** → **C′ 池/模型/问法声明化** → **B 多主控分区**。

★ 为什么把"分档通道"排这么前：**它直接砍掉固定开销** —— 今晚 7 笔里至少 4 笔（113/114 那种十几行的活）
本该走轻量通道，省下来的是**门禁时间 + 我写文书的那一半 token**。

★ 用户随后给了这条通道的**具体形状**（下面 §七）—— 不是"攒够 N 条"，而是**预声明栅栏**。它比我原来写的
"分档"更准，所以 ① 和 ② 合并成一件事做。

## 七、★ 收批 = **任务栅栏**（用户 2026-10-02 提的方向；第二版按用户的纠正重做）

**用户原话（两次，第二次是纠正我理解错的地方）**：

> 第一次：*要引入**版本管理**的理念：小规模的改动应该**堆在一起**，同一个板块堆在一起写文书会好一点。*
> 第二次：*收批应该是我根据**任务的种类**，就是属于不同的板块 —— 比如属于**审美层**的、属于**后端**的、
> 属于**前端**的。然后我在外包程序的某个地方**注册一个任务**，然后任务需要这些板块下面的**多张卡都完成了**，
> 并且**发送了那个成功申请**，然后**集齐所有的成送申请**再写 —— **而不是单纯的数量**。*

★ **我第一版理解错了两处**（照实记）：把"板块"当成了**目录族**（`tools/`、`复盘/`），把放行当成了
"同板块攒够 N 条"。用户要的是：**板块＝层**（审美层/后端/前端 …），**收批的单位是一个任务**，
任务**跨层**地声明它需要哪些卡，**放行判据是"名单上每一张卡都交了成功申请"**，与数量无关。

**一句话形状**：`任务 = 预声明的卡名单（每张卡带自己的层 + 自己的域）+ 一个收件箱 + 集齐判据`。
三样东西都在**主工作树**（`gates/diag/batch/`），全窗口共用一份：

| 文件 | 谁写 | 内容 |
|---|---|---|
| `<任务号>.toml` | **人**，开工前 | 卡名单 · **每张卡属于哪一层** · **每张卡自己的域** · 要自动做什么 · 期限 |
| `<任务号>.d/<卡号>.json` | 各卡自己 | **成送申请**：改了哪张卡 · 为什么 · 碰过的文件 · **证据**（原子写） |
| `<任务号>.json` | 机器 | 哪张卡交了 / 还缺谁 / **history**（每次状态变化追加一行） |

**★ 关键差别（与第一版对照）**：

| | 第一版（我理解错的） | 第二版（用户要的） |
|---|---|---|
| 收批单位 | 一个**目录族**里攒够 N 条小改 | 一个**任务**，跨层地要若干张卡 |
| 成员是什么 | 一条"还没干的小活" | **一张卡**（带层、带自己的域） |
| 放行判据 | 数量（攒够 5 条 / 2 小时） | ★ **名单上每一张卡都交了成功申请**（或缺席者显式豁免） |
| 投的是什么 | "我做完了" | ★ **成送申请**（**成功必须带证据**） |
| 投"不通过" | 只是记一笔 | ★ **挡住收口**（要重投成功申请或显式豁免） |

**"最后一名投递者关门"**：不做常驻守候进程、不轮询 —— 申请写完收件箱**当场数人头**，
齐了就在同一个进程里把状态推过栅栏。★ 理由：守候进程要判死（今晚已经为"判死"付过代价），
而"最后一个到的人顺手关门"天然幂等。

**集齐后自动做**：跑任务里写好的门禁命令 → 读数写进状态（`green` / `red`）→ 按**层分组**生成三段文书骨架
（台账行 / changelog 节 / CHECKPOINT 段，枚举由机器填）。★ **到此停住**（`awaiting-commit`）：
**绝不自动提交** —— ① 门禁红时提交是红线；② 「一笔提交恰好一个台账号」是 `audit_progress` 的机器判据，
要人过一眼。（想全自动：`on_complete` 加 `commit` 即可，**本版故意不实现**。）

**第二版已落地并自证**：`gates/diag/tf_batch.py` —— `register / claim / waive / expire / extend /
advance / landed / status / list` + 可选的 `pool add|list|drop`（"还没定卡的活先按层登记"），
**33 条反例钉子全过**（关键几条）：

- 第 1 张卡交申请 ⇒ 仍是 `collecting`（**不提前放行**）；重复交 ⇒ 幂等（计数不涨）
- ★ **逐卡域越界拒收**（`docs/别的.md` 投进域只有 `tools/a/*` 的卡 ⇒ rc=2 **点名到文件、并指出这张卡的域**，
  且**不覆盖**已收到的申请）—— 卡片级域，比第一版的"批级域"严得多
- ★ **名单外的申请不算数**（防夹带）· ★ **成功申请必须带证据**（不带给 rc=2）
- ★ **有卡投"不通过" ⇒ 哪怕名单上别的卡都成功了也不放行**（要么重投成功申请，要么显式豁免）
- ★ **重投成功申请 ⇒ 集齐当场放行**（`ready → gating → awaiting-commit`，骨架**按层分组**生成）
- ★ **门禁红 ⇒ 停在 `ready`、非零退出**（不提交）；★ **过期 ⇒ 只判死列缺席，绝不放行**（要人显式 `waive`）
- ★ **骨架可重算，但人写的『为什么』在单独文件里、冲不掉**（骨架里只有机器填的枚举）
- ★ **按层把待办登记收成成员**、成任务后从待办表划掉；★ **目录不存在时也能登记**（新机器第一次用）


## 八、五条安全阀（缺任何一条，"等齐"就会卡死或提前放行）

| 安全阀 | 防什么 | 判据 |
|---|---|---|
| ★★ **逐卡的域越界拒收** | 任务变成**绕过冲突域的后门**（最重要的一条） | 一张卡交上来的文件必须落在**它自己声明的 `paths`** 里，否则拒收、点名到文件、并指出这张卡的域 |
| ★ **"不通过"挡住收口** | "名单上别的卡都成功"就把一张黄了的卡蒙混过去 | 有卡投 `failed` 且没被豁免 ⇒ **不放行**（重投成功申请或显式豁免），且非零退出 |
| **名单外不算数** | 夹带 / "以为齐了其实少一张卡" | 不在 `declared` 里的申请 rc=2 |
| **`waive` 显式豁免** | 一张卡挂了整个任务永久卡死 | 豁免**留痕**，账上写着谁没到；豁免后计数照算 |
| **过期只判死** | 悄悄放行一个没干完的任务 | 到 `deadline` ⇒ `timeout` + 列缺席者，**放行要人显式 waive 或 extend** |

★ 另外两条"程序性"约束（不是安全阀但一样硬）：**成功申请必须带证据**（没证据的不叫申请）；
**绝不自作主张提交**（门禁红 / 有人没到 ⇒ 停在 `awaiting-commit` 之前）。

## 九、如实写的边界（这一版还差什么）

- ★ **工具在 scratch 里（gitignore）⇒ 进不了提交**。这与错配③同源：要用起来得先按 §六 的 C 归位。
- ★ **收口入口的批次支持已加**（`_integrate.py --card` / `--batch` 恰好给一个，批号当门禁锁标签），
  但**那是 scratch 工具、没有门禁覆盖** —— 别当成"已经在 git 里的能力"。
- ★ **任务的注册还没有外包面**：现在只能在命令行 `register`；用户说的"**在外包程序的某个地方注册一个任务**"
  还需要把它接到 `infra/pool` / MCP（**下一块活**）。
- ★ **层名没有全局登记表**：目前每个任务的预声明里各自写（审美层 / 后端 / 前端 …）。
  ★ 拿到**多项目**语境下，层名应该属于**项目**（见 §十一），不是全局常量。
- ★ **只治单机**（同机多窗口 / 多卡树）。跨机共用仓不做，也不假装能做。
- ★ **回退粒度 = 整个任务**：一笔提交退不出一张卡 ⇒ 卡内必须逐条写清"改了什么"（申请内容就是为此）。

## 十、第一批真实试用（诚实记录）

**已发现两处"没进 git 就没保障"的实例**：`复盘/号池MCP-使用与设计.md`、`复盘/架构审议-外包与门禁.md`
此前**一直未跟踪**（`git status` 里是 `??`）—— 万一被清理就没了。于是把"这两份 md 文件 + 本节 +
坑清单补充 + 清单 ⑩"当成**一个任务**（`B-DOC1`，4 张"卡"）来收口：一笔提交、一段文书、一趟门禁。

★ 这个任务同时也是**这套机制的第一个反例来源**：搭它的过程中咬出**八条真坑**（`复盘/口径坑.md` 33–40）——
`contextlib` 里 `yield` 写在 `while` 里 · 自证把源文件放进被测目录（假阳性）· 兜底把守卫异常收成退出码 ·
任务目录不存在时建不了锁 · 集成跑一半失败后重跑要先把派生物退回 HEAD（且要 `checkout HEAD --`）·
scratch 工具进不了提交 · `git` 默认把非 ASCII 路径写成八进制 · **通配符写法的 `.md` 引用被 `check_layers`
当断链**（害得卡 116 白跑一趟门禁）。

## 十一、★ 记忆层：同一个窗口跑多个项目，怎么"不干扰 + 还能外包"

**用户第二件事（原话意译）**：*有时候我**同一个对话框**里会运行**不同的项目**（因为一些问题）⇒
需要把**记忆层**弄好：有一个好的方式，**去不干扰，然后又能外包**。*

★ 这个问题的本质是：**设施要通用（否则每个项目分叉一套），记忆要专属（否则脏 token）**。
两者不是矛盾的，只要把"哪一层的东西放哪里"钉死：

| 层 | 内容 | 放哪 | 谁能改 |
|---|---|---|---|
| **通用层**（跨项目一字不变） | 外包协议 · 六条不变量 · 池与模型白名单 · 派活/收批栅栏 · 门禁四要素 | `infra/pool/`（**独立仓**） | ★ 只有用户 |
| **项目层**（每个项目一份） | 该项目的**层名表**（审美层/后端/前端…）· 域表 · 台账/交接/口径坑/工作单 · 卡规格 | **项目自己的文件夹**（本仓 = `复盘/` + `docs/` + `tools/`） | ★ 该项目的主控 |
| **窗口层**（一次会话） | "我现在在哪个项目" + 该项目**最小记忆**（交接卡 + 口径坑 + 在飞任务 + 层名表） | 会话开头**显式声明** | 主控 |

**五条机器判据（"不干扰"要靠机器，不靠自觉）**：

1. **项目索引**（`infra/pool/projects.toml`，＝错配③的 A′）：`项目名 → 根目录 · 记忆入口 · 层名表 · 允许的树前缀`。
   ★ **没登记过的项目不许派活**（存在性即授权，和 MCP 写面同一个思路）。
2. **每个作业/租约/任务/文书都带 `project`**：混跑时能判"这东西属于谁"——池里的租约、任务栅栏的
   `<任务号>.json`、片段文件、提交信息都带上；**同一个 `project` 才允许出现在同一批**。
3. **越界守卫**：派活的 `tree` 必须落在**该项目的根**里；写文书只能写**该项目的记忆入口**；
   跨项目写 ⇒ **拒**（这一条与"逐卡域检查"是同一类守卫，一个治文件、一个治项目）。
4. **记忆按需加载**：主控**只**读当前项目的记忆入口 —— **不**把别的项目的台账/口径坑读进上下文。
   ★ 这就是用户说的"**避免脏 token**"的正解：隔离不是靠"忘掉"，是靠**从来没读过**。
5. **一个窗口同一时刻只活跃一个项目**：切换 = **显式一句**（`tf_project use <项目>`），并把项目态清掉；
   多项目并行 = **多窗口**。★ 机器能提示"你现在带着 A 项目的记忆在动 B 项目"，但**纪律在人**。

**与外包怎么并存**：外包面（池 / 派活 / MCP / 收批栅栏）全部落在**通用层** ⇒ 它天然服务所有项目，
不用为每个项目分叉；项目差异全在"项目的记忆 + 层名表 + 域表"里。今天的实现已经朝这个方向去了一点：
`tf_batch.py` **不硬编码任何层名**（层名写在每个任务的预声明里），所以它天生可移植到第二个项目。

**代价与风险（如实写）**：
- ★ **切换项目要显式**，而且切换后最好**新开一段干净上下文**（旧项目的细节会残留）—— 机器只能提醒，不能代替纪律。
- ★ **同一个窗口"两个项目都活跃"是最容易出错的形态**（写错树、写错记忆入口、把 A 的规矩当 B 的）⇒
  规则是"一次一个活跃项目"。
- ★ **索引本身要有守卫**（项目根不存在 / 两个项目指着同一个根 ⇒ 拒），否则索引会变成新的漂移点。
