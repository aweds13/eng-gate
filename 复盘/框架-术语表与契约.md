# 框架 · 术语表与进程契约

> **这份文件干两件事**：
> 1. **术语表**：把项目里的土话（主控 / 工人 / 栅栏 / 收口 / 坑…）翻译成**权威官方的词**，
>    给出**真出处**、标出**自造词**、并写清**现在用在哪些文件** —— 换个人（或换个 agent）拿到它就能对号入座。

>    这是"框架能不能扔给别人用"的判据。
>
> **出处口径**：标准号 / 书（章节）/ 论文 / 官方文档 URL 一律给**真东西**；查不到就写「**查不到**」，**不编**。
> 「现在用在哪些文件」栏的**计数/文件**来自 2026-10-03 对本卡树（`.wt/terms`，HEAD `244fdff`）的现算，
> 只列**代表文件**（非穷举）。「决策者 / 编排者」两词本卡新增，仓库里 **0 处**，已如实标。

| `0` | 全绿（所有阻断门 `exit_code==0`） | 成功 | 过 | `running` / `done rc=0` |
| `1` | 有门红 | **用法错** | —— | —— |
| `2` | 用法错 / TOML 预检失败 | 接口错（HTTP 4xx/5xx） | 前置检查没过 / 白名单拒单 | 用法错 |
| `3` | **资源闸拒跑**（内存不够） | **环境错**（库/命令表） | —— | `done rc!=0` |
| `4` | —— | 被策略拒绝（写命令没带 `--allow-write`） | 工人自己失败 | —— |
| `6` | —— | —— | 被掐 / 超时 / 撞上限（这一轮不算数） | —— |
| `7` | —— | —— | 白名单模型全挂，停止 | —— |
| `124` | **硬超时**（每道门到点被掐） | —— | —— | —— |

> ★ **同一码语义冲突**（真问题）：`1` 在门禁里 = "有门红"，在 CLI 里 = "用法错"；
> `3` 在门禁里 = "资源闸拒跑"，在 CLI 里 = "环境错"。**四套表没有一份共同真源。**

**与外部惯例逐个对照**：

- **BSD `sysexits.h`（`sysexits(3)`）** —— 把"程序因何退出"分类，供脚本分支：
  `64` EX_USAGE（命令行用法错）· `65` EX_DATAERR（输入数据格式错）· `66` EX_NOINPUT（输入文件不存在/打不开）·
  `69` EX_UNAVAILABLE（服务不可用）· `70` EX_SOFTWARE（内部软件错）· `71` EX_OSERR（操作系统错）·
  `73` EX_CANTCREAT（无法创建输出文件）· `74` EX_IOERR（I/O 错）· `75` EX_TEMPFAIL（临时失败，可重试）·
  `77` EX_NOPERM（无权限）· `78` EX_CONFIG（配置文件错）。
- **shell 保留码（★ 是 shell 发的，不是程序发的）**：`126` = 命令找到但不可执行；`127` = 命令未找到；
  `128+N` = 被信号 N 杀死（如 `130` = 128+2 被 SIGINT）；`128` = 传给 `exit` 的参数非法。
- **`pytest`（官方「Exit codes」）**：`0` 全过 · `1` 有用例失败 · `2` 被中断 · `3` 内部错 · `4` 用法错 ·
  **`5` = 一个用例都没收集到**（★ 与 `0` 严格分开——"没跑"不等于"通过"）。
- **GNU `timeout`（coreutils 手册）**：`124` = **超时**（我们照此约定，见 `scripts/run_gates.py` 文件头）·
  `125` = `timeout` 自己失败 · `126` = 找到但不能调用 · `127` = 未找到 · `137` = 128+9（被 KILL）。
- **「非 0 但不算错」**：`grep` 退 `1` = **没匹配**（不是错）；`diff` 退 `1` = **有差异**（不是错）；
  `cmp` 退 `1` = 有差异；`test` / `expr` 求值为假退 `1`。★ 脚本里**不能**把 `1` 一律当失败。

**三个雷区（必须写进契约）**：

1. **POSIX 只保留低 8 位**：`wait()` / `WEXITSTATUS` 只看 `status & 0xFF` ⇒ `256→0`、`257→1`、`300→44`。
   超过 255 的退出码**会被截断**，跨进程传"大码"必须另走 stdout/文件。
2. **Windows 是 32 位无符号**：`GetExitCodeProcess` 返回 `DWORD` ⇒ 程序 `return -1` 显示成 **`4294967295`**；
   且高位被系统占用（`0xC0000005` = 访问违例等）。跨平台脚本**别用负数/大数当退出码**。
3. **别占用 `126` / `127` / `128+N` 的语义**：它们由 shell / 信号层定义，程序自己发会与"命令没找到 / 被杀"混淆。
   （同理，`64–78` 若要用 `sysexits` 语义，就**整套**用，别只借一两个码。）

### 2. 面向两类调用者的契约

| 调用者 | 要什么 | 我们该给什么 |
|---|---|---|
| **程序 / agent 调** | 可**机器判读**的结果 | **退出码**（稳定、公开、可分支）+ **`--json`**（结构化、schema 稳定、字段不随文案漂）+ **stdio 分离**（`stdout` 只放数据 / `stderr` 只放诊断）+ **幂等可重入** + **不弹交互式提问** |
| **人调** | 一眼看懂、不会误伤 | **`--help`**（自描述：用法 + 参数 + 退出码）+ **人话错误**（说清 *what 错了 / why / 怎么改*，**不许把 Python 栈直接甩给用户**）+ **默认安全**（危险动作要显式旗标，如 `--allow-write`） |

- **正例（本仓）**：`src/timeflow/cli/main.py` —— 有 `EXIT_CODES` 表、`--json`（stderr 给 `{"error":{"code":…}}`）、
  `--help`、`--allow-write` 显式开关，两侧契约都照顾到了。
- **反例（本仓）**：`scripts/run_gates.py` · `tools/wb_dispatch.py` · `tools/wb_task.py` ·
  `scripts/audit_progress.py` · `scripts/check_layers.py` · `tools/wb_land.py` —— **都没有 `--json`**，
  机器只能 scratch 文本（`gates/last.json` 是门禁专属产物，不是通用输出面）。

### 4. 核心 / 薄壳分层

- **原则**：**核心做成库（`import` 可用）**，外面套一层**薄 CLI**。CLI 给**进程/agent**调，库给**代码**调；
  **别人"只调用"用 CLI，"要扩展"用库**。薄壳只做三件事：解析参数 → 调库 → 把库的结果**映射成退出码**。
- **本仓现状（做得好的一半）**：`src/timeflow/**` 是库，`src/timeflow/cli/main.py` 是薄壳，而且 CLI 是
  `docs/commands.toml`（**唯一真源**）的**投影**，不是手写第二份 —— 这正是"核心 + 薄壳"的标准形状。
- **本仓现状（缺口）**：`tools/` 与 `scripts/` 是**顶级脚本**，彼此 `import` 但没有抽成**可安装的库**；
  `harness/`（`harness/README.md` 原话："基础设施与项目之间的『缝』……`tools/` 工作台脚本的**复制体**，
  项目专有值已抽空，全读仓根 `harness.toml`"）就是朝这个方向的**现有尝试** —— 它是复制体，原件仍在 `tools/`。
- **口诀**：**只调用 → CLI；要扩展 → 库**。若某个工具"只能靠改源码才能换值"，那它还不是契约的一部分。

### 5. 文档四象限（Diátaxis）

**Diátaxis**（Daniele Procida，`diataxis.fr`）把文档分成四类，各有各的读者与目的：

| 象限 | 目的 | 读者要什么 | 本仓对应物 |
|---|---|---|---|
| `tutorial` 教程 | **学习**（手把手走通） | "带我走一遍" | `docs/EXTENDING.md` + `examples/01–04_*.py`（可跑的文档） |
| `how-to` 操作指南 | **干活**（解决具体问题） | "我要做 X，怎么弄" | `docs/user-guide.md` · `docs/workbuddy-cli-使用指南.md` · `docs/人工验收-照着点.md`；★ **skills ≈ how-to** |
| `reference` 参考 | **查**（准确、无废话） | "这个参数/命令/字段到底是什么" | `docs/commands.toml` · `docs/specification/**` · `docs/contracts/**` · 各工具的 `--help`；★ **`--help`/手册 ≈ reference** |
| `explanation` 解释 | **理解**（为什么这样设计） | "它为什么长这样" | `docs/README.md` · `docs/implementation/architecture.md` · `复盘/架构索引-分层图.md`；★ **`PIPELINE.md` ≈ explanation** |

> ★ **诚实边界（本仓现状，2026-10-03 现算）**：
> - **`PIPELINE.md` 在本仓当前不存在**（全库 grep `PIPELINE.md` → **零命中**）。它是"框架 + skills"目标态的落点；
>   落地时按 explanation 归位，在此之前，explanation 那一格的现有物是上表右列的三份。
> - **本仓当前没有 `skills/` 目录**（`.codebuddy/`、`.cursor/` 均不存在）。"skills ≈ how-to"是**目标态归位**，
>   不是现状；skill 一旦落地，就按 how-to 写（面向"要干这件事"，不写教程、不写参考）。
> - 四象限是**给自己的体检表**：任一格为空 = 那一类读者没人照顾。本仓当前 **tutorial / how-to / reference / explanation 四格都有**（如上），
>   但 **skills 与 PIPELINE 两格是"计划落点"、非实物** —— 如实标出。
