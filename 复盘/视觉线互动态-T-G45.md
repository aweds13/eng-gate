# 视觉线 · 两件"不需要决定"的小活：互动态补齐 + 手机挤压（T-G45）

> 用户 2026-09-24 说「**先做那两件"不需要你决定"的小活**」—— 两件都在这张卡里，
> 因为它们是"同一个病的两半"：**没人回应**（没有 `:hover` / 看不见焦点）与
> **被挤到读不出来**（不换行的 flex + 中文处处可断行）。合成一张卡 = 只需一轮完整门禁。
> （文件名保留「互动态」是为了不搬动已被台账引用的路径；**第二件见 §9**。）
> 为什么"不需要决定"：登记表里**早就写好了修法**（当初就是照 workbench 抄的），
> 而这两条都不是审美偏好 —— 一条是"手放上去有没有回应"，一条是**可达性缺口**（WCAG 2.4.7），
> 挤压那件则是**读不出来**（实测「改名」两个字被压成一行一个字、43×56）。

---

## 1. 一句话结论

**整张样式表里 `:hover` 与 `:focus-visible` 各 0 条 → 现在 6 / 1 条；一致性门登记表 7 条 → 1 条。**

顺带销账 4 条「一次性裸值」（收敛到最近的档）。两件事都**没有新决定**，但都不是照抄数字：
① 焦点环是**一条全局规则**（只在 `:focus-visible` 生效，鼠标点击不留描边）；
② 悬停**只动 background / border-color / color**（包的原话），实心强调底「**往墨色挪一步**」；
③ 副产品比补 hover 本身更重要：**对比度门从此真读悬停态**（组合数 30 → 34，全部达标）。

**验证**：42 份渲染黄金里 11 份逐字节没动、31 份动的**只有位置**（文字 / 字体 / 颜色全等），
位移与两处档位收敛逐一分类计数（见 §6）—— 也就是"改了观感，没改到内容"。

## 2. 为什么这两条是"最要紧的一条"

登记表当初的原话：

- `interaction:hover` —— 「全表 `:hover` 规则数 = 0。界面没有「手放上去」的回应 ——
  这是「每个元素各过各的」**最大的来源**」；
- `interaction:focus-visible` —— 「键盘用户**看不见焦点**（WCAG 2.4.7）—— 而用户正好提了
  「键盘优先做成附加功能」，所以这条是那个附加功能的**前置条件**，不是可选项」。

第二条尤其值得强调：**它不是"好看"问题，是"能不能用"问题**。
键盘层（⌘K、快捷键）后面才做，但**没有可见焦点**的话，那层做出来也没法用。

## 3. 三条规矩（照 workbench 抄，不自创）

| 规矩 | 包的原话 / 出处 | 我们怎么写 |
|---|---|---|
| 悬停**只动三样** | "Hover moves background/border/colour only" | 不位移、不缩放、不加阴影 —— 工具类界面上"跳一下"比没回应还糟 |
| **一个语速** | `--dur-hover: .12s` / `--dur-state: .18s` / `--motion-ease` | 新令牌进令牌区；`.`toast` 原来手写的 `.2s` 也收回令牌；跟随系统 `prefers-reduced-motion` 归零 |
| 焦点环一条全局 | `.wb-btn:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px }` | `:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px }` —— 一条管全部 |

**实心强调底的 hover 为什么不"再调一个更深的蓝"**：包自己写得很清楚 ——
它**没有**单独的 hover 令牌，因为"发明第二个强调色相"是更坏的做法；
它用的是 `color-mix(in srgb, var(--accent) 88%, var(--ink))`，往**墨色**挪一步：
亮色下变深、暗色下变浅，**两边对比度都上升**（实测 5.22 亮 / 8.13 暗）。

### 3.1 四处必须分开写、不能靠"继承 + 顺序"

这一节是本次真正的坑，全部写进了代码注释（下一次改的人会踩同一个）：

1. **`:not([disabled])` 会带进一个属性选择器的权重** —— `button:not([disabled]):hover` = (0,2,1)
   **高过** `.ghost:hover` = (0,2,0)。也就是说"基础规则在上、变体在下"这套直觉**不成立**，
   hover 必须一条条写全（`button.ghost:not([disabled]):hover`），并放在全表最后。
2. **已勾选的完成圈不能被洗掉**：`未勾选才给浅底` 那条权重 (0,4,0)，和 `.check.on:hover` 并列 ——
   不写清楚的话，鼠标放上去会把"已完成"的实心圈洗成浅灰，**看起来像被取消了**。
3. **当前页的底部 Tab 不给底**：它的颜色就是"你在这一页"的信号；而"强调色当小字"只允许落在
   `--panel` 上（令牌级那对儿在对比度门里）—— 给一层浅底就会掉出 AA。
4. **toast 里的按钮不能套 `--panel-2`**：亮色下那是**浅灰**，而 toast 的字是**白的**。
   改成往横幅里掺 `14%` 字色：可见、安全，而且是**不透明**的 —— 所以对比度门算得了它。
   （模板里 toast 的动作按钮是 `.ghost`，本来会吃到通用的幽灵 hover。）

## 4. 副产品：对比度门从此**真读悬停态**

这是比"补 hover"更重要的一件事。T-G42 的教训是：**一个原子换个写法就整条从对比度表里消失，
门会显得是绿的** —— 而悬停恰恰就是"同一条规则里换个背景"，最容易"加了没人算"。

于是新增 `state_pairs()`：**从 CSS 现算**，不靠手写表。

- 底只认两种写法：`background: var(--x)`，或 `color-mix(in srgb, var(--a) N%, var(--b))`（两令牌 = 不透明，算得了）；
- 字优先取**同一条规则**里的 `color`，没写就取**基础选择器**（剥掉 `:hover` / `:not(...)`）那条的字 ——
  因为悬停只换底，字是从基础规则继承来的，**那才是真会出现的搭配**；
- 带 `transparent` 的合成底**算不了**（得知道它铺在什么上面，那要渲染层）→ **如实跳过**。
  "猜一个底出来"就是造一种假绿，比红更坏。
- 同一对「字/底」**去重**：`.ghost:hover` / `nav button:hover` / 底部 Tab 三条规则落在同一个组合上。

**结果**：组合数 30 → 34，新增两对**全部达标** ——
主按钮悬停 `--accent-ink on mix(--accent 88% over --ink)` = **5.22 亮 / 8.13 暗**；
toast 动作按钮悬停 `--toast-ink on mix(--toast-ink 14% over --toast-bg)` = **9.37 亮 / 8.73 暗**。

## 5. 同时销账 4 条「一次性裸值」

判据是登记表里当初就写好的（"要么并进最近的档，要么承认需要更细的一档"）。**一律选"并进最近的档"**：
多开一档就是让语言更散，而这正是这几条债的病因。

| 原值 | 现在 | 为什么 |
|---|---|---|
| `.swatch` 圆角 `50%` | `var(--r-pill)` | **方形元素上 `50%` 与 `999px` 是同一个圆**；而包对圆角只有三档（6/10/999）——`50%` 只是多出来的第四种写法 |
| `.rail nav` `gap: 2px` | `var(--sp-1)`（4px） | 2px 落在最小档 4px **之下**，不属于任何档 |
| `.card.panel-card .title` `margin-bottom: 2px` | `var(--sp-1)` | 网格外的一次性值 |
| `.fact` `padding: 3px 0` | `var(--sp-1) 0` | 同上 |

**唯一留下的那条**：`literal:line-height:1.5`（`.rail-summary`）——**故意不修**。
它是步 3「排版节奏」的工单：只把这一处换成令牌、而全表其余地方仍然"行距靠浏览器默认"，
那是把债**洗白**（登记表空了，毛病还在）。这一条的理由写进了登记表本身。

## 6. 证明：31 份黄金动的**只有位置**

脚本一次性（比 `HEAD` 的旧黄金与当前渲染）：

- **不许变**（逐行比）：选择器集合（没有元素增删）、**文字 / 字体 / 颜色**；
- **允许变，但每一条都要落到已声明的桶里**：

| 桶 | 行数 | 说明 |
|---|---|---|
| ① 纵向位移 | 3323 | 上面的东西变高了，下面的自然往下走 |
| ② nav 横向位移 | 196 | `.rail nav` 的 gap 2→4：窄屏下 nav 是**横排**的，横向也会动 |
| ③ 容器变高 | 132 | 只允许**无文字的容器**（`.shell`/`main`/卡片/`.fact` 这类） |
| ④ `.fact` padding `3px 0`→`4px 0` | 3 | 声明过的档位收敛 |
| ④ `.swatch` 圆角 `50`→`999` | 18 | 声明过的档位收敛 |

**11 份逐字节没动**（互动态本身零像素：`:hover` 只在指针进入时生效，黄金是静态的）。
没有一处"意料之外"的宽/高/横移/内边距变化 —— 脚本对每一类都判红。

> 中途这个证明**自己出过一次假红**：同一（选择器 + 文字）可能对应多个元素（两张卡上的同一个徽标），
> `pop()` 把 x=89 与 x=183 两个状态点配成了一对，报出"横向位移 94px"。
> 修法是把同一组的元素**按 y 再按 x 排序后配对** —— 位移不改变它们的相对顺序，所以配对是稳的。
> 这正是"证明脚本自己也要能被证伪一次"的例子。

## 7. 没做的（如实记）

- **`--shadow` 的归位**：包把阴影留给真浮层（`--shadow-1`），而我们把阴影用在**卡片**上
  （"层次=1px 边框"是包的规矩）。这是**改视觉**，属步 2「层次语言」。
- **`.card.selected` 的 `box-shadow` 圈**：同上，跟卡片层次一起定。
- **destructive（危险色）按钮的 hover**：包有 `.wb-btn--destructive`（`--danger-weak` 底 + 危险色字），
  我们**没有** `--danger-weak` 这个令牌，且现有删除按钮一律是 `.ghost` ——
  要做就得先决定"删除类按钮要不要升成危险色"，那是产品口径，不是这一步能顺手定的。
- **输入框 / 下拉的 hover**：包没规定，焦点环已覆盖键盘，暂不加（加了就是自创）。
- **非文字对比度（3.0）没有单独的组合表**：状态点、描边仍只靠"令牌级 4.5 地板"兜着
  （T-G27 §6 就记着这条边界）。悬停态的**描边**颜色（如 `.swatch` 的 `--border-strong`）
  同理没被单独量。
  ★ **2026-09-25（T-G70）补了静态那一半**：`AA_NONTEXT_PAIRS` 14 条（控制边界 / 勾选圈 /
  状态点 / 图表数据笔 / 逾期红条，逐对 ≥3.0，没有登记表）+ `AA_NONTEXT_EXEMPT` 11 条（纯装饰，
  只量不判）。这条边界**还剩一半**：**悬停/选中态下的非文字**仍没量（悬停那三对是"字/底"，
  不是"线条/底"）—— 如实留在这里，别以为 3.0 已经全覆盖了。
- **`--accent-weak` 当"选中行"的底**：登记表当初提过这个做法，但那个令牌 T-G44 已经并进
  `--panel-2` 了；真要"选中行"的强调浅底，得先有那个令牌 —— 留给步 2 一起定。

## 8. 教训

1. **"没有 hover"不是审美问题，是两件事**：交互反馈缺失 + 可达性缺口。
   把它登记成一条债、并且**在登记时就写清修法** —— 三个月后做它的人（就是我）不需要重新想一遍。
2. **CSS 的权重不是"后来者居上"**：`:not([disabled])` 带属性权重，能把 `.ghost:hover` 按在地上。
   凡是"基础形态 + 变体形态"的层，**变体的选择器要写全**，不要靠顺序。
3. **门看不见的状态 = 没有门**：补 hover 的同时必须让对比度门**读得到** hover，
   否则下一轮"加一处悬停"就是无人看守的改动。
4. **证明脚本也会撒谎**：它报过一处 94px 的假横移。给证明脚本留一次"自我证伪"的机会
   （先看它报的每一条能不能被人肉解释），比相信它更重要。

## 9. 第二件小活：手机（与另两处）的"中文被压碎"

### 9.1 病根一句话

**不换行的 flex 容器 + 中文处处可断行。** flex 的默认行为是"**先压缩、压不动才换行**"，
而中文的 `min-content` 能低到**一个字宽** —— 于是同一行里有按钮和长文本时，
文本被压成竖排、按钮被压成两行字，而右边其实还有地方。

实测（修复前，390px）：习惯卡标题列 **128×32**（两行）、
「已打卡（点此取消）」**86×73**、「改名」**43×56**（两个字各占一行）、
习惯页摘要卡那一行 **68×80**、「高数」这个分组名 **19×42**。

### 9.2 三处修改（都是"让它换行"，不是"把它调宽"）

| 位置 | 改法 | 为什么 |
|---|---|---|
| `.habit-head` | 加 `flex-wrap: wrap` | 它是**唯一**漏掉 wrap 的动作行（`.card .row` / `.new` / `.offline-bar` / `.gpa-head` 早就有）→ 修完按钮保住原宽、整排落到第二行 |
| 习惯页摘要卡 | `<div class="card">` → `<div class="card block">` | 卡里是**两个块级孩子**（一行摘要 + 一段说明），却被渲染成 flex 行 → 并排互压。其它卡片本来就是 `block`，这处是漏的（三档宽度都受影响） |
| 分组名 | `<span class="grow">` → `<span class="grow minw-160">` | 右边那个 `select`（选项是分组路径）按内容撑宽，把名字压到 19px。给名字一个**宽度下限**，行就换行而不是把字压碎（同 `.card-body` 的 `min-width: 8em` 手法） |

**为什么不是"把按钮改小/改短"**：那是拿内容去迁就布局。
真问题是**没有允许换行** —— 允许之后，三档宽度都拿到合理结果。

### 9.3 验收凭证（这次的判据是**量出来的**，不是"看着好点"）

此前 16 道门**没有一道**看得见这类问题：渲染层把几何采下来了，但**没有人判它**。
于是先补一把尺子：`tools/squeeze_scan.py`（**诊断工具，不进**门禁，理由见下）。

- 修复前：42 份清单里 **11 处**真挤压（5 个视图）；
- 修复后：**0 处**（工具与黄金都已更新）。
- 手机分组名：**19×42（两行）→ 192×21（一行）**，行内布局从"删独占一行"变成"改名/删除一行"。
- 黄金：本轮改 **6 份**（habit × 3 档 + setting × 3 档）。
  其中 desktop/narrow 的 setting 只有**选择器字符串**多了 `.minw-160`（几何逐行相同，y 因上方内容变高而位移）；
  真正改版式的只有 habit × 3 + phone/setting。

**为什么不做成门禁**：判据里有一步是"这行文字要多宽"的**估算**（CJK 按 0.95em、其余 0.5em），
估不准就会误报。硬门迟早会为一次误报把某个视图写进白名单，然后那张表就没人看了。
**人读 + 步 2/步 3 改版式前后各跑一次**才是它的位置 —— 这条边界写在文件头上。

> 这一节也记一条方法论：**"采到了"不等于"验过了"**。渲染层采了几何、对比度门采了颜色，
> 但"这段文字还读得出来吗"一直没人判 —— 补尺子比补一处样式重要。

### 9.4 顺带量到、但**这次不动**的（如实记）

1. **手机任务卡里，标题列被压到 128px**（10 个动作按钮与它抢同一行）。
   这是 T-G32 那类"基宽/下限"问题的残留：屏幕上要放 10 个按钮，**总得有一处让步**。
   这次没动它（改法涉及"手机上动作按钮要不要收进「…」菜单"，属**产品口径**，留给你定）。
2. **5 个输入框根本没穿衣服**（`#exportDir` / `#vaultName` / `#vaultDir` / `#syncPath` / `#archiveDays`）：
   清单里它们是浏览器默认外观（`#ffffff` 底、`1px 2px` 内边距、21px 高），而全站其它输入框是
   `--panel` 底 + 1px 边框 + 10/12 内边距。**根因**：我们把 `input` 按**上下文**上样式
   （`.new input` / `.field input` / `.modal-box input`），而 `select` 有**元素级**基础规则 ——
   于是任何落在这三种容器之外的输入框就是裸的。改法很小（补一条元素级 `input` 规则 + 给
   `#archiveDays` 一个宽度类），但它是**另一件事**（不是挤压），**已登记成新卡**，不塞进这篇。
