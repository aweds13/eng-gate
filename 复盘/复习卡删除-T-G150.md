# 复习卡支持删除（卡 057 · 台账号 `T-G150`）

> 分支/树：`.wt/rev1`（底座 `6f7d4d0`）。这一轮只干这一张卡。

## 为什么有这张卡

用户 2026-09-27 现场提问「**没有删除复习卡功能吗**」。只读盘点
（`gates/diag/盘点-S6-第二批界面反馈.md` §1）实测：界面**零入口**、后端复习那一组**零 DELETE**，
而契约 `docs/contracts/domains/F6-review.md` 的 OP-26 六要素白纸黑字写着「**可逆：可删除**」——
**规格有、实现漏**，不是新需求。

## 改了哪五处（都带指针）

1. **领域层** `src/timeflow/core/review/review.py:205`（`get_item` 与 `update_item` 之间）：
   新增 `def delete_item(conn, item_id) -> bool` —— `DELETE FROM review_items WHERE id=?` + `commit()`，
   返回 `cursor.rowcount > 0`（**是否真删到了**）。形状抄 `src/timeflow/core/memo/memo.py:47` 的 `delete_memo`。
2. **后端路由** `src/timeflow/api/app.py:2075`（复习组内、`get_review` 之后）：
   新增 `@app.delete("/api/review/items/{item_id}")` → 找不到 `404「复习卡不存在」`，成功
   `{"deleted": item_id}`。**为留在白名单内**（见下「边界」），改从实现模块直接导入
   `from timeflow.core.review.review import delete_item as review_delete_item`（`app.py:45`）。
3. **界面入口** `src/web/index.html` 三处：
   - `reviewCard()` 按钮行（`:2931`）加一颗 `ghost danger` 的「删除卡」（带 `data-title`）；
   - `ACTIONS` 表（`:1017`）注册 `'review-delete'`；
   - 新处理函数 `deleteReviewCard`（`regradeReview` 之后）：`confirmAsk` 二次确认 →
     `DELETE /api/review/items/{id}` → `toast('已删除复习卡')` + `view(current)`。
4. **契约** `docs/contracts/domains/F6-review.md`（OP-26 节内，第 30 行起）：补一段**删除实现说明**
   （`DELETE` 路由 + 硬删口径 + facts 不删 + 墓碑自动）——★ **没有新开 OP 编号**（见下「边界」，只加不删）。
5. **测试** `tests/test_review_line.py`（尾部新增 4 条）：硬删后 `get_item` 抛 `KeyError`；
   删不存在 id 幂等返回 `False`；**反证** 删卡不删 `facts`、账目照记；**反证（端到端）**
   删「任务升级来的卡」后 `review-cards` 为空而任务本体还在。

## 口径（主控已在卡里定，未自选）

- **硬删 + 界面二次确认**，不做回收站/撤销 —— 与习惯/成绩/备忘录一致（只有任务有软删+回收站）。
- **`facts` 一个字节都不删**：复习历史流水留在事实层，投入账本不受损。删卡后
  `GET /api/review/{id}/facts` 会因卡不存在而 404（`app.py:2153`），**这是预期**。
- **墓碑自动**：`review_items` 是 LWW 行，v17 已给它挂 DELETE 墓碑触发器
  （`src/timeflow/storage/db.py:1050` + `_migrate_v17`）→ 硬删自动落 `sync_tombstones`，**不手写**。
- **不伤任务**：`review_items.task_id` 是单向弱关联（无外键），删卡只删卡这一行。

## 边界（如实写，没做到/没动的部分）

- ★ **白名单外必需的一处**：`timeflow.core.review` 包（`src/timeflow/core/review/__init__.py`）
  **没有 re-export `delete_item`**，而该文件**不在本卡 §3 白名单**（白名单只列 `review.py`）。
  为**不越界**，`app.py` 与测试都改为**直接从实现模块导入** `timeflow.core.review.review.delete_item`
  —— 与该两文件的既有做法一致：`app.py:43` 本就有 `from timeflow.core.focus import guard as fg`；
  测试文件本就 `importlib.import_module("timeflow.core.review.review")` 进 impl 模块。
  **代价**：`timeflow.core.review.delete_item`（包级）不存在。**待主控定**：要不要把
  `src/timeflow/core/review/__init__.py` 作为「连带文件」补进白名单，做一行 re-export。
- ★ **没有新开 OP 编号**（卡 §2.4 原写「补一条删除操作的 OP 行、先 grep 编号占用」）：
  实测契约层 `OP-1`…`OP-51` **全部已占用**；而 `scripts/check_commands.py`（门禁项 `commands --check`）
  要求**契约里每条 OP 必须有一行 `docs/commands.toml`** —— `commands.toml` **不在本卡白名单**。
  故**不新开 OP-52**，把删除实现说明**补在既有 OP-26 节内**（OP-26 六要素本就写着「可逆：可删除」）。
- **渲染黄金**：复习卡按钮行多了「删除卡」→ 重采。★ `reviewCard()` 同时被 My Day 的

  —— 故**除 `*review*` 外，`*today*` / `*palette*` 黄金也会变**（同一张卡的同一处改动，非越界；
  卡 §2.3.4 担心的「任务详情只读列表」**未动**）。逐份读数见下「黄金」。
- **没动什么**：`facts` / `tasks` 本体、任务详情只读列表、`src/web/app.css`、`core/{memo,tasks,academic,team}/**`、
  `tools/**`、`scripts/**`、其它复盘文件、`.wt/**`、主树外来未跟踪文件。
