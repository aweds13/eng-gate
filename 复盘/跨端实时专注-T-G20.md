# 跨端实时专注 · T-G20 —— 只读镜像（`SR-F3.4` / N17 / OP-51）

> 用户 2026-09-23 定的口径：**实时启动 + 结束时再同步**（见 `复盘/口径落档-T-G19.md` §3.1）。
> 本条把它落地。**没有新表、没有新接口、没有实时推** —— 一句话：把既有那一行 `focus_sessions`
> 读出来，让**另一台设备**当场看见，并且**只看不动**。

---

## 一、这事在原来的代码里缺什么（先说清楚为什么它不是"加个按钮"）

跨端同步专注卡了很久，原因是架构上"两台设备"其实长得不一样：

| 场景 | 真实情况 |
|---|---|
| 手机浏览器打开电脑的页面 | **同一个后端、同一个库** —— 手机不是"另一台机器上的软件"，是远端 UI |
| 手机断网记（T-G10） | 这时手机才真的独立：自己的 IndexedDB + 自己的 `ph-` 设备号 + 离线队列 |
| 电脑 ↔ 电脑（T-G8） | 两台各有各的库，靠同步包合并 |

所以"任一台开始专注，另一台也进入计时"**根本不需要传数据** —— 两边看的是同一行记录。
原来真正缺的只有两件：

1. **分不清是谁开的**：`/api/focus/active` 只回 `{id, task_id, kind, started_at}`，
   没有"哪台设备"；于是**任何**打开页面的人都会看到"专注进行中" + 三个结束按钮 ——
   手机可以**停掉电脑的专注**，电脑重开页面也会把别人的会话当成自己的。
2. **不会自己更新**：右栏只在渲染时拉一次，对面开始了这边不知道（除非手动切页）。

## 二、实现（两处很小的改动 + 一条轮询）

### 后端（`core/focus/timer.py`）
- `active_session()` 多回一个 `device_id`（不改签名、不加表）。
- `start_session()` 把 `device_id` 规整后再落库：`_clean_device()` = 去空格 → 截断到
  `MAX_DEVICE_LEN = 40` → 空白成 `None`。
  **为什么截断而不报错**：它是客户端标识，不是用户填的业务字段 —— 为它拒绝开始专注毫无意义；
  但脏值会让"这是不是我开的"判错，所以入口就规整掉。
- `MAX_DEVICE_LEN` 从 `core.focus` 一并导出（测试与界面文档都引用这一个数）。

### 前端（`src/web/index.html`）
- `clientId()`：**客户端**身份，存 `localStorage: tf_client`。
  - 手机（从局域网地址打开的页面）沿用它自己的 `TFOffline.deviceId()`（`ph-` 号，
    与它导出的同步包**同号**，排障时一眼对得上）；
  - 电脑 UI 用 `cl-` 开头的本机号；
  - **为什么不复用别的号**：服务端的 `sync.device_id` 是"数据库主人"，两个客户端读到同一个值，
    区分不了；`tf_device` 是手机**同步包**的号，电脑浏览器用它会得到一个说谎的前缀。
- `renderActiveMirror()` + `renderActive()` 里一道判断：`active.device_id && active.device_id!==clientId()`
  → 走镜像（只读）；否则（含 `device_id` 为空的老数据）走原来的"我开的"那一支。
- `FOCUS_POLL_MS=10000` + `startFocusPoll()`：每 10 秒问一次 `GET /api/focus/active`；
  **页面在后台/离线时不问**、**失败静默**、**指纹（`id:device_id`）没变就不重画**。
  变了 → 当前在专注页就重渲染该页，否则只重画右栏。
- 结束路径**一个字没改**（`finishFocus` 还是原来那条请求）：这就是"结束时再同步"。

### 镜像长什么样（文案即口径）
```
别处正在专注
12:34
番茄钟 · 来自手机
（归属任务：写高数作业）
这边只看不动：结束请去那边，这里不会重复记一笔投入，也不会打断它。
```
秒数用 `#clockPeer`（**不是** `#clock`）—— `#clock` 永远是"本机计时器"的唯一主人（R3 护栏），
镜像不是本机计时器，它只是把对面的秒数照出来。

## 三、三条硬边界（都是"看起来能用其实是坑"）

| 边界 | 为什么 | 谁在守 |
|---|---|---|
| **镜像卡里 0 个 `data-action`** | 加「结束」= 让这台设备去停另一台；加「我也开始」= 同一段时间记两笔投入 | DOM 探针（`!peerRail.includes('data-action')`）+ 前端护栏 `test_cross_device_focus_mirror_is_read_only` |
| **不重复记账** | 投入口径是账本的地基，同段时间记两笔 = 数字失真 | `test_focus_mirror_line.py`（只读查询前后：行数/事实数/投入全不变）+ 真机自检 5 条 |
| **老数据（NULL）算「我开的」** | 否则「重开页面恢复计时」会退化成"别处正在专注"，老会话还变成谁都不能停 | 单测 `test_legacy_session_without_device_id_is_none` + 探针第三档 |

**另外一句实话**：勿扰在这是"**状态可见**"，不是系统级屏蔽 —— `is_allowed` / `is_do_not_disturb`
本来就只做配置与判定（OP-3c 的口径），主工具不拦系统里的应用。所以镜像卡只说"别处正在专注"，
**不谎称已经替用户按下了勿扰**。

## 四、怎么验的（四层，每一层查的东西不一样）

| 层 | 查什么 | 结果 |
|---|---|---|
| 单测 `tests/test_focus_mirror_line.py`（10 条） | 数据侧：`device_id` 落库/回传/规整；老数据；**只读三次什么都不变**；并行开第二个被拒；端到端只记一笔投入 | ✅ |
| 前端护栏 `tests/test_web_frontend.py::test_cross_device_focus_mirror_is_read_only` | 界面侧：两个入口都带 `device_id`；判定式正确；镜像 0 按钮；轮询的可见性/静默/指纹；不引入推送通道 | ✅ |
| DOM 探针 `tools/ui_dom_probe.mjs`「专注·跨端镜像」 | 真渲染三档：别处（只读 + `clockPeer` + 0 按钮 + 专页文案也变）/ 自己（有结束按钮）/ 老数据（算自己） | ✅ 1/1 |
| 真机自检 `tools/web_live_check.py`「跨端专注」5 条 | 真 HTTP：`device_id` 真落库回传、只读不改、并行被 400、空白归一成 NULL、结束镜像消失且只记一笔 | ✅ 113 → **118 项** |

**踩到的一个坑（值得记）**：探针里第一次跑直接抛 `location is not defined` ——
`clientId()` 用 `location.hostname` 判断"这页是不是从局域网地址打开的"，而假 DOM 没造这个全局。
修法是在探针里补上 `globalThis.location = { hostname: 'localhost' }`（**按回环地址模拟电脑 UI**），
而**不是**给产品代码加 `typeof location` 兜底 —— 真浏览器里 location 一定有，
为测试环境写防御代码等于给产品加噪音。

**顺手被既有护栏抓到的一处**：镜像卡一开始也用了 `id="clock"`，被
`test_focus_timer_has_single_owner`（"页面上只允许有一个计时器读数"）当场拦住 →
改成 `clockPeer`。这条护栏是 R3 留下的，这次证明它还在干活。

## 五、遗留（都不是缺口，是刻意的或等你的）

1. **只在同一局域网且已配对时有效**（跨端那道门默认关）：出门/校园网隔离时看不到镜像 —— 与 T-G10b/10c 同口径。
2. **轮询间隔 10 秒**写死在 `FOCUS_POLL_MS`：我按 §3.1 的建议值定的（你还没点头）；
   要改一个数就行。
3. **镜像态不能停对面的计时**：也是 §3.1 的建议值。若你更想要"这边也能结束"，
   那要先定"结束了算谁的"（记账归属会变），属新口径。
4. **老会话（`device_id` 为 NULL）在两台机器上都开过之后分不出归属** —— 过渡期现象，
   新会话都带号。
