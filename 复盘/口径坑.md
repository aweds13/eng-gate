# 口径坑（主控与工人都先读这一页）

> 一页判据 + 出处。每条都是**真踩过**的（多数是主控自己踩的），照做就少返工。
> 落账 `T-G173`（卡 078）。维护：主控。

1. ★ `last.json` 的「复用」在【顶层 `reused` 字典】，不在每道门里
   （每道门只有 exit_code/name/seconds/summary）。
   —— 主控 2026-09-27 查错两次，第二次把假话写进了凭证文档。
2. ★ 完成判据只看**最后一条** agent 轮次（看整段尾部会被上一轮的「完成。」骗）。
3. ★ PowerShell 的 `>` / `Out-File` 写 **UTF-16LE** → `git commit -F` 报 NUL；
   写 msg 必须用 python 写 UTF-8。
4. ★ 中文路径一律 `git -c core.quotepath=false`；`gates/diag/` 的脚本用 `python -P -X utf8`（铁律 24）。
5. ★ 「现算」类产物（索引/总表/分布数字）必须在**追加台账条目之后**再算一次（铁律 §24.11）。
6. ★ 台账只许在**末尾追加**自己的条目，既有条目一个字不动（铁律 35）。
7. ★ 别 `job_kill` 一个「生了我还要用的外部应用」的作业（子进程会连坐）。
8. ★ 「有没有复用/有没有静默吞活」这类结论，**写进凭证文档前先把字段结构打出来看**。
9. ★ PowerShell 的 `>` / `Out-File` 写的是 **UTF-16** → 落给 python 读的文件要用
   `... | Set-Content -Encoding utf8` 或**用 python 写**。实例（2026-09-28 主控）：拿 `>` 落盘的
   分格 dry-run 表，python 只认出 55/118 行 → 那个"0 处引用"的结论**差点是假的**；改 UTF-8 重做才可信。
10. ★ **验证脚本要先验自己**：查"区段 / 编码 / 行数"之前，先把它们**打出来**。
   实例（同一天）：我用 grep 查"契约类有没有被误列进待分格"，**把【留根层】那半也算了进去**
   → 报出 85 个假警报；按区段分开取（只取 :4..:122）之后才是 0。
   ★ 同族：本文件第 1 条（`last.json` 的 reused 在顶层字典）也是"看错字段"。
11. ★ **「复用通过」≠「这道门现在是绿的」**：`gates/last.json` 的 `reused` 只说「输入没变、采信上一轮」，
    **不说这轮跑过**。自己动过的那道门（或它的输入）**必须 `--no-reuse` 真跑一遍**再提交，否则等于没验。
    实例（2026-10-01，卡 094）：本笔改的正是 `ui_flow` 的输入 —— 靠复用「通过」是自欺，派活时写明 `--no-reuse`。
12. ★ **外包工人的「判决」不是唯一证据源，落盘产物才是**。派活器判「没跑完」时，先翻工人留在
    `gates/diag/` 里的原始读数，别急着重派。实例（2026-10-01，卡 092）：工人在「验收写完、还没自报」那一刻
    被打断（无 `result` 事件、`.meta.json` 没落盘），**6 条原始读数全在 `.ui_run*.txt` / `.ui_before*.txt` 里**，
    直接救回整张卡。
13. ★ **负载器是离体进程**：`gates/diag/flake091_under_load.py` 起的是 detached burn 子进程 ——
    工人被掐 / 超时时**负载会留在机器上**继续烧 CPU，收工前按 `gates/diag/.load_pids` 兜底清一遍。
    同族：**两池并行 + 满载 = 崩** —— 2026-10-01 起第二个池时 node 连崩两次（退出码 `3765269347` / `3221226505`）
    且零产出，`bash` fork 也报 `cygheap read copy failed`。⇒ 外包串行排在门禁 / 负载之后。
14. ★ **封存指纹含未跟踪文件**：`staged_tree()` = `git add -A` 到临时索引（减去 `gates/**`）再 `write-tree`
    ⇒ **封存之后再新增文件，「提交树」就 ≠ 「封存树」**。台账 / changelog / CHECKPOINT / 复盘**必须在跑门禁之前就位**。
    实例（2026-10-01）：想把新复盘塞进同一笔 → 只能改成**后续一笔**。
15. ★ **门禁给每道门都没有超时**：`run_gates.py` 只等子进程 —— 一道门卡死就把**整趟**门禁挂死
    （锁租约到了也不杀它）。实例（2026-10-01）：`ui_flow` 那道门真卡死过 **56 分钟** ——
    `node ui_flow_check.mjs` + `tools/serve.py` + 无头 Edge 全活着、一个字节不写，只能**按 PID 人工掐**。
    自己跑门禁时一律套 `timeout 1800`（Git Bash 里有 `timeout`），别裸跑。
16. ★ **`gate_lock.py release` 要带同一个端口段**：不带 `TF_GATE_PORT_BASE` 时它在**默认段（8531）**里找锁 →
    打印「没有锁，无需释放」→ 真正的锁**泄漏**，一直占着「全局并发上限 2」的名额。
    实例（2026-10-01）：一天泄漏两把（`9034` / `8994`），都是主控自己写的提交脚本忘了带段。
17. ★ **`wb_dispatch.py` 的前置检查看的是「当前工作区」**（不是 `--tree` 指的卡树）：主树一脏就**一律拒派**，
    理由长这样：`工作区不干净（1 个被跟踪文件有改动）→ 一写一读：先提交或收起它们`。
    实例（2026-10-01）：四张卡同时被挡下，只好先把 `复盘/口径坑.md` `stash` 起来才派成。
18. ★ **ruff 的 E501 按「显示宽度」算**，中日韩字符与 `⑯`/`㉒` 这类圈号算 **2 列** ——
    `len(line) < 100` 不等于过。实例（2026-10-01）：一条 61 字符的中文行被判 `103 > 100`。
19. ★ **门禁里任何 `text=True` 却不给 `encoding=` 的 python 子进程都会在中文路径上炸**：
    它按本机区域编码（这台机器 GBK）解，而 `core.quotepath=false` 的 git 吐的是 UTF-8 原始字节 →
    读线程 `UnicodeDecodeError` → `communicate()` 拿到 None → `.stdout.split()` 报 AttributeError
    （**不是**断言失败，容易看错）。实例（2026-10-01，T-G189）：门禁跑的 `pytest` 漏了 `-X utf8`。
    ⇒ 门禁里跑 python 一律 `-X utf8`；写工具时**显式写死 `encoding`**，别指望调用者。
