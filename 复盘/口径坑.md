# 口径坑（主控与工人都先读这一页）

> 一页判据 + 出处。每条都是**真踩过**的（多数是主控自己踩的），照做就少返工。
> 落账 `T-G173`（卡 078）。维护：主控。

1. ★ `last.json` 的「复用」在【顶层 `reused` 字典】，不在每道门里
   （每道门只有 exit_code/name/seconds/summary）。
   —— 主控 2026-09-27 查错两次，第二次把假话写进了凭证文档。
2. ★ 完成判据只看**最后一条** agent 轮次（看整段尾部会被上一轮的「完成。」骗）。
3. ★ PowerShell 的 `>` / `Out-File` 写 **UTF-16LE** → `git commit -F` 报 NUL；
   写 msg 必须用 python 写 UTF-8。
4. ★ 中文路径一律 `git -c core.quotepath=false`；`gates/diag/` 的脚本用 `python -P -X utf8`（铁律 24）。
5. ★ 「现算」类产物（索引/总表/分布数字）必须在**追加台账条目之后**再算一次（铁律 §24.11）。
6. ★ 台账只许在**末尾追加**自己的条目，既有条目一个字不动（铁律 35）。
7. ★ 别 `job_kill` 一个「生了我还要用的外部应用」的作业（子进程会连坐）。
8. ★ 「有没有复用/有没有静默吞活」这类结论，**写进凭证文档前先把字段结构打出来看**。
9. ★ PowerShell 的 `>` / `Out-File` 写的是 **UTF-16** → 落给 python 读的文件要用
   `... | Set-Content -Encoding utf8` 或**用 python 写**。实例（2026-09-28 主控）：拿 `>` 落盘的
   分格 dry-run 表，python 只认出 55/118 行 → 那个"0 处引用"的结论**差点是假的**；改 UTF-8 重做才可信。
10. ★ **验证脚本要先验自己**：查"区段 / 编码 / 行数"之前，先把它们**打出来**。
   实例（同一天）：我用 grep 查"契约类有没有被误列进待分格"，**把【留根层】那半也算了进去**
   → 报出 85 个假警报；按区段分开取（只取 :4..:122）之后才是 0。
   ★ 同族：本文件第 1 条（`last.json` 的 reused 在顶层字典）也是"看错字段"。
