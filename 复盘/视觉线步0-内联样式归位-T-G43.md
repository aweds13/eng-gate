# 视觉线 · 步 0 —— 把内联样式收回 CSS，并证明它零变化（T-G43）

> 用户 2026-09-24 说「继续做」→ 按 `T-G24 §8` 的顺序做**步 0**。
>
> 这一步**看不见任何变化**，它是为后面三步铺路的：样式有一半原先不住在 CSS 里，
> 那么"统一间距 / 统一层次 / 统一排版"就**没法强制**，每改一处都得同时改两个地方。
>
> 这份复盘写四件事：**判据（收哪些、留哪些）**、**怎么证明零变化**、
> **三个当场撞出来的坑**（含两处是"护栏咬到自己"）、以及**诚实的残留**。

## 1. 一句话结论

**99 处内联 `style` → 8 处**（剩下的 8 处**全是动态的**：SVG 几何、进度条宽度、用户挑的强调色预演）。
**视觉零变化有凭证**：42 份渲染清单里，去掉选择器列之后**旧行全是新行的子集**
（唯一一处有意收敛逐条点名）。顺带修掉三个东西：一个我差点造成的整页下移、
一条咬到自己说明文字的护栏、一处把多值当成新档位的档数报告。

## 2. 判据：哪一半该收，哪一半必须留

用一句话判：**这个值随数据变吗？**

| | 例子 | 处理 |
|---|---|---|
| **不变** | `display:block`（卡片放块内容）、`margin-top:8px`、`white-space:pre-wrap`、SVG 的统一外框 `width:100%;height:auto;display:block` | **收到 CSS** |
| **随数据变** | `width:${(r.value/max*100).toFixed(1)}%`（条形长度）、`height:${h}px`（图高）、`background:${c}`（设置页的强调色预演）、`margin-left:${indent}px`（子任务缩进） | **留在标记里** —— 那是数据，不是样式 |

收的时候按优先级走三级，**能用第一级就不用第二级**：

1. **能复用已有语义就复用**：`.card block`（原来 15 处 `class="card" style="display:block"`）、
   `.sub split`（条形图两端标签）、`.meta err`（设置页报错行）、`.bar-track tall/mini`、
   `.fact indent`、`.toast button`（toast 里的动作按钮，原来每处内联 `margin-left` + `padding`）；
2. **不够就按组件命名**：`.ring-head` / `.habit-head` / `.gpa-head` / `.bar-row` / `.stat-label` /
   `.bar-col` —— 它们的 gap 各不相同（14/10/14/6px），合成一个 `.row` 反而要处处覆盖；
3. **只有"同一件事在多个互不相关的组件里各出现一次"才建工具类**，而且**一律单属性 + 令牌值**：
   `.mt-1..5` / `.mb-3` / `.mv-2` / `.mv-4` / `.grow` / `.pre` / `.break-all` / `.minw-*` / `.w-90`。

**为什么工具类必须单属性**：两道门一起在逼这里保持收敛 ——
一致性门的「同形状重复」会把"属性集相同、只有令牌不同"的一族规则报出来
（`.badge` 那四个变体就是这么被抓住的），而「一次性裸值」会把只出现一次的字面量报出来。
单属性 + `var(--sp-*)` 同时躲开这两条 —— **这不是躲门，是让"归位"这件事本身不引入新的破例**。

## 3. 怎么证明"视觉零变化"

`T-G32` 建的那一层渲染清单正好是现成的尺子。清单每行是
`选择器 \t 文本 \t 几何(x,y,w,h) \t 字号/行高/字重 \t 颜色/底色 \t 圆角/内距`。

"归位"只该改**第一列**（元素多了个类名），或者**增加行**（原来匿名的容器有了名字 →
被采进清单）。所以证明写成：

> 把**选择器列去掉**之后，**旧清单的每一行必须能在新清单里找到**（多重集合意义下的子集）。

42 份逐视图跑下来：

- **新增 156 行** —— 原匿名容器有了名字后被采进来了（`.bar-row` / `.bar-col` / `.mt-3` 这类
  包装层第一次进了清单）。**这是覆盖面变大，不是版式变了**；
- **唯一一处有意收敛 42 行**：迷你柱的顶角 4px → `--r-xs`（6px）—— 为什么敢动它见 §4.3；
- 其余**一行不差**。

> 这个证明脚本是**一次性**的（不进仓库）：它的价值在"这一次改动"，
> 而**常年有效的守卫是黄金本身** —— 从今往后谁把某处的间距改了，`render` 门会红。

## 4. 三个当场撞出来的坑

### 4.1 我第一版给雷达图加了 `display:block`，整页往下挪

`.chart` 里写了 `display: block`（手写 SVG 的统一外框——这也是**原来三处内联就写着**的）。
可**雷达图原来没有** `display:block`：它是个没有 display 的替换元素，放在普通 `<div>` 里
—— inline 的替换元素**底下带一行基线空隙**。于是 `.chart.radar` 一加 `block`，
学业页从雷达图往下**整页上移**：证明脚本报`narrow__academic` 79 行、`phone__academic` 79 行不见了。

修法：**`display` 是默认值时，显式写回来**——
`.chart.radar { display: inline; max-width: 260px }`，并把这句理由写在注释里。
（同族的环形图没中招：它在 flex 容器里，flex item 本来就会被 blockify。）

★ **这正是"零变化证明"存在的意义**：这处改动肉眼极难发现（少一行空隙），
而它在 3 档宽度上都留下了痕迹。

### 4.2 R5 那条护栏**咬到了自己的说明文字**

`test_r5_scale_tokens_are_the_only_way_to_write_sizes` 里有一条
`assert not re.findall(r"border-radius:\s*[^;{}]*\d+px", css)`。
我在 `.bar-v` 的注释里为了说清"原来写的是什么"，**原文引用**了那处裸像素 →
护栏把注释当代码，当场红了。

**这是同一个坑的第三次**（T-G39 的令牌抽取、T-G41 的日期护栏各一次）。所以这次不是改注释了事，
而是**改护栏**：先 `re.sub(r"/\*.*?\*/", "", …)` 再判 —— **注释不是代码，护栏该看代码**。
（改注释也能过，但那样下次谁再引用一次代码就又红一次。）

### 4.3 柱子的 4px：唯一一处"有意收敛"，以及为什么不是"顺手改"

模板里那处 `border-radius:4px 4px 0 0` **不在圆角档位上**（6/8/10/12/999），
`T-G24 §3` 早把它记成"令牌化时的漏网（值本身没错）"。收进 CSS 时只有两条路：

- 造一档 4px → 圆角从 7 档变 8 档（`workbench` 的上限是 **3 档**）—— 与"收敛"背道而驰；
- 并进最近的档 `--r-xs`（6px）→ 柱子顶角 2px 的差别。

选了后者，并且**把它当"改动"如实记账**（证明脚本里逐条点名那 42 行、复盘里写在这里），
而不是"混在零变化里过去"。其余任何一处 2px 的差别都不在白名单里 —— 白名单只有这一处。

### 4.4 顺带：档数报告把多值当成"新的一档"

一致性门的档数报告原来对 `border-radius: var(--r-xs) var(--r-xs) 0 0` 这种多值取
"整串字面量"当一个档 → 圆角从 7 档报成 **8 档**，读的人会以为语言又散了一分。
改成**多值只数令牌**（没有令牌的 `0`/`50%` 仍按字面算）—— 报告回到 7 档，
顺带把阴影那行从 `0 0 0 2px var(accent), var(shadow)` 变成 `accent、shadow`（更好读）。

## 5. 收完之后的现状（下一轮的起点）

- **内联 `style` 只剩 8 处**，全是动态值（列表见复盘 §2 的右列）；
- 样式表多了 **19 类工具类 + 18 个组件类**，全部单属性或按组件命名、值全走令牌；
- **`.card.block` 与 `.card.panel-card` 暂时同义**（差别只有 `.title` 那 2px 下边距，
  而那 2px 正是 style_baseline 里登记的一次性裸值）。合并它们属于**步 2（层次语言）**
  —— 那时 `.title` 的间距会进令牌，两处自然归一。这里先把理由写在注释里，免得下一个人
  以为是重复代码。
