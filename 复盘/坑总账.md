# 坑总账（344 条 → 归位点）
这份文件回答一个问题：**我们一路踩过的坑，各自该堵在哪个源头**。

它**不是**检查清单 —— 一份「每趟重跑一遍所有检查」的总表是错题本，冗余且只在事后报「你又忘了」。
分类依据是**归位点**（产生这个坑的那段代码 / 那道门 / 那个登记动作），不是它出现在哪个模块。

数据来路：7 个只读工人把 `复盘/` 下 **218 份**文档逐份读完，**自报合计 314 条**坑（机器从正文逐条解析出 344 条，差额见下）。
机器可判定的那部分压进了 `复盘/不变量台账.toml`（`INV-16` … `INV-77`），本文件写给人看。

> **状态口径**：`已关` = 源头那段代码里真有这条判据**或**真有反例钉子；`半关` = 有判据缺钉子 / 只在复核侧判而源头没判 / 只在文档里写了；`没关` = 只有一句人话承诺，没有任何机器判据。

**总账**：逐条列出 **344 条**（去掉 3 条格式模板残留）—— 已关 **145** / 半关 **116** / 没关 **74** / 未标 9。

> **★ 与工人自报数字对不上，如实记**：7 位工人在结尾自报合计 **314 条**，但机器从 7 份报告**正文逐条解析**出 **344 条**（差额 30）。抽查过：差在**有几份报告的统计行少算了自己列出的条目**（例如前端那位报 42、正文实际列了 61 条）。**以逐条列出的为准** —— 这条差额本身就是下面「④ 同一概念多份真源 / 数字手抄」的又一次现场。

## 跨门类共因 Top 5

**① 判据是单向的（最贵）** —— 只查「你声称的有没有」，不查「实际发生的有没被声称」。
四个面：`scripts/audit_progress.py::eval_assertion` 对 `test:` 只核**文件名**不核用例名；`tools/sync_docs.py::run` 的 `--check` 只查「片段没进汇总」（反方向查不出）；收口链的 `--allow` / `--evidence` 漏了本笔实际改动没有任何东西会咬；栅栏的域检查原先只吃申请方**自报**的 `--files`（卡 131 才改成吃卡树实际改动）。
漏了它会怎样：台账里没点到的文件等于没进账，而**门禁全绿**。

**② 只有一句人话、没有机器判据** —— 协议 §十二（回合收工 / 自动推进）整节、「视觉类改动必须人工过目」、「悬停只许动 background/border/color」、「层次 = 1px 边框」、「教训只写一处」、「状态字段没人复查」。
漏了它会怎样：它会被当成「已经不可能发生」，直到下一次复发现场。

**③ 覆盖面缺口** —— `tools/ui_text_scan.py::INDEX` 只扫 `src/web/index.html`（CLI / MCP / 后端说明文字长回来没人拦）；审计的 `test:` 只核文件名；`tools/**` 与 `scripts/**` 的不弹窗扫描是后补的；`src/web/*.js` 与 `tools/**` 不在时间源反悔闸的扫描面里。
漏了它会怎样：门是绿的，但绿的范围比你以为的小。

**④ 同一概念多份真源（谁也不从谁派生）** —— 域有 4 份声明、模型白名单有 2 份、面板的卡死阈值曾硬写 480 s、卡树基点、`docs/` 里的数字手抄。
漏了它会怎样：改了一处、另一处还在，而且**两处都「绿」**。

**⑤ 判据自己会假绿（判据强度没人验）** —— 空夹具 / 「结构齐全、数据为零」/ 护栏挑了两处都有的串（恒真）/ 桩数据缺字段走保守路径 / `--only` 写错字报「0 条流通过」/ 黄金在**错的那一刻**被采集下来。
漏了它会怎样：该红的不红，而你以为验过了。
