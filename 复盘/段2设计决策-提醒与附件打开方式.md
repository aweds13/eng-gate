## 二、决策 1：系统通知**直接做**，以「设置开关」形式存在

**用户口径**：「直接加设置开关接系统通知就行啦」。

**定案**：
- 加 `tasks.remind_at`（提醒时间，本地时间字符串，可空）。
- **到点发系统通知**（桌面端），并在设置页给一个**开关**（默认**关**，避免装完就弹）。
- 界面同时标出来（今天到期 / 已过期 / 临期），这样"没开通知"也不瞎。
- 通知实现方式与依赖（选型、是否要后台常驻、开机自启）**在 T-B5 动手前先写方案给用户确认**——
  因为它是本项目**第一个新增运行时依赖**，且"关掉 app 还响不响"必须事先讲清，不能做出"以为会响"的假承诺。
- 移动端/浏览器端：PWA 通知需要 HTTPS + 授权，**一版不做**，只在界面上标出来（如实标注，不假装）。

**为什么用开关而不是默认开**：默认开会在第一次运行时弹系统权限 / 突然冒通知；
默认关 + 用户在设置里明确打开，符合"本地优先、不打扰"的基调（N31/N34）。

## 三、决策 2：附件/要求链接的**打开方式按格式切换 + 白名单直接打开**

**用户口径**：「点击后跳转文件夹，设置成可切换，根据文件格式来切换那种，可以单独把一些列成直接打开白名单」。

**定案（三层，逐层收窄）**：

```
① 默认行为（分格式）
   - 网页链接（http/https）      → 新标签直接打开
   - 目录路径                    → 资源管理器打开该目录
   - 本地文件（.pdf/.docx/.md/.png 等"文档类"）→ 打开所在文件夹并定位
     （Windows: explorer /select,"路径"；找不到就退化为打开所在文件夹）
   - 其它本地文件（未知/可执行类）→ **只打开所在文件夹**，不直接运行

② 用户可切换
   设置里一个「打开本地文件的方式」三选：
     - 打开所在文件夹（默认）
     - 直接用默认程序打开
     - 按格式自动（= ① 的规则）

③ 直接打开白名单（用户自己维护）
   设置里列一组**扩展名**（如 .pdf .md .docx .txt .png .xlsx），
   落在白名单里的文件**无论上面怎么选都直接打开**；不在白名单的一律只到文件夹。
```

**为什么默认"到文件夹"而不是"直接打开"**：点开本地文件等于**从文档里启动程序** ——
误存一个 `.exe`/`.bat`/`.lnk` 点一下就跑了。默认收严（到文件夹）、用户显式放行（白名单），
和项目一贯的"默认保守、可放宽"（如专注白名单默认阻止非白名单）一致。

**诚实边界**：
- 浏览器不能凭网页打开本地文件；本项目靠**本地服务**返回 `file://` 链接让浏览器导航 ——
  这条链路**要在真机上验证**（不同浏览器策略不同），验证不过就降级为"复制路径 + 提示"。
- 一旦"复制路径"成为兜底，就**绝不能静默失败**：失败必须提示。

## 四、决策 3：优先级 3 档

**定案**：`tasks.priority` ∈ {高, 中, 低}，默认「中」。
**排序口径**：`截止日 → 优先级 → 创建时间`（把 `list_tasks / myday_tasks / overdue_tasks` 统一）。
**呈现**：卡片小色标（高=强调色实心 / 中=描边 / 低=灰）；**Important 视图 = 高优先级**。
**明确不做**：1~5 数字分级、拖拽排序（拖拽需要前端持久化顺序，属独立任务，未排期）。

## 六、这次三个决策共同体现的一条原则（值得记下来）

**"默认保守 + 显式放行 + 失败必提示"**：
- 通知默认关，用户开了才响；
- 本地文件默认只到文件夹，白名单里的才直接打开；
- 任何"打不开/发不出"都必须出声（toast / 台账 assumption），**不允许静默**。

这条原则来自本轮之前的教训（"测试全绿 ≠ 功能对"、"以为会响其实没响"），
在段2 的三处都会用到。

## 七、实施记录（2026-09-18 · T-B4 附件已落地）

**三层规则照原样落地，但"谁来打开"改了实现方式**（此处如实记录偏离与理由）：

| 项 | 原设计（§三 的诚实边界） | 实施时改成 | 为什么 |
|---|---|---|---|
| 打开本机文件/文件夹 | 本地服务返回 `file://` 链接，让**浏览器**导航；不通则降级"复制路径 + 提示" | **后端直接执行**本机动作（Windows `explorer` / `startfile`；其它平台 `xdg-open`/`open`） | 浏览器不会替网页开资源管理器；`file://` 从 http 页面跳转在 Chrome/Edge 默认被拦。用户要的"点击后跳转文件夹"只有本机进程能可靠做到 |
| `file://` 链接 | 主路径 | 仍随响应返回（`file_url`），只作展示/兜底 | 不依赖它，但不丢掉（信息不浪费） |
| 模式与白名单 | "设置里选" | **存服务端**（`app_settings` 表），**不接受请求参数指定** | 否则任何网页都能要求"直接打开"（服务端有 CORS，本地接口被跨站调用是真实风险） |
| 调用来源 | 未提 | `POST /api/attach/open`、`PUT /api/settings/attach` 加**来源守卫**（Origin 必须是回环，否则 403） | 这两个接口会在本机开东西/改设置，必须确认是"你自己的页面"在调用 |
| 可执行/脚本类 | 白名单"无论怎么选都直接打开" | **永不直接打开、也不许进白名单**（只到文件夹） | 从文档里启动 `.exe/.bat/.lnk` 的风险太高；用户的白名单需求（pdf/md/docx/图片）不受影响 |

**仍然保留的诚实边界**：
- "真正弹窗那一下"（Explorer/默认程序真的打开）**需要人工点一次确认**——
  自动化只能覆盖到"解析结果正确 + 真服务 + 真文件系统 + dry_run"，不会在自检里弹窗打扰你；
- 非 Windows 平台是尽力而为（`xdg-open`/`open`），做不到就返回失败并**复制路径 + 提示**（不静默）；
- 「关掉 app 还响不响」这类问题属于 **T-B5 提醒**，届时单独出方案。

## 八、T-B5 系统通知选型方案（**待用户确认**，2026-09-18）

**已做完的前半**（不需要任何新依赖）：`tasks.remind_at` 字段 + 时间校验 + 界面口径
（`over`/`today`/`soon`/`later`）+ 今日页「该提醒了」区 + 卡片/详情标注。
**剩下的只有一件事**：到点时怎么把通知弹出来。它是本项目**第一个新增运行时依赖**，所以按约定先出方案。

### 三个方案

| | A. 应用内后台轮询（零依赖） | B. Windows 计划任务 + 通知脚本 | C. 第三方通知库 |
|---|---|---|---|
| 做法 | 服务进程起一个后台线程，每 30 秒查 `due_reminders()`；到点用 **Windows 自带的 WinRT 通知**（PowerShell 调 `ToastNotificationManager`，Win10+ 无需第三方包），失败则退化为应用内提示条 + `msg` 尽力尝试 | 用 `schtasks` 注册一个每分钟跑一次的脚本（读同一张表），到点弹系统通知；应用没开也响 | 引入 `win10toast` / `plyer` / `winotify` 之类库 |
| 新增依赖 | **0**（标准库 + 系统自带命令） | 0（但要写进计划任务，属**系统层改动**） | **有**（pip 包，需你同意） |
| 应用关掉还响吗 | **不响** | **响**（这是它唯一的优势） | 不响（库只在进程内） |
| 复杂度/风险 | 低；线程随服务退出，行为可预期 | 中：要写注册表无关但**会改系统计划任务**、要考虑路径/权限/py 环境、卸载要清理 | 低，但多一个包的维护面 + 打包/分发问题 |
| 与"本地优先"基调 | 一致（不装东西、不留系统痕迹） | 留系统痕迹（可清理） | 一致 |

### 我的倾向（供你参考，不替你决定）
**先 A，并把"应用没开也响"作为**已知边界写进界面**；如果你明确要"关掉也响"，再上 B（并且明确它是可逆的：
`schtasks /delete` 能干净删掉）。** 理由：① 现在连界面标注都还没有人用过，先让 A 跑一段、你确认触发时机对不对，
再决定要不要动系统层；② A 不留系统痕迹、零依赖，符合项目基调；③ C 除了省一点代码没有任何独有能力，不值得多一个依赖。

### A 方案的落地细节（你点头就能做，属于 T-B5 后半）
1. 开关：设置页「提醒」区加一个**默认关**的开关（存 `app_settings.reminder.notify=on/off`），
   打开时才真的弹；关掉就只剩界面标注（对齐"默认保守 + 显式放行"）。
2. 只在**应用运行时**轮询：后台线程 30s 一次，`remind_at <= now` 且未完成、且**同一条提醒只弹一次**
   （用 `app_settings.reminder.fired.<task_id>` 记已弹，改时间后重算 —— 避免刷屏）。
3. 通知内容只说事实：任务标题 + 提醒时间 + 「逾期/今天」；**不施压、不告警**（与周结算/热力图文案同一基调）。
4. 移动端/浏览器端：只标不通知（PWA 通知需要 HTTPS + 授权，一版不做），界面如实写明。
5. 失败必提示：弹不出来时在界面上留一行记录（不静默），并可供你排查。

## 九、T-B5 决策落定与实施记录（2026-09-18）

**用户先问"可以调用系统的闹钟软件吗"，再选了 B′（计划任务 + 系统通知）。**

### 关于"系统闹钟 App"的结论（如实记下，免得下次再绕）
- **能**打开「闹钟和时钟」App（`explorer.exe shell:AppsFolder\Microsoft.WindowsAlarms_8wekyb3d8bbwe!App`）；
- **不能**通过任何受支持的接口往它里面**建/改闹钟**（微软没开放；社区多次尝试的结论一致）。
  硬做只能改它的内部状态存储，属不可靠旁路 —— 不做。所以它只能当"打开 App 的便利按钮"，不能当通知通道。
- 另外查证：**计划通知（ScheduledToastNotification）能在 App 未运行时弹**，但**交付窗口只有 5 分钟**
  （机器在窗口内关机超过 5 分钟就丢弃），微软自己建议"要保证送达就用带时间触发器的后台任务"
  （[MS Learn：计划 app 通知](https://learn.microsoft.com/zh-cn/windows/apps/develop/notifications/app-notifications/app-notifications-scheduled)）
  —— 这正是 B′ 用计划任务的理由。

### B′ 落地形态（已实现）
- `core/remind.py`：注册 `schtasks` 计划任务 `timeflow-reminders`（每分钟一次，`/F` 覆盖）；
  命令用 `pythonw.exe`（不闪黑框），脚本与数据库都给绝对路径；`src/timeflow/app/remind.py` 是任务入口
  （也支持 `--check` / `--now` / `--test`）。
- 通知：PowerShell 调 WinRT 系统通知（标题/正文走环境变量，中文不乱码）→ 失败退 `msg` → 都不行如实报错。
- 开关：**默认关**；打开 = 注册任务，关闭 = **删除任务**（可逆、不留痕）；注册失败设置不落库。
- 防打扰：同一条提醒只弹一次（改了时间重新弹）；一次到点太多（>3）合并成一条汇总；失败不标记、下次重试。
- API：`GET/PUT /api/settings/reminder`（PUT 有来源守卫）、`POST /api/reminders/test`。

### 追加：提醒方式（2026-09-18，用户反馈"不是闹钟那种，效果很差"）

**问题**：第一版弹的是普通 toast —— 右下角浮几秒就没了，容易错过，确实不像闹钟。

**改法（仍不引依赖，用 Windows 官方 toast 能力）**：加「提醒方式」设置，默认 **闹钟式**：

```xml
<toast duration="long" scenario="alarm">
  <visual><binding template="ToastGeneric"><text>标题</text><text>正文</text></binding></visual>
  <audio src="ms-winsoundevent:Notification.Looping.Alarm" loop="true"/>
</toast>
```

官方文档依据（[toast 元素](https://learn.microsoft.com/zh-cn/uwp/schemas/tiles/toastschema/element-toast)、
[audio 元素](https://learn.microsoft.com/en-au/uwp/schemas/tiles/toastschema/element-audio)）：
`scenario="alarm"` = 警报通知，**预先展开、一直显示直至消失**、音频**默认循环并使用警报音频**；
`scenario="urgent"` 还能突破专注助手（我们借 alarm 方案的语义，不额外声明 urgent）。

**诚实边界**：
- **实测结论（2026-09-18，用户目视确认）**：闹钟式**确实会一直留在屏幕上、并且有响铃** ✅ ——
  非打包程序（PowerShell AUMID 这条路）也能拿到 alarm 方案的语义，**不需要**再自建响铃窗口。
- 若将来遇到系统策略把它降级（例如企业策略关掉通知），退路仍是自建"响铃窗口"：
  用标准库 `tkinter` 开一个**置顶窗口**（大字号标题 + 「知道了 / 5 分钟后再提醒」按钮）+ `winsound` 循环响铃，
  直到点掉才消失 —— 100% 由我们控制，代价是多一个前台窗口（记 T-B5c，本次不需要）。
- 想更"正经"（通知上显示 timeflow 的名字与图标而不是 Windows PowerShell），需要注册一个通知身份
  （开始菜单放一个带 AUMID 的快捷方式）—— 多一个系统痕迹，等你点头再做。
