## 3. 修法：三件事，都不是"我调了一个颜色"

### 3.1 `--danger` / `--ok` 换成包自己的值（同一件事 T-G39 对强调色做过）

我们原来用 `#ef4444` / `#22c55e`。**这一档颜色的性质是"当色块可以、当字和点不行"**：

| | 当 12px 小字 | 当 8px 状态点（非文字只要 3.0） |
|---|---|---|
| `#ef4444` / `#22c55e`（我们原来） | 3.60 / 2.18 ✗ | 3.76 / 2.28 ✗ |
| `#d1242f` / `#1a7f37`（**包自己的**） | **5.01 / 4.85** ✅ | **5.24 / 5.08** ✅ |

"把 `#ef4444` 自己调深一点"就**是发明一个包不拥有的颜色**（包的 Gotcha 原话，T-G26 §3 已继承）。
所以跟包，不自己调。暗色同样跟包：`#e5534b` / `#3fb960`（亮暗同源：一个语义角色一个值）。

> 这一步**不申请新的颜色**，只是承认"我们抄包的时候抄错了两个值"。T-G39 换强调色用的是同一条理由。

### 3.2 徽标：一个原子抄了四份 → chip 原语 + 状态点

旧写法（四份 `background` + `color`，其中三份是"同色写字"）→ 新写法：

```css
/* 原语：几何只写一遍 */
.badge { display:inline-flex; …; border:1px solid var(--line); border-radius:var(--r-pill);
         background:var(--card); color:var(--muted); font-size:var(--fs-xs) }
/* 映射表：状态只映射"点"的颜色 */
.badge .dot        { width:8px; height:8px; border-radius:var(--r-pill); background:var(--muted) }
.badge.done  .dot  { background: var(--ok) }
.badge.doing .dot  { background: var(--accent) }
.badge.hard  .dot  { background: var(--danger) }
```

- **中性徽标**（分组名 / 课程 / 附件数…）照包的 chip：**卡片底 + 1px 边框 + `--muted` 字**。
  `--muted` 落在卡片底上是 **4.76** ✅（落在旧的浅灰底上只有 4.23/4.34）。
- **状态徽标**照包的 `StatusDot`：**8px 圆点承担颜色，字一律是芯片色**。
  顺带满足包那条"**状态绝不只用颜色**"—— 点旁边永远有字（完成于…/未完成/进行中/硬考核）。
- `.badge.todo` 的规则删掉：它和中性和同一种，"未完成"由字说出来（类名留在模板里当状态钩子）。

### 3.3 状态点为什么是**真元素**而不是 `::before`

第一版我写的是 `.badge.done::before`（更省 DOM，也更像"造型"）。写完意识到一个**验证层的问题**：
`tools/render_check.mjs` 采的是 `document.body.querySelectorAll('*')` 的**计算样式与几何** ——
**伪元素不在里面**。也就是说这个点"还在不在、什么颜色"，**没有任何一层能验**：
对比度门只看令牌值（不知道谁用了谁），一致性门只看规则形状，渲染黄金看不到它。

那正是 T-G32/T-G40 反复抓到的同一类盲区（**采不到的东西等于没验过**）。改成真元素之后，
黄金里每个视图都多了一行，形如：

```
div.card-body>div.meta>span.badge.done>i.dot    305,310,8,8    11/normal/400    #64748b/#1a7f37    999;0px
```

—— **8×8、色 `#1a7f37`、圆角 999**，视图级钉住。另有一条 pytest 钉"每个状态徽标都必须带点"
（谁以后新写一处 `class="badge done"` 忘了 `<i class="dot">`，当场红 —— 否则那一枚会静默地没有颜色信号）。

## 4. 顺手关掉的两道门

### 4.1 一致性门：8 条 → 7 条（`.badge` 同形状抄 4 份那一条真的消失了）

T-G29 登记的 8 条里有一条是「`.badge.done/.doing/.hard/.todo` 四个变体同形状、只有令牌不同」
（它给的修法就是"抽原语 + 状态映射表"）。这次照它做，**副产品是这条判定自己不再命中**：
状态色搬到 `.badge.X .dot` 上之后，原来的 `.badge.X` 规则不存在了。

> 顺带说清一个**门的能力边界**（这次撞到的）：`check_shape_duplicates` 判的是"属性集相同、
> 只有令牌不同"。**纯 CSS 里表达"原语 + 状态映射表"本来就长成四行同形状规则**，
> 所以它分不清"抄了四份"和"老老实实做了一张映射表"。我没有去改这道门的判据
> （放宽它就会连原来那条真问题一起放过去），而是**选了另一条路**：让状态落在 `.dot` 这个
> 子选择器上 —— 子选择器本来就被这条检查跳过（它只看单一类选择器）。这是"用形状表达语义"，
> 不是把门调松。

### 4.2 对比度门：棘轮 → 硬门（`--strict`）

登记表清空之后，`run_gates.py` 里那条命令从 `--check` 换成 **`--strict`**：
不只是"不许新增/不许变坏"，而是**任何一条不达 AA 都当场红**，连"登记一下先欠着"这条退路也关掉了
（要欠账就得改这条命令，那是一个有痕迹的动作）。

同一次还**泛化了 `badge_pairs()`**：原来只认 `color-mix(...)` 合成的底，现在令牌底
（`background: var(--ok-weak)`）也认。理由写进代码注释了 —— 这个函数是"别漏抓"的保险，
**一个原子换了写法就整条从表里消失，门会显得是绿的，那是最坏的一种绿**（T-G27 自己在
"注释被吃进选择器"上栽过一次）。它的回归守卫也一并改成喂**合成 CSS**，不再绑当前配方：
绑配方等于"配方一换，守卫跟着换"，那它守的就不是这个能力了。

## 5. 撤掉的三行 —— 不是"改好了"，是**搭配不存在了**

组合表少了 3 对 × 两套主题（42 → 30 条）。**这三行是删的，不是修的**，在这里逐条交代：

| 撤掉的组合 | 为什么它不属于"欠账" |
|---|---|
| `--muted on --surface-2` | 那是旧 `.badge.todo` 的底。徽标换底之后，**样式表里没有"`--muted` 坐在 `--surface-2` 上"这种搭配了** |
| `--muted on --accent-soft` | 同上（旧 `.badge` 默认） |
| `--accent on --bg` | 唯一实现处是 h1 那个装饰点，**连类带用法一起删了** |

> **为什么要删而不是留着当"已知"**：`tests/test_contrast_audit.py` 有一条
> 「登记表不许有对不上任何组合的行」—— 僵尸行就是假证据。
>
> ⚠️ **残留风险，如实记**：静态表看不见"以后有人又在页面底上写一处强调色小字"。
> 那不是"没想到"，而是**静态分析的信息不够**（要知道"谁坐在什么底上"得有渲染层 / 有布局）。
> 现在的兜底是：库里的 chip 原语已经把"颜色由形态承担"变成默认写法，且 `.accent` 这个类不存在了。

## 6. 顺手纠正的两处语义误用（"语义色不做装饰"）

审样式表时发现的，不属于对比度欠账，但**同一个病**（拿状态色当装饰）：

| 处 | 原来 | 现在 | 为什么 |
|---|---|---|---|
| 计划步骤的序号徽标（`doing`） | `<span class="badge doing">1</span>` | `<span class="badge">1</span>` | 序号**不是状态** —— 借强调色只是让数字好看，正是 workbench 禁的"语义色做装饰" |
| 复习「今天记的是 记得/模糊/忘了」 | `badge done`（绿点） | `badge`（中性） | 那是**档位标签**，不是"完成"状态 |

（两处都没被任何断言/黄金点名，属于"没人看见的错误语义"；改了它们黄金只差一点颜色。）
