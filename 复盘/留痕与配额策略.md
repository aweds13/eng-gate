## §一 术语（照用户口径：官方记录管理的词，不比喻）

| 土话 | 正式术语 | 出处 |
|---|---|---|
| 该留多久 | **保留期限 / 保留计划（retention schedule）** | ISO 15489-1（信息与文献 — 记录管理） |
| 到期怎么处理 | **处置（disposition）**：销毁 / 移交 / **归档（archival）** | ISO 15489-1 |
| 什么算一份记录 | **记录（record）** = 内容 + 结构 + **背景（context）** | ISO 15489-1 |
| 什么该留在配置里 | **配置项（CI）· 基线（baseline）** | ISO 10007（配置管理） |
| 留痕的台账 | **登记册（register）** | ITIL 4 / ISO 10007 |

★ **处置一律先是「归档」而不是「销毁」**：本卡默认动作是**归档（移动 + 留索引）**，
**删除**只有主控明确拍板才做（卡 182 硬要求 1）。

## §三 保留计划表（5 类留痕）

每行：**是什么记录 · 保留多久 · 到期处置 · 判据**（机器判 / 机器判不了 + 理由）。
判据列写「**在哪个环节、由谁触发**」。

### 1. 工作树（`.wt/<卡>`）

| 项 | 内容 |
|---|---|
| 是什么记录 | 一张卡的一次执行环境：工作区 + 指向某 commit 的 HEAD（**背景** = 卡号 + base + 模型，长在 `wb-<卡>.jsonl` 第 1 行 `init`） |
| 保留多久 | **卡 `status=done` 且 tip 已集成到主树 HEAD** 之后即可处置；未完工卡（`status != done`）**永久保留** |
| 到期处置 | **归档**：先把 `<树>/gates/diag/wb-*` 拷回主树 `gates/diag/`（`wt_prune.rescue_tree`，留档在先），再 `git worktree remove`（不带 `--force`）。**销毁**（真删）只有主控看完 dry-run 表后调 `wt_prune.py --apply` 才做 |
| 判据 | **机器可判**（`wt_prune.judge` 七条）：①在 `.wt/` 下非主树非当前树 ②tip 已集成 ③无未提交跟踪改动 ④无进程占用（cwd）⑤无门禁锁 ⑥无 `locked` ⑦非未完工卡（现读 backlog）。七条全成立 = 可处置；任一不确定 = 保留 |
| 环节 / 谁触发 | **收工后**：主控调 `python -X utf8 tools/wb_retention.py summary`（印「该拆哪些树」dry-run 汇总）。**真删**：主控另开 `python -X utf8 tools/wt_prune.py --apply`（看完表再决定） |

### 2. 派活日志（`gates/diag/wb-*.jsonl`，含 `.claim`/`.old` 变体）

| 项 | 内容 |
|---|---|
| 是什么记录 | 一次跑活尝试的完整会话流（**内容** = 每条 user/assistant/result 事件；**背景** = 第 1 行 `init` 里 `model=` / `cwd=` / `tools=`）。是「这张卡用了哪个模型」的唯一凭证 |
| 保留多久 | **有同名 `wb-<X>.verdict.txt`**（已判决）→ 保留至该卡 `status=done` 且主控复核通过；**无判决** → 保留至查明原因（是崩了、还是没跑完、还是派活器丢判决），查明后可归档 |
| 到期处置 | **归档**：`wb_retention archive --apply` 移到 `gates/diag/archive/` + 留 `index.jsonl` 索引（幂等）。**不许直接销毁**——日志是模型凭证，丢了事后查不出「哪张卡用了哪个模型」（2026-09-26 真丢过一次，见 `复盘/wt清理器证据留档-T-G178.md`） |
| 判据 | **机器可判**：`wb_retention.has_verdict(p)` = 同名 `wb-<X>.verdict.txt` 存在（**逐文件配对**，不按卡号聚合——claim 不蹭正跑的判决）。无判决 = 有 jsonl 但无同名 verdict |
| 环节 / 谁触发 | **收工后**：`wb_retention summary` 印无判决份数 + 卡号。**归档**：主控调 `wb_retention archive`（默认 dry-run）→ 看完 → `--apply` |

### 3. 判决（`gates/diag/wb-*.verdict.txt`）

| 项 | 内容 |
|---|---|
| 是什么记录 | 一份 `card= 退出码= 会话= 判决：…` 的人/机两读小结（**背景** = 卡号 + 会话 id + 结束时间） |
| 保留多久 | **永久**（它是「这张卡跑出了什么结论」的凭证，比日志更难重建） |
| 到期处置 | 不处置。即使对应日志被归档，判决**留在原位**（归档只动无判决的 jsonl，不动 verdict） |
| 判据 | **机器可判**：文件存在 = 有判决；`wb_retention.has_verdict` 用它 |
| 环节 / 谁触发 | 派活器收活时写（`wb_dispatch` 现有逻辑）；`wb_retention` 只读不写 |

### 4. 门禁日志（`gates/last.json` / `gates/reuse.json` / `gates/diag/*.log`）

| 项 | 内容 |
|---|---|
| 是什么记录 | 最近一轮门禁的通过/失败快照（`last.json`）+ 复用决策（`reuse.json`）+ 各门逐轮 `.log` |
| 保留多久 | `last.json` / `reuse.json`：**滚覆盖**（每轮门禁覆写，只留最新一轮，这是现有语义）；`.log`：保留至该卡处置完 |
| 到期处置 | 随工作树归档时一起被 `wt_prune.rescue_tree` 拷走（在 `wb-*` 通配族里）；主树 `gates/diag/` 里的留作历史 |
| 判据 | **机器判不了 + 理由**：哪些 `.log` 该留、该归档，没有自然判据——它们是「跑一次留一份」，没有「到期」语义；`last.json`/`reuse.json` 是覆盖语义不是追加语义，不适用保留计划。★ 这一类**处置没有机器判据**，靠工作树归档时顺带拷走 |
| 环节 / 谁触发 | 随工作树归档（同第 1 类环节） |

### 5. 卡规格（`docs/workbacklog.toml` + 各卡 `.md`）

| 项 | 内容 |
|---|---|
| 是什么记录 | **配置项（CI）**：卡的 `id/task/tree/spec/files/status`（backlog）+ 卡的口径正文（`.md`）。是派活的输入基线 |
| 保留多久 | **永久**（配置项，ISO 10007 基线管理）。`status` 从 `pending`→`claimed`→`done` 是状态机，不是保留期限 |
| 到期处置 | 不处置。`status=done` 的卡留在 backlog 里作为「做完了」的登记册条目 |
| 判据 | **机器可判**（`wb_plan.load_backlog` 现读 `status` 字段）；但 **`status=done` 不代表真做完**——是否真完工要主控复核（`wb_review`），这是**人判**。`wt_prune` 判据 7 只信 `status != done`，不信 `status=done` 能删树 |
| 环节 / 谁触发 | 派活前 `wb_dispatch` 读 backlog 派活；`wt_prune` 读 backlog 判据 7 |

## §五 D-12：`wt_prune --apply --min-size N` 把「已跳过」的小树照样删掉

**出处**：`复盘/审计-GLM53-外包系统对抗审核.md` D-12（方向⑥，严重度：高）。
**真因**：`collect` 对小于 min-size 的树只置 `v.skipped=True` 不清 `v.deletable`；
`do_apply` 只判 `if not v.deletable: continue`，不看 `skipped` → 跳过的树照样进删除循环。

### 5.1 复现的真输出（红）

用 `WT_PRUNE_UNDER_TEST` 指向一个**把修撤回**的 `wt_prune` 副本，跑反例钉子：

```
$ WT_PRUNE_UNDER_TEST=…/wt_prune_buggy.py \
  pytest tests/test_wt_prune.py::test_d12_min_size_skipped_tree_survives_apply

FAILED tests/test_wt_prune.py::test_d12_min_size_skipped_tree_survives_apply
>   assert p.exists(), "D-12：因体积被跳过的小树被 --apply 删掉了！"
E   AssertionError: assert False
E    +  where False = exists()
E    +    where exists = …/repo/.wt/small.exists
```

→ `.wt/small`（七条全过但因 `--min-size 999999` 被跳过的小树）被 `--apply` **删掉了**。

### 5.2 修

`tools/wt_prune.py:662-666`（`collect`）：置 `skipped` 时**同时** `v.deletable = False`：

```python
if min_size_mb > 0 and size < min_size_mb * MB:
    v.skipped = True
    v.deletable = False          # ★ D-12：不清这个 → do_apply 照删
    v.reason = f"小于 --min-size {min_size_mb} MB（跳过 → 不删）"
```

### 5.3 修后的真输出（绿）

```
$ pytest tests/test_wt_prune.py -q --no-cov
...................                                                      [100%]
19 passed
```

## §七 ★ 哪一类留痕的处置仍然没有机器判据
