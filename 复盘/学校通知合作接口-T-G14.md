# 复盘 · 学校通知的合作接口（SR-F10.1 / G 批 · T-G14）

> 触发：用户 2026-09-23「全做」——交接文档里列的最后一张"规格里写着、还没做"的小件。
> 规格原文（`docs/specification/domains/F10-notify.md`）第一行就写着 **（后置）**：
> "状态：后置，不阻塞第一版"。所以这一卡的前半件事是**把"后置"里的哪一部分提前**说清楚。

## 一、规格要什么（先读原文再动手）

规格的定位、规则、边界都写得很明确，三句话概括：

1. **监测由独立脚本/软件做**（网站/公众号/群聊/考试网站），主工具**只提供合作接口**，"不让主软件膨胀"；
2. **主工具不直接抓取外部网站**、不新增对外依赖；外部脚本不可用时**主工具不崩、不报错，只提示未接入**；
3. 非法/重复通知要**去重 + 来源标记**；接口契约未定 → **字段保持扩展位，不写死**。

所以"提前做"能做的只有第 1 句里那半截：**合作接口**。抓取永远不该由主工具做 —— 那不是"还没做"，
是**规格明确不允许**（越界抓取 = 替你连外部网站 + 新增依赖）。这一点写进界面文案与边界自述里。

## 二、三件"规格写了但是待定"的事，我怎么定的（都不需要你再拍板）

| 规格里的原话 | 这一版怎么落 | 为什么这样定 |
| --- | --- | --- |
| "可通过合作接口**转成任务/提醒（只读或新增，待定）**" | 投递进来**先只落在收件箱**；**转任务/提醒要你点一下**（`to_task`） | 自动把外部内容变成你的任务清单，是在替你决定"什么算我的事" —— 那是产品口径，不擅自定；人点了才转，人始终在环里 |
| "外部脚本不可用：只提示未接入" | 开关**默认关**；关着时投递 **403 + 原话**"去设置页打开" | 与 AI 接口同一套 N16「默认收严、用户再放宽」；"未接入" ≠ 故障，所以不报错、不轮询、不重试 |
| "非法/重复通知：去重、来源标记" | `fingerprint` **唯一索引** + `source` 必填 | 去重靠**数据库约束**而不是"调用方自觉"（脚本写错一次就重复一百条是很容易发生的事） |
| "字段保持扩展位，不写死" | 认不出的字段原样进 `extra`（JSON）列 | 脚本先多加一个字段**不会丢**，等哪天真需要再提升成正式列 |

一个连带的取舍：**重复投递只覆盖"这次真的带了"的字段**。脚本再投一次只带标题（很常见），
若把链接/摘要/截止日一并写成空，那是**数据丢失**不是更新 —— 有测试钉着。

**放 `core/notify.py` 而不是 `getaways/`**：`getaways/` 是给"出站适配器"（往外推/拉第三方服务）留的位；
而这一版是**本机合作用的 HTTP 接口 + 领域逻辑**，与 `core/ai.py` 是同一类东西（AI 接口也在 core）。
`docs/implementation/*` 里 `getaways/` 的说明也随之改准，不留错话。

界面上的几处"说实话"：

- 「**主工具不去网上抓**：监测由你自己的独立脚本做，这里只是收件箱」—— 边界自述由后端给，界面不复述；
- 关着时写**"这叫未接入"**（不是"出错"），并说明投递会被 403；
- 收件箱的三种状态给**不同的按钮**：待看 → 「转成任务」「转成任务（加入今天）」「忽略」；
  已转任务 → 只剩「打开原文」（不给"转过头再转一次"的假动作）；已忽略 → 「改回待看」；
- 转出来的任务**备注里写着从哪来**（来源 + 通知时间 + 原文链接 + 摘要），以后翻任务时查得出来。

## 四、踩到的坑（三个，两个是我自己的）

1. **日期只做形状校验 = 放行 `2026-13-40`**（测试当场抓到）：`\d{4}-\d{2}-\d{2}` 形状对、
   日子不存在。改成真解析一次（`date.fromisoformat`）—— 外部脚本送来的脏数据必须当场拦住。
2. **模板串里少写 `:''`**（探针抓到）：`${extra?\`…\`}` 三元缺了 else 分支 = **整份脚本语法错误**
   → 假 DOM 探针直接报"脚本求值就抛错"，`web_live_check` 的 `node --check` 也点名了行号。
   这正是那道门存在的理由：**前端字符串断言全绿也挡不住语法错误**。
3. **幂等分支让"非法参数"没被校验**（测试抓到）：同一条通知第二次 `to_task(priority="超级高")`
   走的是"已经转过了 → 返回原来那个任务"，参数根本没看。**这是有意的**（要改就去改任务），
   但要在 docstring 里写明，测试也得换成"另一条没转过的通知"来验非法值 —— 否则这条断言是假绿。

## 五、边界（测试钉住的）

- 默认关；投递 → **403 带原话**（`NotConnected` 是 `ValueError` 的子类，所以老的调用方按
  `ValueError` 接也不会漏）；参数错 → **400**。**两种状态码分得开**是刻意的：一个要用户点开关，
  一个要脚本改代码，靠字符串猜迟早出错。
- **转任务/忽略/看收件箱都不要求开关开着** —— 开关管的是"脚本能不能投递"，收件箱里的东西是你的数据；
  关掉接口后你照样能把它转成任务。
- 已转任务的通知**不许**再被标成忽略（否则任务还挂着、通知却说自己被忽略了，两处说法打架）。
- 忽略**不删行**（删了下次投递又回来，反而像"没收到过"）；可以改回待看。
- 跨站网页偷着投递 / 偷着开开关 → 403（整组要求本机来源）。
- 已转的任务被**彻底删掉**后，允许重新转（否则这条通知永远转不出任务了）。
- **不进同步包**（`EXCLUDED_TABLES` 里显式记着）：它是外部脚本送来的收件箱，不是你自己写的东西；
  转成**任务**之后任务本身照常跨端。

## 七、遗留（如实写）

- **没有现成的监测脚本**：这一版给的是接口与收件箱。要真用起来，得有一个（你自己的）脚本定期
  去学校网站/群里取通知并 POST 进来 —— 那是规格划给"独立软件"的部分，主工具不代劳。
- 没有做「定期自动调用外部脚本」的调度（那又是一个对外依赖 + 权限问题）；
  也没有做通知的**删除**（只做忽略，避免"删了又回来"造成"我没收到过"的错觉）。
- 收件箱放在**设置页**（与 AI 接口那一节并列，都是"外部接进来的东西"）。若以后通知多了，
  再考虑搬到独立页或学业页 —— 那时是布局问题，不是接口问题。
