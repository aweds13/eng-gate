> 文档缺口比产品缺口多**。本文记的是后者（前者见 §五）。

## 一、先说结论（这次核对的结果）

**链条的六条边，机器看着四条、看不见两条：**

| 边 | 谁在守 | 结果 |
|---|---|---|
| intention `N1–N46` → specification | `scripts/check_layers.py` 第 1 项：`needs.md` 里每个 `N` 必须在 `specification/traceability.md` 出现 | ✅ 46/46 都在 |
| specification `SR-*` → 台账 | `audit_progress.check_shape()`：规格里每条 SR 必须有台账条目；台账不许有规格没有的 SR 号 | ✅ 64 个基号两边一致 |
| 台账 `done` → 证据（代码/路由/界面/测试） | `audit_progress.audit_evidence()` | ✅ 138 条 done 断言全过 |
| 后端路由 → 有人负责 | `check_shape()` 的 routes 覆盖 | ✅ 151 条路由全部被引用或进 acknowledged |
| 台账 ↔ git | `audit_progress.progress()` + 提交 trailer | ✅ |
| **契约 `OP-*` / `FLOW-*` → 实现** | **没人守** | ❌ 见 §三 |
| **台账里 `todo`/`partial` 的 gaps 是否还成立** | **没人守** | ❌ 见 §二（这次真抓出两条） |

**一句话**：机器能查的都绿；它查不到的（"人写的理由还成不成立"、"契约里那条操作有没有人做"）
就会漂 —— 这次两处都漂了。

## 二、抓到的失真①：过期 gaps（`todo` 的理由早就不成立了）

`audit_progress` 只查「`done` 必须有证据」，**不查「`todo`/`partial` 写下的理由还是不是真的」**，
也不查「一条规格的子卡全 `done` 了，母条还挂 `todo`」。于是：

### 1. `SR-F1.7` 任务存档 —— 台账写 `todo`，实际两半都做完了
- 台账原文：`status = "todo"`，gaps =「无 attempt/关联笔记字段；无存档视图（GAP-F1-05）」。
- 实测（逐条到代码找）：
  - **存档视图** ✅ `tasks/manager.py::archived_tasks` / `def auto_filed` / 路由 `GET /api/tasks/archived`
    —— 这就是 F 批 `T-F2`（完成满 N 天自动进档案 + 档案视图）做掉的；
  - **过去尝试** ✅ `attempt_failed` / `attempt_count` / `attempt_notes` +
    路由 `/api/tasks/{id}/attempts`、`/api/tasks/{id}/attempt-failed`
    —— 这就是 `T-F3`（「尝试失败」显式计次）做掉的；
  - `T-F2` 与 `T-F3` 两张卡在台账里**都是 `done`**，母条却没回头改。
- 真正剩的：规格后半句「可关联笔记名/链接」**没有"笔记"语义的字段** ——
  任务能挂 `attach`（链接/路径）与 `note`（备注），算不算「关联了笔记」需要用户一句话（待定 ㉘）。
- 处置：`todo` → **`partial`**，补齐证据（把 T-F2/T-F3 的实现点挂上来），gaps 重写成"剩哪一件"。

### 2. `DELIVERY.READY` 可达性 —— gaps 写着两处"没有界面入口"，两处界面都在
- 台账原文 gaps：「白名单/勿扰配置（SR-F3.3）、子任务（OP-12）等仍无界面入口」。
- 实测：设置页有「专注（白名单 / 勿扰）」一整节（`set-focus-guard`，前端批次③ 落的），
  任务详情面板有「步骤（子任务）」区（`addSubtask`，T-A2 落的）——**两处都在**。
- 处置：不再靠人眼，写工具核（见 §四），gaps 换成本次核出来的**具体 11 条**。

> **教训**：`gaps` 是**人写的断言**，它的保质期和代码一样短。台账里 138 条 `done` 有机器钉着，
> 剩下 11 条 `partial/todo/deferred` 全靠自觉 —— 而"自觉"正是 T-G17 那次 `Task:` 写错的老毛病。
> 这次不发明新机制（那是门禁口径变更，要用户拍板），**只把过期的改成真的**，并把缺口写进 §六。

## 三、抓到的失真②：契约层的 `OP`/`FLOW` 没人对账

- `docs/contracts/` 里**定义成条目的操作有 53 条**（`OP-1`…`OP-50` 含 `OP-3b/3c/4b`）。
- `docs/traceability.toml` 里**只出现过 18 个 OP 号**：`OP-1`…`OP-12` + `OP-18` `OP-27`
  `OP-33` `OP-45` `OP-46` `OP-47`。**其余 35 条从未进过台账**（既不是条目，也没当证据被引用）。
- 例：交接文档手写的那行「契约闭环：…**OP-24**（任务↔课程）/**OP-42**（备份回滚）/
  **OP-26**（任务→复习卡）… 已落地」——这些落地是真的，但**只写在交接文档的手写行里**，
  机器一个都不知道。
- `docs/contracts/flows.md` 的「动线自查表」：`FLOW-1`~`FLOW-4` 的 4×3 个格子**全是 `☐`**，
  从来没回填过（动线本身有 LF-1 真机脚本 + 验收靶子在跑，但**文档层是空的**）。

**为什么这是链条问题而不是文档洁癖**：契约层是"怎样才算真的做成"那一层。
现在「intention→spec→台账」都机器对账了，**偏偏中间这层没人看** ——
新窗口读契约会以为有 53 件事排着，读台账又只看得到 18 件，两边对不上。

**要不要修、怎么修（属门禁/流程口径变更，等用户拍板）**，我列了三条路（§六）。

## 六、遗留：这次**没做**的三件事（都要用户拍板，属门禁/流程口径）

1. **给契约层加覆盖检查**：让 `audit_progress` 认 `OP-*`（每条契约操作要么进台账、
   要么进一份"有意不登记"的白名单），并把 `flows.md` 那 4 行动线自查表回填或删掉。
   难点：53 条里有很多是"同一个操作的不同失败态"，逐条登记会把台账撑肥 ——
   所以**要么按域收（一条动线一张卡）**，要么**明确"契约不需要逐条进台账"**，两条都行，但要定一条。
2. **给 `gaps` 加"过期检测"**：机器目前只能查"有没有写 gaps"，查不到"这理由还成不成立"。
   能机械化的只有一种：**子卡全 `done` 而母规格仍 `todo`** （SR-F1.7 就是这种；容易做）。
   其余（"无 attempt 字段"这类）本质上是散文，机器判不了 —— 只能靠"回头看"（本卡就是这么发现的）。
3. **把 `tools/route_ui_gap.py` 做成门禁第 12 项**：现在它是报告工具（退出码永远 0），
   要让"新加一条没界面的路由"当天就红，得先维护一份"允许没有界面"的白名单（AI 5 条 + health + 运维）。

> 三条都**没动门禁**（门禁口径变更这个项目一贯要用户点头，见 T-G17 §六同样的处理）。

## 七、怎么核的（可复现）

```powershell
# 1. 台账分布 + 断言（严格模式：审 HEAD 那条提交 + 逐条断言）
python -X utf8 scripts/audit_progress.py
# 2. 意图 N → 规格（机器本来就在查，看第 1 项）
python -X utf8 scripts/check_layers.py            # [FAIL] 一栏为空 = 46 个 N 都在 spec 追踪里
# 3. 后端路由 ↔ 前端界面（本次：151 条路由，11 条前端一个字都没提）
python -X utf8 tools/route_ui_gap.py --ack ai,health
# 4. 规格 SR ↔ 台账 SR（本次 64 个基号两边一致）、契约 OP 覆盖（53 条定义 vs 台账出现过 18 个）
#    这两条是**一次性核对**，没留脚本 —— 用的是正则抽编号后比集合，见下
```

第 4 条的核对方式（没写成工具，因为还没决定它要不要变成常设检查，见 §六）：

- **规格 SR ↔ 台账 SR**：`docs/specification/**.md` 里抽 `SR-F\d+\.\d+[a-z]?` / `SR-NF\d+[a-z]?`，
  去掉小写后缀得基号，与台账 `[entries]` 的键比集合（读 `docs/traceability.toml` 用 `tomllib`）。
- **契约 OP**：`docs/contracts/**/*.md` 里抽**行首**的 `OP-nn`（`##` 标题 / 表格首列 / `- **OP-nn**`）
  得 53 条；再在台账全文里正则找 `OP-\d+` 得 18 个。

`tools/route_ui_gap.py` 的判定方式（三段都是实测踩出来的）：
① 后端 `{task_id}` 与前端模板 `${id}` 都收敛成通配段再**按段比**（只做字符串包含会把
`/api/tasks/${id}/complete` 判成"没人用"，第一版误报 **49** 条）；
② 前端路径先切 `?query`（否则 `/api/gpa?scale=${s}` 永远匹配不上，第二版误报 **27** 条）；
③ 末段也可能是变量（状态动作 `/api/tasks/${id}/${verb}`）→ 通配对通配也算命中（收敛到 **11** 条）。
