# 黄金跨天漂移 → 可注入的「今天」（T-G62）

> 这一张卡是**被上一张卡撞出来的**：T-G61 在 2026-09-24 23:5x 重采完黄金、00:0x 再跑，
> `render` 红 **6 份**（`habit` / `stats` 各 3 档宽度）。它不是随机失败，也不是界面变了 ——
> 是**验证层里最后一块会自己动的时钟**。用户 2026-09-24 那句话（「想一个不会漂移的验证方式」）
> 说的就是这一类。教训进 `复盘/视觉线地图.md` §6。

---

## 1. 现象与根因（先量，再改）

| 证据 | 内容 |
|---|---|
| 差异份数 | **恰好 6 份** = `habit` × 3 档宽度 + `stats` × 3 档宽度 |
| 差异长什么样 | 热力图格子少/多一格（`nth-child(368)` → `(369)`）、统计页窗口首日标签 `08-26` → `08-27` |
| 什么时候出现 | **跨过午夜**；同一个日期内怎么跑都一样（两遍自检也逐字节一致） |

**根因**：习惯热力图的窗口是「**53 周、到今天为止**」，而**未来几天不渲染**（T-G55 的「未来留白」）
→ 同一个星期内每过一天，末尾就多一个格子；统计页那个首日标签同样是「今天 - 370 天」。
两者都由**服务器的"今天"**决定，而 fixture 的打卡/复习数据又是**相对今天**种的 —— 于是整块画面随日期滚。

**为什么之前没发现**：这几轮黄金采得很勤（一张卡一采），而"当天采、当天提交"正好把它盖住。
**它是慢漂移，不是随机**：跑在同一天的任意时刻都一样，换一天就全变。

**同族的另一条（顺手一起修掉了）**：复习线的 FSRS 步长是**分钟级**（学习中的卡「记得」→ +10 分钟），
而落库只存**本地日历日** → "下次到期算不算今天"还会随**几点跑**变。
证据：2026-09-24 23:53 那次全量 `pytest` 红了两条复习线用例（23:57 的下一步落在 00:07），
**过了午夜再跑又是绿的**。

## 2. 修法：一处出口 + 一个采集用的假时钟

**没有**去改产品行为（凌晨复习、下一步落在明天，本来就是 SRS 的正常语义；
热力图窗口跟着今天走也是对的）。改的是"**每个调用点各自问系统时钟**"这件事：

1. **`src/timeflow/clock.py`（新）**：全仓唯一的「现在」出口 ——
   `today()` / `today_iso()` / `now()` / `now_utc()`；`src/timeflow/**` 里 27 处
   `date.today()` / `datetime.now()` 全部收敛过来（19 个文件加 import）。
   **不设环境变量时行为与系统时钟完全一致**（有测试钉着这一点）——
   它不是功能开关，是**测试用的假时钟**。
2. **`TIMEFLOW_FAKE_TODAY=YYYY-MM-DD`**：设了就把四个函数钉在**那一天的本地正午**。
   为什么是正午：离日界最远；为什么钉到具体时刻：FSRS 那种分钟级调度要一个确定的瞬间。
   写坏的值**当没设**（静默按别的日期跑比报错更坏）。
3. **采集侧三处一起钉**（`render_check.mjs`，`CAPTURE_DAY = 2026-06-15`）：
   - `tools/serve.py --today` → 服务器的「今天」；
   - `seedFixture` 的基准日（`setFixtureDay`）→ 数据的相对日期；
   - 浏览器 `Date` 垫片（`Page.addScriptToEvaluateOnNewDocument`，导航**之前**注入）→ 前端网格。
   **只钉一处就是自相矛盾**：服务器以为 6-15、数据按 9-25 造、浏览器以为今天 —— 那不是验证，是伪造一个界面。
4. **黄金第一行记 `day=2026-06-15`**：告诉读的人这份清单是按哪一天采的；
   谁改了 `CAPTURE_DAY`，45 份黄金一起红（口径变了要有人看见）。
5. ★ **渲染层每轮当场自检**「页面是不是真的以为今天是采集日」：
   垫片要是不生效（CDP 版本差异 / 注入点变了），**报错**而不是悄悄退回"按真今天采"。

## 3. 验证

| 层 | 证据 |
|---|---|
| 单元（`tests/test_clock.py`，8 条） | 默认=系统时钟 / 假时钟钉住日期与时刻 / 坏值当没设 / 时刻不随"几点跑"变 |
| **反悔闸**（同文件） | `src/timeflow/**`（除 `clock.py`）里出现裸的 `date.today()`/`datetime.now()` 就红（判据剥掉注释与字符串）；反过来"用了 `clock.` 必须 import 了它"也查（这轮是脚本批量替换的） |
| 标记层 | 采集侧三处接线 + `day=` 头 + `serve --today` 都在；且**采集日只写一处**（`CAPTURE_DAY`），写坏值/写两处都会红 |
| **真浏览器** | 重采 45 份后**再跑一遍**：`--only stats` / `--only setting` 逐字节一致；每轮打印「[假时钟] 今天钉在 2026-06-15」+ 页面自检通过 |
| 确定性 | 每轮两遍逐字节一致（这条本来就有） |

**这一轮黄金 45 份全动**：头一行多了 `day=`，而且 `habit`/`stats` 的格子数变成了**固定值**（采在 6-15）。
理由在 `gates/render/LAST_UPDATE.md`。

## 4. 边界（不许假装验证过）

- **没做"真的跨午夜再跑一遍"**（要等到明天）：判据是**机制** —— 页面的 `new Date()` 已被钉成常量、
  fixture 与服务器同一个基准日、且每轮有"页面是不是真以为今天是采集日"的自检。数学上它不可能再随日期变。
- **`ui_flow` 保持真实时钟**：它判行为、不存黄金，而它那些日期断言本来就是相对 fixture 的。
  好处是"真实时钟下的行为"仍被每轮跑一遍（`clock.py` 的默认分支也被它覆盖）。
- **`date.today()` 跨午夜那一瞬**（写 23:59:59.9、读 00:00:00.1）仍是理论上的 1 秒窗口：
  `TIMEFLOW_FAKE_TODAY` 不设时它就是真日期。要消掉得连"今天"都假掉，代价比收益大。
- **不假造"现在"给产品用**：`clock.now()` 默认就是 `datetime.now()`；采集时的假时刻只活在采集进程里。
