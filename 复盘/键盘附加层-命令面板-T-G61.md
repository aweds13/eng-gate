# 键盘附加层：⌘K 命令面板 + 首批快捷键（T-G61）

> 键盘线第 ③ 步（T-G30 排的顺序：① 焦点环 → ② 命令表 → **③ 面板 + 快捷键** → ④ 之后 CLI/MCP）。
> 前置两件都已落地：**T-G45** 那条全局焦点环（`:focus-visible` 0 → 1）、**T-G31** 那张命令表
> （`docs/commands.toml` 53 条 OP ↔ 路由 ↔ 界面入口）。这一步把它们连起来。
> 教训一律进 `复盘/视觉线地图.md` §6。

---

## 1. 用户要的是什么（原话留档）

> 「键盘优先可以做成一种**附加功能**吗？就是我有些东西是要靠键盘的。然后以后假如是你去做的话，
> 你也是通过**虚拟键盘**就给它命令的。」（2026-09-23）

T-G30 当时给的答复里有两句关键判断，这次照它做：
① **"附加功能"的正确形态不是"到处加快捷键"**，而是**把已有的 `ACTIONS` 注册表升级成一张带元数据的命令表**，
面板只是它的一份投影 —— 不碰鼠标路径、移动端不受影响；
② **AI 用合成 DOM 事件驱动界面是最脆的一层**（把界面当 API），所以顺序是 命令表 → HTTP/CLI → MCP；
合成事件只留一个用途：**测试**"界面真的能纯键盘走通"（这一步正好把它做了）。

## 2. 做了什么（三样，一张表喂三个用途）

| 件 | 落点 | 说明 |
|---|---|---|
| **命令表** | `src/web/index.html` 的 `const COMMANDS` | 18 条命令 × 7 个键位；每条写 标题/分组/键位/跑哪个**已注册**动作/对应哪条 OP |
| **⌘K 面板** | 同一个文件 + `app.css` 的 `.palette*` | `Ctrl/⌘+K` 打开，打字筛（中文走 `input` 事件）、`↑↓` 换选中、`Enter` 跑、`Esc` 关；鼠标点也行 |
| **首批快捷键** | 同一个 keydown | `n` 新建任务 · `t/f/r/s/h/p` 六个视图 · `Esc` 关最上面那层（面板 → 模态 → 右栏详情） |

**三条口径（写进代码注释，也写进 `SR-NF1`）**：
1. **只加不改**：原有按钮一个没删、没改（面板是"多一条通路"）；
2. **行是 `div` 不是 `button`**：焦点始终留在过滤框（`aria-activedescendant` 那套）——
   写成按钮的话 `Tab` 要在这十几行里走一遍，那不是"键盘优先"是"键盘折磨"；
3. **不抢键**：单字母只在**没在打字**时生效（输入框 / textarea / select / contenteditable 里一概不抢）、
   模态开着时不生效、不带 Ctrl/⌘/Alt（⌘K 自己除外）。

**顺手补上的一个真缺口**：模态（`ask` / `confirmAsk`）从 R2 建起来那天起注释就写着"可键盘"，
但 **`Esc` 对它一直没有作用** —— 这次 `Esc` 分了三档，模态那档是白捡的（`closeModal(null)`，确认框 = 取消，不动数据）。

**「新建任务」这条不造第二个创建路径**：它只做"切到今日页 + 把光标放进那个输入框"，
写标题与回车走的还是 OP-1 原来的入口（`#newTitle` + `data-enter="task-add"`）——
面板里**没有**任何一行自己打接口（有测试钉着这一点）。

## 3. 怎么证明它没变成"第二套命令系统"

这是本卡最要紧的一层，因为"再写一套命令"是最容易发生的漂移：

- `scripts/check_commands.py` 多了一节判定，逐条核对**四个真源**：
  ① 动作必须真在 `ACTIONS` 注册过；② 键位不许重复（抢键是最隐蔽的键盘缺陷）；
  ③ 视图必须在 `VIEWS` 里；④ **声称对应某条 OP 时，那条 OP 的 `ui` 里必须真有这个动作/视图**。
- 四条对不上时**门禁当场红**（实测：第一次跑就报出 6 条"面板挂了 OP 但命令表 ui 里没有它"）。
- 顺带**把 6 条一直空着的 `ui` 补上**（OP-1 加 `palette-new-task`；OP-7/OP-3/OP-19/OP-25/OP-35 各加一个 `view=`）
  —— 那些界面入口本来就在（左栏那 14 个按钮、今日页那个输入框），只是命令表从没记过。
  **命令表"还没填出界面入口的"从 10 条降到 7 条**（这是进度，不是错误）。
- 读那张表**不能用正则**：注释里的 `{` 会被当成"一条命令的开头"，然后配对到别处的 `}`、从中间错位。
  第一版就踩了（`_top_level_objects` 找第一个 `{` 再配对）→ 改成**一个扫描器同时负责跳字符串/注释与配对**，
  并把"注释里的 `{` 与 `'`"钉成一条测试（`test_ui_commands_reads_the_palette_table`）。

## 4. 验证（钱花在哪）

| 层 | 证据 |
|---|---|
| 标记层（pytest） | `test_command_palette_is_an_additive_keyboard_layer`（8 组、含"行不是 button""遮罩是兄弟节点""不抢键那三条分支""不自己打接口"） |
| 命令表（pytest + 门） | `test_real_palette_is_a_projection_not_a_second_system`、`test_checker_main_is_green_on_the_real_repo`（跑的就是门禁那条判定） |
| **真浏览器真按键** | 行为流第 **K** 条：**34 项断言（34 是 T-G61 当时的读数；现役真值见 `docs/specification/nonfunctional.md`）** —— `Ctrl+K` 真开、`Esc` 真关、真打字筛（含中文）、`↑↓` 换选中、`Enter` 跑、单字母切视图、**在输入框里打 `h` 不被当成快捷键**、模态 `Esc` 取消后**任务还在**（不是"确认"） |
| **视觉黄金** | 渲染层多了一个**浮层伪视图** `palette`：3 档宽度 × （14 视图 + 1 浮层）= **45 份**，两遍逐字节一致 |

**新增的采集能力（工具侧）**：浮层默认不出现，所以 `render_check.mjs` 多了 `PSEUDO_VIEWS`
（`{ open: 打开它的选择器, over: 先站到哪一页 }`）。`over` **必须写死**——顺手用"上一轮停在哪"就是
T-G51 那个教训（`offline` 页会读别人写的缓存，采到假黄金）；这次固定"先回今日页再开面板"。

## 5. 边界（不许假装验证过）

- **只认单字母 + ⌘K**：没做可配置键位、没做 `?` 键的键位表浮层、没做方向键之外的导航键。
- **面板里只有 18 条命令**：`ACTIONS` 有 147 个动作，绝大多数是"针对某个任务/分组"的上下文动作
  （必须带 id），不适合放进面板 —— 这一条是**有意的**，不是没做完。
- **`Ctrl K` 那个徽标写死**（不按系统换成 `⌘K`）：黄金是逐字节比的，按平台变的标签会让同一份黄金
  在两台机器上不一样；按键是**两个都认**的（`ev.ctrlKey || ev.metaKey`）。
- **移动端不受益**（≤640px 左栏隐藏、没有键盘）：这一层按"附加"定位，没给手机做命令入口。
- **不算 AI 面**：AI/MCP 读同一张表是第 ④ 步，还没做（用户定的顺序：CLI/MCP 排最后）。

## 6. 教训（已同步进 `复盘/视觉线地图.md` §6 与 §3）

1. **PowerShell 会把 node 的 stderr 变成终止错误**：`node xxx.mjs 2>&1 | Select-Object -Last` 会让
   一条本来通过的命令报 `[exit code: 1]`（本节实测：探针打印了 ✅ 却"失败"）。改法：`*> 文件` 再读文件。
2. **`ruff` 的 E501 按"显示宽度"算**：中日韩字符算 **2** 列（`line-length = 100` 时一行 80 个字符可能
   已经是 107）。中文表格行要按宽度留余量，别按字数。
3. **工具的"读法"本身要有测试**：这一卡里唯一一次真缺陷是**解析器**把注释里的 `{` 当成条目开头
   （报"括号没配对"）。凡是"从源码里读一张表"的地方，都要有一条"注释/字符串里放干扰字符"的用例。
4. **键盘快捷键的正确顺序是"先有焦点环、再有命令表"**：直接加 `Ctrl+K` 会变成"只有知道的人能用"
   —— 左栏那个带键位徽标的入口（可学习性）+ 面板里每行显示键位，才是"附加功能"能被发现的全部原因。
5. **空态只有一个出口**：面板的"没找到"第一版直接写了 `<div class="empty">`，被 R5 那条护栏
   （`html.count('<div class="empty">') == 1`）当场拦下 —— 空态一律走 `emptyState()`，
   **新写一个空态就是在给这条护栏加负担**（它数的是"还有没有别的地方自己画空态"）。
6. **判据依赖墙上时钟 = 会在某个时刻自己变红**（本卡顺带修掉的一条，见 §7）。

## 7. 顺带修掉的一条门禁午夜红（不是本卡的代码，但同一提交）

**现象**：2026-09-24 23:53 起跑全量，`pytest` 红两条（`test_learning_card_stays_due_until_graduated`、
随后 23:59 又多了 `test_review_after_undo_counts_again`），而**过了午夜再跑又是绿的**。

**根因**：FSRS 的学习步长是**分钟级**（学习中的卡「记得」→ +10 分钟），而落库只存**本地日历日**
（`_local_date`）。于是"复习完这张卡还算不算今天到期"随**离午夜还有几分钟**变：
23:57 复习 → 下一步 00:07 → 存成明天 → 卡不在今天的 My Day 里 → 断言红。

**这是缺陷吗**：不是 —— 凌晨复习、下一步落在明天，正是 SRS 的正常语义。**红的是用例**：
它的结论依赖墙上时钟。这跟 **T-G40** 记的是同一族（那次是"fixture 与星期几相关"）。

**修法**（`tests/test_review_line.py`）：
① 这个文件加一条 **autouse fixture**，把复习线的「现在」钉在**今天本地正午**（只钉 FSRS 用的那一刻，
`date.today()` 仍是真实日期 —— 没有伪造"今天"）；② 新增一条**把跨午夜行为写死**的用例
（23:57「记得」→ 到期日 = 明天、离开 My Day、账目照记），谁想"顺手改成留在今天"就得先回答为什么。
**踩到的第二个坑**：包 `timeflow.core.review` 的 `__init__` 把同名函数 `review` 重新绑进了包命名空间，
所以 `monkeypatch.setattr("timeflow.core.review.review._now", …)` 会走到**函数**上去
（pytest 的 `resolve()` 是逐段 getattr，一段变成函数就回不到模块）→ 必须先
`importlib.import_module("timeflow.core.review.review")` 再 setattr。
**边界（如实留档）**：`date.today()` 跨午夜那一瞬（写 23:59:59.9、读 00:00:00.1）仍是理论上的 1 秒窗口
—— 要连日期一起假才消得掉，代价比收益大。
