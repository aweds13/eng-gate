# 轻量化通道（开工切片 + 一屏核实 + 一屏现状 + 派活器 `--lean`）· T-G173

> 卡 078 的复盘。底座 `d842771`（本树为 `.wt/lean1`，HEAD 开工时 `150de81`）。
> 三件新工具 + 派活器一个默认关的开关；目标是**把每张卡的开场成本从 ~222K tokens 压到 ~2K**。

## §一 为什么做（主控读数，别去复核）

每张卡开场被**强制读**的四份文档合计 **693 KB ≈ 222,000 tokens**：

| 文档 | 大小 |
|---|---|
| `复盘/交接-重构进度.md` | 302 KB（★ **超 256KB 工具上限 → 读它就是失败**） |
| `复盘/长任务执行协议.md` | 190 KB |
| `复盘/新窗口交接卡.md` | 109 KB |
| `复盘/外包-卡表与规矩.md` | 92 KB |

而**卡本身只有 9–25 KB**。交接文档 2188 行 / 28 个 `CHECKPOINT`，每张卡真正需要的只有
**最新 1 段**。主控的上下文比工人更稀缺 —— 所以切片**两边都吃**（`--master` 版）。

## §二 四件交付物与用法

### 1) `tools/wb_brief.py` —— 开工切片（≤6KB）

```bash
python -X utf8 tools/wb_brief.py --card 078                 # 工人版 → stdout + gates/diag/brief-078.md
python -X utf8 tools/wb_brief.py --spec gates/diag/卡078-*.md --out gates/diag/brief-078.md
python -X utf8 tools/wb_brief.py --master --out gates/diag/brief-主控.md   # 主控版
```

五节固定顺序（卡 §1.1）：**一** 现状（现算，不抄任何文档：HEAD/分支、`sync_counts --check` 原文那一行、
被跟踪改动数 + 外来未跟踪数）· **二** 最新 1 个 `CHECKPOINT` · **三** 本卡引用到的规矩 ·
**四** 本卡白名单/禁区（从卡里原样摘出）· **五** 固定坑页（`复盘/口径坑.md` 八条）。
总长硬上限 **6144 字节**，超了截断并在末行写 `…(已截断)`。纯标准库；交接文档**按行流式**扫，
只留命中的段（不整体读 302KB 进内存）。

### 2) `tools/wb_verify.py` —— 一屏核实（`verify_i9` 参量化）

```bash
python -X utf8 tools/wb_verify.py --tree .wt/foo --expect-parent d842771 \
    --allow "复盘/*" --allow "docs/*" --allow "tools/*" --allow "gates/*"
python -X utf8 tools/wb_verify.py --tree .        # 缺 --expect-parent 时用该树 HEAD^
```

七行判据（`OK`/`FAIL`/`INFO` 各一条一行）+ `SUMMARY FAIL=<n> OK=<n>`；**退出码 = FAIL 条数**：
提交骨架（HEAD/父/脏/trailer 计数）· 门禁（`ok` / `rev`=父提交 / 17 门 / 非零 / not_run / **顶层 `reused` 字典**）·
`sync_counts --check` · 提交后 `audit` · 越界（`git show --name-only` ∩ 白名单）·
`wb_review` 末行 · 既有文件（只读跳过）。**只读**：不 `git add/commit`、不跑 `run_gates.py`、不动锁。

### 3) `tools/wb_state.py` —— 一屏现状（≤30 行，只读）

```bash
python -X utf8 tools/wb_state.py
```

一行 HEAD/分支/脏(tracked)/外来未跟踪；一行锁（`gate_lock.py status` 首行）；
在跑的派活器（命令行含 `wb_dispatch.py`，打 PID+card）与门禁（含 `run_gates.py`）计数；
最近 5 条提交；Trae 池余额（读不到打 `(需 IDE 在跑)` —— **不为此起 IDE**）。

### 4) 派活器 `--lean`（**默认关**）

`tools/wb_dispatch.py` 加了 `--lean`（`store_true`，默认 `False`）：**默认行为一字不变**（等同 `--full`）。
`--lean` 时不再拼那四份文档，改读 `gates/diag/brief-<卡>.md`（不存在则自动调 `wb_brief.py` 生成）。
另固化 `复盘/口径坑.md` 八条判据 + 在 `复盘/外包-卡表与规矩.md` 末尾追加 **§24.12**。

## §三 实测（现读，可复现）

- `wb_brief.py --card 078` → **5956 字节**（≤6144 ✓，五节齐全）；`--master` → **3479 字节**。
- 省了多少：693 KB → 5.8 KB ≈ **0.84%**。按 693KB≈222K tokens 折算，**每张卡省 ≈ 219K tokens**
  （≈ 99.2%）。★ 估算依据：tokens ≈ 字节 ÷ 3.1（由 693KB↔222K 反推），非实测分词。
- `wb_verify.py`：干净树 `--tree .` → 退出码 **0**（`SUMMARY FAIL=0 OK=5`）；
  故意给错 `--expect-parent deadbeef` → 退出码 **1**（`SUMMARY FAIL=1 OK=4`）。
  带 `--allow`（7 条）在 `150de81` 上 → 退出码 **0**（`SUMMARY FAIL=0 OK=7`，越界 7 文件全在白名单）。
- `wb_state.py` → **14 行**（≤30 ✓）。
- `--lean`：`--help` 第 3 行含 `--lean`；默认 `-p` 含四份文档名、不含 `brief-078.md`；
  `--lean` 的 `-p` 含 `brief-078.md`、不含四份文档名；**除 `-p` 外其余参数逐字相同**（`d[4:]==l[4:]`）。

## §四 已知限制（如实写）

1. ★ **§二「取最后一段」与实现偏差**：交接文档是**新→旧**排列（2026-09-28 那段在第 5 行），
   卡 §1.1 字面的「取最后一段全文」会取到**最旧**那段（2026-09-26）。本实现按**日期最大**取
   （= 卡 §0 明写的「只取最新那一段」），并列时取出现靠前的。
2. ★ **§三会截断**：按卡里出现的编号抓小节，总量 1750 字节内**每节再按份数截断** ——
   露出「标题 + 头几行」，**全文仍在 `复盘/外包-卡表与规矩.md` 里**，切片是"指路"不是"替代全文"。
   卡里没引用任何编号时，§三只指向第五节固定坑页。
3. **切片只取最新 1 个 `CHECKPOINT`**：需要更早上下文时，得自己翻交接文档（卡 §1.1 只要求最新 1 段）。
4. **`--lean` 只改首轮开场白**：续跑（`--resume`）走 `continuation_prompt`，不读切片（未改续跑路径）。
5. **`wb_verify` 的「17 门」是硬编码**（与 `verify_i9` 同口径）；门数变化时要同步。
6. **`wb_state` 的进程枚举依赖 PowerShell**（Windows）：不可用时如实打「无法枚举进程」。
7. **Trae 余额**只试读 `%LOCALAPPDATA%` 下几个候选文件，读不到就打占位（不为此起 IDE）。
8. **没动什么**：`src/**`、`scripts/**`、其余 `tools/**`、`tests/**`、`docs/**`（除台账那块）、
   `gates/diag/**` 的既有文件、`.wt/**` 别的树、主树外来未跟踪文件、`data/` 一律未碰。
