# 分层问题清单（A 稿）—— 把 12 层拆成可问的问题

> 目的：把「这套系统的每一层**怎么管才算好项目管理**」变成**能被追问**的问题。
> 主题面：**软件工程 × Agent 工程 × vibe coding**。
> 用法：这份给 **Kimi K3** 深化归并；各层原文给 **V4.1 便宜工人（effort=max）** 分头深想。
> ★ 写法纪律：每问都要能落到**"谁的什么动作"**上；不写"最佳实践是什么"这种问不出东西的。

## L0 · 意图层（人说了算）

1. 「意图」怎么**落成可撤回的表达**？—— 用户一句话（如「GLM5.3 用完就撤」）与它造成的代码状态，谁负责对账？
2. 意图**变更**时，已经在跑的工人/已经落的提交怎么处理？有没有"停止条件"的机器表达（现在协议里那条 §四 5 条停止条件**只有人话**）？
3. 「用户不在场」（如睡觉）时，代理的**授权边界**怎么表达？—— 今晚真实发生过：我替你改了一个"只有用户能改"的文件（模型开关），依据是你那句授权。
4. 意图层与规格层的**翻译损耗**怎么测？（台账里那条"只有人话、没有判据"的 21 条就是这个病的病历）
5. 「我不确定」怎么成为一等公民？—— 现在只能写进边界段落，没人会读第二次。

## L1 · 规格/契约层（`docs/specification` · `contracts` · `commands.toml`）

1. 契约里的**六要素**（入口/可逆/状态机…）怎么保证"写了就有人实现"？（真咬过：OP-26 写「可逆：可删除」而零 DELETE）
2. 规格**一句话带过**（"支持暂停/放弃/记中断"）时，谁逼问边界？能不能做成"规格必须给异常路径"的判据？
3. `commands.toml` 的**六份真源**（契约/路由/界面/⌘K/CLI/MCP）对账是单向的 —— 反方向（真有的没登记）只算"洞"不判红，这条要不要改成双向？
4. 规格与**实现**之间那层（`docs/implementation`，只有 5 个文件）为什么这么薄？它是被跳过了，还是本来就该薄？
5. 一个能力跨 3 层文档（specification/contracts/implementation）时，**谁是唯一真源**？

## L2 · 产品层（`src/timeflow/**`）

1. 「谁在写库」的**唯一出口**（事实层）怎么强制？（真咬过：各线各写各表）
2. **时间源**（`clock.py`）可注入这条，怎么从"一个模块"升格成"全仓不许绕"的判据？（现在反悔闸只扫 `src/timeflow/**`，`src/web/*.js` 与 `tools/**` 不在扫描面）
3. 读-改-写的**版本守卫**只覆盖了 myday 那一列 —— 通用判据该怎么写才不误报？
4. 领域层抛出的"给人看"的异常，怎么保证**每个都有 HTTP 归属**？（现在没有对账，新增一个异常就多一个 500）
5. 「声明了没人建 / 写了没人调」这类**空转**，该在哪一层拦？

## L2.5 · 基础设施层（clock/config/vocab/logs/storage）

1. 日志/配置/词表/时间这些"三方共用"的东西，怎么防止**领域层反向依赖接口层**？（现在只靠一条注释声明）
2. 迁移（SQLite）的**升级路径**怎么被测？（真咬过：所有测试都从新建库出发，升级链从来没测过）
3. 配置项的**默认值与文档**怎么不分叉？

## L3 · 验收/测试层（`tests/` 2034 用例 + 真机探针）

1. 「**人肉验收**」还剩多少条没搬给机器？搬不动的理由怎么变成机器可读的字段（而不是散文里的 `【已搬给机器】`）？
2. 判据**自己会假绿**这件事怎么防？—— 空夹具 / 结构齐全数据为零 / 护栏挑了两处都有的串 / `--only` 写错字报"0 条流通过"。
3. 「**判据不许跨求值**」（两次取值之间世界会变）能不能成通则？
4. 测试的**定时炸弹**（依赖真实 HEAD / 真实时间 / 真实求值次序）怎么机器识别？
5. 每条判据是否都该配一条"**合成数据证明它会红**"？（现在只有零星几条这么做）

## L4 · 门禁层（`scripts/run_gates.py` 17 门）

1. 「**本笔动过的门必须真跑**」怎么判？（现在复用只说"输入没变"，不说"这轮跑过"；卡 095 因此漏过一次真回归）
2. **整趟总预算**要不要做？（现在只有每门 1800s；真出过"锁被占 56 分钟"）
3. 「**门红了**」的分类提示（时间敏感/竞态/工具脆）能不能进 `finish_gate`？现在全靠人判。
4. 门数变化（17→18）怎么不破既有断言，又保持"门表只有一份真源"？
5. `--affected` 与全量的**边界**怎么向人证明？（已有卡 147 查门数，够不够？）
6. **慢**本身能不能成为判据？（pytest 612s 占 86%，而"把 worker 拧到 1"没有任何东西会红）

## L5 · 审计/台账层（`audit_progress` · `check_layers` · `check_commands` · `traceability.toml`）

1. ★ **判据是单向的** —— 只查"你声称的有没有"，不查"实际发生的有没被声称"。这条能做成通用判据吗（改动集合 ⊆ 证据指针 ∪ 显式豁免）？
2. `test:` 证据只核**文件名**不核**用例名** —— 升级到用例级要改 77 条既有条目，做不完时**怎么不许静默降级**？
3. 台账 `gaps` 是人写的**否定句**，保质期和代码一样短 —— 有没有办法让它带"到期日/负责层"？
4. 「手抄的数字」怎么机器对账？（现在只对账交接文档那一行，实测漂过 3 次）
5. **封存树 vs 提交树**的完整对比要不要进复核主链？（现在只咬三个片段目录）

## L6 · 外包/流水线层（`tools/` 61 py + `tools/pool/`）

## ★ 跨层问题（我认为最可能问出东西的）

1. **"谁判它"矩阵**：12 层里 **L0 意图 / L7 证据 / L9 号池**三层**没有机器判据**（或够不着）—— 这三层的共同点是什么？缺的是"判据"还是"表达方式"？
2. **单向 vs 双向**：这条共因横跨 L5/L3/L6 —— 有没有**一个通用机制**（不是一堆检查）能表达"实际发生 ⊆ 声称"？
3. **动作的原子性**：预声明要 `写文件 + register` 两步、收口要 7 步 —— Agent 工程里"**多步动作只做一步**"是不是系统性风险？怎么表达"这一步没做"？
4. **"环境变量双用途"**：沙箱重定向 `HOME` 隔离登录态，顺手把"工具在哪"也隔离了 —— 这类**隐式耦合**怎么在架构上隔离？
5. **人的在场/不在场**：授权边界、停止条件、"我不确定"—— vibe coding 里**代理的自主度**该怎么分级并机器表达？
6. **固定开销**：一次改动的最小成本（文书 + 门禁）与改动大小无关 ⇒ 什么规模的项目/团队下这种"重仪式"才划算？轻改动该走什么通道？
7. **判据的元判据**：谁能判"这条判据有牙"？—— 现在靠对抗审核（GLM-5.3）+ 反例钉子，能不能形式化？
8. **证据的可信度分级**：测试尾行 / 门禁结论 / 原样输出 / 人写的散文 —— 四级证据在"完成判据"里的权重该怎么定？
9. **"没收到 ≠ 没产出"**：工人报告没回推时去磁盘翻 —— 这类"**观测面**"的兜底该怎么设计（而不是靠我记得）？
10. **从复盘到卡到代码的转化率**：344 → 77 → 60(未关) → 卡 17 张。这条漏斗哪一段漏得最多？
