## 1. 为什么有这张卡（背景 + 出处）

料来自盘点卡 S-1 的 **A4 + A21**（`gates/diag/盘点-20260926.md`）。两件事同域（都在
`src/web/index.html`），所以合成一张卡。

**① A4 · myday 拖拽的「落点没变就不发请求」是死代码**（出处 `gates/diag/wb-review-T-G79.md` 边界 D）。
改前 `src/web/index.html:2051-2054`：

```js
const rest=order.filter(x=>x!==d.id);            // d.id 已经被滤掉了
const want=d.before===null?rest.length:rest.indexOf(d.before);
if(want<0)return;                                // 这一行把真正的 -1 挡掉了
if(want===rest.indexOf(d.id))return;             // ← 恒等于 want===-1，永远不成立
```

本意是「落点没变 → 省一次请求」，但 `d.id` 已从 `rest` 里去掉，`rest.indexOf(d.id)` **恒为 -1**，
而上一行 `want<0` 已经把真正的 -1 挡掉了。于是**把卡片拖回原位照样发请求** → `placeMyDay` →
`POST /api/tasks/{id}/myday-move` → 又一次全列规整写库（与复核的边界 A/B 叠加）。

**② A21 · 界面文案 ≥20 汉字的棘轮还挂在 43**（出处 `tools/ui_text_baseline.toml` 的 `[ratchet].count = 43`）。
T-G57 把 ≥30 那一档清到 0，≥20 从 66 降到 43；`count` 是**上限**，只许往下调。

## 2. 做了什么

### 2.1 修掉恒假早退（§2.9① 裁定：选 **B**）

选 **B**（改成真正生效的判断，用**全表** `order.indexOf(d.id)`，而不是把 `d.id` 滤掉之后的
`rest.indexOf`）。理由是那条判断的**本意**就是「落点没变就别发请求」——A（只删）等于把这条优化丢掉。

改后 `index.html` 的 `mydayDragUp`：

```js
  if(want<0)return;                                        // 落点不在这一列里（理论上到不了这儿）
  // 落点没变 → 不发请求（省一次重画）。★ 要比的是**全表**里它现在的位置（`order.indexOf`）：
  //   `rest` 已经滤掉了 `d.id`，`rest.indexOf(d.id)` 恒为 -1 —— 那条判断永远不成立（T-G101 修）。
  if(want===order.indexOf(d.id))return;
  await placeMyDay(d.id,d.before);
```

**为什么 `order.indexOf(d.id)` 就是「落点没变」的正确判据**（推导，供复核）：
「把 d 放到 `d.before` 之前」结果与现状一致 ⟺ `d.before` 正是 d **当前的下一项**。
`rest = order \ {d}`；当 `d.before` 紧跟在 d 后面时，它在 `rest` 里的下标恰好等于
d 在原表 `order` 里的下标 → `want === order.indexOf(d.id)`。`d.before === null`（落末尾）时
`want = rest.length`，与「d 已在末位」的 `order.indexOf(d.id) = order.length - 1 = rest.length` 相等，
同样被正确挡住。落点不在这一列 / 落自己 → 仍由上一行 `want<0` 挡住（行为不变）。
