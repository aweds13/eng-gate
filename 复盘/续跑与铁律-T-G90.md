# 续跑与铁律：把"中断"从灾难变成一次重试（T-G90）

> 用户 2026-09-26：「能不能尽量把活给 WorkBuddy，增强稳定性」。这条卡就是把稳定性做实的四件事：
> **续跑**（断了能接着干）、**自动重试**、**铁律进系统提示**、以及**"什么样的活能给工人"的判据**。

## 1. 外包最大的风险不是慢，是"白干"

卡 002 那一轮花了 **14.2M input tokens**（cache read 13.9M）、跑了 44 分钟才收工。
它要是跑到第 80 分钟被卡死掐掉，**这 14.2M 就全白花了** —— 之前的做法是"从头再派一张"。所以
稳定性的第一件事不是"让它更快"，是**让它断了能接着干**。

## 2. 续跑（实测能做）

CLI 有 `-r/--resume [sessionId]` 与 `-c/--continue`。探针（真机）：

```
① -p 「请记住一个数字：42」                        → 回「记下了」，拿到 session_id
② --resume <同一个 id> + 「我刚才让你记的数字是多少」 → 回「42」，session_id 不变
```

所以 T-G90 改了三处：

- **不再传 `--no-session-persistence`**（T-G85 当初加上它是为了"干净"，代价正是"断了就续不上"）；
- 跑完把 `session_id` 落到 `gates/diag/wb-<卡>.session.txt`；
- `--resume <id>` / **`--resume auto`**（读那个文件）带着**同一个会话**接着干；续跑时的指令由
  `continuation_prompt()` 生成，核心一句是 **"不要重做已经做完的部分"** + 把中断现场（最后几步）交给它。

**自动续跑**：`--retry N`（默认 1）—— 卡死 / 超时 / 没跑完时自动带同一会话再来一轮，每轮一个 log
（`wb-<卡>.r2.jsonl`，证据不互相盖）。

★ **只对"被打断"续，不对"空转"续**：空转是原地打转，续跑只会让它接着转 —— 那正是看门狗要掐的东西。
（`should_resume()` 一条判断，测试里两个方向都钉了。）

## 3. 铁律进系统提示（不再只靠开场白）

工人换轮次、上下文被自动压缩之后，**开场白会越来越远，系统提示还在**。所以八条铁律改成
`--append-system-prompt` 直接钉进系统提示：

```
① 以卡规格为准（能改哪些文件/要不要跑门禁/能不能提交）
② 只在卡的白名单内改文件 —— 越界 = 这一轮作废
③ 不许假完成：说「做完了」必须给出可复现的命令与输出（先跑红、再跑绿）
④ 门禁不过不许提交；要提交就带四行 trailer（Task/Refs/Ledger/Gates）
⑤ 一写一读：工作区归你，别人的未提交改动一个字都不许碰
⑥ 禁区：真实数据库、备份目录、别人的未跟踪文件
⑦ 拿不准口径就停下说明，别自己定产品决策
⑧ 按卡的回报格式回报，边界如实写、不假装
```

与卡规格冲突时**以卡规格为准**（卡才是"这一轮的口径"）—— 这一条也写在系统提示里。

## 4. 什么样的活能给工人（判据，不是感觉）

**能给**（外包的"甜点区"）：
1. 目标**能用命令验收**（有判据 / 有测试 / 有真机探针）；
2. 改文件白名单**列得清**；
3. **不需要产品口径决策**；
4. 是"一张卡一件事"，不牵动别的卡；
5. 我**能在提交前读懂 diff**（几百行以内、集中在一两个文件）。

**不能给**（必须我做 / 必须问用户）：
1. 产品口径决策（如三分类 A/B/C）；
2. 破坏性 / 不可逆（真实库、备份、删数据、改协议）；
3. 需要看**这场对话**的上下文（"用户刚才那句话是什么意思"）；
4. 架构级改动（先由我拆成卡，再一张一张派）。
5. ★ **跨卡一致的收尾**（台账数字、交接文档、`sync_counts`）—— 两张卡并行写同一个台账必然互相盖，
   这类收尾留给我，一次做完。

> 这条边界的意义：**"尽量给工人"不等于"什么都给"** —— 给错的代价是"回来我还得逆向搞清它干了啥"，
> 比自己做还贵。判据在上面，能用判据判的就不靠感觉。

## 5. 证据

- `tests/test_wb_dispatch.py` **32 条**（25 → 32）：铁律进系统提示 / `resume_command` 形状 /
  `session_id_seen` / `continuation_prompt` 里那句"不要重做" / `should_resume` 两个方向 /
  **端到端**："第 1 次被掐 → 自动带同一会话续跑 → 第 2 次成功" / "空转不许续跑（只跑 1 次）"。
- 真机探针（原样 argv）：首轮带 `--append-system-prompt` → `subtype=success`、拿到 session_id；
  用 `wd.resume_command()` 的输出原样续跑 → 回「7」（首轮让它记的数字）→ **续跑记得住**。
- 边界（如实写）：会话会落在 `~/.codebuddy/projects/` 下**慢慢堆积**（换来的是能续跑）；
  续跑时工人会重新看到之前的上下文，**token 照花** —— 它省的是"重做一遍的活"，不是"重读一遍的钱"。
  另外：`--retry` 只兜"被打断"，真跑上还没触发过（头几轮派活要盯一眼）。
