## L0 · 意图层（人说了算 / 授权边界 / 停止条件）

### Q-L0-1 用户那一句「授权」到底授权到哪个动作，代理凭什么在**动手前**知道自己没越界？
- 为什么它会咬人：真实现场 —— `复盘/长任务执行协议.md` §四「停止条件」是五条**人话**（破坏性 / 需要产品决策 / 超范围 / 门禁红 / 文档冲突），没有任何机器表达；`复盘/架构索引-分层图.md` 把 L0 判为「人；无机器判据」。真咬过：主控据一句口头授权改了「只有用户能改」的模型开关（10.5 立规之前）。
- 该由谁回答：人（给授权粒度）＋ 机器判据（判「动作 ⊆ 授权集」）
- 什么证据能把它了结：一条能把某个具体动作（如改 `tools/wb_dispatch.py` 的 `MODEL_WHITELIST`）判成「越权 / 未授权」的判据或反例钉子，附它的红/绿读数。

### Q-L0-2 代理的「我不确定」现在只能写进散文，谁会去读第二次？
- 为什么它会咬人：真实现场 —— `复盘/不变量台账.toml` 77 条里有 **8 条 `judge = -`**（其 gaps 原文自认是「只有人话、没有机器落点」那一类）；`docs/traceability.toml` 第 5505 行也记着「`judge = -` 的 7 条」这一类；`复盘/交接-重构进度.md` 的待定清单同样是散文。
- 该由谁回答：人（定「不确定」的字段形态）＋ 机器判据（判它有没有被读第二次 / 关掉）
- 什么证据能把它了结：能把一条「我不确定 X」变成门禁/审计会点到名的字段，并证明它在被关掉之前一直亮着的读数或反例钉子。

### Q-L0-3 「只有用户能改」的名单是一条**代码常量**，谁来判代理没动它？
- 为什么它会咬人：真实现场 —— 10.5 写「名单 = `tools/wb_dispatch.py` 顶部 `MODEL_WHITELIST` 常量……**只有用户能改**」；但这句话本身没有判据：代理改了常量，17 道门里没有哪道会红（git 只看有没有提交，不看是谁改的）。
- 该由谁回答：机器判据（把「人专属文件」做成清单并按 blob 比对）或人
- 什么证据能把它了结：一份「人专属文件」名单 ＋ 一条改动即红的判据（或一条证明「代理真改过而没人拦」的反例钉子）。

### Q-L0-4 「这算不算产品决策」由代理自己判，判错的代价谁兜？
- 为什么它会咬人：真实现场 —— §四 第 2 条把「需要产品决策」列为停止点，但「哪些算产品决策」没有清单；`docs/specification/conventions.md` 第 5 行又写「由人维护，AI 不得自行增删」，同样只是一句话；规则面（`conventions.md` / `contracts/` / `ACCEPTANCE.md`）本可以当机器可读的边界，现在只是散文。
- 该由谁回答：人（给判据）
- 什么证据能把它了结：一条能把「改动落在三处规则面」自动判成「必须先问人」的判据，及它的读数。

### Q-L0-5 用户**不在场**时，一条「不可逆」动作的授权边界怎么落成可复核的东西？
- 为什么它会咬人：真实现场 —— 协议 §二 能力边界写「工作区外写入 ❌」，而并行期实际在仓库内 `.wt/<卡>` 建 worktree（§十 10.2）；规则一直在往「可逆」一侧挪，全靠人记。
- 该由谁回答：人 ＋ 机器判据
- 什么证据能把它了结：一份「无人值守授权」清单，写清哪些动作可做、哪些必须等在线，并有能用它复核某笔机器动作的读数。

### Q-L0-6 意图中途改了（换模型 / 换口径），已派出去的卡和已落的提交谁对账？
- 为什么它会咬人：真实现场 —— 10.5 定「换模型只影响新派的卡，正在跑的卡不许中途换」；但「意图变更那一刻有哪些卡在跑、各自按哪版意图做」没有落成可查的东西，只在日志/人脑里。
- 该由谁回答：机器判据（记「卡 ↔ 当时的意图版本」）
- 什么证据能把它了结：能回答「HEAD `9ba2e02` 上有几张卡、各按哪版意图」的一张表或读数。

### Q-L0-7 N → SR 的「翻译损耗」谁来量？
- 为什么它会咬人：真实现场 —— `docs/intention/needs.md` 的 N 编号只被 `scripts/check_layers.py` 查「是否被 spec 引用」（编号闭合），不问「翻译得对不对」；intention 层自己的判据「一个动作做完了吗 → 它在框架上落节点了吗」（`docs/intention/README.md`）是人话。
- 该由谁回答：人 ＋ 外部（论文/工具）
- 什么证据能把它了结：一条能把某个 N（如 N3 债务口径）对到它的 SR/OP/测试的追踪读数，且能指出哪条 N 掉在地上。

### Q-L0-8 意图层文档**自己过期**，谁判？
- 为什么它会咬人：真实现场 —— `复盘/长任务执行协议.md` §二「能力边界」表写于 2026-09-18，其中「真实 spawn sub agent ❌」「联网 ❌」「worktree ❌」都已由文末注推翻，**表体一字未改**；读表的人先被骗一次，注解在 2000 行之外。
- 该由谁回答：机器判据（把「被推翻的断言 ↔ 推翻它的注解」对账）或人
- 什么证据能把它了结：一张「协议/意图文档里已失效断言」清单，或一条能抓「表体与注解矛盾」的判据。

## L1 · 规格与契约层（specification · contracts · commands.toml · ACCEPTANCE）

### Q-L1-1 `commands.toml` 的三个「判断」字段（`kind` / `reversible` / `ai`）没有机器核对 —— 填错了谁红？
- 为什么它会咬人：真实现场 —— `scripts/check_commands.py` 只机器核对 `title`/`routes`/`ui`/`cli`/`mcp`；`reversible` 是「契约里的原话」。真咬过：OP-26 曾写「可删除」而路由里零 DELETE，直到 **T-G150（2026-09-27）** 才补上 `DELETE /api/review/items/{item_id}`。现在 OP-26 的 `reversible = 可删除` 与路由对上了，可**核对机制仍是空的**。
- 该由谁回答：机器判据（拿 `reversible` 里的动词对账路由集合）
- 什么证据能把它了结：一条「写了可删除就必须有 DELETE 路由」的判据 ＋ 反例钉子（用旧 OP-26 当负样例，看它能不能变红）。

### Q-L1-2 六份真源对账是**单向**的：真有的没登记只算「洞」，洞有没有到期日？
- 为什么它会咬人：真实现场 —— `docs/commands.toml` 顶注「洞是进度，不是错误」；现在 53 条 OP 里 **4 条 `routes = []`**（OP-8 / OP-39 / OP-43 / OP-49）；表里没有字段记「这个洞归谁、什么时候关」。
- 该由谁回答：人（定口径）＋ 机器判据（数洞并跟踪）
- 什么证据能把它了结：洞清单带负责人/到期日，或一条「洞连续 N 笔不降就告警」的读数。

### Q-L1-3 契约六要素「写了就有人实现」谁保证？
- 为什么它会咬人：真实现场 —— `docs/contracts/interactions.md` 的自查表 OP-1~OP-8 全填 ✅（2026-09-18 手填）；`check_layers.py` 只查「契约里引用的 SR 能在 specification 找到」，**不查六要素是否真落地**（入口/输入/后续/可逆/反馈逐条）。
- 该由谁回答：机器判据
- 什么证据能把它了结：把某个 OP 的六要素逐条对到路由/界面/测试的判据，或一条能把某要素缺失判红的反例钉子。

### Q-L1-4 规格「一句话带过」异常路径时，谁逼问边界？
- 为什么它会咬人：真实现场 —— `docs/ACCEPTANCE.md` 自己写着「已知局限：下表 AC 以功能存在为判据，**不足以发现『操作做一半/联动断裂』**」；`conventions.md` 也没有「必须写异常路径」的硬要求。
- 该由谁回答：人（定规格写法）＋ 机器判据（查每条 SR/OP 是否带异常/边界段）
- 什么证据能把它了结：一条能标出「哪些 SR/OP 只描了顺路径」的读数或清单。

### Q-L1-5 一个能力跨 specification / contracts / implementation 时，谁是唯一真源？
- 为什么它会咬人：真实现场 —— `commands.toml` 的 OP-2 `note` 明写「顺序口径以 `docs/contracts/domains/F1-tasks.md` 的 OP-2 为准（T-G102）；本表不另抄一套语义」；这是**手工声明**的真源归属，没有判据禁止别处再抄第三份。
- 该由谁回答：机器判据（真源声明 ＋ 反向查重）
- 什么证据能把它了结：一条能抓「同一口径在两处各写一份」的判据，及一个真实的重叠实例。

### Q-L1-6 `conventions.md` 写「由人维护，AI 不得自行增删」，没有判据。
- 为什么它会咬人：真实现场 —— 文件第 5 行原话如此；它下游被 `check_layers.py` 读（约定层存在性 ＋ 规则须标来源 N），但只查形态，**不查「谁改的」**。
- 该由谁回答：机器判据
- 什么证据能把它了结：`conventions.md` 一改动就触发「需人确认」的判据（或一条证明代理改过而没被拦的反例钉子）。

### Q-L1-7 `docs/implementation/` 只有 5 个文件 —— 它是被跳过了，还是本该薄？
- 为什么它会咬人：真实现场 —— `docs/implementation/README.md` 自己说本层只回答「哪个模块负责」，并警告「直接按本文件写代码，必然产出半成品」；`coverage.md` 仅 24 行、状态列全是**人写** ✅。
- 该由谁回答：人（定分界）＋ 机器判据（哪条 SR 该有落点）
- 什么证据能把它了结：一张「SR → 是否有 impl 落点」的判据读数，能指出哪条 SR 只落在 spec 没落到模块。

### Q-L1-8 跨域 12 条交叉（`_CROSS.md`）的「验收」有没有机器判据？
- 为什么它会咬人：真实现场 —— `docs/specification/domains/_CROSS.md` 列 C1–C12「触发→传导→落点」，规则写「链上任一环断开，整条不成立」；`docs/implementation/coverage.md` 的状态列是人写 ✅，没有交叉级判据。
- 该由谁回答：机器判据
- 什么证据能把它了结：把某条交叉（如 C1 专注×任务）对到测试/真机读数的判据，或一条能判「某个交叉没落点」的反例钉子。

### Q-L1-9 `ACCEPTANCE.md` 里标「手动」/「待人工看一眼」的条目，谁判它真的只剩手感项？
- 为什么它会咬人：真实现场 —— `ACCEPTANCE.md` 顶部说「本文件里标手动的条目……都在那份清单里」，AC-11「桌面窗口界面」标着「待人工看一眼」；这些「待人工」没有机器判据，只靠人记，且真咬过（「测试全绿但 UI 崩了」）。
- 该由谁回答：机器判据（把已搬给机器的那半边标出来）
- 什么证据能把它了结：一张「仅剩人手」的清单带勾选读数，能证明某条确实不能再机器化、或揭穿它其实可以。

## L11 · 示例层（examples/ 可跑的文档）

### Q-L11-1 示例到底 3 个还是 4 个？—— 三处文档各说各的
- 为什么它会咬人：真实现场 —— `examples/README.md` 表列 **4 个**；`docs/EXTENDING.md` 第 3 行写「能跑的示例在 ../examples/（**三个**，由浅入深）」；`tests/test_examples.py` 文档串写「**三个** examples/*.py」，但同一个文件里的 `NAMES` 列 **4 个**；`examples/README.md` 引 SR-NF10 又写「2–3 个由浅入深扩展示例」。
- 该由谁回答：机器判据（`examples/*.py` 计数 vs README/SR 声明）
- 什么证据能把它了结：一条「示例数与 README/SR 一致」的判据，或把当前 4 vs 3 vs 2–3 判红的读数。

### Q-L11-2 示例的「教学文字」会腐烂，谁的判据管它？
- 为什么它会咬人：真实现场 —— `tests/test_examples.py` 只断言「能跑 ＋ stdout 含 OK 例 ＋ 文件名在 README」，**不核 docstring/表里的说法**。例 2 讲「config.toml → env → 代码默认，后者胜」，接口或优先级一变，docstring 照旧绿着。
- 该由谁回答：机器判据（同源核对）或人
- 什么证据能把它了结：能把示例里的教学断言对到核心口径的判据（像例 3 那条「与账本同源」的钉），或一条证明某句教学已过时而测试仍绿的读数。

### Q-L11-3 四个示例的判据强度不一样（只有例 3 有「与核心同源」的钉），谁定这个差？
- 为什么它会咬人：真实现场 —— `tests/test_examples.py` 有 `test_example_3_matches_the_ledger_wording`，而例 1/2/4 只有「跑绿 ＋ 打印 OK」；同样是「教一件事」，判据待遇却不同。
- 该由谁回答：人（定每个示例该钉到什么强度）＋ 机器判据
- 什么证据能把它了结：一张「示例 → 它被钉住的断言」矩阵，或一条能判「示例只验了能跑、没验对照」的读数。

### Q-L11-4 示例跑在临时库，那它与门禁到底是什么关系？
- 为什么它会咬人：真实现场 —— `tests/test_examples.py` 是 `tests/` 的一支，进 pytest 门（门禁 2034 用例）；示例自己用 `tempfile.TemporaryDirectory`，每个都是独立子进程；`examples/README.md` 说「示例跑不通 = 测试红 = 门禁拦人」。
- 该由谁回答：机器判据
- 什么证据能把它了结：示例失败会不会真让门禁红的一次实测（先红后绿），以及它跑在门禁的哪一步。

### Q-L11-5 SR-NF10 说「2–3 个」，实物 4 个 —— 加第 4 个时谁改了规格？
- 为什么它会咬人：真实现场 —— `examples/README.md` 顶部引 SR-NF10「零基础定制友好：2–3 个由浅入深扩展示例」，表里 4 行；规格与实物的数字没有对账判据（`check_layers.py` 只数覆盖矩阵的域，不数示例）。
- 该由谁回答：机器判据（规格数字 vs 实物计数）
- 什么证据能把它了结：一条能判「SR-NF10 的数量口径与 `examples/` 实物一致」的判据读数。

### Q-L11-6 例 4 只走 `TestClient` 不起真服务，谁判真机那层没漂？
- 为什么它会咬人：真实现场 —— `docs/EXTENDING.md` §六说例 4 用 `TestClient` 只为不占端口、形状「和真机完全一致」；但真机路径还带「写类接口要求本机页面来源（`require_local_origin`）」这类判定，示例里没有覆盖到那一层（不确定它是否等价绕过）。
- 该由谁回答：机器判据 / 人
- 什么证据能把它了结：一条把示例请求与真机请求对账的判据，或一条证明二者在某字段/校验上不一致的读数。

### Q-L11-7 示例的三条红线（不折算 / 不出本地 / 温和）在示例层有没有机器判据？
- 为什么它会咬人：真实现场 —— `examples/README.md` 专列「三条红线（示例也守）」；而 `check_layers.py` 的禁用词扫描面向 docs 层（如「时间折算」），示例的 docstring/输出是否在同一张扫描网里，没有明说。
- 该由谁回答：机器判据
- 什么证据能把它了结：一条能对示例文本/输出跑三条红线判据的读数（或证明它现在够不着示例层）。
