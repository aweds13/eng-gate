## 4. ★ 一个真回归，和它的修法（值得记住的因果链）

`squeeze_scan` 从 **0 → 8 处**，全部在 `phone__offline`：`完成` 两个字被压成两行（58×56）。

因果链（**不是"字体变了"，是"少了两像素"**）：`.card > button` 是可收缩的 flex 项，而它的自动最小尺寸是 min-content ——
中文处处可断行 → 下限低到「一个字宽」。这次 `1px 边框` 每边吃掉 1px 内容宽（嵌套卡是 4px），原本**刚好**放得下的标签就过界了。

修法：`.card > button { white-space: nowrap }` —— **只限直接孩子**。理由两条：
① `.card .row` 里的按钮靠**容器换行**解决（T-G45 已定的口径），不该在这里再来一套；
② 标签可能很长的按钮（用户自己的任务名/分组名）都住在 `.row` / `.sub` 里，**绝不能被 nowrap 顶出容器**。
修完 `squeeze_scan` 回 **0 处**。

### 4.1 ★★ 我用"最快的档"采到了**错的黄金**（这一轮最值钱的教训）

修完按钮，我只重采了 `offline` 那 3 份：`node tools/render_check.mjs --update --only offline --reason "…"` ——
**16.4 秒**（全量 110 秒）。看着是最划算的一步。结果下一次全量门禁立刻红，而且红在同一批 3 份上。

我当时的两个误判（都写下来，因为它们是"快路"特有的陷阱）：
1. 先猜"是 `ui_flow` 并行污染了它" → 起 `ui_flow` 并行复现，**没复现**（`--only offline` 与黄金逐字节一致）；
2. 再去看门禁日志 —— 只印了一行摘要，**看不到差异** → 只能把 render 单独再跑一遍。

真正的原因（改了差异打印之后一眼看到）：**视图之间不是独立的**。
离线页那半页「上次联网时看到的样子」读的是**别的页面联网时**写下的缓存
（`src/web/index.html` 的 `rememberForOffline` → IndexedDB 的 `STORE_CACHE`）——
`--only offline` 根本不访问那些页面 → 缓存是空的 → 我采到的是**退化版式**（`span.sub 还没有缓存到习惯`、
少一行、卡片矮 15px）。全量跑按固定顺序访问全部视图，到 offline 时缓存已经有货。

**所以这不是"慢了 110 秒"，是"判据坏了"** —— 假红会让人去修一个没坏的东西。
处置（进 T-G58）：工具**默认拒绝** `--update --only`（除非 `--force`），并把这条写进地图 §3/§6。

## 6. 这一轮的过程账（用户：「注意优化过程」）

**做法上的四个压缩**（都当场生效，不是计划）：

| 做法 | 省了什么 |
|---|---|
| 四个**只读盘点**子任务并行（图标系统 / 图表规范 / 文案清理剩余 / 路由 1·2）—— 每个都精确到行号与数字，主上下文只收表格 | 这是"每个新窗口都要重付一遍的税"（地图开头那句）。四张卡的勘察一次性付掉，主上下文没被四个大文件吃掉 |
| 令牌改名走**一次脚本**（单遍映射 + CRLF 保护 + 每条断言），不是手改 109 处 | 改名 92 处 + 测试 2 处，**一次跑完**，`--fast` 立刻给反馈 |
| 大文件改动走**一次性补丁脚本**（每条 `old` 必须**恰好命中一次**，否则整脚本不落盘） | 不重读 700 行的 `app.css`、不手改 29 处标记；命中数不对就整批不写，比"改了一半"安全 |
| `--only offline --update`（16.4s）+ 一轮门禁覆盖 3 张卡 | 机器税从「每张卡一轮全量」摊到 **一轮 ≈ 3 张卡** |

**这一轮也踩了两个坑**（都已进地图 §6）：
① 补丁脚本里混进 **ASCII 双引号**（中文正文里），Python 直接语法错 —— 与 TOML 那条是同一个病根，**中文正文里的引号一律用「」**；
② 我用"把 ASCII 引号换成中文引号"的**字符级**修补器改脚本，它**越界把 TOML 结构里的引号也换了** —— 从备份恢复后改用"**片段文件 + 按块定位拼接**"。
教训：**字符级替换脚本只能按块定位（`'''` / `[entries.]`），改前先 `Copy-Item` 备份，替换逐条打印出来核对。**

外加一个更值钱的：§4.1 那条"快路采到错黄金"。**它暴露的是工具的两个诊断缺陷**（T-G58 一并修了）：
① 界面校验的差异只印前 8 行 → 整页位移时全是坐标、看不到原因（改成优先印"有文字内容"的差异行）；
② 全量门禁红了只印一行摘要、门自己的输出**直接丢掉** → 想查原因只能把门单独再跑一遍
（render 110s / ui_flow 176s，随机失败还未必复现）→ 现在每道门的全量输出落 `gates/logs/<门名>.log`，
失败时当场印尾部 12 行。

**时间账（估）**：三张卡合计约 **70 分钟**（含一处真回归的诊断与修复、四条只读盘点、42 份黄金重采与全量门禁）。
按上一轮的账（一张视觉卡 ~90–120 分钟、其中自闯的祸 ~60 分钟），这一轮**没有出现"自己闯的祸"那一项**（两个坑各 2–3 分钟就收敛了）。
