## 二、抓到的那条真缺陷：番茄钟其实没有"番茄"

**契约原文**（FLOW-3 贯通验收第 1 条）：
> 番茄钟能倒计时并在结束时自动提示或结束。

**实测**：`renderActive()` 里计时器一直是 `fmt((Date.now()-started)/1000)` —— **正计时**，
没有任何到点判断；`pomodoro_minutes` 在整个前端只出现在**按钮文案**里
（`番茄钟 ${cfg.pomodoro_minutes||25} 分`）。所以：
- 没有倒计时；
- 到点没有提示、也不会结束；
- 更糟的是 **`/api/config` 根本没返回 `pomodoro_minutes`** → 那句 `||25` 里配置永远取不到，
  于是 config.toml 里改成 40 分钟也还是写"25 分"（**配置项是死的**），
  连 `config.example.toml` 里都没有这个键。

**为什么一直没人发现**：台账里 `SR-F3.1` 是 `done`，证据是 `text:src/timeflow/core/focus/timer.py::tomato`
—— 这个 needle 只证明"存在一个叫 tomato 的常量"。**这就是 T-G18 记过的老毛病**：
声称 done 时挑的证据太弱（"文件里有这个词"），于是"倒计时/到点"这半句谁也没验。

**这次怎么修**（三步，都很小）：
1. **后端**：`/api/config` 补 `pomodoro_minutes`（一处三行）；`config.example.toml` 补上这个键与注释。
2. **前端**：番茄钟改成**倒计时**（`fmt(total-sec)`），到点后显示 `+MM:SS`（"已经多做了多久"），
   并**提示一次**（toast + 卡片里一行「到点了（25 分）—— 结束或继续都行，**不会替你停**」）。
   提示按 session id 记，不重复弹；到点**不改任何数据**、不自动结束。
3. **证据补强**：`SR-F3.1` 的证据换成能真证行为的那几条（倒计时表达式、到点文案、`/api/config`）。

**为什么选"提示"而不是"自动结束"**：契约写的是"自动提示**或**结束"，两者都算通过。
自动结束会替用户做决定，而"这一轮还想再做一会儿"是常事；提示一次既满足契约、又不改变账目。
到点后读数显示"已继续多久"，人自己看得见 —— 这比进度条归零后再从 0 开始更诚实。

## 三、验证（四层）

| 层 | 查什么 | 结果 |
|---|---|---|
| 前端护栏 `test_web_frontend.py::test_pomodoro_length_comes_from_config_and_only_notifies` | 倒计时用配置分钟数、到点只提示一次、提示块里**零请求**（不自动结束）、`/api/config` 真暴露、模板里有这个键 | ✅ |
| DOM 探针「专注·番茄钟」三档 | 真渲染：走了 1 分钟的番茄钟显示 `23:5x`（倒计时）/ 走了 40 分钟的显示 `+MM:SS` + 到点文案 + 动作按钮还在 / 普通计时仍 `40:00` 正计时且无提示 | ✅ 1/1 |
| 真机自检 | `GET /api/config` 真回 `pomodoro_minutes = 25` | ✅（113 → **119 项**） |
| 文档自检 | 回填表里引用的每个测试文件与用例名都真存在（脚本核过） | ✅ |

**探针踩的两个小坑**（都记在这儿，免得下次再踩）：
1. 假 DOM 的 `getElementById` 只认**登记过**的 id —— 秒数与提示是 `textContent` 写到元素上的，
   而 `#clockPeer` / `#pomoNote` 没登记 → 读数根本落不到任何地方。补登记 + 每次渲染前清 `_text`。
2. 断言别钉死那一秒：`sleep(60)` 之后读到的是 `23:59`（断言本身也要花时间）→ 改成看区间 `2[34]:\d\d`。
