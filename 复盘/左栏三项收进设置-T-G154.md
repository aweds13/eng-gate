# 「重要 / 有计划 / 已标记」收进设置开关（卡 060 · 台账号 `T-G154`）

> 工人卡 · 2026-09-27 · 规格：`gates/diag/卡060-左栏三项收进设置开关.md`（底座 `6f7d4d0`，本树 `.wt/left1`）。
> 用户 2026-09-27 原话：「重要，有计划，已标记可以不用放在左栏，我想在设置里自由切换是否直达」，
> 被问「直达」时选**方案 A**：设置里给开关决定这三项**是否出现在左栏**，开了就一点直达那个筛选视图。

## 为什么这么做

- 只读盘点（`gates/diag/盘点-S6-第二批界面反馈.md` §3）实测：这三项是**写死的 markup**
  （`src/web/index.html:21-23`），没有任何开关、也没有偏好键。
- 但**不能删 markup**：`tests/test_web_frontend.py` 的 `test_smart_views_are_reachable_at_every_breakpoint`
  （468-493）静态断言左栏 nav 里必须有这三个 `data-view`（489 还要求设置页也有 `flagged`）。
  → 所以实现走**运行时隐藏**，markup 一字不动。
- 关了左栏**不能丢入口**（手机端 ≤640px 左栏 nav `display:none`，这三个视图在手机上就靠别处进）：
  ① 设置页「入口」那排快捷跳转（`3547-3549` 一带）；② `smartViewNavHTML()` 互跳行
  （全部任务页 + 各智能视图头）。两条都**原样保留**。

## 做了什么（逐处）

### 左栏隐藏怎么做的
- `src/web/index.html` 新增状态 + 函数（挨着右栏那套 `RAIL_KEY`/`applyRail`/`toggleRail` 放）：
  `const LEFT_RAIL_KEY='tf_rail_direct'`、`const SMART_RAIL_VIEWS=['important','planned','flagged']`、
  `let railDirect=false`、`function applyLeftRail()`、`function toggleLeftRail()`。
- `applyLeftRail()` 对 `.rail nav button[data-view]` 里属于这三视图的按钮设 `b.hidden=!railDirect`
  （**不删 markup、不加 CSS** —— 用元素自带的 `hidden` 属性，`app.css` 一行没动）。
- **切视图后仍生效**：在 `view()` 的渲染链里（`nav button` 刷 `active` 之后）加一行 `applyLeftRail()`，
  **每次切视图重套一遍**（不是只在启动跑一次）；启动时另加一次 `applyLeftRail()`（挨着 `applyRail()`）。

### 设置开关落点与偏好键
- 落点：设置页「**外观**」节（`#set-appearance`），紧挨「右栏（宽屏才有）」那一行之下，
  形态是「一颗 `.settings-sub` 标题 + 一颗按钮 + 一句短 `.sub`」（照抄同节现成做法）。
- 按钮：`<button class="ghost" data-action="left-rail-smart">${railDirect?'从左栏收起':'在左栏显示'}</button>`；
  `ACTIONS` 里注册 `'left-rail-smart': () => toggleLeftRail()`。
- 偏好键：**`tf_rail_direct`**（值 `'on'`/`'off'`）；读/写都包 `try{}catch(e){}`
  （启动 `localStorage.getItem(LEFT_RAIL_KEY)==='on'`，切换时 `setItem`）。

### 默认值
- **默认 = 不显示**（`railDirect` 初始 `false`，且只有 `tf_rail_direct==='on'` 才为真）——
  与用户「可以不用放在左栏」的语气一致。开关打开后三项回到左栏、一点直达筛选视图。

### §2.4 的流怎么处理的
- 先按卡的提示 grep：`tools/ui_flow_check.mjs` 里**没有任何**流程点左栏这三个按钮
  （`git grep -n 'important\|planned\|flagged' -- tools/ui_flow_check.mjs` 零命中）→ **没有既有流被默认隐藏打坏**。
- 按 §2.4「建议加」，新增一条流 **㉙**（`desktop`）：默认左栏三项都 hidden 且主视图在 →
  设置页「外观」里点开关 → 三项回左栏 + `tf_rail_direct=on` → 点左栏「重要」**直达筛选视图** →
  刷新后保持 → 再点开关收回去 + `tf_rail_direct=off`。共 **10 项断言**。

## 碰到什么坑 / 怎么发现的

1. ★★ **卡 §7 的预期有一处与代码不符（窄屏）**：卡写「手机档（narrow/phone）不该变（手机没左栏）」，
   但 `src/web/app.css` 的断点在 **640px**（`.rail nav{display:none}` 只在 `max-width:640px`），
   而工具的 **narrow = 820px**（`tools/tf_browser.mjs:28`）→ 窄屏**仍有上图式左栏**。
   实测：默认隐藏后**桌面 15 + 窄屏 15 = 30 份黄金变、手机 15 份零改**
   （`git status gates/render` 里 `phone__*` 0 份）。这是本改动**机械上必然**的结果，不是「动了别的东西」；
   按 §7「重采全部桌面黄金」的意图，窄屏 15 份**一并重采**，并把与卡预期的这处不同**如实记在这里**（边界见下）。
2. `PYTHONPATH` 坑（卡 §0.5 / 规矩「铁律 26」）：在 Git Bash 里用 `$PWD/src` 设 `PYTHONPATH`
   时 Python 认不出 POSIX 路径 `/d/…`，`import timeflow` 会**静默回落到可编辑安装指向的主树 src**
   （症状：起的是主树页面 → 黄金假绿）。先用 `python -c "import timeflow;print(timeflow.__file__)"`
   验到指向主树，改用 `$(pwd -W)`（`D:/…`）后指向本树 `.wt/left1/src/timeflow/__init__.py`。所有 node 工具都带了这个环境。

## 黄金重采（范围 + 为什么）

- **重采 30 份**：`desktop__*.txt` 15 份 + `narrow__*.txt` 15 份（各视图左栏少三行 → 行号前移、rail 变矮）。
- **手机 15 份零改**：`phone__*.txt` 不出现（≤640px 左栏 nav 本就 `display:none`）。
- 为什么是这个范围：改动只作用于 `.rail nav` 里那三个按钮；桌面/窄屏显示该 nav、手机不显示 ——
  与实测「30 改 / 0 多余 / phone 0」一致。

## 没动什么

- `src/web/app.css`（隐藏靠 `hidden` 属性，**无新样式**）；`src/timeflow/**`、`tools/**`（除 `ui_flow_check.mjs` 加一条流）；
  `scripts/**`；`复盘/` 的其它文件；`.wt/**`；主树 3 个外来未跟踪文件；`data/`。
- **别的地盘一字没碰**：学业段（058）、复习段与 `ACTIONS` 里复习那几行（057）、memo/team 段（059）。
- 三个入口一个没删：左栏 markup、设置页「入口」跳转、`smartViewNavHTML` 互跳行。

## 边界（如实写）

- 与卡 §7.1 的**预期不同**：窄屏 820px 仍有左栏，所以 15 份窄屏黄金**也变了**（见「碰到什么坑」第 1 条）。
