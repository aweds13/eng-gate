## 2. 为什么是 workbench（不是我挑了个好看的）

`sheleg-design` 自己的风格包索引里，**workbench 就是"产品 UI 没有更强信号时"的默认包**，
定位一行写着：`dashboards, admin, internal tools`。

更要紧的是：**它的 register 和我们早就写下的规格是同一句话**。

| 出处 | 原话 |
|---|---|
| `docs/intention/needs.md` **N30** | 视觉美感：**中性底色 + 单一强调色**（线性 / 滴答那档），素雅、克制、统一 |
| `docs/specification/nonfunctional.md` **SR-NF1** | 界面必须：中性底色+单一强调色；支持亮/暗双主题；强调色可自定义；状态色…；字体/间距/圆角/阴影统一 |
| workbench 包 register | a calm, dense, utilitarian product UI: **neutral grays, borders as elevation, one functional blue accent, mono for data** |

所以这不是"审美偏好"，是**我们规格里那条质量属性第一次有了可执行的判据**。
（另一个候选 `ledger` 是"你要审计的账"、`showroom`/`paperclip` 是"卖工具的营销页" ——
都不对：timeflow 是**你自己操作的那张工作台**，用户要的是工具本身，不是它的广告。）

## 3. 这个基线钉死了什么（从现在起，这条线上的"好看"不是我说了算）

workbench 是 **core contract** 包：它只锁"值"这一半，**刻意不管**组件状态 / 首屏 / 响应式规则 /
签名元素这四段（那四段是**我们自己定、并且必须说出声**）。它锁定的部分：

1. **只有一个强调色**：`--accent` + `--accent-weak`(浅底) + `--accent-ink`(它上面的字)；
   **一屏最多一个实心强调按钮**；第二个强调色 = 设计缺陷；顺序型数据（热力图/图表）是
   `--accent` 的浓淡，**不是新色相**。
2. **状态色只表状态，且不许只靠颜色**：`--ok`/`--warn`/`--danger`/`--info` 各自带一个 `-weak` 浅底；
   **琥珀色留给"需要人"**；`--info` **就是**强调色那个色相（"正在跑"是产品自己的信号，不是新颜色）；
   成功/警告/失败永远配一个图标或一个字 —— **状态绝不只用颜色表达**。
3. **层次 = 1px 边框，不是阴影**：`--panel` / `--panel-2` 台阶 + `--border`；
   真浮层（对话框/气泡/菜单）才用唯一的 `--shadow-1`。
4. **几何只有三档**：圆角 `6 / 10 / 999`；间距走 **4px 网格**（4/8/12/16/24/32）；
   表格行高 32–36px、数字列右对齐。
5. **字号成令牌**：11(芯片) / 12(标签，大写加字距) / 13(正文与密集 UI) / 15(卡片标题) /
   20(区标题) / 28(页标题)；**所有数据用等宽字体 + `tabular-nums`**。
6. **亮/暗同源**：day one 就两套都出，组件只吃 `var(--…)`；换主题是切 `data-theme`，不是两套硬编码。
7. **动效上限**：`--dur-state` 0.18s / `--dur-hover` 0.12s，只做有意义的**状态**过渡；
   **没有循环、没有滚动驱动**；`prefers-reduced-motion` 下全关。**`MOTION_INTENSITY` 超过 3 就是读错了这个包。**
8. **禁令**（逐条照抄）：不许渐变；不许拿阴影当装饰；不许毛玻璃；不许插画/吉祥物；
   不许图标噪音；**不许在产品 UI 里用 emoji**；不许第二个强调色；不许语义色做装饰；
   不许琥珀色出现在"需要人"以外；**不许显示体/衬线体**（这是工作台不是品牌页）；
   不许在有实时状态时还转圈；不许出现没有动作的徽标；不许电影感/滚动动效。

**它自己的坦白（我们必须一起继承，不许当成没看见）**：
- 包自己量出亮色下 **5 对不到 AA**（`--ok`/`--ok-weak` 4.47、`--danger`/`--danger-weak` 4.47、
  `--warn`/`--warn-weak` 4.41、`--accent`/`--panel-2` 4.30、`--accent`/`--accent-weak` 4.00）
  并**明确拒绝改值** —— 理由是"在这里调深一点，就是发明了一个这个包不拥有的颜色"。
  它给的解法是**规则**不是新颜色：**芯片里的状态词用正文色写**（在三种浅底上都是 14–15:1），
  状态色由**点或底**承担；**强调色文字绝不坐在 `--bg` / `--panel-2` / `--accent-weak` 上**。
- 它的 `Origin:` 写的是一条**记在案的例外**（只有"Builder Pro 生产设计系统"这个名字、没有可核对的地址），
  所以那四段空缺**不许靠发明补上**——"从 token 层回填"就等于"给发明出来的值配一条引用"。

## 4. 第一次拿它量自己：亮色主题 9 对不到 AA（**这是缺陷，不是审美**）

包的 `## Gotchas` 是**拿生产令牌算出来的数字**。我照它做了同一件事：把
`src/web/app.css` 令牌区的颜色两两算 WCAG 对比度（脚本是一次性的，方法见 §7）。
**暗色主题全过；亮色主题 9 对不达 AA 正文**：

> ⚠️ **数字以 T-G27 为准**：下面这 9 条是我当时**手挑的一个子集**（15 对里挑出的）。
> T-G27 把它做成了门（`tools/contrast_audit.py`），用**系统化的 42 条组合**（含 6 个强调色预设
> 与三个徽标的合成底）重算，亮色实际是 **18 条**不达标。**结论方向完全一致，只是覆盖面更全** ——
> 要看完整的 18 条与三条根因，读 `复盘/审美门-对比度-T-G27.md`。

| 场景 | 前景 / 背景 | 对比度 | AA 正文(4.5) | AA 大字(3.0) |
|---|---|---|---|---|
| `.accent` / `.flag` / 底栏选中 / `.prio.mid` —— **强调色当文字** | `#3b82f6` / `#f8fafc` | **3.52** | ❌ | ✅ |
| 同上，在卡片上 | `#3b82f6` / `#ffffff` | **3.68** | ❌ | ✅ |
| **徽标 · 完成**（`color-mix(ok 18%)` 底 + ok 当文字） | `#22c55e` / `#d7f5e2` | **1.96** | ❌ | ❌ |
| **徽标 · 进行** | `#3b82f6` / `#dce9fd` | **3.00** | ❌ | ✅ |
| **徽标 · 硬考核** | `#ef4444` / `#fcdddd` | **2.96** | ❌ | ❌ |
| 实心强调底上的白字（`.prio.high` / 主按钮） | `#fff` / `#3b82f6` | **3.68** | ❌ | ✅ |
| 危险色当文字 | `#ef4444` / `#f8fafc` | **3.60** | ❌ | ✅ |
| 完成色当文字 | `#22c55e` / `#f8fafc` | **2.18** | ❌ | ❌ |
| 次级文字在浅底上 | `#64748b` / `#eef2f7` | **4.23** | ❌ | ✅ |

三条结论：

1. **最糟的不是配色，是"色块里用同一个颜色写字"**（完成徽标 **1.96**）。
   这正是包那条 Gotcha 描述的形状 —— 而它的解法在**我们这里算出来是通的**：
   徽标文字改用正文色 `--text`，同一批底色上变成 **11.5 / 11.9 / 12.6**，全部 PASS。
   **不需要发明任何新颜色。**
2. **`--accent-soft` 名不副实**：它的值是 `#f1f5f9`（一个中性灰），注释却写"浅强调底"；
   真正需要强调浅底的三处徽标只好**各自手写 `color-mix(… 18%, transparent)`**（`app.css:155/284/287`）。
   包里正好有一句 Gotcha 说这件事：**"一个 Chip/Badge 原语抄三份，就是令牌层开始烂的方式"**——
   我们有 **3 份**。而且这 3 份就是上面最糟的 3 行。
3. **`--accent-on` 是个单值，但强调色有 6 个预设**（设置页可选）。白字在 6 个预设上
   **没有一个过 4.5**：`#f59e0b` **2.15** / `#10b981` **2.54** / `#0ea5e9` **2.77** /
   `#3b82f6` 3.68 / `#ef4444` 3.76 / `#8b5cf6` 4.23。
   → **"让用户换强调色"这件事，必须连"它上面的字用什么颜色"一起定**，否则换色就等于把按钮文字弄糊。
   （包的做法是 `--accent-ink` 随主题翻转：亮色 `#fff`、暗色 `#0f1218`，因为白字在暗色强调上也不够。）

### 4b. 去 AI 味基线量自己：反模式命中 2 条，其余 7 条没中

`web-artifact-designer` 的 9 条「一眼看穿的 AI 味」逐条对我们：

| 反模式 | 我们的实况 |
|---|---|
| 紫→蓝默认渐变 | **0 处渐变**（`app.css` 里 `gradient` 命中 0）✅ 没中 |
| 全部居中、无层级 | 全站左对齐 ✅ 没中 |
| 字体/字号雷同 | 系统字体栈 + 6 档字号，但**字重/行高没有令牌**（全文 1 处 `line-height`、4 处 `font-weight`）→ **半中**（与 T-G24 §5-3 一致） |
| **emoji 当图标** | **命中**：左栏/底栏 6 个视图的图标就是 6 个 emoji（📅 🗂️ 👥 🔥 📈 ⚙️，`index.html:58–64` 的 `span.ic`）；另有 ✅×4 / ❌×3 / ⚠️×3 当状态记号 |
| **每张卡片一样的圆角、一样的灰边** | **命中**：66 处 `.card` 同一套（T-G24 §5-1） |
| 阴影乱用（又大又糊） | 只有 **4 处** `box-shadow`，且都很轻 → 没中（我们的问题是**几乎没有阴影**，层次全压在 1px 边框上） |
| 颜色随手挑、没系统 | 有令牌 + 有护栏；但 `--accent-1..6` 是 6 个并列**色板**、`--accent-on` 只有一个 → **半中**（见 §4-3） |
| `margin: 20px` 随机散布 | 有 `--sp-1..11` 且护栏强制 → 没中（残余是那 114 处内联 `style`） |
| 无响应式/小屏塌 | 4 个断点 + 移动端底栏 ✅ 没中 |

**一句话**：我们不是"通用 AI 味"（渐变、居中、乱阴影一条没中），我们中的是
**"只有一套卡片语言 + 缺中性色阶 + 缺字重行高 + 拿 emoji 当图标"**——
和 T-G24 §5 独立量出来的那几条**完全重合**。两条独立的路量到同一处，说明那确实是主因。

> ★ **顺手量到的一件好事**：那 6 个导航 emoji **没有被任何测试断言**
> （`tests/test_web_frontend.py` 里 0 命中，探针/真机自检里也没有）——
> 也就是说"换成内联 SVG"**不会撞护栏**，比 T-G24 §8 里估的代价低。
> 但 ✅/❌/⚠️ 在探针（`tools/ui_dom_probe.mjs`）里**是有的**，动那几个要同提交改断言。

## 5. 它对 T-G24 §8 那条三步路径的四点修正

T-G24 给的是"先收内联样式 → 建层次语言 → 排版节奏 + 图表规范"。用 workbench 的
**craft bar（七道门，按依赖排序）**对一遍，缺了两道：

| 包的门（顺序有意义） | T-G24 的三步里 | 处置 |
|---|---|---|
| ① 任务本身能跑 | 不在视觉线里 | 不管（本项目主线在管） |
| ② 状态/流程定完 | 不在视觉线里 | 不管 |
| **③ 可用性：键盘 / 对比度 / 文本缩放** | **缺** | ★ **新增，排在"打磨"之前**：§4 那 9 对就是它的第一批工单。理由很硬 —— 后面每一步都在改颜色，先把"读得清"钉住，免得改完再返工 |
| ④ system：视觉决定只住一处 | 已有（令牌区 + 护栏） | 保持 |
| ⑤ polish：**全量吃令牌，diff 里零裸值 / 零 ad-hoc 字号** | 部分（尺度有护栏，**颜色/字重/行高没有**） | 把"零裸值"从尺度扩到**颜色 + 字重 + 行高**（可做成护栏） |
| ⑥ 情绪：只做挣来的动效 | workbench 动效上限 0.12–0.18s、无循环 | 明确写进基线，免得重构时顺手加动效 |
| ⑦ 一致性：一张脸、一套缓动、一个强调色、一个原子一件事 | 待做 | 与 §4-2 的"3 份手写徽标"是同一件事 |

**另外两点**：

- **组件层那个问题已经回答了**：包要求"每个项目问一次：用不用 `shadcn/ui`？默认 yes"。
  我们的答案是 **不用** —— ① 本项目「前端零依赖、无构建步骤」是既有约定（`docs/EXTENDING.md`）；
  ② 我们已经有组件层了（`app.css` 的 `.card`/`.badge`/`.btn` + `emptyState()` + `toast()`）。
  包自己也说"已经有组件层的项目就算已经回答过了，凭口味迁移不是设计决定"。**记在案，不引依赖。**
- **图表规范有了判据**：包说"顺序型数据刻度是 `--accent` 的浓淡，不是新色相"，并给一条硬规则 ——
  **在 `--bg` 上画密集表格是错的**（亮色下 `--bg` 与 `--panel-2` 同色，行 hover 会隐形；表格必须落在 `--panel` 卡片上）。
  这正好接住 T-G24 §5-4（6 个图表各写各的）和 `SR-F1.5b` 那个待做的热力图。

## 6. 明确**不**用的那一半（以及为什么）

`sheleg-design` 有一半是电影感/滚动驱动（一个滚动时钟、WebGL/粒子、GSAP、morph 数学、
`SURFACE_COMPOSITION` 六层景深…）。这一半**整块不适用**，三条例由都在包自己嘴里：

1. 包的 `When to Use` 写着：产品 UI 走 **style-pack only**，并且
   **"Never apply the cinematic motion layer to: product UI"**；
2. workbench 包自己写着：**"这是唯一一个可以单独用的包 —— SHELEG 的电影感动效层在这里出界"**，
   动效只留 0.12–0.18s 的状态过渡，`MOTION_INTENSITY > 3` 算读错；
3. 我们这边还有一条硬约定：**前端零依赖、零构建步骤**（引 GSAP/Three 是违反既有约定的产品决定）。

所以这次取的是：**token 层 + 规则 + 判据 + 反模式清单**，不取动效层。
（`web-artifact-designer` 同理：它面向"自包含 HTML 设计稿"这类**产出物**，不是把我们这个
多文件无构建的 app 改造成单文件。它的**反模式清单 + 质量清单**在写任何界面时都适用，
"生成一张海报/信息图"那种产出才用它那套五步流程。）

## 7. 数字怎么来的（可复现）

对比度是用一次性脚本算的（WCAG 相对亮度公式，`#rgb` / `#rrggbb` / `rgba()` 都认）：

```python
def lum(c):                      # c = (r, g, b)，每个分量 0..1

    r, g, b = map(f, c)
    return 0.2126 * r + 0.7152 * g + 0.0722 * b

ratio = (max(lum(a), lum(b)) + 0.05) / (min(lum(a), lum(b)) + 0.05)
```
