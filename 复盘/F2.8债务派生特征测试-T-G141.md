# F2.8 债务派生特征测试（T-G141 · 卡 050）

## 为什么有这张卡

用户 2026-09-26 当面裁定：`SR-F2.8`（重规划/债务重组）在软件开发完成前**暂时不做**，但要一张
**只钉现状**的护栏卡。现状（开工前自行复核，与卡规格 §1 叙述一致）：

- 债务是**纯派生**的：真名 grep 自 `src/timeflow/core/tasks/manager.py` ——
  `overdue_tasks()`（manager.py:783，两条 SELECT + Python 排序）、
  `debt_groups()`（manager.py:1973，归卡，内部走 `overdue_tasks` + `overdue_days` +
  `behavior.undated_myday_counted`→`current_variant`→`_get_raw`（behavior.py:137，SELECT）、
  `_debt_root`（manager.py:1951，`get_task` 只读））、
  `debt_count()`（manager.py:2019，`= len(debt_groups())`）——
  整条链上**没有任何写语句**；
- `git grep -E "重组|重规划|replan|clear_debt|reset_debt" -- src` → **ZERO-HITS**（收工前又跑了一次，仍零）；
- 快照机制在 `src/timeflow/storage/backup.py`，本卡没动它。

将来做 F2.8 时最容易犯的错：把债务实现成**写库清零**（两套真相）。这三条钉子让将来那个人
必须**先有意识地改掉这些测试**。

## 钉了哪三条（tests/test_debt_derived_line.py）

1. **钉① 纯派生、读时零写库**（`test_debt_read_paths_issue_zero_write_sql` +
   `test_debt_reads_are_pure_functions_of_the_db`）：调 `overdue_tasks` / `debt_groups` /
   `debt_count` 期间，用 `conn.set_trace_callback` 记录这条连接上真实执行的每一条 SQL，
   按写语句正则 `\b(INSERT|UPDATE|DELETE|REPLACE|CREATE|DROP|ALTER|VACUUM)\b` 筛 → 必须为 0；
   同一份库同一个「今天」读两遍，结果逐项相等（纯函数性质）。
2. **钉② 逾期硬考核计入债务且不消失**（`test_overdue_hard_assessment_counts_and_never_vanishes`，
   参数化 `tm.COURSE_TASK_TYPES` = 作业/考试/论文/小测，词表派生自
   `manager.VALID_TASK_TYPES`，不写死）：造已逾期任务 → 反复读 3 遍，
   每次都在 `debt_groups` / `debt_count` / `overdue_tasks` 里 —— 没有「读一次就消化」。
3. **钉③ 不存在清零/重组路径**（`test_no_write_route_for_debt_reset_or_replan` +
   `test_no_replan_or_clear_implementation_in_src`）：路由真源 = `create_app()` 现场注册的
   `app.routes`，断言**写方法**（POST/PUT/PATCH/DELETE）端点路径不含 debt/replan/重组/重规划；
   另扫 `src/**/*.py` 全文，`重组|重规划|replan|clear_debt|reset_debt` 必须零命中。
   将来有人加路由或埋实现 → 这两个测试红，那正是它该做的事。

判据全部**相对**：函数真名、类型词表、路由表都从源码/`create_app` 现场推导，没写死行号/条数/编号。

## 「读时零写库」怎么判的（选型）

卡给了两条路（UoW 记录 / monkeypatch sqlite3）。选了第三条更直接的：**`sqlite3.Connection`
自带的 `set_trace_callback`** —— 它记录这条连接上**真实执行**的每一条语句，不 patch 内部、
不依赖抽象存在与否（本仓没有 UoW 抽象，`conn` 就是裸 sqlite3 连接），语句只要发出就躲不掉；
测试里 `finally` 里摘掉回调，不污染其它用例。

## 与既有测试的关系（卡 §2.6）

`tests/test_task_debt_card_line.py`（T-F9）钉的是债务**归卡语义**（父卡/挂步/天数取最大/
三处同源）；`tests/test_behavior_rollback_line.py` 钉的是口径开关回滚。本卡钉的
「纯派生、零写库、无清零路径」**没人钉过**，故独立成新文件，不改任何既有测试。

## 反证（三贴，先红后绿）

1. **插写库**：临时在 `overdue_tasks()` 里插 `conn.execute("UPDATE tasks SET title = title")`
   → `test_debt_read_paths_issue_zero_write_sql` **FAILED**（读数：断言左值抓到
   `UPDATE tasks SET title = title`）→ `git checkout --` 还原 → 8 passed 绿。
2. **插假路由**：临时在 `create_app()` 里插 `@app.post("/api/debt/reset")`

   `['POST'] /api/debt/reset`）→ 还原 → 8 passed 绿。
3. 每次还原后 `git status --porcelain`：只剩本卡自己的两个新文件（未跟踪），**src 零改动**。

## 踩到的坑（真踩，给后来的工人）

- ★ **Git Bash 里 `$PWD` 拼 PYTHONPATH 会打到主树**：`PYTHONPATH="$PWD/src;…"` 拼出
  `D:\d\文档\…`（无效路径），import 静默回退到 site-packages 里 editable 安装指向的
  **主树** src —— 第一轮「8 passed」其实是打在主树上的（反证①当时没咬，就是这么发现的）。
  修法：`PYTHONPATH="$(cygpath -w "$PWD/src");$(cygpath -w "$PWD/tools/sandbox_shim")"，
  并先 `import timeflow; print(timeflow.__file__)` 确认落在本树再跑测试。
- ★ 卡规格 §5 的 `*> 日志` 是 PowerShell 语法；在 bash 里 `*` 会被展开成文件名参数
  （pytest 收到 `config.example.toml` 等假参数报 not found）。bash 下用 `> 文件 2>&1`。

## 没做的（边界）

- `src/**` 一行没改（反证里的临时插入已全部还原，工作区可复核）；没加字段/路由/迁移；
- 没实现任何 F2.8 功能（用户已裁定暂不做）；没动台账（`SR-F2.8` 仍是 deferred）；
- 没跑全量门禁（卡 §0.3 明令不许；轻门 = ruff + 本文件 pytest，见下）；
- 钉③的源码扫描只覆盖 `src/**/*.py`（路由断言覆盖 FastAPI 注册表）；`src` 里的非 .py 文件
  不在扫描范围（现状 grep 零命中，风险极低，如实写明）。
