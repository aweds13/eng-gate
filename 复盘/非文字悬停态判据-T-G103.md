# 非文字对比度门补「悬停 / 选中态」那一半（外包卡 016 · 台账号 `T-G103`）

> 料来自盘点卡 S-1 的 **A12**（`gates/diag/盘点-20260926.md`）。三处互相印证同一条边界：
> ① `tools/contrast_audit.py` 文件头明写「仍然算不了的：…**悬停/选中态下的非文字**…」；
> ② `复盘/视觉线地图.md` §8「已知的验证层缺口」那行标 ⏳ 未开；
> ③ `复盘/非文字对比度-T-G70.md` §7 原话：「悬停那三对是"**字 / 底**"，不是"线条 / 底" ——
> T-G45 补的是前者」。**静态那半补了，悬停这半没有。**

---

## 1. 一句话结论

`tools/contrast_audit.py` 现在非文字有**两层**，都是**从 CSS 真读**、每道门都跑：

- **静态**（T-G70）：`AA_NONTEXT_PAIRS`，8 对 / 两套主题 = **16 条**，≥3.0；
- **悬停 / 选中态**（本卡）：`nontext_state_pairs` 从 `:hover` / `.on` 规则里读出，判出 **5 对 /
  两套主题 = 10 条**，≥3.0；
- 旁栏 `AA_NONTEXT_EXEMPT`（纯装饰，只量不判）：**7 行 / 12 条**（本卡 +1 行 —— 暗色 toast 动作
  按钮的**悬停边框**，它原来那一行只写了静态底 `--toast-bg`）。

**判据没红**：真 `app.css` 上两层全过 3.0（`--strict` 退 0）—— 本卡是**补判据**，不是改界面。

## 2. 口径：做法 B（从 CSS 真读），hover 与 selected 都要

主控 §2.9 裁定：**做法 B**（手写的表会腐烂）+ **hover 与 selected 两种态都要**。落地成：
**从 `:hover` / `.on` 规则里读「图形 / 底」。**

- **图形**只认图形/边界属性：`border[-…]-color` / `border` 简写里的色 / `fill` / `stroke` /
  `outline-color`（值可以是 `var(--x)`，也可以是两令牌 `color-mix(… var(--a) N%, var(--b))`）。
  ★ **`color` 不算** —— 那是**字**那一半，归 `state_pairs`（同一条 `:hover` 规则可能两个角色都有，
  T-G45 为文字那半吃过这个亏）。
- **只改 `background`（换一层"底"）** 的状态：图形取**基础选择器**那条规则的图形
  （悬停不改边界时边界是**继承**来的 —— `.check:not(.on):hover` 的圈仍是 `--accent`），底 = 新底；
  `background` 与基础图形**同色**时按「实心图形」对**卡片底 `--panel`** 判（`.check.on` 那种）。
- **底**默认 `--panel`（本应用里控件住在卡片上 —— 与静态表对 `.check` / `.swatch` 的取法一致）。
- `transparent` / `…%, transparent` 的底**算不了**（要渲染层）→ 如实跳过，不猜。

## 3. 真表：从 CSS 读出来 5 对（两套主题各一遍）

| 组合 | 亮 | 暗 | 来自哪条规则 / 为什么是"非文字识别" |
|---|---|---|---|
| `mix(--accent 88% over --ink)` on `--panel` | **5.22** | **7.40** | `.check.on:hover`（选中勾选圈悬停：整块图形重新着色）+ `button:hover` |
| `--accent` on `--panel-2` | **4.07** | **6.04** | `.check:not(.on):hover`（未选圈悬停给浅底，圈 `--accent` 落在**新底**上） |
| `--danger` on `--danger-hover-bg` | **4.66** | **4.61** | `.danger:hover`（危险按钮的边框落在按主题各给的悬停底上） |
| `--accent` on `--panel` | **4.57** | **6.70** | `.check.on`（**选中态**的实心填充）—— 与静态表同一对，报告里两边都看得见 |
| `--ink` on `--panel` | **14.63** | **14.45** | `.swatch.on`（**选中态**的取样圈描边）—— 同上 |

★ 后两对**静态表里也在判**（同一个图形的两个态）：生成的组合**不因 key 撞了就丢掉**（从 CSS 真读
就该如实报），打印时标一句「同一对静态非文字表里也在判」。**本卡"新增"的是前 3 对。**

## 4. 豁免表新增的那一行（辅助线索，只量不判）

`AA_NONTEXT_EXEMPT` +1 行：`--border-strong on mix(--toast-ink 14% over --toast-bg)`（**只有暗色**，
实测 **1.01**）—— 暗色 toast 动作按钮的**悬停边框**。理由：按钮的**字**是识别线索（`--toast-ink`
13.04），边界不承担识别；亮色那条 6.31 本来就过，所以只写暗色（与静态那行 `--toast-bg` 同一写法）。

另外三条**悬停态**的辅助组合**沿用**了表里已有的行（同一种"不承载识别的浅底 / 装饰线"）：
`--panel-2 on --panel`（命令面板行 / 幽灵按钮 / 导航项的悬停浅底，实测 1.12 / 1.11）、
`--border on --panel-2`（幽灵按钮悬停浅底上那圈 1px 边界，1.10 / 1.20）、
`--border-strong on --panel`（取样圈**悬停描边**，1.48 / 1.64 —— T-G70 起就在表里）。
★ 理由是**同一句话**（hover 是辅助线索、识别靠字与静态边界），所以不重复登记；
这三行也在打印里逐条写清「悬停时也用它」。

## 6. 边界（如实写）

- **辅助线索不判**：悬停浅底 / 悬停描边这类（上节三条）**仍然是"只量不判"** —— 判据是
  T-G70 那句「悬停是辅助线索，静态下已经看得见」。它们若真变成唯一线索，要挪进判据表。
- **`.grab:hover` 不在这一档**：它只改 `color`（拖拽手柄靠 `currentColor`），归**字**那半。
  ★ 即便算，也是 `--ink on --panel`（14.63）—— 静态表里已有那一对，所以**没漏一个真判据**。
- **`…%, transparent` 的底**（`.bottom-nav button.active:hover` 的 `background: transparent`）
  算不了 → 跳过。
- **`.check.on:hover` 的"边界 vs 自己的填充"没量**：同一条规则同时给边界与底时，判的是
  （边界 / **卡片底**）—— 邻接判定（边界贴着它自己的填充）要渲染层，如实不算。
- **顺带发现、但本卡没改**（不在口径内，留给下一张卡）：`_COLOR` 正则是 `color\s*:…`，
  会匹配 `border-color: var(--x)` 里的 `color:` —— 给一条**同时有 `background`**的悬停规则写
  `border-color: var(--x)`，文字表就会读出一个**假前景**（第一次反证就是这么红起来的）。
  现有样式表下无影响（那条 hover 规则没有 `background`，`state_pairs` 会跳过），故未动。
- **豁免表条数变了**（6 → 7 行 / 11 → 12 条），`tests/test_contrast_nontext.py` 里那条冻结断言
  同步改了（加豁免必须是个**有痕迹**的动作）。
