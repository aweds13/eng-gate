# 非文字对比度 3.0 表（T-G70）—— 不看字也得看得见，顺带抓到输入框边框只有 1.23

> 起因：`T-G27 §6` 与 `T-G45 §7` 各自留了同一条边界 —— 对比度门量的是「字 / 底」（WCAG 1.4.3，4.5），
> 而**图标、图表的笔、状态点、控件边框**（WCAG 1.4.11，3.0）没人管。
> 用户 2026-09-25 从工程债清单里挑了它（也是"不做暗色渲染基线"那条决定的**替代方案**：
> 暗色下"看不见"的风险交给这张表）。
>
> 本卡把它做出来，并在做出来的当天抓到一条真缺陷：**输入框的边框是 1.23 / 1.33**。

---

## 1. 一句话结论

`tools/contrast_audit.py` 现在有**两张表**，都从 `app.css` 真读、每道门都跑：

- **判据表** `AA_NONTEXT_PAIRS`：**14 条**（7 对 × 亮暗）—— 控制边界 / 勾选圈 / 状态点 /
  图表数据笔 / 逾期红条，逐对 **≥3.0**，**没有登记表**（边界看不见是**缺陷**不是欠账）；
- **纯装饰表** `AA_NONTEXT_EXEMPT`：**11 条** —— 卡片边 / 分隔线 / 图表网格 / 环轨道 / 热力图空格 /
  悬停描边 / toast 按钮边框，**实测值照打、不当判据**（WCAG 明文 `pure decoration`）。

**修法是一条令牌拆分**：`--border`（分隔线，1.23 / 1.33）与 `--border-control`（控件边界，
**3.64 / 3.55**）分开 —— 7 条控件规则改用后者。**黄金一份没动**（渲染清单只采 fg/bg，不采边框色）。

---

## 2. 为什么单列一张表，而不是"把阈值改成 3.0"

因为**管的东西不一样**，混在一起会把两件事都说糊：

| | 管什么 | 规范 | 阈值 | 失败的样子 |
|---|---|---|---|---|
| 文字表 `TOKEN_PAIRS` | 字在底上读不读得出来 | WCAG **1.4.3** | 4.5 | 字看不清 = **读不了内容** |
| 非文字表 `AA_NONTEXT_PAIRS` | **不看字**能不能认出控件、读懂图形 | WCAG **1.4.11** | 3.0 | 框看不出是框、点看不出状态、线看不出走向 |

同一对令牌可能两边都要（`--accent on --panel` 既是"强调色当小字"又是"勾选圈的边"），
而**角色不同、失败后的修法也不同**。所以 `Pair` 多了一个 `kind` 字段，`key` 带 `图形` / `装饰`
前缀 —— 这样两条都留得住，不会被去重掉；文字的 `key` **不带前缀**（历史登记行与测试都按它写，
一个字节都没变）。

## 3. 判据表：14 条，全部达标

| 组合（两套主题各算一遍） | 亮 | 暗 | 谁在用（**为什么它是"识别控件"的唯一线索**） |
|---|---|---|---|
| `--border-control` on `--panel` | **3.64** | **3.55** | 输入框 / 下拉 / 文本域：框的底与卡片底**同为 `--panel`** |
| `--border-control` on `--bg` | 3.47 | 3.90 | 模态 / 命令面板里的输入框（底是 `--bg`，要与外面的 `--panel` 分得开） |
| `--accent` on `--panel` | 4.57 | 6.70 | 完成勾选圈 `.check`、8px 状态点、图表数据笔 |
| `--accent` on `--panel-2` | 4.07 | 6.04 | 落在静音面（读数卡）上的数据笔：`.chart-cell-done` / `.bar-fill` 等 |
| `--ok` on `--panel` | 5.08 | 6.75 | 「已完成」的状态点 |
| `--danger` on `--panel` | 5.24 | 4.60 | 逾期 / 硬考核左红条、`.danger` 按钮边框 |
| `--ink` on `--panel` | 14.63 | 14.45 | 取样圈 `.swatch.on` 的选中描边 |

★ 其中 4 对**是"借文字表的地板"**：它们在文字表里按 4.5 管着（更严），所以这里必然也过 ——
报告里会打一行「← 同一对在文字表里按 4.5 管着」，让人看见这两张表的关系，
而不是以为它们是两套互不相干的数字。

**为什么这一档没有登记表**：T-G27 对 toast 那条缺陷写的原话是「它是缺陷不是欠账」——
**控件边界看不见就是缺陷**。想要"先欠着"，得改 `run_gates.py` 里那条命令，那是个有痕迹的动作。

| `--border` on `--panel-2` | 1.10 | 1.20 | 图表网格 / 轴基线 / 环轨道 / 空格描边：**背景结构**，数据由 `--accent` 那几笔承担 |

★ **这是本卡最该被复核的一列。** 判断"哪些算装饰"没有机器判据，只有 WCAG 的一句
`pure decoration`。我的口径是：**这块图形/线本身不携带信息，或者不携带信息时内容里另有更清楚的线索**。
如果用户不认其中任何一条，要复议的就是这 6 行 —— 改法是把它挪进判据表并换令牌
（代价写在下面第 6 节：热力图那一档一旦提到 3.0，那张图会变丑，所以它不该被挪）。

## 5. ★ 抓到的真缺陷：输入框的边框只有 **1.23 / 1.33**

`--border` 一个令牌干了两件事，而 1.4.11 只对其中**一件**要 3.0：

```
.new input / input:not(...) / select / .field input / .textarea / .modal-box input / .palette-box input
    border: 1px solid var(--border)      /* 亮 1.23 · 暗 1.33 */
    background: var(--panel)             /* ← 和卡片底一模一样 */
```

**框的底与卡片底同为 `--panel`** ⇒ 边框是「这里能输入」的**唯一**线索，而它是 1.23 ——
33px 高的输入框立在卡片里，等于没有边。这不是"不够好看"：WCAG 1.4.11 的教科书例子就是
"文本输入框的边界必须有 3:1"。

**它与 T-G46 是同一类病的两个阶段**：T-G46 修的是"5 个输入框**没穿衣服**"（完全没有规则、
浏览器默认外观），本卡量的是"**穿上衣服了，但衣服看不见**"。两次都是渲染层/计算层能看见、
而没有任何一层在判它。

**修法**（不发明颜色，只拆角色）：

| 令牌 | 亮 | 暗 | 角色 |
|---|---|---|---|
| `--border` | `#e2e8f0` | `#26324a` | 分隔线 / 卡片边（**跟包**，继续用） |
| `--border-control`（新） | `#7c8798` | `#63738f` | **控件边界**，值由门逐对算（3.64 / 3.55） |

## 6. 为什么是"拆令牌"，不是"把 `--border` 整体调深"

三条都试过、都被否掉，理由都值得留：

1. **整体调深 `--border`**：那会让**每一根分隔线**都变成 3:1 的深灰（卡片边、左栏竖线、分组线、
   芯片描边、`.kbd`、ghost 按钮）—— 一次改掉全表的层次语言，而其中**没有一根**受 1.4.11 管。
   那是拿视觉换合规，换得还不必要。
2. **照包的值**：包自己**没有**"控件边界"这一档 —— 它的 `--border` 就是同一类 1.2~1.3 的浅灰。
   也就是说**包自己也不满足 1.4.11 的输入框那一条**。本项目"跟包、不自己发明颜色"这条规矩
   在这里**不适用**：它不是"包有个色阶我们别乱动"，而是"包把两个角色合成了一个令牌"。
   与其跟一个不合规的值，不如**把包合掉的两个角色拆开**（这正是规则背后的意图）。
3. **给输入框加浅底（`--bg`）当区分**：那是改视觉 + 仍然要给底找 3:1，绕远路。

值也不是"挑的好看灰"：`#7c8798` / `#63738f` 是按"对 `--panel`、`--bg`、`--panel-2` 都要 ≥3.0
且留一点余量"算出来的（3.64 / 3.47 / 3.23 亮，3.55 / 3.90 / 3.21 暗），门每轮重算一遍。

## 7. 算不了什么（诚实边界）

比"做了什么"更重要的一节：

- **半透明填充**：`.chart-area`（10%）/ `.chart-fill-soft`（18%）—— 合成结果取决于底下是什么，
  静态表算不出来（要渲染层）。它们是**同一支笔的陪衬**，数据由不透明的描边承担。
- **悬停 / 选中态下的非文字**：`.check:hover` 的浅底、`.swatch` 的悬停描边这类。
  （悬停那三对是"**字 / 底**"，不是"线条 / 底" —— T-G45 补的是前者。）
- **浏览器自己画的控件**：`input[type=checkbox]` / `radio` 用 UA 外观，颜色不受我们控制。
  黄金里它们的 `fg/bg` 是空的（`#000000/#000000@0.00`）—— **采集也拿不到**，所以这不是"漏验"，
  是"这一层根本没有可判的值"。
- **`color-mix(…, transparent)` 的合成底**：得知道它铺在什么上面（T-G45 定的同一条口径）。
- **图标 vs 底**：本项目图标是内联 SVG（`.ic svg`），颜色继承 `currentColor` →
  它落在什么底上就等于"字在什么底上"，已经被文字表按 4.5 管着；所以**没有一对新的**。

## 10. 与用户决定的关系（这条为什么现在做）

用户 2026-09-25 当面定的第 ① 件是「**不做全量暗色渲染基线**」，判据是"版式与主题无关，
暗色只换令牌值不换布局"，并写明 **"暗色下看不见的东西"改由非文字对比度表覆盖**。
所以这张表不是一条普通工程债 —— **它是一条决定的技术兜底**：那张决定要成立，
这张表就得真的存在、真的每轮跑、并且**说清楚它不覆盖什么**（第 7 节）。
`docs/user-guide.md` 的已知局限那一节现在照着这个口径写。
