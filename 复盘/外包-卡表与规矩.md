## §2 这个项目的规矩长什么样（与普通仓库不同的地方）

五层治理，**机器强制**，不是文档口号：

| 层 | 在哪 | 谁管 |
|---|---|---|
| 意图 | `docs/ACCEPTANCE.md` | 人 |
| 规格 | `docs/specification/functional.md`（`SR-Fx.y`）/ `nonfunctional.md`（`SR-NFnn`） | 人 + 台账对账 |
| 契约 | `docs/contracts/**`（`OP-nn`，每条操作） | `scripts/audit_progress.py` 覆盖检查 |
| 实现 | `src/**` + `tests/**` | 门禁 |
| 口径/成品 | `docs/traceability.toml`（**唯一真源**）+ `复盘/*.md` | 门禁 + 人 |

**一张卡（Task）= 台账里的一个编号**（`T-Gxx` 是"实现层自造卡"；`SR-*` 只给规格条目用）。
每条台账条目的 `status=done` **必须**有能机器求值的 `evidence`（`text:`/`route:`/`column:`/`ui:`/`test:`/`file:`），
`scripts/audit_progress.py` 会逐条求值 —— **证据对不上就是 FAIL，不许提交**。

## §3 铁律（不可协商，违反=这一轮作废）

1. **一轮一张卡。** 开工前先回话说明：卡号 + 打算动哪些文件 + 验收打算怎么写。
2. **门禁不过不许提交。** 提交前必须**真跑**一轮全量门禁（`python -X utf8 scripts/run_gates.py`），
   不是 `--seal`（`--seal` 只盖章、不跑门）。
3. **一条提交装齐三样**：代码 + 台账（`docs/traceability.toml`）+ 复盘/变更文档。
   提交信息四个 trailer：`Task: <一个卡号>` / `Refs: <其它编号>` / `Ledger: <台账变化一句话>` / `Gates: <门禁结论>`。
   `Task:` **只能有一个编号**（机器会拦）。
4. **不许伪造完成。** 没跑过的门禁不许写"通过"；没验过的事不许写 done。
   本项目的习惯：**先量再改**、**反空转**（新判据要配一条"故意坏掉"的用例证明它真会咬）。
5. **不许碰真实数据**：真实库、真实备份目录、`%USERPROFILE%` 下的东西。
   要跑数据相关的事，用 `python tools/serve.py --fresh`（临时库在 `%TEMP%/timeflow_fresh_*`）。
6. **重活不许并发**：`run_gates.py` / `ui_flow_check.mjs --twice` / 全量 pytest **同一时间只跑一个**
   —— 提示条类断言在满负载下会假红（这一层最著名的假红来源）。
7. **一写一读**：同一时间**只有一个人**写工作区。工人干活时主控不写（见 §6）。
8. **产品决策停下来问**：`SR-F1.9` 三分类（"再挂一枚 vs 扩现有类型"）、`SR-F2.8` 债务重组（待定）
   —— 这两条**不许自己定**，写清楚"卡在哪、需要哪个决定"就停。

## §4 一张卡干完必须齐的东西

- [ ] 代码（`src/**`）—— 只在需要时动；能不动就不动（很多卡是"验"或"口径"卡）。
- [ ] 测试/证据（`tests/**` 或门上的工具）—— **每个新行为至少一条会失败的断言**。
- [ ] 台账（`docs/traceability.toml`）：新卡条目（`id/title/group/status/evidence/gaps`），
      `gaps` 写清**边界与没做的事**（这里没人想读"一切正常"）。
- [ ] 复盘（`复盘/<一句话>-<卡号>.md`）：为什么这么做 / 碰到什么坑 / 怎么发现的 / 没动什么。
- [ ] 变更（`docs/changelog.md`）一条；若动了界面 → **渲染黄金必须重采**（`--update --reason`，见下）。
- [ ] 门禁全量跑过 + `python -X utf8 scripts/run_gates.py --seal` + `git add gates/last.json gates/reuse.json`。
- [ ] **一条提交**（带四个 trailer）。

## §6 冲突怎么避（这一条最重要）

两个 agent 同时写一个 git 工作区 = 索引打架、临时库打架、浏览器端口打架、门禁互相污染。
**用户 2026-09-25 定的模式：我（主控）停手，你先独占工作区；我复核完再决定下一步。**
两种可行安排（由主控在每轮开始前明确指定一种）：

1. **独占模式（默认，最稳）**：主控在你这一轮期间**不写工作区**（连文档都不改）。
   你直接在 `line/impl-v1` 上干活、提交。干完报 §5；主控复核（读你的提交 + `gates/last.json` + audit）。
2. **分支/工作树模式**（要并行时才用）：你开自己的分支（如 `line/wb-<卡号>`）或 `git worktree add .worktrees/<卡号>`，
   自己提交；主控复核后再合。★ 用 worktree 时注意：`git worktree` 里的路径**不算**仓库内路径，
   有的门（黄金/渲染）按仓库根算路径，跑之前先确认 `pwd` 是哪个树。

**任何情况下**：开工前先 `git status --short`，如果工作区**不干净**（有别人的未提交改动）→ **停下来报**，
不要试图"顺手一起提交"。

## §8 已知的坑（都是真踩过的，先读再动手）

1. **TOML 里写 ASCII `"`** → 整份台账解析不了。中文正文一律用「」；改完立刻
   `python -X utf8 scripts/check_toml.py`（0.1 秒）。修法工具：`gates/diag/probes/fix_quotes.py <行号>`。
2. **`… \| Select-Object -Last N`** → 子进程 stderr 变终止错误 + 输出被缓冲（会把通过的命令报成 exit 1）。
   一律 `*> 文件` 再读文件。
3. **按进程名杀进程**（`taskkill /F /IM msedge.exe`）→ 会杀掉用户正在用的 Edge。只按"是不是我起的"杀
   （命令行含 `--remote-debugging-port=85xx` / `tf-*-profile`）。
4. **ruff E501 按显示宽度算**（CJK 算 2 列）→ 中文行按宽度估，改完看 `gates/logs/ruff.log`。
5. **`render_check.mjs --update --only <视图>`** → 采到退化黄金（离线页读别的页面写的缓存）；
   改黄金**一律全量**：`node tools/render_check.mjs --update --reason "为什么"`（理由进 `gates/render/LAST_UPDATE.md`）。
6. **拿 2.2 秒的提示条当异步操作的唯一判据** → 满负载下采样间隙里生灭 = 假红。异步结果先等**持久信号**
   （列表多一行 / 库里的值 / 刷新后的顺序）。
7. **判据假设"两次求值之间世界没变"** → 取坐标/尺寸要在**同一次求值**里全读出来（T-G79 现场：
   `scrollIntoView` 让第二次读到的 rect 作废，抓手按在了另一张卡上）。
8. **写库的小工具漏 `commit()`** → 只在「写完早退、下次是读」的边界路径上炸（`database is locked`）。
   边界路径要配"动作之后再读一次"的断言。
9. **界面读写同一个东西用了不同名字**（写 `data-myday-id`、读 `dataset.id`）→ 看着能拖、其实没发生。
   属性名只在一处定义；交互类改动配一个接管 `fetch` 的探针看请求体。
10. **文档里的数字会漂** → 台账分布一律 `python -X utf8 tools/sync_counts.py --check`；
    门禁项数一律读 `gates/last.json`，别抄文档。
11. **`--twice` 的断言标签里不许写测量值**（会把工具自己变成假红来源）。
12. **`test:` 证据只写到文件名**（写 `文件::函数名` 会解析出不存在的路径 = 假红）。

## §13 反空转三道（T-G88）

**为什么要有**：工人在**别的进程**里干活，主控看得见的只有它落的 log。没有护栏时，两种"等"
都会发生而且都不报警 —— **卡死**（进程活着、日志不动）与**空转**（一直在动，只是原地重复同一件事）。
用户 2026-09-26 点名要"检测心跳的方式保证"，这三道就是答案。

| 道 | 判据 | 默认 | 触发之后 |
|---|---|---|---|
| ① 回合上限 | `--max-turns`（进 CLI 命令行） | 写卡 **240** / 只读卡 **80** | CLI **自己停**（退出码仍 0）→ 跑完判「没做完」，退 6 |
| ② 看门狗·卡死 | 日志静默 ≥ `--stall-seconds` | **480 秒** | 掐掉整棵进程树 + 报现场，退 6 |
| ③ 看门狗·空转 | 最近 12 次工具调用里同一（工具+参数）出现 ≥ **5** 次 | 5 | 同上 |
| ④ 心跳 | 每 `--heartbeat-seconds` 打一行 | **120 秒** | 只打印（让"它在动"看得见） |

**上限是标定出来的，不是拍的**（★ 口径经 T-G89 更正）：`--max-turns` 数的是**工具调用回合** ——
卡 002 实测 **111 次工具调用**（88 条带工具调用的 assistant 消息）。**别拿 `result` 里的
`num_turns`（卡 002 = 319）去比上限**，那是另一个计数器 —— 真机探针判定：
「要依次跑 6 条命令」的活 + `--max-turns 2` → 只跑 2 次工具调用；`--max-turns 8` → 跑满 6 次。
所以写卡给 240（≈2.2 倍余量）、只读 80。
`--max-turns` / `--autocompact` 两条都对过 CLI 2.158.0 的 `--help`
（`--autocompact <auto|tokens> … clamped to 100k-1M`）。

**★ 撞上限是"静默腰斩"**：CLI 给的是 `result.subtype = error_during_execution` + **回话是空的**，
而**进程退出码仍是 0**。所以判据有两条、互为补集：**数回合**（提前预警）+ **读 `result` 事件**
（硬证据：没有 result 事件 / `subtype != success` / 回话空 → 都算没做完）。

**边界（如实写）**：
- 空转只抓**完全一样**的调用；参数每次差一点点的"原地打转"抓不到 —— 那一类靠**静默超时**兜底
  （两条判据互为补集）。
- 判据每轮把已落的 log **整段重解析**（简单、够快：卡 002 那种量级毫秒级）；真到几万条事件再谈增量。
- 掐的是**按 PID 的整棵进程树**（不按进程名 —— 按名字会误伤同名的别的进程）。
- ★ **"真掐"那条路还没在真工人身上触发过**：用桩命令真跑钉住了行为（装死 → 掐、重复 → 掐），
  真机上阈值该收紧还是放松，得靠头几轮派活校准。
