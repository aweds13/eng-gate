## §2 这个项目的规矩长什么样（与普通仓库不同的地方）

五层治理，**机器强制**，不是文档口号：

| 层 | 在哪 | 谁管 |
|---|---|---|
| 意图 | `docs/ACCEPTANCE.md` | 人 |
| 规格 | `docs/specification/functional.md`（`SR-Fx.y`）/ `nonfunctional.md`（`SR-NFnn`） | 人 + 台账对账 |
| 契约 | `docs/contracts/**`（`OP-nn`，每条操作） | `scripts/audit_progress.py` 覆盖检查 |
| 实现 | `src/**` + `tests/**` | 门禁 |
| 口径/成品 | `docs/traceability.toml`（**唯一真源**）+ `复盘/*.md` | 门禁 + 人 |

**一张卡（Task）= 台账里的一个编号**（`T-Gxx` 是"实现层自造卡"；`SR-*` 只给规格条目用）。
每条台账条目的 `status=done` **必须**有能机器求值的 `evidence`（`text:`/`route:`/`column:`/`ui:`/`test:`/`file:`），
`scripts/audit_progress.py` 会逐条求值 —— **证据对不上就是 FAIL，不许提交**。（2026-09-26 注：各前缀的求值语义与代码行号见 §22；自测在 scripts/ 下时不能用 test:，见 §22）

## §3 铁律（不可协商，违反=这一轮作废）

1. **一轮一张卡。** 开工前先回话说明：卡号 + 打算动哪些文件 + 验收打算怎么写。
2. **门禁不过不许提交。** 提交前必须**真跑**一轮全量门禁（`python -X utf8 scripts/run_gates.py`），
   不是 `--seal`（`--seal` 只盖章、不跑门）。
3. **一条提交装齐三样**：代码 + 台账（`docs/traceability.toml`）+ 复盘/变更文档。
   提交信息四个 trailer：`Task: <一个卡号>` / `Refs: <其它编号>` / `Ledger: <台账变化一句话>` / `Gates: <门禁结论>`。
   `Task:` **只能有一个编号**（机器会拦）。
4. **不许伪造完成。** 没跑过的门禁不许写"通过"；没验过的事不许写 done。
   本项目的习惯：**先量再改**、**反空转**（新判据要配一条"故意坏掉"的用例证明它真会咬）。
5. **不许碰真实数据**：真实库、真实备份目录、`%USERPROFILE%` 下的东西。
   要跑数据相关的事，用 `python tools/serve.py --fresh`（临时库在 `%TEMP%/timeflow_fresh_*`）。
6. **重活不许并发**：`run_gates.py` / `ui_flow_check.mjs --twice` / 全量 pytest **同一时间只跑一个**
   —— 提示条类断言在满负载下会假红（这一层最著名的假红来源）。
7. **一写一读**：同一时间**只有一个人**写工作区。工人干活时主控不写（见 §6）。
8. **产品决策停下来问**：`SR-F1.9` 三分类（"再挂一枚 vs 扩现有类型"）、`SR-F2.8` 债务重组（待定）
   —— 这两条**不许自己定**，写清楚"卡在哪、需要哪个决定"就停。

## §4 一张卡干完必须齐的东西

- [ ] 代码（`src/**`）—— 只在需要时动；能不动就不动（很多卡是"验"或"口径"卡）。
- [ ] 测试/证据（`tests/**` 或门上的工具）—— **每个新行为至少一条会失败的断言**。
- [ ] 台账（`docs/traceability.toml`）：新卡条目（`id/title/group/status/evidence/gaps`），
      `gaps` 写清**边界与没做的事**（这里没人想读"一切正常"）。
- [ ] 复盘（`复盘/<一句话>-<卡号>.md`）：为什么这么做 / 碰到什么坑 / 怎么发现的 / 没动什么。
- [ ] 变更（`docs/changelog.md`）一条；若动了界面 → **渲染黄金必须重采**（`--update --reason`，见下）。
- [ ] 门禁全量跑过 + `python -X utf8 scripts/run_gates.py --seal` + `git add gates/last.json gates/reuse.json`。
- [ ] **一条提交**（带四个 trailer）。

## §6 冲突怎么避（这一条最重要）

两个 agent 同时写一个 git 工作区 = 索引打架、临时库打架、浏览器端口打架、门禁互相污染。

两种可行安排（由主控在每轮开始前明确指定一种）：

1. **独占模式（默认，最稳）**：主控在你这一轮期间**不写工作区**（连文档都不改）。
   你直接在 `line/impl-v1` 上干活、提交。干完报 §5；主控复核（读你的提交 + `gates/last.json` + audit）。
2. **分支/工作树模式**（要并行时才用）：你开自己的分支（如 `line/wb-<卡号>`）或 `git worktree add .worktrees/<卡号>`，
   自己提交；主控复核后再合。★ 用 worktree 时注意：`git worktree` 里的路径**不算**仓库内路径，
   有的门（黄金/渲染）按仓库根算路径，跑之前先确认 `pwd` 是哪个树。

**任何情况下**：开工前先 `git status --short`，如果工作区**不干净**（有别人的未提交改动）→ **停下来报**，

## §8 已知的坑（都是真踩过的，先读再动手）

1. **TOML 里写 ASCII `"`** → 整份台账解析不了。中文正文一律用「」；改完立刻
   `python -X utf8 scripts/check_toml.py`（0.1 秒）。修法工具：`gates/diag/probes/fix_quotes.py <行号>`。
2. **`… \| Select-Object -Last N`** → 子进程 stderr 变终止错误 + 输出被缓冲（会把通过的命令报成 exit 1）。
   一律 `*> 文件` 再读文件。
3. **按进程名杀进程**（`taskkill /F /IM msedge.exe`）→ 会杀掉用户正在用的 Edge。只按"是不是我起的"杀
   （命令行含 `--remote-debugging-port=85xx` / `tf-*-profile`）。
4. **ruff E501 按显示宽度算**（CJK 算 2 列）→ 中文行按宽度估，改完看 `gates/logs/ruff.log`。
5. **`render_check.mjs --update --only <视图>`** → 采到退化黄金（离线页读别的页面写的缓存）；
   改黄金**一律全量**：`node tools/render_check.mjs --update --reason "为什么"`（理由进 `gates/render/LAST_UPDATE.md`）。
6. **拿 2.2 秒的提示条当异步操作的唯一判据** → 满负载下采样间隙里生灭 = 假红。异步结果先等**持久信号**
   （列表多一行 / 库里的值 / 刷新后的顺序）。
7. **判据假设"两次求值之间世界没变"** → 取坐标/尺寸要在**同一次求值**里全读出来（T-G79 现场：
   `scrollIntoView` 让第二次读到的 rect 作废，抓手按在了另一张卡上）。
8. **写库的小工具漏 `commit()`** → 只在「写完早退、下次是读」的边界路径上炸（`database is locked`）。
   边界路径要配"动作之后再读一次"的断言。
9. **界面读写同一个东西用了不同名字**（写 `data-myday-id`、读 `dataset.id`）→ 看着能拖、其实没发生。
   属性名只在一处定义；交互类改动配一个接管 `fetch` 的探针看请求体。
10. **文档里的数字会漂** → 台账分布一律 `python -X utf8 tools/sync_counts.py --check`；
    门禁项数一律读 `gates/last.json`，别抄文档。
11. **`--twice` 的断言标签里不许写测量值**（会把工具自己变成假红来源）。
12. **`test:` 证据只写到文件名**（写 `文件::函数名` 会解析出不存在的路径 = 假红）。（2026-09-26 注：自测在 scripts/ 下时不能用 test:，见 §22）

## §12 反空转三道（T-G88）

**为什么要有**：工人在**别的进程**里干活，主控看得见的只有它落的 log。没有护栏时，两种"等"
都会发生而且都不报警 —— **卡死**（进程活着、日志不动）与**空转**（一直在动，只是原地重复同一件事）。
用户 2026-09-26 点名要"检测心跳的方式保证"，这三道就是答案。

| 道 | 判据 | 默认 | 触发之后 |
|---|---|---|---|
| ① 回合上限 | `--max-turns`（进 CLI 命令行） | 写卡 **240** / 只读卡 **80** | CLI **自己停**（退出码仍 0）→ 跑完判「没做完」，退 6 |
| ② 看门狗·卡死 | 日志静默 ≥ `--stall-seconds` | **480 秒是底线**（T-G94 起不再固定：有工具在飞上抬到 `BUSY_STALL_SECONDS=1800`，再按「历史最长 × 2.5」自适应；T-G96 封顶 3600 —— 详见 §15；2026-09-26 更正） | 掐掉整棵进程树 + 报现场，退 6 |
| ③ 看门狗·空转 | 最近 12 次工具调用里同一（工具+参数）出现 ≥ **5** 次 | 5 | 同上 |
| ④ 心跳 | 每 `--heartbeat-seconds` 打一行 | **120 秒** | 只打印（让"它在动"看得见） |

**上限是标定出来的，不是拍的**（★ 口径经 T-G89 更正）：`--max-turns` 数的是**工具调用回合** ——
卡 002 实测 **111 次工具调用**（88 条带工具调用的 assistant 消息）。**别拿 `result` 里的
`num_turns`（卡 002 = 319）去比上限**，那是另一个计数器 —— 真机探针判定：
「要依次跑 6 条命令」的活 + `--max-turns 2` → 只跑 2 次工具调用；`--max-turns 8` → 跑满 6 次。
所以写卡给 240（≈2.2 倍余量）、只读 80。
`--max-turns` / `--autocompact` 两条都对过 CLI 2.158.0 的 `--help`
（`--autocompact <auto|tokens> … clamped to 100k-1M`）。

**★ 撞上限是"静默腰斩"**：CLI 给的是 `result.subtype = error_during_execution` + **回话是空的**，
而**进程退出码仍是 0**。所以判据有两条、互为补集：**数回合**（提前预警）+ **读 `result` 事件**
（硬证据：没有 result 事件 / `subtype != success` / 回话空 → 都算没做完）。

**边界（如实写）**：
- 空转只抓**完全一样**的调用；参数每次差一点点的"原地打转"抓不到 —— 那一类靠**静默超时**兜底
  （两条判据互为补集）。
- 判据每轮把已落的 log **整段重解析**（简单、够快：卡 002 那种量级毫秒级）；真到几万条事件再谈增量。
- 掐的是**按 PID 的整棵进程树**（不按进程名 —— 按名字会误伤同名的别的进程）。
- ★ **"真掐"那条路还没在真工人身上触发过**：用桩命令真跑钉住了行为（装死 → 掐、重复 → 掐），
  真机上阈值该收紧还是放松，得靠头几轮派活校准。

## §15 长任务怎么保证跑得完（T-G91）

★ **第一原则：不要做"一次长跑"，做"一串短跑"**。长任务先由主控**拆成一串卡**（每张 30–60 分钟量级），
每张卡的产物 = 一次提交 + 一次复核。状态存在 **git / 台账 / 复盘 / 交接文档**里，
**不依赖任何进程活着** —— 任何一环断掉，接手的人（或下一个窗口）都能从仓库读出"干到哪了"。
这比任何"保活"手段都硬。

**确实没法拆、要一次跑几小时（甚至过夜）时**，四件套：

| 机制 | 命令 / 文件 | 保证什么 |
|---|---|---|
| 扔出去跑 | `--detach` | 派活进程**活过主控窗口**；输出落 `gates/diag/wb-<卡>.dispatch.log` |
| 看状态 | `--status` | 一条命令只读**文件**：心跳 / 判决 / 会话 / log 尾巴（不用翻 1 MB 的 log） |
| 断点续跑 | `--resume auto` / `--retry` | 会话落 `wb-<卡>.session.txt`；续跑指令写明「不要重做已完成的部分」 |
| 现场落盘 | `wb-<卡>.heartbeat.txt` / `.verdict.txt` | 心跳每 2 分钟一行（带时间戳）；收工或被掐都写判决 |

**超时不是失败**：默认 2 小时（`--timeout`），到点**掐掉再续跑**；机器睡眠 / 断网 / CLI 崩了同理
（日志静默 → 判卡死 → 掐 → 续跑）—— **这是故意设计的**。

**边界**：`--detach` 之后看门狗是那个脱离进程自己带着的；它被系统杀掉就没人盯了，只能靠 `--status`
看"心跳停在几点"（想让看门狗也独立，是之后的候选）。详见 `复盘/长跑保命-T-G91.md`。

★ **看门狗那个"静默 480 秒"已经不是固定阈值了**（T-G94 已落地）：旧口径假定"一次工具调用最多
几分钟"，可全量 `run_gates.py` 一次要 **~4 分钟**（`pytest` 一项就 110 秒）、冷缓存 worktree 里
`ui_flow`（要起浏览器）到 **十几分钟** —— 于是**工人只要跑一次重门禁，就会被自己的看门狗掐**。
现在改成**先看现场再判**：有工具在飞（`tool_use` 没配上 `tool_result`）→ 静默是**预期**的，底线上抬到
`BUSY_STALL_SECONDS`（**1800 秒 = 30 分钟**）；再按「历史最长一次**已完成**调用 × 2.5」自适应
（取**最长**而非平均、乘 2.5 留余量：宁可晚掐、不要误杀）；**判卡死时报告里会写出当时在跑什么**
（在跑什么 / 已跑多久 / 历史最长 / 这一次的阈值）。
★ **残留（如实写）**：~~这个自适应阈值**上界未封顶**~~ —— 「上界未封顶」那半已过时
（2026-09-26 核台账更正：**T-G96 已封顶** `ADAPTIVE_MAX_SECONDS = 3600`，即
`min(max(base, 2.5 × 历史最长), 3600)`，一次 60 分钟的调用最多把阈值抬到 60 分钟而非 150 分钟）；
**「一轮内不衰减」那半仍是事实** —— 一次长调用之后即使都是短调用，本轮内仍按已抬高的阈值算

**读 `--detach` 出来的日志一律显式 `-Encoding utf8`** —— `Get-Content` 默认按 GBK 读 UTF-8 文件，
满屏乱码看着像文件坏了（实际没坏）。

## §17 证据要带指针、报告要短（T-G108）

## §18 调试者角色（**只读**）与卡规格模板

### 18.1 什么时候派调试者

出现「**红的用例 / 说不清的失败 / 症状知道但不知道在哪**」时，**先派一个只读调试者，
主控自己别去读代码** —— 调试是**只读**活，它**不占树、不占域**，所以
**能跟任何正在写的工人并行**（这是它最大的价值）。

### 18.2 调试者只做四件事（缺一不可）

1. **复现**：给出**能复现的最小命令**（不是「我看了代码觉得」）；
2. **定位**：**`file:line`**（精确到行）+ **为什么是这里**（触发路径）；
3. **根因**：一句话说清机制；
4. **最小补丁建议**（可以贴 diff）+ **修好后该绿的用例名**。
   ★ 但它**不许改任何文件** —— 一旦它动手，它就变成第二个作者，「一写一读」当场破掉。

### 18.3 卡规格模板（写卡时照这个骨架，一节都别少）

| 节 | 写什么 | ★ 最容易漏的 |
|---|---|---|
| §0 并发期通用条款 | 六条照抄；**轻门换成该卡真正要跑的测试文件** | 照抄不改 = 指向不存在的测试 = 假红 |
| §1 背景 | **每条事实带出处**（文件:行 / 台账条目 / 报告） | 没出处的"事实"= 编 |
| §2 口径 | 逐条可验收；**需要决策的写「★ 待主控定：选项 + 代价」** | 自己挑一个写死 = 越权 |
| §3 白名单 | 只能改的文件 + **连带文件** | ★ **改常量/令牌/签名的卡，必须把「钉住它的断言文件」一起写进来** |
| §4 台账条目 | 放复盘末尾的 TOML 块；`id` 用**主控发的号** | 自编号 = 撞号（真撞过） |
| §5 自检 + 真机证据 | 先红后绿 + **至少一条真东西**（别只靠单测）；判据类卡要**突变检验** | 只有单测 = 判据可能没牙 |
| §6 回报格式 | 六项，别复述过程 | —— |
| §7 已知的坑 | **真存在的**坑（从源码/报告里挑） | 写通用废话 = 噪音 |

### 18.4 三条硬约束（都是真撞出来的）

1. ★ **产物路径不许留占位** —— 规格里写 `复盘/xxx-待分配.md`，集成时改名会**打碎台账的
   `file:` 证据指针**（同一类耦合一天撞到四次）。
2. ★ **只用相对路径** —— worktree 隔离只是**君子协定**：CLI 的 `trustedDirectories` 覆盖整个仓库，
   工人用绝对路径能写到自己树外面（撞过两次）。
3. ★ **判「工人干没干活」看 `git log`，不看 `git status`** —— 提交过的卡 `git status` 是空的（误判过两次）。

### 18.5 派「写卡工人」（S-x）时的额外要求

★ 必须**同时要求它输出「待定项清单」**（哪张卡有几处「待主控定」、分别是什么）。

## §20 ★★ 2026-09-26 本轮实测的三条硬伤（都真撞过，别重犯）

### 20.1 `--detach` 在 DSH 下**不是真独立** —— 发起它的 runner 异常死，工人被**连带杀掉**

- **现场**：卡 024 跑到第 **14 分钟**、**心跳正常**（16 回合 / 27 次工具调用 / 8 个文件），

  **时间完全吻合**。
- **结论**：`DETACHED_PROCESS` 出来的子进程**仍待在同一个 Windows Job object 里** →
  ★ **「我的窗口关了它照样跑」在"异常退出"这条路上是假的**（正常关窗大概没事，异常死会连坐）。

  ③ 被连带杀的卡 = **无半成品可续** → 只能**从零重派**（别以为 `--resume` 能救）。

**补记（2026-09-26 卡 024 真机探针发现，★ 推翻了「孤儿工人」这个设想）**：

卡 024 用**桩命令真起进程**做探针时发现：**工人的 stdout 是管道，而读管道的泵线程在派活器进程里** ——

→ 所以「**派活器死了、工人还在跑**」这种孤儿情形**在真实世界里不可达**；
★ 连带的硬结论：**工人不可能比派活器活得久**（`--detach` 也一样，正常关窗也一样）。

`heartbeat_stall_alert()`）；「日志仍在更新但没人盯」那个分支**已删**（不可达的死代码）。
★ 残余风险（如实记）：**从文件看不出工人的生死** —— 要真解决，得让工人自己写「我还活着」的凭证

（`ui:` 的 key 不在上述四种里 → False（`未知 ui 断言`，186 行）。）

### ② 该用哪个（判据表）

| 你要钉的东西在哪 | 用哪个前缀 |
|---|---|
| 仓库内任意真实文件（含 `scripts/`、`复盘/`、`docs/` 下的） | `file:<相对路径>` |
| `tests/` 下的测试文件 | `test:<文件名>`（只写文件名；不带 `tests/` 前缀、不带 `::函数名` —— 见本文档 §8 第 12 条） |
| **自测/护栏脚本放在 `scripts/` 下** | **不能用 `test:`**（它只按 `tests/<名>` 求值）→ 用 `file:` + `text:`（★ 这就是 `T-G127` 撞的那一下） |
| 钉住某个函数 / 某行实现 | `text:<路径>::<真字面>` —— 字面从源文件**原样复制**（含空格标点），别手打、别改措辞 |
| 钉住后端接口存在 | `route:<METHOD> <路径>`（方法大写、单个空格） |
| 钉住表 / 列存在 | `table:<表名>` / `column:<表>.<列>` |
| 钉住界面动作 / 视图 | `ui:data-action=<名>`（等三属性）/ `ui:view=<名>` |

### ③ 两条硬禁

1. **证据不许指向会变的内容** —— 写死的条数 / 号值 / 编号 / 行数 / 「第 N 次」都会随项目演进漂移；
   漂了这条证据就从真变假，audit 红、阻断集成。要钉就钉**稳定字面**（标题、函数签名、路由、表列）。
2. **不许改写别人文档里的原句** —— 改措辞会打穿别人台账的 `text:` 指针（本仓真撞过：改 3 处措辞 →
   台账 3 条 `text:` 失效 → 审计红 → 提交被挡）。要动受影响的旧句，按本文档通行的做法：
   **只加日期注、不删不改原句**。

### ④ 自检命令（粘进台账之前自己先跑，只读、不改任何文件）

把你自己复盘里的 toml 代码块当台账解析（验 TOML 能不能解析），再把它里面每条 `evidence`
交给 `eval_assertion` 逐一求值（含 `text:` 字面是否真命中）。★ 命令里用 `chr(96)*3` 代替三个反引号
—— 反引号在 PowerShell 双引号里是转义符，直接写会被吃掉：

```powershell
python -X utf8 -c "import sys,tomllib,pathlib; sys.path.insert(0,'scripts'); import audit_progress as ap; md=pathlib.Path('复盘/<你的复盘文件>.md').read_text(encoding='utf-8'); bt=chr(96)*3; blk=md.split(bt+'toml',1)[1].split(bt,1)[0]; d=tomllib.loads(blk); evs=[e for ent in d['entries'].values() for e in ent.get('evidence',[])]; [print(('OK  ' if ap.eval_assertion(e)[0] else 'FAIL'), e) for e in evs]"
```

全 `OK` 才许粘；出现 `FAIL` 就是证据写错了（多半是 `test:` 用在了 `scripts/` 文件上，或
`text:` 字面没从原文复制）。另：TOML 字符串里不许出现未转义的 ASCII 双引号（会打碎解析），
中文一律用「」。

### 24.7 门禁锁口径（`gates/diag/gate_lock.py`）

> 来源：`gates/diag/第二批界面反馈-队列.md` §五（2026-09-27）与铁律 25（见本文件 §24.3）。
> ★ **2026-09-27 日期注（`T-G169` 更新，卡 075）**：下面「跨树一把 / 默认 1800s」的旧口径
> 已按用户原话「不能多几把跨树锁」与 062 的两段并发实测改掉 —— 现行为见本节末尾的
> 「T-G169 后的现行口径」；旧文保留，只是过时（历史原样，别再照旧文办事）。

★★ **门禁串行锁**（本轮新增工具）：`gates/diag/gate_lock.py`（跨树共享，锁文件在主仓 `gates/diag/gates.lock`）。
并行多张卡跑门禁前必须 `acquire --card <卡号>`，跑完 `release`；否则撞固定端口 → 假红（铁律 13）。

- **用法**：
  ```powershell
  python -P -X utf8 gates/diag/gate_lock.py acquire --card <卡号> --wait 5400
  python -X utf8 scripts/run_gates.py
  python -X utf8 scripts/run_gates.py --seal
  python -P -X utf8 gates/diag/gate_lock.py release --card <卡号>
  ```
  ★ 锁是**跨树一把**（串行语义），机器只有约 2 GB 空闲内存 —— **端口隔离是防误杀，不是让你绕开锁**。
- **为什么不许用 pid 判陈旧**：`acquire` 与 `run_gates` 是**两次不同的进程调用**，建锁那个进程一退出 pid 就"死"了；
  若按 pid 判僵尸，下一张卡会**把正在跑门禁的活锁偷走** → 又撞端口（铁律 25，见 §24.3）。

# 待补 · 铁律 34「改口径要搜全，别半改」（068 抓出来的主控错误）+ 文本落盘一律走 python

## 34. 用户更正口径之后，**必须全文搜一遍旧措辞** —— 只改一节就是"半改"

**现场**（2026-09-27，卡 068）：用户先说了 A（「把它们放在左栏固定」），我写卡时按 A 写了
**标题 / §4 提交模板 / §5 读数 1、3**；用户随后更正为 B（「**我不是说并成一组固定在左栏，我是说能自由选择**」），

★★ **工人这次的处理是标准答案**（值得所有工人照抄）：
1. **按更正后的那一节执行**（§2.1），不是按标题；
2. 在**提交信息里**写明「卡 X 的标题/模板/读数 1 写 A，与 §2.1（更正后口径）冲突，按 §2.1 执行」；
3. 在**changelog 与复盘里**再写一遍，并说明哪条读数因此**不成立**；
4. **不偷偷挑一个**，也不为了"和卡一致"去实现已经被用户否掉的口径。

**规矩**：

1. ★★ **改口径 = 一次全文替换**：用户/主控更正一条口径后，必须在卡里 `grep` 旧措辞的**关键词**
   （本例：`并成一组` / `固定` / `默认显示`），**每一处都改**或**显式标"这句已作废"**。
2. ★ **留痕不粉饰**：作废的旧句**不删干净就跑**，而是划掉 + 注明"这句是错的、以 §X 为准" ——
   下一轮读卡的人（尤其是工人）要能看见**曾经错在哪**。
3. ★★ **冲突的仲裁顺序写进卡里**：`§0 铁律 > 用户原话（最新）> 分节口径 > 标题/模板/回报格式`。
   标题和模板是**最容易被写旧**的地方（因为它们是我最早写的）。
4. ★ **工人发现卡内矛盾时不许停工**：按上面的仲裁顺序自己判、按判的结果干、**在回报里点名矛盾**。
   （与铁律 32 的"残差不是清单→停工报主控"不冲突：**那条是"机械上还原不出来"（信息不足），
   这条是"两处文字打架"（信息足够，可仲裁）**。）

## 34b. 凡是"把文本交给另一个工具读"，一律用 **python 落盘**

**现场一**（今天早先）：`git commit -F <file>` 报 `error: a NUL byte in commit log message not allowed` ——
因为 PowerShell 的 `>` 写的是 **UTF-16LE**（`FF FE 66 00 …`）。
**现场二**（2026-09-27 19:1x，主控复现 075 的红绿）：同样用 `>` 把 `git show <rev>:gate_lock.py` 写盘，
拿去做 `GATE_LOCK_UNDER_TEST` 的替换实现 → pytest 报 **10 errors / `SyntaxError`**，
**看起来像"工人自报的红复现不出来"**（差一点误判工人）。用 python 取 bytes 写盘后，真结果立刻出来：
`8 failed, 2 passed` —— 与工人自报逐字一致。

**规矩**：

1. ★★ **跨工具传文本，不走 PowerShell 的 `>` / `Out-File`**。用：
   `python -X utf8 -c "import subprocess,pathlib; pathlib.Path(dst).write_bytes(subprocess.run([...],capture_output=True).stdout)"`
   —— **bytes 进 bytes 出**，不经任何编码解释。
2. ★ **自查口径**：`Get-Item <file> | Select Length` 对不上源大小（差一倍左右 / 多两个字节 BOM）就先怀疑编码。
3. ★★ **"复现不出来"先怀疑自己的取证工具**，别急着下"工人自报不实"的结论 ——
   今天的顺序是：先怀疑工具 → 发现 UTF-16 → 复现成功。**判据坏了和判据说"不通过"是两件事。**
