# 复盘 · AI 接口的边界（T-G6）

> 性质：**功能落地 + 口径复盘**（要什么 / 常见歧义 / 怎么定的 / 怎么落地的 / 边界与待办）。
> 上游：`复盘/口径定案-待定清单.md` §2（用户 2026-09-21 定的**乙案**）+ N23 / N46 + SR-F7.3 + 契约 OP-34。
> 结果：`/api/ai/*` 一组接口（**默认关**）；AI 能读任务、能加步骤、**只能勾它自己建的**；
> 你建的东西它碰不了（400 带原话）；它干过的事在事实层查得出来（`source=ai`）。

---

## 一、要解决什么

两条 need 之间有张力：

> **N23**：为 AI 智能体（Hermes）提供读写任务的接口/端口；**第一版只读 + 新增**（不改不删，
> 避免和你手动冲突）。
> **N46**：AI 作为执行者之一，通过 N23 接口**接收任务 + 回报进展**。

"回报进展"按今天的实现就是**改状态**（`PATCH`），而 N23 说"不改不删"。**你的定案（乙案）**把
判据换了：

> 判据从"改不改"换成"**动的是不是你亲手写的东西**" —— **AI 能勾它自己建的步骤，不能碰你建的**。
> 进展**用子步骤表达**（加步骤本身就是"新增"，天然符合 N23）。
> 其余要求：**可审计、可撤销、可回溯"这是 AI 干的"**；**默认关**。

这一卡就是把这四句话落成能拦得住的东西。

## 二、几个必须先想清的歧义（都定了）

| 歧义 | 怎么定 | 为什么 |
|---|---|---|
| "谁建的"放哪？ | **字段** `tasks.created_by`（`me` / `ai`，schema v16） | 边界要拦得住就得有事实依据；靠约定拦不住代码（T-G9 的教训：**记录 ≠ 事实**） |
| AI 勾掉你建的步骤 | **400 + 原话**，状态不动、**不发事实** | 静默忽略最坏：AI 以为帮你做完了；而且"没做成的事不该有记录" |
| AI 能改自己建的吗？ | **能**（就是勾完成） | 乙案判据是"归属"，不是"动作类型"——AI 自己的东西它有权推进 |
| 联动把父任务带完成呢？ | **照常发生**，事实记 `source=ai` | 那条规则**跟谁点的无关**（你自己点也一样）；挡住反而制造不一致状态 |
| "新增"怎么算可回溯？ | 看 `created_by` 字段 | 人建任务本来也不发事实；为 AI 单独造 `task.created` 会变成"同一件事两种记法" |
| 改/删怎么拒？ | 没有路由 → **403 + 原话 + 动作清单** | 规格 R4 要"明确拒绝，不静默改"；一个光秃秃的 404 对 AI 等于没说 |
| 谁能调？ | **本机来源**（跨站 403）+ **默认关** | AI 在你本机跑；网页不该能读你的任务清单（N16「默认收严」） |
| 默认位放哪边？ | **关** | 与专注白名单/到点通知同一取向：能改你数据的口子，一开始不该开着 |

## 三、落地（怎么做的）

### 3.1 一处规则，一处措辞

`src/timeflow/core/ai.py`：开关（`ai.enabled`，三层默认）、`require_enabled()`、`require_own()`、
动作表 `SURFACE`、自述 `BOUNDARY / WHY / EXAMPLE`。`api/app.py` 只做 HTTP 落地
（把 `KeyError`→404、`ValueError`→400/403 翻译出来，并做来源校验）——
**界面与 AI 读到的边界说明是同一份**（`GET /api/settings/ai` 与 `GET /api/ai/ping` 共用 `describe`）。

### 3.2 四条边界（写在这里，免得以后靠猜）

```
读      GET  /api/ai/ping              自证：开着吗、边界是什么（不读你的数据）
读      GET  /api/ai/tasks             任务列表（view / assignee / limit 与人侧同口径）
读      GET  /api/ai/tasks/{id}        一个任务 + 它的步骤树
新增    POST /api/ai/tasks             建任务；给 parent_id = 给那个任务**加一个步骤**
勾完成  POST /api/ai/tasks/{id}/complete   只勾 created_by='ai' 的；你建的 → 400
（改/删）PATCH/PUT/DELETE /api/ai/**   → 403 + 原话 + 上面这张表
```

### 3.3 "AI 干的"怎么查

- **状态变化**：走和人**完全相同**的领域路径（`complete_task(..., actor="ai")`），
  事实的 `source` 记 `ai`（人做的仍然是 `desktop`，**不改历史含义**）；
  账本口径一点没变 —— 完成就是完成，不因为是谁做的换算法。
- **新增**：归属写在 `created_by` 上；界面上有「AI 建的」徽标（卡片与详情各一处）。
- **撤销**：你自己在界面上撤销即可（AI 自己没有删接口，也不需要另造一套撤销）。

## 四、证据

- **单测 23 条**（`tests/test_ai_line.py`）：默认关时整组 403；三层开关与怪值拒绝；
  只读不改东西（版本号与状态都不动）；新增（含字段白名单、三层嵌套上限、过期截止日照样标逾期）；
  **勾自己建的 200 且事实 `source=ai`**；**勾你建的 400、状态不动、不发事实**；
  联动"最后一个步骤带完成父任务"如实记（`['desktop','ai','ai']`，且父任务那条也是 `ai`）；
  幂等；账本不变；归属不可手改；改/删 403；关掉后已建项仍在；跨站读写 403；
  v16 迁移（老行 `me`）与**新建库第一次连接就有这列**。
- **真机自检 10 条**（`tools/web_live_check.py`，跑在**真服务**上，按"关→开→用完再关"走一遍）：
  默认关 403 / 开关能开 / ping 自证 / 能新增（归属 `ai`）/ 能勾自己建的 / **勾你建的被 400 拦下** /
  改删 403 / 跨站读写都拦 / 动作在事实里可回溯 / 关掉后又回到 403。
- **DOM 探针「AI 接口 3/3」**：设置页渲染出开关（开/关两态）+ 边界 + 动作表 + 示例命令；
  **反证**：`AI 建的` 徽标只出现 1 次（只有那张 AI 的卡带，你建的不带）。
- 顺手修掉的两个真问题（都是测试逼出来的）：
  1. `assignee` 过滤一开始调了 `team.assignments(conn, t.id)` —— 那是**按执行者过滤**的接口，
     把任务 id 传进去只会静默返回空（还可能撞上同名的"人"）；改成 `assignments_for_task`；
  2. 未知 `view` 参数在 AI 路由里直接抛 `ValueError` → 500；改成 400 带原话（与人侧一致）。

## 六、边界与后续（诚实清单）

1. **没有真正的身份认证**：守住的是"本机来源 + 默认关"。同一台机器上的其它程序（不只 Hermes）
   只要开关开着就能调 —— 这符合 N23"本地接口"的定位，但**不是**多用户鉴权。要更严得另立一卡
   （令牌/白名单进程），属产品决策。
2. **AI 无法"改内容"**：改标题、改截止日、改优先级、删任务都做不到。这是这一版**故意**的，
   不是遗漏（N23 的"不改不删"）。
3. **`created_by` 不会跟着所有权变化**：AI 建的任务你接手改标题，它仍然是 `ai` 建的、
   仍然可以被 AI 勾完成。要"接手后就不许 AI 动"得另加字段（现在没这需求）。
4. **不写审计文件**：靠事实层（`source=ai`）而不是另写日志 —— 事实本来就带 `recorded_at`、
   `subject_id`，再加一份只会两处漂。
