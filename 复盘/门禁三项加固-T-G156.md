# 门禁三项加固：端口按树隔离 + 开场清遗留 + pytest 限并发（T-G156）

> 卡号 062（台账号 `T-G156`）。只改 `scripts/run_gates.py`（主）、`gates/diag/gate_lock.py`（配合）。
> **不设新环境变量时，端口 / 门数 / 复用键 / 黄金 / `gates/last.json` 形状全部逐字不变。**

## 一、为什么（三条实测病灶，出处见卡 §1）

1. `scripts/run_gates.py:21` 明写「render 8531/8532、ui_flow 8541~8544」→ 五棵树抢同一段端口
   （059 那张卡 87 分钟里约 45 分钟纯等端口）。
2. 清端口按**进程特征**杀（`serve.py --fresh` / `tf-flow-profile-`），不认哪棵树 → 058 把 059
   正在跑的 render_check 杀了。
3. 工人 CLI 单次调用有 10 分钟上限，而全量门禁常超它 → 被掐 → 服务/浏览器变孤儿 → 又撞又清。

## 二、§2.0 盘点：用端口的每一道门

| 门 | 端口来源 | 可否配 | 谁起服务/浏览器 | 谁关它 |
|---|---|---|---|---|
| `render` | `tools/render_check.mjs`：`ARGS.port` 默认 **8531**；CDP = `port+1` = 8532；profile `tf-render-profile-<port>`（`render_check.mjs:97,106,408-410`） | 是：`--port`（文件头已声明），T-G156 起由 run_gates 透传 | node 起 `serve.py --fresh --port` + 无头 Edge（CDP port） | `render_check.mjs:563-565` `finally`：`cdp?.close()`（杀 Edge）+ `server.child.kill()`（杀 serve） |
| `ui_flow` | `tools/ui_flow_check.mjs`：`ARGS.port` 默认 **8541**；每遍 `server=port+2*(pass-1)`、`cdp=server+1`；profile `tf-flow-profile-<server>`；流内对端再起 `server+4`（另一真客户端 CDP）/`server+6`（另一份真库 server）（`ui_flow_check.mjs:103,1709-1712,1297,1483`） | 是：`--port`，T-G156 起传 `BASE+10` | 同上 + 流内自起第二 serve / 第二 Edge | `ui_flow_check.mjs:1754-1757` `finally`：同上 |
| `lf1_live` | `tools/lf1_live_check.py:62,69` `free_port()`（bind 0 自动挑空闲） | 自动挑空闲（也可 argv） | 本进程内 `uvicorn` 线程 | 进程退出即消 |
| `web_live` | `tools/web_live_check.py:721-723` `_free_port()`（**T-G47 已自动挑空闲**） | 自动挑空闲 | 本进程内/子进程 `uvicorn` | 自行收尾 |
| `ui_dom_probe` | **不用端口**（假 DOM，不起服务、不起浏览器） | N/A | 无 | 无 |
| 其余（pytest/acceptance/ruff/mypy/三护栏/两审计/commands/ui_text） | 不用端口 | — | — | — |

**★ 卡 §2.0 三问的答案**：`ui_dom_probe.mjs` **不用端口**（纯假 DOM，无需 `--port`，故未动它）；
`lf1_live_check.py` 用 `free_port()` **自动挑空闲**、`web_live_check.py` 按 **T-G47 已自动挑空闲**
—— 这两门**不需要也未被**端口隔离改动（保持自动挑）。

## 三、三种改法（判据）

1. **端口按树隔离**：新增可选 `TF_GATE_PORT_BASE`（不设 = 8531 段，逐字不变）；设了则
   `render=BASE`、`ui_flow=BASE+10`，由 `render_cmd()`/`ui_flow_cmd()` **构造命令行时透传 `--port`**
   （`run_gates.py` `port_base()`/`render_cmd()`/`ui_flow_cmd()`）。黄金与端口无关（见读数⑤）。
2. **开场按端口清遗留**：`cleanup_leftovers()` 在**全量档**（含浏览器层）开场跑，判据 =
   **端口段 ∩ cwd=本树根**（`gate_port_set()` ∩ `_is_our_tree()`）。只掐**本树**在本段端口上的
   LISTENING 进程、以及绑这些端口的**本树**无头浏览器（`_is_orphan_browser`：镜像名像浏览器
   **且**命令行含 `--remote-debugging-port=<本段端口>` 或 profile 名 `tf-*-profile-<端口>`）。
   **幂等 + 有读数**：打印「掐了几个 / 本来空着 / 没动的（含原因）」，不静默。
   ★ 实现里**没有**任何"按 `serve.py --fresh` 匹配就杀"（铁律 27）。
3. **pytest 限并发**：`pytest_workers()` 读 `TF_PYTEST_WORKERS`，不设时 `min(4, cpu)`（32 核 / 15.2 GB
   → 不再 `-n auto` 拉 32 个 worker）。`xdist_available()` 与「没装就串行」口径**一个字不动**。

## 四、★ 真事故（本卡自己撞出来的，反而成了双判据的来由）

**只按端口的判据不够**：默认端口段是**多棵树共用**的。我第一版实现只按端口，跑验证时把
**另一棵树（`.wt/left1`，卡 060，正握着门禁锁跑全量）** 正在跑的 `render_check` / `ui_flow`
**一起掐了**：它的 `gates/logs/render.log` / `ui_flow.log` 尾巴是 node 的
`Warning: Detected unsettled top-level await ...`，两个门都 **exit 13**（node 因事件循环空转退出），
`gates/last.json` 落成 `ok=false`。这正是病灶② 的翻版。

**修法**：加一条**树判据** —— 只掐「(近)祖先 cwd = 本仓库根」的进程（`_pid_cwd()`/`_is_our_tree()`）。
本树起的 node/serve/Edge 的 cwd 都是本仓库根；别人的树 cwd 不同 → 天然不碰。
★ **cwd 拿不到就不杀**（拒绝优于跨树误杀）。

## 五、★ 读数（先红后绿）

- **③ 清理双判据（真机，红→绿）**：
  - 红（只有端口）：掐掉了 `.wt/left1` 在本段端口上的活进程（见 §四，`ok=false`）。
  - 绿（端口 ∩ cwd）：对 left1 的活进程**全部打印「不是本树 → 不动」**（实测 `pid=23808@8531`
    `pid=17572@8542` 等 cwd 均为 `.wt\left1`，全未动）；对**本树**进程
    （`serve.py --fresh --port 8543`，cwd = 本树根）**照掐**（`AFTER 8543 = False`）。
  - 别的 BASE 段（卡 §5.4）：在 **8899** 起 `serve.py --fresh --port 8899` → 清理后**仍存活**
    （8899 不在本段端口、且 cwd 非本树）。
- **⑥ pytest 全绿**：`PYTHONPATH=… python -X utf8 -m pytest tests/ --no-cov` → **1489 passed, 2 deselected**（rc=0）。

## 六、封版读数（实测）

- **① 默认不变**（不设任何新变量，`--no-reuse` 真跑）：`gates/last.json` **ok=True、17 门**；
  `git status --porcelain -- gates/render` 空（**黄金零变动**）；`render` 45 份清单与黄金逐字节一致；
  `ui_flow` 通过；开场清理打印「本树端口段本来就空着（11 个端口都没人听）」；
  `=== pytest 跑法：并行（pytest-xdist，-n 4） ===`（新的保守默认）。
- **② 隔离生效**（`TF_GATE_PORT_BASE=8601`，`--no-reuse`）：`ok=True、17 门`；清理打印
  「BASE=8601：8601..8619 … 空」；`render` 45 份仍与黄金一致 → **换端口没让黄金变**
  （`git status --porcelain -- gates/render` 空）。
- **③ 真并行**：浏览器层两段**同时**跑（`render --port 8601` ∥ `ui_flow --port 8611` ∥
  `render --port 8701` ∥ `ui_flow --port 8711`）。t≈25s 两段端口**同时 LISTENING**：
  `8601/8602/8611/8612` 与 `8701/8702/8711/8712` 各占各的、零冲突；四个进程**退出码全 0**，
  两个 render「渲染验证层通过 ✅」、两个 ui_flow「行为流层通过 ✅ 24 条流 / 328 项断言」。
  ★ 边界：这一条是**浏览器层**双段并发；**未**在同一棵树同时跑**两个全量** `run_gates.py`
  —— 那会互写 `gates/last.json` / `reuse.json` / 同一个 `.coverage`，且违反铁律 6「重活不许并发」。
- **④ 清理不误杀**：`serve.py --fresh --port 8899`（**别段** + cwd=主树）→ 清理后**仍存活**；
  `--port 8546`（**本段** + cwd=本树）→ **被掐**。另有 §四 的真机读数：`.wt/left1` 的活进程
  （8531/8542 等）全部打印「不是本树 → 不动」。
- **⑤ 黄金与端口无关**：`git grep -l '8531' -- gates/render/` = **0**；`'8541'` = **0**。
- **⑥ pytest 全绿**：见上「读数」。

## 七、门禁怎么跑才不被 10 分钟工具上限掐（卡 §2.4）

`run_gates.py --help` 的既有开关只有 `--quick/--fast/--serial/--no-reuse/--seal`，**没有**后台/分段
开关。所以卡里跑全量门禁要**后台 + 轮询**（别让单次 Bash 调用挂着跑）：

```bash
python -X utf8 scripts/run_gates.py > gates/logs/full.log 2>&1 ; echo "exit=$?" > gates/logs/full.rc &
# 轮询 gates/logs/full.log 与 full.rc；或读 gates/last.json 的 ok/at
```

★ **建议加进卡模板**：全量门禁一律「后台跑 + 轮询 log + 读退出码文件/`last.json`」，不要
同步等（一次全量 > 10 分钟就会被工具上限掐，留下孤儿服务 = 病灶③）。

## 八、没动什么 / 边界

- **没动**：`src/**`、`docs/**`（除白名单三件）、`tools/render_check.mjs` 与 `tools/ui_flow_check.mjs`
  的**行为逻辑**（只被 run_gates 透传 `--port`，它们自己的代码零改动）、`tools/ui_dom_probe.mjs`
  （不用端口，未动）、`tests/**`（既有门禁自测无需改）、`.wt/**`、主树外来未跟踪文件、`data/`。
- **默认行为**：不设新变量时 `render_cmd`/`ui_flow_cmd` 传的仍是 8531/8541，端口/门数（17）/
  复用键/黄金/`last.json` 形状逐字不变；`pytest` 的 worker 数从 `auto` 改为 `min(4,cpu)`
  （卡 §2.3 明令的默认收紧，非"不设变量也要变"的那类）。
- **边界（如实写）**：
  1. `gates/reuse.json` / `gates/last.json` 是**每棵树各一份**（各自提交的 tracked 副本）→
     端口隔离**不会**造成跨树假复用；判据 = 这两个文件在树里是 tracked 的副本（`git ls-files`）。
  2. 端口隔离**不放松门禁锁**：`gate_lock.py` 仍是**跨树一把**（`gate_lock.py` 的 `gate_ports()`
     只让"报哪些端口忙"跟随 `TF_GATE_PORT_BASE`，串行语义不变，向后兼容）。
  3. 清理只在**全量档**跑（`--quick`/`--fast` 不起真机服务，清了无意义且可能误伤，故不碰）。
  4. 修正口径：`TF_GATE_PORT_BASE` 非法（非整数 / 越界 1024..65500）→ 打印 `[WARN]` 并退回 8531
     （不静默改端口段）。
  5. **未能**：真并行证据用**浏览器层双段并发**（见 §六 ③），**未**在同一棵树上同时跑
     **两个全量** `run_gates.py`（那会互写 `gates/last.json` / `reuse.json` / 同一 `.coverage`，
     且违反"重活不许并发"铁律 6）；`lf1_live`/`web_live` 自动挑端口，不受基段影响。
