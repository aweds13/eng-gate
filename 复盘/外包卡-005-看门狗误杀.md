# 外包卡 005 · 看门狗会误杀正常的长工具调用（台账号 `T-G94`）

> 八条铁律在你的系统提示里（以卡规格为准）。卡号 005。**这一轮只有你一个工人在主工作区
> `line/impl-v1` 上干活**（没有别的卡在跑），所以**你要自己提交**。干完按 §6 回报给主控。

## §1 背景（真机撞到的，不是我猜的）

看门狗判"卡死"的口径是「**日志静默 ≥ 480 秒 → 掐掉整棵进程树**」。它假定"一次工具调用最多几分钟"。实测不是：

- 主树全量 `python -X utf8 scripts/run_gates.py` 一次约 **4 分钟**（其中 `pytest` 一项就 110 秒）；
- 冷缓存的 worktree 里 `ui_flow`（要起浏览器）能到 **十几分钟**。

也就是说：**工人只要在卡里跑一次重门禁，就会被自己的看门狗掐掉** —— 而且掐的理由写着"卡死"，
报告里**没有**"它当时正在跑什么"，主控拿到现场还得自己翻 log 去猜。
现在只靠"工人不许跑全量门禁"这条**规矩**绕开（见 `复盘/外包-卡表与规矩.md` §16）—— 规矩只对
"卡里不跑门禁"的活有效，**不是阈值对**。这张卡就是去把阈值改对。

## §2 口径（要改成什么）

★ **关键发现（主控已经在真 log 上验过，你可以直接用）**：agent 的事件流里 **每个事件都带
`__timestamp`**（**两个下划线**，值是 ISO-8601 UTC 字符串，例如 `2026-09-26T02:39:42.910Z`），
而且 `assistant` 事件里的 `tool_use` 块与 `user` 事件里的 `tool_result` 块**一一配对**。
所以"某次工具调用跑了多久"是**可测的**，根本不用猜。
（卡 003 的 log 实测：330 个事件全带 `__timestamp`；104 个 `tool_result` ↔ 104 次工具调用。）

做三件事：

1. **识别"在飞的工具调用"**：新增 `inflight_tool(lines) -> tuple[str, float] | None` ——
   数 `tool_use` 与 `tool_result`，**没配对的**就是正在跑的。返回 `(工具签名, 已跑秒数)`；
   没有在飞的返回 `None`（秒数用那个 `tool_use` 事件的 `__timestamp` 算到"现在"）。
2. **在飞就不按普通阈值判卡死**：有工具在飞时，静默是**预期**的 —— 用新常量
   `BUSY_STALL_SECONDS`（**1800 秒 = 30 分钟**），**只有超过它**才判卡死。
3. **按实测耗时自适应**：新增 `tool_durations(lines) -> list[float]` —— 用 `__timestamp` 算
   **每一次已完成工具调用**的耗时。判卡死的阈值改为
   `max(stall_seconds, 2.5 × 已完成调用里最长的那次)`。
   这样"跑过一次 12 分钟的 `ui_flow`"之后，看门狗自动知道这活儿能跑 12 分钟。
   （乘 2.5 是留余量；取**最长**而不是平均，是宁可晚掐、不要误杀。）

★ **报告必须带现场**：判卡死时，把「最后一次工具调用是什么 / 它已经跑了多久 / 历史上最长一次多久 /
这一次用的是哪个阈值」**全写进原因里**。现在只说"X 分钟没有新事件" —— 主控还得自己去翻 log。
心跳行里**可以加**"在跑：<工具>"（有帮助），但**不要删**现有字段。

★ **一个字都不许动**：`repeat_signal()` 的空转判据（T-G88 那道）、`kill_tree()`、`cap_verdict()`、
`finish_verdict()`、`--max-turns` 口径、`detached_argv()` 与 `--detach` 那整条路（T-G92 刚修完）、
模型默认值、`--autocompact 1m`、超时默认 7200。**只改"判卡死"这一件事。**

## §5 自检 + 真机证据（都要贴输出）

```powershell
python -X utf8 -m ruff check tools/wb_dispatch.py tests/test_wb_dispatch.py
$env:PYTHONPATH = "$PWD\tools\sandbox_shim"
python -X utf8 -m pytest tests/test_wb_dispatch.py -q --no-cov
```

**单测至少覆盖（先红后绿）**：

1. 有在飞的工具调用 + 静默 600 秒 → **健康**（旧写法在这里判卡死）；
2. 没有在飞调用 + 静默 600 秒 → **仍然卡死**（证明阈值不是被一味放宽）；
3. 历史最长一次调用 300 秒 → 阈值抬到 750 秒：静默 700 秒**健康**、静默 800 秒**卡死**；
4. `inflight_tool()` 配对判据（`tool_use` 有配对 → `None`；多一个没配对 → 认出来）；
5. `tool_durations()` 算得出耗时；**缺 `__timestamp` 时不许炸**（退回空表 / 不放大阈值）；
6. 卡死报告文本里**必须出现工具名**。

★ **真机证据（这张卡的核心，别只靠单测）**：用**桩命令**证明"长工具调用不再被误杀" ——
起一个真会跑很久的桩（例如 `python -X utf8 -c "import time; time.sleep(500)"`），让 `run_worker()`
真去跑它，观察**旧口径会在 480 秒掐、新口径不掐**。为了让证据别等太久，可以用
`--stall-seconds 20` 这种小阈值把时间压缩（阈值是可配的），但要**如实写清**你是压缩过的，
别把 20 秒说成 480 秒。同时贴出：判卡死时的**报告文本**（要能看到"最后一次工具调用是什么"）。

## §7 已知的坑（主控替你踩过）

1. 一律 `python -X utf8`；pytest 要 `$env:PYTHONPATH="$PWD\tools\sandbox_shim"`。
2. ★ **时间戳键是 `__timestamp`（两个下划线），不是 `timestamp`** —— 主控第一次就读错了键，
   得到"没有时间戳"的错误结论。你直接用 `__timestamp`。
3. **别把"真睡 500 秒"的用例写进 `tests/`**（测试要快）—— 单测里构造带 `__timestamp` 的
   **假 JSON 行**即可；真睡的桩只用在 §5 的真机证据那一步。
4. **半截 log 不许炸**：日志是边跑边写的，可能出现"有 `tool_use`、还没等到 `tool_result`"
   （这正是"在飞"的正常状态），也可能 `__timestamp` 缺字段 —— 一律**退回保守行为**（不放大阈值、
   不抛异常）。
5. 提交消息用 `git commit -F gates/diag/msg-T-G94.txt`；**PowerShell 的 heredoc 会把反引号搞坏**，
   用写文件再 `-F`。
6. 看中文路径加 `-c core.quotepath=false`。
7. TOML 里**不许出现裸 ASCII 双引号**（台账 `gaps` 长文最容易踩）—— 要引用就用「」。
