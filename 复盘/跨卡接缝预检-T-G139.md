# 跨卡接缝预检 `tools/seam_check.py` —— 按「符号」取交集（卡 048 · T-G139）

## 一、为什么有这张卡（第二次撞到同类问题）

- **第一次**：两张卡抢同一个共享文件 → 定了「同域串行 + 后一张基于前一张」的规矩。
- **第二次（本卡起因）**：几张卡**文件一个字都不重叠**，但碰了同一个函数 ——
  卡 022（`5f51806`）改了 `src/timeflow/core/tasks/manager.py` 里 `_write_myday_rank` 的**签名**
  （新增 keyword-only 参数 `bump_version`）；T-G126（`803be3a`）在**另一个文件**
  `tests/test_myday_conflict_409.py` 里用 `monkeypatch.setattr(manager, "_write_myday_rank", always_conflict)`
  把它整只替换成老四参的桩。两卡各自在自己树里全绿，**集成时**全量门禁才红
  （`TypeError: 多了 bump_version` → 500，走不到 409 映射）。
- ★ 结论：**白名单只保证「文件不相交」，保证不了「契约不相交」**。所以需要一件在
  派活/排队阶段就能报警的器械 —— 按符号取交集，而不是按文件路径。

### 手工证明接缝真实存在（工具写出之前先跑，先红的一半）

```
git show 5f51806 -- src/timeflow/core/tasks/manager.py | grep 关键行 →
+    bump_version: bool = True,            （签名多了一个 keyword-only 参数）
git show 803be3a | grep 关键行 →
+    monkeypatch.setattr(manager, "_write_myday_rank", always_conflict)   （老四参桩整只替换）
```

## 二、符号怎么取（三类判据，都在 `tools/seam_check.py` 的 `extract_symbols()`）

1. **定义**：改动行里的 `def NAME(` / `async def NAME(` / `class NAME`
   （`RE_DEF` / `RE_CLASS`，`tools/seam_check.py:44-45`）。
2. **被桩替换/打补丁的对象**：`setattr(…, "NAME"` / `monkeypatch.setattr(…, "NAME"` /
   `patch(…, "NAME"`（`RE_SETATTR` / `RE_PATCH`，`tools/seam_check.py:46-50`）——
   ★ 本卡接缝正是这个形状，这条必须存在。
3. **新增/改动的形参名**：只收**打开的 def 参数表里**像参数的行（`NAME: 类型 = 默认` /
   `*, NAME`，`RE_PARAM` + 参数行守卫），并把**所在签名的函数名**一并记为「签名改动」符号
   —— ★ 关键点：`def` 行本身在 diff 里常是**上下文行**（卡 022 正是如此），
   不把形参归属到所在签名就会漏报这次接缝。
   函数体局部变量、字符串里的词一概不算（宁可少、不可滥）。

**什么时候跑**：集成前；或队列里有两张以上改同一模块的卡时。一行用法：

```
python -X utf8 tools/seam_check.py --card 022=5f51806 --card 126=803be3a
```

**输出与退出码**：三段（每卡符号 / 交集）；交集非空 → `★` + **exit 1**（必须串行或重排基点）；
无交集 → 「无交集」+ **exit 0**（将来好接门禁）；用法错/提交不存在 → exit 2。
只读：只跑 `git show`，不写任何仓库文件。

## 四、反证（三贴的第三贴：突变检验）

把「被桩替换」这一类判据整段去掉（`RE_SETATTR`/`RE_PATCH` 两行循环换成 `pass`）→ 重跑钉子①：

```
[交集] 无交集        （exit=0 —— 真接缝没报出来 = 钉子①失败，正是预期）
```

还原（`cp` 回备份，`git diff --stat` 为空 = 逐字节一致）→ 钉子①恢复 exit=1 报出交集、
pytest `5 passed`、ruff `All checks passed!`。证明「桩替换」判据是必要的，不是摆设。

## 五、碰到的坑

1. **括号计数少 1**：`RE_DEF` 把 `def NAME(` 的开括号自己吃掉了，基数按 0 算 → 签名永远
   判成「已闭合」→ 形参归属不到函数名 → 钉子①假阴。是先红（`test_common_symbol_reported`
   FAIL）暴露的，修法 = 基数 1 + 余量（`tools/seam_check.py` 两处 `1 + _paren_delta(...)`）。
2. **上下文行的 `def` 也要开签名状态**：卡 022 的 `def _write_myday_rank(` 在 diff 里是上下文行，
   只看改动行会漏掉整个签名改动 —— 状态机对上下文行同样推进，只有**记符号**限改动行。
3. **参数行守卫要够狠**：带引号（字符串）、带括号、不以逗号/星号收尾的行一律不要 ——
   真实 diff 里函数体与文档行（`"myday_rank = ?" if bump_version else …`、docstring 里的
   `bump_version=False`）都会被误当参数行。

## 六、没动什么 / 边界（如实写）

- **只新增三个白名单文件**（`tools/seam_check.py`、`tests/test_seam_check.py`、本复盘）；
  任何既有文件一个字没动（含台账 / changelog / 交接文档 / `gates/**` / `tools/wb_dispatch.py`）。
- 没跑全量门禁（卡 §0 明令）；轻门 = ruff + `pytest tests/test_seam_check.py`（5 passed）。
- 符号交集**只按名字**：不同模块同名函数会撞（假阳性方向）；跨 hunk 丢开签名状态、
  def 行内联参数不抽（假阴性方向）—— 两头都按「宁可少、不可滥」的口径接受，
  真撞到再收紧，不预作聪明。
- 形参里下标/属性链（如 `by_id[task_id].version`）取不出名字，直接跳过。
- 只读工具：不 `git checkout/add/commit`，不写任何仓库文件。
