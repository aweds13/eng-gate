# 视觉重构素材清单 · T-G24 —— 你打算重做视觉，先把"改动面"和"地雷图"摊开

> 起因：你说「之后我打算重构视觉设计，现在太平庸、太丑」。
> 我没有动任何样式（**这份是一个盘点，不是一次改版**）：把"要改的东西有多少""改的时候会撞到什么"
> 先量出来，免得你开线之后才发现"改一个颜色要动 20 处、还会撞 8 条护栏"。
> 所有数字都是脚本数出来的（命令附在 §7，可复现）；§5 那几条"我觉得平庸在哪"是**可验证的观察**，
> 不是"我觉得丑"。

## 1. 一句话结论

**"改动面"比你想的小，"会被撞到的护栏"比你想的多。**

- 改动面小，是因为 R1–R5 那次已经做过一轮接缝重构：**颜色只有一处（`app.css` 令牌区）、
  尺度只写令牌、脚本里一个色值都没有**（护栏强制）。所以视觉重构 ≈
  **改 42 条令牌 + 组件层微调**，不是"重写前端"。
- 但**护栏盯着大量中文文案与结构**：DOM 探针 14 个视图 + 11 个专项档、真机自检 **119 项**、
  前端护栏里含中文的断言 **257 处**。你改视觉时如果顺手改文案/结构，这些会红 ——
  **它们是"界面合同"不是噪音**，正确做法是同一提交里同步改，而不是删断言。

## 3. 令牌区清单（`app.css`：改视觉，九成在这里）

**颜色（亮/暗两套，`<html data-theme>` 切）**
```
--accent / --accent-on / --accent-soft     强调色 + 它上面的文字 + 浅底
--bg / --card / --line / --line-strong     背景 / 卡片 / 分隔线 / 强分隔线
--danger / --ok                            状态色
--accent-1..6                              色板（图表与分类用；JS 用 getComputedStyle 读）
```
**尺度**
```
--sp-1..11    4/6/8/10/12/14/16/18/20/24/30 px
--r-xs..pill  6/8/10/12/999 px
--fs-xs..xl   11/12/13/14/15/18 px      --fs-num/-lg/-xl  30/34/44 px（大数字）
--nav-clearance 90px   --page-bottom 60px（移动端底部 Tab 让位）
```
**没有令牌的东西（重构时的机会，也是不统一来源）**：
- **行高**：全文只出现 **1 次** `line-height`（没有令牌）；
- **字重**：只有 **4 处** `font-weight`（没有令牌）→ 标题/正文/数字的层级基本靠字号撑；
- **阴影**：只有 **4 处** `box-shadow` → 层次几乎全靠 1px 边框；
- 还有 **2 处** `border-radius` 写了裸像素（令牌化时的漏网，值本身没错）。

## 5. "平庸/丑"可能的来源（可验证的观察，不是审美判断）

1. **只有一种卡片语言**：66 个 `card` 全是"白底 + 1px 边框 + 同圆角 + 同内距"，
   层级完全靠边框 → 一屏里所有东西**权重相同**，没有"主次"（这是"平"的最大来源）。
2. **颜色只有 3 档中性色**（`--bg` / `--card` / `--line`）：没有中性色阶（没有 hover/active/disabled/
   次级文字色），大面积同色 → 缺少"呼吸"与层次。
3. **字重/行高没有令牌**（§3）：字号有 6 档，但**粗细与行距靠默认** → 标题不"立"、长文案不"松"。
4. **6 个图表各写各的**：配色、网格线、标注、留白没有统一规范（`--accent-1..6` 只是色板）。
5. **114 处内联 `style="…"`**：视觉重构时最痛的一笔 —— 你要改的样式有一半不在 CSS 里。
   （这是 R5 令牌化时**故意留着**的：它们是"一次性小间距"，但数量已经涨到该收了。）
6. **导航没有图标系统**：左栏与底部 Tab 都是纯文字按钮（14 个视图），
   在窄屏上"一排字"既占宽也没有视觉锚点。

## 6. 重构时的地雷图（会被撞到的护栏）

| 护栏 | 位置 | 撞到会怎样 |
|---|---|---|
| **颜色只能住 `app.css` 令牌区**；组件里不许写色值 | `test_web_frontend.py` 的 R1/R5 相关断言 | 在 CSS 里写 `#3b82f6` 而不是 `var(--accent)` → 红 |
| **尺度只写令牌**（`--sp/--r/--fs`） | `test_r5_scale_tokens_are_the_only_way_to_write_sizes` | 组件里写裸 `12px` → 红（离群值会被抓） |
| **`#clock` 全页唯一**（计时器唯一主人） | `test_focus_timer_has_single_owner` | 多加一个计时器读数 → 红（T-G20 时真被拦过一次） |
| **离线页排在 `/api/config` 之前渲染** | `test_mobile_offline_capture_is_wired_and_honest` | 调整渲染顺序 → 红（断网时它是唯一能开的一页） |
| **动作必须注册**（`data-action` ↔ `ACTIONS`） | 探针 + 真机脚本 | 模板写了动作没注册 → 点了没反应 + 红 |
| **视图白名单** | `test_web_frontend.py` / 真机脚本 | `VIEWS` 与 `render()` 分支不一致 → 红 |
| **中文文案断言**：探针 21 处 `includes(中文)`、真机自检 **119 项**（109 处中文键）、前端护栏 **257 处含中文断言** | `tools/ui_dom_probe.mjs`、`tools/web_live_check.py`、`tests/test_web_frontend.py` | 改了文案**又不改断言** → 一片红 |
| 探针 14 视图 + 11 个专项档 | `tools/ui_dom_probe.mjs` | 视图结构大改（换容器/类名）→ 档里的 needle 失配 |

> **怎么对待这些红**：它们是**界面的合同**（写着"这个按钮必须有""这句话必须说"）。
> 正确的做法是**同一提交里同步改断言**（改文案就改断言），而不是删掉。
> 如果某条断言你**故意不想要了**（比如某个说明文案不再出现），
> 那就等于改口径 —— 按项目规矩：写进台账 gaps / 复盘，别默默删。

## 8. 我建议的重构路径（三步，每步都能单独验收 / 单独回退）

| 步 | 做什么 | 为什么先做 | 代价 |
|---|---|---|---|
| **0（半天）** | **先收 114 处内联 `style`**：把"一次性小间距"归进 `--sp-*` 令牌或类 | 不先做，后面每一步都要在"CSS + 内联"两处改样式 | 机械但有量；改完视觉应**零变化**（可用"解析后像素多重集合"对比，R5 那次就是这么验的） |
| **0.5（T-G26 新增）** | **先过可用性门**：把亮色那 9 对不达 AA 的对比度修到 PASS（徽标里改用正文色写字、强调色不做小字、`--accent-on` 与 6 个预设配对） | 它是**缺陷不是审美**（最糟的完成徽标 **1.96:1**），而后面每一步都在改颜色 —— 先钉住"读得清"免得返工 | **已经有工具了**（T-G27）：`python -X utf8 tools/contrast_audit.py` 量 42 条组合，亮色**实际 18 条**不达标、逐条登记在 `tools/contrast_baseline.toml`（**那份就是这一步的工单**，修一条删一条）；它已接进门禁（第 12 项），改坏了会红 |
| **1（1–2 天）** | **建层次语言**：中性色阶（次级文字/悬停/禁用）+ 卡片层级（阴影/边框/底色三选一，定一套） | 这是"平"的主因（§5-1/2） | 会动到令牌与组件层；改完要跑探针 + 真机自检（文案不动 → 断言不该红） |
| **2（1–2 天）** | **排版节奏 + 图表规范**：`--fw-*` / `--lh-*` 令牌；6 个图表统一配色/网格/标注/留白 | 标题立起来、数据看得清 | 图表是手写 SVG：改的是几何与配色，**不动数据来源**（数字仍由后端算好） |
| **可选** | **图标系统**（左栏/底部 Tab/动作按钮） | 窄屏最受益 | 新增依赖要谨慎（本项目**前端零依赖**是条既有约定；建议内联 SVG，不引图标库） |

**别动清单**（这几条不是"审美"，动了会坏东西）：
1. 离线页的渲染顺序（断网时唯一能开的一页）；
2. `#clock` 的唯一主人地位（计时不丢）；
3. `data-action` + `ACTIONS` 注册表（事件委托是"可测试"的基础）；
4. 颜色只住令牌区、尺度只写令牌（R1/R5 的成果，也是重构能"一处改全局"的前提）；
5. 事实/解读分离、数字都由后端算 —— **视觉重构不碰数据口径**（换皮不换账）。
