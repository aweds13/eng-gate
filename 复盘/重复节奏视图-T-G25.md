> `SR-F1.5b`（N9）的规格原话是：「重复任务到点按上次完成自动生成下一次；**节奏可用时间热力图管理**」。
> 前半句第 5 步就做完了（`process_repeats` + `task.repeat.generated` 幂等 + 血缘）；
> 后半句一直挂着 `partial`，gaps 写着「热力图是「天 × 指标」，没有按任务/重复节奏的视图」。
> 本条把它做掉（夜班第 4 项；也把 GOAL 里最后一件没做的收了）。

## 一、先想清楚"节奏"到底是什么（这一卡的关键不是画图）

看到规格那句，最容易的做法是：**按周期推算日历** —— "每 3 天一次，那从今天往后画格子"。
**那个做法是错的**，理由很实在：

- 周期是「**每 N 天**」，锚点是"上次完成时间"，所以**它本来就会漂**（早做一天，下一轮就早一天）；
- 一旦按"应该哪天"推算，图上会出现一堆**从来没排过**的格子 —— 那就是我在替用户的日历编数字；
- 而用户真正想知道的是："**我这件事的节奏到底怎么样**"（哪几天真做了、哪些排了没做）。

所以这条投影的口径定成：**只用已经发生过的事实** ——
每个轮次的 `due_date` 就是**真实排过的日子**，那天做没做看那一轮现在的状态。
**不预测、不补格、不算"达标率"**。

## 二、实现（三层，各管一件事）

| 层 | 位置 | 做了什么 |
|---|---|---|
| 领域（任务） | `tasks/manager.py::repeat_tasks()` | 取所有设了重复的行（按排期日排序）—— SQL 留在任务域，`insights` 不猜字段 |
| 投影 | `insights.repeat_rhythm(conn, days=56)` | 按 **(标题, 周期)** 归成一条节奏；窗口内每一轮 → 一格 |
| 接口 | `GET /api/insights/repeat-rhythm?days=` | 1–180（默认 56 = 8 周）；非法 400；连口径说明（`note`）一起返回 |
| 界面 | 统计页「重复节奏（近 N 天）」 | 一条一行：标题 + 「每 N 天 · 完成 K / 排期 M」+ 逐日方格 |

**三种格子状态**（形状 + 颜色都不同，不只靠颜色 —— 色觉差异也读得出来）：

| 状态 | 画法 | 含义 |
|---|---|---|
| `done` | 实心（`--accent`） | 那一轮做完了 |
| `missed` | **空心**（描边 `--accent`） | 排了，还活着但没做 |
| `off` | 淡灰（`--line`） | 取消 / 搁置 / **归档但没完成** |

**两条容易做错的判定**：
1. **归档 ≠ 做完**：`archive_task` 不要求先完成（未完成的也能归档），所以"归档"这一状态
   只有在**有 `task.completed` 事实**时才记 `done`，否则记 `off`。这一条单独有用例钉着。
2. **被彻底删除的轮次不进图**（它已经不是排期了）；软删除（已删）同样跳过。

## 三、界面上的克制（约定层：温和不施压）

- 只给两个数：**完成 K / 排期 M** —— 不给百分比、不给"达标率"、不画目标线
  （前端护栏里直接断言这三个词不许出现）。
- 说明文字**由后端给**（`note`），界面只 `esc()` 显示 —— 改口径只改一处（与守卫/局域网那套同款）。
- 空态走统一的 `emptyState()`：「还没有重复任务：给一件事设个「每 N 天」的重复，这里就会长出它的节奏」。

## 四、验证

| 层 | 查什么 | 结果 |
|---|---|---|
| 单测 `tests/test_repeat_rhythm_line.py`（13 条） | 一格里三种状态、归档未完成不算做完、删除的轮次不进图、无排期日不进图、窗口裁剪、同标题不同周期拆两条、days 夹取、API 形状与 400 | ✅ |
| 前端护栏 `test_repeat_rhythm_view_is_wired_and_kind` | 统计页真接投影 + 空态 + 三种画法 + 只给两个数 + 温和措辞 + 说明用后端的 | ✅ |
| DOM 探针（统计页那档扩了） | 真渲染：段落标题、两条节奏的「完成/排期」、**三种格子状态的提示文字都在**（只画完成格会被抓） | ✅ |
| 真机自检 6 条 | 真 HTTP：空表不报错 / 一轮做完一格 done / 排了没做一格 missed / **只画真实排过的日子** / 不重复的任务不进图 / days=0 → 400 | ✅（119 → **125 项**） |

## 五、遗留

1. **跨设备合并**：同步包按行搬，标题+周期相同仍会归成一条 ✅；但"两台机器各生成了一轮"
   这种重叠没有单独验过 —— 记在这儿，别当已验。
2. **样式**：本卡复用现有 SVG 方格与令牌（没引新视觉语言）—— 视觉重构那轮统一时，
   它跟着 `app.css` 的令牌一起变（`复盘/视觉重构素材清单-T-G24.md` §8 的"图表规范"那一步）。
3. `SR-F1b.5b` 那半句的"管理"目前是"看得见 + 如实标"：**没有**做"点格子补做/改排期"这类动作
   （那会引入新口径：补做的完成日算哪天），要的话另开卡。
