# 门禁四要素（**人话版**）· 每一道门：防什么 / 怎么算过 / 花多少秒 / 红了怎么办

> **为什么有这一页**：用户 2026-09-28 点名「**黄金**之类的无聊词」「**审美门**」—— 门禁里的黑话
> 让人（尤其是我自己隔几天再看）**读不懂它在防什么**，读不懂就会绕过它、或者红了乱改。
> 所以逐门给四要素，并**把术语换成大白话**。★ 这一页是**说明**，不是判据；判据在代码里，**唯一真源**是
> `scripts/run_gates.py` 的门清单 + `gates/last.json` 的结论。
>
> **秒数**取自这台机器的实测（`gates/last.json` 的几趟：其中 `render`/`ui_flow`/`pytest`/`*_live` 是**真跑**的读数，
> 另外几趟它们会**命中复用**、秒数是 0 —— 见下面「复用」那条）。跑一趟全量门禁的**墙钟**约 **6~10 分钟**
> （轻门 15 道并行 ∥ 真机浏览器 2 道串行）。

## 一、术语对照（左边是黑话，右边是人话）

| 黑话 | 人话 |
|---|---|
| 门禁 / 门 | 提交前那套**自动检查**；一道「门」= 一项检查 |
| 黄金 | **基准**。渲染层的版面清单（`gates/render/*.txt`），改界面就得对着它逐字节比 |
| 审美门 | **观感检查**（对比度、风格一致性、文案长度）—— 不是"好看不好看"，是"有没有踩硬线" |
| 假红 / 假绿 | **误报 / 漏报**。红了但其实没事 = 假红；绿了但其实没查 = 假绿（更坏） |
| 复用 | **抄上次的结论**：这道门的输入一个字节没变 → 采信上次的"通过"，这趟不重跑 |
| 封存 / 封存指纹 | **落章**。把「这一趟验的是哪份内容」记成一个哈希写进 `gates/last.json`，提交后能反查 |
| 泳道 | **并行跑道**。轻门 15 道并排跑，真机浏览器那 2 道**自己内部串行**（两个真浏览器一起抢资源会假红） |
| 台账 | `docs/traceability.toml` —— 这个项目的**唯一真源**：每张卡的编号、状态、证据、缺口 |
| trailer | 提交信息末尾那几行 `Task:` / `Refs:` / `Ledger:` / `Gates:` |

## 三、四条所有人都该知道的判据（今天现踩的）

1. **「复用通过」≠「这道门现在是绿的」**：`reused` 只说"输入没变、采信上次"，**不说这趟跑过**。
   自己动过的那道门（或它的输入）**必须 `--no-reuse` 真跑**再提交。
2. **门禁红了一律不提交**（本仓铁律）。红了先分类：**每趟挂同一条 = 时间敏感**；**每趟挂不同条 = 竞态**；
   **报错像工具自己崩了**（比如 `AttributeError`）→ 先当成"**工具脆**"查，别急着改被测代码。
3. **别裸跑门禁**：`run_gates.py` 给每道门**没有超时**（截至 2026-10-01，卡 100 正在补），实测 `ui_flow`
   真卡死过 **56 分钟**。自己跑一律套 `timeout 1800`。
4. **红的门单独重跑**：`python -X utf8 scripts/run_gates.py` 没有"只跑一道门"的开关，但每道门都是**独立命令**
   （`ui_flow` = `node tools/ui_flow_check.mjs --port <BASE+10>`；`pytest` = `python -X utf8 -m pytest`），
   照门里的同一条命令单独跑一遍即可（日志在 `gates/logs/<门名>.log`）。
