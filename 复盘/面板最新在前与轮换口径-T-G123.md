  卡号小的在前、刚跑的卡沉底，同卡轮次旧的在前。

  - **组**（同树 + 同卡）按**组内最新 mtime 降序** —— 刚动过的卡在最上面；

  `-latest[(e[0], _split_card(e[1])[0])]`
- 只改整体行序与两处 docstring；行模型、列、状态带口径、续跑合并、只读原则一个没动。

## 6. 边界（如实写）与没动的

- **稳定次序**：等值 mtime →（树名, 卡号）升序；组内各轮只看**轮次号**（单调、且 ctime 在 Windows
  上不可靠，T-G113 已钉过）、不看各轮自己的 mtime。
- **口径变动**：T-G93 行模型/多树粒度、T-G113 一行一轮/同卡相邻/「第 N 轮」标识**没动**；
  只把 T-G113 的「组内轮次升序」改成「轮次新的在前」—— 这是本卡 §2.1 用户明令。
- **面板要重启才生效**：常驻进程不会热加载，用户那边 8787 那份需要重启才能看到新行序（本卡没做热加载）。
- **没跑全量门禁**（卡 §0.3，主控集成时跑）；只跑了 ruff + 本测试文件 + 真机核对 + 突变检验。
- 中途两个环境坑（与代码无关）：Git Bash 里 `*>` 不是 PowerShell 的重定向、`*` 会被当 glob
  展开传进 argparse —— 第一次起 8788 就这么失败了一次（面板根本没起来），改 `> file 2>&1` 后成功；
  另有两次 Edit 撞 Windows 文件锁（EBUSY），重试即过。
- **没动的**：行模型/列/状态带口径/续跑合并/只读原则；`tools/wb_dispatch.py`、`tools/wb_watchdog.py`、
  `tools/wb_status.py`；`src/**`、`scripts/**`、`docs/**`、其它 `复盘/*.md`、`gates/**`、
  三个外来未跟踪文件；真实库与真实备份目录。
