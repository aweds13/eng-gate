# 复盘 · Obsidian 跳转 + 把红线做成"拦得住"的规则（T-G5）

> 性质：**功能落地 + 口径复盘**（要什么 / 摆在桌上的歧义 / 怎么定的 / 怎么落地的 / 边界与教训）。
> 上游：G 批 · T-G4（沉淀型 md 与"数据库权威"）+ `复盘/口径定案-待定清单.md` §7（2026-09-21 用户定）。
> 结果：引用句柄（复习卡 / 备忘）能一键跳进 Obsidian；红线 `SR-F8.2` 从"文档里写着"变成**三处拦得住**。

---

## 一、这一卡要解决的问题

`复盘/口径定案-待定清单.md` §7 把沉淀型内容分成两类，其中 **B 类（备忘录 / 温故知新产出）**
用户的原话是：

> 备忘录、温故知新产出这类**直接调出 obsidian**，或者**我写完你存到我指定的地址**。

后半句 T-G4 已经落地（每天一个 md 落到独立目录）。**前半句当时做不到**：复习卡与备忘上挂的
`ref_handle`（引用句柄：Vault 相对路径 / KB-ID）在界面上**只能看着**，点不了 ——
用户手上只有一个字符串，还得自己去 Obsidian 里找。

同时这次落地顺手处理第二件事：**红线只写在文档里是不够的**。

> `SR-F8.2`：不得**直接写外部知识资产库（Obsidian 笔记、知识管理的 PDF/KB）**。

T-G4 的代码注释里写着"不碰 Obsidian 的 vault"，但那是**约定**，不是**机制**：只要用户在设置页
把导出目录指到 Vault 里（或者 `config.toml` 里写歪），程序会**老老实实往里写**。
"靠我记着别写进去"不叫实现了一条红线。

## 二、摆在桌上的歧义（先定清楚才动手）

| 歧义 | 怎么定的 | 为什么 |
|---|---|---|
| 跳转要不要写 Vault？ | **只读跳转**，一个字节都不写 | 红线；用户要的是"调出来看"，不是"让 timeflow 管理笔记" |
| Vault **名字** vs **根目录** | 两个都配，但**用途不同** | 名字是协议要求的（`obsidian://open?vault=`）；根目录只用来把**绝对路径**句柄换算成库内位置 |
| 根目录不存在时 | **拒绝保存**（400 带原话） | 软件**不会替你在 Vault 里建目录** —— 那本身就是"动知识资产库"；而且建不出来就说明路径填错了 |
| 句柄不在 Vault 里 | **不跳**（并说明原因） | Obsidian 会按名字去找同名文件 → 可能打开**另一个**东西，等于指错路；宁可明说"这个路径不在 Vault 里" |
| 没配 Vault 时界面 | **不摆按钮**（不给"点了没用"的按钮） | 摆了就变成"报错按钮"：用户点一下只得到一句"还没填 Vault 名字" |
| 跳不起来时 | **必须出声**：原话 + 复制链接兜底 | 与 T-B4 的附件打开同一条规矩（失败不许静默） |
| 导出目录落在 Vault 里 | **三处都拦**（见下） | 红线要机器拦得住，不能靠人记得 |

## 三、落地（怎么做的）

### 3.1 拼 URL：逐段编码，句柄不许夹带参数

`core/vault.py` 的 `obsidian_url(vault, file)`：

```python
segments = [quote(s, safe="") for s in file.split("/")]
return f"obsidian://open?vault={quote(vault, safe='')}&file={'/'.join(segments)}"
```

两个细节都是刻意的：

- **`/` 保留**：Obsidian 认的是"库内路径"，把分隔符也编码成一长串 `%2F` 就不是路径了；
- **段内字符全编码**：句柄里出现 `&`/`#`/空格时，`&file=` 之外**不会**多出协议参数 ——
  否则用户随手粘一个带 `&` 的标题就能把跳转目标换掉（`test_url_encodes_so_handles_cannot_smuggle_parameters`
  断言 `?` 与 `&file=` 各出现一次）。

### 3.2 句柄换算：相对路径直接用，绝对路径必须在库里

```python
def to_vault_file(handle, vault_dir) -> tuple[str | None, str]:
    # ① 相对句柄（notes/数学.md、KB-1234）→ 直接用；含 `..` 一律拒绝（不许借道跳出 Vault）
    # ② 绝对句柄 → 必须填了根目录，且 resolve() 之后要落在根目录之内，否则给原话
```

**换个说法**：根目录不是"多一个配置项"，而是"承不承认这个句柄对不对"的唯一依据 ——
没有它就没法判断"这个绝对路径到底是不是库里的东西"，那就**不能冒然跳**。

### 3.3 红线机器化（三处）

| 时机 | 拦什么 | 用户看到的 |
|---|---|---|
| 保存导出目录（`set_dir`） | 新目录落在 Vault 里 | 400：「导出目录不能放在 Obsidian 的 Vault 里…换一个与 Vault 分开的目录」 |
| 保存 Vault 根目录（`set_vault`） | 新根目录把**现在的**导出目录包进去 | 400：「这个 Vault 根目录把现在的导出目录包进去了…先把导出目录换到 Vault 外面」 |
| 真正写文件前（`export_day`） | 配置里就重叠（不是从界面设的） | 手动导出 400 带原话；自动导出只记 `export.last_error`（**不挡"完成任务"**） |

第三条是关键：**前两处只是 UI 路径上的校验**，`config.toml` 里写歪、或者将来多一个写入口，
就绕过前两处了。所以落盘前再判一次 —— 这一条才真正把红线变成了**不变量**。

另外 `describe()` 会算出 `vault_overlap`（配置里就重叠时给一句告警），设置页标红显示：
**不假装没这回事**。

### 3.4 界面

- 设置页「导出（Markdown）」里加一小节「Obsidian（只读跳转）」：Vault 名字 + Vault 根目录 + 保存 +
  现状（"已填：MyVault · 根目录 …" / "还没填…"）+ 重叠告警 + 只读口径；
- 复习卡与备忘录：**后端给了 `ref_url` 才**渲染「在 Obsidian 打开」；句柄那行带 `title`，
  鼠标停上去能看见"为什么这条跳不了"（没配 Vault / 路径不在库里 / 有 `..`）；
- 点击 → `POST /api/vault/open` → 成功 toast「已在 Obsidian 打开」；失败 → **复制链接 + 说原因**。
- **URL 只在后端拼**：界面里不出现 `obsidian://` 字面量（`test_obsidian_jump_is_wired_and_read_only`
  把这条钉住）—— 编码口径与相对路径换算只能有一处，否则两边早晚不一致。

### 3.5 顺手修掉的显示问题

设置页的说明文字是后端一处写的，里面用 `**重点**` 标重点，而界面一律 `esc()` → 屏幕上出现
一堆**字面星号**（T-G4 的「**数据库是权威，md 是产物**」就一直这么显示的）。
新增 `noteHTML()`：**先转义再只认 `**`**（说明文字也走防注入那条路），导出/Obsidian 三句说明
现在是真的粗体。

## 四、边界（诚实清单）

1. **能不能真的唤起 Obsidian，取决于你的机器**：装没装 Obsidian、`obsidian://` 协议有没有注册。
   本沙箱没有 GUI，自动化只能验到"URL 拼对了 / 交给系统了 / 交不出去会出声" ——
   **这一条要你在自己机器上点一次**（见 §五）。
2. **不写 Vault 只做到"我们这个程序不写"**：读它的清单不变这条有测试钉着；
   但 Obsidian 自己在跑，它的插件会写什么是另一回事（不在本项目范围）。
3. **KB-ID 这类非路径句柄**：当成"库内相对路径"直接交给 Obsidian。是不是真的存在由 Obsidian 说了算 ——
   我们不做全库索引（那等于把 Vault 读进来，超出"只读跳转"的必要范围）。
4. **Vault 根目录填了就必须存在**：U 盘/移动硬盘上的库没插着时保存会失败（如实报错，不静默降级）。

## 五、请你在自己机器上验一次（3 步）

1. 设置 → 「Obsidian（只读跳转）」：填 **Vault 名字**（Obsidian 里显示的那个库名）
   + **Vault 根目录**（库文件夹路径）→ 保存（应显示"已填：…"）；
2. 随便给一张复习卡或一条备忘填个**库内真实存在的**引用句柄（如 `notes/数学.md`）→
   点「在 Obsidian 打开」→ 应当真的跳到那篇笔记；**同时看一眼那篇笔记有没有被改动**（不该有）；
3. 反着试一次：把导出目录填成 Vault 内的某个子目录 → 保存 → 应看到 **400 + 一句原话**
   （这就是红线在起作用），把它改回 Vault 外面就恢复正常。

## 六、教训

1. **"文档里写着"和"程序拦得住"是两件事**：红线要么做成校验，要么等于没有 ——
   这次把 `SR-F8.2` 落在了三个时机上，其中**落盘前那一次**才是真正的不变量。
2. **能自动跑的断言要盯"数据对不对"，不是"界面有没有"**：探针这次除了正向（按钮/两栏/口径都在），
   还加了**反证**（把 `ref_url` 抽掉后按钮必须消失）—— T-G3 的教训（只断言"渲染出来了"会漏）
   在这一卡里直接变成了写法。
3. **转义与"富文本"的顺序**：要支持 `**粗体**`，必须**先转义再贴标签**；反过来就是把说明文字
   当 HTML 执行（说明文字同样是外部输入）。
