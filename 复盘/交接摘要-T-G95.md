## 1. 为什么有这张卡（主控写的背景）

主控每收一张卡，最贵的开销**不是复核**（`tools/wb_review.py` 一条命令 5 秒），而是**读工人那一轮的
原始事件流**：卡 005 那轮是 `gates/diag/wb-005.jsonl`，**264 行 / 316 KB**，而他要的东西（工人的
六项回报 / 判决 / 工具与文件计数）**只压在它末尾**。读一次上万 token，纯浪费。

**要做的**：让派活器**自己在收工时**落一份 1~2 KB 的摘要，主控只读它、**永远不必再碰 jsonl**。

## 2. 做了什么（口径按卡规格）

### 2.1 `write_report(...)` → `gates/diag/wb-<卡>.report.md`

`write_report(log, *, card, code, reason, scene, sid, attempts, lines, started_at)`，输出结构按卡规格
固定：判决 / 会话 / 开始结束与用时 / 回合·工具·文件·报错 / log 行数字节数 → **`result` 事件回话原文**
→ **最后 10 次工具调用** → 机械读数（未提交文件数 / `gates/last.json` 的 ok·rev / 复核命令模板）。

★ **口径复用现成的、不写第二份**：回合数走 `turns_seen()`、工具签名走 `tool_signatures()`、
log 摘要走 `wb_status.parse_events()`。只新加了一个 `result_event_text()` —— 因为 `parse_events()`
里的 `final` 是**截断过**的（400 字 + 空值退回 subtype），而卡要的是**原样搬运**工人的回话。

### 2.2 每一条退出路径都落一份

收工 / 被看门狗掐 / 超时 / 撞 `--max-turns` / **重试的每一轮** 都调它。文件**按 log 名派生**
（`report_file_for()` = `log.with_suffix(".report.md")`），所以：
- 第 1 轮 → `wb-<卡>.report.md`
- 重试第 2 轮 → `wb-<卡>.r2.report.md`（**不覆写**上一轮 —— 与"每轮一个 log、证据不互相盖"同一口径）

★ **这是"覆写还是另存"那个选择**（卡里让我定）：选**另存**，并在
`test_a_retry_round_gets_its_own_report_not_an_overwrite` 里钉死。
另外**前置检查没过**（`--detach` 前四道检查挂了）那条路也落一份（判决写「前置检查没过 → 没派活」）——
卡说"每一条退出路径"，这条也算，且 `--status` 因此对"没派活"也看得见。

### 2.3 `--status` 指向摘要

`status_report()` 在摘要存在时多打一行 `[摘要] gates/diag/wb-<卡>.report.md（先看它）`，
放在最前面（主控先看它）。

### 2.4 顺手修**块缓冲**（T-G93 记录在案，主控撞了三次）

- 进度 `print(...)` 全部加 `flush=True`；
- `detached_argv()` 给解释器补 `-u` —— ★ **只加这一个参数**，输入里已有的 `-u` 也去重，只留恰好一个。

## 6. 边界（如实写：没做的、没动过的）

- `write_report` 的签名按卡规格带 `scene`，输出结构也按规格固定；**现场只在被掐 / 超时**（`scene` 非空）时
  多出一节 `## 现场`，正常收工不占地方。
- 「最后 10 次工具调用」复用 `tool_signatures()` 的 `名字|参数JSON`，再裁到 120 字 —— 没另写事件解析器。
- 未提交文件数走**全量** `git status --porcelain`（含未跟踪文件）—— 与 preflight 的 `-uno` 口径不同，
  因为这里要的就是"工作区现在有多少东西没提交"。

- `--status` 只指**最新**那份摘要（按 mtime）；重试轮更新时指 `.r2`，前几轮仍在磁盘上。
- 真机证据用的是**桩 CLI**（不是真 deepseek）；它证明的是**机制**（detach → 落摘要 → dispatch.log 非 0 →
  `--status` 指摘要），**不证明**真模型这一轮的产出质量。
