## 二、关键取舍（当时怎么想的）

### 2.1 切分顺序：先口径、后图形
第 7–9 步始终遵守「**后端只出数据、前端出图形**」（取自 `复盘/写法参考-feat-ui-refactor分支.md` 的取向），
但**不沿用它的口径**——它的 `daily_insights` 读 `focus_sessions.status='finished'`，
而那正是"开始即 finished"的旧状态机耦合。本线全部改为**只读 facts**，与 `ledger.summary()` 同源。

### 2.2 三处"不归一"的坚持（都是避免造假）
1. **分组分布不归一**：任务可属多分组 ⇒ 各组之和可能大于总投入。没有强行按比例缩放，而是在界面上注明"可重复计数"。
2. **未绑定专注不计入分组**：否则会凭空出现一个"未分组"大头，把分布图变成假的。
3. **债务时间热力图 = 当日快照**：是"那天欠多少"，不是"当天新增债务"。这两个含义差别很大，在契约里写清了。

### 2.3 温和口径做成可测约束
`steady_note`（周结算）与热力图空态文案都不允许出现"目标/应该/警告/失败/落后"——
**在测试里直接断言这些词不得出现**。把"温和不施压"从口号变成回归测试，
是因为这类语气最容易在后续迭代里被无意改回"打鸡血"。

### 2.4 复用而非复制
`heatmap()` 与 `daily_insights()` 共用同一个 `_cell()` 取数。
理由：两处图表若各自实现取数，将来改投入口径时**必然悄悄不一致**——这类静默漂移比崩溃更难发现。

### 2.5 不做的事（同样重要）
- 没有为了实现可视化而引入任何前端图表库（SVG 手写，保持零依赖）。
- 没有为 `OP-24 学校任务↔课程合流` 顺手加 schema 字段（超出当步范围，改为显式标注未实现 + 用分组暂代）。
- 没有做 `OP-33 团队视角切换页`（分配信息直接挂任务卡片，对个人使用更省事）。

## 三、踩到的坑与修正（值得记录）

### 3.1 层检查抓到我自己写的花括号简写
在 `docs/changelog.md` 里写了 ``docs/implementation/{modules,architecture,...}.md``，
`scripts/check_layers.py` 判定为**引用断裂**并 FAIL。改回逐条写全路径。
→ **教训**：护栏对文档里的路径是"字面解析"的，简写会被当成真实引用。

### 3.2 测试发现了生产代码的真 bug（第 10 步）
写"同步状态"测试时连记两条冲突，触发 `sqlite3.IntegrityError`：
`sync.log_conflict` 原来**拿秒级时间戳当主键**（`_now_iso()`），同一秒两次冲突即撞键。
→ 冲突日志正是"不静默覆盖"依赖的留痕机制，写不进去等于静默。
→ **修正**：改随机 id，并在代码注释里标注来源。**教训**：把"可观测面"补上时，往往会顺带发现被观测对象本身的问题。

### 3.3 早期误判（本会话之外，但值得留档）
更早的窗口里我曾把"重构第 3 步"表述为"旧数据迁移"，实际做的是 **schema v5：历史已完成任务回填 facts**
（计算型内部迁移）；而 conventions 说的"沉淀型内容落 Markdown"是**另一件事**，至今未开工。
→ 已在交接文档里纠正命名，避免下个窗口误以为"第 3 步已完成"。

### 3.4 环境层坑（会持续影响每个窗口）
本沙箱下 `os.mkdir(mode=0o700)` 会被立刻拒绝访问（pytest `tmp_path` 用它），
导致几乎所有用例 setup 报 `PermissionError`。垫片 `tools/sandbox_shim` 解决；
另：pytest 自建 basetemp 目录事后不可删，`.gitignore` 已登记。
→ **教训**：质量门红先判"环境 vs 代码"，不要急着改代码。

## 五、给下一个窗口的建议

1. **下一步优先级**：前端（NF1/NF4）> 未实现项收口 > 跨端同步传输 > 沉淀型 Markdown（后者需产品决策）。
2. **动前端前先读** `复盘/前端现状评估与接缝重构方案.md`：那里有实测数据（735 行 / 7 变量 / 22 处 hex / 56 处内联事件）
   与分阶段方案（R1 抽 CSS → R2 抽壳与状态 → R3 三栏 → R4 暗色 → R5 收尾）。
3. **动前端前先把烟测加厚**：`tests/test_web_frontend.py` 目前只查字符串存在，**发现不了交互被改坏**。
4. **保持零依赖**：不引框架/打包器/图表库；新增可视化继续走"后端出数据、前端手写 SVG"。
5. **口径只有一个出口**：任何"投入/产出/复习/债务"的数字都必须来自 `facts`（经 `ledger` 或 `insights`），
   不允许视图层自己聚合业务表。
