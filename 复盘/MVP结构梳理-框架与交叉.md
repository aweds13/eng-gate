# 复盘 · MVP 结构梳理：一框架 × 多线 × 多交叉 × 多节点

> 阶段：Intent 重读后的**结构复盘**（接《任务复盘-全程》）。
> 依据：`docs/intention/needs.md`（N1–N46 全文，逐条核对）。
> 目的：解释"功能只做一半"的**结构性原因**，并据此理顺 MVP 的切法。
> 结论先行：**现在的实现是"按线的清单"做的，但框架与交叉没人负责。**

## 一、intent 的真实结构

用户指出的「一个框架下多条线与多交叉与多节点」，在 intent 里是可精确指认的结构——**这不是修辞，是 needs.md 的组织方式**。

```
                    ┌──────────────────────────────┐
                    │  框架：债务/储蓄账本（唯一）      │
                    │  投入轴 / 产出轴 / 欠账          │
                    │  「贯穿」：逾期=债务、专注=投入   │
                    └──────────────▲───────────────┘
                           ↑ 每条线/每个交叉都必须向其落节点
   ┌───────────┬───────────┬───────┴───┬───────────┬───────────┐
   │ 线1 任务   │ 线2 专注   │ 线3 学业  │ 线4 复习   │ 线5 反馈   │ …
   └─────┬─────┴─────┬─────┴─────┬─────┴─────┬─────┴─────┬─────┘
         └───── 交叉（线之间的强制咬合点）─────┘
                    ↓
              节点（框架里的账目条目）
```

### 1.1 【框架】— 1 个

> **N3 债务/储蓄记账（贯穿核心）**

- 它是**度量衡**，不是功能：一切都要被换算成「投入 / 产出 / 欠账」。
- **横切所有线**：不是"一个模块"，而是"所有模块都必须向它汇报"。
- intent 原话：「**贯穿**：逾期任务=债务；专注投入=储蓄；完成悬赏=收益/储蓄；复习逾期=轻度债务」。

### 1.2 【线】— 7 条（每条是一个业务流）

| 线 | intent 出处 | 骨架 |
|---|---|---|
| **线1 任务线** | C（N6–N11, N45） | 建任务 → My Day → 逾期/处置 → 完成 |
| **线2 专注线** | E（N15–N17） | 开始计时 →（绑定任务）→ 中断三选 → 结束 |
| **线3 学业线** | F（N18–N21） | 课程档案 → 考核项 → KPI 单 → 漏考提醒 |
| **线4 复习线** | H（N26–N29） | 建卡/升级 → FSRS 调度 → 到期 → 三态反馈 → 推进 |
| **线5 反馈线** | D（N12–N14） | 每日计划 → 执行 → 差距 → 自检 |
| **线6 协作线** | C·N46 + G·N23 | 管理者/执行者 → 分配 → 回报 |
| **线7 备忘录线** | G·N24 | 随手记 →（顺手建任务）→ 引用句柄 |

### 1.3 【交叉】— 11 个（线与线的强制咬合点）★最关键

intent 中凡出现「**贯穿**」「**自动计入**」「**联动**」「**合流**」「**升级**」处，都是交叉：

| # | 交叉 | intent 原话 | 性质 |

| C4 | **任务逾期 × 框架** | N45「与 B 系统联动（逾期=债务）」+ 强度分档 | 分级 |

### 1.4 【节点】— 交叉产生的账目条目

| 节点 | 触发 | 落点 |
|---|---|---|
| 逾期节点 | 任务到期未完成 | 债务（天数/程度/强中弱） |
| 专注节点 | 专注结束 | 投入（时长） |
| 完成节点 | 任务完成 | 投入/收益 |
| 复习节点 | 复习完成/温故知新 | 投入 +（可选）产出 |
| 成绩节点 | 成绩录入达标 | 产出（KPI） |
| 知识资产节点 | 手动/评价器 | 产出（资产） |
| 习惯节点 | 打卡 | 纳入同套可视化 |

## 二、结构性诊断：为什么"功能只做一半"

**现在的实现按「线的清单」组织**（`modules.md` 按 SR-F1~F10 分模块 ≈ 按线切），**但框架与交叉没人负责**：

| 结构成分 | 现状 | 后果 |
|---|---|---|
| 7 条**线** | ⚠️ 大多只做了骨架 | 每条线"看起来有" |
| 1 个**框架**（N3） | ⚠️ `ledger.py` 只算「债务+今日投入」；**产出轴仅空表，无写入** | **框架没立起来** |
| 12 个**交叉** | ❌ **基本全断**（专注不记账、完成不记账、复习不记账、成绩不记账） | **线是"孤线"** |
| N 个**节点** | ❌ 大多无写入 | **框架收不到数据** |

**一句话**：7 条线各自"有半条"，交叉全断 → 框架（唯一真正重要的差异化价值）收不到数据 → **"看起来什么都有，但什么都没串起来"**。

**这才是"多交叉"的真身**：不是"模块之间要通信"，而是**每个业务动作都必须在框架上落一个节点**。

## 三、据此理顺 MVP

**MVP 不是"砍掉几条线"，而是"先让 1 个框架 + 最少 2 条线 + 全部交叉跑通"。**

### 3.1 MVP 结构（框架优先，非功能优先）

```
【框架】债务/储蓄账本（投入轴 + 产出轴最小集）
        ← 必须先立，且**必须有写入**
   ↑ 向上收割交叉节点

【线】只保留 2 条：
        线1 任务线：建 → My Day → 完成 → 逾期
        线2 专注线：开始 → 结束 / 中断三选

【交叉】把这 5 个全部接通（★MVP 的全部价值所在）：
        C1 专注 × 任务   → 时长归因到任务
        C2 专注 × 反馈   → 时长自动累加当日反馈
        C3 专注 × 框架   → 结束即记「投入」节点
        C4 任务逾期 × 框架 → 逾期即记「债务」节点
        C5 任务完成 × 框架 → 完成即记「投入」节点
```

### 3.2 MVP 验收（结构语言，而非功能清单）

> **不是**「有任务功能 + 有专注功能」，而是：
> **一条任务能被建出 → 做起（专注）→ 做完，且这个过程在框架上留下至少 3 个节点（投入×2、可能的债务×1），且摘要能看到它们。**

### 3.3 为什么这样切

| 理由 | 说明 |
|---|---|
| 框架是**唯一差异化价值** | 任务/专注谁都会做；「债务/储蓄如实记账」是本项目原创心智（intent 原文） |
| 交叉是**当前最大漏洞** | 现有实现证明：线做完了，交叉全断 |
| 其余 5 条线**都是"往框架加节点源"** | 框架通了，加线只是多一个节点源，风险低 |
| 与 intent 的第一版范围一致 | intent 自列第一版 ①④⑦ = 任务+专注+基础记账 |

### 3.4 被推迟的线，在"框架已通"前提下并不难

| 线 | 接入框架的方式 | 难度 |
|---|---|---|
| 学业线 | 成绩达标 → 产出节点（C10） | 低 |
| 复习线 | 复习完成 → 投入；温故知新 → 产出（C8） | 低 |
| 反馈线 | 消费框架数据（自检） | 低 |
| 协作线 | 分配出去 → 不记我的投入（C11） | 低 |
| 备忘录线 | 转化 × 任务（C12） | 低 |

**因为它们全都只是"加一个节点源"，不改框架本身。**

## 四、与既有文档的关系

| 文档 | 层级 | 回答 |
|---|---|---|
| `intention/needs.md` | 意图 | 为什么要这些（含结构：框架/线/交叉/节点） |
| `specification/functional.md` | 规格 | 系统必须有什么 |
| `specification/conventions.md` | 约定 | 不能违反什么 |
| `contracts/interactions.md` | 契约·操作 | 单个操作怎样才算做完 |

> 本文件比 contracts 更上层：contracts 说"操作怎么做完"，本文件说"**哪些操作必须存在、它们在哪咬合**"。

## 五、方法论沉淀

1. **框架 ≠ 功能**：框架是度量衡，横切所有线；把它当"一个模块"实现，必然落空。
2. **交叉最容易漏**：按线分工时，没人负责"线之间"；必须显式列出交叉并指定归属。
3. **节点是验收单位**：一个动作"做完了吗"→ 问"它在框架上落节点了吗"。
4. **MVP 切法**：先立框架 + 最少线 + 全部交叉；而非"先做完几条线再连"。
5. **加线 = 加节点源**：框架通了以后，扩展成本从"重构"降为"注册"。
