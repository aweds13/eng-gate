> 时间：2026-09-23。任务卡：**T-G10**（`复盘/任务重规划-剩余工作.md` G 批）。
> 口径依据：`复盘/口径定案-待定清单.md` §3（用户 2026-09-21 定顺序 **③ → ① → ②**）。
> 提交：见 `git log`（`feat(offline): …`）。
> 一句话：**手机在没有网络时也能记，回电脑导出一份同格式的包，在电脑上导入 —— 判断全部留在电脑一处。**

---

## 一、这一版做了什么

| 能做的（手机上，断网也行） | 落在哪 |
|---|---|
| 新建任务（标题 / 截止日 / 优先级 / 放进今天 / 备注） | 队列 `tasks` 行 |
| 勾完成、撤销完成 | 队列 `tasks` 行 + 一条 `task.completed` / `task.uncompleted` **事实** |
| 习惯打卡 / 取消打卡 | 队列 `habit_logs` 行（`done` 0/1） |
| 一句备忘 | 队列 `memos` 行 |
| 每日反馈（计划 / 差距） | 队列 `feedback_logs` 行（整行，带上电脑已有的字段） |
| 把队列导出成同步包 | `timeflow-sync` v1 JSON（与场景 ③ 同一个格式） |

三个落点：

1. **`src/web/offline.js`（新）** —— 手机侧引擎。上半段是**纯函数**（造行 / 打包，不碰 DOM、
   不碰 IndexedDB、不发请求），下半段是 IndexedDB 队列与缓存。**为什么值得拆成独立文件**：
   纯函数能在 Node 里用**同一份代码**真跑一遍（见下），不然手机侧的一切就只能靠"看字符串在不在"。
2. **`src/web/index.html`** —— 新增「离线记」视图（`offline`）+ 顶部离线提示条 + 四处写动作的
   **离线兜底**（今日页新建任务 / 勾完成 / 习惯打卡 / 备忘 / 每日反馈）+ 设置页一节。
3. **`src/web/sw.js`** —— 应用壳预缓存里加 `/offline.js`（缓存名 v1 → v2 才会真的重新预缓存）。

**电脑侧一行代码都不用改**：导入用的还是 T-G8 那套（`core/syncpack.py` 的先规划后执行 + 冲突留痕 +
墓碑），因为这个包就是**同一个格式**。

## 二、为什么这么切（三个技术选择）

### 1. 手机只做"采集 + 打包"，**不自己做合并**

浏览器里没有 SQLite，也没有领域层（债务 / 账本 / 状态机 / 层数上限）。要是手机上也写一套"半套合并"，
两边的口径（谁新谁旧、同一条算一条还是两条）早晚分叉 —— 而分叉了没人能发现。
所以手机的边界是：**把行装进包里**；判新旧、留冲突、判重复，全在电脑上那**一处**实现。

### 2. 字段按**白名单**挑，不照抄接口对象

界面拿到的任务对象是 `TaskOut`：除了库里的列，还带着 `groups` / `overdue_days` / `course_name` /
`depth` 等一堆**派生字段**。原样塞进包里 = 给电脑塞它没有的列。
于是 `offline.js` 里有一张 `FIELDS` 白名单（只列库里真有的列），护栏**两头对账**：
包里出现的键 ⊆ 白名单 ⊆ 真库的 `PRAGMA table_info`。

### 3. 完成/撤销**必须发事实**，不能只改状态

账本（完成收益、今日做成了什么）读的是**事实**，不是任务行的状态。
所以手机勾完成时写两样东西：任务行（状态 → 完成）+ 一条 `task.completed` 事实
（`occurred_at` = **手机上那一刻**、`source="phone"`、`extra` 带 `completed_on`）。
只改状态的话，导进去会"看起来完成了，但账本一分不涨"。

> `source="phone"` 只作记录与追溯，**不参与任何计算**（电脑那边是 `desktop` / `ai`）。

## 三、踩坑与修正（都是实测抓到的，不是读代码猜的）

1. **`attach` 在库里是 JSON 文本、在接口上是列表。** 第一版直接把接口的列表塞进队列行 →
   Node 自检当场红（`attach 应该是 JSON 文本`）。修法：`cachedTaskRow()` 统一转一次
   （布尔 `is_myday`/`flagged` 也顺手转成 0/1，与库里存法一致）。
   *教训*：**接口的形状 ≠ 库里的形状**，跨端传的是"库里的形状"。
2. **队列的键要跟表的主键走，不能假设都叫 `id`。** `habit_logs` 是 `(habit_id, date)` 复合主键、
   `feedback_logs` 是 `date`。队列键 = `表|主键`，于是"同一条反复改"只留最新一条 ——
   这正好也是电脑侧墓碑的口径（`syncpack.row_key`）。护栏拿两边的 `PRIMARY_KEYS` 对账。
3. **习惯"取消打卡"是 `done` 改 0，不是删行**（`feedback.toggle_habit_log` 是 UPDATE）——
   所以离线也能表达它：按缓存里"今天打没打过卡"决定写 1 还是 0，连点两次不会变成两笔。
4. **离线页必须排在 `/api/config` 之前。** `render()` 一上来就拉配置；离线时它必然失败 →
   整页空白。也就是说：**最需要这一页的时候它正好打不开**。现在 `offline` 分支写在拉配置之前。
   同理 `paintRail()` 离线时不再去问"有没有进行中的专注"（问一次弹一次提示，最需要安静的时候最吵）。
5. **子进程的编码坑（护栏自己踩的）**：`subprocess.run(..., text=True)` 在 Windows 上按 GBK 解码，
   而 node 的输出是 UTF-8（里面有中文）→ 读线程抛 `UnicodeDecodeError`。
   全部改成 `encoding="utf-8", errors="replace"`。这条**不是产品 bug**，是测试基础设施的坑，
   但它会让"看门禁日志时莫名其妙少一截"，记在这里免得下次再花时间。
6. **入队之后要就地改缓存（不然界面骗人）**：离线勾完成 / 新建任务后，队列里确实有了，
   但这一页读的是**缓存里的那份清单** —— 不改它就会"看着没反应"，人会以为没记上再点一次
   （点两次不会错账：账本按 task id 去重、`today_done` 也按 id 去重；但**界面不该骗人**）。
   所以入队后同步把那一行的 `status` 改掉 / 把新行放进清单。同一件事在习惯打卡上也要做
   （否则连点两次分不出"打卡"和"取消打卡"）。
7. **新发现（登记 **T-G11**，本次不改）**：`index.html` 里大量**静态文案**写成 `**重点**`
   （例：`待定 = 挂在那儿、没放弃，**不计债**`）。页面上就是**字面的星号** ——
   `noteHTML()` 只对**后端给来的**文字生效（`${noteHTML(...)}`），静态模板里没人转。
   实测确认（临时在假 DOM 探针里数了一次）：`today` `tasks` `planned` `habit` `setting` 五个视图
   的渲染结果里都有 `**…**`，共 6 处以上。**本次只保证自己新加的文案用 `<b>`**；
   全站修正（30+ 处、且要用 DOM 文本节点处理或逐处改 `<b>`）另开一张卡，见 `docs/traceability.toml` 的 `T-G11`。

## 四、验证：做到了什么，做不到什么

**做到的（都能在门禁里重复跑）**

- `tests/test_offline_phone_line.py`（14 条）—— 用 `node tools/phone_check.mjs` 跑
  **页面用的同一个 `offline.js`** 造一份真包，再把它**真导入**进一个真库，逐条验：
  ① 包过得了 `check_pack`；② 每行的键都在真表里（拿 `PRAGMA` 对账）；③ 手机勾的完成让
  任务变完成 + `version` 3→4 + 事实 `source=phone` + **账本 `gain_count` 真的 +1**；
  ④ 手机撤销让收益归 0；⑤ 新记的任务/习惯/备忘/反馈都落地，且**没有抹掉**电脑已有的字段
  （`executed` / `focus_minutes` 还在）；⑥ 重复导入一行都不动；⑦ 不动本机设置；⑧ 不删本机任何行；
  ⑨ 覆盖**逐条留痕**；⑩ 设备号不可能与电脑撞车（撞了电脑会拒）。
- `tools/ui_dom_probe.mjs` 新增「手机离线记 1/1」—— 在**内存版 IndexedDB** 里真入队 2 条 →
  真渲染离线页 → 真打出一份包（校验格式/设备号前缀/行数/墓碑为空/不含设置表）。
  这是本环境里"最接近浏览器"的那一层。
- `tools/web_live_check.py` 新增 10 条真机检查（共 **49** 条）：`/offline.js` 真发得出来、
  页面真引它、sw 真预缓存它、**手机造的包在真 HTTP 服务上真导入**（`inserted >= 5`）、
  手机记的任务真进了库、**再导一次 `inserted == 0`**、账本接口照常作答。
- `tests/test_web_frontend.py` 新增 `test_mobile_offline_capture_is_wired_and_honest`：
  把上面五条口径钉在代码里（尤其"离线分支必须排在 `/api/config` 之前"这条**位置**要求）。

**做不到的（如实写在这里）**

- **真浏览器里的 IndexedDB、Blob 下载、"离线模式"下的界面表现** —— 本沙箱没有浏览器（也没有 GUI）。
  用 `new Function` + 内存 IndexedDB 桩能覆盖"逻辑与数据流"，覆盖不了"浏览器实现差异"
  （比如 iOS Safari 对 `<a download>` 的限制）。
- **真手机**：手机现在**打不开这个应用** —— 服务只监听回环地址，那属于场景 **②**（同一 WiFi 直连，
  默认关，还没做）。所以这一版的验收路径是：**电脑浏览器开发者工具 → Network → Offline**。

## 五、请你点一次（人工验收，三步）

1. 起服务（`python tools/serve.py` 或 `python -m uvicorn timeflow.api.app:create_app --factory --port 8520`），
   打开页面 → 先在「今日 / 全部任务 / 习惯 / 备忘录」各逛一遍（**这一步是为了让缓存有东西**）。
2. 开发者工具 → **Network → 选 Offline**（或直接拔网线）→ 刷新页面：
   应该**自动落到「离线记」页**（而不是一片报错）；顶部出现离线提示条。
3. 在离线状态：新建一个任务、勾掉一个缓存里的任务、打个卡、写条备忘 → 点**导出同步包**
   （浏览器会下载一个 `sync-ph-….json`；若被拦，点「复制包文本」）。
   然后**关掉 Offline 模式**刷新 → 设置页「数据与同步 → 跨端同步」把路径/内容导进去 →
   应该看到「新增 N 行」，且**刚才离线勾的那条任务在电脑上真的完成了**。
   > 注意：**手机包不能导回同一台设备**（设备号相同会被明确拒掉，这是对的）。

## 六、边界与未做（写清了才不叫"忘了"）

- **不做离线删除**：硬删要动电脑上的墓碑，手机上判不准"这条电脑那边是不是也改过"。
- **不做离线改字段**（截止日 / 优先级 / 分组…）：LWW 会拿手机的快照覆盖电脑上更新的那份，风险不对等。
- **不做从电脑回传到手机**：手机没有库，不做反向合并。
- **不做离线专注计时**：`focus.finished` 会牵动电脑那边的**派生缓存**（当日反馈里的专注分钟），
  而"导入"是直接写行、**不过订阅器** —— 那条派生链要在电脑侧重算，单独一张卡。
- **导出不清空队列**：文件丢了不至于丢数据；重复导入是安全的（电脑那边合并幂等），
  所以要清空得自己点「清空（我已导入电脑）」+ 二次确认。
- **手机要真的能打开** → 场景 ②（同一 WiFi 直连 + 配对码，默认关）。
