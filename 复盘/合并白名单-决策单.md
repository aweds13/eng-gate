## 一、为什么「落 146 而没配套」必然出事（三条，均带出处）

卡 146 落地后的机器语义（读其未提交 diff，`.wt/onemodel` 工作树）：

- `DEFAULT_MODEL` 变成「真源首项」—— diff 原文：
  ```python
  def __getattr__(name: str) -> Any:
      if name == "MODEL_WHITELIST":
          return load_model_whitelist()
      if name == "DEFAULT_MODEL":
          return load_model_whitelist()[0]
  ```
- `--model` 参数的默认值取自它（现行代码 `tools/wb_dispatch.py:2047`：`parser.add_argument("--model", default=DEFAULT_MODEL, …)`，146 不改这一行）；
- 允许集变成「真源名单 ∪ 一次性授权 ∪ 开关文件打开的」（diff 里 `effective_allowed_models()`：`out = [*load_model_whitelist(), *ONE_OFF_MODELS]`）。

而真源**现在的内容**只有一条华为码道条目（原文摘录见 §二）⇒ 落下去立刻发生：

1. **裸名一律被拒**：`deepseek-v4.1-flash` / `glm-5.3-flash` 不在真源里。闸门是逐字比较（`tools/wb_dispatch.py:301-307` `model_rejected`：「逐字比较（连大小写 / 连字符都不许含糊）」）⇒ 显式 `--model deepseek-v4.1-flash` 也会被拒。
2. **默认值变成 `huaweicloud-maas/GLM-5.2`**：= 真源首项（146 diff 的 `load_model_whitelist()[0]`）—— 这是【华为码道】号池的 id（真源文件自证：`pool = "codearts-cli"`），**CodeBuddy CLI 服务不了的名字**（CodeBuddy 侧用裸名体系：`tools/wb_dispatch.py:30-31` 记录 CLI 2.158.0 的可用列表实测；开关文件 `model-switches.toml:15` 也写明「模型名与 `MODEL_WHITELIST` 同一套写法（裸名）」）。
3. **⇒ 所有「不带 `--model`」的派活全挂**：默认值就是那个坏名字，派出去必失败。

**备注（别以为「打开开关就行」）**：`infra/pool/model-switches.toml` 只做**加法**（该文件第 6 行：「这里 `true` 的模型是**额外放行**」），而默认值取的是真源首项（146 diff 的 `__getattr__`），**开关文件救不了默认值**。现在开关里打开的是 `"glm-5.3" = true`（`model-switches.toml:24`），它只扩大允许集，不改默认。

## 四、★ 落地顺序（先补真源 or 先改默认值，谁先谁后为什么）

### 若选候选 ①（推荐顺序：**先补真源 → 再落 146**）

1. **第一步（用户动 `infra`，只有用户能改）**：把 CodeBuddy 裸名写进真源，**且必须排在首项**。
   ★ **为什么必须首项**：默认值 = 真源**首项**（§一）。卡 158 样例写的是「**追加**」到文件末尾——按那个写法，首项仍是 `huaweicloud-maas/GLM-5.2`，默认值**仍然坏**，光追加救不了。⇒ 要么把 `[[approved]] pool="codebuddy-cli" model="deepseek-v4.1-flash"` 写在华为条目**之前**，要么接受默认值换成别的坏名字（不可）。
   ★ 这一步此刻对现行代码**零影响**：现行 `wb_dispatch.py` 根本不读这份文件（名单是 :132 的硬编码）；只有 `pool_models` MCP 工具的批准集显示会变（快照口径 `models.live.json` 里 `approved`/`live` 全是华为形式，加进裸名后 `approved_but_missing` 会多出 CodeBuddy 名——只报告、不启用，符合真源第 6 行规矩）。
   ★ 另要想清楚一件产品语义：**429 轮换链只走真源名单**（`model-switches.toml:8-9`「不进 429 轮换链」；146 diff 的 `next_whitelist_model` 只走 `load_model_whitelist()`）——合并后，两个号池的 id 会串进**同一条轮换链**（首项挂了按序换下一个，可能换到另一个池的名字）。要不要允许「跨池轮换」，用户拍板时一并定。
2. **第二步（落 146）**：此时真源首项 = `deepseek-v4.1-flash` ⇒ 落地后 `DEFAULT_MODEL` 仍是它，**派活不断档**；轮换序 = 真源条目出现顺序（卡 146 规格第 2 条「顺序即轮换序」）。

先在派活器里改掉「默认 = 真源首项」（改成「必须在真源里、且显式给或按白名单兜底」），**再**落 146；顺序反了，中间任何一笔不带 `--model` 的派活都会拿华为名字打 CodeBuddy CLI。
