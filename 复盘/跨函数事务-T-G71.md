# 跨函数事务（T-G71）—— 收掉 T-G33 那条残留：一起成功，或一起撤

> 由来：T-G33（分组不存在时的 500 + 指错对象的 404）当时把**输入错**先验掉了
> （`_require_groups`），并在复盘里如实留了一句残留：
> 「验完之后若再出数据库级错误，任务仍然会留下 —— 两个 core 函数各自 `commit`，没有跨函数事务。
> 要彻底解决得动事务边界，不在这张卡里做。」
> 本卡就是那句"另一张卡"。

---

## 1. 一句话结论

`db.unit_of_work()` 把一段里的**多条 core 调用合成一次提交**：成功一次 `commit`、抛异常一次 `rollback`。
**实测 6 个"一个处理函数里调了 ≥2 个会自己 commit 的 core 函数"的地方**：3 个包了事务
（建任务 / 改任务 / 改提醒设置），3 个在**带理由的豁免清单**上（第二笔是导出一份 md）。
清单本身也进了 pytest —— **以后新写一个这样的处理函数会被当场拦下**。

---

## 2. 残留到底是什么（真实现象，不是假想）

```
POST /api/tasks  {"title":"写周报","groups":[<真分组>]}
  ├─ _require_groups()          ← T-G33 补的：分组不存在 → 404，先验干净
  ├─ tm.create_task(...)        ← 自己 conn.commit()：任务**已经落库**
  └─ tm.set_task_groups(...)    ← 这里若抛数据库级错误（磁盘/约束/…）
                                   → 接口报错，可库里躺着一条没有分组的任务；重试 = 两条
```

T-G33 修的是"**输入**错要先验"，这半句修不了"**验完之后**仍然可能失败"。
两者都要有，缺一个都还是"客户端看到报错、库里却变了"。

---

## 3. 做法：在**代理层**拦 `commit()`

`src/timeflow/storage/db.py` 里的 `_ThreadLocalConn` 是 HTTP 那条路上的连接代理
（T-G18 那次并发修复留下的：每线程一个真连接）。core 里 60 多个函数各自
`conn.commit()`，而它们拿到的就是这个代理 —— 于是在代理上记一层账：

```python
def commit(self) -> None:
    if self._defer:      # 在 unit_of_work 里（★ 这个标记**每线程一份**，见 §7 第 1 条）
        return           # 记着"有写入"，真提交等退出那一刻
    self._conn().commit()
```

```python
with db.unit_of_work(conn, what="POST /api/tasks"):
    t = tm.create_task(...)          # 它自己 commit() → 被推迟
    tm.set_task_groups(conn, t.id, payload.groups)   # 同上
# 退出：成功 → 一次 commit；抛异常 → 一次 rollback
```

SQLite 的隐式事务从**第一次写**就开着（默认 `isolation_level=""`），所以推迟提交等于把这几笔写
放进同一个事务里 —— 不需要给 60 个 core 函数加参数、也不需要引入 ORM/UoW 框架。

---

## 4. ★ 边界：这套东西**不**假装支持真 `Connection`

`unit_of_work` 只认 `db.thread_local()` 的代理。拿一个真 `sqlite3.Connection` 调它
**直接 `TypeError`**，并在那句话里说清为什么：

- 真连接的 `commit` 是 C 方法，**拦不住**；"支持"它只能给一个"以为有事务"的假象；
- 与 `db.raw_conn()` 同一条规矩：**不猜、不静默降级**（那条函数拿不到真连接也是抛错）。

其它如实记的边界：

- 事务覆盖的是**数据库行**，不覆盖**系统副作用**：`PUT /api/settings/reminder` 里
  `set_enabled` 还会注册 Windows 计划任务 —— SQLite 回滚不了那个。包事务仍然更好
  （两笔设置行现在同生共死，而以前 `style` 改了、`enabled` 失败就留下半套），
  但"计划任务与设置行之间"仍有一个极小的窗口；
- `executescript()` 会先隐式提交（sqlite3 的规定），等于撕开事务 —— 本项目没有这样的调用点；
- 段里某一笔失败被**上层自己 try/except 吞掉**再继续跑，那笔写不会被单独撤掉
  （没有 savepoint；要么整段成、要么整段撤）。现在没有这样的调用点；
- core 自己 `rollback()` 时回滚的是**整段** —— 这正是"有事就全撤"的语义。

## 5. ★ 怎么保证"残留不再长回来"：清单进 pytest

本卡顺手写了个 AST 扫描（先当探针用，`gates/diag/probes/multi_write.py`，判据搬进了测试）：

1. 从 `app.py` 的 `from timeflow.… import … as alias` 建「别名 → 模块/包」映射；
2. 在那些模块里找**函数体含 `commit()` / `executescript()`** 的函数名 → "会自己提交的写入"；
3. 遍历 `app.py` 里被 `@app.<method>` 装饰的函数，数它调了几个这样的函数；
4. **≥2 个的必须包 `unit_of_work`，或者在带理由的 `EXEMPT_MULTI_WRITE` 清单上**。

实测清单（6 个）：

| 处理函数 | 两笔写 | 处置 |
|---|---|---|
| `create_task` | `tm.create_task` + `tm.set_task_groups` | ✅ 包事务（T-G33 残留的正主） |
| `update_task` | `tm.update_task` + `tm.set_task_groups` | ✅ 包事务（第二笔崩了，连标题一起撤） |
| `put_reminder_settings` | `remind_mod.set_style` + `set_enabled` | ✅ 包事务（系统副作用见 §4） |
| `create_memo` | `memo.create_memo` + `vault.try_export` | 豁免：第二笔是**派生 md**（T-G4 起吞错），且必须在提交**之后** |
| `delete_memo` | `memo.delete_memo` + `vault.try_export` | 同上 |
| `ledger_output` | `memo.add_output_entry` + `vault.try_export` | 同上 |

★ 两条测试互相咬合：一条判"清单没变歪"（多一个少一个都红），一条判"清单本身是空转吗"
（`create_task` 必须被数到 ≥2 笔）；**豁免理由短于 10 个字也红**（防止写个"因为"就豁免）。

## 7. 踩过的坑（记下来，别再犯）

1. **★★ 延迟标记挂错了地方 —— 并发测试当场抓到**（本卡最大的坑）：
   第一版把 `_defer` 写成**实例属性**（`self._defer`），可 `_ThreadLocalConn` 是
   **全进程一个**、被所有线程共用。于是线程 A 进事务后，线程 B 的 `commit()` 也被记成"推迟"，
   而 A 退出时提交的是 **A 自己的连接**（`_conn()` 按线程取）—— B 那笔写**永远没人提交**：
   别的连接看不见它、写锁还一直攥着，30 个并发建任务直接 `database is locked`。
   ★ **抓到它的是 `tests/test_concurrency.py`**（T-G18 留下的老守卫），不是我新写的单线程用例 ——
   "每线程一个连接"这条规矩的**状态也必须每线程一份**，否则代理就成了新的共享点。
   修法：`_defer` 住进 `threading.local()`，并补一条**确定性**的最小复现
   （A 线程停在事务里、B 线程写一条并提交 → B 的必须立刻可见）。
2. **★ 第一版扫描器量出来的清单是假的**：`timeflow.core.tasks` / `timeflow.core.memo` 都是**包**
   （`__init__.py` 只做 re-export），只解析 `__init__.py` 的话 `set_task_groups`（真身在
   `groups.py`）根本看不到 —— 清单只报出 1 条。**扫包必须扫整棵树**，并且要有一条
   "扫描器真的看得到东西"的测试盯着它（否则它会安静地空转）。
   ★ 这条与 T-G40/T-G69 那条教训是同一族：**判据自己也会撒谎**。
3. **量出来才知道"残留"比想象的小**：真去看之前，我以为"两条 core 调用"的地方有一堆
   （子任务、复习、专注、团队…）。实际只有 **6 个**，而其中 3 个的第二笔是导出 ——
   也就是说**需要事务的只有 3 个**。先量再改，省下了一场大手术。
4. `unit_of_work` 的"支持面"要**说清并且真的拒绝**：一开始想"真连接就退化成
   `with conn:`"，那会给出一个**假的事务**（内层 `commit()` 照样提交）—— 与其糊过去，
   不如抛错（`raw_conn` 的老规矩）。
5. **TOML 串里写 ASCII 引号（第 13 次）**：T-G71 那条 `gaps` 又混进 3 对，`check_toml.py` 当场报行列；
   还是用 `gates/diag/probes/fix_quotes.py <行号>` 把**那一行内部**的引号成对换成「」。
