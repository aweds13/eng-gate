## 一、L6 外包与流水线层（`tools/` + `tools/pool/`）

### Q-L6-01 一张卡走「全量门禁 + 三段文书」还是走轻量通道，是**谁的什么动作**决定的？
- 为什么它会咬人：真实现场 —— 卡 113 实际改 16 行、卡 114 改 9 行，照样走「写卡 + 建树 + 切片 + 工人 + 17 道门 + 三段文书」，固定开销 ≈ 10KB 文书 + 6~10 分钟门禁，**与改动大小无关**（复盘/架构审议-外包与门禁.md §二①，复盘/外包工具-需求与架构.md §5 第4条）。现在 `pool/plan.py` 只按 `depends` 与冲突域排批，整条链里**没有任何**「改动大小 → 通道」的决定点。
- 该由谁回答：机器判据（先要一张「门 × 输入」表，且方向是「漏跑危险」而不是「多跑安全」）+ 人（拍板档位阈值）
- 什么证据能把它了结：一条反例钉子 —— 同一份 backlog 喂进去，一张单文件域的卡被排进轻量通道、一张跨 3 文件的卡被排进全量，且探针证明轻量通道**没漏掉**它该跑的门（读数可查）。

### Q-L6-02 卡规格与预声明是**两步动作**，谁判「这两步都做了」？

### Q-L6-03 门禁锁的 `renew` 子命令**有能力、零接线**——谁判「这把锁还要不要续租」？

### Q-L6-04 模型闸门是**派活器级**的，直接起 CLI 就绕过 —— 谁判「这次模型调用经过了闸门」？

### Q-L6-06 沙箱用 `USERPROFILE`/`HOME` 重定向隔离登录态 —— 顺手把「工具在哪」也隔离了，谁判这两件事该分开？

### Q-L6-12 观测面把「我不知道它怎么了」渲染成「它卡死了」的历史 ——谁判「无心跳的日志该说什么」？

### Q-L9-02 账号快照清单是**照上一次会话的留档逐条对齐**的 ——谁核「少存一件就切不回来」？

### Q-L9-03 切号守卫 `_live_cli` **认不出 psutil 就返回空并放行** ——谁判「现在能安全切号」？
- 为什么它会咬人：结构上必咬 —— `codebuddy_accounts.py::_live_cli` 的注释原话：「认不出 psutil 就返回空并**放行**（如实说）」。也就是说**守卫的缺省方向是放行**：装不上 psutil 的机器上，「有 codebuddy 在跑就别切」这条闸**静默失效**，而切号会把正在写的实例的凭据换掉。

- 什么证据能把它了结：一条反例钉子 —— 在没有 psutil 的环境里 `use` 被**拒**（或明确要求 `--force`），而不是静默放行。

### Q-L9-04 「现在能用什么模型」有**四处**真源 ——谁判它只有一个答案？
- 为什么它会咬人：真实现场 —— 复盘/外包工具-需求与架构.md §5 第3条：`wb_dispatch.MODEL_WHITELIST`（裸名）与 `infra/pool/models.whitelist.toml`（`provider/model`）是两份真源、**连 id 体系都不同、已经漂了**；再加上 `wb_dispatch.ONE_OFF_MODELS` 与 `infra/pool/model-switches.toml` 两条「只做加法」的路径 —— 合计四处。卡 132（T-G229）加的 `pool/models.py::compare_rosters` **只报告、绝不自动改名单**（白名单只有用户能改），所以对账判据红不红、红了谁去关，没有归属。
- 该由谁回答：人（合并成一处是用户的决定）+ 机器判据（对账判据挂在哪道门、红了谁关）
- 什么证据能把它了结：一个决定 + 一条钉子 —— 两份工具答「现在能用什么模型」**不许互相矛盾**，且矛盾时有一条判据红并点名人。

### Q-L9-05 `model-switches.toml` 的 true/false，**谁判它是用户按的**？
- 为什么它会咬人：真实现场 —— `model-switches.toml` 文件头写着「谁改它：**用户**（或用户点界面上的开关）」；`pool/models.py::load_switches` 只负责读（坏文件抛 `SwitchFileError` 点名路径行号），**没有任何判据**分辨这次 `true` 是用户按的还是别的客户端写进去的。写面若能被任意带 env 的客户端调到，开关就是「谁都能开的模型闸门后门」。
- 该由谁回答：机器判据（改开关要留痕 / 只有用户那条路能写）+ 人（界面开关的鉴权边界）
- 什么证据能把它了结：一条反例 —— 「非用户路径改开关」被拒或留痕并在下一次派活时被点到名。

### Q-L9-06 `pool/models.py` 读的是**快照**不是现拉 ——谁判「这份 `models.live.json` 还新鲜」？
- 为什么它会咬人：真实现场 —— `pool/models.py` 模块头：「这里读的是**快照**（带 `at` 时间戳），**不是现场拉取**」；而 `pool_models.py`（号池侧）是「**每次现拉**、不长期缓存」（规矩第5条）。两条路对「现在能用什么」给的口径不同：快照可能几小时前，甚至上一次求交失败时留下的。`model-switches` 的可用性判定若读旧快照，会把「服务端已经撤掉的模型」当还能用。
- 该由谁回答：机器判据（快照过期 ⇒ 明确降级 / 拒，或强制现拉）+ 人（可接受的快照新鲜度）
- 什么证据能把它了结：一条读数 —— 拿一份过期快照去判可用性，工具要么现拉、要么明确标「数据 N 小时前，不足以判」，不许拿旧的当现在。

### Q-L9-07 429 轮换链是**硬编码元组**、开关打开的模型**不进链** ——谁判「轮到谁了」？
- 为什么它会咬人：真实现场 —— `wb_dispatch.py:132`：`MODEL_WHITELIST` 是两条裸名按序排成的元组（`deepseek-v4.1-flash` → `glm-5.3-flash`），「顺序就是默认优先」，`next_whitelist_model()` 只看这个元组；而 `model-switches.toml` 打开的大模型（`glm-5.3` / `kimi-k3-1`）**故意不进 429 轮换链**（文件头第2条）。于是「谁被限流了该换到谁」是**源码里的一个元组**，改它=改代码+跑门禁，和「开关=数据」的设计正相反。
- 该由谁回答：机器判据（轮换顺序也应是数据 / 或明确说它就是代码）+ 人（哪些模型有资格当替补）
- 什么证据能把它了结：一条读数 —— 撞 429 时打印出的「换到谁」能追溯到一处**可改的真源**（不是源码元组），或如实写明「轮换顺序是代码、改它要过门禁」。

### Q-L9-08 凭证轮换「**真换待用户下次换 key 时走一遍**」——谁判「新凭证真的生效了」？
- 为什么它会咬人：真实现场 —— `README.md` 待办第3条原文：「dry-run 已验，**真换待用户下次换 key 时走一遍**」；`rotate_credentials.py` 的自检只跑一次 `codearts models`（无失败特征 + 见到 `model_id` 表 = 通过）就回滚或不回滚。也就是说「轮换成功」的判据是**一次列表能出来**，不是「派活真的能跑通」。
- 该由谁回答：外部（华为侧凭证生效的官方判据）+ 机器判据（自检要不要升级成真派一条极短请求）
- 什么证据能把它了结：一条读数 —— 一次真轮换后，用**新**凭证真跑通一条最小请求（不是只列模型），并留痕。

### Q-L9-09 额度**没有预警**，本地账还漏记手工命令 ——谁判「这个号还剩多少」？
- 为什么它会咬人：真实现场 —— 种子文档 L9.3 记「今晚我自己的号 429 才知道，没有预警」；`usage_report.py` 模块头明写：本地账**只记经 `dispatch.py` 发出去的**，手工敲的 `codearts` 命令不在里面，两边对不齐「是设计如此，不是漏记」。⇒ 撞 429 之前没有任何东西会红，撞上之后账又是两本。
- 该由谁回答：外部（服务端有没有配额查询接口）+ 机器判据（本地账要不要把手工命令也记上 / 加一条额度预警）
- 什么证据能把它了结：一条读数 —— 在额度耗尽**之前**，某个工具给出一个可比的「已用量 / 剩余量」数字（或明确说查不到）。

### Q-L9-10 项目索引里的字是**用户口径的投影**（`[project.maidao]` 写错并留了很久）——谁判「索引里的字是对的」？
- 为什么它会咬人：真实现场 —— `projects.toml` 里那段自己认的错：原来写了 `[project.maidao]`（「码道」），而「码道**不是项目**、是华为号池」，主控「一直在一个**不存在的东西**上等答案」。索引只有用户能改、`memory` 入口「只有用户知道」、缺了「不许编」—— 也就是说索引的内容既没有真源、也没有判据，**用户的措辞错误会原样变成数据**。
- 该由谁回答：人（口径归用户）+ 机器判据（索引的自洽判据能拦「结构错」但拦不住「语义错」——要问这条边界够不够）
- 什么证据能把它了结：一条判据或一个流程 —— 索引里再出现一个「不是项目的东西被登记成项目」，能被拦下或至少被点名复核。

### Q-L9-11 沙箱 profile 的**隔离判据要联网、花额度** ——谁判「两个号真的隔离了」？
- 为什么它会咬人：真实现场 —— `codebuddy_accounts.py::cmd_profile_check`：默认**离线**只核目录与环境；要真判「这个 profile 未登录」得加 `--run`，那会「真起一次实例、联网、花一点额度」（代码里写死用 `deepseek-v4.1-flash` 跑一条 `-p 只回 OK`）。隔离的**唯一硬证据**因此是「愿意花钱跑一次」；日常不跑，就只剩「目录都在」这种弱证据。
- 该由谁回答：机器判据（有没有不花钱的隔离指纹，比如核凭据文件的指纹是否被指走）+ 人（隔离验证的频率）
- 什么证据能把它了结：一条读数 —— 不联网也能给出「这个 profile 的登录态落点与主号不同」的指纹对账。
