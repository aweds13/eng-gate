# 环境问题 · 零基础说明

> 场景：项目搬家后 `pytest` / `import` 报 `ModuleNotFoundError`。
> 面向：零基础读者（本文用类比讲清原理，不假设编程背景）。
> 实例：2026-09 项目从 `D:/docs\engineering\` 迁到 `D:/repo/engineering\` 后，`timeflow` 导不进来。

---

## 一、先打个比方

把 Python 想象成**图书馆**，你的项目是**一本书**。

- 你的项目代码放在书架：`D:/repo/engineering\src\timeflow\`
- Python 想 `import timeflow` 时，需要知道"这本书在哪个架子上"
- 图书馆有一张**索引卡片**，写着书的**位置**

**出问题的地方就在这张卡片上。**

---

## 二、那张"卡片"是什么

Python 安装一个包（尤其是"开发模式"安装）时，会在一个特殊目录放一个 **`.pth` 文件**，里面写着一行路径。

本机这张卡片在：
```
C:/Users/example\miniconda3\Lib\site-packages\__editable__.timeflow-0.1.0.pth
```

**卡片上写的内容：**
```
D:/docs\engineering\src          ← 旧地址
```

---

## 三、问题出在哪

项目**搬过家**：

| | 地址 |
|---|---|
| **卡片上写的**（旧） | `D:/docs\engineering\` |
| **项目实际的**（新） | `D:/repo/engineering\` |

**项目搬走了，但卡片没跟着改。**

于是 `import timeflow` 时：
- Python 照卡片去找 → `D:/docs\engineering\src` → **已空**
- 找不到 → `ModuleNotFoundError: No module named 'timeflow'`

> **不是项目坏了，是"路标"还指着旧址。**

---

## 四、"改代码"和"改环境"是两回事（最容易混淆）

| | 存在哪 | 举例 | 影响范围 | 进 Git 吗 |
|---|---|---|---|---|
| **代码/文件** | 你的项目文件夹 | `.py` 文件、`.md` 文档 | 只有这个项目 | ✅ 进 |
| **环境** | Python 的安装目录 | `.pth` 卡片、装的包 | 整台电脑的 Python | ❌ 不进 |

**推论**：
- 改脚本（`check_layers.py`）= 改**文件** → 进 Git，有提交记录
- 重装包 = 改**环境** → **不进 Git**（不在项目文件夹里）
- **这就是环境修复"没有产生提交"的原因**

---

## 五、怎么修（逐词解释）

```bash
python -m pip install -e ".[dev]" --no-build-isolation
```

| 片段 | 意思 | 类比 |
|---|---|---|
| `pip install` | 安装 | 让图书馆重新登记这本书 |
| `-e` | editable（可编辑模式） | **"别复制，就指着原位置"** |
| `.[dev]` | 装当前目录，附带开发工具（pytest 等） | 连"说明书"一起登记 |
| `--no-build-isolation` | 别另开干净房间装 | **关键**：默认要联网下工具，网不好会失败；这个=**用本机已有的工具** |

**结果**：卡片被重写成正确路径，`import` 恢复正常。

---

## 六、"editable 安装"为什么特殊

| | 普通安装 | **editable（开发模式）** |
|---|---|---|
| 做法 | 把代码**复制**到 Python 目录 | **不复制**，只记一个"指针"指向你的项目 |
| 你改代码 | 改了**不生效**（要重装） | 改了**立刻生效** |
| 项目搬家 | 没影响（副本还在） | ❌ **立刻失效**（指针还是旧地址） |

你是开发者（要不断改代码），所以用 editable —— 好处是改完立刻生效，**代价是项目一搬家就得重装**。

---

## 七、三条实用经验

1. **项目搬家后 `import` 报错找不到模块** → 十有八九是 editable 失效
   ```bash
   pip install -e . --no-build-isolation
   ```
   重装一次即可。

2. **Git 只管项目里的文件**，不管电脑上装的 Python 包：
   - "我的改动为什么没进 Git？" → 可能改的是环境，不是项目文件
   - "换台电脑能跑吗？" → 代码能，但**环境要重装**（标准做法）

3. **看到 `No module named 'xxx'` 先别慌** —— 多半不是代码错，是"路标断了"。
   用 `pip show xxx` 看安装记录，确认路径对不对。

---

## 八、本次修复的完整命令与验证

```bash
# 1. 查看本机 setuptools 版本（要 ≥68）
python -c "import setuptools; print(setuptools.__version__)"
# → 82.0.1  ✅

# 2. 重装 editable（--no-build-isolation 用本机工具，避免联网失败）
python -m pip install -e ".[dev]" --no-build-isolation -i https://pypi.tuna.tsinghua.edu.cn/simple

# 3. 验证
python -c "import timeflow; print(timeflow.__file__)"
# → D:/repo/engineering\src\timeflow\__init__.py  ✅

# 4. 跑测试
python -m pytest
# → 44 passed  ✅
```

> ⚠️ 若首次不加 `--no-build-isolation` 报 `Could not find a version that satisfies the requirement setuptools>=68`，
> 说明构建隔离环境拉不到 setuptools（源/网络问题），加上该参数即用本机已有的 setuptools，绕过联网。
