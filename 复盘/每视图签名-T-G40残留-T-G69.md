# 每视图签名：判据自己也不许在错的时候被写下来（T-G69 / `T-G40 §六` 那条残留）

> 来历：用户 2026-09-25 在我把待办问清楚之后，从三条工程债里挑了这一条（"每视图签名断言"）。
> 它是 `T-G40` 复盘里明确记下的**没做**：「『每个视图采到的内容必须与它自己有关』这道保险
> （防『三方一致地错』）—— 记在这里当下一张卡」。这一张就是那张卡。

---

## 1. 这道保险防的是什么（不是"界面变了"）

黄金层的判据是「与上一次采的逐字节比」：谁把没打算改的东西动了就红。它挡得住"回归"，
但有一个盲区：

> **如果黄金自己是在错的那一刻采的**，那么渲染层、假 DOM 探针、行为流层会**一致地**把错的当成对。

**这不是假设 —— T-G40 就真撞到过**：`stats` 视图冷启动时 7 个接口串行（含 371 天热力图），
"点视图 → 请求在飞 → 最后一次 innerHTML"中间**一段 DOM 都不动**，于是采到了**上一个视图（focus）
的残留画面**。旁证是两份黄金**逐字节同大小、`rows` 都是 51**。

所以需要一层**与黄金无关**的判据：这屏**该有什么**。

## 2. 怎么做的：每个视图一份"签名"

`tools/render_signatures.json`（15 屏：14 个视图 + 浮层 `palette`），四条判据：

| 判据 | 意思 | 例子 |
|---|---|---|
| `must` | 清单里必须出现的**签名元素** | `today` 必须有 `circle.chart-ring-progress`（完成度进度环） |
| `forbid` | 必须**不**出现 —— 用来钉"这不是**别的**屏" | `today` 里**不许**有 `input#allTitle`（那是全部任务页的输入框） |
| `min_count` | 出现次数下限 —— 钉"网格真的铺出来了" | `habit` 的 `rect.chart-cell` ≥ **300**（实测 730） |
| `min_rows` | 非表头行数下限 —— 挡"几乎没渲染出来的空白页" | `today` ≥ 60（实测 98） |

**判据是数出来的，不是我拍的**：先把候选模式在**已提交的 45 份黄金**里跑一遍矩阵
（`gates/diag/sig_matrix.py`），只留"确实有辨识度"的那些 —— 一个模式要在半数以上的屏里都出现，
它就证明不了"这是哪一屏"，那正是"三方一致地错"最爱的形态。这条也被钉成了测试
（`test_signatures_are_not_vacuous`）。

**两处生效，缺一不可**：

1. **采集的当场**（`tools/render_check.mjs`）：采完每一屏立刻核对，不成立就抛，
   **绝不让它落成黄金** —— 这是唯一能挡住"三方一致地错"的时点（一旦落成黄金，后面三层都会说它对）。
   错误消息会告诉你：要么这屏真坏了，要么**你确实是有意改版**（那就改签名并写清理由）。
2. **`tests/test_render_signatures.py`**：判这份表本身合不合格（覆盖每一屏 / 每条 `must` 有辨识度 /
   不许空签名），并判**已提交的 45 份黄金**逐份满足自己的签名。

## 3. 为什么是 JSON 不是 TOML（老实说清）

这份表要在**采集的那一刻**被 Node 读 —— 那是它该在的位置。而 **Node 没有内置 TOML 解析器**，
本项目零依赖（不引 npm 包）。JSON 两种语言都能原样读，语义也不会两处解释。
四条判据的解释**只写在 JSON 的 `_why` 里**，两边实现都照它（子串 + 计数，窄到不会各自演化）。

## 4. 证明它咬得住（上了闸就得证）

| 证据 | 怎么证的 |
|---|---|
| 真仓库的 45 份黄金全部满足签名 | `test_committed_goldens_satisfy_their_signatures`（45 份逐个判） |
| **把"另一屏的清单"喂给 `today`** → 两条都响 | `test_the_check_bites_on_a_wrong_screen`：`desktop__tasks.txt` 当作 today → 报「找不到进度环」+「出现了全部任务页的输入框」；反证：喂自己的清单干净 |
| 几乎空的清单被 `min_rows` 拦住 | `test_min_rows_catches_an_almost_empty_capture` |
| **采集侧真的会拦**（端到端） | 我故意往 `today` 的签名里加了一条不存在的模式 → `node tools/render_check.mjs --only today` **退 1**，消息是「找不到『ZZZ…』……若确实是有意改版，改 tools/render_signatures.json 并写清理由」，`notes` 记「每视图签名不成立」；随后撤销那条假模式、复跑绿 |

## 5. 边界（不许假装）

- **它不替代黄金**：签名是"这屏像不像它自己"，黄金是"这次改了什么"。两者一起才完整。
- **签名会过时**，而且**必须过时**：哪天有意改版（比如今日页不要进度环了），签名就得改 ——
  这不是缺陷，是"它确实在守着某句话"。所以改签名要写理由（跟改黄金、销棘轮账同一个规矩）。
- **它挡不住"内容对但数据错"**：比如数字算错了，签名看不出来（那是 pytest 与口径层的事）。
- **手机档的判据与桌面同一条**（行数下限按三档里最紧的那档留了余量），没有为某档单独放宽。
