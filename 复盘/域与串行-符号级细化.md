# 域与串行 —— 从**文件级**细化到**符号级**（卡 188 · 台账号 T-G288）

**一句话**：`tools/pool/plan.py` 的冲突域是**文件级**的，比 git 的**行级合并**还粗；本卡交一个
**符号级判定零件** `tools/domain_symbols.py`，把「两张卡会不会写同一处」下探到**顶层符号 + 行区间**，
并说清「必须串行」的两种成因（(a) 真不得不 / (b) 假不得不）。

★ **本卡只交零件、不接线**（理由见 §4）；接线是**另一张小卡**。

## §2 「必须串行」分两种 —— 判据（本卡要沉淀的第一条规矩）

任何「这两张卡不得不串行」的主张，**都要标明是 (a) 还是 (b)**：

| | 成因 | 判据 | 处置 |
|---|---|---|---|
| **(a) 真不得不** | B 的**判据必须读 A 的产物** | B 的测试/验收**引用了 A 才会生成的符号 / 路数 / 值** | 只能靠**契约冻结 + 桩**并行（**本卡不做**） |
| **(b) 假不得不** | 只是**两个改动落在同一个文件**里 | 两处改动落在**不同的顶层符号 / 行区间**，彼此不读对方产物 | ⇒ **可拆**；**不许直接接受 (b) 的串行** |

★ **规矩**：`wb_plan` 报出「同文件冲突」时，**先判 (a)/(b)**：
- (b) → 给出**拆法**（本卡的符号级判定就是那把尺子）；
- (a) → 写清 B 读的是 A 的哪个产物，才允许串。
★ 现状的 10 张 `wb_dispatch.py` 卡，从卡头列的改动点看**全部是 (b)**（各写各的部分）——
这正是本卡要证的那一半。

## §3 设计

### 3.1 零件：`tools/domain_symbols.py`（本卡已交）

四个公开函数（签名与真输出见卡 188 回报）：

| 函数 | 语义 |
|---|---|
| `symbols_of(path, *, root=None) -> set[str]` | 一个 `.py` 的**顶层符号名**（函数 / 类 / 模块级常量；方法不算） |
| `symbol_ranges(path, *, root=None) -> dict[str, tuple[int,int]]` | 符号 → `(起始行, 结束行)`；结束行 = **下一个顶层定义的前一行**，最后一个到文件末尾 |
| `declared_symbols(decl, *, root=None) -> set[str]` | 解析 `path::sym` → `{sym}`（**核对存在**，查不到抛错）；不带 `::` → `{WHOLE_FILE}`（整文件，**不读文件**） |
| `overlap(a, b, *, root=None) -> Overlap` | 两份声明的关系 → 四种之一 |

### 3.2 队列声明：新增**可选** `symbols`

`docs/workbacklog.toml` 的每张卡现在只有一个 `files = [...]`（精确路径 = 整文件域）。
设计上新增**可选** `symbols = [...]`，条目形如 `tools/wb_dispatch.py::main`：

- **写了 `symbols`** → 该卡在这些文件上的域**收窄**到列出的符号；
- **没写**（今天全部如此）→ 该文件仍是**整文件**域（**行为逐字不变**）。

### 3.3 `wb_plan check` 的判定表（接线后；本卡**未实现**）

对**同一路径**上的一对声明，把 `overlap()` 的四种结果映射成排班判定：

| `OverlapKind` | 条件 | 判定 |
|---|---|---|
| `DISJOINT` | 文件不相交 | ✅ 可并行 |
| `SAME_FILE_DIFFERENT_SYMBOL` | 两边都写了 `symbols`，符号不相交 | ✅ 可并行 + **提醒**「同文件 / 撞了就 rebase」 |
| `SAME_FILE_SAME_SYMBOL` | 符号有交集 | ❌ 串 |
| `WHOLE_FILE` | 至少一方没写 `symbols`（整文件） | ❌ 串（**= 今天的 `files_intersect()`，向后兼容**） |

★ 接入点（后续小卡动）：`tools/pool/plan.py` 的 `files_intersect()`（改成"按路径分组再逐组判
符号级"）、`validate()` 的冲突段、`greedy_pack()`、`wb_plan.py` 的 CLI 与文案、
`tests/test_wb_plan.py`。**这五个此刻是卡 157/161 的域** —— 见 §4。

### 3.4 向后兼容（硬要求，已用钉子证）

**不带 `::`** 的声明（= 今天队列里的**全部**声明）⇒ `overlap()` 的判定与
`tools/pool/plan.py::files_intersect()`**逐字相同**；钉子 4 直接对着**真源**交叉核（不是自己另写一份规则）。

## §5 风险（如实写）

1. ★★ **符号级判定是概率性的，不是保证**：文本级合并工具会**漏检 75~79% 的编译期 / 动态冲突**
   [arXiv:2102.11307]；轻量 Git 特征预测冲突 98% 精度 / 96% 召回 [arXiv:1907.06274] —— **是预测**。
   ⇒ 符号不相交只说明**大概率**能并行，**落地撞了就 `rebase` + 留痕**（写进接线卡的验收）。
2. ★★ **判据不许拍**：接线后要**实测两个数**才算答完这张卡的问题 ——
   ① **同批并行度提升多少**（例：10 张 `wb_dispatch.py` 卡从 10 批压到几批）；
   ② **落地冲突率涨了多少**（需要 rebase / 真冲突的笔数占比）。
   **这两个数才是"值不值得"的答案**，不是符号级判定本身。
3. ★ **文献站位**：本卡走「**冲突要预测，而不是禁止并行**」这条路（[1907.06274] 可预测；
   高冲突下乐观并发反而更优，first-committer-wins [arXiv:2110.03028]；并行候选 + 差分验证
   [arXiv:2106.01154]）—— 但**绝不把预测当保证**（见第 1 条）。
4. ★ **"假并行"是最贵的失败**：两张卡被判可并行却在同一符号里各写各的 → 落地必撞、且是**静默**
   撞（排班器这一关放过了它）⇒ 所以钉子 5 专门钉死「符号写错 → 红，不许静默降级成整文件」。

## §6 为什么这么做 / 怎么发现的

- **为什么**：用户 2026-10-03 16:5x 问「有的不得不串行的工作，能否实现并行？」—— 本卡回答最便宜的
  一半：**把"假不得不"（同文件）从"真不得不"（判据依赖产物）里分出来**，并给出可用的尺子。
- **怎么发现的（一个真数字）**：`wb_plan.py plan` 现量显示 10 张卡**各自独占一批**，
  只因为它们声明了同一个文件；而 git 的合并是行级 —— **域检查粗于合并粒度**这一句是被排班输出证出来的。
- **怎么防假绿**：钉子 5 的**突变检验**真跑过 —— 把 `declared_symbols` 的"未知符号"分支
  故意改成 `return {WHOLE_FILE}`（静默降级）→ `test_nail5` **当场红**（`DID NOT RAISE UnknownSymbolError`），
  还原后 12 passed（真输出见卡 188 回报）。
