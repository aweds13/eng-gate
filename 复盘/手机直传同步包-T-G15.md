# 复盘 · 手机**直接上传**同步包（跨端延伸 / G 批 · T-G15）

> 触发：用户 2026-09-23「全做」——交接文档里那条"跨端延伸：手机**直接上传**同步包
> （现在仍要"导出文件 → 拷到电脑"）"。这也是本批最后一张卡。

## 一、这一卡在说什么

跨端三步（③ 走文件 / ① 手机离线记 / ② 同一 WiFi 直连）都已落地，但手机上记完东西之后的
动作仍然是"**导出文件 → 拷到电脑 → 电脑上选文件导入**"：手机明明已经连着电脑（② 已经打通），
却还要绕一个文件。

这一卡就是把最后这一段接上：**手机连着电脑时，点一下"直接传到电脑"，包就过去了。**

## 二、那条一直没定的口径："上传时谁合并"

交接文档里这句话出现过两次（T-G8 与 T-G10 的遗留）：
> 手机直接上传同步包（会引入"上传时谁合并"，值得单独定一次）。

**答案其实前面的卡已经给过**：合并规则（LWW 判新旧、墓碑、冲突留痕、幂等）**只有一处实现**，
在电脑上（`core/syncpack.py::plan_merge`）。手机侧从来不判谁新谁旧 —— 它只负责
"把用户离线记下的行装成同一个格式的包"。所以上传时**依然是电脑合并**，
手机只是**换了一条把包送过去的路**（不再经手文件）。

于是这一卡**没有引入任何新口径**，也没有新增合并逻辑：它复用的就是
`POST /api/sync/import`（那个接口本来就接受 `pack` 内容，不只是文件路径）。
这跟"手机离线记"当初的判断是同一条：**判断只在电脑一处**，手机不做半套。

## 三、落地

| 层 | 落点 |
| --- | --- |
| 界面 | 离线页新增「**直接传到电脑**」按钮（排在"导出同步包"前面）+ 说明那几行；状态卡的两句话也跟着改准 |
| 引擎 | `offline.js::packOnce()` 现在**连 `pack` 对象一起返回**（上传发的是它，界面不再把文本反解一遍） |
| 接口 | 复用 `POST /api/sync/import`（已配对设备本来就能调 —— `require_local_origin` 认配对） |
| 边界 | ★ **局域网设备只能传内容（`pack`），不能指路径（`path`）** —— 见下 |
| 验证 | `tests/test_phone_upload_line.py`（5 条）+ 真机自检 4 条（真局域网地址 + 真配对码 + 真 HTTP） |

交互上的三件"说实话"：

1. **传之前问一次**（`confirmAsk`）：包里是什么、要合并进电脑的库；
2. **传成功之后才问要不要清队列**（数据已经在电脑库里了）；**传失败绝不清空** ——
   代码结构上就写死了：`clearQueue` 只出现在成功返回之后那段；
3. **离线时直接说清**（"先导出同步包，等连上再点这里"），而不是让请求失败后让人猜。

## 四、顺带补的一个真边界：配对 ≠ 可以指路径（第一版判错了，被老用例抓住）

`/api/sync/import` 有两种送包方式：`pack`（**包内容**）与 `path`（**在电脑上读一个文件**）。
② 打通之后，配对过的手机也能调这个接口了 —— 于是 `path` 就成了一个多余的口子：
**配对码证明的是"你是本人"，不是"你可以让这台电脑去读盘上任意一个路径"**。

所以这次顺手收窄：局域网来源的请求不许指路径，带 `path` → **403 + 原话**
"请把包的内容（pack）直接发过来（手机上的「直接传到电脑」就是这么做的）"。

★ **第一版判据写错了**：我按 **TCP 来源地址**判（`request.client.host` 不是回环就拒），
结果**误伤了本机脚本** —— `TestClient` 的来源地址是 `testclient`（不是回环），
于是三个老用例（"自己的包 400""按路径预览"）当场变红。真实世界里也一样：
本机脚本 / curl / 反向代理后面都可能不是回环地址。

正确判据是**页面来源（Origin）**：手机是"从局域网地址打开的那个页面"（带局域网 Origin），
而本机脚本**没有 Origin**、本机页面是回环 Origin。改完之后：局域网页面 403、
本机页面与脚本照旧 —— 三条路都有测试钉着。
**教训**：判"谁在调用"要看**它自己声称的来历**（页面来源），别拿网络层地址当身份。

## 六、遗留（如实写）

- **不做自动上传**：队列不会自己飞过去 —— "数据离开这台设备"该由你点。
- **不做双向**：电脑不会把东西推回手机（手机没有库、不做反向合并），这仍与 T-G10 的口径一致。
- **上传不带"删除"**：手机侧本来就不产生删除（离线只做新建/完成/撤销/打卡/备忘/反馈），
  所以这条路上不涉及 `apply_deletions`（那颗勾选框只在电脑的设置页，默认不勾）。
- 手机上还没有"看电脑回了什么"的界面：合并报告只在**当下那条 toast** 里说一次
  （新增/覆盖/保留/冲突条数）。要看细节仍得回电脑的「跨端同步」看冲突日志。
