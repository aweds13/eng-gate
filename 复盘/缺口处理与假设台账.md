# 复盘 · 缺口处理与假设台账

> 目的：当规格没有写清用户逻辑时，把「脑补」变成「可追溯的默认假设」或「明确的决策点」。
> 适用范围：所有域、所有操作、所有边界。
> 与 conventions 冲突时以 conventions 为准，并升级为决策点。

---

## 一、处理流程

1. 识别缺口：属于产品规则 / 交互体验 / 技术行为 / 边界异常？
2. 找上游依据：N、SR、conventions、既有 contracts / ACCEPTANCE、taste。
3. 生成默认方案：优先最小侵入、可逆、温和、与同类操作一致。
4. 评估影响：用户可见？不可逆？跨模块？改核心心智？
5. 处置：
   - 可逆、非核心：写入台账，带默认值继续执行；
   - 不可逆 / 核心心智 / 与红线冲突：停下，列为决策点等用户确认。
6. 回填：更新对应规格 / 契约 / 验收 / 测试；台账标记状态。

## 四、更新规则

- 任何批次发现新缺口，先登记再实现。
- 台账是「事实来源」之一；与 conventions 冲突时以 conventions 为准，并升级决策。
- 已采用的假设若后续变更，必须在复盘 / 交接留下变更记录。
