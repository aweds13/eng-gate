# 复盘 · 缺口处理与假设台账

> 目的：当规格没有写清用户逻辑时，把「脑补」变成「可追溯的默认假设」或「明确的决策点」。
> 适用范围：所有域、所有操作、所有边界。
> 与 conventions 冲突时以 conventions 为准，并升级为决策点。

---

## 一、处理流程

1. 识别缺口：属于产品规则 / 交互体验 / 技术行为 / 边界异常？
2. 找上游依据：N、SR、conventions、既有 contracts / ACCEPTANCE、taste。
3. 生成默认方案：优先最小侵入、可逆、温和、与同类操作一致。
4. 评估影响：用户可见？不可逆？跨模块？改核心心智？
5. 处置：
   - 可逆、非核心：写入台账，带默认值继续执行；
   - 不可逆 / 核心心智 / 与红线冲突：停下，列为决策点等用户确认。
6. 回填：更新对应规格 / 契约 / 验收 / 测试；台账标记状态。

## 四、更新规则

- 任何批次发现新缺口，先登记再实现。
- 台账是「事实来源」之一；与 conventions 冲突时以 conventions 为准，并升级决策。
- 已采用的假设若后续变更，必须在复盘 / 交接留下变更记录。

## 五、变更记录

- 2026-09-18（第 2 步子任务 1/2）：
  - A-011 由「自动值为底、手动只增不减」改为「派生重算」——原因：`focus_minutes` 若同时支持增量与手动，
    会出现 facts 与列值漂移（第 1 步已把投入口径收拢到 facts）；改为每次按当日事实重算，口径唯一、天然幂等。
  - 新增 A-014（撤销完成恢复状态）。
  - A-003 状态推进：撤销机制已在任务域落地（`task.uncompleted` 成对事实），仍未做 UPDATE 历史。
- 2026-09-18（第 3 步旧数据迁移）：
  - 新增 A-015（历史复习记录不回填，只记缺口）。
  - schema v5：历史**已完成任务**幂等回填 `task.completed` 事实；归属时间取 `updated_at`（完成时最后写入），
    缺列/缺值时退回 `created_at`；`extra.migrated=True` 标明来源；只回填「完成」状态，不做反向猜测。
- 2026-09-18（第 5 步手动投入物化）：
  - 新增 A-016：手动投入单位定为**秒**（用户确认）；摘要单列 `manual_hours`，**不并入** `invest_hours`。
  - `ledger_entries` 至此仅为兼容/迁移来源（手动投入与手动产出都已走事实层）。
