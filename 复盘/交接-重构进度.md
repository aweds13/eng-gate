## 一、这是什么项目

**timeflow** —— 本地优先的个人「时间与学习投入」管理工具。
核心心智：**债务/储蓄如实记账**（逾期=债务、专注=投入、完成=收益）。

项目根：`D:/repo/engineering\`

### 文档体系（五层，各有分工）
```
docs/
├─ intention/       为什么做（N1–N46）——含「结构读法：一框架×多线×多交叉×多节点」
├─ specification/   必须做到什么
│   └─ conventions.md  ★ 约定层：横切基线（不能违反什么），实现前必读
├─ contracts/       ★ 怎样才算真的做成
│   ├─ interactions.md  单个操作六要素（入口/前置/输入/后续/可逆/反馈）
│   └─ flows.md         多操作动线（触发→传导→落点）
├─ implementation/  哪个模块负责
├─ taste/           技术品味（当前为空壳，待完善）
├─ ACCEPTANCE.md    验收（★「闭环验收」章节 = 现行标准）
├─ CODING_GUIDELINES.md / README.md / changelog.md
└─ （DESIGN.md / LEARN.md 曾补建后**经用户决定撤回**，暂不建）
```

## 三、关键决策（新对话必须知道）

1. **方向：修复，不重写。** 后端 90% 可用（60 项测试全绿），问题在「缺联动 + 前端薄」。

2. **架构核心：事实与解读分离。**
   - **事实层**（已建）：只记「发生了什么」，与心智模型无关
   - **解读层**（= ledger）：按当前心智模型算成"账目"
   - **换心智模型 = 只换解读层，事实不动**（这是用户最关心的能力）

3. **表设计三原则**：
   - `kind` 自由字符串（加新事实类型**不改表**）← 真正的扩展点
   - 高频值放 `value_num`/`value_text` 公共列；`extra` JSON 只作兜底
   - `revision`/`supersedes` **预留但不实现**（MVP 不做修正机制）

4. **事件驱动用「同步执行」**（非异步队列）：本地单机无性能压力，强一致、易调试。

5. **实测确认的断点**（重要，别再凭读代码猜）：
   | 项 | 实测 |
   |---|---|
   | 专注结束 → 摘要投入 | ✅ **没断**（0.42h 真进账了，实时聚合） |
   | 专注 → 当日反馈自动累加 | ❌ 断 |
   | 专注 → 累加绑定任务时长 | ❌ 断 |
   | 完成 → 记投入账 | ❌ 断 |
   | Repeat 触发 | ❌ 死代码（无端点） |
   | 产出轴 | ❌ 断（无写入） |

6. **MVP 范围** = 框架（账本）+ 2 条线（任务、专注）+ 全部交叉。
   其余（复习/学业/团队/备忘录/分组/习惯/同步/PWA）**延后**。

7. **事实语义（第 0.1 步已修）**：只有正常结束记 `focus.finished`；暂停/放弃/记中断分别记 `focus.paused/abandoned/interrupted`，避免第 1 步误计入投入。

8. **历史数据**：schema v4 幂等回填历史 `focus_sessions` → facts（第 0.1 步）；schema v5 幂等回填历史**已完成任务** → `task.completed`（第 3 步）。历史复习记录无逐次时间戳，**不回填**（A-015）。

9. **存储边界**：按 conventions 数据分流——计算型事实（专注/完成/复习等）走 SQLite facts；沉淀型内容（任务/备忘录/产出）走 Markdown（目标态，第 3 步定契约）。

10. **约定固化（用户确认）**：「事实/解读分离」已写入 `docs/specification/conventions.md`（固定口径）——事实只记「发生了什么」，ledger 按当前心智模型算账；换心智模型只换解读层。
