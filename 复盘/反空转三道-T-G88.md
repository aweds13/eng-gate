# 反空转三道：回合上限 / 看门狗 / 心跳（T-G88）

> 一句话：工人在**别的进程**里干活，主控看得见的只有它落的 log —— 所以三道护栏全建在这份 log 上。
> 用户 2026-09-26 点名要"检测心跳的方式保证"，这就是答案。

## 1. 为什么要有（两种"等"）

没护栏的时候，主控在工人跑的那一小时里**什么都看不见**，于是两种"等"都会发生，而且**都不报警**：

- **卡死**：进程还活着、日志一行不涨（模型/网络吊住、工具死循环在某处）。主控只能干等，
  等到 `--timeout`（默认一小时）才发现白等；
- **空转**：它**一直在动**，只是原地重复同一件事（读同一个文件、跑同一条命令），
  每一轮都可能烧掉真金白银的时间。

这两种都不是"报错"，所以没有任何东西会红 —— 这正是最该被机器盯住的那一类。

## 2. 三道

| 道 | 判据 | 默认 | 触发之后 |
|---|---|---|---|
| ① **回合上限** | `--max-turns`（进 CLI 命令行） | 写卡 **150** / 只读卡 **60** | CLI **自己停**（退出码仍 0）→ 跑完判「没做完」，脚本退 6 |
| ② **看门狗·卡死** | 日志静默 ≥ `--stall-seconds` | **480 秒** | 掐掉整棵进程树 + 报现场，退 6 |
| ③ **看门狗·空转** | 最近 12 次工具调用里同一（工具+参数）出现 ≥ **5** 次 | 5 | 同上 |
| ④ **心跳** | 每 `--heartbeat-seconds` 打一行 | **120 秒** | 只打印（让"它在动"看得见） |

心跳长这样（一眼看出它跑到哪了，不用去翻 log）：

```
[心跳] 已跑 10.2 分钟 | 回合 90 | 工具 111 次 | 碰过文件 21 个 | 日志静默 3 秒
```

## 3. 上限是**标定**出来的，不是拍的

> ★ 本节的两个数字（150 / 60）**已被 §7 更正为 240 / 80**：上限数的是**工具调用回合**，
> 不是 `result` 里的 `num_turns`（那是另一个计数器，卡 002 = 319）。下面的过程留着 ——
> 它记录了第一次是怎么想的，以及探针是怎么把它拦下来的。

卡 002 那轮真 log（`gates/diag/wb-002.jsonl`）量出来的数：

```
回合（assistant 事件的 message.id 去重）= 90
assistant 事件 = 206      （同一条回合会发几条事件：文本一条、工具一条）
工具调用 = 111            工具报错 = 0
```

**90 个回合**才收工 —— 所以第一版想要的"写卡 60"会把**正常的卡腰斩**。现在写卡 150（1.6 倍余量）、
只读卡 60。这条数字也顺手把两个函数的判据钉上了：`turns_seen()` 按 `message.id` **去重**数回合，
不是数事件（数事件会多算一倍多）。

★ 撞上限时 **CLI 自己停、退出码仍是 0** —— 要是只看退出码，腰斩会被当成成功。
所以跑完还有一句 `cap_verdict()`：「没做完：回合数 N 撞到上限 M」。

两条 CLI 参数都对过 **2.158.0 的 `--help`**（不是照记忆写的）：

```
--max-turns <number>            Limit the number of agentic turns
--autocompact <auto|tokens>     … (e.g. 400000, 400k, 1m; clamped to 100k-1M)
```

## 4. 证据：真跑（不是假 runner）

三道里只有②③会"动刀"，所以**必须真跑**一遍 —— 假 runner 证明不了它真能把工人停住。
`tests/test_wb_dispatch.py` 用**桩命令**（吐事件然后装死 / 原地重复）真起进程：

| 用例 | 桩子行为 | 断言 | 实测 |
|---|---|---|---|
| 健康的一轮 | 吐 2 条事件后退出 | 落盘、退 0、**不掐**（reason 空） | 0.25s |
| **卡死** | 吐 1 条事件然后装死 60 秒 | 阈值 2 秒 → `卡死` + 真被掐 + 现场里有它最后那步 + 心跳真打了 | **2.81s**（没等它 60 秒） |
| **空转** | 吐 6 条**一模一样**的调用然后装死 | 日志不静默也算出 `空转` 并掐掉 | 0.70s |

测试条数 12 → **23 条**；跑法：`python -X utf8 -m pytest tests/test_wb_dispatch.py -q --no-cov`。

**自己踩的一个坑（留档）**：第一版主循环是 `while proc.poll() is None: … time.sleep(poll_seconds)`
—— 工人**已经收工**了还要白等一个轮询周期（实测健康那轮 5.06 秒）。改成
`proc.wait(timeout=poll_seconds)`：它一退出就立刻返回，同一用例降到 **0.25 秒**。
（`--execute` 那条路本来只多几秒，但"每轮都白等"这种事会一路积少成多。）

## 5. 边界（如实写，不假装）

- 空转只抓**完全一样**的调用（同一个工具 + 同样的参数）；参数每次差一点点的"原地打转"抓不到 ——
  那一类靠**静默超时**兜底。两条判据互为补集，不是"一条就够"。
- 判据每轮把已落的 log **整段重解析**（简单、够快：卡 002 那种量级 300 多条事件是毫秒级）；
  真跑出几万条事件再谈增量。
- 掐的是**按 PID 的整棵进程树**（`taskkill /F /T /PID`），**不按进程名** —— 按名字会误伤同名的别的进程。
- ★ **"真掐"还没在真工人身上触发过**：真跑过的是它"能不能掐"（桩命令），
  真机上"该不该掐"的阈值（8 分钟 / 5 次）得靠头几轮派活校准 —— 头一轮要是被误掐，
  就把阈值放宽并把那次记进这个文件。
- 心跳是**行数**不是 UI：它只说"它在动 + 跑到哪了"，不判断内容对不对。

## 6. 没动的

- `tools/wb_status.py` 一行没改（判据复用它的 `parse_events`，不写第二份解析器）。

- `--effort` **不加**：按用户 2026-09-26 的决定保持 CLI 默认（High）。

## 7. ★ 2026-09-26 更正（T-G89）：上限数的是**工具调用回合**，而撞上限是**静默腰斩**

§3 那两个数字（150 / 60）与那条判据都改过了。**发现方式**：T-G88 落盘之后，我拿真机探针先验一遍
"这个上限到底怎么数" —— 两处错都不是靠推理能发现的。

**① 口径**：`result` 事件里有 `num_turns`，卡 002 = **319**；而 §3 的标定按 `message.id` 去重数是
**90**。谁对？探针说话（真机）：

```
--max-turns 2 + 一个「依次跑 6 条 Bash 命令」的活 → 只跑了 2 次工具调用；
               result.subtype = error_during_execution，回话是空的，退出码 0
--max-turns 8 + 同一个活                        → 跑满 6 次；subtype = success，回话完整
--max-turns 1/2/6 + 一个不用工具的问题           → num_turns 都是 3（说明被卡的不是这一格）
```

结论：`--max-turns` 数的是**工具调用回合**（卡 002 实测 **111 次工具调用** / 88 条带工具调用的
assistant 消息），而 `num_turns`(=319) 是**另一个**计数器（多半把内部请求、自动压缩那些也算进去了）。
★ 两次差点犯错都被探针拦住：照 60 定会把卡 002 **腰斩**；照 319 定会把上限抬到 600（放到天上）。

**② 判据**：撞上限时 `subtype = error_during_execution` + **回话是空的** + **进程退出码仍是 0** ——
只看退出码就会把"腰斩"当成成功。

**改法**：上限 → 写卡 **240**（≈2.2 × 卡 002 的 111）/ 只读 **80**；新增 `finish_verdict()`：读
`result` 事件判"到底跑完没有"（没有 result 事件 / `subtype != success` / 回话空 → 都算**没做完**）。
它与"数回合"**互为补集**：数回合是提前预警，读事件才是硬证据。测试 23 → **25 条**
（新增：`finish_verdict` 四种形状 + "退出码 0 但 stream 说 error_during_execution → 必须报没跑完"）。

**边界（照样如实写）**：`--max-turns` 与 `num_turns` 的确切定义仍是从**行为**反推的
（CLI 的 `--help` 只写 `Limit the number of agentic turns`）—— 哪天真机行为对不上，以探针为准；
上限给得宽是**故意**的（护栏的目的是掐跑飞，不是卡正常卡）。
