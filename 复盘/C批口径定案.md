## 二、T-C1 习惯：只报次数、并排显示（不折算）

**为什么不能"算进投入小时"**：投入轴单位是**小时**（专注 `focus.finished` 秒 / 手动 `invest.manual` 秒），
而"把打卡**折算**成分钟"正是项目**已砍概念**（`check_layers.py` 的 FORBIDDEN 里就有「时间折算 / 折算成」；
needs.md 也写着债务只记天数程度、不折时间）。所以"习惯算不算投入"这个提法本身撞红线 ——
**换成的问法是：习惯要不要在投入旁边被看见**。用户选择：**看见，但只报次数**。

**怎么做**：
- `ledger.summary()` 增 `habit_count`（今日打卡次数，**只读计数，不进 `invest_hours`**）；
- `ledger.weekly_summary()` 增 `habits_done`（本周打卡次数）；
- 前端两处并排显示：顶部摘要行 + 专注页「本周投入」数字行（写成「习惯 N 次」，与小时并列、不合并）；
- 想让它真的占用投入时间的人，走**已有的手动补记**（备忘录页手动投入，kind 可选「习惯」）——
  **自己填真实分钟，不猜不折算**（习惯页加一句指路）。

## 三、T-C4 产出分区 + **新需求：可点开的完成明细**（T-C11）

### 3.1 产出分区（原需求）
数据里**已经有分类**（`output.manual` 的 `value_text` = `kpi` / `asset`），只是显示成一个总数。
改成两行：`今日产出：学校 KPI 2 条 · 知识资产 3 条`（数字仍来自同一事实层，只是分组显示）。

### 3.2 新需求（用户原话要点）
> "我点那个今日产出，学校 KPI 两条、知识资产三条，**点这两个文字，会像选项卡一样蹦出来**，
>  然后蹦出我完成哪些 KPI。
>  因为这种任务不一定（一天推完），**大任务很难一天全部推进完**，
>  所以我感觉**突出我完成哪些步骤也很重要** —— 希望能看到自己完成哪些子步骤。"

**设计（T-C11）**：
- 后端新增只读接口 `GET /api/today/done`（名字待定），一次给出"今天做成了什么"：
  - `tasks`：今天完成的任务（`task.completed` 事实，`occurred_at` = 今天，非子任务）；
  - `steps`：今天完成的**子步骤**（同一天事实，且有 `parent_id`），带父任务标题；
  - `parents`：这些子步骤所属的父任务 + **今天完成了几步 / 该父任务共几步**（"大任务推进到哪"）；
  - `outputs`：今天的产出条目按 `kind` 分组（kpi / asset），带数量、备注、时间、是否已撤销。
- 前端：今日页一条「今天做成了什么」区，三个可点击的**选项卡**（默认收起）：
  1. `完成任务 2 项` → 展开任务列表；
  2. `完成步骤 5 个（属于 3 个任务）` → 展开，**按父任务分组缩进**，并显示父任务进度（如「高数作业 2/5」）；
  3. `产出：学校 KPI 2 条 · 知识资产 3 条` → 展开该类的产出明细（备注/数量/时间；已撤销的如实标注）。
- 口径：全部**只读事实层**（`facts` + `habit_logs`/产出事实），不新造派生表；数字与展开明细同源，
  **不出现"总和对不上明细"**。

## 四、T-C9 三类任务：不加字段，改规格

**用户决定**：不加 `tasks.category`。**"哪件事不能拖"用「优先级（高）」+「学校硬考核强提醒」表达**
（后者 = T-C8 强弱提醒分级），三类任务字段要求从一版规格里去掉（**改规格，而不是让代码假装做到**）。

**为什么要改规格**：`docs/specification/functional.md` 的 SR-F1.9（源于 N45）字面要求区分
①有指标类 ②逾期不候·作业/考核 ③逾期不候·竞赛/活动；审计记为 GAP-F1-07（无字段、无界面）。
既然决定不做这个字段，就必须**同步规格与台账**（状态改 `deferred` 并写依据），
否则"规格说有、代码没有"的缺口会一直挂着（这正是审计要抓的东西）。

**T-C8（强弱提醒分级）因此成为这条决策的落地项**：
学校硬考核（考核项有 `due_date` 且未录成绩）在界面上**更强**呈现（文案/颜色/位置），
普通任务逾期保持温和 —— 对应 N45「逾期提醒分级（强/弱）」，且**不施压、不告警**的基调不变。

## 六、T-C12：任务「类型 + 所属课程」（用户中途补充要求）

**用户原话（2026-09-19）**：
> "有的作业任务它是课程相关的，就是我希望你那种任务这样，我能选择它是作业类型的话。我能绑定到那个课程上。"

**结论**：
- 任务上加两列：`task_type`（**普通 / 作业 / 考试 / 论文 / 小测**，默认「普通」）+ `course_id`（→ `courses.id`）。
  类型词表**复用 `course_assessments` 已有的四种学校事项**（考试/作业/论文/小测），不另造说法。
- **与 §四 的 T-C9 不冲突**：T-C9 决定不做的是"三类任务（有指标/作业考核/竞赛活动）**分类字段**"，
  回答的是"这件事**属于哪一类**、要不要强债务"；T-C12 只回答"这件事**属于哪门课**"，是**指向具体课程**的关联。
  所以这里加字段**不等于**推翻 T-C9 —— 不是分类法，是一根指向 `courses` 的线。
- **一条口径**：**「普通」不挂课程**（挂了课程就等于说"它属于某门课"）。校验按**改完之后的状态**判，
  非法类型 / 课程不存在 / 普通+课程 → 拒绝 + 人话（**不静默降级、不静默清空**）。
- **弱关联**：不建外键、删课程不级联；任务照旧活着，只显示「课程已删」；重复任务回落"不挂课程"继续生成。
- **反向要能看见**：学业页课程卡列出挂在该课上的任务（未完成优先）——不然"绑到课程上"只做了一半。
- **不做**（如确需另开一条）：任务 ↔ `course_assessments` 考核项的互链；按课程统计投入/产出。

> 注：末一条"按课程统计投入/产出"在 2026-09-20 被**部分推翻** —— 用户为 T-C10 定了
> 「学业投入 = 只算挂了课程的任务专注」，于是**按课程归属**的投入对照图做了（见 §七）。
> 差别在于：做的是**全局的学业 vs 自学对照**，不是"每门课各自的投入报表"。

| **T-C2** | 复习完「记一笔产出」的入口形态 | **想记才点**：复习完成的 toast 上给一个「记一笔产出」按钮（**不自动弹窗、不打断复习**） | `review()` → `toastAction(...)` → `reviewOutput()`（`kind=asset`，入知识资产） |
| **T-C10** | 「学业投入」怎么算？ | **只算挂了课程的任务专注** | `insights.academic_vs_self()` + `GET /api/insights/academic-vs-self` + 统计页对照图 |

### 7.1 T-C8：为什么"只做视觉"

「强提醒」很容易滑向施压（红色闪烁、声音、弹窗），而本项目约定层写死了**温和不施压**。
所以"强"只体现在**可读性**上：位置更前（置顶）、标识更明确（角标 + 更粗左边条）、
理由写清楚（"逾期不候：交了就计成绩，没交就没了"）。
**判断"强"的基准是旁边的普通任务逾期**：普通逾期仍是细左边条 + 温和文案；硬考核才升级。

### 7.2 T-C2：为什么"想记才点"

复习是**高频动作**，每次完成都弹一个输入框会变成拦路虎（也正是"温和不施压"要避免的）。
但"想记的时候找不到入口"又会让这条链路等于没有 —— 折中是**把入口挂在 toast 上**：
完成复习后 6 秒内可点，不点就自然消失，不打断。产出固定入**知识资产**
（温故知新 = 新理解/笔记/灵感），不让人再选一次类别。

### 7.3 T-C10：为什么"只算挂了课程的任务专注"

替代方案是"含考核项"或"含手动补记里 kind=学业的部分"，但两者都会让读数**说不清来源**
（考核项本身不是一个计时主体；手动补记的 kind 是自由文本，靠人填对）。
选"只算挂了课程的任务专注"的好处是**一个口径一句话讲得清**，且与 `group_insights` 的取向一致：
**只统计绑定了任务的专注**，未绑定任务的专注**单列、不归入任何一边**（不制造假归因）。
手动投入不参与这张图（它按口径就不绑定任务）。**不做"学业该占多少"的建议**。
