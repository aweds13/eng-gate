## 三、判定标准

**一个文件属于哪一层，取决于它回答的问题：**

1. 回答「为什么做、满足谁、痛点」→ **intention**
2. 回答「必须做到什么、如何验证（行为与约束）」→ **specification**
3. 回答「如何实现、模块职责与取舍（计算的抽象原则）」→ **implementation**

### 关键判断说明

- **intention 层**只谈动机、痛点、原始需求，不涉及「必须做到什么」。`needs.md` 中虽夹有「已定口径/决策」（如 Repeat 规则、FSRS 库、PWA 方案），这些是**需求文档内部对需求的细化与决策记录**，文件整体仍属需求清单，不能据此拆走。
- **specification 层**输出为「可验证契约 / 必须…」。`specification/traceability.md` 输出的是**规格（SR）**，属规格层校验。
- **implementation 层**输出为「模块名 + 职责 + 取舍」的抽象。`implementation/traceability.md` 输出的是**模块落点**，属实现层校验。

### 追踪矩阵为何「就地正确」

两份 `traceability.md` 都**跟着自己验证的下游层走**：spec 矩阵验证「意图→规格」，impl 矩阵验证「规格→实现」，且各自被本层 README 引用，定位自洽。
