# 复盘 · 复习「改判」（F6 OP-27 可逆的延伸 / G 批 · T-G13）

> 触发：用户 2026-09-23「全做」——把交接文档里列出的剩余可选方向逐张做完（这是第二张）。
> 交接卡里这条写的是「复习『改判』反馈；契约 `docs/contracts/domains/F6-review.md`；
> 撤销已实现；改判涉及 FSRS 参数重算」——所以这一卡要解决的就是"重算"这件事。

## 一、这一卡在说什么

现在复习完只有两条路：**撤销**（当这次没发生）或**认了**（排期按错的档走）。
但真实场景是"手滑点错了"——你其实想点「模糊」，结果点了「忘了」。
撤销再重来当然也行，可那样用户得点两次，而且**"撤销"这个词读起来像"删掉"**，
不像"我记错了，改成另一档"。

契约 OP-27 的「可逆：可撤销本次反馈」已经把这扇门开着；这一卡把门后面的动作补全。

## 二、口径：改判 = 撤销 + 按新档重来（不新增口径）

实现上最容易走偏的一条路是"**自己写一套重算**"（拿当前的 interval/ease 再乘一次之类）——
那条路必错，因为 FSRS 的 next 值依赖**进入这一次复习之前**的卡片状态，
而"改判"要的正是"当时就点另一档"的那个结果。

所以做法是**复用两条既有路径**：

```
regrade(item, 新档) = undo_review(item)          # ① 退回"复习前"的快照（原事实留着，追加 review.undone）
                    + review(item, 新档)         # ② 走**完全相同**的复习路径（FSRS 重算 + 写新事实 + 计账）
                    + 记一条 review.regraded      # ③ 留痕：从哪一档 → 到哪一档
```

由此直接得到三条性质（都是**测试钉住的**，不是"应该"）：

1. **改判 ≡ 当时就点那一档**：拿两张卡做对照，一张直接点「忘了」，一张「记得」后改判成「忘了」
   → 到期日/间隔/次数/遗忘次数**逐项相等**；
2. **投入不重复计**：账本按"当日有效完成事实（同卡只算一次）"计数，所以改判 1 次、连着改判 3 次
   `review_count` 都是 1（`invest_hours` 也始终只认专注）；
3. **改判不抹掉历史**：原来那条 `review.completed` 不删，追加 `review.undone` 指回它，
   再写新的 `review.completed` + 一条 `review.regraded` —— 流水上看得出"改过"。

拒绝的情况一律 **400 带原话**（不静默、不假装成功）：
今天还没复习过这张卡 →「没有可以改判的反馈」；给的档和原来一样 →「不用改判」；非法档 →「非法反馈…」。

## 三、落地

| 层 | 落点 |
| --- | --- |
| 领域 | `review.regrade()` + `review.reviewed_today_items()`；`_pending_last()` 抽出来给撤销与改判**共用** |
| 接口 | `POST /api/review/{item_id}/regrade`、`GET /api/review/today` |
| 词表 | 三档中文（记得/模糊/忘了）下沉到后端 `meta.ratings`；界面三态按钮与改判按钮都从它渲染 |
| 界面 | 复习页新增「今天复习过的」一段：显示今天记的是哪一档 + **只给另外两档**的「改判为」按钮；复习完成的提示里加一句"记错了可以在下面改判" |

`_pending_last()` 是顺手的收益：原来"当日最近一次未撤销的完成事实"这套判据只写在 `undo_review` 里；
现在撤销与改判共用一份 —— 两份实现迟早会出现"一个认为有、一个认为没有"。

## 四、踩到的坑（都是真事）

1. ★ **`reviewCard()` 还有第二个调用点**（探针抓到的）：我把签名改成 `reviewCard(r, ratings)` 后，
   今日页那句 `due.map(r=>reviewCard(r))` 就传了一个参数 → `ratings.map` 报
   `Cannot read properties of undefined`。**单元测试全绿、前端字符串断言全绿**，
   是假 DOM 探针把它抓出来的（9 条运行时异常 + 今日页/债务卡/状态机几档跟着红）。
   教训：**改函数签名前先搜一遍调用点**（`grep reviewCard(`），别只看眼前那个视图。
   修法：今日页也拉一次 `/api/review/meta`，把 `ratings` 明确传进去。
2. **我自己写的探针断言切错了段**：`html.split('今天复习过的', 2)[1]` 之后又想在那一段里找
   `今天复习过的（1）` —— 被切掉的分隔串当然找不到。改成按带计数的那句切，并在注释里写明
   `[1]` 是"之后的那一段"。
3. **测试里对事实条数的预期算漏了对照卡**：`test_regrade_twice_...` 里为了对照建了第二张卡，
   它自己也写一条 `review.completed` → 总数是 4 不是 3。预期写错而不是代码错，改预期并注明原因
   （对照卡那一条为什么在）。

## 五、边界与遗留

- 「改判」只对**今天**、且只对**最近一次**有效（与撤销同一口径）：上星期的反馈改不了，
  同日多次改判只影响最后一次 —— 这不是限制，是"当时记的是什么"本来就是瞬时事实。
- 契约 OP-26 写着复习卡「可逆：可删除」，但**目前没有删除接口**（只有撤销/改判）。
  这属于另一张卡的事（删除要不要连事实一起删、要不要进回收站），**这一卡不顺手发明**，
  在交接文档里如实记着。
- 手机离线记**不含**改判（离线队列只做"记一笔"那几件事）：改判要重算 FSRS，
  而合并判断只在电脑一处（跨端口径）—— 手机上不做排期计算。
