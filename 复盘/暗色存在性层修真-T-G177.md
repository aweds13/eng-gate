## 一、病根：一条一直是假的存在性护栏（「手写第二套切法」）

`tests/test_web_frontend.py:78`（**修前**原文逐字）：
```python
dark = css.split('[data-theme="dark"]', 1)[1].split("}", 1)[0]
```
`src/web/app.css` 的**文件头注释**（**第 6 行**）里先出现了 `[data-theme="dark"]` 这句话：
```
 * - [data-theme="dark"] 在 R1 就位、由 R4 接通开关（本轮不改视觉）。
```
于是 `split(..., 1)` 的第一次命中落在**注释**里，切出来的是「注释之后到第一个 `}`」= 整个
`:root` **亮色**块（真暗色块在第 141 行）。→ 名为 `test_css_tokens_exist_and_cover_both_themes`
的那条断言，**一直在查亮色块**：把暗色块**清空**它仍绿（080 实测）、从暗色块**删掉 `--panel-2`** 它也绿。

同类**第二处**：`tools/web_live_check.py:876`（修前）只有
```python
"暗色令牌可取到": '[data-theme="dark"]' in css,
```
—— 只断**选择器字符串**在不在，块里有没有令牌根本不看（清空暗色块照样绿）。

同类**第三处**（080 报告 §四 D/E）：删装饰类暗色令牌（`--border`）无人抓、清空暗色块体无人抓 ——
修好上面那两处即可覆盖（`--border` 在必需令牌清单里）。

## 二、修法（复用令牌层同一条切法，**不再手写**）

- **切法**：`tests/test_web_frontend.py` 与 `tools/web_live_check.py` 都改用令牌层
  `tools/contrast_audit.py::token_blocks` 用的**同一条正则** `\[data-theme="dark"\]\s*\{(.*?)\n\}` +
  同样「**先剥注释**」，取**真暗色块**（`web_live_check.dark_block_text`）。病根就是「手写第二套切法」，本卡把它收成一处。
- **必需令牌集合只有一份**：`tools/web_live_check.py::DARK_REQUIRED_TOKENS =
  ("--bg", "--panel", "--panel-2", "--border", "--ink")`（背景 / 文字 / 表面）；存在性层
  `tests/test_web_frontend.py` **import 它**，两处共用同一份 —— 别两处各写一份。
- **只判「暗色块自己声明的令牌」**：`contrast_audit.token_blocks(css)["dark"]` 是 `{**light, **delta}`
  （亮色块有而暗色块没有的令牌会从亮色"看得见"），判不出「暗色块自己删了一个令牌」；所以取 **delta**
  （`web_live_check.dark_declared_tokens`，用令牌层同一条 `ca._TOKEN` 正则，不手写第二套）。
- ★ **没有碰 `src/`**：改好测试后 `pytest tests/test_web_frontend.py` 直接**绿**（真暗色块的必需令牌是全的），
  按卡的限定条件（「没有变红就不许碰 `src/`」），`src/web/app.css` **一个字节未动**。
