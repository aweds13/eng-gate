# 左栏整理与离线记挪位（T-G162 · 卡 068）

> 2026-09-27 · 树 `.wt/rail2` · 底座 `b90c4e4`（集成十一张那一笔）。

## 一、为什么有这张卡

用户 2026-09-27 两句话：

> 「让我奇怪的是，设置里面没有是说把那个重要 / 有计划 / 已标记那几项放在一起……我没有说切换，把它们放在左栏固定。这个功能你没有吗？」
> 「离线记这个功能，好像我是偏 App 端的，为什么你把它放在 PC 端上了？」

随后用户**更正**（同日）：

> 「我不是说并成一组固定在左栏，我是说能自由选择。」

所以本卡的最终口径是 §2.1 那条：**三项各自一个开关、能自由选哪几个出现在左栏**，不是「并成一组固定」。

### ★ 卡内矛盾与执行口径（如实写）

卡 068 的**标题、§4 提交信息、§5 读数 1** 写的是「默认显示、并成一组」；但操作节 §2.1 写的是
「用户 2026-09-27 的更正原话……三项各自一个开关」「默认沿用今天（三项默认不出现在左栏）……你按本卡执行」，
并且 §2.1 自己的小节标题就是「**不是**三项绑一个开关，也**不是**并成一组固定」。
两处口径直接冲突，**按 §2.1 执行**（它带着用户的更正原话，是更晚、更具体的口径），提交信息按实际行为写。
由此：卡 §5 读数 1（「清空/不设 tf_rail_direct 时左栏看得到三项」）在本实现下**不可能成立**——
未存偏好 → 三项全关（见 §2.1 迁移口径「off/未存 → 三项全关」）。实测读数改为：未存 → 三项全 hidden。
若主控要的是「默认显示」，那是改默认值的产品决定，需另行下卡。

## 二、做了什么

### §1 三项各自独立可选（`src/web/index.html`）

- **设置 → 外观 → 左栏智能视图**：原来的一颗 `left-rail-smart`（「在左栏显示 / 从左栏收起」）拆成
  **三个按钮**，名字显式写出、各自切换，按钮上直接写状态：

  ```html
  <div class="settings-sub">左栏智能视图</div>
  <div class="row tight">${SMART_RAIL_VIEWS.map(v=>
    `<button class="${railViews[v]?'':'ghost'}" data-action="left-rail-view" data-view="${v}">${esc(SMART_VIEWS[v].title)}（${railViews[v]?'在左栏':'不在左栏'}）</button>`).join('')}</div>
  <div class="sub">三个开关各管各的：想让谁出现在左栏就开谁；名字后面写着它现在的状态。</div>
  ```

  位置没挪：仍在「外观」卡里（紧跟「右栏」小节）——用户抱怨的是「看不清」，改法是名字显式 + 状态写在名字后。
- **状态与持久化**：`let railViews={important:false,planned:false,flagged:false}`（**默认全关**，沿用 T-G154 的默认；
  用户只要求能自由选择，没要求改默认）；新键 `tf_rail_views` 存「哪几个开着」（JSON 数组，如 `["planned"]`），
  **不再存一个布尔**。
- **老偏好迁移**（可被断言钉住）：`migrateRailPrefs(oldVal,newVal)` —— 新键存在则以新键为准（迁移只走一次）；
  否则按旧键 `tf_rail_direct` 映射：`'on'` → 三项全开；`'off'`/没存 → 三项全关。启动时迁移并把结果落进新键，
  **旧键只读不写**。
- **运行时隐藏不变**：markup 三个 `data-view` 一个没删（`test_smart_views_are_reachable_at_every_breakpoint`
  静态钉着），`applyLeftRail()` 按项套 `hidden`；左栏**不分组、不加标题、不固定**，按项显示/隐藏。
- **动作注册**：`ACTIONS['left-rail-view'] = el => toggleLeftRailView(el.dataset.view)`；旧的
  `left-rail-smart` / `toggleLeftRail` 整体删除（`docs/commands.toml` 无引用，`check_commands` 不受影响）。

### §2 「离线记」移出 PC 左栏

- 左栏 nav 删掉 `data-view="offline"` 那颗按钮（留注释说明去向）。
- **PC 通路没丢**：设置 → 数据的 `set-offline` 小节（「手机离线记（从手机往电脑带）」）本来就有
  「打开『离线记』这一页」的入口（`index.html` 的 `id="set-offline"` 小节），原样保留 —— 离线包的导出/导入都在那一页。
- **手机端入口未动**：顶部提示条（`offlineBar`）原样；`smartViewNavHTML` 互跳行一字未动
  （`git grep -c smartViewNavHTML` 改前 4 = 改后 4）。
- **离线引擎一字未改**：`src/web/offline.js`、IndexedDB 队列、包格式、`renderOffline` 全部原样 —— 纯入口搬家。

## 三、反证（必带读数）

1. **逐项生效 + 逐项持久化 + 迁移**（真浏览器，行为流 ㉙ 重写为 13 项断言，全绿）：
   - 默认（没存过偏好）：左栏三项一个都没露（`:not([hidden])` 计数 0）、主视图「今日」还在；
   - 设置里是三个独立开关（计数 3）；
   - 只开 planned → 左栏只露「有计划」1 项；`tf_rail_views` = `["planned"]`；
   - 刷新后仍只有「有计划」；
   - 预置旧偏好 `tf_rail_direct='on'`（删新键）→ 重载后三项全回左栏、新键落成
     `["important","planned","flagged"]`（迁移只走一次）；
   - 再收起「重要」→ 左栏剩 2 项，数组 = `["planned","flagged"]`。
2. **老偏好被尊重**：同上第 5 条（`on` → 全开）；`off`/没存 → 全关由默认全关 + 迁移函数覆盖
   （`migrateRailPrefs` 里 `oldVal==='on'` 之外一律 false，静态断言钉住）。
3. **手机端入口未动**：`git grep -c 'smartViewNavHTML' -- src/web/index.html` 改前 4、改后 4。
4. **离线记**：`data-view="offline"` 在左栏 nav 里已无（现仅剩离线页自身 + `set-offline` 小节各一处）；
   设置 → 数据入口在（`id="set-offline"` 小节片段见上）；顶部提示条 `offlineBar` 原样。
5. **静态**：`tests/test_web_frontend.py` 109 passed（新增
   `test_left_rail_views_are_individually_chooseable`；`test_mobile_offline_capture_is_wired_and_honest`
   的左栏断言**换方向**钉——左栏不许再有、设置→数据里必须有）；ruff 全绿。

## 四、碰到什么坑

- **树里直接跑 node 工具忘带 PYTHONPATH**（卡 §0 明写的坑，自己撞上了）：单跑行为流 ㉙ 两轮全红，
  且失败形状恰好是「旧代码的行为」——起服务时 `serve.py` import 到的是**主树**的可编辑安装包、
  页面壳是主树的旧 `index.html`。带 `PYTHONPATH="$PWD/src;$PWD/tools/sandbox_shim"` 后同一条件全绿
  （经 `run_gates.py` 跑则不用，063 已处理）。教训照旧：**越绿的读数越要先问它在看哪个树**。
- 行为流 ㉙ 旧版 10 项断言全部作废重写（13 项）；流没删，编号沿用 ㉙，替掉的人工项不变。

## 五、黄金重采（范围 + 为什么）

- **全量重采**：左栏是**桌面档公共区域**（去掉一颗按钮 → 其后按钮前移、nav 变矮），设置页「外观」节
  又在**三档宽度**都渲染（手机也有设置页）——所以三档黄金全部会动，不存在「手机零改」的子集，
  按卡 §7.2 全量重采（份数以 `gates/render/LAST_UPDATE.md` 与 `render_check` 输出为准）。

- 左栏 markup 三项与设置页「入口」那排（T-G154 的保留项全部原样）。

## 七、边界（如实写）

- 卡 §5 读数 1（「未设时左栏看得到三项」）与 §2.1 冲突，按 §2.1 执行，未满足读数 1（见 §一）。
- 提交信息与卡 §4 模板不同：模板里「默认显示并并成一组」与本实现（自由选择、默认全关）不符，
  按实际行为改写；Task/Refs/Ledger/Gates 四行 trailer 照卡。
- 「默认值要不要改成显示」是产品决定，本卡未自行更改。
