## 3 探针 `tools/dark_probe.mjs`（新建，只读）

- 跑法：`node tools/dark_probe.mjs --view habit,planned,review`（`--port` / `--json` 可选）。
  复用 `tf_browser.mjs` 的 `startServer --fresh` + `seedFixture` + `bootApp` + 假时钟三处钉齐
  （`CAPTURE_DAY=2026-06-15`），1280×900，对每屏分别在
  `document.documentElement.dataset.theme = 'light' / 'dark'` 下渲染，等渲染稳定
  （body 背景 + 变异计数连续 4 拍不变）再逐可见元素读
  `background-color / color / border-*-color / font-size / 最近不透明祖先背景`。
- 输出：令牌自检三个数 + 判据 A 表（暗值逐字节 == 亮值且不在白名单：

## 4 反证 ①（未改代码的现场）

`node tools/dark_probe.mjs --view habit,planned,review`（改前）：

- **合计：A 60 处 / B 10 处**。
- A 的样（表头几行；`rgb(47, 111, 235)` = 亮色 `--accent` `#2f6feb`）：
  ```
  habit | div.shell > aside.rail > nav > button.active | background-color | rgb(47, 111, 235)
  habit | main#main > div.new > button | background-color | rgb(47, 111, 235)
  habit | textarea#fbPlan | background-color | rgb(255, 255, 255)
  habit | textarea#fbPlan | color | rgb(0, 0, 0)
  planned | main#main > div.card > div.card-body > div.meta > span.prio.high | background-color | rgb(47, 111, 235)
  planned | main#main > div.card > div.card-body > div.meta > span.flag > svg > path | color | rgb(47, 111, 235)
  ```
  （A 的计数口径：逐元素逐属性，svg/path 与其父 span 会各自命中一次同一规则 —— 60 里有不少是
  这种父子重复，如实说明；去重后的问题类只有两类，见 §5。）
- B 的样（全部同一对：暗色墨 `rgb(11, 18, 32)` 落在亮色强调底 `rgb(47, 111, 235)` 上 = 4.1 < 4.5）：
  ```
  habit | div.shell > aside.rail > nav > button.active | [dark] rgb(11, 18, 32) on rgb(47, 111, 235) = 4.1（要 ≥ 4.5，正文）
  habit | main#main > div.new > button | [dark] rgb(11, 18, 32) on rgb(47, 111, 235) = 4.1（要 ≥ 4.5，正文）
  ```
- **根因只有两类**（用一次性 CDP 脚本对质过：切暗色后 `--bg`/`--ink` 都变了，
  但 `nav button.active` 的背景仍是 `rgb(47, 111, 235)`）：
  1. `index.html` 的 `view()` 里有 `else{ applyAccent(cfg.accent_color); localStorage.setItem('tf_accent',…) }`
     —— 把**配置默认**强调色写成**内联** `--accent`。内联样式优先级高于 `[data-theme="dark"]`，
     暗色的 `--accent:#60a5fa` 永远不生效；暗色墨 `--accent-ink:#0b1220` 落在亮色强调底上
     → A 的大头 + B 全部 10 处（4.1）。
  2. `.textarea` 是唯一没写 `background/color` 的文本控件（`select`/`input` 元素级都有
     `var(--panel)`/`var(--ink)`），暗色下吃 UA 白底黑字 → `#fbPlan`/`#fbGap`
     （用户点名的每日反馈）A 4 处。**这正是用户那句原话里的东西。**

## 5 修了什么（只加暗色 / 删一条暗色才会踩的 JS 分支）

- `src/web/index.html`：删掉 `view()` 里的 `else` 分支 —— 没选过强调色时**不再**把配置默认
  写成内联 `--accent`、**不再**持久化 `tf_accent`。默认值交给令牌区
  （亮色 `:root` 同为 `#2f6feb`，**亮色视觉零变化**；渲染黄金的 `bootApp` 本来就把
  `tf_accent` 钉住，走的是 `accentChoice` 真值路径，不受影响）。用户真选过 → 仍写内联（原行为）。
- `src/web/app.css`：`[data-theme="dark"]` 块加 `color-scheme: dark`（原生控件默认底 /
  select 弹层 / 滚动条 / 日期选择器跟随暗色；只存在于暗色块，亮色零影响）。
- `src/web/app.css`：新增 `[data-theme="dark"] .textarea { background: var(--panel); color: var(--ink) }`
  （只加暗色覆盖不动亮色 —— 亮色 UA 白底恰好等于 `--panel`，直接改 `.textarea` 会刷掉渲染黄金）。
- 改前按铁律 2 跑 `pin_check --literal` 四条（两条 JS / 两条 CSS 锚点）：全部钉子 0。

## 7 判据留下（选 A：`ui_flow_check.mjs` 加暗色流 ㉚）

- **为什么选断言而不是 dark 黄金**：黄金层要动 `render_check.mjs` 的采集/更新/命名三处，
  亮暗同目录极易互相覆盖（反证 ③ 的风险面大）；断言流不改任何既有判据、
  复用现成流底座（真点击 + `waitIdle`），且突变可当场红给主控看。
- 流 ㉚「暗色模式：切到暗色后关键元素落在暗色集、没有『文字与背景同色』的元素」
  （`item` = 新增（不是搬移项）：用户 2026-09-27 反馈暗色没适配（T-G163））：
  1. 清掉工具钉住的 `tf_accent` 再重载 —— 走「用户没选过强调色」的默认路径（暗色令牌真正生效的路径）；
  2. 先记亮色基线（同时证明「跟亮色不一样」，防「body 背景 == --bg 计算值」这种恒真断言）；
  3. 走真 UI：设置页「外观」→「暗色」按钮（不是直接改 `data-theme`）；
  4. 断言：`html` 上没有内联 `--accent`；habit / planned / review 三屏的
     body 底 == `--bg` 暗色计算值、卡片底 == `--panel` 暗色计算值、
     **不存在「文字色 == 背景色」的元素**（全页扫有自有文字的可见元素）；
  5. habit 屏额外断：每日反馈 `#fbPlan` 底 == `--panel` 暗色值（不再吃 UA 白底）、
     强调色亮暗确实换档（不只 == 令牌，还要 != 亮色基线）。
- 跑法：`node tools/ui_flow_check.mjs --only ㉚`（全量门禁自动包含）。
  实测：**21 项断言全绿**（16.2s）。
- 已知边界：断「选中项底 == accent」会撞悬停态的 `color-mix`（点完左栏鼠标还停在那颗按钮上），
  所以强调色只断「亮暗换档 + 无内联」两条，不比相等 —— 如实写，不是放松。

## 11 边界（没做到 / 没动的，如实写）

  启动时顶层的 `applyAccent(localStorage.getItem('tf_accent'))` 仍会把它写成内联 →
  这些旧会话的暗色强调色依旧不生效；要点一次设置页的「默认」（`setAccent(null)` 清 `tf_accent`）
  才回到令牌路径。区分「用户真选过」与「被持久化的默认」需要别的判据（或改启动写入逻辑），
  超出本卡白名单口径，没动，报主控。
