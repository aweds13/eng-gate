# 过期的「连不上」替现在回答（T-G76）—— 提示不许当判据

> 一句话：界面把 `offlineNow()`（= **上一次请求**的结论）拿去**拒绝这一次的动作** ——
> 断网回在线的那一两秒里，一个**明明能成**的操作连试都不试就被回了「先导出同步包」；
> 写入被白白绕进手机队列；更坏的是轮询也被它挡住 → **再没人能推翻这个结论**。
> 修法两条：**一条失败只代表它出发的那一刻** + **要拒绝，先探一次**。
> 2026-09-25；分支 `line/impl-v1`；台账 `T-G76`。

---

## §1 症状与病灶（触发它的是一条"顺手修"）

T-G73 搬完第五批时**照实记过一条观察**：断网期间"在飞"的请求失败得晚，回到在线后界面还会说
「连不上」**一两秒**（真机上很难发生，主要是测试里秒切状态）。用户 2026-09-25 点名顺手修。

动手时先问了一句"**这两秒是显示问题还是判断问题**"，答案比那两秒重得多：

| 地方 | 旧写法 | 后果 |
|---|---|---|
| `offlineUpload`（直接传到电脑） | `if(offlineNow()){toast('先「导出同步包」…');return}` | 一个**明明能成**的操作连试都不试 |
| `writeOrQueue`（写入 / 离线入队） | `if(!offlineNow()){…走接口…}` | 本该落库的记录被**白白绕进手机队列**，人还得导出导入一圈 |
| `toggleDone`（离线勾完成） | `if(offlineNow()&&!t){拒绝}` | 同上 |
| `startFocusPoll`（10 秒轮询） | `if(document.hidden\|\|offlineNow())return` | ★ **唯一会自己重试的请求被挡掉** → 这个结论从此**没人能推翻**（自锁） |
| `paintRail` / `renderOffline`（显示） | 见 `offlineNow()` 就写"离线中" | 显示跟着一个过期结论走 |

所以病灶不是"慢了两秒"，而是：**用"上次"替"这次"回答**。
一个只是"提示"的东西，被拿去当了"判据"。

## §2 修法（两条规矩，缺一条都堵不住）

```js
function markDown(startedAt){                     // ① 一条失败只代表**它出发的那一刻**
  if(typeof startedAt==='number'&&startedAt<lastOkAt)return;   // 出发早于最近一次成功 → 过期结论，丢弃
  if(!netDown){netDown=true;paintOfflineBar()}
}
function markUp(){                                // 一条请求回来了
  lastOkAt=Date.now();
  if(!netDown)return false;
  netDown=false;paintOfflineBar();
  view(current);                                  // 判断被推翻了 → 当场重画一遍
  return true;
}
async function probeServer(){ … fetch('/api/health') … }        // 真探一次（1.5s 超时）
async function offlineConfirmed(){return offlineNow()&&!(await probeServer())}
```

1. **一条失败只代表它出发的那一刻**（`startedAt < lastOkAt`）—— 修的是"**界面自己走回在线**"。
   断网期间发出去的请求失败得晚，回来时世界已经变了；它那一下不许把标记再打回离线。
2. **要拒绝，先探一次**（`offlineConfirmed()` 是**唯一入口**）—— 修的是"**不许拿上次替这次回答**"。
   提示说在线就直接信它（信错那边只会多一次白跑的请求，**不会拒绝用户**）；提示说连不上才真探一次。

★ **探测的判据是「有没有回话」，不是「回话是不是 200」**：401/429（配对墙）是"后端说不行"，
不是"连不上" —— 与 `api()` 里 `__offline` 那条分界同一条规矩。超时 1.5 秒，探不通就照离线办。

**配套四处**（各自堵一个看不住的口）：

- `api(..., {quiet:true})`：探测与轮询失败**不弹提示**（不然每 10 秒吵一次）；
- **轮询不再被提示挡住**：它是唯一会自己周期性重试的请求，挡掉它等于关掉唯一的自愈路径；
- **`markUp()` 里当场重画**：判断变了 → 界面跟着变（一处机制）。为什么必须有它：停在「离线记」
  那一页不动时，页面标题/右栏的话不会自己更正（旧写法里连标记都不会被清）；
- `online` 事件用 `markUp()` 的返回值决定要不要补一次重画：`navigator.onLine` 那半带来的离线
  （我们**从没失败过请求**，`netDown` 本来就是假）标记没翻，那种情况得单独把停着的那一页叫回来。

★ **为什么不在这里各探各的**（第一版就是那样，三处各探一次）：判据分散 → 一个页面里同时存在
"谁探的、谁画的"三套路径，出问题时（本卡 §3 就出了）很难说清是谁动的。收成"**判断变了 → 重画**"
一处之后，`probeServer()` 只剩一个调用点（`offlineConfirmed()`），右栏/离线页都不用再自己探。

## §3 判据为什么必须**确定性地**造出那个状态（这一步我第一版做错了）

**旧判据**（T-G73 那版）只能"**等它稳下来**"：轮询 `offlineNow()===false` 且**再等 400ms 仍然为假**，
才敢往下点。那不是在验产品，**是在等竞态**：等到了就绿，等不到就红，而"到底该不该等"没人说得清。

**新判据**：把"界面以为是断的"与"点下去"放进**同一次求值**（同一个同步块，JS 不会在中间插任务）：

```js
const forced = await t.cdp.eval(`(() => {
  netDown = true;
  const b = document.querySelector('[data-action="offline-upload"]');
  const hint = offlineNow();      // 点下去那一刻，界面以为自己是离线的
  b.click();
  return { hint };
})()`)
```

旧写法在这一步**必然**被拒绝（`offlineNow()` 为真 → 直接 return），新写法会去探一次然后照做。
这一条不依赖任何时序。**为什么这一步允许合成 click**：要验的是**决定**（拒绝之前探不探），
不是"点得到" —— 后者同一条第 ④ 步已经用**真鼠标**证过（真点击 → 真原话），往下的确认与上传
也仍然走真鼠标。

### ★ 第一版那条判据红了，而它红了两次：一次是判据错，一次是我猜错了原因

第一版判据分成**两次** `cdp.eval`（先置位、再点击），当场红了：

```
· （准备）界面现在以为自己还断着 —— 实际 false，期望 true
· 点得到：offline-upload（没被别的东西挡住） —— 找不到元素
```

我第一反应是"**有一条探测在飞**，回来把标记清了、还把页面重画了"。**探针把这个猜想否了**
（`gates/diag/probes/stale_flag_probe.mjs`，2026-09-25 实测）：

| 探针测的 | 实测 | 说明 |
|---|---|---|
| ① 干净启动下强制置位留得住吗 | 同读 `true`、500ms 后仍 `true` | 置位方式没问题（不是"读不到同一个绑定"） |
| ② 断网时 `probeServer()` 多久回来 | **3~13 ms**（失败） | ★ **否掉"在飞的探测"**：它压根不"在飞" |
| ③ 浏览器 `online` 事件迟到多久 | **2~10 ms**（调用刚返回它就到了） | 也不是"事件迟到" |
| ④ 断网刷新 → 回网后 1.5 秒里**谁动了标记 / 谁重画**（带调用栈） | `markUp@3 ← online 事件处理器`<br>`view:offline@3 ← online 事件处理器`<br>`markUp@14 ← api()` | ★ **真凶**：回网事件触发的**那次重画**里 `paintRail` 发的 `/api/focus/active`，14ms 后**成功**了 |

于是那两条红有同一个解释：**两次求值之间，世界变了** ——
回网事件触发了重画（`view:offline`），重画自带的请求随即成功（`markUp`）→ ① 标记被**正当**清掉
（那条请求**确实**成功了，清得对）；② `#main` 被重画 → 行为流打在按钮上的 `data-tfprobe` 标记
随之消失 → `rectOf` 找不到 → 报「找不到元素」（**按钮其实还在**）。

> 教训（进地图 §6）：**判据不许把"两次求值之间的世界"当成没变**。凡是我做了什么、与世界变成
> 什么样之间隔着一次往返，就要用**世界的样子**去断言（T-G37 那条），或者干脆把两件事放进**同一个
> 同步块**。★ 顺带记一句对自己的：**第一版的"原因"是猜的，探针一量就否了** —— 猜出来的因果
> 只要没量过，就不该写进复盘。

## §4 验收（每一条都在问"它会在错的时候红吗"）

**静态护栏**（`tests/test_web_frontend.py::test_offline_verdict_is_a_hint_never_a_refusal`）：

- 三个会拒绝人的地方（`offlineUpload` / `writeOrQueue` / `toggleDone`）**都必须**出现
  `offlineConfirmed()`，且**不许**再出现 `if(offlineNow()){`（"提示即判据"那种写法）；
- `markDown` 必须拿出发时刻与 `lastOkAt` 比；`api()` 必须把 `startedAt` 交出去；
- **轮询不许被提示挡住**（判的是那个条件本身，不误伤注释里提到函数名）+ 必须 `quiet`；
- `markUp` 必须**重画**、且如实返回"翻没翻"；
- `offlineNow()` 上面必须写着「它只是提示、要拒绝先探」（免得下一个人又拿它当判据）。

**★ 另一条更值钱的**（`test_health_route_the_probe_relies_on`）：**探测的证据路径必须真的存在**。
拿一条**不存在**的路径去探，`fetch` 会因为 404 而"有回话" → **永远探得通** → 离线时界面会以为
网回来了。这正是 T-G69/T-G74 那一族（**判据自己替被测者兜底**）的第二次露头，所以它单独一条用例。

**行为流层 ㉖**（真浏览器 + 手机档 + 真 `Offline`）：**25 项断言**，比 T-G73 多两项 ——
① 回网后**界面自己走回在线**（不靠用户点、不靠刷新）；② 把"它以为是断的"与"点下去"放进
**同一次求值**，确认框必须照样出来（旧写法在这里必然被拒绝）。两遍指纹一致。

### ★ 顺带抓到并修掉一个**工具**缺陷：断言标签里写了测量值

`--twice` 比的是「每条流 × 每条**断言的标签 + 通过与否**」。㉘ 里有一条：

```js
t.ok(`★ 今日专注分钟只涨了一次的量（涨了 ${grew}s，会话约 ${secs}s）`, grew >= secs - 4 && …, …)
```

**秒数写进了标签** → 两遍只要差一秒，指纹就"不一致"，报的是
「这是**工具的**问题（时序/状态没钉住）」—— 报得对，但**位置指错了**（听起来像流本身不稳）。
T-G73 那次没红，纯属两遍的秒数**凑巧一样**（所以它是潜伏的假红，不是"一直没事"）。
修法：**标签固定、数字搬进 `detail`**（detail 给人看，不进指纹）。

同一次还把那条报错变有用：两边都全绿却指纹不同时，旧写法只印「第一遍 `[]` / 第二遍 `[]`」
（等于什么都不说）→ 现在印**只在某一遍出现的断言标签**（本卡就是靠它一眼定位的）。

## §5 没动的 / 边界（不假装）

- **后端一行没改**：`/api/health` 本来就在（T-G54 建的健康检查），只是**从来没人拿它当判据**。
- **45 份渲染黄金一份没动**（这次没碰版式）；离线包格式与合并规则一个字没改。
- 探测会**多一次请求**：提示说离线时每个"会被拒绝的动作"多一次 `/api/health`（真断网时实测
  3~13ms 就失败，不拖人）。这是"不许拿上次替这次回答"的价钱，如实记着。
- `markUp` 的重画**一次离线只发生一次**（重画里的请求成功时标记已是假，直接返回）；
  代价是那一刻可能出现一次多余的重画（重画里的请求会被 `AbortController` 取消，AbortError 静默）。
- 边界仍在：`navigator.onLine` 本身可能是错的（VPN/受限网络里它说在线而服务不可达）——
  所以真正的判据一直是"**请求有没有回来**"，这条没变。

## §6 教训（已进 `复盘/视觉线地图.md` §6）

1. **提示不许当判据**：一个"上一次的结论"只能用来**说话**，不能用来**拒绝**这一次的动作 ——
   要拒绝，先花一次真请求去问现在。
2. **迟到的结论只代表它出发的那一刻**：给结论带上"什么时候得到的"，比它晚的成功就能作废它。
3. **判据不许假设"两次求值之间世界没变"**：要么用世界的样子断言，要么把相关动作放进同一个同步块。
4. **猜出来的因果没量过就不算数**：这次第一版猜"在飞的探测"，探针 3ms 就把它否了 ——
   **先量再改**在这里又一次救了场（同 T-G71 的"先量再改"）。
