# 复盘 · 全量补充执行计划（工程管理 / 规格 / 验收）

> 时间：2026-09-18
> 目标：让工程管理、其他域规格、用户逻辑细节、测试与验收足以支撑长程自主任务。
> 方式：以 N / SR / conventions / contracts / ACCEPTANCE 为源，叠加通用工程知识与项目品味；产品假设写入《缺口处理与假设台账》；默认可逆，破坏性/核心心智变更停下确认。
> 结论：分 4 批执行；本文件是总计划与 checkpoint 入口。

---

## 一、要补的缺口（来自用户提问）

| 缺口 | 表现 | 补法 |
|---|---|---|
| 工程管理不足 | 规格没写清时，AI 可能自行脑补 | 缺口处理协议 + 假设台账 + 行为细则 |
| 其他域规格不足 | F4-F10 多为一句规格 | 每域一份详细规格 + 操作/动线契约 |
| 用户逻辑细节不足 | 空态/错误/撤销/边界/并发缺失 | 横切行为细则 + 每域边界清单 |
| 测试/验收不足 | 缺端到端，验收偏人工清单 | 可执行验收层 + 覆盖矩阵 + 覆盖率门 |
| 工程品味未落地 | taste 层为空壳 | 重写为项目专属品味并作为取舍依据 |

## 四、完成定义（DoD）

- 每个 SR 有：详细规格、操作/动线契约、边界与异常、验收标准、测试映射。
- 每个操作六要素齐备，含空态/错误/撤销/确认/幂等/边界。
- 缺口处理协议生效：所有未定项进入假设台账，可追溯、可回退。
- 质量门：pytest / ruff / mypy / check_layers / 护栏自测 / 覆盖率门全绿。
- 交接与 checkpoint 可让新窗口无缝续接。

---

## 五、停止条件

- 破坏性 / 不可逆；核心心智变更；与 conventions 红线冲突；需要新依赖 / 联网；质量门红且修复方案分叉。

---

## 六、checkpoint

每批结束写：完成范围、质量门、下一批、阻塞、决策、文件清单；并更新 `复盘/交接-重构进度.md`、`复盘/长任务执行协议.md`。
