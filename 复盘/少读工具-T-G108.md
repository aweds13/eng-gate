## §1 为什么有这张卡（主控少读文件的实测账）

复核工人产物最贵的两笔是 **① 整份读代码**、**② 读长报告**。已有的工具替掉了一部分
（`wb_review.py` 五条、`audit_progress.py`、`wb_status.py` 摘要），还缺两件——

- **改文件之前的索引**：T-G93 真撞过一次——某卡改了 `tools/wb_dash.py` 里 `_state` 的**签名**，
  更早那条「整段签名」的台账证据**字面失配** → 提交时被 `audit` 打脸（`_myday_rank_plan` 同理）。
  正确做法是**事前**能问：「改这个文件，哪几条台账证据会碎？」
- **日志的失败定位器**：`gates/diag/wb-007.jsonl` 是 **435 行 / 1133 KB**，主控要的只有几行。

★ **只做 grep 做不到的**：卡里明写「按函数名查行号」这种索引 grep 已经能做，不做。

## §2 交付一：`tools/evidence_map.py`（台账证据 ↔ 源文件 倒排索引）

四个模式（都**只读**）：`--file <路径>` / `--entry <卡号>` / `--stale` / `--stat`。

★ **求值口径只有一个真源**：**直接复用** `scripts/audit_progress.py` 的 `eval_assertion`
（第 **154–189** 行；它依赖的仓库事实取数在同文件 `routes()` 56–60 / `tables()` 103–105 /
`columns()` 108–131 / `declared_actions()`·`registered_actions()`·`views()` 138–150）。
做法是 `sys.path` 挂 `scripts/` 后 `import audit_progress` **调用它**，而不是照抄一份代码 ——
这样「本工具与 audit 不一致」在结构上**不可能**发生（本项目一贯规矩：别写第二套口径，
T-G93 复用 `parse_events` 同此理）。`--stale` 只求值 `status=done` 的条目，遍历口径与
`audit_evidence`（245–260 行）一致。

## §3 交付二：`tools/wb_diag.py`（日志失败定位器）

把 log 压成五段：**① 红的用例**（`FAILED/ERROR <path>::<test>`，去重）/ **② 断言原文**
（`assert` / `AssertionError` / 其它 `Error:`，每类 ≤10 行）/ **③ 项目内栈帧** /
**④ 它最后在干什么**（最后 3 次工具调用）/ **⑤ 一行汇总**（退出码 / 有无 `result` 事件 /
`subtype` / log 行数 / 红用例数）。

- ★ **为什么丢掉外部库栈帧**：真 traceback 里 7 帧有 7 帧来自 stdlib（`<string>` /
  `miniconda3\Lib\re\…`）——留着就是**噪音淹掉信号**；只留 `File "<路径>", line N`
  里**落在本仓库根之下**的，且只留**仓库相对路径**。仓库根用
  `git rev-parse --git-common-dir` 的父目录取（worktree 里跑也要认得出**主树**里的帧）。
- ★ **口径复用**：时间线 / 摘要 / 工具数走状态器 `tools/wb_status.py` 的 `parse_events`；
  本文件只补它**故意裁掉**的部分（它把 `tool_result` 压到 120~200 字，抓 `FAILED` 行不够用）。
- ★ **顺手挡住一类噪音**（先红后绿，见 §4）：`Error:` 只认**行首**的异常名（可选 pytest 的 `E `
  / grep 的 `NN→` 前缀）——工具回话里常夹着工人 grep 出来的**源码**
  （`except json.JSONDecodeError:` 之类），字面也符合 `Error: `，不挡的话 10 行额度会被占满。
- ★ **只读**：不跑 CLI、不改任何文件；坏的 / 半截的 JSONL 行一律容忍，**不炸**。

## §5 真东西验证（不是只有单测）

1. **`--stale` 对 audit 口径 → 一致**：真台账 **0 条失配**；`audit_progress.py --no-git` 同时报
   `[OK] 所有 status=done 的断言都成立（228 条）`、**审计通过 ✅**。→ **无差异**（卡 §5.1）。
2. **`--file tools/wb_dash.py` → 9 条**（`T-G93` 六条 + `T-G97` 三条），全**命中**。
   这正是「改前先看会碎什么」的样子（其中 `def card_state(root: Path | None = None) -> list[dict]:`
   那条一改签名就碎）。
3. **`wb_diag.py` 跑真日志 `wb-007.jsonl`：1133.1 KB / 435 行 → 52 行 / 4929 字节（≈ 1/235）**，
   抓到 **12 条红用例**、最后 3 次工具调用；第 3 段（项目内栈帧）**空**——因为 wb-007 的红是
   **断言失败**（pytest 短回溯，没有 `File "…"` 帧），不是 error。**输出全文见回报。**
4. **`wb_diag.py` 跑本轮自己的真日志 `wb-015.jsonl`**：抓到**这条卡自己的 28 条红**
   （先红那一轮），其中含 `NotImplementedError: 还没实现` —— 定位器在**真场景**下也对。

## §6 边界（如实写）

- **卡里「`--file`/`--entry` 纯读、`--stale` 才求值」与「输出要带『命中与否』列」有措辞冲突**：
  我按**输出格式**落 —— 三种模式都只读求值（不写任何文件），`--stale` 是「**只列失配**」的那个模式。
  若口径应为「`--file`/`--entry` 不读文件」，改一行即可。
- **与 audit 的口径差异：没有**（求值函数就是同一个）。但**覆盖面**上有意收窄：`--stale` **只查
  `status=done`**（与 audit 一致；`todo/partial/deferred` 的断言没打算成立，报出来是噪音）。
- **抓不到的**：① `text:` 的 `re:` 前缀走 audit 原样支持，但本工具**索引**时按字面取路径，
  不影响求值；② 栈帧只认 `File "<路径>", line N`（别的形状，如 `  at …`，不认）；
  ③ `FAILED/ERROR` 只认 `.py::` 结尾的行（`FAILED ...::x` 这种省略写法不算，避免噪音）；
  ④ 空转/回合不在这里判——那是派活器的事。
- **退出码**：jsonl 里**没有**这一项（派活器才知道），所以 `--exit-code N` 是**可选**输入，
  不传就写「未提供」——**不猜**。
- **真日志的位置**：`gates/diag/` 是 gitignored、**按树各存各的**；本轮真日志 `wb-007.jsonl`
  在**主树**，我按**绝对路径只读**跑了一次（没进主树、没改它一个字节）。
