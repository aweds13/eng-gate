> 难道你不能想一个不要总是局限于现在那些质量的方法？有没有更好的方法？是你的工具不够好吗，
> 流程有问题吗？」

## 1. 先说量出来的事实（不是感觉）

| 环节 | 改前 | 改后 |

台账/changelog/CHECKPOINT 三处」≈ 20 分钟仪式。所以这一轮同时定了**按主题批量卡片**
（视觉线剩下的步 2+步 3 合成一张卡，一次给人看）。

## 2. 三层速度（`run_gates.py`）

```powershell
python -X utf8 scripts/run_gates.py --fast    # ① 7.4s：ruff + 对比度 + 一致性 + 命令表 + 两道审计
python -X utf8 scripts/run_gates.py --quick   # ② ~90s：再加 pytest（跳过真浏览器）
python -X utf8 scripts/run_gates.py           # ③ 184s：全量（两层真浏览器都跑）
```

`--fast` 挑的是「**改一行就能犯、且十几秒内查得出来**」的那几类 —— 尤其 `audit`
（TOML / 台账证据指针的语法，我在这一轮里就犯了第 6 次）与 `contrast`/`style`（照抄包时
最容易抄错的令牌层）。

★ **`--fast` 不写 `gates/last.json`**。它不是提交闸；写了就会让审计第 ⑤ 条
（"门禁产物与提交一致"）失效 —— 那是**拿半轮结果冒充一轮**，比慢更坏。

## 3. 两条泳道并行：安全性逐条查过，不是"应该没事"

| 共享资源 | render | ui_flow | 结论 |
|---|---|---|---|
| 服务端口 | 8531（CDP 8532） | 8541~8544（两遍各一对） | 互不相同 ✅ |
| 数据库 | `serve.py --fresh` 临时库 | 同左，各自的 | 分开 ✅ |
| 浏览器 profile | `tf-render-profile-<port>` | `tf-flow-profile-<port>` | 按端口分目录 ✅ |
| 导出目录 | 只**读**路径（没写、没列目录） | 会往里写 `flow-export/`、`flow-vault/` | 不冲突（已核对渲染黄金里没有它的内容） ✅ |

顺带修掉一个**真隐患**：`tools/web_live_check.py` 的局域网自检**写死 8531** ——
那正好是渲染层的默认服务端口。串行跑时看不出来，一旦并行就是"两个服务抢一个端口"，
表现为**随机失败**（最难查的那种）。现在自动挑空闲端口（顺带也避免"用户机器上 8531 被占"的假红）。

## 4. 输入没变就复用（`gates/reuse.json`）

真机层的判定只取决于几样东西，`REUSE_INPUTS` 把每道门的输入写死：

```python
"render": ("src/**", "tools/render_check.mjs", "tools/tf_browser.mjs", "tools/serve.py",
           "gates/render/*.txt"),
"ui_flow": ("src/**", "tools/ui_flow_check.mjs", "tools/tf_browser.mjs", "tools/serve.py"),
```

哈希一致且上次是通过 → 跳过，并在 `last.json` 的 `reused` 一栏 + 输出 + 建议 trailer 里
**写出来**（"没跑"和"跑了"必须看得出差别，这是这个项目一以贯之的规矩：NOT RUN 不是 PASS，
**复用**也不是 PASS —— 它是"输入一个字节没变，所以上次那个判定仍然成立"）。

★ **pytest 永不复用**：它是唯一"从行为上证明功能还在"的那层，也是唯一能发现
"谁动了 `src/` 却以为无关"的那层。省它 66 秒 = 把安全网摘掉。

## 5. 过程中撞到的两件事（都留了痕）

1. **我自己的 bug**：`resolve_cmd` 第一版先看 `if name in cmds` —— 而 `jobs` 里
   `("pytest", [])` / `("render", [])` 这些**空占位**正好会被命中 → 返回空命令 →
   `Popen([])` 在 Windows 上抛 `OSError: [WinError 87] 参数错误`（报错完全看不出跟命令有关），
   四道占位门全记"起不来"。修法：**先判"是不是占位门"，再取字面命令**。
   顺手把"起不来的门"从"让整轮脚本崩掉"改成"记一条 FAIL" —— 崩掉会把其余门的结论一起丢掉，
   而"失败要留下证据"先于"这次跑得顺"。
2. **审计当场抓到证据腐烂**：重构 `run_gates.py` 时挪动了两个字面量，
   台账里 T-G32/T-G34 的证据指针（`text:scripts/run_gates.py::("render", [])`）当场失效 →
   `audit` 红。指针改成 `def render_cmd()` / `def ui_flow_cmd()`（**函数定义比字面量稳**）。
   这正是「证据会烂」那条铁律在干活 —— 它花 3 秒，比我自己记住"我改过那个文件"可靠。

## 6. 还有一张纸：`复盘/视觉线地图.md`

之前每换一个窗口、每改一处悬停样式，都要重读 `app.css` 三段 + 两个审计工具 775 行 +
两个测试文件。这张纸把它一次沉下来：

- **改了 X → 动哪几处**（颜色/档位/状态/布局/模板/视图/后端/台账各一行）；
- **每道门判什么、大概多少秒**；
- **渲染层怎么用**（清单=判据、PNG=证据、改黄金必须写理由、伪元素采不到）；
- **12 条踩过的陷阱**（TOML 引号、PowerShell 过中文、行内 style 优先级、
  `:not([disabled])` 的权重、`.card` 是 flex 行、flex 不换行 + 中文、写死端口…）；
- **事实在哪**（台账/规格/两个 baseline/门禁产物，都指到真源，不抄表）；
- **视觉线当前进度**（哪几步 ✅、下一步是哪一步）。

## 7. 没做的（如实记）

- **`tools/squeeze_scan.py` 仍不进 `run_gates.py`**：它的判据里有一步是字宽**估算**，
  做成硬门迟早会为一次误报把某个视图写进白名单，那张表就没人看了。它是"改版式前后各跑一次"的尺子。
- **`--quick` 里 pytest 的 66 秒没动**：那是安全网本身，能省的只有"不该跑的时候别跑"。
- **没做分布式/缓存 pytest**（`pytest --lf` 之类）：上一次失败集在"全绿"时没有意义，
  而按文件缓存测试结果会引入"改了这个却跑了那个"的静默漏测 —— 这类"快一点但可能漏"的优化不做。
