# 外包工具（外挂设施）· 需求与整体架构（v1）

> **这份文档是什么**：把「AI 干活」这套**外挂设施** —— 号池 / 派活 / 门禁 / 收批栅栏 / MCP 面 ——
> 的**需求**与**整体架构**一次说清，充当**审查与接手的唯一入口**。
> **怎么读**：先读 §1（要什么）与 §2（长什么样）；要细节时按 **§7 索引按需取读**，
> ★ **不要整份读库**（这套设施的价值之一就是"少读"）。
> **权威性**：凡属**通用层**（`infra/pool/**`）的事实，权威在 **infra 仓**；
> 凡属**项目层**（本仓 `tools/**` `gates/**` `docs/**` `复盘/**`）的，权威在**本仓**。
> 本文只**指路**，冲突时以**代码与真源文件**为准；发现不一致 ⇒ 记一条坑，**别默默改**。

## §1 需求

### 1.1 一句话

把"让 AI 干活"拆成 **主控（判断）** 与 **工人（执行）** 两侧，中间全部用**机器判据**连接
（队列 · 冲突域 · 门禁 · 台账 · 封存指纹 · 栅栏 · 守卫）；
**设施通用**（跨项目复用、只有用户能改），**记忆专属**（项目知识留在项目自己的文件夹里）。

### 1.2 五条原始诉求 → 落成了什么

| # | 用户原话（意译） | 落成的东西 | 状态 |
|---|---|---|---|
| ① | 「**尽量把活给 WorkBuddy**，增强稳定性」 | 派活器 `tools/wb_dispatch.py`（五道前置 + 看门狗 + 心跳 + 续跑） | ✅ 在跑 |
| ② | 「任务未经我允许**不准给 kimi / glm…**」「**只白名单里的模型才能调**」 | **模型白名单 + 默认拒绝**（不在名单 = 退出码 2、不起进程） | ✅ 硬闸门 |
| ③ | 「小改动应该**堆在一起**；同一板块堆在一起写文书」→ 纠正为「**我注册一个任务**，任务下多张卡都完成并**交了成功申请**，**集齐**才写 —— **不是数量**」 | **任务栅栏（收批）** `tools/pool/task.py` + `tools/wb_task.py` | ✅ 进 git |
| ④ | 「同一个对话框里会跑**不同项目** ⇒ 记忆层要弄好：**不干扰**、又能外包」 | **项目索引** `infra/pool/projects.toml`（根 / 记忆入口 / 层名表 / 树前缀） | ⚠️ 已写未接线 |
| ⑤ | 「外包设施可以给**不同窗口**干不同项目」「**不同块要不同主控**」⇒ 少脏 token | **MCP 面** `tools/pool_mcp.py`：只读 9 + 写 4（存在性即授权） | ✅ 已落地 |

### 1.3 角色（谁干什么，不越界）

| 角色 | 是谁 | 能做什么 | 不能做什么 |
|---|---|---|---|
| **用户** | 本人 | 改白名单 / 改项目索引 / 拍板产品口径 / 定"什么算外包甜点区" | —— |
| **主控** | 当前窗口的 AI（我） | 定卡 · 派活 · 收口（跑门禁 + 提交 + 记账）· 下结论 | 不伪造完成、不替用户拍板、不碰真实数据 |
| **工人** | 另一个模型进程（CodeBuddy / 码道 / Trae） | 在**自己的卡树**里干活 · 自验 · 交**成送申请** | 不提交、不碰共享文档、不越白名单 |
| **复核者** | 只读卡（`R-<卡号>`） | 对抗性复核：越界 / 证据逐条求值 / 原始读数 / 攻击 | **只读**：不改任何文件（突变检验后必须还原） |
| **收口者** | = 主控（**唯一写者**） | 集成、门禁、封存、白名单提交、审计 | 一棵树同时只能有一个 |

### 1.4 不可协商的约束（铁律）

1. **门禁不过不许提交**（提交前必须**真跑**一轮全量门禁，不是 `--seal`）。
2. **一笔提交 = 代码 + 台账 + 文档**，四个 trailer：`Task:`（**只能一个**编号）/ `Refs:` / `Ledger:` / `Gates:`。
3. **审计必须 PASS 且 `[exceptions]` = 0**（豁免不是"通过"）。
4. **不许伪造完成**：没跑过的门禁不许写"通过"，没验过的不许写 done；新判据必须配一条"故意坏掉"的用例。
5. **一写一读**：同一时间只有一个写者；共享文档（台账 / changelog / 交接 / 门禁产物）**由主控串行收口**。
6. **模型默认拒绝**：`--model` 必须**逐字**命中白名单；换模型只影响**新派**的卡。
7. **不许碰真实数据**（真实库 / 备份 / `%USERPROFILE%`）。
8. **产品决策停下来问**，不许自己挑一个写死。

### 1.5 非目标（明确**不做**，别当成缺口）

- **不做跨机共用仓**（只治**单机多窗口 / 多卡树**）；不假装能做。
- **不做无人值守全自动提交**：栅栏集齐后**停在 `awaiting-commit`**，提交永远要人过一眼。
- **不替用户做产品判断**（问法 / 三分类 / 债务重组这类口径）。
- **不做"保活"**：状态存在 git / 台账 / 复盘里，**不依赖任何进程活着**。

### 1.6 成功判据（这套设施算不算有用）

- **机器判的比人多**：今晚的读数形态是「**9 次漏细节、0 次错提交**」。
- **少读**：复核只看 diff / 摘要 / 指针，不整份读文件（§7 索引就是为此）。
- **可换人**：换模型 / 换池 / 换厂商，**流程一行不改**。
- **并行可判**：冲突域相交 ⇒ 机器拒派；提交层靠**片段 + 封存指纹**可判。

## §2 架构

### 2.1 三层（设施通用 / 记忆专属）

| 层 | 内容 | 在哪 | 谁能改 |
|---|---|---|---|
| **通用层**（跨项目一字不变） | 号池与凭证 · 模型白名单 · 派活器 · 收批栅栏 · MCP 面 · 项目索引 | `infra/pool/`（**独立 git 仓，不在任何项目里**） | ★ **只有用户**（白名单/索引）；文档主控可改 |
| **项目层**（每个项目一份） | 队列 · 台账 · 交接 · 口径坑 · 卡规格 · 层名表 · 门禁与审计脚本 | 项目自己的文件夹（本仓 = `tools/` `gates/` `docs/` `复盘/`） | 该项目的主控 |
| **窗口层**（一次会话） | 「我现在在哪个项目」+ 该项目**最小记忆**三份 | 会话开场**显式声明** | 主控 |

★ **避免脏 token 的正解不是"忘掉"，是"从来没读过"**：主控**只**加载当前项目 `memory` 列的那几份。

### 2.3 五条数据流

1. **派活**：主控定卡 →（队列登记 + 卡规格）→ 守卫干跑（树/域/锁/内存/日志/模型）→
   占树 → `--detach` 起工人 → 心跳 + 看门狗 → **判决**（正常收工 / 失败 / 被掐 / 没跑完）。
2. **看进度**：任意窗口 `job_list` / `job_status` / `job_result`（只读 log，不猜）。
3. **收批**：用户（或主控）`register` 一个**任务** → 各卡 `claim` 交**成送申请** →
   **最后一名投递者关门**（当场数人头，不轮询）→ 集齐 ⇒ 跑 `gate_cmd` → 按**层**生成三段文书骨架 →
   **停在 `awaiting-commit`**。
4. **收口**：主控跑 `_integrate.py` → 全量门禁 → 封存指纹 → 白名单提交 → 审计 → `ff` 合流。
5. **记忆**：会话开场**只**读当前项目的 `memory` 三份；切换项目 = **显式一句** + 清项目态。

### 2.4 任务栅栏的状态机

```
collecting ──(名单上每张卡都交了成功申请)──> ready ──> gating ──> awaiting-commit ──> landed
     │                                          │
     │                                          └─(门禁红)─> 停在 ready + 非零退出（不提交）
     └─(到 deadline)─> timeout（只判死列缺席，**绝不放行**，要人显式 waive/extend）
```

- **放行判据是"集齐成功申请"，与数量无关**；名单外的申请 **rc=2**（防夹带）。
- **成功必须带证据**（`paths` + 为什么 + 证据指针）；**有卡投 `failed` ⇒ 挡住收口**。
- **逐卡域越界拒收**（交上来的文件必须落在**它自己声明的 `paths`** 里，点名到文件）。
- **骨架可重算，人写的『为什么』在单独文件里冲不掉**。

### 2.5 三个号池（换池不动流程）

| 池 | 入口 | 当前可用 | 备注 |

| **CodeBuddy** | `tools/wb_dispatch.py`（默认 `deepseek-v4.1-flash`；备 `glm-5.3-flash`） | `hy4-preview` / `hy3(-x)` / `deepseek-v4.1-flash` / `deepseek-v4-pro` / `glm-5.3(+flash/flashx)` / `glm-5.2` / `glm-5.1` / `glm-5v-turbo` / `minimax-*` / `kimi-*`（kimi **黑名单**） | ★ **默认拒绝**：白名单常量在 `tools/wb_dispatch.py` |

### 3.2 MCP（13 工具）

- **只读 9**：`pool_plan` `job_list` `job_status` `job_result` `lock_status` `pool_models`
  `task_list` `task_status` `task_pool`。
- **写 4**（**只在服务端 `POOL_MCP_WRITE=1` 时存在**）：`pool_dispatch` `pool_cancel` `task_register` `task_claim`。
- 两条授权规矩：① **存在性即授权**（没 env 就没工具，不是"有但禁用"）；

- 机器可读块跟在唯一标记 `--- tf-json ---` 之后（防正文里的 JSON 样例冒充）。
- ★ **服务进程是会话启动时拉起的**：改 `tools/pool_mcp.py` 要**重启 DSH / 新会话**才生效。

## §4 判据在哪（不变量 + 安全阀）

**六条不变量**（谁判）：

| # | 不变量 | 判据在哪 |
|---|---|---|
| ① | 一棵树同时一个写者 | `tools/pool/guards.py::tree_guard` |
| ② | 冲突域不许相交（域从队列读，**查不到就拒**） | `guards.py::domain_guard` |
| ③ | 门禁还在跑就别动手 | `guards.py::lock_guard` |
| ④ | 内存不够不派活 | 委托 `wb_dispatch.py` 前置（`TF_GATE_MIN_FREE_GB`） |
| ⑤ | 日志不许覆盖 | `guards.py::log_guard`（写面**不给** `--force`） |
| ⑥ | 模型白名单 | `wb_dispatch.py::MODEL_WHITELIST` + `tools/pool/models.py` |

**五条安全阀**（缺任何一条，"等齐"就会卡死或提前放行）：逐卡域越界拒收（**最重要**）·
「不通过」挡住收口 · 名单外不算数 · `waive` 显式豁免（留痕）· 过期只判死（要人显式放行）。

**项目索引的三条硬判据**（`infra/pool/projects.toml`）：**没登记过的项目不许派活** ·
`root` 必须**真实存在**（宁可拒绝、不许猜路径）· 派活的树必须落在该项目的 `tree_prefixes` 里。

## §5 已知边界（诚实清单，别当成已完成）

1. ★ **收口工具还在 scratch**（`gates/diag/_integrate.py` 等，gitignore）⇒ **别的窗口能派活、不能落地**。
   这是当前**最大缺口**（错配③：权威与工具位置错配）。
2. ★ **项目索引写了但没接线**：`projects.toml` 存在，但派活器 / MCP / 栅栏**还没有**读它 ⇒
   "没登记不许派活""树必须落在项目根里""作业带 `project` 字段"**都还没生效**（记忆层 = 卡 120，用户要求押后）。
3. ★ **两个白名单真源**：`tools/wb_dispatch.py::MODEL_WHITELIST` 与 `infra/pool/models.whitelist.toml`
   —— 改名单的权限归谁、要不要并成一处，**要用户拍板**。
4. ★ **粒度错配未治**：十几行的改动照样走"写卡 + 建树 + 切片 + 工人 + 全量门禁 + 三段文书"，

9. ★ **Trae 池**只做到"读余额 / 发指令"，**没有**并入统一的派活-收批链。
