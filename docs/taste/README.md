# taste — 技术品味 / 架构审美（品味层）

> 本层回答：为什么这样设计、什么叫好的改动、什么坚决不做。
> 状态：2026-09-18 已从空壳重写为项目专属品味；通用原则已内化，不再依赖项目外路径。

---

## 一、系统灵魂

timeflow 是本地优先的个人「时间与学习投入」**如实账本**：逾期=债务、专注=投入、完成=收益；目标是长期均匀投入，**温和不施压**。

---

## 二、产品品味

1. **闭环优先于功能数量**：一个操作必须六要素齐备、动线贯通，才算存在。
2. **如实不粉饰**：估不准就不折算；做不到就不假装；逾期就显示逾期。
3. **温和不施压**：无强制红点、无焦虑放大；提醒可关、默认温和。
4. **默认值 + 可配置**：常见操作一键完成；高级项交给配置。
5. **一屏不淹没**：默认聚焦 My Day；重信息点进去才有。
6. **低门槛**：打开即用、中文界面、可撤销、空态友好。
7. **学校与自学平衡**：学校硬约束单独分级，但不打乱每日执行视图。

---

## 三、架构品味

1. **事实 / 解读分离**：事实只记「发生了什么」，解读层按当前心智模型算账；换模型不动事实。
2. **事件驱动、同步执行**：本地单机用同步发布-订阅，强一致、易调试。
3. **本地优先、隐私最小**：数据不出本地；不新增对用户数据的外部依赖。
4. **计算型 / 沉淀型分流**：计算型走结构化索引；沉淀型走 Markdown。
5. **模块化 + 局部错误隔离**：一个模块出错不崩全局。
6. **边界干净**：知识资产只存引用句柄，不直接读写 Vault / PDF 库。
7. **可回退、可观测**：关键路径有日志 / 计数；改动可回退。
8. **不为假想未来过度设计**：派生层、修正机制按需再加。

---

## 四、工程品味

1. **契约先于实现**：先定义「怎样算做完」，再写代码。
2. **测试守护**：新增功能默认带测试；护栏脚本必须自测。
3. **迁移版本化、幂等、可回滚**：旧数据不丢、不重复。
4. **文档与代码同步**：改接口 / 数据流 / 决策必须回写文档。
5. **最小侵入**：优先在现有抽象上加分支 / 开关，不重写。
6. **证据链 > 感觉**：结论给文件 / 行号 / 数据；能跑就实测。

---

## 五、红线（摘要；完整见 `../specification/conventions.md`）

- 数据不出本地；敏感信息只存本机。
- 不折算精确时间；不设独立目标实体；不用算法推荐；不做知识资产打分器。
- 学校硬考核逾期不可重组清零。
- 外部知识资产只存引用句柄。
- AI 接口第一版只读 + 新增。
- 不破坏 LWW / schema 迁移 / 备份回滚一致性机制。

---

## 六、改动判断清单

1. 是否直接推动软件能用？
2. 是否闭环（六要素 + 动线）？
3. 是否可逆 / 可回退？
4. 是否违反 conventions 红线？
5. 是否有测试与文档同步？
6. 是否最小侵入？
