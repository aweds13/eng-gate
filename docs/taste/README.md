## 可迁移的品味（通用原则）

### 架构品味
1. **分层清晰、边界干净**——一层只干一件事，跨层只走定义好的接口。
2. **事件优先 + 持久化**——先落事实再更新派生状态；崩溃可恢复。
3. **该便宜的便宜、好钢用在刀刃**——规则/确定性算法/本地计算优先；模型（LLM）只用在「语义判断 + 生成」处，收窄到漏斗最窄处。
4. **增量 + 缓存 + 预筛**——面向长期运行，成本随使用时长可控，不是一次跑完。
5. **能力上下限意识**——改「判别/排序/基线」=可能用上限换效率，必须 shadow + 可回退。
6. **可观测 + 可回退**——关键路径有日志/计数；任何改动一键退回现状。

### 项目管理品味
1. **分域干净**——不同主题单独成文件/模块。
2. **存量打磨 > 增量堆砌**——先理清框架再精细化，反对一味加东西。
3. **别一刀切、别急于颠覆**——错了才颠覆，保留对的（换骨架不删血肉）。
4. **回退优先、先 shadow 后合入**。
5. **证据链 > 感觉**——改基线先量化，结论给文件/行号/数据。
6. **成本与隐私并重**——本地优先、数据不出；省钱别牺牲核心能力。
7. **最小侵入**——优先在现有抽象上加分支/开关，不重写架构。

### 红线（坚决不做）
- 不泄露敏感数据到日志/PR/截图；数据不出本地。
- 不破坏一致性机制（事件优先、增量、缓存、去重）。
- 不降能力上限、不塌下限（异常/冷启动可回退）。
- 不增加对用户数据的新外部依赖（本地优先/隐私最小）。
