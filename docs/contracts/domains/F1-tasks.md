# SR-F1 任务管理 · 操作与动线契约

> 六要素定义见 `../interactions.md`；横切行为 B-x 见 `../../specification/behaviors.md`。
> 每个操作 = 入口 / 前置 / 输入 / 后续 / 可逆 / 反馈 + 空态 / 错误 / 撤销 / 幂等 / 边界。

## OP-1 新建任务（扩展）

- 入口：今日页输入区（标题 + 截止日 + 是否加入 My Day + 可选分组）。
- 前置：无。
- 输入：标题必填；截止日可选；是否加入 My Day 默认不勾选；分组可选。
- 后续：校验 → 落库 → 过去日期即标逾期 → 刷新列表 → 清空输入并回焦。
- 可逆：可删除（软删除 + 撤销）。
- 反馈：新任务即时出现；错误就地提示。
- 边界：空标题、非法日期、超长文本、重复提交均按 B2/B5 处理。

## OP-2 加入 / 移出 My Day

- 入口：任务卡片上的「加入 My Day」/「移出 My Day」。
- 前置：任务未取消/未归档。
- 输入：无。
- 后续：切换 is_myday → 列表与摘要刷新。
- 可逆：同一按钮反向操作。
- 反馈：按钮文案与所在分区即时变化。
- 边界：重复点击幂等；已完成任务默认不可加入（可配置）。
- **顺序（T-G79 起，2026-09-25）**：My Day 这一栏的先后**由用户自己摆** ——
  拖拽抓手拖到某一条前面，或按卡片上的 ↑↓（键盘/读屏那条路，与拖拽写的是**同一份**顺序）。
  落点语义是「**放到那一条前面**」而不是「第几格」（`{"before": "<id>"}`；`{"before": null}` = 末尾），
  所以中间插队或有条目被隐藏都不会错位；`POST /api/tasks/{task_id}/myday-move` 承担这一件事
  （两键**要么给一个要么不给**，都给 → 400；`before` 给**空串**（`{"before": ""}`）也 → 400
  —— **空串不静默当末尾**，只有 `{"before": null}` 才是"末尾"；任务不存在 → 404 先于「不在今天」那一步）。
  **进「今天」= `NULL`（新来的排最后）**、**离开「今天」= 清空**、**没拖过的排后面**并按老口径
  （`截止日 → 优先级 → 创建时间`）—— 顺序**只由用户动作产生**，没有任何后台逻辑改它。
  边界：拖到自己前面 / 已在头尾按 ↑↓ = 原地不动（幂等）；只排「今天」这一栏，不做跨视图拖拽；
  `myday_rank` 不是 PATCH 可写字段。见 `SR-F1.1b` / 台账 `T-G79`。

## OP-5 完成任务 + 撤销

- 入口：任务左侧勾选。
- 前置：任务未完成/未取消；父任务需子任务全完成（或确认强制）。
- 输入：无。
- 后续：置完成 → 发 `task.completed` 事实 → 账本记投入 → 父任务联动 → Repeat 生成下一次。
- 可逆：取消完成 → 发反向事实 `task.uncompleted` → 回退投入 → 恢复原状态。
- 反馈：划线；摘要/债务即时更新。
- 边界：重复完成幂等；已完成子任务；Repeat 只生成一次；撤销后 Repeat 生成的下一次也被撤销或标记。
- API（第 2 步实现）：`POST /api/tasks/{id}/complete`、`POST /api/tasks/{id}/uncomplete`
  （body 可选 `restore_status`，默认回「未开始」）、`GET /api/tasks/{id}/facts`（事实流水）。

## OP-6 删除任务

- 入口：任务卡片「删除」。
- 前置：无。
- 输入：无。
- 后续：二次确认 → **软删除**（status=已删）→ 发 `task.deleted` 事实 → 默认视图移除 → 提示条可撤销。
- 可逆：**是**（`POST /api/tasks/{id}/restore`，默认恢复「未开始」；回收站 `GET /api/tasks/deleted`）。
- 反馈：项消失 + 「已删除，可撤销」提示。
- 边界：删除不存在任务 404；重复删除/重复恢复幂等；已删任务不计债务、不进 My Day。
- **彻底删除（2026-09-18 按用户反馈暴露到界面）**：`DELETE /api/tasks/{id}/purge`（单项）与
  `POST /api/tasks/purge-deleted`（清空回收站，固定路径须声明在 `/{task_id}` 之前）；
  **只能删回收站里（已删）的任务**，活动任务会被拒（400）—— 先软删除再彻底删除，避免误用；
  界面两处都二次确认（清空是两道），且明确写「不可恢复」。
  理由：纯软删除会让回收站无限堆积，需要一个真正的清理出口。

## OP-8 Repeat 生成下一次

- 入口：无独立入口，由完成触发。
- 前置：任务有重复设置且本次完成。
- 输入：无。
- 后续：以上次完成时间为基准 + 周期 → 生成下一次（继承标题/分组/重复/My Day 设置）。
- 可逆：可删除生成项。
- 反馈：列表多出下一次任务。
- 边界：未完成不生成；重复完成不重复生成；无截止日的重复任务不生成（无从推算）。
- 实现（第 5 步）：`complete_task` → `process_repeats`；幂等依据 = `task.repeat.generated` 事实
  （subject=原任务、extra 带 `next_task_id`/`next_due`/`repeat_days`），同一任务只生成一次。
- **节奏回看（T-G25，2026-09-23；补上 SR-F1.5b 的「节奏可用时间热力图管理」）**：
  每完成一轮就多一行任务，所以一个重复事项在库里是**一串** —— 统计页「重复节奏」按
  **同一标题 + 同一周期**把它归成一条，格子按**排期日**画三种状态（做完了 / 排了没做 /
  取消·搁置·归档未完成）。两条别改的规矩：**不推算"以后该哪天"**（周期是「每 N 天」，
  锚点会漂，算出来的日历是假的）、**归档 ≠ 做完**（未完成的也能归档，所以只认
  `task.completed` 事实）。实现：`insights.repeat_rhythm()` + `GET /api/insights/repeat-rhythm`。

## OP-9 编辑任务

- 入口：任务详情面板。
- 前置：任务存在。
- 输入：标题/截止/分组/备注/重复/优先级/提醒。
- 后续：校验 → 落库 → 刷新；due_date 变化时重算逾期。
- 可逆：再次编辑回原值（可撤销到上次保存）。
- 反馈：保存 toast + 列表更新。
- 边界：已完成任务可编辑备注但不改历史完成事实。
- 实现（2026-09-18）：详情面板「编辑」态可改 标题/截止/分组/重复/是否在今天（T-A3）；
  **备注 note 已落地**（T-B1，schema v6：编辑态文本域可写可清空，非编辑态显示，**列表不显示**；
  备注不发事实、不动账本）；**优先级 priority 已落地**（T-B2，schema v7：三档高/中/低、默认中，
  编辑态可改，卡片与详情显示色标；非 My Day 视图排序统一为 `截止日 → 优先级 → 创建时间`，
  见 SR-F1.1b —— **My Day 那一栏自 T-G79 起改成「你拖出来的顺序在前、没拖过的按这个口径垫后」**）；
  **附件/要求链接 attach 已落地**（T-B4，schema v9：详情面板可挂/可点开/可删，见 OP-46）；
  **提醒 remind_at 已落地**（T-B5，schema v10：`datetime-local` 可设、可清空；界面按
  `over/today/soon/later` 标出，今日页有「该提醒了」区）；**到点系统通知也已落地**
  （计划任务方案 B′，见 OP-47：默认关、开关可逆、关掉应用也响、注销/关机不响）；
  **响铃收口已落地**（T-B5c，用户实测"电脑一直在响"后加）：闹钟式**会一直响到被关掉**，
  因此 ① 弹新的**先清旧的**（同一时刻最多一条）② 一次只弹一条（多条合并）③ 设置页有
  **「停止响铃」**（`POST /api/reminders/stop`，本机来源守卫）—— 不必去通知中心找 ✕。

## OP-10 逾期处理

- 入口：逾期栏任务卡片操作区。
- 前置：任务逾期。
- 输入：推到明天 / 改 ddl / 标逾期 / 取消 四选一。
- 后续：改 due/status → 刷新债务与摘要。
- 可逆：改 ddl 可再改；取消需确认。
- 反馈：逾期项数与程度即时变化。
- 边界：学校硬考核提示更强但不改温和基调。
- 实现（第 5 步）：逾期卡片提供「推到明天」（`PATCH due_date=明天`）与「取消」（二次确认 + `PATCH status=取消`）；
  「改 ddl」由同一 PATCH 承担（界面暂只给快捷入口）。

## OP-11 分组管理

- 入口：侧栏/分组视图。
- 前置：无。
- 输入：分组名（非空、唯一）。
- 后续：创建/重命名/删除；删除需确认，任务保留。
- 可逆：删除分组需快照或二次确认。
- 反馈：分组计数更新。
- 边界：重名拒绝；空名拒绝。

## OP-12 子任务管理

- 入口：任务详情「添加子任务」。
- 前置：父任务存在。
- 输入：子任务标题等。
- 后续：建立父子关系；子任务全完成 → 父任务自动完成。
- 可逆：删除子任务不影响父任务历史。
- 反馈：任务树折叠显示。
- 边界：禁止成环；父任务手动提前完成需提示。

## OP-45 智能视图筛选（Important / Planned / Flagged）

> 编号说明：OP 编号是**全局**的（不按域重开），F1 的 OP-1~OP-12 之后，13–44 已被 F2–F10 占用，
> 故本操作顺位取 OP-45。

- 入口：左栏「重要 / 有计划 / 已标记」；「全部任务」页与各视图顶部的互跳行；设置页「入口」。
- 前置：无。
- 输入：视图名（`important` / `planned` / `flagged`）。
- 后续：`GET /api/tasks?view=<名>` → 按领域层口径筛选 → 仍按统一排序返回。
- 可逆：随时切回「全部任务」（`GET /api/tasks`）。
- 反馈：标题显示当前视图与条数，并写明这个视图"是什么"（口径不靠猜）。
- 边界：**口径定在领域层**（`tasks_in_view`）——Important=优先级「高」、Planned=有截止日、
  Flagged=手动标记位；基线同「全部任务」（只隐藏 归档/已删，完成的仍显示）；
  **未知视图名 400**（不静默返回全部）；标记开关 `POST /api/tasks/{id}/flag` 幂等翻转、不发事实、不动账本。

## OP-46 附件 / 要求链接（挂上 → 点开）

- 入口：任务详情「附件 / 要求链接」区（列表 + 添加 + 打开 + 删除）；学业考核项同一套（见 `F5-academic.md`）。
- 前置：任务存在；打开动作要求来源是本机页面。
- 输入：`target`（网址或本地路径）+ 可选 `title`。
- 后续：`POST /api/tasks/{id}/attachments` 落库（同一 target 幂等不加）→
  `POST /api/attach/open` 按三层规则解析并执行 → 界面按结果反馈。
- 可逆：`DELETE /api/tasks/{id}/attachments/{index}`（越界 400）；附件只是引用，删掉不动原文件。
- 反馈：打开成功 →「已打开文件夹/已定位到该文件/已在新标签打开」；**打不开 → 复制路径 + 明确提示**
  （`action="copy"`，不许静默失败）。
- 边界（`core/attach.py` 一处定义）：
  - 网址（http/https）→ 浏览器新标签；目录 → 打开该目录；
  - 本地文件：白名单扩展名 → 直接打开；否则按模式 `folder`（默认，只到文件夹）/ `direct`（直接打开）/
    `auto`（文档类定位到文件，其它只到文件夹）；
  - **可执行/脚本类任何模式都不直接打开、也不许进白名单**（安全底线）；
  - 路径不存在 → `copy` + 原因；
  - 打开方式与白名单**存服务端**（`app_settings`），不接受请求参数指定；跨站来源 403。

## OP-47 到点通知开关（计划任务 + 系统通知）

- 入口：设置页「提醒」一节（开启 / 关闭 / 试一下）。
- 前置：Windows；用户显式打开（**默认关**）。
- 输入：`enabled`（true/false）、`style`（`alarm` 闹钟式 / `gentle` 温和）。
- 后续：打开 → `PUT /api/settings/reminder` → 注册计划任务 `timeflow-reminders`
  （每 1 分钟跑 `pythonw src/timeflow/app/remind.py --db <库>`，到点弹系统通知）；
  关闭 → **删除该计划任务**（可逆、不留痕）。
- 可逆：随时关闭（删任务）；任务注册失败时**设置不落库**。
- 反馈：状态行显示"是否已注册 / 上次通知时间 / 上次结果 / 上次错误"；「试一下」当场弹一条测试通知。
- 边界：**应用关掉也响**（计划任务在系统层），但**注销/关机时不响**（不擅自用 SYSTEM/密码凭据）；
  同一条提醒只弹一次（改时间重新弹）；一次到点 >3 条合并成一条汇总；**弹失败不静默**（记错误 + 下次重试）；
  改系统状态，故要求来源本机（跨站 403）。
- **提醒方式（2026-09-18 用户反馈"普通通知效果很差"后加）**：`alarm` = Windows **警报通知**
  （`scenario="alarm" duration="long"` + `Notification.Looping.Alarm` 循环响铃 → **留在屏幕上直到手动关掉**、
  能突破免打扰）；`gentle` = 普通通知（几秒消失）。**默认 `alarm`**；两种都不引第三方依赖。
- **响铃收口（T-B5c，2026-09-20 用户实测"电脑一直在响"后加）**：闹钟式**会一直响到被关掉**，所以
  ① 弹新的**先清旧的**（同一时刻最多一条）② 一次只弹一条（多条合并成一条汇总，绝不堆成多个闹钟）
  ③ 设置页有「**停止响铃**」（`POST /api/reminders/stop`，本机来源守卫，幂等）——
  不必去通知中心里找 ✕。清不掉时如实报原因（不静默）。

## OP-48 今天做成了什么（可展开的完成明细）

- 入口：今日页「今天做成了什么」区 —— 三个可点开的项（**默认收起，点一下原地展开**，不用弹窗）。
- 前置：无（只读；不需要开通知、不需要任何设置）。
- 输入：`GET /api/today/done?day=YYYY-MM-DD`（`day` 可省，默认今天；非法日期 400）。
- 后续：只读展示，**不写库、不发事实、不改任何状态**。
- 可逆：点「收起」即折叠（纯界面状态）。
- 反馈：三行数字与展开的明细**同源**（同一次只读统计）：
  1. `完成任务 N 项` → 今天完成且**现在仍是完成**的非子任务（按 id 去重，带完成时刻）；
  2. `完成步骤 M 个（属于 K 个任务）` → 子步骤**按父任务分组缩进**，每组显示父任务进度
     （`今天几步 / 已推进几步 / 共几步`）—— 回答"大任务推进到哪了"；
  3. `产出 K 条（学校 KPI x · 知识资产 y）` → 今天产出明细（备注/数量/时间；**已撤销的如实标出**
     且不计入条数）。
- 边界：**只读事实层**（`task.completed` + `output.manual`），不新造派生表；
  今天完成又被撤销的**不算**"做成了"（数字不许比明细多）；昨天的完成不算今天；
  父任务被硬删时明细仍在、父标题显示"（父任务已不在）"，整页不报错。
- 现状（T-C4 + T-C11，2026-09-19/20）：已实现（测试 `../../tests/test_today_done_line.py`）。

## FLOW-1 / FLOW-2 扩展

- FLOW-1：①新建 → ②进列表/My Day → ③从任务发起专注 → ④结束专注 → ⑤账本+反馈+任务时长+摘要 → ⑥完成 → ⑦摘要更新。
- FLOW-2：到期 → 逾期栏/分级 → 四处置 → 债务变化 → 完成后当天清零。
