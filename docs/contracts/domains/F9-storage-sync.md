# SR-F9 存储 / 同步 · 操作与动线契约

> 六要素见 `../interactions.md`；横切行为见 `../../specification/behaviors.md`。

## OP-39 启动迁移

- 入口：应用启动 / connect。
- 前置：有本地库。
- 输入：目标 schema 版本。
- 后续：逐版本升级；建表/索引/回填；更新 schema_version。
- 可逆：迁移前备份；失败回滚。
- 反馈：日志 + 健康检查。
- 边界：重复启动幂等；残缺库跳过缺表；不丢旧数据。
- 回填口径（v5 / 第 3 步）：只回填**可考证**的事实（历史已完成任务 → `task.completed`，时间取 `updated_at`）；
  缺列/缺值退回 `created_at`；**不伪造时间**，不可考证者（历史复习逐次记录）不回填、记缺口（A-015）。

## OP-40 同步数据

- 入口：**设置页「数据与同步」→「跨端同步（走文件）」**（导出 / 预览 / 导入三个按钮）；
  API：`POST /api/sync/export`、`POST /api/sync/import`（`dry_run=true` 只预览）。
- 前置：两端有数据；导入方**本机来源** + 有一份同步包文件。
- 输入：一份 `timeflow-sync` v1 的 JSON 包（`format` / `format_version` / `schema_version` /
  `device_id` / `created_at` / `tables` / `tombstones` / `counts`）。包里**不含** `app_settings`
  （本机设置）、`sync_logs`（本机冲突历史）、`schema_version`（结构由迁移管）。
- 后续：**先规划后执行**（同一套判断，预览=真跑）：同 id 去重 → 内容一样跳过 →
  LWW（version → updated_at）决定覆盖或保留 → 关系行缺则插（墓碑拦住的不插）→ 墓碑并集 →
  逐条写 `sync_logs`（带 `result` 与"差在哪"）。
- 可逆：包是文件（想回退用**备份与恢复**，OP-42）；覆盖的旧值记在冲突日志里。
- 反馈：报告含 `totals`（新增/覆盖/保留/按墓碑跳过/记下墓碑）+ `conflict_count` + 分表条数；
  界面上是"预览 → 二次确认（写明新增/覆盖/冲突）→ 导入"。
- 边界：**导入永不删本地数据**（远程墓碑只防复活 + 继续传播，v1 明确边界）；
  坏包/非本格式/版本更新 → 400 带原话；**自己导给自己** → 400（设备号相同）；
  跨站来源 403；三类表三套规则（LWW 行 / 只增行 / 关系行）。
- **实现（T-G8，2026-09-22）**：口径见 `复盘/口径定案-待定清单.md` §3（用户定 ③→①→②）。
  模块 `src/timeflow/core/syncpack.py`（包格式 + 合并 + 报告 + 状态，**规则与措辞一处**）；
  schema **v17**：六张会被改的表补 `updated_at`（**触发器**自动维护，不靠逐个入口记得写；
  `tasks` 刻意不挂 —— 换「进行中」顺序不动 `updated_at`，见 T-F1）+ `sync_tombstones` 墓碑表
  （各表 DELETE 触发器自动留痕）+ `sync_logs` 补 `result`/`note`。
  复盘与边界（含"删除不跨端传播"这条 v1 边界）见 `../../../复盘/跨端同步合并机制-T-G8.md`。

## OP-49 手机离线记（跨端场景 ①）

- 入口：**左栏 / 设置页「手机离线记」→「离线记」视图**（视图名 `offline`）；断网或队列非空时，
  顶部提示条也会给一个入口（手机上没有左栏，靠它进得去）。**没有新 API** —— 这一版全在浏览器侧。
- 前置：浏览器支持 IndexedDB（不支持时这一页**照常渲染**，只是明确说「这台设备存不了离线数据」）。
- 输入：新建任务（标题 / 截止日 / 优先级 / 放进今天 / 备注）、勾完成或撤销完成（对**缓存里已有的**任务）、
  习惯打卡 / 取消打卡、一句备忘、每日反馈（计划 / 差距）。
- 后续：连不上电脑时按表入队（`tasks` / `facts` / `habit_logs` / `memos` / `feedback_logs`），
  队列键 = `表|主键`（同一条只留最新）；导出成 `timeflow-sync` v1 包（与 OP-40 同一个格式），
  拷到电脑后在 OP-40 的入口导入 —— **合并判断全部发生在电脑侧**（一处口径）。
- 可逆：**导出不清空队列**（文件丢了不至于丢数据）；清空要显式点「清空（我已导入电脑）」+ 二次确认；
  重复导入是安全的（电脑侧合并幂等，OP-40）。
- 反馈：离线时如实说「这一笔存在手机上」（不假装成功）；顶部提示条常显「还有几条没同步」。
- 边界：
  - **只有「连不上」才兜底**：后端回 400/404 是它说了算，**不入队**（入队＝骗人）；
  - **不改字段、不删除、不做反向回传**：手机上判不准电脑那边有没有更新过（见复盘 §六）；
  - 完成 / 撤销**必须同时写事实**（`source=phone`，`occurred_at` = 手机上那一刻）——
    只改状态的话账本一分不涨；
  - 行的字段按**白名单**挑（`TaskOut` 的派生字段不进包），护栏拿 `PRAGMA table_info` 对账；
  - **离线专注计时不做**（它会牵动电脑侧的派生账目，而导入不过订阅器）—— 单独一张卡。
- **实现（T-G10，2026-09-23）**：`src/web/offline.js`（纯函数造行 + 打包、IndexedDB 队列与缓存）、
  「离线记」视图与离线兜底在 `src/web/index.html`、`src/web/sw.js` 预缓存该引擎。
  测试：`../../tests/test_offline_phone_line.py`（Node 用**同一份代码**造真包 → 真导入真库）、
  `tools/phone_check.mjs`、假 DOM 探针「手机离线记 1/1」、真机自检 10 条。
  复盘（含边界与不做的事）见 `../../../复盘/手机离线记-T-G10.md`。

## OP-50 局域网访问 + 配对（跨端场景 ②）

- 入口：**服务启动方式**——`python tools/serve.py --lan`，或 `config.toml` 的 `[net] allow_lan = true`
  （窗口模式 `timeflow` 同样认）；界面在**设置页「数据与同步 → 局域网访问」**看现状。
  API：`GET /api/settings/lan`（现状）、`PUT /api/settings/lan`（换配对码）、`POST /api/lan/pair`（配对）、
  `POST /api/lan/selfcheck`（本机网络自检）。
- 前置：这台电脑与那台设备在**同一个 WiFi**；服务**显式**开着局域网（默认关）。
- 输入：手机的浏览器打开 `http://<本机局域网地址>:8520`；第一次要输入**配对码**
  （在电脑的设置页显示，或起服务时打印）。
- 后续：静态壳先放行（页面能打开）→ `/api/*` 要配对码 → 配对成功后每个请求带
  `X-Timeflow-Pair`（前端存本机 localStorage）→ 与桌面浏览器**同一套界面**可用。
- 可逆：去掉 `--lan`（或把 `allow_lan` 改回 false）**重启**即恢复只监听本机；
  清掉本机记住的码 = 配对墙上的「清掉本机记住的配对码」；换码 = 电脑上「换一个配对码」（旧码立刻失效）。
- 反馈：起服务时打印地址 + 配对码 + **代价**（同一 WiFi 下别的设备也可能访问到 / 不是加密）；
  没配对时整页显示**配对墙**（说清去哪看码、为什么手机上看不到），不是"操作失败"。
- 边界：
  - **默认关**（口径同 N16「默认收严、用户再放宽」）；**只在同一个局域网里管用**
    （同一个 WiFi，**或你自己开的热点**），不涉及公网；
  - ⚠️ **校园网 / 公共 WiFi 常开客户端隔离**（看着同一个 WiFi，设备之间其实不通）——
    那是网络策略，不是本软件的问题；**按公共网络对待**（要用才开、用完就关）。
    排查顺序（口径在 `lan.selfcheck().hint`）：**热点优先** → 手机热点/USB 共享 → 「离线记」导文件；
  - **自检只报能查的那一半**（`POST /api/lan/selfcheck`）：服务开没开、有哪些地址、
    本机能否经它们访问自己（≈防火墙）；**客户端隔离查不出来**（"手机 → 电脑"的事），
    不假装能判 —— 返回里带 `caveat` 说明"可达"是必要条件不是充分条件；
  - ★ **配对码只在本机（回环）响应里出现** —— 局域网设备能读数据，读不到"钥匙"；
    `PUT`（换码）也只允许回环；
  - 静态壳与 `/api/lan/pair` **免检**（否则手机连输码那一页都打不开）；
  - 失败节流：连续错 20 次锁 5 分钟（按来源），防 6 位数字被慢慢试；
  - 配对过的设备 = **当作本机页面**（那道 origin 守卫防的是跨站，不是"你的另一台设备"）；
  - 这条路上是**明文 HTTP**：配对码防的是"随手连一下"，不是同 WiFi 抓包 —— 不装作它是加密。
- **实现（T-G10b，2026-09-23）**：判定在一处 `src/timeflow/core/lan.py`（纯函数，可真值表测）；
  中间件 `lan_gate` 在 `src/timeflow/api/app.py`；启动方 `tools/serve.py` / `app/main.py` 与
  "绑哪个地址"是**同一个决定**。测试：`../../tests/test_lan_pairing_line.py`（20 条）、
  假 DOM 探针「局域网配对 1/1」（含配对墙出现与撤销）、真机自检 7 条（**从本机局域网地址真访问**）。
  复盘（含四条设计选择与诚实边界）见 `../../../复盘/局域网访问与配对码-T-G10b.md`。

## OP-41 冲突处理

- 入口：同步结果 / 冲突日志（`GET /api/sync/logs`，设置页显示条数）。
- 前置：有冲突（两边都改过、或只增行内容不同、或远程删过本地还有）。
- 输入：无（自动）或用户选择保留哪版（改回即可）。
- 后续：逐条记 `sync_logs`：`result`（**覆盖（远端较新）** / **保留本地（本地不旧）** /
  **按墓碑跳过** / **远程已删（本地保留）** / 只增行冲突）+ `note`（差在哪，最多三处）。
- 可逆：可手动改回；导入前的状态可用**备份与恢复**回退（OP-42）。
- 反馈：冲突可见（报告里给样例、日志里是全量），**不静默**。
- 边界：时间戳相同 → 按版本决胜；版本也相同 → **保留本地**并记一条冲突（不随机、不偷改）；
  秒级精度决定了"同一秒两边都改"会落在这一条上。

## OP-42 备份 / 回滚

- 入口：**设置页「数据与同步」→ 备份与恢复**；命令行仍是 `tools/serve.py`（启动前自动备份）。
- 前置：有数据库。
- 输入：要恢复到哪个时间点（从备份列表里点一个）。
- 后续：见下面「实现」——恢复是**整库回到那一刻内容**，不是挑表回滚。
- 可逆：**恢复前会先自动再备份一次现库**，所以这一步是可逆的（界面上必须写明，否则用户不敢点）。
- 反馈：成功提示（含"恢复前的现库也留了一份：<文件名>"）；备份比程序新时**如实提示**。
- 边界：**备份名是唯一的安全边界**（不许带路径、不许 `..`、必须是本库的备份）；
  恢复是**不可逆动作** → 必须壳级二次确认（确认按钮写清"恢复到这个备份"）。
- **实现（2026-09-21 用户定：设置页列出最近几个备份、点一下恢复）**：
  - 模块 `src/timeflow/storage/backup.py`（**口径只有一份**，`tools/serve.py` 与 `app/main.py` 共用）：
    `make_backup()` / `list_backups()` / `resolve_backup()`（名字校验）/ `restore()`；
  - **什么时候自动备份**：起服务前（`tools/serve.py`）**与开窗口前**（`app/main.py`）各一次 ——
    都在"首次连接会跑 schema 迁移"之前；
  - **恢复怎么写**：SQLite **在线备份 API**（`Connection.backup`）把选中备份的**内容**写回当前库，
    **不替换文件**（Windows 上替换正被连接打开的文件会失败，且已打开连接的页缓存还是旧的）；
    为此 `storage/db.py` 提供 `raw_conn()`（拿到线程代理背后的真连接）与 `migrate()`（就地升级 schema）；
  - **老备份的 schema** 恢复后就地升到当前版本；备份比程序**新**时（降级场景）不改它，
    但返回值带 `newer_than_app=true`，界面如实提示；
  - API：`GET /api/settings/backups`（最多 20 条，最新在前）、`POST /api/settings/restore`
    （**服务端持有 + 只接受本机页面**，非法名 400）；
  - 测试：`../../../tests/test_backup_restore_line.py`；界面接线见 `../../../tests/test_web_frontend.py`。

## 桌面形态与启动入口（AC-11 / SR-NF16）

- **窗口形态**：`timeflow`（`src/timeflow/app/main.py`）或 `python tools/serve.py --window` ——
  起本地服务 + pywebview 窗口（依赖已在 `pyproject.toml` 的主依赖里，不需要另装）。
- **回退**：`import webview` 失败、或窗口起不来（例如缺 WebView2 运行时）→ **打印原因**后
  退回浏览器。**不许静默回退**（静默会让人以为自己在用桌面版）。
- 两个入口**都先备份**（同一份口径，见 OP-42）。
