# 契约层 · 动线契约（flows）

> **本层是什么**：`docs/contracts/` 的第二份。`interactions.md` 管「单个操作怎样才算做完」，本文件管「**多个操作串起来的主流程必须走通**」。
> 它回答的问题是——**用户从"想做"到"做完"，路径是否连续、数据是否流动**。
> 上游：`specification/functional.md` + `specification/conventions.md`。配套：`contracts/interactions.md`。
> ⚠️ **实现任何联动前必读**。只写「链路与触发」，不写"哪个模块"（implementation 的事），不贴源码。
> 范围：**MVP 主链路**（任务 / 专注 / 记账 / 反馈 / 摘要）。其余域延后。

---

## 使用方式（给 AI 的硬约束）

1. 动线是**端到端**的：链上任一环断开，整条动线即不成立——**不允许"我这块做好了"就算完**。
2. 实现时按「触发 → 传导 → 落点」逐步核对，每一跳都必须有真实调用。
3. 每条动线给「贯通验收」——**必须真的跑一遍**，不是看代码有没有函数。

---

## FLOW-1 主链路：把一件事做完（MVP 核心动线）

> 这是 MVP 的**唯一命脉**。走不通 = MVP 不成立。

```
① 新建任务（标题 + 截止日 + 加入 My Day）
        ↓
② 任务出现在「今天」或「任务列表」
        ↓
③ 从任务上「开始专注」（绑定任务）→ 计时器可见
        ↓
④ 「结束专注」→ 时长落库
        ↓
   ┌────────────────┬─────────────────┬──────────────────┐
   ↓                ↓                 ↓                  ↓
⑤投入账+1条     ⑤当日反馈自动累加   ⑤任务累计时长+    ⑤摘要「投入」即时+1
        ↓
⑥ 勾选「完成」→ 状态完成 + 投入账+1条（任务完成）
        ↓
⑦ 摘要更新：债务/投入随之变化
```

**传导契约（每一跳必须真实存在）**

| 跳 | 触发 | 传导 | 落点 | 缺则 |
|---|---|---|---|---|
| ①→② | 落库 task | 列表重取 | 今日/任务列表 | — |
| ③ | 开始专注（带 task_id） | session 落库为**进行中** | 计时器显示 | ⚠️P0 现无计时器、无绑定、状态即完成 |
| ④→⑤a | 结束专注（正常） | **专注 → 投入账** | ledger 投入轴 +1 | ⚠️P0 无 |
| ④→⑤b | 结束专注 | **专注 → 当日反馈** | 当日 focus_minutes 自动累加 | ⚠️P0 无（现靠前端传参且不传） |
| ④→⑤c | 结束专注（有绑定） | **专注 → 任务** | 该任务累计时长 + | ⚠️P0 无 |
| ④→⑤d | 结束专注 | **专注 → 摘要** | 今日投入即时刷新 | ⚠️P0 无 |
| ⑥→⑦ | 勾选完成 | **完成 → 投入账** | ledger +1（kind=任务完成） | ⚠️P0 无 |
| ⑥→⑦ | 勾选完成 | **完成 → 摘要** | 债务/投入刷新 | ⚠️P1 非即时 |

**贯通验收（必须实测）**
- [ ] 从零到「摘要有投入数字」：新建 → 专注 → 结束 → 摘要投入 > 0。
- [ ] 结束专注后，当日反馈的专注分钟**未经任何手动输入**自动增加。
- [ ] 绑定任务后，该任务的累计时长增加。
- [ ] 勾选完成一条任务后，投入账多一条。

## FLOW-2 逾期处理动线

```
任务到期未做
   ↓
出现在「逾期（债务）」区（标红，但不施压）
   ↓
显示债务程度分档（轻/中/重，按逾期天数）
   ↓
用户可处置：推到明天 / 改截止日 / 标逾期 / 取消
```

**传导契约**

| 跳 | 触发 | 传导 | 落点 | 缺则 |
|---|---|---|---|---|
| 到期 | 时间推进 | 未完成且有截止 → 计入逾期 | 逾期区 + 债务项数 | ⚠️P1 现靠 `created_at` 近似 |
| 展示 | 渲染逾期区 | 附**程度分档**（轻≤3/中≤7/重>7） | 界面 | ⚠️P1 现不展示分档 |
| 处置 | 用户操作 | 推到明天→改截止；取消→计完即止 | task 状态 + 债务 | ⚠️P0 四个动作全无入口 |
| 清零 | 完成 | **完成 → 债务当天清零** | 债务项数减少 | ⚠️P1 无落账，靠实时算 |

**贯通验收**
- [ ] 逾期任务显示程度分档，且语气温和（无告警、无强制红点）。
- [ ] 能「推到明天」，且逾期消失。
- [ ] 完成后债务项数减少。

## FLOW-3 专注闭环动线（含中断）

```
开始专注（番茄/普通，可绑定任务）
   ↓
计时中（UI 可见）
   ↓
 ┌─正常结束───→ 记投入 + 反馈累加 + 任务累加 + 摘要刷新
 ├─暂停───────→ 保留 session，可继续
 ├─放弃───────→ 不计入投入（或按规则部分计入）
 └─记中断─────→ 记录中断事件，时长按实际计入
```

**传导契约**

| 跳 | 触发 | 传导 | 落点 | 缺则 |
|---|---|---|---|---|
| 开始 | 点击 | session = **进行中** | 计时 UI | ⚠️P0 状态即完成 |
| 正常结束 | 点击结束 | 见 FLOW-1 ④→⑤ | 账本/反馈/任务/摘要 | ⚠️P0 |
| 放弃 | 点击放弃 | 不计投入 | session 标记 abandoned | ⚠️P0 无入口 |
| 记中断 | 点击 | 记中断 + 时长按实际 | 账本（按实际时长） | ⚠️P0 无入口 |

**贯通验收**
- [ ] 番茄钟能倒计时并在结束时自动提示或结束。
- [ ] 「放弃」的专注不产生投入记录。
- [ ] 「记中断」产生一条带中断标记的记录。

## FLOW-4 反馈闭环动线

```
当日进行任务/专注
   ↓
专注时长自动累积到「当日反馈」
   ↓
用户补录：计划 vs 执行差距
   ↓
反馈数据可被「自检」消费（非 MVP，延后）
```

**传导契约**

| 跳 | 触发 | 传导 | 落点 | 缺则 |
|---|---|---|---|---|
| 专注 → 反馈 | 结束专注 | 自动累加 focus_minutes | feedback_logs | ⚠️P0 无 |
| 任务 → 反馈 | 完成/未完成 | 反映在"执行"侧 | feedback | ⚠️P1 前端 `executed` 从不传 |
| 用户补录 | 保存 | 写入 plan_note / gap_note | feedback | ✅ 有 |

**贯通验收**
- [ ] 只做专注、不手动填，当日反馈的专注分钟也已自动有值。
- [ ] 能记录「计划」与「执行差距」两侧（不再只有计划）。

## 与三层文档的关系（防混淆）

| 文档 | 回答什么 | 颗粒度 |
|---|---|---|
| `specification/functional.md` | 系统**必须有什么**（结果） | 一条条"必须" |
| `specification/conventions.md` | **无论做什么都不能违反什么**（横切基线） | 简短规则 |
| **`contracts/interactions.md`** | **单个操作要走到哪步才算做完**（行为链路） | 六要素 |
| **`contracts/flows.md`** | **多个操作串起来必须走通什么**（数据流动） | 触发→传导→落点 |
| `implementation/modules.md` | **哪个模块负责** | 模块名+职责 |

> **一句话：spec 说"要有什么"，契约说"怎么才算真的做成"，impl 说"谁来写"。**
