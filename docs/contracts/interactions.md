# 契约层 · 操作契约（interactions）

> **本层是什么**：介于 `specification/`（必须做到什么）与 `implementation/`（哪个模块负责）之间的**行为链路层**。
> 它回答的问题是——**一个操作要走到哪一步才算"做完"**。
> 上游：`specification/functional.md`（SR）+ `specification/conventions.md`（约定）。下游：真实代码。
> ⚠️ **实现任何操作前必读**。只写「行为与链路」，不写"哪个模块"（那是 implementation 的事），不贴源码。
> 范围：**MVP 核心操作**（任务 / 专注 / 记账 / 摘要）。其余域（复习/学业/团队/备忘录/分组/习惯/同步）延后。
> 其余域与全部边界契约见 `domains/README.md`（B1–B3 逐域填充）。

---

## 使用方式（给 AI 的硬约束）

1. 实现任一操作前，先读本文件 + `specification/conventions.md`。
2. **每个操作的「后续」全部是必须项**，不是可选项。少做一条即视为未完成。
3. 每个操作实现后，用本文件的「验收」逐条自检并回填。
4. 若某要素当前无实现（见下各条 `⚠️P0`），**必须先补齐才算实现完成**。

## OP-1 新建任务

- **入口**：今日页输入区（标题输入 + 截止日选择 + 「加入 My Day」勾选 + 「添加」按钮）。回车等同点击添加。
- **前置**：无。
- **输入**：标题（必填，去空格后非空）+ 截止日（可选）+ 是否加入 My Day（可选，**默认不勾选**）。
- **后续**：
  1. 校验标题非空，否则就地提示、不入库。
  2. 落库（title / due_date / is_myday）。
  3. 若 due_date < 今天 → 初始状态置「逾期」。
  4. 刷新列表：进了 My Day 的出现在「今天」，否则出现在任务列表。
  5. 清空输入框，焦点回到标题。
- **可逆**：可删除（见 OP-6）。
- **界面反馈**：新任务即时出现在对应列表；输入框清空。
- **验收**：
  - [x] 只填标题能建成（不进 My Day）。
  - [x] 能设截止日，且过去日期建成即标逾期。
  - [x] 勾选后出现在 My Day。
- **✅ 第 4 步已闭环**：今日页输入区 = 标题 + 截止日 + 「加入今天」勾选；回车等同点击；建成后清空并回焦。
  （「未进 My Day 的任务」在今日页不可见，需靠 OP-2 的「全部任务」视图；见该条残留。）

## OP-2 把已有任务加入 My Day

- **入口**：任务列表项上的「加入 My Day」按钮；已在 My Day 的项显示「移出 My Day」。
- **前置**：存在未完成/未取消的任务；需有「全部任务」列表视图（当前缺失）。
- **输入**：无。
- **后续**：
  1. 置 `is_myday=true`（或反向）。
  2. 刷新：项在「今天」与「任务列表」间移动。
- **可逆**：是（同一按钮反向操作）。
- **界面反馈**：按钮文案随之切换；项在两个分区之间移动。
- **验收**：
  - [x] 能把已有任务挑进 My Day。
  - [x] 能移出 My Day。
  - [x] 按钮文案与实际行为一致。
- **✅ 第 4 步已闭环**：任务卡片按钮按状态显示「加入 My Day」/「移出 My Day」（原「移除」名实不符已修正）。
- **⚠️残留**：仍无「全部任务」列表视图 —— 未进 My Day 的任务在今日页看不到（不影响后端，属第 4 步后续补页面）。

## OP-3 开始专注

- **入口**：专注页「番茄钟 / 普通计时」按钮；任务卡片上的「开始专注」（用于绑定任务）。
- **前置**：当前无进行中的专注（若有 → 提示先结束或拒绝开始）。
- **输入**：模式（番茄 / 普通）+ 可选绑定任务 id。
- **后续**：
  1. 落库 session，状态置「进行中」（**不得**直接置 finished）。
  2. 界面进入计时态：显示计时（番茄倒计时 / 普通正计时）+ 「结束」「暂停/放弃」按钮。
  3. 若绑定了任务，界面标明当前专注归属的任务。
- **可逆**：可放弃（见 OP-4）。
- **界面反馈**：计时器可见并走动；按钮区切换为「结束 / 放弃」。
- **验收**：
  - [x] 开始后能看到计时在走。
  - [x] 能从任务发起，且标明绑定成功。
  - [x] 重复开始被拒（不产生两条并行 session）。
- **✅ 第 4 步已闭环**：`start_session` 落 `status=进行中`（第 4 步修）；新增 `GET /api/focus/active` 支持重开页面恢复；
  专注页有走动计时器与「不绑定任务 / 选任务」下拉；任务卡片有「专注」按钮（绑定该任务）。

## OP-4 结束专注（MVP 最关键）

- **入口**：计时态下的「结束」按钮；中断时另有「暂停 / 放弃 / 记中断」。
- **前置**：存在状态为「进行中」的 session。
- **输入**：无（时长自动计算）；中断时选择处置方式。
- **后续（四步全部必须执行）**：
  1. **落库**：写 ended_at、duration_sec、status（finished / paused / abandoned / interrupted）。
  2. **记投入账**：若为正常结束 → 记一条投入（值=时长），kind 标明来源为「专注」。
  3. **累加当日反馈**：当日反馈的专注分钟数**自动累加**（不由前端传入）。
  4. **累加绑定任务**：若绑定了任务 → 该任务累计专注时长增加。
  5. 界面退出计时态，刷新「今日专注分钟」。
- **可逆**：否。但「放弃」不计入投入（时长不入账）。
- **界面反馈**：计时停止；今日专注分钟即时 +N。
- **验收**：
  - [x] 结束一次专注后，今日摘要的「投入」增加。
  - [x] 当日反馈的专注分钟自动增加（前端不传参也增加）。
  - [x] 绑定任务的累计时长增加。
  - [x] 放弃的专注不入账。
- **✅ 第 4 步已闭环**：计时态有「结束 / 记中断 / 放弃」；结束时前端只传真实时长，投入、反馈、任务时长由事实层联动完成；
  结束后回到专注页可见「今日专注分钟」即时变化（真机验证见 `tools/lf1_live_check.py`）。

## OP-5 完成任务

- **入口**：任务左侧圆形勾选。
- **前置**：任务非已完成/已取消；若是父任务 → 其子任务须全部完成（否则提示，可手动提前勾）。
- **输入**：无。
- **后续**：
  1. 置 status=完成。
  2. **记投入账**：完成一条任务记一条投入（kind 标明来源为「任务完成」）。
  3. 若该任务有重复设置 → 依据上次完成时间生成下一次任务（见 OP-8）。
  4. 若其父任务的子任务此时全完成 → 父任务自动完成。
- **可逆**：是 —— 可「取消完成」，撤销后回到原状态，**并撤销该次投入记账**。
- **界面反馈**：标题划线；摘要中债务/投入随之更新。
- **验收**：
  - [x] 勾选后任务消失于待办、出现在已完成。
  - [x] 完成后投入账增加一条。
  - [x] 可撤销完成，且投入账回退。
  - [x] 子任务全完成时父任务自动完成。
- **✅ 第 2/4 步已闭环**：完成发 `task.completed` 事实、撤销发 `task.uncompleted`（投入轴按事实解读）；
  前端勾选即完成、再点即撤销；「记录」按钮可查看该任务事实流水。
- **⚠️残留**：Repeat 生成仍无触发点（`process_repeats` 未被调用），留待后续。

## OP-6 删除任务

- **入口**：任务卡片上的「删除」。
- **前置**：无。
- **输入**：无。
- **后续**：
  1. 二次确认（不可逆操作）。
  2. 删除任务及其关联记录（分组关联、子任务关系）。
  3. 界面移除该项；提供「撤销」提示（若实现软删除）。
- **可逆**：删除本身不可逆，故**必须二次确认**；有条件时提供短时撤销。
- **界面反馈**：项消失 + 一句确认提示。
- **验收**：
  - [x] 删除前有二次确认。
  - [x] 删除后列表与摘要同步更新。
- **✅ 第 5 步已闭环（软删除）**：删除 = 置 `status=已删`（软删除，不物理删行），默认视图（列表 / My Day / 逾期 / 债务）
  全部隐藏；留 `task.deleted` 事实；提示条给「撤销」按钮（`POST /api/tasks/{id}/restore`，默认恢复为「未开始」）；
  今日页有「回收站」区可再恢复。彻底删除仅保留 `purge_task()` 供明确清理场景使用。

## OP-7 查看今日摘要

- **入口**：页面顶部摘要区。
- **前置**：无。
- **输入**：无。
- **后续**：
  1. 取债务：逾期任务 → 项数 + 每条天数 + **程度分档（轻≤3天 / 中≤7天 / 重>7天）**。
  2. 取投入：**当日已完成专注时长**（仅正常结束的计入）。
  3. 任一操作（新建/完成/结束专注）后即时刷新。
- **可逆**：—（只读）。
- **界面反馈**：一行摘要「债务 N 项 · 投入 X h（· 复习 N 张）」；债务程度以温和方式呈现，**不告警、不施压**。
- **验收**：
  - [x] 完成一次专注后投入立刻变化。
  - [x] 逾期任务计入债务项数，且程度正确。
  - [x] 呈现语气温和，无强制红点/警报。
- **✅ 第 4 步已闭环**：投入口径改读事实（只有正常结束计入）；摘要行含复习张数；今日页在债务非 0 时以
  「轻≤3天 / 中≤7天 / 重>7天 + 每项天数」一行温和文字呈现，无红点无告警。
- **第 9 步补充（SR-NF3 进度形态）**：今日页顶部加「今日完成度」进度环 ——
  `已完成 ÷（已完成 + 仍在手）`，只统计今天的清单与今天完成的（不翻旧账、无目标对标）；无任务时显示「—」。
- **⚠️残留（P2）**：非即时推送 —— 仍是操作后重新拉取（本地单机可接受）。

## OP-8 重复任务生成下一次（联动项）

- **入口**：无独立入口（由「完成任务」触发）。
- **前置**：该任务设置了重复周期，且本次已完成。
- **输入**：无。
- **后续**：
  1. 以**上次完成时间**为基准 + 重复周期 → 计算下次截止日。
  2. 生成下一次任务（标题/分组/重复设置继承）。
  3. 新任务初始进 My Day 与否，遵循其自身设置。
- **可逆**：生成后可删除。
- **界面反馈**：完成后列表中多出下一次任务。
- **验收**：
  - [x] 完成重复任务后，自动出现下一次。
  - [x] 下次截止日基于**完成时间**而非创建时间。
- **✅ 第 5 步已闭环**：`complete_task` 对设了重复的任务调用 `process_repeats`；
  幂等依据是 `task.repeat.generated` 事实（同一任务只生成一次，重复完成/重复扫描都不再生成）；
  继承标题/分组/周期/My Day；无截止日的重复任务不生成（无从推算）。前端完成后刷新即见下一次。
