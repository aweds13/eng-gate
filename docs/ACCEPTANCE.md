# 验收清单（ACCEPTANCE / DoD）

> 每个功能 = 一段**具体、可验证的验收标准（DoD）**。编码拿它当"完成定义"，提交前逐条打勾，跑测试 + 手动验证。对应 `CODING_GUIDELINES.md` 与规格（SR）。
> ⚠️ **术语警告**：本文件的"MVP"＝**第一版功能清单**；与 `contracts/`（契约层）中的"MVP"＝**框架+2线+交叉**含义不同，勿混用。
> ⚠️ **已知局限**：下表 AC 以「功能存在」为判据，**不足以发现"操作做一半/联动断裂"**——闭环验收见 `contracts/interactions.md` 的自查表 + `contracts/flows.md` 的贯通验收。
> **可执行验收层（B4）**：闭环验收将逐步落成 API 全链路测试（后续加 UI 冒烟）；覆盖矩阵见 `implementation/coverage.md`。人工清单只保留手感 / 审美项。

## ★ 闭环验收（现行标准·优先使用）

> **判据升级**：从「**功能存在**」升级为「**操作闭环**」。
> 一个操作"存在"≠"完成"；只有**六要素齐备**且**动线贯通**，才算真正做完。
> 依据：`contracts/interactions.md`（操作契约）+ `contracts/flows.md`（动线契约）。

### A. 操作闭环验收（MVP 核心操作）

> 每个操作须满足六要素：**入口 / 前置 / 输入 / 后续 / 可逆 / 反馈**。少一条即未完成。
> 详细定义与逐条验收见 `contracts/interactions.md` 的 OP-1~OP-8。

| # | 操作 | 闭环验收（DoD） | 契约 | 现状 |
|---|---|---|---|---|
| LC-1 | 新建任务 | 能设标题+**截止日**+是否进 My Day；过去日期建成即标逾期 | OP-1 | ❌ 缺截止日输入、强制进 My Day |
| LC-2 | 加入/移出 My Day | 有「加入 My Day」入口；按钮文案与实际行为一致 | OP-2 | ❌ 无「加入」入口；「移除」名实不符 |
| LC-3 | 开始专注 | 计时器**可见并走动**；可绑定任务；重复开始被拒 | OP-3 | ❌ 无计时 UI、无法绑定 |
| LC-4 | **结束专注** | 结束即：①落库 ②**记投入账** ③**自动累加当日反馈** ④**累加绑定任务** ⑤刷新 | OP-4 | ❌ 无结束入口；四步联动全无 |
| LC-5 | 完成任务 | 完成即**记投入账**；可**撤销**（并回退记账）；子任务全完成驱动父任务 | OP-5 | ❌ 不记账、不可撤销 |
| LC-6 | 删除任务 | 二次确认；删除后列表与摘要同步 | OP-6 | ❌ 无删除入口 |
| LC-7 | 查看摘要 | 债务项数（含**程度分档**）+ 投入时长；操作后即时更新 | OP-7 | ⚠️ 口径失真、不显示分档 |
| LC-8 | 重复任务生成 | 完成后自动出现下一次（基于**完成时间**） | OP-8 | ❌ 逻辑存在但无触发点 |

### B. 动线贯通验收（端到端必须走通）

> 详见 `contracts/flows.md`。**动线是端到端的：链上任一环断开，整条动线不成立。**

| # | 动线 | 贯通验收（必须实测） | 契约 |
|---|---|---|---|
| LF-1 | **把一件事做完**（MVP 命脉） | 新建 → 专注 → 结束 → **摘要有投入数字**；且反馈的专注分钟**未经手动输入**自动增加 | FLOW-1 |
| LF-2 | 逾期处理 | 逾期显示程度分档且语气温和；能「推到明天」；完成后债务减少 | FLOW-2 |
| LF-3 | 专注闭环 | 番茄能倒计时并结束；「放弃」不入投入；「记中断」带标记 | FLOW-3 |
| LF-4 | 反馈闭环 | 只做专注不手动填，当日反馈已有值；能记「计划」与「执行」两侧 | FLOW-4 |

### C. 闭环验收门（每阶段必跑）

python scripts/check_layers.py        # 五层对齐（含引用完整性、约定层标注）
python scripts/test_check_layers.py   # 护栏脚本自测（正/负样例）
python -m pytest                      # 功能单测
