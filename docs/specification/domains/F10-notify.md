# SR-F10 学校通知接口 · 详细规格

> 上游：N21–N22 + `../functional.md` SR-F10.1 + `../conventions.md`。
> 契约见 `../../contracts/domains/F10-notify.md`。
> **状态（2026-09-23 更新）**：**合作接口已落地**（T-G14，schema v18）；
> **抓取仍然不做** —— 那不是"还没做"，是本规格第 2 条明确不允许（见下 §2）。

## 1. 定位

- 学校通知监测（网站/公众号/群聊/考试网站 → 抓取/集成/通知）由**独立脚本/软件**实现。
- 主工具只提供**合作接口**，不让主软件膨胀。
- **一版落地（T-G14）**：接口 = 收件箱 —— 外部脚本把抓到的通知投递进来，
  主工具负责去重、来源标记、看、以及"转成任务/提醒"；**主工具不去网上拿**。

## 2. 规则

- 主工具不直接抓取外部网站；不新增对用户数据的外部依赖。
- 外部监测结果可通过合作接口转成任务/提醒。**一版口径（T-G14）**：投递进来**先只落在收件箱**，
  **转任务/提醒要用户点一下**（人始终在环里）—— 自动把外部内容变成用户的任务清单，
  是在替他决定"什么算我的事"，属产品口径，不擅自定。
- **默认关**（口径同 N16「默认收严、用户再放宽」，与 AI 接口一致）：没开 = "未接入"，
  投递一律 403 带原话；主工具不轮询、不重试、不报错。
- 隐私：本地优先，不上传用户数据。

## 3. 边界与异常

- 外部脚本不可用：主工具不崩、不报错；只提示未接入（界面上写着"未接入"与去哪打开）。
- 非法/重复通知：**去重靠数据库唯一约束**（`fingerprint`），来源标记必填；
  重复投递只覆盖"这次真的带了"的字段（不把上次的链接/摘要/截止日抹成空）。
- 字段保持扩展位：认不出的字段原样存进 `extra`（JSON），**不丢也不写死**。
- 转任务/忽略/看收件箱**不要求开关开着**（收件箱里已是用户的数据）；
  已转任务的通知不许再被标成忽略（两处说法不能打架）。
- 收件箱**不进同步包**（是外部送进来的东西，不是用户自己写的；转成任务后任务照常跨端）。

## 4. 验收

- 第一版**不设 AC**（F10 不是第一版的验收项，它是"给外部脚本留的口子"）。
- 落地的行为由测试与真机自检钉住（见 §5），不写进 ACCEPTANCE。
