# specification（规格层）— 系统「必须具体满足什么」

> 每条规格 = **可验证契约**（"必须…"），不依赖实现技术。上游是 `../intention/`（需求 N），下游是 `../implementation/`（实现落点）。

## 文档写作规范（约定）

- **区分长期规则与当前细节**：长期适用、横切多处、违反即错的规则 → 进 `conventions.md`；只属于某功能的实现细节 → 留在该功能条目。
- **删去无关说明**：不写解释性/过程性/背景性文字；规则只写「规则本身」。
- **按需加载**：实现某个 SR 前，只需读 `conventions.md` + 该功能的 SR 区块；不加载其它功能的 SR。

> ⚠️ **任何 SR 的实现前，先读 `conventions.md`**（稳定基线，横切所有功能）。

## 编号约定（贯穿三层）
| 前缀 | 含义 | 例子 |
|---|---|---|
| `N` | 需求（intention） | N6 |
| `SR-F` | 功能规格 | SR-F1.1 |
| `SR-NF` | 非功能规格 | SR-NF1 |

每条 `SR` 末尾标注满足的 `N`（可多条），形成 `N → SR` 追踪链（见 `traceability.md`）。
