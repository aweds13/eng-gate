# 文档系统导航 —— 我要找 X，该读哪一份

> 一页纸，只回答路由问题：**哪份是索引、哪份是证据、哪份是判据**，以及五类意图各该读哪个文件。
> 这里不复制任何内容；每一条都落到具体路径，路径由 `gates/diag/nav_refcheck.py` 现跑核过。
> 目录归属和「什么别读」的完整版在 `docs/归置地图.md`。

## 1. 六份索引/总览各管什么

先说最容易踩的一条：这六份**性质完全不同**，混着用就会读错东西。

| 文件 | 是什么 | 什么时候读 | 什么时候别读 |
|---|---|---|---|
| `AGENTS.md` | 仓根路由入口。只做路由，不重复各项目自己的规则 | **每次开工第一份**，先看「活在哪，先看哪」那张表 | —— |
| `docs/INDEX.md` | `docs/` 的**机器生成**索引：按目录列全量篇目，只读 frontmatter 的 title/mode/status/owner/supersedes | 要列 `docs/` 的完整清单、想看某个子目录有哪些页 | 想找「为什么这么定」「具体怎么做」——它只有标题，没有内容；**也别手改**，首行就是 `do not edit`，`python -X utf8 scripts/gen_doc_index.py --check` 会咬 |
| `复盘/INDEX.md` | `复盘/` 的**指路牌**（篇数会漂：2026-11-21 现读 1122 篇，数法 `git -c core.quotepath=false ls-files 复盘`）。三层披露：L0 主题表 → L1 每篇一句话 → 回原文 | 想查「以前踩过什么坑」「某个主题历史上做过什么」，又不想在 1122 篇里翻（★ 这份索引只收 **773 篇**：抽取输入 `gates/diag/retro_*.json` 是 2026-10-26/27 的快照，重跑（`scripts/retro/retro_index.py`）也只是把同样 773 篇重排一遍 —— 新篇目它**一定**不收录，查新东西用 grep） | 把它的 L1 一句话当结论用 —— 它是索引，结论在原文 |
| `docs/归置地图.md` | **什么在哪、什么别读**。六格归属 + `gates/diag/` 扁平契约 + 别读清单 + 一页命令 | 不知道某类东西该放哪个目录；或想确认「这份能不能读」 | —— |
| `复盘/架构索引-分层图.md` | **2026-10-03 的架构浅扫快照**（12 层 + 分层图；各层**计数**已于 2026-10-28 与 2026-11-21 两次现测校正，命令写在该页开头） | 要理解「层 = 谁负责什么 + 谁判它」这个口径；或要一份历史证据 | 把它当**当前**结构用 —— 它是快照，最新结构以 `docs/文档架构.md` 与 `docs/INDEX.md` 为准 |
| `复盘/交接-重构进度.md` | 交接流水（2026-11-21 现读 762423 B ≈ 745 KiB，`pathlib.Path(...).stat().st_size` 现量）。**最新一段在最上面**（每次落地自动插入），旧段越往下越老 | **不整读**。要现状用 `gates/last.json` 与 `python -X utf8 tools/wb_state.py`；要最新一段 CHECKPOINT 用 `python -X utf8 tools/wb_brief.py --card <卡号>`（开工切片会带出来） | 永远：745 KiB 远超工具 256 KB 上限，整读它就是失败 |

外加两份，不算「索引」但也常被当索引翻：

| 文件 | 是什么 | 什么时候读 |
|---|---|---|
| `skills/README.md` | 技能层的分工判据（薄适配层；删掉整个目录框架仍完整可用） | 要跑门、派活、落地、接手的**操作顺序** |
| `复盘/文档索引.toml` | `python -X utf8 tools/wb_docmap.py` 生成的文档地图（路径/字节/归属/被引次数/是否被台账钉住） | 要机器口径的「谁引用了谁」 |

## 2. 按意图路由

### 2.1 我要改代码

顺序是硬的：**先判层，再读实现前必读四步，最后才动手**。

1. 判层与端到端数据流 → `docs/implementation/architecture.md`（实现包根约定为 `src/timeflow/`）
2. 实现前必读（`docs/CODING_GUIDELINES.md` 规定的四步）：
   - `docs/specification/conventions.md`（**由人维护，AI 不得自行增删**）
   - `docs/specification/behaviors.md` + `docs/specification/domains/`
   - `docs/contracts/interactions.md` + `docs/contracts/flows.md` + `docs/contracts/domains/`
   - `docs/implementation/README.md` + `docs/implementation/modules.md` + `docs/implementation/coverage.md`
3. 落点在哪 → `docs/implementation/modules.md`（按规格分组的模块落点）
4. 改动面要不要跑门 → `gates/defs/domains.py`（改动面 → 必需档）
5. 收尾 → `python -X utf8 scripts/check_layers.py`（层完整性 + 引用完整性）

要看具体代码就只有这几个入口：`src/timeflow/core/facts/`（事实层）、`src/timeflow/core/ledger/`（解读层）、`src/timeflow/core/insights.py`、`src/timeflow/api/app.py`、`src/timeflow/app/main.py`、`src/web/index.html`（界面层）。
覆盖矩阵在 `docs/implementation/coverage.md`（`scripts/check_layers.py` 判它含 SR-F1~F10），SR→模块在 `docs/implementation/traceability.md`。

### 2.2 我要查某张卡为什么这么做

先用切片，别直接从 459 张卡规格里翻（2026-11-21 现读：`git -c core.quotepath=false ls-files 复盘` 里卡规格 459 篇；交接片段 `复盘/交接.d` 现读 391 篇 md（目录共 392 个文件））：

1. **开工切片** → `python -X utf8 tools/wb_brief.py --card <卡号>`（硬上限 6 KB，五节固定顺序：现状 / 最新 CHECKPOINT / 本卡引用到的规矩 / 白名单禁区 / 固定坑页）
2. 卡规格原文 → `复盘/卡/`（2026-11-21 现读 459 篇）
3. 落地记录 → `docs/changelog.d/`（逐卡一篇，含红样与真读数）；跨卡汇总在 `docs/changelog.md`
4. 交接流水 → `复盘/交接.d/`（2026-11-21 现读 392 篇，汇总进 `复盘/交接-重构进度.md`）
5. 判决 → `gates/review/`（每卡一份 JSON：改了什么文件 / 域外文件 / 门过没过）
6. 当时那次门禁 → `gates/last.json`（`rev` + `at` + 每道门退出码）
7. 规矩本身 → `复盘/口径坑.md`（每条都是真踩过的，带出处）

### 2.3 我要知道某个门怎么判

判据**只住代码**，文档只是说明。

1. 有哪些门、分几档 → `scripts/run_gates.py`（`GATE_PROFILES` = lang / audit / product）
2. 每道门具体跑什么命令 → `gates/defs/lang_python.py`、`gates/defs/contract.py`、`gates/defs/product_timeflow.py`
3. 我这次改动要哪几档 → `gates/defs/domains.py`（口径：**并集**；落不进表 ⇒ 全量三档，fail closed）
4. 最近一次到底过没过 → `gates/last.json`（每道门的退出码、未跑、复用）；**门数本身**读 `python -X utf8 -c "import sys;sys.path.insert(0,'.');from scripts.run_gates import build_jobs;print(len(build_jobs(False,False)))"`（2026-11-21 现读 = 23 道）
5. 说明页（**不是判据**）→ `复盘/门禁四要素.md`
6. 跑门与读结果的操作顺序 → `skills/pipe-gate/SKILL.md`
7. 红了要定位 → `skills/pipe-forensics/SKILL.md`

### 2.4 我要知道某条规矩的来历

1. 为什么这么定、当时多大把握 → `docs/decisions/`（ADR **不可改**，台账可改 —— 两者语义相反，不要把台账条目导成 ADR）
2. 需求侧动机 → `docs/intention/needs.md`（N1–N46）
3. 真踩过的坑与口径 → `复盘/口径坑.md`
4. 按主题找历史 → `复盘/INDEX.md`（L0 主题表 → L1 一句话 → 回原文）
5. 被推翻过什么 → `复盘/INDEX.md` 的「历史与被推翻」一节

### 2.5 我要发一个新功能

1. 先判属于哪一层、每层要留什么痕迹 → `docs/EXTENDING.md`（模板，依据 SR-NF7 / SR-NF10）
2. 找个最近的例子照着写 → `examples/README.md` + `examples/01_add_a_fact_kind.py`、`examples/02_add_a_config_option.py`、`examples/03_add_a_ledger_view.py`、`examples/04_external_script.py`、`examples/05_plugin_demo/plugin.py`
3. 登记进待办 → `docs/workbacklog.toml`（**受保护，不手改**，走工具）
4. 排期与冲突域 → `python -X utf8 tools/wb_plan.py plan`
5. 开卡 → `skills/pipe-card/SKILL.md`
6. 发布日期口径 → `skills/pipe-land/SKILL.md`
7. 怎样算做成 → `docs/ACCEPTANCE.md`（DoD 清单）+ `tests/acceptance/README.md`（可执行验收，`-m acceptance`）+ `docs/人工验收-照着点.md`（人工层）

## 3. 哪些地方**不是**权威

这一节比上面任何一节都重要：本仓有「证据层 / 索引层 / 判据层」三种东西，混用就会把历史当现状。

- **`复盘/` 不是权威**，是证据层。任何结论以**原文**与 `gates/last.json` 的读数为准；`复盘/` 里的摘要、地图、结论都可能落后。
- **`复盘/架构索引-分层图.md` 的「结构描述」是 2026-10-03 的浅扫**，不是当前结构。最新结构以 `docs/文档架构.md` 与 `docs/INDEX.md` 为准。它的**计数**已于 2026-10-28 与 2026-11-21 两次全部现测校正（一页里每条数字后面都写了怎么数的），但计数仍会随提交漂移 —— 引用前先看那条命令，别把快照当现值。
- **`复盘/门禁四要素.md` 不再自己数门数**：逐门表按 `scripts/run_gates.py` 的 `build_jobs()` 对齐（2026-11-21 现读 **23 道**），它自己也声明**门数以门清单为准**。它写的秒数是那趟实测，**墙钟不写死**（pytest 单门就几百秒）。
- **`复盘/新窗口交接卡.md` 已在 2026-11-21 降级成「入口 + 防漂移清单」**：它的 CHECKPOINT 段停在 2026-09，只当历史；现状看 `gates/last.json` 的 `at` 与 `python -X utf8 tools/wb_state.py`，最新一段 CHECKPOINT 在 `复盘/交接-重构进度.md` 顶部。
- **`docs/INDEX.md` 是机器生成物**，不要手改。它的新鲜度由 `tests/test_gen_doc_index_fresh.py` 在**每次全量门禁**里守着（该钉子跑 `python -X utf8 scripts/gen_doc_index.py --check` 子进程，不一致就红并点名行号）—— 不再靠「人记得跑验收命令」。要现核仍可手跑 `--check`。另：`复盘/INDEX.md` 不走这条链，它由 `scripts/retro/retro_index.py` 生成，本卡没动。
- **`复盘/交接-重构进度.md` 2026-11-21 现读 762423 B（≈745 KiB）**，超工具 256 KB 上限 —— 不要整读，要现状就走工具（`gates/last.json` + `tools/wb_state.py`）。
- **计数类数字默认都过期**。`tests/`、各目录文件数这类读数会随提交漂移；引用它们时写清「哪天实测的」。
