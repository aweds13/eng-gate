# 决策记录（ADR）

> 这里只回答两个问题：**当时为什么这么定**、**当时有多大把握**。
> 台账可以改，ADR 不可以改 —— 两者语义相反，**不要**把台账条目导成 ADR。

## 什么时候该开一条

开：

- 定了判据 / 红线 / 口径，以后要改它得先知道原委（例：域红线、封存「比提交不比长度」）。
- 在两个以上方案里选了一个，且以后一定有人问「为什么不选另一个」。
- 对外依赖或边界定案（例：搜索走官方 API、MCP 只留扩展位）。
- 复盘里出现「定案 / 拍板 / 以后就这么办」。

不开：

- 日常修 bug、调样式、补测试 —— 写 changelog 与复盘就够。
- 设计指南、教程、方案全文 —— ADR 只写「选了什么 + 为什么 + 多大把握」，细节外链。

## 目录与命名

- 目录：docs/decisions/，一篇一个文件。
- 文件名：4 位编号 + 连字符 + slug + .md。
- 编号从 0001 起**连续**，不许有空洞、不许重号、不许复用已删的号。
- slug 只用小写字母、数字、连字符；新记录取「当前最大号 + 1」。

文件名合不合规看这条（判据在检查器里，写在这里方便人查）：

```text
^([0-9]{4})-([a-z0-9]+(?:-[a-z0-9]+)*)\.md$
```

## 模板（五段，一段不许少）

```text
# 0007 决策的短标题

Status: Accepted
Date: 2026-10-24
Supersedes:
Superseded-by:
来源: 台账 T-AG452 + 复盘里的那一篇

## 背景与问题

当时的约束、症状、为什么非定不可。

## 候选方案

A …（代价）
B …（代价）

（记不清就写「当时没有正式比较过」，不要补编。）

## 决定

选了 B，因为 …；放弃 A 的代价是 …。

## 把握程度

medium —— 有一条实测依据，但没在满负载下验过。
```

头信息三件：

- `Status:` 必填，只能是 Proposed / Accepted / Superseded。
- `Supersedes:` / `Superseded-by:` 用不到就留空（留空行或整行不写都行）。
- `来源:` 必写：台账条目号 / 卡号 / 复盘篇名，能顺着读回去。检查器**不判**它
  （判不了出处是真是假），但人评审时会问。

## Status 与取代关系

- **Proposed**：还没定；**Accepted**：已生效；**Superseded**：已被新记录取代。
- 改主意 = 新写一条 000N，写 `Supersedes: 0003`；同一次改动里把 0003 改成
  `Status: Superseded` + `Superseded-by: 000N`。两边必须**互指**，检查器逐对核。
- Accepted 之后只有两行可改：`Status`、`Superseded-by`。标题、来源、`Supersedes`、
  正文全部冻结。
- 记录**不许删**，编号不许复用。

## 把握程度

- **high**：线上跑过 / 多轮实测 / 有明确外部权威依据。
- **medium**：有依据但只在局部验过，或没经过满负载。
- **low**：时间压力下先定，随时可能改。

格式固定成一行：`high —— 因为 …`（`high` 也可以是 medium / low）。检查器认这一行：
没有它、或者符号后面没跟一句话，都判红。

## 怎么检查

```text
python -X utf8 scripts/check_docs.py --decisions
```

它判：编号连续 / 文件名 / 五段齐全且非空 / status 合法 / supersedes 成对 /
HEAD 里已 Accepted 的正文与冻结头信息未被改 / 记录未被删。

它不判：出处是否真实、决定对不对、候选方案是否穷尽 —— 这三件机器判不了，别指望它。

退出码：0 通过 / 1 不通过 / 3 没判完（没有 HEAD，只追加那条没判）。
换一棵树用 --root <路径>（测试拿它喂合成坏样例，真实仓库一个字节都不写）。
