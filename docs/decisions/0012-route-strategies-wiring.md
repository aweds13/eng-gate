# 0012 七种路由策略：判据层全带，接线只到 used

Status: Proposed
Date: 2026-11-21
Supersedes:
Superseded-by:
来源: 卡 A390（台账号 T-AG678）· 规格 `复盘/卡/卡A390-F17七种路由策略接线现状-证据钉子与缺席判词.md` · magpie 移植功能清单 F17

## 背景与问题

magpie 的七个路由策略（In order / In turn / Least used / Weekly pace / Weighted / Free first /
Speed first）是**外部契约**，不是内部枚举：配置里写的就是这些字。本仓把它们逐字抄进了
`tools/pool/route.py` 的 `BUILTIN`，七个策略函数与 `apply_strategy` 分派全在，
`tests/test_pool_route_strategies.py` 63 条钉着它们。也就是说「实现」这一层在卡 A352 就落完了。

真正没落的是**喂料**。生产侧唯一的消费者是网关：`tools/pool/gateway.py` 的 `_seat()`
把一行账本翻成一个座位，四条构造只放 `key` / `account` / `known` / `used` 四项；
而七个策略要的输入并不止这一维 ——

- `weight` 要 `seat.weight` 与跨请求的 `state["rounds"]` 两样；
- `free` 要 `seat.free`，而 `tools/pool/route.py` 自己写着它没有自动来源；
- `pace` 要 `seat.pace`；
- `fast` 要 `seat.ttft` / `seat.tps` 与 `state["probes"]`；
- `rotate` 要跨请求的轮转计数，卡 A372 才把调用方持有的 `turns` 接进 `_order()`。

于是「给 `--routing weight` 跑起来会怎样」这件事今天**没有任何断言拦着**：谁顺手在
`Seat(...)` 里补一个 `pace=`，排位就会静默变化，而既有 171 条判据（网关 108 + 策略 63）
一条都不会红。本记录要回答的正是：**缺席的那几档凭什么缺席，下一次还有人看得见吗。**

## 候选方案

**甲：把六档全部接上线。** 给 `Seat` 补齐六个字段，给每个策略补一份跨请求状态。
代价：六个字段今天**没有一个有数据源** —— 账本里没有权重列、没有免费额度列、没有 TTFT 读数，
号池配置目录下的 toml 里 `weight` 零命中。硬补只能把它们填成 0 或 None，
而「不知道当成知道」正是卡 E95 修掉的那个病。否决。

**乙：什么都不做，把现状留给读者。** 代价：现状散在六处注释与 docstring 里，而注释会漂 ——
草稿写的「没人传 state」在 A372 落地后就翻了（卡规格「诚实边界」第 7 条）。
「谁被喂饱、谁没有」这个问题今天只能靠人重读一遍源码才能回答。否决。

**丙（采纳）：判据层只钉现状，产品码一个字节不改。** 把「喂料下谁动、谁不动」写成可执行的钉子，
把「缺席的为什么缺席」写进这份记录。将来真接线的那一天，钉子会红 —— 红的那一刻就是
改判据、改本记录、另开一张卡的信号，而不是悄悄漂过去。

## 决定

**一、七种策略的判据层全带，接线只到 `used`。**
生产在用的只有 `order`（网关的默认值）与 `usage`（唯一在喂料下会动的策略）；
`smart` 不吃新字段，生产可用；`rotate` 在 A372 之后已喂饱。`pace` / `weight` /
`free` 是**结构在、喂不饱**：函数与分派都在，输入不在。三档各自缺的那一样东西如下
（缺件归属一并写出，免得「以后再说」）：

| 策略 | 缺的输入 | 缺的那一样归谁 |
|---|---|---|
| `pace` | `seat.pace`：本周配额消耗比 | 账本要有一列周节奏读数，属号池账本（仓外 `infra` 侧的 schema），不在本仓 |
| `weight` | `seat.weight` + `state["rounds"]` | 权重列同上；`rounds` 与 `turns` 同形，接线时要与 A372 那次一样由调用方持有 |
| `free` | `seat.free`：这号今天还剩不剩免费额度 | 平台侧的免费额度探测，本仓今天无此接口 |

**二、`fast`（别名 `speed` / `speed-first`）只许存在于判据层，不许接进派活链。**
它是唯一一档会**主动花代价去探测**的策略：`PROBE_EVERY = 5`，每 5 个请求拿最快的那个真试一次。
在号池里「探测」等于真花一次额度，而派活链是按 pending 卡顺序干活的 ——
把 speed 接进去等于让排序器决定去花谁的钱。这不是本卡能裁决的事。
**这条规矩在本记录之前仓内没有成文条款**（全仓搜到的 speed 全是测试耗时语境与吞吐测量），
只散见任务书的用户红线。本记录把它第一次写成机检面：新建的接线钉子文件里，
`test_dispatch_sink_never_names_a_speed_strategy` 扫 `tools/wb_dispatch.py` 的字符串常量
（走 AST，不走正则），要求那一族八个名字一个都不出现，并要求 `SINK_ROUTING` 仍是 `order`。

**三、喂料字段的缺席是设计现状，不是 bug，但必须以断言的形式在场。**
六个喂料字段（`free` / `credits` / `ttft` / `tps` / `pace` / `weight`）
在生产侧的座位构造里零出现。断言只认 `Attribute` 形态的 `Seat(...)`：
`tools/dsh_panel.py` 那三处同名调用是**裸 `Name` 形态的面板条目**，与号池座位不是同一个东西，
按名字扫会把它们误判成违规 —— 这正是必须走 AST、不许 grep 的原因。

**四、状态只在调用方手里。** `tools/pool/route.py` 零写盘，也不许把 `turns` / `rounds` /
`probes` 提成模块级变量。magpie 原件用的是包级 `turns`（进程内活着、跨请求累加），
本仓**故意**没抄：进程内全局会让「同一份状态」在测试里不可控，也会让多进程部署各转各的。
`apply_strategy` 的生产调用点恰一处（网关），`state` 只由调用方递进来的
`turns` 包成 `{"turns": turns}` —— 传个新空 dict 糊过去，轮换会静默退回恒等。

**五、这四条都落在断言上，不是落在注释上。** 新建的接线钉子文件七条，
对应卡规格的六条判据（判据 1 拆成前后两条）。判据 1 / 4 / 5 在「真把某一档接上线」那天会红，
**这是设计意图，不是回归**：红一次就是一次「该来改判据 + 改本记录」的提醒。

## 把握程度

high —— 上面五条里，前四条各有一条今天实跑为绿的断言支撑（七条钉子全绿、既有 171 条一条不红），
「谁被喂饱」是逐条读过 `tools/pool/gateway.py` 的构造现场与两次实跑读数得出的，不是推断。

medium —— 「所以问题在**输入形状**而不是实现」这句是**判断**，不是读数。
判据能证明的只有三件事：喂料下只有 `usage` 与 `rotate` 会动、六个字段零构造、
`route.py` 不落盘；「问题在输入形状」是从这三条读出来的解释。

low —— magpie 侧的七种策略行为全部来自**读 Go 源码**，没在 magpie 树里跑过它的测试，
也没发过一个带 `routing=` 的请求；`pace` 在 `k == 0` 时落哪一带是按 Go map
零值语义**推的**，不是读到某一行断言。这两条的不确定性原样继承，本记录不把它洗成确定结论。
