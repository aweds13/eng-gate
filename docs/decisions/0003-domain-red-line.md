# 0003 C14 域红线：卡只许动自己声明域里的文件

Status: Accepted
Date: 2026-10-24
Supersedes:
Superseded-by:
来源: 台账卡 225 / T-G341（成员映射按声明域）、卡 188 / T-G288（域细化到符号级）、卡 111 / T-G208（干跑守卫）；`tools/pool/task.py` 的 `check_domain`

## 背景与问题

多张卡并行走、共用同一棵树，冲突不能等提交后靠 diff 去吵。事后判「谁动了谁的文件」有两层代价：
一是要人读 diff，二是回退别人的树比拒收贵得多。所以域必须是**事前声明、提交时机器验**。

## 候选方案

A 事后按 diff 判域外（不改声明流程，但要人看、会吵、且回退代价高）。

B 事前把域写进预声明（`[member].paths` / `files`），收口时机器点名拒收域外文件。

## 决定

选 B。判据落在 `tools/pool/task.py` 的 `check_domain(man, member_id, files)`：
卡碰了**自己域外**的文件就点名拒收，理由写死在同一处 ——「要动域外的文件 ⇒ 改预声明里的域
（那是**改冲突域声明**，要显式做）或另开一张卡」。域一开始是文件级，
后来细化到符号级（卡 188），收口链的成员映射只取声明域（卡 225）。
放弃 A 的代价：动域外成了一个显式动作，多一步；换来的是「域外」不再靠人自觉。

## 把握程度

high —— 拒收文案、名单校验、符号级域都有测试，且这张卡自己就在这条红线里跑。
