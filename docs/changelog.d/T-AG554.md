### 病灶

`tools/web_live_check.py` 有**两个** HTTP 客户端：`_json_call` 走 `call_timeout()`（卡 E67 把等待窗做成 env 可调、超时抛 `LiveCallError`），`_lan_json` 却自带一份 `timeout: int = 3` 硬编码窗，结尾还把 `urllib.error.URLError` 与 `OSError` 一律吞成 `(0, None)`。

`TimeoutError` 是 `OSError` 的子类，所以 `_lan_json` 等不到时也返回 `(0, None)` —— 与「防火墙 / 没有局域网地址」同一个壳。云机 `web_live` 的 `[FAIL] 手机直传：没配对传不进来（401）` 就是这么来的：服务端真的回了 401（云机日志 `POST /api/sync/import status 401` 有据），客户端 3 秒没等够，看到的是 0。

### 做了什么

- 模块级常量 `WAIT_TIMEOUTS = (TimeoutError, socket.timeout)` —— `except (TimeoutError, socket.timeout)` 直写撞 ruff UP041，用常量让 `except` 与 `isinstance` 共用同一个集合，**不加 `# noqa`**。
- `_lan_json` 的等待窗默认改走 `call_timeout()`（与 `_json_call` 同一个 env `TF_WEB_LIVE_TIMEOUT`）。
- `except` 四段化：`HTTPError` 照旧回 `(code, body)`；`URLError` 里看 `e.reason`，是等不到就抛 `LiveCallError`，否则才是真的连不上回 `(0, None)`；裸 `TimeoutError` 同样抛；其余 `OSError` 仍回 `(0, None)`。
- `live_lan_checks()` 改成边算边写进 `checks`，`try/except LiveCallError/finally` 收口 —— 一处等不到不会把已算出的行一起丢掉（判据 4）。
