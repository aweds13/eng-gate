### 做了什么

magpie 有一层「全都忙就歇一会儿再问」（`internal/gateway/patience.go`，F21）——候选组里每个成员都以**会过去**的方式失败（overloaded / busy / 短暂限流）时，暂停后重问，每轮更久，永不短于成员自报的 `Retry-After`，直到组预算耗尽。本仓 pool 此前撞了 `限流` 只有一处固定等待，没有递增、没有预算、不会重问。

**算术层逐字搬，两层明确不搬：**

- `tools/pool_quota.py` 紧挨 `round_wait()` 之后新增六个常量与两个纯函数：`RETRY_PAUSE_S = 1` / `REPLAN_LONGEST_S = 30 * RETRY_PAUSE_S` / `PATIENCE_OFF = -1` / `PATIENCE_DEFAULT_S = 60` / `PATIENCE_LONGEST_S = 240` / `REPLAN_ROUNDS = 12`；`patience_waits(patience)` 三支（`None` 或 `<0` ⇒ 0 / `==0` ⇒ 60 / 其余 `min(p, 240)`）；`replan_wait(round_no, soonest_s=0)` = `min(RETRY_PAUSE_S << (round_no + 1), REPLAN_LONGEST_S)` 再 `max(wait, soonest_s)`，取值实测 `0⇒2 / 1⇒4 / 2⇒8 / 3⇒16 / 4 起恒 30`。
- `tools/wb_dispatch.py` **恰好一处**接入：`quota_error()` 判出之后、续跑界之前，只有 `kind == 限流` 才进门（`余额耗尽` 是硬挡 —— 等多久都不会好，照旧走到界出口）。

**两个数字三件事，不合并**：`PATIENCE_DEFAULT_S` 是「没配时给多少预算」（**0 不是关**），`PATIENCE_LONGEST_S` 是整张卡的预算上限，`REPLAN_LONGEST_S` 是**单次**重问间隔的上限。与既有的 `WAIT_MIN_S` / `WAIT_MAX_S` / `WAIT_MARGIN_S`（`round_wait()` 那套「按记录等一次」）更是两套语义，互不调用。

### 为什么这么修

**触发层搬不动**：magpie 的 `busy(status, body)` 读 HTTP 状态码（`408/500/502/503/504/529` 加 429），而 pool 的工人是子进程，事件里没有任何 HTTP 状态码。本卡只认 pool 已有的 `quota_error()` 两档 `kind`。

**不造第四个「组」**：pool 已有三套「一组号」真源（`lanes.toml` 每号并发闸 / `rotation_chain_for()` 每池模型链 / `approved_models` 每号白名单），硬造一套谁也不认的假源不如把耐心作用在「这一轮这一张卡的重试」上。

**保活层完全不可移植**：`pauseAlive()` / `didNotStream` / `protectionRefused` 都是 HTTP 网关「还没开始发」的形态，pool 没有等价边界。

### 工人自查出的真缺陷（本卡最值钱的一条）

初版把成员自报的续期写成 `wait_seconds(reset_at, 0)` —— 而 `wait_seconds()` 把 `fallback` 当**上限**，传 0 恒得 0 ⇒ 成员自报的 `Retry-After` 那一层等于没接。改成 `upper=10 ** 9`（只解析、不封顶），并补了**真路钉子** `test_retry_after_floor_reaches_the_sleep`：喂一个 120 秒后的 reset，断言第一觉 ≥55s —— 第 0 轮递增间隔只有 2s，能睡到 55+ 只可能来自下限。没有这颗钉子，这个缺陷一行测试都不红。
