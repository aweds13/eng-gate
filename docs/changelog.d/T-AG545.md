## 2026-10-30 · 中午之前的已签过不算数：magpie 签到复查窗口移植进 pool（F29）（卡 A343，T-AG545）

### ① 病灶：一天只问一次，上午那句「已经签过了」被当成定案

`tools/pool/checkin.py` 的形状是「人开口一次」——跑一次 `checkin` 拿到结论就写台账、写当日留档，之后这一天再没人问。而 magpie 那边有一条每分钟都在的后台节拍 `keepCheckedIn`（`internal/provider/workbuddy_checkin.go:565-593`），把「上午说已签过」当成**未定论**，到点自己再问一遍。

这条判据的来历是实测事故（magpie `workbuddy_checkin.go:140-147` + issue `#3326`）：北京日刚过 `00:00:28`，六家平台全回 already in；到 `10:54` 再问，才真的领到。29 个号里 14 个中招。**上午那句「已签过」说的大概率是昨天。**

### ② 改法：只搬判据，不搬触发

`tools/pool/checkin.py` 加 4 个常量 + 1 个平台集合 + 3 个纯函数（**既有函数一个字节没动**）：

- `CHECKIN_SURE_HOUR = 12`（`workbuddy_checkin.go:147`）—— 中午之前那句不算数。**不许改成可配置**：magpie 侧是 `const`，这个值来自那次事故的读数，不是策略旋钮。
- `RECHECK_EVERY_S = 1800` / `RETRY_AFTER_S = 1800` / `RETRY_FLOOR_S = 60`（`workbuddy_checkin.go:53/56/87`）。
- `RECHECK_PLATFORMS = 一个只含 qoder 的集合` —— 只有活动类平台要按时复查（`checkin.go:105-110` + `qoder_checkin.go:289`）。
- `provisional(outcome, *, at, now, timezone)`：三件事同时成立才算「上午那句不可信」——结论是 `ALREADY_CLAIMED`/`INACTIVE`、`at` 与 `now` 同一时区日、`now.hour < 12`。naive 时刻 ⇒ `ValueError`（时区只有一个真源，绝不猜）。
- `retry_after_s(*, offline, tries)`：在线恒 1800；离线 `min(1800, 60 << min(tries, 5))` ⇒ 60/120/240/480/960/1800。
- `due_for_recheck(last, *, at, now, timezone, platform, offline, tries)`：八步顺序即优先级，返回 `(要不要问, 为什么)`，理由给人看。

`tools/pool_accounts.py` 加只读的 `recheck_rows()` 与 `due` 子命令（`--json` / `--now` / `--platform`）。**不签到、不写台账、不写留档**；`run_checkin` / `_record_checkin` / `cmd_checkin` / `write_checkin_archive` 一字未动。
