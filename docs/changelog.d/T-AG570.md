pool 没有「清空用量」这个概念，但有一个**语义相反**的东西：`tools/pool/ledger_spend.py:196-223 forget()` —— 它**物理把行搬走**。magpie 的选择完全不同，理由逐字写在 `internal/usage/cleared.go:12-20`：清空**永不写进日志**，日志保留每一次调用 —— 因为「一个 key 的花费限额、额度的窗口估算、网关自己的 `Visit`」都还要数那些被清掉的调用，而 agent 的 session 文件与其他机器共享的天数 magpie 改不了，所以它改的是**读法**。可核证据 `cleared_test.go:78-82`：同一份日志，页面数 3 条、`Visit` 数 5 条，**一个字节都不改**。照抄 `forget()` 会破坏一个已被测试咬住的语义（`tests/test_pool_limits.py:256-279`），而且是净损失：让「不想看见」悄悄松开限额。本卡照 magpie 的形状落地：标记单独一份 `gates/diag/usage-cleared.json`，`pool-spend.jsonl` 一个字节不动；`sums(..., clears=None)` 数全部行（= magpie 的 `Visit` 面），只有显式给了 `clears` 才过滤；全清是**闭区间**上界；坏文件读到 `[]` 而**不是**当全清（隐藏是危险方向，判不出就显出全部）。
