pool 今天**只有墙钟**（`gates/diag/wb-usage.jsonl` 的 `用时分钟` 与事件里的 `duration_ms`），没有首字延迟、没有流转时长（242 份 `wb-*.jsonl` 实测：`result` 事件键有 `duration_api_ms` / `duration_ms` / `total_cost_usd` / `num_turns` / `modelUsage` / `usage`，但**没有** `ttft_ms` / `first_text_ms` / `flow_ms`）。于是「这条回复每秒写了多少 token」在 pool 侧算不出来，而 magpie 那边有一整套判据回答的是另一个问题：**什么情况不许报速度**。这套判据是纯算术，闭的是一个真错 —— 拿墙钟冒充速度：一条 5 秒的回复里有 4.5 秒是排队与首字延迟，用 `output_tokens / 总时长` 算出来的速度是假的，而且系统性偏低（把快的号看不出来）。本卡把它整块搬进 `tools/pool/speed.py`：最小可测窗 100 ms、最快 10000 tok/s、末端爆发（`flow * 4 < w`）、推理节奏（`ThinkPace = 20`）、有推理无首字时不许拿推理 token 冒充答案、Codex 的 1000 ms / 100 token 双门槛。**只搬判据不搬数据面**：pool 今天零生产方，所以 `tools/` 里没有一处 import 它。
