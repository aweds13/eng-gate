# 程天学（acm.tju.edu.cn）可迁移功能报告 —— 哪些「我们自己」能用

> 这份报告回答一个问题：**把程天学拆开看，哪些东西值得搬进我们自己的自学场景（OpenMAIC + DSH）**。
> 素材是十份域报告（`D:/repo/_tools/acm/usable/`，合计约 443 KB、534 张截图），
> 判定口径写在 `D:/repo/_tools/acm/usable/_BRIEF.md`。
> 一句话结论：**值得搬的只有 12 条独立规则，其中 3 条是骨架；其余要么是站特有的壳，要么我们已经有更好的。**

## 0. 先给结论

| 档 | 数量 | 说明 |
|---|---|---|
| 立刻能搬（不依赖站点任何数据） | **3 条** | 掌握度公式、自我评估校准、错题四关重练 |
| 需要搬一份数据才能用 | **2 条** | 130 知识点本体（一份 JSON）、CF rating 量纲 |
| 只作设计参考（要重做，不是搬） | **7 条** | 天梯算分、分级提示 L1–L4、成绩加权+缺项折算、ACM/OI 罚时、找反例 hack、圆桌三角色、六字段上下文信封 |
| 明确不搬 | **全部教师侧 9 项 + C 类功能点** | 教师侧用户已明确「不用理」；其余依赖班级/课程/管理员身份 |

这正是我们（DSH 宿主 + OpenMAIC 课件）现在最缺的东西 —— 我们有「对/错」，没有「什么时候该再考一次」。

## 1. 判定口径（先说明白，否则后面的数字没法引）

### 1.1 三档可用性
- **A 独立可用**：一个人自己就能完整用起来，不需要老师建课、不需要班级、不需要同学。
- **B 半可用**：入口开放、UI 能看，但内容依赖老师建课；**只有贴出空态原文才算 B**（否则是 C）。
- **C 不可用**：必须教师 / 管理员 / 班级身份才能进。

### 1.2 可迁移性 1–5 分
- **5** = 方法/规则，与站点无关，拿过来就能用；
- **4** = 结构化领域知识，需要改造；
- **3** = 交互范式，能借鉴但要重做；
- **2** = 站特有流程，搬了没意义；
- **1** = 完全不需要。

## 2. 立刻能搬的三条（P0）

### 2.1 掌握度公式

**站点原文口径**（三个域独立复现，`01`/`07`/`08`/`09` 四处）：
- 掌握度 = **关联题按比重加权的得分率**；
- **同题同人取最后一次**；
- **实时算、不落库**；
- **点亮阈值 60%**；
- 提交次数影响：**每多一次提交 −5%，封顶 70%**；
- 提示折扣：**看了 L3 提示 ×85%、L4 提示 ×70%**；
- 非编程题**封顶 80%**；
- 遗忘衰减：**最多降到 70%**，隔天再做对记得更久。

**我们现状**：`lib/quiz/grading.ts:67 gradeChoiceQuestions()` 只给 `earned: correct ? pts : 0`
（`pts = q.points ?? 1`），**没有任何加权、折扣、衰减**。`lib/quiz/attempt-fold.ts` 有
`incorrectNow` / `everIncorrect` 两个布尔语义，但没有分数。

**为什么值得搬**：这是全站唯一一条「把一堆对错变成一个连续数」的规则，而且**四个独立域互相印证**（课程侧、帮助页、教师侧、跨模块），说明它是产品里稳定的东西，不是临时口径。

**落地成本**：低。纯函数，输入是 `QuizQuestion[] + answers + 作答历史`，输出一个 `number`。
不需要数据库、不需要模型、不需要网络。

**判据（怎么算做成了）**：
1. 同一份答题记录算两遍，结果逐位相同（纯函数）；
2. 连提交 3 次的题，掌握度 = 首次掌握度 − 15pp（不触顶时）；
3. 看了 L4 提示的题，掌握度 ≤ 未看提示时的 70%；
4. 60% 是点亮线，不是 50% 也不是 70%（**站点 tips 写 60，星图着色用 40/70 两档 —— 两套都有，取 60**）。

### 2.2 自我评估校准

**站点原文口径**（09-crosscut.md）：
- 四档把握度：**25 / 50 / 75 / 95**；
- 校准判语：`expected − actual ≥ 20` → **over**（高估），`≤ −20` → **under**（低估）；
- **门槛 8 题**（不足 8 题不给结论）；
- 三类判语文案。

**我们现状**：`git grep confidence` 在 `lib/**` 只命中两处 —— `components/ai-elements/prompt-input.tsx:1014`
（UI 组件的 `confidence: number`）与 `lib/document/types.ts:199`（文档字段），**都与学习者自评无关**。
`把握` / `自评` / `calibration` 在全仓 `lib/**` **零命中**。

**为什么值得搬**：这是唯一一条**不需要任何题库**的元认知功能 —— 只要学生自己打一个把握度。
而且「高估/低估」这个判语比掌握度更能驱动行为改变。窗口只有 ±20pp 且门槛 8 题，**不容易误判**。

**落地成本**：低。一个可选字段 + 一个纯函数 + 一句提示词。

**判据**：
1. 不足 8 题时**不出结论**（不是出「暂无数据」占位就完事，是根本不进判语分支）；
2. 恰好 8 题、差值恰好 ±20 时进对应分支（边界要测）；
3. 四档只能是 25/50/75/95，不接受 60 这种中间值。

### 2.3 错题四关重练

**站点原文口径**（`01`/`02`/`08`/`09` 四处复现）：
- 间隔：**第 1 天 → 3 天 → 7 天 → 15 天**；
- **做错回第 1 关**；
- **四关全对才出本**（才从错题本里移除）；
- 无同知识点题时，**AI 出变式题**。

**我们现状**：`lib/quiz/attempt-fold.ts` 的 `everIncorrect` 头注释原文就写着
「历史上错过（含已经改对的）：**间隔重考**的候选」—— 但**只有「候选」语义，没有排期算法**。
`spacedRepetition` / `nextReviewAt` / `reviewDue` 三个标识符**全仓为空**。
`lib/quiz/learner-state.ts:190` 有一句提示词：「曾经做错、后来改对的共 N 道 —— 这些可以在间隔复习时再抽查，但不是当下的重点。」
⇒ 我们知道「该复习」，但不知道「今天该复习哪几道」。

**为什么值得搬**：这是三条里**唯一能直接改行为**的 —— 它把「一次做对」变成「四次做对」。
而且四关是硬编码常数，没有调参空间，落地零歧义。

**落地成本**：低—中。需要一个「每道错题的四关状态 + 下次到期时间」，落在哪需要决定
（建议跟着 学习状态.md 那条链，因为 `lib/server/agent-runtime/learner-state.ts` 的头注释已经写明
「Python 那边的 BKT 重算将来接在同一个位置」—— 排期器接同一个位置最顺）。

**判据**：
1. 今天做错的题，明天出现在「今天该复习」里，第 2 天不出现，第 4 天出现；
2. 第 3 关做错，下一次到期回到「第 1 天」而不是「第 8 天」；
3. 四关全过后从列表消失，且**不再出现**（不是降权，是移除）。

## 3. 需要搬一份数据才能用的两条（P1）

### 3.1 130 知识点本体

**实测结构**（`02`/`05`/`10` 三域一致）：
- `GET /api/get-cf-tag-graph` → **32063 B**，`nodes 130 / links 158 / categories 10 / problemTagged 157799`；
- 关系类型 `{prereq: 138, contains: 20}`（**158 = 138 + 20，正好相加**）；
- 10 个 category 及题数：语言基础 7 / 基础算法 13 / 搜索 6 / 数据结构 27 / 动态规划 11 / 图论 21 / 数学 25 / 字符串 9 / 计算几何 4 / 综合技巧 7（合计 130）；
- tier 分布 `{0:19, 1:27, 2:47, 3:37}`；
- 每个节点带 `checkpointId` 与 `count`（1–25694）。

**关键事实**：**读侧完全公开，无 token 也 200**（`get-cf-tag-graph` / `get-cf-tags` / `get-all-problem-tags` 都是）。
`/api/get-all-problem-tags` 有 **253 条**，与图谱 130 条的差集是 **101 条** —— 两套词表，别混。

**为什么值得搬**：这是**唯一一份「中文计算机知识体系」的现成 JSON**，25 KB、零渲染耦合，
`tier` 直接就是熟练度分层。自己从零建一份等价的本体，成本远高于「拉一次存下来」。

**注意**：OpenMAIC **没有知识图谱本体**（`知识图谱` 在 `lib/**`+`components/**` 零命中；
`prerequisite` 只在 `lib/chat/pi/tools/course-search.ts:236,:294`，那是 MIT/Berkeley 等**真实大学课程目录**的先修字段，
与知识本体无关）。所以搬进来是**新增**，不是对接。

**判据**：130 个节点、158 条边、10 个分类、tier 四档全部逐项对得上；`prereq + contains = 158`。

### 3.2 CF rating 量纲

**实测**：题库 11 档来源合计 **78802** 题（LOCAL 1365 / CF 15212 / 洛谷 19913 / AtCoder 7663 / 力扣 3704 / 牛客 15196 / LibreOJ 4444 / UOJ 1109 / HDU 7169 / POJ 3027），
难度统一压成 **CF rating 8 档**。

**为什么值得搬**：一旦难度用同一个数轴，**跨题库的出题、ZPD 分带、天梯算分全都变成同一套算法**。
这是「一份量纲省三套实现」的典型。

**注意**：外部 7.7 万题**只有索引没有题面**（`/problem/239` 是空壳，正文写「该题号对应的题目不存在」），
所以拿过来的只是「难度标签」，不是题目。

## 4. 只作设计参考的七条（P2，要重做不是搬）

| 6 | 圆桌三角色 | 主持 / 追问 / 初学者误解，概念辨析与辩论两种玩法，**每桌 10 轮** | OpenMAIC 的 PBL 已是多角色（`lib/pbl/v2/agents/` 八个 agent，`instructor.ts:667` 有 role-play 分支）—— **我们有更好的**，只需借鉴「三个固定角色 + 轮数上限」 |
| 7 | 六字段上下文信封 | `tjuoj:{cid, scene, homeworkId, problemId, hint, level, role, spot}` 把「在哪问」编码成可序列化对象，服务端据此拼 prompt | 这是**范式**不是代码；我们自己有 `stageId + sceneId` 进对话上下文（B0 已做） |
