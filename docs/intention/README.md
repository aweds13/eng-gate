# intention — 为什么做（动机层）

> 定位：**本地优先、跨平台的个人「时间与学习投入」管理工具**——管要做什么（To-Do）、算投入是否均衡（债务/储蓄）、守住学业不冲突，可外接 AI 与 Obsidian。

回答：「我们为什么要做这个时间管理软件？想满足谁、解决什么？」

这一层只谈**动机、痛点、原始需求**，不涉及技术、不涉及「必须做到什么」。每条需求用 `N1..Nn` 编号，并给出「为什么成立 + 衍生方向」。

## 怎么读
- 需求清单在 **`needs.md`**（N1..Nn）。先读本文件定位，再看 needs.md。
- 下游是 `../specification/`：它把这里的需求翻译成「可验证的必须做到」。

## 结构读法（怎么理解这批需求）
需求的组织方式是「**一个框架 × 多条线 × 多交叉 × 多节点**」：
- **框架**：N3 债务/储蓄记账——唯一，**横切所有线**（一切都要被换算成 投入 / 产出 / 欠账）。
- **线**：任务(C) / 专注(E) / 学业(F) / 复习(H) / 反馈(D) / 协作(N46,N23) / 备忘录(G)。
- **交叉**：线与线的**强制咬合点**（如「专注→自动计入任务+反馈+投入」「学业任务同构合流进 My Day」），共 12 处。
- **节点**：交叉在框架上落下的账目条目（逾期 / 专注 / 完成 / 复习 / 成绩…）。

> 判据：**一个动作"做完了吗" → 问「它在框架上落节点了吗」。**
> 完整结构分析与 MVP 切法见 `../../复盘/MVP结构梳理-框架与交叉.md`（**该文档属分析结论，非需求本身**）。
