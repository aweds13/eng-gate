# 工作台 · 不建模清单（当初决定不做的，写在这里）

> 为什么有这份清单：一个系统里最容易被遗忘、也最容易被人「顺手加进去」的，就是**当初明确决定不做**的那些东西。
> 用户 2026-10-13 笔记原话（意译）：**「把不建模的东西写下来」**。这些决定此前散在聊天、文书、卡规格里，
> 没有一处权威、也没有东西会拦住违反 —— 这份文件就是那「一处」。
>
> ★ 规矩：每条写**四样** —— **不建什么 · 为什么不做 · 谁拍的 · 替代做法**，并**指回出处**；
>   缺一样，判据 `tools/notmodel_audit.py` 就红并点名。本清单**从现成真源里挖结论，不编**：
>   每条都指得出出处；找不到出处的**单列在 §四，如实标注、不当结论**。

## 一、领域模型与口径（不建什么）

### NM-01 不建独立「目标」实体
- **不建什么**：独立的「目标 / Goal」实体（数据表、字段、实体）。
- **为什么不做**：独立目标是**伪需求**，避免过度抽象。
- **谁拍的**：`N3` 结算（intention 层「结算」段）。
- **替代做法**：目标 = 大的任务分组 / 项目，用 `N8` 自定义分组涵盖（必要时给任务打多分组 / 领域标签）；投入基准靠如实记账 + 趋势自判断。
- **出处**：`docs/intention/needs.md` N3 结算；`docs/specification/conventions.md` 红线；`docs/taste/README.md` §五；`复盘/意图到规格-产品判断复盘.md` 问题 2；`scripts/check_layers.py` 的 FORBIDDEN 词表。

### NM-02 债务不折算成精确时间
- **不建什么**：把债务（逾期）折算成精确时间（分钟 / 小时的欠账）。
- **为什么不做**：**估不准、不造假**。
- **谁拍的**：`N3` 债务口径；用户 2026-09-19 在 C 批口径里再次确认。
- **替代做法**：债务 = 如实列逾期清单 + 逾期天数 / 程度分级（轻 ≤3d / 中 ≤7d / 重 >7d）。
- **出处**：`docs/intention/needs.md` N3 债务口径；`docs/specification/conventions.md` 固定口径；`复盘/C批口径定案.md` §二；`scripts/check_layers.py` FORBIDDEN（「时间折算 / 折算成」）。

### NM-03 不用算法推荐、不硬对标
- **不建什么**：算法推荐 / 目标对标（替用户算「你该做多少」）。
- **为什么不做**：投入基准靠**如实记账 + 趋势自判断**，不硬对标。
- **谁拍的**：`N3` 结算。
- **替代做法**：如实记账 + 趋势自判断 + 曲线 / 热力图让用户自己看。
- **出处**：`docs/intention/needs.md` N3；`docs/specification/conventions.md` 红线；`复盘/意图到规格-产品判断复盘.md` 问题 2 / 红线；`docs/specification/domains/F2-ledger.md` R6。

### NM-04 不做知识资产的「产出打分器」（评价器）
- **不建什么**：给知识资产（笔记 / 产出）打分的「产出打分器 / 评价器」。
- **为什么不做**：**知识管理未对齐不写死**；参考的 toolkit 只有质检 / 检索评估 / 文风评审，**没有产出打分器**。
- **谁拍的**：`N3` 产出口径（用户裁决）；`SR-F8.4b` 被标 `deferred`、等外部口径。
- **替代做法**：粗颗粒 + 手动的产出入口（`SR-F8.4` 第一版手动粗颗粒 + 撤销）；产出量化交给知识管理系统。
- **出处**：`docs/intention/needs.md` N3 产出段；`docs/specification/conventions.md` 红线；`复盘/意图到规格-产品判断复盘.md` 问题 2；`复盘/交接-重构进度.md` §③ 表（`SR-F8.4b` deferred，契约边界栏写「不做打分器」）。

### NM-05 不直接读写外部知识资产库（Obsidian / PDF / KB）
- **不建什么**：本软件直接读 / 写 Obsidian Vault 文件、PDF 库、知识管理系统的 KB。
- **为什么不做**：联动与知识管理强相关，**独立项目更干净**，避免本软件膨胀。
- **谁拍的**：`N24`（Obsidian 深度联动后置到「知识资产管理项目」）。
- **替代做法**：本软件只存**引用句柄**（Vault 相对路径 / `KB-…` 资源 ID）；读写交给知识资产项目。已落判据：`T-G5` 把 `SR-F8.2` 红线做成「导出目录落在 Vault 里就三处拒写」。
- **出处**：`docs/intention/needs.md` N24；`docs/specification/conventions.md` 红线；`docs/taste/README.md` §三-6 与 §五；`复盘/交接-重构进度.md`「沉淀型内容写 Markdown」条。

### NM-06 砍掉 `Assigned to me` 视图
- **不建什么**：`Assigned to me` 筛选视图。
- **为什么不做**：**个人不适用**。
- **谁拍的**：`N7` 筛选视图。
- **替代做法**：团队分配语义由管理者 / 执行者模式（`N46`）承接。
- **出处**：`docs/intention/needs.md` N7；`scripts/check_layers.py` FORBIDDEN（「Assigned to me」）。

### NM-07 不做「三类任务」分类字段
- **不建什么**：给任务加「有指标类 / 逾期不候-作业考核 / 逾期不候-竞赛活动」的分类字段（`tasks.category`）。
- **为什么不做**：用「优先级（高）」+「学校硬考核强提醒」就能表达；**改规格，而不是让代码假装做到**。
- **谁拍的**：用户 2026-09-19 拍板（C 批口径 T-C9）。
- **替代做法**：优先级（高）+ 学校硬考核强提醒（`SR-F1.8` 强弱分级 / T-C8）+ `task_type` 扩「竞赛 / 活动」取值（T-G140：零迁移、**不加字段**）；分类字段与「指标可重规划」留二版。
- **出处**：`复盘/C批口径定案.md` §四；`docs/specification/functional.md` `SR-F1.9` 一版口径调整；`复盘/交接-重构进度.md`「未实现」条；`复盘/F1.9三类扩类型-T-G140.md`（「① 按 N3 定案『不设目标实体』不做」）。

### NM-08 习惯不折算成投入（只报次数）
- **不建什么**：把习惯打卡折算成投入分钟 / 小时。
- **为什么不做**：折算正是项目**已砍概念**；用户选择「看见，但只报次数」。
- **谁拍的**：用户 2026-09-19 拍板（C 批口径 T-C1）。
- **替代做法**：只读计数（`habit_count` / `habits_done`），与投入**并排显示**；想真占投入时间走已有的手动补记（自己填真实分钟，不猜不折算）。
- **出处**：`复盘/C批口径定案.md` §二；`复盘/交接-重构进度.md`「未实现」条（习惯计入投入轴：已决定不折算、只报次数）。

### NM-09 不物化独立「派生层」
- **不建什么**：从事实算中间量的物化派生层 / 派生表。
- **为什么不做**：**MVP 不做**（派生层可选、为性能；不必要）。
- **谁拍的**：事实层架构设计复盘的三层分离。
- **替代做法**：解读层按当前心智模型**从事实现算**（`facts` + 只读投影），不新造派生表（例：`ledger.today_done()` 只读事实层）。
- **出处**：`复盘/事实层架构设计复盘.md` §二 三层分离；`复盘/C批口径定案.md` §三（「全部只读事实层……不新造派生表」）。

### NM-10 AI 接口第一版不做写 / 改 / 删（只读 + 新增）
- **不建什么**：AI 对用户数据的写 / 改 / 删接口。
- **为什么不做**：第一版保守，**避免覆盖用户的操作、避免和手动操作冲突**。
- **谁拍的**：`N23`（intention 层「第一版只读 + 新增」）。
- **替代做法**：只读 + 新增（含「记一条事实」）；AI 的进展以**事实**回报（`source=ai`、只追加、可撤销），状态由解读层算；写 / 改 / 删后置。
- **出处**：`docs/intention/needs.md` N23 与「已定决策」；`docs/specification/conventions.md` 红线「AI 接口（N23/N46）：第一版只读 + 新增」；`复盘/交接-重构进度.md`（T-G21 AI 写事实回报进展）。

## 二、产品范围（后置 / 不做）

### NM-11 手机离线端不做：离线删除 / 改字段 / 反向回传 / 离线专注计时
- **不建什么**：手机离线队列支持「删除、改字段、反向回传、离线专注计时」。
- **为什么不做**：**合并判断仍只在电脑一处** —— 这四类动作会绕开那处单点判断。
- **谁拍的**：G 批 `T-G10` 的口径。
- **替代做法**：手机离线能记的只有：任务 / 完成与撤销 / 习惯打卡 / 备忘 / 每日反馈（走同一个包格式导出）。

### NM-12 首版不做公网远程实时
- **不建什么**：公网远程实时同步 / 上云后端。
- **为什么不做**：避免上云 / 过重 / **违背本地优先**。
- **谁拍的**：移动端方案（intention 层）。
- **替代做法**：离线优先伴生端 + 异步同步（PWA + IndexedDB + LWW）；未来要「出门实时」再考虑内网穿透 / 远程后端（后置决策）。
- **出处**：`docs/intention/needs.md`「移动端方案（已定·完整）」条。

### NM-13 不建 `DESIGN.md` / `LEARN.md`

### NM-14 「逐条事实都记 `device_id`」不做

### NM-15 团队视图不引入账号
- **不建什么**：团队视图里的账号 / 登录体系。

## 三、工程与工作流（决定不做）

### NM-16 不做「每张卡一个栅栏」（逐张落地）
- **不建什么**：给**每张卡**建一个只有 1 个成员的栅栏（`B-DTREE` / `B-DSHTIE` ……）。
- **为什么不做**：那样**永远攒不成批** —— `--batch B-XXX` 一次只能收一个成员，等于逐张落地，只是换了个写法。
- **谁拍的**：用户追问**「这个机制为什么没有固定到工作流里」**逼出来的规矩。
- **替代做法**：**当天所有卡登记到同一个栅栏**（如 `B-20261013`），收口一次 `wb_land.py --batch B-<批号>` ⇒ 一次门禁、一笔提交、整批落地。
- **出处**：`复盘/并行与攒批模型.md` §二「★ 一条被用户追问才逼出来的规矩」。

### NM-17 不做暗色「全量渲染基线」
- **不建什么**：暗色主题的全量渲染黄金基线。
- **为什么不做**：判据是「**版式与主题无关**」；暗色可见性的风险交给一张更省的对照表。
- **谁拍的**：用户 2026-09-25 当面定。
- **替代做法**：把暗色「看不见」的风险交给**非文字对比度 3.0 表**（近 0 成本、每轮都跑）。
- **出处**：`复盘/交接-重构进度.md`「用户当面定的四件（2026-09-25）」条。

### NM-18 不引入 `shadcn/ui`（保持前端零依赖、无构建）
- **不建什么**：引入 `shadcn/ui` / Tailwind 这类前端组件依赖与构建步骤。
- **为什么不做**：「本项目前端**零依赖、无构建步骤**」是既有约定；组件层已经自己有了。
- **谁拍的**：设计基线（`T-G26`）答复「**不用**」。
- **替代做法**：用现有组件层（`app.css` 的 `.card` / `.badge` / `.btn` + `emptyState()` / `toast()`）与令牌区。**记在案，不引依赖**。
- **出处**：`复盘/设计基线-workbench与去AI味-T-G26.md`「另外两点」；`docs/EXTENDING.md`（前端零依赖约定）。

### NM-19 `depends` 字段不接进派活前置（只做规划用，不拦派活）
- **不建什么**：把 backlog 的 `depends` 字段当成派活的硬前置。
- **为什么不做**：`depends` 没有任何消费端；真正把同文件卡串起来的是 `files` 域相交。
- **谁拍的**：卡 157（`T-G257`）选了 (b) —— 降级成注释，不接进派活前置。
- **替代做法**：同文件卡靠 `files` 域相交串批（`plan_batches`）；`depends` 只是人读的规划字段。
- **出处**：`tools/wb_plan.py` `cmd_check` 的「说明」打印与注释（卡 157 / `T-G257`）；`docs/workbacklog.toml` 头部字段口径。

### NM-20 受保护共享文件不交给作者（工人一律不许碰）
- **不建什么**：允许作者（工人）改跨卡共享文件（`docs/traceability.toml` / `docs/changelog.md` / `复盘/交接-重构进度.md` / `复盘/新窗口交接卡.md` / `gates/last.json` / `gates/reuse.json`）。
- **为什么不做**：它们是**跨卡共享**的 —— 并发时两张卡写同一个 → 合并必冲突、台账互相盖。
- **谁拍的**：卡 010 §2.4 写死（`PROTECTED_FILES`）。
- **替代做法**：改这些的活统一由集成者（串行收口）做；规划器在 `validate()` 直接**拒单**。
- **出处**：`docs/workbacklog.toml` 头部字段口径（「含 `docs/traceability.toml` 等受保护共享文件 = 直接拒单」）；`tools/pool/plan.py` 的 `PROTECTED_FILES`。
