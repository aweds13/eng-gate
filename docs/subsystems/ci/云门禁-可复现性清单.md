# 云门禁可复现性清单 —— 「云机上跑出来算不算数」

> 这份文档回答一件事：**凭什么相信云机回传的 `gates/last.json` 是云机跑的、而且换台机器跑结果一样。**
> 它是一份**可核清单**：§2 每一行的「判据」都写成一个**能跑的 pytest 节点 id** ——
> 判据不是文字，是钉子；钉子不咬，那一行就是债。
>
> **与 [云门禁机](云门禁机.md) 的分工**（那份不要在这儿重复）：
> - [云门禁机](云门禁机.md) 讲**机器事实与历史读数**：这台 ECS 是什么规格、怎么装的、哪天跑出多少分钟、踩过哪些坑。
> - 本页讲**可复现性判据**：两台机器的差异清单、哪一条会改变判定、仓库里现在有谁看得见它。
>
> 关联：[CI 项目书](README.md) · [测试流程五维](测试流程.md) · [事后判据清单](事后判据清单.md)。
> 跑门禁的操作顺序见 [`skills/pipe-gate/SKILL.md`](../../../skills/pipe-gate/SKILL.md)。

## 0. 一句话结论

**云门禁今天能跑，但真正被钉住的只有三类：`host` 自证（判据 A）、CI 脚本不依赖本机私有状态（判据 B）、
以及本轮补上的「装依赖的解释器 == 跑门禁的解释器」（R14）。**
其余各行要么只钉了一半（Python 版本只记录不比对、`C:/pins.txt` 只验存在性），要么明确登记为债（R2 的本机 D 盘默认值、R12 的裸本地钟）。
§2 的「修没修」列把这件事逐行写清 —— **⚠️ 半条 / ❌ 未修的行就是今天的已知不可复现面**。

## 1. 怎么用这张表

1. 想一次性复核本表的**自钉行**（R1/R2/R5/R9/R12/R13/R14/R16）：

   ```
   python -X utf8 -m pytest tests/test_ci_portability.py -q --no-cov
   ```

   其余行的判据在别的文件里，按「判据」列给的节点 id 单跑，例如
   `python -X utf8 -m pytest tests/test_cloud_sync.py -q --no-cov`。

2. 哪一行红 ⇒ 那一行的差异**已经**会造成判据分歧，或那条判据自己被改松了。
   红的时候先看该行「现状」，再看「修没修」：⚠️/❌ 的行本来就没人保证。

3. **本表不许出现「判据」列写不出节点 id 的行** ——
   `tests/test_ci_portability.py::test_doc_rows_are_all_machine_checkable` 会解析这张表：
   任何一行引用不存在/已删除的节点，或者「风险等级」「修没修」空着，都会红。
   这条自指钉子是本页「不是纯文字」的唯一保证。

## 4. 判据 A：云机回传的 `last.json` 必须能证明是云机跑的

### 4.1 `host` 字段为什么原来没有

**不是 `run_gate.sh` 回传时丢的，是 `scripts/run_gates.py` 压根没写。**
本卡改动前，`scripts/run_gates.py` 全文 `grep -n host` **零命中**；云机 `C:/eng/gates/last.json` 实测 21 个键里没有 `host`。

### 4.2 怎么补的

在 `payload` 构造处（`**payload_env_fields(),` 之后，`scripts/run_gates.py:2771`）加一行 `"host": socket.gethostname(),`。
`import socket` 本来就在（`_is_listening()` 用），不需要新 import。

★ **为什么不塞进 `payload_env_fields()`**：那条函数被
`tests/test_gates_reuse_line.py` 的 `test_payload_records_python_version()` **精确**钉成 `{"python": ...}`，
往里加键会打红一条与本题无关的钉子。分开写，谁也不碰谁。

★ **`seal()` 不会抹掉它**：`seal()` 只重算 `tree` / `tree_scope` / `untracked` / `sealed_at`，不重建 payload
（`tests/test_ci_portability.py::test_a3_seal_does_not_reassign_host` 钉住这一条）。

★ **但它不会自己变出来**：`seal()` 不写 `host`。要让 `host` 出现在回传的 `last.json` 里，
必须在云机上**真跑一遍门禁**。仓里 `gates/last.json` 现在**带 `host`**（2026-11-03 23:59 那趟：`rev 7cb8ddbd`、`host=DEV-HOST`、22 门），
但 `--seal` 仍然不会补出这个键 —— 「代码已修」和「产物已重跑」是两个不同状态，别混。

### 4.3 消费者（证明这条判据真的有人用）

| 位置 | 行为 |
|---|---|
| `tools/gate_pool.py:430` `validate_cloud_return(...)` | 五条 fail-closed 校验，第 ③ 条：`host` 空 ⇒ 记问题；显式给了 `expect_host` 才比字符串 |

★ **`--gate-on cloud` 卡 E82（T-AG587，`61ffa120`）起不再是死路**：`tools/gate_pool.py:745` 的

## 5. 判据 B：CI 脚本不许依赖本机私有状态

### 5.1 实现

`tests/test_ci_portability.py` 用 **AST**（不是正则找字符串）扫两类目标：

- `scripts/cloud/**` 下所有 `.sh` / `.ps1` / `.py` / `.bash`
- `scripts/cloud/profiles/*.toml` —— ★ profile 化之后，仓相关的默认值从骨架搬进了 profile，
  它就是「CI 真正会执行的那份脚本」的一部分（骨架里只剩 `${P_<键>}` 槽位）。不把 `.toml`
  加进扫描面，R2 那条本机 D 盘路径会**正好落在扫描面之外**，B1 变成假绿
- `scripts/run_gates.py` 与 `scripts/cloud/pool-config/projects.toml.tmpl`

禁止两类字面量：

| 类别 | 规则 | 例 |
|---|---|---|
| 本机私有路径 | `(?<![A-Za-z])D:[\\/]`（本机 D 盘）、`(?<![A-Za-z])C:[\\/]Users[\\/]`（用户目录）、`(?<![A-Za-z0-9_])~[\\/]\.ssh[\\/]`（裸 `~/.ssh`） | `D:/docs/...`、`C:/Users/example/...` |
| 硬编码 IP | `(?<![\d.])(?:\d{1,3}\.){3}\d{1,3}(?![\d.])` | `administrator@203.0.113.12` |

**白名单**（每条都写理由，理由短于 20 字符判红；白名单条目指向的行不存在也判红 —— 防「豁免烂在原地」）：

| 文件 | 规则 | 子串 | 理由 |
|---|---|---|---|
| `scripts/cloud/run_gate.sh` | 裸 `~/.ssh` | `KEY="$HOME/.ssh/id_ed25519_cloud"` | 这段跑在**本机** bash（去连云机），方向相反 |
| `scripts/cloud/run_gate.sh` | 裸 `~/.ssh` | `云机 SSH 可用（~/.ssh/id_ed25519_cloud）` | 文件头前提注释，同上 |
| `scripts/cloud/profiles/engineering.toml` | 本机 D 盘 | `source_default = "D:/repo/infra/pool"` | ⚠ **现存债，不是合理**，见 §2 的 **R2**（profile 化之后债从 `run_gate.sh` 搬到这里，债没消失、只是换了位置） |
| `scripts/cloud/profiles/engineering.toml` | 本机 D 盘 | `repo_root = "D:/repo/engineering"` | 按设计如此：profile 就是「这台机器上的这个仓」那层配置，`repo_root` 是必填键；骨架对 `P_REPO_ROOT` **零引用** ⇒ 不流向云机 |
| `scripts/cloud/profiles/openmaic.toml` | 本机 D 盘 | `repo_root = "D:/repo/program/OpenMAIC"` | 同上（第二仓） |
| `scripts/run_gates.py` | IP | `127.0.0.1` | 回环，两台机器语义相同 |

## 6. `run_gate.sh` 的不幂等步骤（为什么它今天不是「可复现」的）

`scripts/cloud/run_gate.sh` 是唯一能真跑的云门禁路径。其 `set -u`（**没有 `-e`**）⇒ 中间步骤失败不自动中止，全靠每个 `if !` 手工判。

| 步骤 | 做什么 | 为什么**不幂等** |
|---|---|---|
| `0/5` | `git bundle create … line/impl-v1` → `scp` 到 `$HOST:C:/inc.bundle` → 云机 `git fetch` | 云机侧文件名**固定** ⇒ 多卡并发互相覆盖 |
| `0.35/5`–`0.45/5` | 推仓外配置 → 用仓内模板渲染 `projects.toml` | 会**删除**目标目录里白名单外的所有文件 |
| `1.5/5` | `Get-Process python \| Stop-Process -Force` | **杀掉云机上所有 python 进程**，不管是谁的 ⇒ 并发即互相残杀 |
| `2/5` | 把本机 `gates/diag/seed-<卡号>/{last,reuse}.json` 播种到云机 | **用本机私有产物当云机的判据输入**；seed 必须手工准备且必须是绿的（R6） |
| `3/5` | `scp` 补丁到 `$HOST:C:/card-<卡号>.patch` | 固定文件名，并发冲突 |
| `3.5/5` | `pip install -e ".[dev]" -c C:/pins.txt` | **每趟联网**；版本钉在**仓外**文件（R8） |
| `4/5` | `run_gates.py && run_gates.py --seal` | `&&` 串联 ⇒ `--seal` 只在第一趟 `exit 0` 时才跑。★ 本轮把这一行从裸 `python` 钉到 `"C:/Program Files/Python312/python.exe"`（R14） |

★ **`5/5` 的 `host` 自证故意不改退出码**：`0/5` 送的是**已提交**分支，而 `run_gates.py` 的 `host` 写入在修复落地前还在本机工作树里 ⇒ 云机这趟回传必然没有 `host`。此时硬退会**直接掐断云门禁**。所以这一版只打印 `★★` 提示并给处置办法；等 `host` 写入落地（并真跑过一次）后，把那段 `sys.exit(0 if h.strip() else 1)` 的返回码接上去即可。

- 本页所有读数都标注了**取证时刻的机器状态**；`last.json` 里的 `at` / `rev` / `python` / `host` 才是那次运行的现场，本页只是清单。
