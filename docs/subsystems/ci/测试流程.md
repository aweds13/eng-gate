## 1. 为什么需要五维

同一个词「跑门禁」在本仓至少有五种含义：`--fast`（十几秒那几道）、`--quick`（跳过真机层）、
全量（22 道，见 表一）、按域 `--profiles auto`（A327，依改动面选档）、TIA 选测（`TF_TIA=1`，按覆盖映射
裁 pytest 用例）。谁在什么时候该用哪一档，此前没有一处写全 —— 于是出现过「卡树跑全量 →
主树又前进 → 重 realign → 再跑一趟」（E10 五趟、E39 两趟；源：卡 E43 §1 的实测记录）。

「绿」也必须有分层：`gates/last.json` 只给一个 `ok`，而落地要的是
「`rev == 父提交` + 全量（或必需档）+ 封存指纹一致」；卡内自测要的是「我改的文件相关用例绿」。
**拿自测的绿去承诺落地的绿**是本仓踩过的坑，`tools/wb_verify.py` 就是那道理性闸。

## 2. 五维（每一维都写「不满足时怎么办」）

| 维 | 取值 | 谁决定 | 落点（唯一真源） | 不满足时怎么办 |
|---|---|---|---|---|
| 档位 | `--fast` / `--quick` / 全量 / `--only` | 改动面 + 你要证明什么 | `scripts/run_gates.py` 的 `build_parser()` | `--fast` 不落盘 ⇒ **不许**当提交闸；`--only` 落盘但门数不全 ⇒ `wb_verify` 判红（fail closed） |
| 域 | `lang` / `audit` / `product`（A327） | 改动路径 | `gates/defs/domains.py::required_profiles()` | 有任何路径落不进表 ⇒ **全量**（fail closed）；`.gitignore` 收掉的派生/残留不算改动面 |
| 选测 | `TF_TIA=1` 的覆盖映射子集（E2） | `gates/tia.json` 的映射与过期判定 | `scripts/tia_map.py` + `run_gates.py` 的 `TF_TIA` 分支 | 没有映射 / 映射过期 / 判不出 ⇒ **退回全量**（fail closed）；选测**永不被算作全量** |
| 夜间 | 每天一趟全量（计划任务 / cron） | 无人（定时器） | 操作系统计划任务调 `python -X utf8 scripts/run_gates.py`（本仓**没有**专门的夜间脚本；通知用 `tools/wb_notify.py`） | 夜里没跑 / 跑了红 ⇒ 落地前**必须**补一趟全量，**不许**拿昨天的绿当今天（`gates/diag/_daily_full.json` 是机器判据） |
| 异机 | 云机门禁池（E42：`--gate-on cloud`） | 里程碑 / 落地 | `tools/gate_pool.py` + `scripts/cloud/run_gate.sh` | 云机不可达 ⇒ **退 2 并明说「未跑门禁」**，不回落本机（fail closed）；要本机跑必须人显式 `--gate-on local` |

## 3. 决策树（五步）

```
改了什么？
├─ 只改 docs/、skills/、复盘/
│   → --fast（十几秒那几道）+ audit；**不必**全量（审计档本来就覆盖文档类改动）
├─ 只改 tools/、tests/、scripts/ 的实现（不动判据本体）
│   → --profiles auto（lang+audit）+ 相关 pytest 子集（--affected / TF_TIA=1）
│   红了一道：--only <那道门> 单独重跑（见 表二）
├─ 改判据本体（gates/**、scripts/run_gates.py、tools/pool/landing.py、pyproject.toml）
│   → **全量**，且必须在云机跑：wb_land --gate-on cloud
└─ 要落地一张卡
    → 全量（或必需档）+ --seal + rev==父提交；默认云机（--gate-on cloud）
```

档位名与工具参数的对应**只有一处真源**（`scripts/run_gates.py` 的 `build_parser()`）：
`--fast` / `--quick` / 不给（全量）/ `--profiles auto` / `--profiles lang,audit` / `--only` /
`--affected` / `--changed-from` / `--seal`。`tests/test_ci_docs.py` 会拿本文里的档位名
**逐个**去问那个 parser（写成两套当场红）。

## 4. 表一：22 道门清单表

耗时取**同一趟**（`gates/last.json`，`at = 2026-10-25T18:44:56`，`rev = 4c481eb`，4 worker、

## 5. 表二：红门处置表

先读 `gates/logs/<门名>.log` 的尾部，再**只重跑这一道**：
`python -X utf8 scripts/run_gates.py --only <门名>`（这一趟会落盘并在 `last.json` 记 `only`；
★ 它是**半趟**，`wb_verify` 会判红，修好后仍要跑全量）。

| 门 | 最常见的 3 个原因 | 只重跑这一道 |
|---|---|---|
| `pytest` | ① 新用例真红 ② 测试 fixture 写到真实落盘目录 ③ 并行下的偶发竞态（用 `--serial` 对照） | `--only pytest` |
| `acceptance` | ① 验收层依赖的 app 起不来 ② 覆盖率 addopts 误伤（已 `--no-cov`） ③ 用例选择标记写错 | `--only acceptance` |
| `ruff` | ① 未用 import ② 行超 100 字 ③ 版本与云机不一致（0.16.6） | `--only ruff` |
| `mypy` | ① 返回 `Any` 未标注 ② 新模块没进 strict 口径 ③ 第三方缺 stub | `--only mypy` |
| `check_layers_selftest` | ① 检查器自身的负样例失效 ② 命名用例改名没同步 ③ 临时树写盘 | `--only check_layers_selftest` |
| `audit` | ① 声称缺 `file:`/`test:` 指针 ② 台账 status 与 gaps 不匹配 ③ 交接文档那行分布没同步 | `--only audit` |
| `invariants` | ① 新能力没进不变量台账 ② 判据路径写错 ③ 钉子用例名改名 | `--only invariants` |
| `audit_titles` | ① SR 卡没有同号规格 ② 标题错位 ③ 规格文件重命名 | `--only audit_titles` |
| `check_layers` | ① 反引号里包了计划中的 markdown ② 五层缺一层 ③ 中文路径被转义 | `--only check_layers` |
| `contrast` | ① 新令牌对比度不达 AA ② 登记欠账又变差 ③ 明文/悬停两态漏测 | `--only contrast` |
| `style` | ① 一次性裸值 ② 缺 `:hover` / `:focus-visible` ③ 同形状重复 | `--only style` |
| `ui_text` | ① 新增 ≥30 汉字的文案 ② 已有 ≥20 汉字变长 ③ 登记项对不上 | `--only ui_text` |
| `commands` | ① 命令表与 CLI/⌘K 漂移 ② MCP 工具表没跟着 registry ③ 参数改名 | `--only commands` |
| `ui_dom_probe` | ① 选择器改名 ② 页面结构变了 ③ 环境里没有 node（那时是 `not_run`，**不是**通过） | `--only ui_dom_probe`（要有 node） |
| `proxy` | ① `last_verified` 过期 ② 指标改了没重验 ③ 代理映射键拼错 | `--only proxy` |
| `lf1_live` | ① 端口被占 ② 服务没起 ③ 端口段与别的门重叠 | `--only lf1_live` |
| `web_live` | ① 同上 ② 静态资源 404 ③ 浏览器缓存 | `--only web_live` |
| `render` | ① 视图/宽度改了没更新黄金 ② 采两遍不一致（工具不可信，退 4） ③ 浏览器没装 | `--only render`（要有真浏览器） |
| `ui_flow` | ① 行为流步骤改名 ② 元素 0×0/匹配 0 个 ③ 与 render 并行争浏览器资源 | `--only ui_flow`（要有真浏览器） |
| `docs` | ① 新写的相对路径指不到文件 ② 底账被顶破（改完债没跟着下调） ③ 文档自称已废弃却没写 `status: superseded` | `--only docs` |
| `skills_claims` | ① 技能正文里的命令与 `tools/` 源码真漂移（参数改名/脚本改名） ② 「对不上」不为 0（`--mode report` 下「判不出」不红，但**不是**通过） ③ 新工具写进技能正文却没建 | `--only skills_claims` |

## 6. 表三：时机表

| 时机 | 跑什么 | 在哪跑 | 判据（机器可判的那一条） |
|---|---|---|---|
| 卡内自测（改完立刻） | `--fast` + `--only <改到的那几道>` | 本机 | `--fast` **不落盘**，不许当提交闸 |
| 提交前 | `--profiles auto`（必需档）或 `--quick` | 本机 | `last.json` 的 `profiles_run` ⊇ `required_profiles` |
| 落地前 | 全量（或必需档）+ `--seal` | **云机**（`wb_land --gate-on cloud`） | `wb_verify`：`rev == 父提交`、门数 == 门表、`not_run` 空 |
| 每天 02:00 | 全量 | 本机或云机（只许一台） | `gates/diag/_daily_full.json` 记着「今天跑过全量」 |
| 里程碑前 | 全量 ×2（异机） | 云机两趟 | 两趟读数一致；差异 ≤5% 算噪声（方法见 `云门禁机.md` §4） |

## 7. 常用命令（可直接复制）

```bash
# 内循环：十几秒那几道（不落盘，不是提交闸）
python -X utf8 scripts/run_gates.py --fast

# 只跑某几道门（半趟；wb_verify 会判红，修好后仍要全量）
python -X utf8 scripts/run_gates.py --only pytest,ruff

# 按改动面选必需档（判不出 ⇒ 全量）
python -X utf8 scripts/run_gates.py --profiles auto

# 落地前全量（本机；离线/排障时用）
python -X utf8 scripts/run_gates.py && python -X utf8 scripts/run_gates.py --seal

# 落地（默认云机门禁池；云机不可达 ⇒ 退 2 且不回落本机）
python -X utf8 tools/wb_land.py --card <卡号> --tree .wt/<卡树> --task T-… \
    --title "…" --evidence … --allow … --gate-on cloud

# 读结论：一屏核对（FAIL 条数就是退出码）
python -X utf8 tools/wb_verify.py --tree .wt/<卡树> --allow '*' --allow '**'
```

## 8. 边界（如实写）

- **夜间有入口脚本，但不装系统计划任务**：夜间那一趟由操作系统计划任务调
  `python -X utf8 tools/wb_nightly.py --run`（该脚本自己在 `git worktree add --detach` 的独立副本里
  跑 `scripts/run_gates.py` 全量，产物落 `gates/diag/nightly/nightly-<时间戳>.json`，`ok` 只认门禁
  退出码 0；它同时给 `tools/pytest_select.py` 供「最近一次全量绿 ≤24h」那一问）；红了的通知走
  `tools/wb_notify.py`。装计划任务那一步在操作系统那边，脚本自己不装
  （`python -X utf8 tools/wb_nightly.py --status` 只打印判定）。
- **云机 2026-10-28 前没有 node**：装配脚本只装 Python + Git（`云门禁机.md` §2）；补装
  node v22.14.0 之后三道 node 门能真跑。仍有一条硬限制：`render` 的金样本与**采集机的
  显示栈**绑定 ⇒ 非采集机上记 `EXCLUDED`、`ui_flow`/`web_live` 在没浏览器的机器上记
  `not_run`。`not_run` 是「未验证」，**不是**通过；`EXCLUDED` 是「这门在本机不成立」，
  也**不是**通过 —— 三者都由 `tools/gate_verdict.py:judge()` 同一份判据判（卡 E63）。
- **「没写」不等于「没问题」**（卡 E63 三条，都能在 `tools/gate_verdict.py` 里读到）：
  ① 阻断门那一行**没写 `exit_code`** ⇒ 未验证（不是「默认 0」）；
  ② `build_jobs()` 被 `--profiles`/`--affected` 裁成**零门** ⇒ `run_gates.py` 退 3
  （未验证），不是退 0；③ 云机回传的产物 `host` 必须是**这台云机**（`wb_land` 用
  `check_host=True`），哈希对得上但换台机器重跑不算数。

- **云机慢不等于不能用**：同 commit 受控 A/B（源：`云门禁机.md` §7.1 实测表，原始日志
  `gates/diag/bench-cloud4.log`）本机 pytest 403.46 s、云机 684.27 s —— 慢的是墙钟，
  省的是工人的机器（卡 E42 §1）。
- 本页不新增门、不给「跳过某门」的建议：只说明「这一档本来就不含它」。
- **宿主给对话窗口的指纹不是被测物**：`DSH_SESSION_ID` 由宿主注入，一旦渗进测试进程，
  `tools/wb_session.py` 就会去读**本机**那份 `gates/diag/session-leases.json`（gitignored），
  判据于是吃进「这台机器上谁持有哪张卡」——落一份纯文档改动时也能假红 9 条（卡 E57）。
  `tests/conftest.py` 的 autouse 夹具统一摘掉它；需要指纹的用例自己 `monkeypatch.setenv`。
- **仓外配置同理**：`TF_PROJECTS_TOML` / `TF_MODEL_REGISTRY` / `TF_MODEL_WHITELIST` /
  `TF_POOL_CFG_DIR` / `TF_POOL_CFG_DST` 由 `scripts/cloud/run_gate.sh` 注入，同族处理（卡 E49）。
