# 租约与锁 —— 四把锁各保什么、TTL 多少、死主怎么办

> 口径：**「谁在动这棵树」必须有一处机器可读的回答**。pool 用四把锁回答它，四把都**不记 pid** ——
> Windows 上没有"探活"，`os.kill(pid, 0)` 会把真在跑的进程**杀掉**（`复盘/口径坑.md` 坑 27）。
> 判据本体在 `tools/pool/registry.py`、`tools/pool/guards.py`、`tools/pool/locks.py`、
> `gates/diag/gate_lock.py`、`tools/pool/task.py`；本篇只做对照表与实测读数。

## 1. 四把锁一览

| # | 锁 | 真源 | 保什么 | TTL / 陈旧判据 | 死主怎么办 |
|---|---|---|---|---|---|
| 1 | **租约**（lease） | `tools/pool/registry.py` | 谁占了哪棵树、哪个冲突域、哪个池/模型 | `DEFAULT_TTL = 21600` s（6 h，`:48`）；判死 `is_dead`（`:192`）= ① 超过 TTL **或** ② 该卡日志被判「断了 / 已判决」 | 只读时**不列**（`list_reservations`）；下次 `reserve` 先把死的剔掉再写（`:300`） |
| 2 | **树占用** | `tools/pool/guards.py:95`（`tree_guard`） | 一棵树同时只能有**一个活租约**（主树也占） | 不自己算 TTL —— 只看活租约（`_is_live`，`:67`） | 租约死了就不算占用 |
| 3 | **门禁锁** | `gates/diag/gate_lock.py` | 同一**端口段**不许两条线同时跑门禁（会互掐服务 ⇒ 假红） | `DEFAULT_STALE_AFTER = 10800` s（3 h，`gate_lock.py:81`）；`age > 持有者租约` ⇒ 可清 | 后来者 `acquire` 时清掉陈旧锁并打印原文；`--wait 5400` 是等锁上限 |
| 4 | **收件箱自旋锁** | `tools/pool/task.py:243`（`spin_lock`） | 同一任务的**状态机**并发写（投递 / 豁免 / 标 landed） | `DEFAULT_LOCK_TTL = 3600` s；`DEFAULT_LOCK_WAIT = 10` s | 陈旧可被接管，接管记进状态 `history`（`takeover`） |

四把锁的**分工**一句话：① 管"人"，② 管"树"，③ 管"门禁端口"，④ 管"任务账本"。
它们**互不替代**：租约活着不等于门禁锁活着（一个窗口可以占着树却在等锁），
门禁锁空着也不等于树空着。

## 2. 几条必须记住的口径

- **主树也是"一棵树"**：`tree=""` 就是主树，`tree_guard` 照样判（`_tree_label` 打「（主树）」）。
  所以"我想在主树上改两行"也要先占 —— 这正是主干保护（`tools/pool/landing.py:1514` 那条 `return 5`）的前置。
- **空域会绕过域守卫**：`--files` 一个都不给 ⇒ 与谁都不相交 ⇒ `domain_guard` 放行。
  所以租约 CLI 把 `--files` 设成 **required**（`tools/pool/lease.py:92`），
  「查不到的卡不许猜成空域」是同一条口径的反面。
- **同文件不同符号可以并行**：`domain_guard` 分两层判（粗筛 `files_intersect` + 细判
  `domain_symbols.overlap`）；声明写成 `<路径>::<符号>` 且符号不同 ⇒ 放行（只打一行 rebase 提醒）。
  整个文件（不写 `::`）照旧拒。
- **门禁锁 `release` 必须带同一端口段**：不带 `TF_GATE_PORT_BASE` 时它在默认段（8531）里找锁，
  打印「没有锁，无需释放」⇒ **真正的锁泄漏**，一直占着全局并发名额（`复盘/口径坑.md` 坑 16）。
- **门禁锁不靠 pid 判活**：`acquire` 与 `run_gates` 是**两次进程调用**，pid 正常就是死的；
  活不活只看租约（`gate_lock.py status` 自己会打这句话）。
- **落地链任何退出路径都还锁**：① `atexit` 兜底（`tools/pool/landing.py:1502`，`--commit-only` 不注册）；
  ② 门禁跑着时有续租线程（`_renewer_loop`，默认 `TF_GATE_RENEW_INTERVAL=300` 秒），锁不会被误判陈旧。

## 3. 实测读数（原样，可复现）

**① 一条活租约长什么样**（主树 `gates/diag/pool-registry.json`，这是**当前**那张卡的登记）：

```json
{ "card": "F5", "tree": ".wt/F5", "files": ["docs/subsystems/pool/README.md", "…共 8 条"],
  "project": "engineering", "pool": "", "model": "deepseek-v4.1-flash",
  "owner": "<主机名>:<pid>", "at": "2026-10-25T09:46:48", "ttl_seconds": 21600.0 }
```

读法：**`at` + `ttl_seconds` 就是这条租约的寿命**，没有心跳字段 —— 判活只问这两样（加上日志状态）。
写入是**原子**的：同目录 `tmp` + `os.replace`（`:149`），读者只会看到旧的整份或新的整份。
文件**坏了不清空**（`load` 抛 `RegistryError`，`:131`）—— 坏文件原封不动留着，人来看得见全貌。

**② 门禁锁空着时**（`python -P -X utf8 gates/diag/gate_lock.py status`）：

```
[锁] 空着（没有任何段的锁）
[锁] ★ 别看 pid 判活：acquire 与 run_gates 是两次进程调用，pid 正常就会是死的。
[锁] 全局并发上限 TF_GATE_MAX_CONCURRENT=2，当前租约内 0 把在跑
[锁] 本段门禁端口占用（base=8531）：全空
```

`tools/pool/locks.py:51` 的 `parse_entries` 就是按上面那行的形状解析的（认不出的行跳过，不猜）。

## 4. 死主（进程没了但锁还在）怎么处置

| 情形 | 判据怎么说话 | 人该做什么 |
|---|---|---|
| 租约过了 TTL | `is_dead` 为真 ⇒ 不再列进活租约；`reserve` 时被剔掉 | 什么都不用做；确要立刻放，跑 `tools/pool/lease.py release --card <卡>`（用法实测：`usage: lease.py release [-h] --card CARD`，只有 `--card` 一个参数） |
| 日志已判「断了 / 已判决」 | 同上（复用 `tools/pool/jobs.py` 的三态判据，不另写一套） | 同上 |
| 门禁锁过了租约 | `acquire` 打印「清掉陈旧锁（已 N s 未动 > 租约 M s）」 | 直接重跑；**别手删锁文件**（会绕过端口段口径） |
| 收件箱锁过了 TTL | `spin_lock` 接管并在 `history` 里留一条 | 直接重试；翻 `history` 看是谁的旧锁 |

★ 一条不许做的事：**别用 `os.kill(pid, 0)` 判活**（见篇首）。这也解释了为什么租约里**根本不记 pid**。
