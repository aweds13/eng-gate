# 派活口径 —— 四张入口的契约表

> 口径：**一个任务从"派出去"到"收成一笔提交"，只经过四张入口**；每张入口谁写、写什么、
> 参数怎么给、失败怎么报，都钉在代码里。这篇只做**索引与实测**，判据本体在 `tools/pool/**`。
> 实测环境：`.wt/F5` 卡树，2026-10-25；命令一律 `python -X utf8`。

## 0. 一句话分工

```
wb_dispatch  →  wb_task register  →  wb_task claim  →  wb_land
（派出去）      （预声明要哪些卡）    （各卡交成功申请）   （收成一笔提交）
```

四张入口**不是流水线四步**：`register` 是**开工前**（人写），`claim` 是**每张卡自己**在干完后写，
`wb_land` 是**主控**收口。`wb_dispatch` 只负责把工人拉起来并占树 —— 它**不收口、不提交**。

## 1. 契约表

| # | 入口 | 谁写 | 写什么（落盘） | 参数口径 | 失败怎么报 |
|---|---|---|---|---|---|
| 1 | `tools/wb_dispatch.py` | 主控 / 任意窗口 | 工人日志 `gates/diag/wb-<卡>.jsonl`、判决 `gates/diag/wb-<卡>.verdict.txt`、摘要 `gates/diag/wb-<卡>.report.md`；**占树**（写租约账） | ★ **只认 `--cwd`，没有 `--tree`**；`--pool codebuddy\|codearts`；默认 dry-run | `[FAIL] …` + 退 **2**（前置拒，零副作用） |
| 2 | `tools/wb_task.py register <toml>` | 人（开工前） | 主树 `gates/diag/batch/<任务>.toml`（预声明）+ `<任务>.json`（状态机） | 位置参数是**那份 toml 的路径**；或 `--from-pool <层>` 由机器生成 | `✗ BatchError：…` + 退 **2** |
| 3 | `tools/wb_task.py claim <task> <member>` | 每张卡自己 | `<任务>.d/<卡>.json`（收件箱）+ 状态机推进 | ★ `--files` 是**逗号串**；`--claim success` 必须带 `--evidence` | `✗ RefuseError：…` + 退 **2** |
| 4 | `tools/wb_land.py` | 主控 | 一笔提交（四 trailer）+ `gates/review/<任务>.json` | `--card` 或 `--batch` **恰好给一个**；`--tree/--task/--title/--evidence/--allow` 必填 | 退 **1/2/3/4/5/6/7**，见 §4 |

三条容易记错的口径：

- **`wb_dispatch` 没有 `--tree`**。树是靠 `--cwd` 给的（改的是**工人进程的 cwd**）；
  派活产物仍落**主仓**的 `gates/diag/`（那份目录 gitignore、卡树里没有）——
  所以要工人落在卡树里干，必须 `--cwd <卡树绝对路径>`（卡 103 / 卡 203）。
- **`claim --files` 是逗号串**，不是空格分隔的多个参数：代码里就是
  `(args.files or "").split(",")`（`tools/pool/task.py:647`）。
- **`wb_dispatch` 默认 dry-run**：不加 `--execute` 只做前置检查 + 打印命令；
  加 `--already-reserved` 表示调用方（MCP 写面）已经占过树 ⇒ 只跳过守卫与占/还树。

## 2. `register` 的预声明必填项（实测）

预声明是一份 TOML，落盘**之前**全套校验（`tools/pool/task.py:357`）：

| 字段 | 要求 | 不满足时报什么 |
|---|---|---|
| `id` | 必须与**文件名**一致 | `BatchError：预声明里的 id（…）与文件名（…）不一致` |
| `why` | 非空（这个任务要干成什么） | `预声明缺 why（这个任务要干成什么）` |
| `[[member]]` | 至少一张卡 | `预声明里一张卡都没有（[[member]]）` |
| 成员 `id` | 非空、不重复 | `有成员没写 id（卡号）` / `成员（卡号）有重复` |
| 成员 `layer` | 非空（审美层 / 后端 / 前端 …） | `卡 X 没写 layer（属于哪一层…）` |
| 成员 `paths` | **非空**；审计型只读成员须显式 `read_only = true` 才可空 | `卡 X 没写 paths（这张卡的域＝它能碰的路径）` |
| 成员 `paths` × 受保护共享文件 | 谁都不许把台账 / changelog / 交接 / 门禁产物写进域 | `卡 X 的域 … 覆盖了受保护共享文件 …` |
| `gate_cmd` | 只认 `python -X utf8 scripts/…` 或 `python -X utf8 tools/…`，禁 shell 元字符 | `gate_cmd 含 shell 元字符 …` / `必须以 python -X utf8 开头` |
| `on_complete` | 只认 `gate` / `draft`（**故意不含 commit**） | `on_complete 里有不认识的动作 …` |

★ 卡规格里那句「`paths` 必须含卡规格」是**写卡口径**（把本卡要产出的文件全列进域）；
代码层钉的是「`paths` 非空」这一条 —— 别把两件事混成一条机器判据。

## 3. 实测读数（原样，可复现）

**① `wb_dispatch` 只认 `--cwd`**（给 `--tree` 当场被 argparse 顶回，退 2）：

```
$ python -X utf8 tools/wb_dispatch.py --card F5 --tree .wt/F5 --spec 复盘/卡/卡F5-pool子系统文档.md
wb_dispatch.py: error: unrecognized arguments: --tree .wt/F5        # 退 2
```

**② 跨池串用被拒**（`--pool codearts` 却给了 `codebuddy` 的裸名，退 2）：

```
$ python -X utf8 tools/wb_dispatch.py --card F5 --pool codearts --model deepseek-v4.1-flash --cwd <卡树>
[FAIL] 跨池串用被拒：模型「deepseek-v4.1-flash」属于「codebuddy」池，不在当前「codearts」池。
两个池的 id 体系不同（codebuddy 用裸名、codearts 用 provider/model 形式），不许串用。
请用 ``--pool {belongs_to}`` 切到那个池，或换一个「codearts」池的模型。
```

> ★ 原文如此：那句 `--pool {belongs_to}` 的占位符**没被插值**（`tools/pool/model_registry.py:95` 的
> `PoolMismatchError.__init__` 里少了一个 f 前缀）。档里照抄原文，别照自己以为的改。

**③ 未知池**（退 2）：`[FAIL] 未知池：trae（已接的池：codebuddy, codearts）。请用 ``--pool <codebuddy|codearts>`` 指定。`

**④ `register` 缺 `why`**（退 2，错误走 stderr）：

```
$ TF_BATCH_DIR=<临时目录> python -X utf8 tools/wb_task.py register <临时目录>/B-NOWHY.toml
✗ BatchError：预声明缺 `why`（这个任务要干成什么）        # 退 2
```

**⑤ `claim` 的域外文件被点名**（退 2；`--files` 给的是逗号串，这一趟给了域外的 `tools/pool/guards.py`）：

```
$ TF_BATCH_DIR=<临时目录> python -X utf8 tools/wb_task.py claim B-F5TEST F5T1 \
      --claim success --evidence 读数 --files tools/pool/guards.py
✗ RefuseError：卡 F5T1（文档）碰了**自己域外**的文件：tools/pool/guards.py；
这张卡的域是：docs/subsystems/pool/*.md；
要动域外的文件 ⇒ 改预声明里的域（那是**改冲突域声明**，要显式做）或另开一张卡   # 退 2
```

**⑥ 交成功申请后当场推进**（同一份任务、域内文件）：状态直接到 `awaiting-commit`，
打印 `还缺：（齐了）` 并生成两份骨架（`gates/diag/batch/<任务>.draft.md` 与 `gates/diag/batch/<任务>.why.md`）—— **停在等人补『为什么』，绝不自动提交**。
（★ 原文里的"补完 → 走正常收口（`_integrate.py --batch`）"仍是**旧名**；今天的壳是 `tools/wb_land.py`。）

## 4. `wb_land` 的两种跑法与退出码

| 退出码 | 含义（`tools/pool/landing.py:1418` 起） |
|---|---|
| 1 | 门禁红 / 门禁硬超时（124 → 当作 1，锁当场放掉） |
| 2 | 计划外暂存或空暂存区 ⇒ 停手；`--commit-only` 那条提交失败也退 2 |
| 3 | 卡树 HEAD 不是主树 HEAD 的祖先 ⇒ 停手（`checkout` 会抹掉已提交的改动） |
| 4 | ③′ fail-fast 钉子红（队列里登记的卡规格没进索引） |
| 5 | 主干保护：主树有跟踪文件改动且不在白名单 ⇒ 拒 |
| 6 | `--card` / `--batch` 不是**恰好给一个** |
| 7 | ③″ 快门禁预检红（全量门禁一步没跑、锁也没拿） |

**`--batch` 与 `--commit-only` 的差别**（实测依据 = `tools/pool/landing.py` 里那段分叉，不是印象）：

| | `--batch` | `--commit-only` |
|---|---|---|
| 走哪几步 | ⓪ 回退派生物 → ① 迁树 → ② 文书 → ③ sync → ③′/③″ → ④ 门禁 → ⑤′ 白名单/翻账/暂存 → ⑤ 封存 → ⑥ 提交 → ⑦ 审计/ff → ⑧ 复核 | **从 ⑤′ 起**；①~⑤ 全跳（`landing.py:1720` 的 `if a.commit_only`），⑧ 也跳（`landing.py:1922`） |
| 门禁 | 真跑（默认按域选档；碰判据本体/空计划/今天没跑过全量 ⇒ 强制全量） | **不跑**；封存也不重做（`landing.py:1783` 的 `not a.commit_only`） |
| 多棵树 | 走 `_integrate_multi_tree`：批成员的产物不在同一棵树 ⇒ 合进集成树，冲突就停手 | 不涉及 |
| trailer | `Gates: 全量门禁绿 + seal`（增量那趟写「非全量」字样） | `Gates: 复用已绿的那一趟（--commit-only，封存未变）；真读数见 gates/last.json` |
| 适用 | 正常收口 | 门禁已绿、封存没变，只需要补提交（例如上一趟死在 ⑤′ 之后） |

两条不写在表里但会咬人的：`--commit-only` **不注册** atexit 还锁（`landing.py:1502`），也不做 ⓪ 回退 ——
因为它要提交的正是上一趟写好的文书，退了就没东西可交。

## 5. 收口面（谁进提交）

- `--allow` 是**白名单**（glob），越界判据在 `tools/pool/review.py:24`（`outside_allow`）——唯一实现。
- 落地链会自动补三样：三个文书片段（`docs/changelog.d/`、`docs/traceability.d/`、`复盘/交接.d/` 下以台账号命名的那三份）+ 三个派生共享文档 + 两个门禁产物（`landing.py:74`、`:89`）。
- 暂存区里出现白名单外的项 ⇒ **停手**（退 2），不"顺手带上"。
- 提交前先跑 ⑤′ 翻账：单卡按 `--task == 卡.task` 认，攒批按 `[[member]]` 逐成员认（`landing.py:234`、`:303`）。
