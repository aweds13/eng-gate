# 模型与号池 —— 批准集 / 可用集 / 开关文件，三者怎么咬

> 口径：**「能不能派某个模型」和「号池里现在有哪些模型」是两个问题**，答案来自两套账，
> 别混成一条。本篇只讲这两套账怎么咬、跨池为什么拒、429 怎么处置；
> 判据本体在 `tools/pool/model_registry.py` 与 `tools/pool/models.py`，这里不抄。
> 实测环境：`.wt/F5` 卡树，2026-10-25。

## 1. 五个名词（先分清，再谈关系）

| 名 | 住哪 | 谁能改 | 作用 |
|---|---|---|---|
| **注册表** | `tools/pool/model-registry.toml`（**仓内**） | 只有用户 | 「一层统一、按池分流」的**可写真源**；每条声明 `alias / pool / id / default / note` |
| **批准集** | `infra/pool/models.whitelist.toml`（**仓外**，号池目录） | 只有用户 | 号池侧「批准了哪些模型」；码道池的真实 id 从这里派生 |
| **可用集** | `infra/pool/models.live.json`（**快照**，带 `at`） | 机器（号池侧的 `pool_models.py --check` 现拉） | 号池侧「现在真能调通哪些」 |
| **开关文件** | `infra/pool/model-switches.toml`（**仓外**，与号池同目录） | 只有用户（UI 也是改它） | 按一下就 true/false 的**加法**开关：`[switch.<池>]` |
| **一次性授权** | `ONE_OFF_MODELS`（`tools/wb_dispatch.py:185`） | 用户口头令，主控填 | 机制在、**今天名额为空**（用完就撤） |

**快照过期了怎么让它变新**：那条命令留在一处 —— `tools/pool/models.py` 的 `probe_command(pool)`（路径**现算**：号池目录在任何祖先层级都行）与 `probe_hint(pool)`（脚本不在 ⇒ 明说没有，不给假命令）。读面三处都调这一份：`load_pool_models()` 的 `snapshot_note`、`gateway._model_block()` 的 404 文案、`pool_mcp.tool_pool_models()` 的人话段。同一个「过期」在两处态度不同：**网关硬拒**（404，一个字节不出网），**派活器只提示不拦**（`tools/wb_dispatch.py` 的 `snapshot_stale_problem` 只往 stderr 打一行）。

## 2. 三者怎么咬（一条判据 + 一条对账）

**判据：派活只看「允许集」，不看批准集。**

```
允许集(池) = 注册表该池条目            （下限，缺它就没得派）
           ∪ ONE_OFF_MODELS            （今天为空）
           ∪ 开关文件里该池打开的       （只做加法，不许把名单里的关掉）
```

- 实现：`tools/pool/model_registry.py:343`（`effective_allowed_for`）；
  闸门在 `tools/wb_dispatch.py:414`（`model_rejected`），不在允许集 ⇒ `[FAIL] 未授权模型，已拒绝派活：…` + 退 2。
- **轮换链只走注册表**（`rotation_chain_for`）：一次性授权与开关**都不进 429 轮换链** ——
  开关是"允许你调"，不是"允许系统拿它去轮换"。
- 开关文件**按池分段**：`[switch.codebuddy]` / `[switch.codearts]`；旧文件只有顶层 `[switch]` 时当 codebuddy 读
  （卡 166 判据 ⑥：CodeBuddy 池行为不变）。文件**不存在 ⇒ 空字典、不报错**；
  文件**坏 ⇒ `SwitchFileError` 点名路径与行号**（不许静默当空，`tools/pool/models.py:143`）。

**对账：批准集 ∩ 可用集 是仓外那本账的体检，不是派活判据。**

| 字段 | 意思 | 今天的实测读数 |
|---|---|---|
| `in_both` | 既批准又出现在可用集里（**只是号池两本账的交集**；今天派不派得出去按池现算，见 `pool_models` 的「按池判决」段与机器块的 `dispatch`） | `huaweicloud-maas/GLM-5.2`（1 条） |
| `approved_but_missing` | 批准了但拉不到（可能下线/改名） | 空 |
| `live_but_unapproved` | 能调通但**没批准**（不许用） | `glm-5.2-sft-harmony`、`glm-5.3`、`openpangu-2.0-flash`、`openpangu-2.0-pro`（4 条） |
| `snapshot_at` | 可用集的取数时间 | `2026-10-20 20:43:16` |

`compare_rosters()`（`tools/pool/models.py:208`）拿本仓名单与批准集比，**只报告、绝不自动改名单**；
它会专门点出「id 体系不同」这一条（裸名 vs `provider/model`）—— 那是第 3 节要拒的根。

## 3. 跨池为什么拒

两个池**连 id 体系都不同**，所以"挑一份当真源"这条路本身是错的（卡 166 的立项理由）：

| 池 | id 形态 | 默认值从哪来 | 今天接没接 |
|---|---|---|---|
| `codebuddy` | **裸名**（`deepseek-v4.1-flash`） | 注册表里该池 `default = true` 的那条 | 已接（在跑） |
| `codearts` | `provider/model`（`huaweicloud-maas/GLM-5.2`） | `[pool.codearts].default` 声明的那个 | **只留接口 + 拒绝路径**（真实调用另立卡） |

三条硬规矩（都在 `tools/pool/model_registry.py`）：

- **跨池串用 ⇒ 拒**（`:95` `PoolMismatchError`）：给的模型属于别的池，就点清"它属于哪个池、当前是哪个池"。
- **未知池 ⇒ 拒**（`:109` `UnknownPoolError`）：不静默降级到别的池，并列出已接的池。
- **默认值绝不"取注册表首项"**（`:312` `default_model_for`）：卡 146 就是栽在这 ——
  把码道池的白名单当唯一权威后，`--model` 缺省取到"首项"= 一个 CodeBuddy CLI 不认的名字 ⇒ 不带 `--model` 的派活全挂。

实测的两条拒单原文见 [`派活口径.md`](派活口径.md) 的 §3 ②③。

## 4. 429 / 额度：三拍「等 → 按序换 → 全挂就停」

429 **长得像成功**：CLI 给 `result.subtype = error_during_execution` + 空回话 + **退出码 0** ——
只看退出码会把"额度烧干"读成"正常收工"（2026-09-26 真撞过）。所以判据读事件本身：

| 拍 | 做什么 | 代码 |
|---|---|---|
| ① 认 | 读 `result.errors` / `errors_info` 里的 `429` / `6004` / `quota`（回话正文只认完整中文短语） | `tools/wb_dispatch.py:1468`（`quota_error`） |
| ② 等 | 撞上先等 `DEFAULT_QUOTA_WAIT = 300` 秒再探（**别把整卡重跑当探测**） | `tools/wb_dispatch.py:217` |
| ③ 换 | 按**该池**注册表顺序取下一个（`next_whitelist_model`）；已是最后一个 ⇒ `None` | `tools/wb_dispatch.py:435` |
| 停 | 全挂 ⇒ 退 **7**（不是"成功"），判决里写「429 限流（额度重置时间：…）」 | `tools/wb_dispatch.py:3334` |

四条边界：① 轮换**不跨池**（换到别的池 = id 体系不同 ⇒ 必挂）；
② 额度账按**钟表**算（`import pool_quota`，卡 201）：不凭记忆、按记录时间 vs 现实时间。
③ 四态里「已过期 / 余额耗尽 / 未记录」三态都说**要探** ⇒ 读数自带那条命令：
   `python -X utf8 tools/pool_accounts.py probe --platform <池>`（卡 E112）。
   它写**仓外账本**的观测时刻、联网；`gates/diag/quota-state.json` 只由 429 派生 ⇒ **探完四态未必变**。
④ 账本里「探过但没探到」与「从没探过」是两件事，读数必须分得开（卡 E118）：
   额度列有三支 —— 有 `amount` ⇒ 念余额；没 `amount` 也没 `samples` ⇒ 「未观测」（**只有这一支**表示账本里从没探过）；
   没 `amount` 但有 `samples` ⇒ 念末条的 `kind` + `at` + 「连败 N」+ `health.state`，例如
   `skipped @2026-11-16T12:57:30+08:00（连败 1；健康 unknown）`。
   `amount` 是**余额**口径、由探针之外的人填，四个非 ok 结论码（skipped / uncertain / failed / not-supported）本来就不写它 ⇒
   拿 `amount is None` 当「没探过」是错的。机器面同一件事：`list_rows` 每行另带 `quota_kind` / `quota_at` / `health_state` /
   `consecutive_failures` 四个键，缺键就是 `null`（不补 `""` / `"ok"` / `0`）。
④ **坏文件是读数，不是「没有」**（卡 E131）：`models.whitelist.toml` / `models.live.json` / `gates/diag/quota-state.json`
   读不懂时那几个读面**不抛**（抛 = 整条 MCP 工具变成 `-32603` 协议层错误，人只看到「工具坏了」），
   而是把「**哪份文件 + 解析错误首行**」念出来：`load_pool_models` 的 `whitelist_error` / `snapshot_error`、
   `status()` 的 `state_file_broken`（正常都是 `None`）。与「文件不存在」**必须能分开**：
   不存在 ⇒ 这条不知道（仍是 `is_error=False`，念「不知道它多旧」或「没记录」）；
   坏了 ⇒ 工具坏了（`is_error=True`，念「坏了」+ 解析错误首行）。
   形状不对（顶层不是表 / `approved` 不是数组）走同一条路，念「结构不对」——
   **不许**让 `AttributeError` 冒出来（那会把「文件写歪了」读成「程序有 bug」）。

## 5. 今天的一次实测（原样）

```
$ python -X utf8 -c "…effective_allowed_for('codebuddy')…"
codebuddy allowed : deepseek-v4.1-flash, glm-5.3-flash, glm-5.3, kimi-k3-1, glm-5.2
codebuddy chain   : deepseek-v4.1-flash, glm-5.3-flash          # 轮换只看这两条
codearts  chain   : huaweicloud-maas/GLM-5.2
switch(codebuddy) : {'glm-5.3': True, 'kimi-k3-1': True, 'glm-5.2': True}
```

读法：允许集 5 条 = 注册表 2 条（= 轮换链）+ 开关文件 3 条；**开关打开的那 3 条能派、但不参与轮换**。
这条读法是本节的机器判据：改注册表或改开关文件之后，上面两行会**同时**变 —— 那就是单一真源在起作用。

## 6. `[account.health]` 六个键谁写

它跟顶层 `[[account]].state` **不是一套**：顶层那五个是人判定的「这个号还能不能用」，
`health` 这一块是**机器观测到的事实**。分开写、分开读，谁也别替谁下结论。

| 键 | 唯一的写方 | 什么时候写 | 谁读它 |
|---|---|---|---|
| `state` | `_apply_probe_health()`（`tools/pool_accounts.py:1137`） | 探测拿到结论码 ⇒ 走 `derive_health_state()`（`:1118`）的表：`ok`→`ok`、`failed`→`auth-expired`，其余（`uncertain` / `skipped` / `not-supported` / `unknown-platform`）**不写** —— 不编 | `account_status` 一类只读面 |
| `consecutive_failures` | 两条写路**同一口径**（`tools/pool_accounts.py:1162` 探测 / `:1587` 签到） | 结论码 ∈ `_ck().NEEDS_HUMAN`（只有 `uncertain`、`failed`）⇒ 加一；其余 ⇒ **归零**（归零与 `state` 写不写无关） | `recheck_rows()` / 工作台 |
| `last_probe` | 探测路（`:1157`）与签到路（`:1570`） | 每次真的问了上游 | 只作「最近一次问的时刻」；**不是**签到时刻 |
| `last_checkin` | 只签到路（`:1577`） | 领过 / 问过、且**不是** `--probe` | `recheck_rows()` 的结论码来源 |
| `last_checkin_at` | 只签到路（`:1583`），卡 E121 新增 | 同上，与 `last_checkin` 同一支一起写 | `recheck_rows()` 算「隔了多久」时**优先**它，缺失才回落 `last_probe`（`:1663`） |
| `revoked` / `revoked_at` | 只有 `saved_refresh_failed()`（`:537`，卡 A335） | 凭据确认被吊销 | 人看 |

**为什么非要拆出 `last_checkin_at`**：`last_probe` 是「最近一次问上游」，签到也是问，
所以它**天然会被探测刷新**。下午 `probe` 一次，`last_probe` 就变成下午 —— `recheck_rows()`
若拿它当签到时刻，上午真签到过的那次就会被读成「刚签过」⇒ 判成「当日已定案」，
那天再也不会去领。两个时刻只能分开存：一个记「问过」，一个记「领过」。

**写路径收口**：`health.state` 只认卡 E45 的五值（`HEALTH_STATES`，`tools/pool_accounts.py:70`）。
坏值在 `save_ledger()` 里当场抛 `LedgerError` 且**盘上字节不变**（`:360`）——
不靠 `lastgood.write_atomic()` 兜底：那里的 `validate` 只判**旧文件**能不能进 `.bak`，
新 payload 一个字节都没验过。

**别整块替换** `acc["health"]`：`revoked` / `revoked_at` 与这三键同住一块，整块赋值会把它们冲掉。
探测路的写方一律**逐键写**，这就是 `_apply_probe_health()` 存在的理由。

## 7. 窗口 / 回复上限：知道就说数，不知道就说 null（卡 E143 · T-AG657）

注册表每条 `[[model]]` 可以写两个**可选**字段，不写就是「不知道」：

| 字段 | 含义 | 缺席时 |
|---|---|---|
| `context_window` | 上下文窗口（token），**模型属性不是号属性** | `/v1/models` 发 `null` |
| `max_output` | 单次回复上限（token） | 网关按 `model_registry.UNKNOWN_MAX_OUTPUT`（今天 = 16384）发 |

三件事别混（`tools/pool/model_registry.py::_window_field`）：**缺席 = 不知道（None）** /
**0 = 合法读数**（一点都装不下）/ **负数、`true`、`"64k"`、`1.5` = 注册表坏**，点名第几条。
`true` 是 `int` 的子类，所以先判 bool 再判 int —— 否则它会以 `1` 的身份悄悄过关。

`GET /v1/models` 每条 `data` 是七键：`id` / `object` / `owned_by` / `context_window` /
`max_output_tokens` / `limits_source`（`registry` = 至少一个字段是填过的；`unknown` = 两个都没填）/
`disabled`（拒绝维度，见下）。
顶层 `note` 追加一句「有 N 条模型的窗口未知」—— **N 是读数**，0 也照说。

### 7.1 `disabled`：列出来的必须能用（卡 A383 · T-AG671）

第七键 `disabled` 说的是**这条模型能不能请求**，三态、一格都不许洗：

| 值 | 含义 | 怎么来的 |
|---|---|---|
| `null` | 查过了，**没**被禁用 | `model_registry.model_disabled()` 回 `None`（禁用表不存在也走这一支） |
| `"?"` | **不知道**（禁用表读不懂 / 形状不认识） | 回 `model_registry.UNKNOWN` |
| 原样 pattern | 被这条 pattern 命中，**请求会 403** | 回命中的那条 pattern（不归一化） |

顶层 `note` 再追加一句「有 N 条模型的禁用状态未知（disabled = \"?\"）；M 条被禁用（请求会 403）」，
两句都是**读数**，0 也照说 —— 与上面「窗口未知」那句并列，谁也不覆盖谁。

为什么是**加标注**不是**删条目**：清单的真源仍是批准集（`tools/pool/models.py` 的 `_approved_of`），
禁用只加标注、条目一条都不删。删掉的话用户拿着 403 文案在清单里查不到这一条 —— 而原件 F95 的
「隐藏 ≠ 不可用」在本仓方向相反（本仓是「列出来 ⇒ 必须能用」），所以这里**不新造 hidden 维度**，
只把「为什么不能用」发布出来。

判据只有一份：`list_models()` 调 `model_registry.model_disabled()`，与准入面 `_model_block` 的
`assert_not_disabled()` 同源；读面**不**用会抛的那一支（一坏表就 500 的话，`/v1/models` 会整面挂掉 ——
该做的是把「不知道」念出来）。

**未知按 16384 发**（F86 ② 的第二档）：回复上限**总有值**，没人知道时就是 16384 —— 这个数只有一处字面量，
住 `tools/pool/model_registry.py` 的 `UNKNOWN_MAX_OUTPUT`，网关 / 注册表 / 测试都不许抄第二份。

为什么 `null` 不能写成 0：0 是「量过，一点都装不下」，`null` 是「没人量过」。
混起来下游会把「没量过」读成「装不下」⇒ 全拒。同理，**不许**为了填满而抄一个「看着合理」的
128k / 200k / 1m：今天这两条 CodeBuddy 模型**没有可信来源**，就留空、就发 `null`。

**F86 ③「按 95% 挑号」不移植**：pool 的候选池是同一个模型的多个号，窗口是模型属性不是号属性 ⇒
换号装不下还是装不下（`tools/pool/gateway.py:184` / `:597`）。按 95% 挑号需要 token 计数，
本仓没有分词器。所以本仓只做**发布读数**这一半，挑号那一半留给消费方。

注册表坏掉时 `/v1/models` **不 500**：窗口这一维退化成「不知道」，清单照旧发布
（清单的真源是批准集，不是注册表）；注册表坏了该让**派活**拒绝，不该让只读读面挂掉。

## 8. 裸 id 行：一个只发布读数、默认关的开关（卡 A386 · F85）

有些消费方（编辑器插件、桌面客户端的模型下拉框）按**裸模型名**（`GLM-5.2`）认模型，
而批准集里的 id 是 `provider/model` 形式（`huaweicloud-maas/GLM-5.2`）。这个开关让
`GET /v1/models` 在既有行**之后**追加一圈裸 id 行，好让那些消费方能看见名字。

| 项 | 口径 |
|---|---|
| 开关 | `TF_POOL_GATEWAY_BARE_IDS`，**默认关** |
| 认什么 | 只有 `"1"` 是开；`""` / `0` / `true` / `yes` / 空白**一律关**（与 `TF_POOL_GATEWAY_REQUIRE_ORIGIN` 同款） |
| 关着时 | 答复与没这个开关时**逐字节相同**（测试钉死，不是「差不多」） |
| 打开后 | 既有行先原样，裸 id 行后追加 |

**只发布读数，不接请求。** 开关打开后 `POST /v1/chat/completions` 带 `"model": "GLM-5.2"`
仍然 404 + 「不在批准集里」—— 批准集**始终**是准入的唯一权威。`/v1/models` 里出现了某个名字，
不等于它可以拿来发请求；请求侧的按裸名路由不在这一层（见下「没搬的四件」）。

**追加行的内容 = 被指向的那一行的副本，只有 `id` 不同**：`object` / `owned_by` /
`context_window` / `max_output_tokens` / `limits_source` 逐键相同。裸 id 是同一行的**另一个名字**，
不是另一个模型 —— 给它单开一份读数就是在造第二份真源。

**尾段撞名不列，只报数。** 裸 id 取的是批准集 id 的最后一个 `/` 之后那段（`\` 不参与）。
若两条不同的批准行尾段相同（`pa/x` 与 `pb/x`），列一条 `x` 就是替调用方猜「是 pa 的还是 pb 的」
—— 本仓没有 provider 目录，猜不了，所以**不列**，只在顶层 `note` 追加一句
「有 N 条裸 id 因重名未列」。**N 是读数**，0 也照说（与「N 条模型的窗口未知」同款）；
开关关着时这句一个字都不出现。

**没搬的四件**（卡 A386 明确不做，别顺手补）：

- `GET /v1/models/{id}` 认裸 id：只读面的路径集合仍然是那四条，一条都不多。
- 用网关自己的解析决定裸 id 落到哪条 entry：尾段唯一才列，解析器不掺和。
- 设置面（写裸 id 配置的 HTTP 接口）：开关只从环境变量来。
- 请求侧按裸名路由：那是准入面的改动，得单独立卡。

判定「裸 id 该指谁」的现实约束：本仓 pool 层没有 provider 目录 / 路由组（那是上游
Magpie 的东西），所以「裸 id 该指谁」只能弱化成「批准集里的行 + 尾段唯一」。
## 9. 决策模型 / System One：不移植（卡 A381 · T-AG669）

magpie 有一整套「决策模型」设施：自己的端点 `POST /v1/systemone`、一类只做决定的模型与只装它们的
路由组（`jev-latest` / `decision-model-preview`）、一个拿 decision 模型判「这句话是哪个 intent /
这一轮多难」的 classifier 宿主。本仓**一条都不搬**，而且不是「搬了没接线」—— 生产码 `tools/` 与
`scripts/` 下 170 个 `*.py` 对六条字面零命中，`PATHS` 恰好四条，仓外账本 / 平台表 / 模型注册表
里一个 decision 号都没有。

为什么不搬，三条都写在 `docs/decisions/0011-no-systemone.md` 里：① System One 的 body 不是对话
（是「问题 + 候选答案 + 概率」），搬它就得搬一层协议翻译，撞 `tools/pool/gateway.py` 模块头
「**不做协议翻译**」；② 加第五条路径就是把「**四条路径，一个都不多**」这条判据自己推翻；③ classifier
要一个「用户这一轮开始时先问一次」的请求前调度点，那是给每个请求加一次上游往返，与「**不做定时器**：
每次请求现读现算」相反。

**这不是「以后再说」**：判的是「今天没有」，两半的失效条件分开写着 —— 只要哪天账本或平台表里登记了
哪怕一个 decision 号，`SKIP_NOT_APPLICABLE` 那一半立刻失效、要重新立卡；`SKIP_BY_REDLINE` 那一半
只有先改网关模块头那三条边界才会失效。钉子在 `tests/test_pool_no_systemone.py`（真服务 404 / 源码与
结构 / 生产码零命中 / ADR 与两处文档），要接的时候它会先红。
