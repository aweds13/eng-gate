# 映射表（mapping）—— 对方产物 → 我们的词

> ★ 「**不映射**」是一等值：写 `none`，**不是省略**。硬塞出来的台账条目没有可求值证据，
> 必然过不了对账。

| 对方的产物 | 映射到 | 判据（怎么算映射成立） |
|---|---|---|
| issue / 缺陷单 | **卡**（队列里的一条，进 backlog 文件） | 有标题、有验收 |
| CI job / 检查脚本 | **门**（一道能退出码判读的检查） | 能跑出 0 / 非 0 |
| 测试报告 / 覆盖率产物 | **证据**（台账条目里机器可求值的指针） | 文件路径能打开 |
| PR / 变更集 | **一笔提交**（落地单位） | 有 diff 边界 |
| 看板列（todo/doing/done） | 台账条目的 **status** | 一列一值 |
| TODO 注释 / 未完事项 | 台账条目的 **gaps** | 写的是边界不是口号 |
| 口头约定、聊天记录、wiki 里「应该怎么改」 | **none（不映射）** | 没有可求值形态，只能当背景写进复盘 |

## 用法

1. 勘察定类之后，逐条对对方的产物过这张表。
2. 映射上的：写清「它在我们这边叫什么、落在哪个文件」。
3. 映射不上的：显式写 `none` + 一句理由（例：「周会口头排的优先级 → none：没有可求值形态」）。
4. 表里没有的产物形态：**不许现场发明映射** —— 写 `none`，把「要不要加新映射」升级成一张卡。

## 反例（硬塞会怎样）

- 把 wiki 里的「建议目录结构」塞进台账当证据 ⇒ 没有文件可打开，对账必红。
- 把「群里说过这块先不做」写成 status=done 的依据 ⇒ 证据不可求值，假 done。
- 省略不写（而不是写 `none`）⇒ 下游分不清「漏了」还是「判过不映射」，只能重勘一遍。
