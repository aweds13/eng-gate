# 限制清单（limits）—— 接管第一笔就生效的六条禁止

> 第一笔只许是**只读或隔离内**的动作。六条禁止逐条对过才许动手；
> 违反任何一条 = 这一轮作废。

## 六条禁止

1. **不改对方主干。** 骨架与首批改动只落在隔离分支 / 隔离副本；对方主干一个字不动，
   集成由对方的人决定。
2. **不装依赖。** 不给对方项目装任何依赖（系统级、项目级都不装）；跑对方现有测试 / CI
   用它自己声明的环境，缺什么如实记进勘察笔记。
3. **不动 CI。** 不改对方的 CI 配置、门禁判据、测试断言 —— 红了是事实，写进台账 gaps，
   **不许调成绿**。
4. **不覆盖已有测试。** 对方的测试文件一个字不删、一行不改；要加测试只许新增文件。
5. **不引入新语言运行时。** 骨架与工具只用对方项目已有的运行时；想加新运行时升级为一张卡。
6. **不删对方文件。** 任何脚本 / 数据 / 备份目录都不删，哪怕看着像死代码。

## 允许的（对照着记）

- 只读勘察：`git log --oneline -5`、`git status --short`、读 README 与目录清单、跑 `wb_takeover.py`。
- 跑对方**现有**的测试 / CI 命令（不改配置）。
- 在隔离层铺骨架（只加文件）；把勘察结论写进自己这边的复盘文件。

## 怎么算违反（各给一个可观察的样子）

| 条 | 违反的样子 |
|---|---|
| 1 | `git log` 里出现非对方作者的骨架提交，直接在对方主干上 |
| 2 | 对方环境的包管理器记录里多了我们装的包 |
| 3 | 对方 CI 配置文件或测试断言出现在我们的 diff 里 |
| 4 | 对方已有测试文件有删行 / 改行 |
| 5 | 骨架里出现对方项目没有的运行时（如新语言的工具链） |
| 6 | 对方任何文件出现在 diff 的删除侧 |
