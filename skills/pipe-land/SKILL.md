# pipe-land —— 集成与发布

落地不是 `git commit`、也不是 `git merge`：它是**落地入口**那条八步链（外加几个子步），
**每一步都留读数**，链红了就停，绝不带着红门禁提交。

> 本页只写**换仓不变的动作与读法**。命令落在哪个路径、锁叫什么、环境变量叫什么、本仓读数是多少、
> 历史证据挂在哪：全在 [本仓绑定](references/repo-bindings.md)（相对链接，只深一层）。
> 换一个仓用这套技能，**只换那一份**，别改本页。

## 什么时候用

- 一张卡的结果齐了（提交在卡树里、申报已交），要落进主树。
- 落地跑到一半被打断，要从断点续（`--commit-only` / `--no-reset`）。
- 已经落了，要判断这一笔算不算数（封存 / 队列 / 台账是否一致）。

## 什么时候别用

- 还没交申报：入口条件不满足会被挡（不是异常，是设计上的挡）。
- 只想跑门：用 `pipe-gate`（落地链内部会自己跑，别外面再压一趟）。
- 想用普通 `git commit` / `git merge` 交差：那**不是**落地；封存、审计、队列翻转都会缺。
- 工人树里还脏着（`git status --porcelain -uno` 非 0）：先让工人提交。

## 前置检查

1. 申报齐：申报入口的 `status` 能查到这条任务已交（入口路径见本仓绑定）。
2. 卡树干净：在卡树里 `git status --porcelain -uno` 为 0 行。
3. 卡上的活留在**工作区**，不要先在卡树里 commit；要暂存就 `git add -N`（链 ① 会 `git checkout`
   主树 HEAD —— 已提交、主树没有的提交会被挡下）。这一条优先于上一条：卡树里**允许**有工作区改动，
   **不许**有主树没有的提交。
4. 主树干净：别人的未提交改动先收起（落地会做 `add` / `commit`，会被卷进去）。
5. 卡归谁：卡若归别的对话窗口，会退 2 并打印持有者 —— 确要接手就加 `--take-over`，别反复重试。
6. 参数齐：`--card` 与 `--batch` **恰好给一个**；卡树 / 台账号 / 标题 / 证据指针 / 白名单五样必填。
7. 参数细则与三段文书见 [落地参数](references/land-steps.md)；**走 `--commit-only` 先看那份的 §4.1 五步前置**。
8. **落地串行于门禁锁**：同时只跑**一趟**落地 —— 链 ④ 要占全局门禁锁，两趟并行只会互相等锁 / 互相挡；
   上一趟没走到 ⑦ 释放锁之前，别起第二趟（锁在哪、租约多久、唯一那条强放命令见本仓绑定）。
9. **文书 gaps 指针只认主树里现存的文件**：gaps 每条都要带指针，且指针必须在**落地时那棵树里真实存在**
   （文件路径 / commit sha / 快照 id）；指向「计划中的 / 还没生成的」产物 ⇒ 链 ② 当场停
   （先自检的入口见本仓绑定）。
10. **证据是文件路径，不是散文**：每个改动文件至少要有一条指针；写一句「改好了」不算证据 ——
    审计会按文件点名红。
11. **攒批**：`--batch` 走多成员预声明（一次 `register` 收齐）；**批要小（≤4）** ——
    批树合不上就整批停，小批才二分得动「是哪张卡」（批号文件与攒批入口见本仓绑定）。

## 真命令

```bash
# 命令名与档位换仓不变；本仓的确切路径见 references/repo-bindings.md
<落地入口> --card <卡号> --tree <卡树> --task <台账号> --title "<一句话>" \
    --type <类型> --scope <域> --allow <文件>... --evidence <指针>... --port-base <端口段>

# 门禁已绿、封存没变：从 ⑥ 起接着走（跳过 ①~⑤ 与那两个子步）
<落地入口> ... --commit-only

# 只体检不落地：判据一次说全、只读、秒级（条数与逐条名字现读，见本仓绑定）
<落地入口> --preflight --task <台账号> --allow <文件>...
#   0 = 全绿（可以直接落地）/ 1 = 有 ❌（逐条点名）。给了 --card / --batch ⇒ 绿了才接着落地。

# 攒批落地（批号来自多成员预声明；--card 与 --batch 恰好给一个）
<申报入口> register <预声明.toml>
<落地入口> --batch <批号> --tree <批树> --task <台账号> ...

# 落地后一屏核实
<核实入口> --tree . --expect-parent <期望父提交>
```

## 怎么读结果

- 这一笔算不算数（五块一屏：提交骨架 / 门禁 / 封存 / 台账 / 审计）：`python -X utf8 tools/wb_verify.py --tree .`。
- 队列翻没翻（落了却仍 `pending`、或翻了却没落）：`python -X utf8 tools/wb_reconcile.py`。
- 复核产物在不在：`python -X utf8 tools/wb_review.py --rev <新提交> --json`（落盘位置见本仓绑定）。
- 卡与门的当前形态：`python -X utf8 tools/pipeline_view.py --json`（`cards` / `gates` 两块）。
- 每一步的开关与退出码：`python -X utf8 tools/wb_land.py --help`（`--commit-only` / `--no-reset` / `--affected` 都有说明）。
- 长任务一律走 `python -X utf8 tools/run_logged.py --log <日志> -- <命令>` 落盘后增量读，别用管道截断。

## 常见错与处置

| 现象 | 真因 | 处置 |
|---|---|---|
| 被挡在入口 | 申报不齐 / 卡树脏 / 参数互斥 | 先补申报；脏树先提交；`--card` 与 `--batch` 只给一个 |
| 门禁红 | 链 ④ 真跑红了 | 修红；**不许**加跳过门禁的开关（那会在 trailer 里如实写「没跑门禁」） |
| 封存对不上 | 封存文件里的 `rev` 不是这一笔的父提交 | 说明封的不是这一笔；重新落地，别手改封存文件 |
| 重跑报「重复合成」 | 上一趟把 changelog / 台账 / 交接合成过一遍 | 默认 ⓪ 会回退派生物；若关了 `--no-reset` 才会撞，重跑别再关 |
| 落了但队列还是 `pending` | 卡块缺 `status` 行 ⇒ 翻状态**静默跳过** | `--allow` 里要含队列文件；**补 `status`** 后重核队列检查 |
| 链 ② 停「文书指针不存在」 | gaps / 证据指向计划中或已改名的文件 | 指针只认**落地时那棵树里真实存在**的文件；先跑文书预算自检 |
| 链 ⑦ 审计咬「某文件没人声称」 | 本笔实际改的文件 ⊄ 台账指针（`file:` / `text:` / `test:`）∪ 例外表 | 按**文件**补证据；别只写一句「改好了」。单跑审计入口（0 / 1） |
| 落到 ⑦ 报「锁没释放 / 别人还在等」 | 门禁锁还在 | 正常是链自己放；真泄漏才按本仓绑定里**那一条**强放命令放，别反复重试 |
| 增量门禁被当全量 | 给了 `--affected` 却按全量汇报 | trailer 会写「非全量」；别把它当全量读数 |
| 复核没产物 | `--no-review` 用了，或复核跑挂 | 默认别关；挂了先看复核目录与日志（路径见本仓绑定） |

## 落地链（八步 + 子步）

| 步 | 干什么 | 失败就停在哪 |
|---|---|---|
| ⓪ | 回退派生物（幂等重跑；`--no-reset` 可关） | 回退不干净 ⇒ 后面必撞「重复合成」 |
| ① | 卡树迁到主树 HEAD | 冲突 ⇒ 先解，别 `checkout` 硬盖 |
| ② | 文档件（gaps / changelog / checkpoint） | 缺段落 ⇒ 停 |
| ③ | 重算计数类派生物 | 台账分布漂 ⇒ 停 |
| ③′ / ③″ | fail-fast 钉子 → 快门禁预检（十几秒，不落盘） | 红 ⇒ 停，全量门禁一步没跑、锁也没拿 |
| ④ | 门禁锁 + 门禁（按域；碰判据本体则全量） | 红 ⇒ 停（链内自己跑，别外面再压） |
| ⑤′ / ⑤ | 白名单核对 + 翻队列状态 → `seal`（写封存文件） | 封存指纹与提交树对不上 ⇒ 停 |
| ⑥ | 白名单 → `add` → `commit` | `--allow` 少了文件 ⇒ 那文件没进这一笔 |
| ⑦ | audit → 释放锁 → `ff` 合流 | 锁没释放会占全局并发名额 |
| ⑧ | 复核落盘 | 异步、不挡提交，但申报收口前必须有 |

## 自查

按顺序四条，任一条不成立就**别报「落成了」**：

1. `git status --porcelain -uno` 主树 0 行（工人的活都进了这一笔）。
2. `python -X utf8 tools/wb_verify.py --tree .` 五块里没有 FAIL。
3. 队列里这张卡是 `done`，且 `python -X utf8 tools/wb_reconcile.py` 无 stale。
4. 回报里写清「跑的是全量还是增量」—— 增量那次 trailer 有「非全量」字样。

> 八步的定义、白名单语义、封存范围（去掉门禁产物目录的提交树）：判据在落地入口与链实现里，本技能只讲怎么跑、怎么读。
> 入口路径 / 退出码表 / 体检逐条清单 / 锁与端口段 / 环境变量 / 历史证据：见 [本仓绑定](references/repo-bindings.md)。
