# pipe-gate —— 跑门禁并读懂结果

跑门禁用本仓的门禁入口，读结论看它落盘的判决文件与逐门日志。
**门数是现算的**（门表只有一处真源）：以那一趟落盘产物里门条数为准。文档可以写**带日期**的读数，
但**不许**把数字当常量引用 —— 门表一变，写死的老数字就在骗人。

> 本页只写**换仓不变的动作与读法**。命令落在哪个路径、锁叫什么、环境变量叫什么、本仓读数是多少、
> 历史证据挂在哪：全在 [本仓绑定](references/repo-bindings.md)（相对链接，只深一层）。
> 换一个仓用这套技能，**只换那一份**，别改本页。

## 什么时候用

- 改完一小块，自查这棵树还绿不绿（快档，十几秒）。
- 提交 / 收口前要一份全量结论（次档跳过真机层；收口链内部跑全量）。
- 某道门红了，要知道「哪道门、什么退出码、日志在哪」。

## 什么时候别用

- 要验证**门本身还活着**（判据没退化成注释）：那是金丝雀自检，不是跑门。
- 想把红改成绿：先修代码或修门；**不许**放宽判据、加豁免、手改判决文件；**也不许靠再跑一次门禁把它跑绿**
  —— 假红要读红门 `detail` 第一段的隔离判定，重跑不是证据。
- 只想看「今天该做什么 / 谁在飞」：用工作台路由技能。
- 已经有一趟门禁在跑：**同一时间只跑一趟**（重活并发 = 假红的头号来源）。

## 前置检查

1. 在**要判的那棵树**里跑 —— 每棵 worktree 有各自的产物目录：`pwd` + `git rev-parse --show-toplevel`。
2. 工作区状态先看清：`git status --porcelain -uno`（有别人的未提交改动就先停手）。
3. 内存 / 端口够不够：真机层要起服务与浏览器；快档只跑轻门，不受影响。
4. 读法细则（每行字段、未跑、复用、退出码）见 [输出读法](references/output.md)。
5. ★ **全量门禁只有一把锁**：锁在 = 有人正在跑这趟 —— **等锁不是卡死**；锁文件消失 = 那趟收口了。
   判「卡死」之前先读锁账本（它给持有者与**租约剩余**，★ 别看 pid 判活）；人工兜底**只有一条**强放命令。
   具体路径 / 段号 / 租约秒数 / 强放命令见 [本仓绑定](references/repo-bindings.md)。
6. 跨会话共享一台机的口径见那一份它自己的文档 —— 别自己发明排队规矩；那台机器现在能不能上，
   读那份里的自检命令，别读某张卡的进度。

## 真命令

```bash
# 命令名与档位换仓不变；本仓的确切路径见 references/repo-bindings.md
<门禁入口> --fast            # 内循环：十几秒那几道（不落盘）
<门禁入口> --quick           # 跳过真机层
<门禁入口>                   # 全量（提交前用这一档）
<门禁入口> --no-reuse        # 不信复用记录，全部重跑
<门禁入口> --affected <路径>  # 只跑受影响的门（自查，不是提交闸）
<门禁入口> --seal            # 只更新判决文件的 tree 字段，不跑门
```

## 怎么读结果

- 一屏核对五块（提交骨架 / 门禁 / 封存 / 台账 / 审计，且报出「not_run N 道 · 复用 N 道」）：`python -X utf8 tools/wb_verify.py --tree .`。
- 每道门一行（名字 / `exit_code` / 秒数）：`python -X utf8 tools/pipeline_view.py --json` 的 `gates.items`。
- 自己动过的门（或它的输入）要 `--no-reuse` 真跑；复跑后用 `python -X utf8 tools/wb_verify.py --tree .` 看「复用 N 道」有没有降下来。
- 红门的日志尾在逐门日志目录；跨树汇总、缺源说明用 `python -X utf8 tools/pipeline_view.py --json`（缺块给 `null` + note，不洗成空）。
- 红门先看 `detail` 第一段的隔离判定（`[隔离跑绿]` / `[隔离也红]` / `[判不出]`）：`python -X utf8 tools/pipeline_view.py --json` 取那道门的 `detail` —— **`[隔离跑绿]` 也不等于通过**，门照样红、退出码不改；关着时 detail 明写「本次未做隔离复核」。
- 长任务（全量门禁常跑十几分钟）一律走 `python -X utf8 tools/run_logged.py --log <日志> -- <命令>` 落盘后增量读，别用管道截断。

## 常见错与处置

| 现象 | 真因 | 处置 |
|---|---|---|
| 快档全绿就改了提交 | 快档**不落盘**、只覆盖「改一行就能犯」那几类 | 提交前跑次档或全量；快档不是提交闸 |
| 有门 `not_run` 却当通过；或门是绿的但 summary 写着「没判完 / 判不出 N」 | 运行状态 ≠ 判决；「判不出」也不是判过 | 补依赖再跑；report 档的门 **判不出也退 0**，要看 summary 里的 `判不出 N` / `[DEBT]`；回报里如实写「未跑」「判不出」，别折成绿 |
| 门全绿但结论是上一棵树的 | 在别的 worktree 里读到了自己的判决文件 | 用 `rev` / 树路径对齐；`wb_verify` 会报 `rev` 与父提交的关系（真祖先 + 只差台账 ⇒ 读数写「未复验」，不算冒充） |
| 自己改过的门显示复用 | 增量执行读了缓存 | `--no-reuse` 真跑；别拿复用当验证 |
| 整趟门禁卡住几十分钟 | 某道门卡死（**门禁有逐门硬超时**，不是没有） | 先看判决文件里那道门是不是 `exit_code = 124` + `timeout=True`（超时秒数与覆盖变量见本仓绑定）；清洗残留按 PID 收，别杀用户的浏览器 |
| 两趟门禁同时跑 | 重活并发 | 串行；两个池也别同时满载 |
| 一直等锁 / 报「卡死」 | 死主没清锁 | 先读锁账本看是哪一段、持有者是谁、租约还剩多久（**别看 pid 判活**）；确实过了租约才按前置检查第 5 条那**一条**兜底命令强放，别反复重试 |
| 引用完整性门报「引用断裂」 | 文档里反引号包了个**不存在 / 计划中**的路径（通配符也算） | 单跑那道门的入口（0 / 1）点名到「哪篇引了哪个」；改成「路径（计划建）」并去掉反引号，或把文件真建出来 |
| 换机器后自己的门莫名「复用」 | 解释器版本不同会改门输入哈希的展开语义 | 看判决文件里的解释器版本字段与 `rev`；低版本会被开跑前拦下。别把「哈希一样」当「文件没变」 |

## 自查

按顺序四条，任一条不成立就**别报「绿了」**：

1. 我跑的是**这棵树**：`git rev-parse --show-toplevel` 与 `pwd` 同一棵。
2. 我报的那一档是**落盘档**（全量 / 次档），不是快档。
3. 判决文件的 `ok` 为真，且 `rev` 是本笔的父提交 —— 或者是父提交的真祖先且差异只在台账（这时读数会标「未复验」，别当复验过；封存口径见 `pipe-land`）。
4. 每道 `not_run` 都在回报里点了名，没有混进「通过」里。

> 判据（哪道门算过、三值与空集、复用规则、分档成员）在门禁入口与门表里，本技能只讲怎么跑、怎么读。
> 该跑哪一档、跑在哪台机器、何时选测与夜间：见本仓绑定里指的那份测试流程文档。
