# pipe-workbench —— 工作台四件套

一条线：**一份读数 → 今日一页 → 注入 → 面板**。上游只有一个读数入口，
下游都只加工、不另读源文件（两份一漂必出事）。判据在工具里，这层只讲怎么用。

> 本页只写**换仓不变的动作与读法**。四条命令落在哪个路径、产物叫什么、退出码是多少、
> 今日一页现读几段、历史证据挂在哪：全在 [本仓绑定](references/repo-bindings.md)（相对链接，只深一层）。
> 换一个仓用这套技能，**只换那一份**，别改本页。

## 什么时候用

- 主控要**一份现场读数**：队列 / 门禁 / 判决 / 租约 / 栅栏 / 树，六块一起看。
- 每天**巡检**「今天该做什么」：待派几张、在飞几张、哪些批到收口、落了没翻状态。
- 派活时给工人的开场白要一段**同源**状态（哪张卡 / 谁在飞 / 域占用 / 该看哪个产物）。
- 要确认**工人动没动 / 那张卡收工没有**（收工信号见下面那一节）。

## 什么时候别用

- 要**改**状态：四件套**全只读**（唯一占端口的是面板，起一个本地只读页面）；派活 / 申报 / 收口各有自己的动作技能，别拿读数器当写入口。
- 要**跑门禁**或读三值判决：用跑门禁那个技能；这里只把「最近一次门禁」当一块读数。
- 想**另写一份读数器**（六块唯一入口就是那个读数器，缺块如实标 `null` + note），或想把面板当**内容判据**（它只报在不在动，不判干得对不对）。

## 前置检查

1. **在哪跑**：四件套从自身位置推仓库根；池状态住**主工作树**的产物目录 —— 从别的树跑今日一页 / 注入要 `--root` 指回主树；面板要多树视野就从主工作区起（主树在哪见本仓绑定）。
2. 上一道能跑通：`python -X utf8 tools/pipeline_view.py --report` 六块里缺哪块它自己会说。
3. 参数与产物全表见 [四件套](references/tools.md)。

## 真命令

```bash
# 命令名与档位换仓不变；本仓的确切路径见 references/repo-bindings.md
<读数入口> --report                                  # ① 一份读数（人读）
<读数入口> --json                                    #    机器读
<今日一页>                                            # ② 今日一页（只读）
<注入> --card <卡号> --tree <树标签> --batch <批号>    # ③ 注入
<面板> --port <端口>                                 # ④ 面板（默认只绑回环）
```

## 怎么读结果

- 六块齐不齐（`cards` / `gates` / `verdicts` / `leases` / `fences` / `worktrees`）：`python -X utf8 tools/pipeline_view.py --json`（缺源 = `null` + `*_note` 写原因，不许拿空对象冒充「拉到了、是空的」；租约为空 ≠ 没人干活，先确认注册表读没读到）。
- 今天该做什么（待派 / 在飞 / 到收口的批 / 落了没翻状态 / 内存）：`python -X utf8 tools/wb_daily.py --json`。
- **今日一页的分区数是现算的**，别把某天的段数当常量引用：`python -X utf8 tools/wb_daily.py`（现读几段、哪几段恒在、哪些是条件行见本仓绑定；数字一变，写死的老数字就在骗人）。
- 注入段读法（卡行 → 租约 → 判决 → 栅栏；缺源整段省略并写原因；同输入两次逐字节相同）：`python -X utf8 tools/workbench_bridge.py --card <卡号>`。
- 面板读法（每组一行「卡 / 在不在动 / 在跑什么与卡死阈值 / 判决」，最新活动在最上面）：`python -X utf8 tools/wb_dash.py`（口径同它的 docstring）。

## 看完工信号

派活器**默认**已经挂好收工看守（派完那一屏会写「看守已起」），所以「工人收工了吗」不用靠每两分钟敲一次状态。要自己看或重挂：

```bash
# 命令名换仓不变；本仓的确切路径与阈值见 references/repo-bindings.md
<收工看守> --cards <卡号>                 # 只读：盯到收工 / 判死 / 超时
<收工看守> --cards <卡号> --write-done    # 顺手写一份 done 事件 + 通知一行
<收工看守> --cards <卡号> --mode shared   # 合用看守：引用计数 +1/-1/归 0
<面板侧看守> --task <标题片段> --card <卡号>  # 面板里的任务（没有进程、也没有判决）
```

- **收工信号**落成一份一行 JSON 的 done 文件；中间态看通知文件末尾那一行。路径与字段见本仓绑定。
- **退出码**：`0` 全部收工 · `3` 有卡判死（没跑完就断了）· `4` 超时（**没判决不算成功**）·
  `5` 看守自己死了 / 面板侧被终止或空转 · `2` 用法 / 批次读不到。
- **合用看守**的计数在它自己的登记文件里：派一张 `+1`、出判决 `-1`、归 `0` 才写一条批收工（看中间态读它，别等最后的通知）。
- **面板侧看守**（面板任务没有进程、也没有判决）每拍采一次页面判四态：真收工 ⇒ 与工人同一种 done 行；
  被终止 / 空转塌陷 ⇒ 另一份 `.stopped` 文件 + 各自通知，都退 **5**。锚点、阈值、路径见本仓绑定；不给写事件开关就只读。

## 常见错与处置

| 现象 | 真因 | 处置 |
|---|---|---|
| 某块 `null` 带 note | 来源文件缺 / 坏 | 按 note 补来源；**别当空数据用** |
| 今日一页读不到租约 / 批；面板看不到别的树 | 从非主工作树里跑的（池状态住主树） | 加 `--root <主树>`，或回主工作区起面板 |
| 注入说「查不到卡 X」 | `--card` 与队列 `id` 对不上 | 用 `cards` 块里的 `id` 原样传 |
| 工人收工了却没人知道 | 派活时关了看守（那一屏会明说） | 用 `python -X utf8 tools/wb_watch.py --cards <卡号>` 单看，或看 done 文件在不在 |
| 同输入两次输出不同 | 工具被改出非幂等（时戳 / 遍历序） | 口径破洞：停手报主控，别手工圆 |
| 想靠面板判「内容对不对」 | 面板只报在不在动 | 内容对错看判决文件与主控复核 |
| 分区数 / 段名对不上记忆 | 分区是现算的，旧文档写死过老数字 | 以实跑为准；抄旧数字前先跑一次 |

## 自查

1. 我用的**同一份**读数源：先一份读数，后加工；没有自己重读队列。
2. 我报的六块里，每块要么有数据，要么带了 `null` + note —— 没有静默留空。
3. 我在**主树**里跑的巡检（或显式给了 `--root`），租约读得到。
4. 我给工人的开场白与面板读数来自同一次运行（不是两趟拼的）。

> 判据（六块的真源、done 行的字段、退出码、看守的引用计数）在工具里，本技能只讲怎么看。
> 删掉整个 `skills/` 目录，四件套照常能用。
