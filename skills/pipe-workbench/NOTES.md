## 这一层在防哪类错误

防两类：

1. **各读各的、口径漂** —— 同一批现场数据（队列 / 租约 / 判决 / 批状态）曾有多个读取点，
   各拼各的开场白。这层把「先调唯一读数器、再加工」固化成动作顺序。
2. **靠人记得** —— 「今天该做什么」从前靠人肉看守；这层把巡检固化成一条只读命令加一块面板。

还有一条是读法上的：**「空」与「没读到」必须分得开** —— 缺源要给 `null` + note，
不许拿空对象冒充「拉到了、是空的」。租约为空 ≠ 没人干活。

## ★ 为什么分「SKILL.md / references/repo-bindings.md」两页

依据是 `docs/reference/agent-skills-spec.md`：

- **§5 渐进加载三层**：元数据（~100 tokens）→ 指令（激活时整篇载入）→ 资源（按需读）。
  正文每多一行，**每次激活都要付一次钱**；本仓还把正文收紧到 120 行（卡 209）。
- **§6 引用只深一层**：`references/repo-bindings.md` 是相对技能根的一层链接，符合口径。
- **§8「稳定的写死、随环境变的留成参数」**：动作与读法换仓不变 ⇒ 写死在 `SKILL.md`；
  路径 / 端口 / 段数 / 退出码 / 卡号 / 复盘文件名随仓库变 ⇒ 全部下沉成「本仓绑定」。
- **§9 第 ⑤ 条「长表下沉 references，正文给相对链接」**：所以六块的源、看守退出码表、
  7 段读数、复盘缺口证据链都搬进 `references/repo-bindings.md`，正文只留一行链接。

**改造中踩的坑（2026-11-08）**：

- 正文把命令块改成 `<读数入口> --report` 这种占位后，**「怎么读结果」那几条不能跟着占位** ——
  钉子 C 要求每个 `- ` 条目里有**反引号包住、且真实存在**的脚本路径（`tools/` `skills/` `framework/cli/` 三根之一、`.py/.mjs/.js/.sh`）。
  第一版我把「面板读法」写成了 `<面板>`，当场判红；改法是**命令块用占位、读法条用真路径**，
  真路径留在正文不违「泛用化」—— 它是「本仓怎么跑一遍」的可重跑指针，不是判据。
- 同理，「分区数」这种**会变的读数**别写进 `SKILL.md`（写了就要带日期，还得有人维护）；
  正文写「现算是几段、去本仓绑定看」，数字只活在 references 里。
