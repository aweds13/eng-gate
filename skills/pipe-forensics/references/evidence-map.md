# 证据落点全表（细则）

> `pipe-forensics/SKILL.md` 的按需参考。**这里不写判据**：什么算红、什么算过由门与工具决定；
> 本表只回答「出事了该翻哪个文件」。

## 1. 落点

| 证据 | 路径 | 谁写 | 读它回答什么 |
|---|---|---|---|
| 门禁结论 | `gates/last.json` | `scripts/run_gates.py` | 哪道门、exit_code、未跑、复用、封存 rev |
| 门全量输出 | `gates/logs/<门名>.log` | 同上门禁 | 那道门到底报了什么错 |
| 复用指纹 | `gates/reuse.json` | 门禁 | 这道门为什么被判定「输入没变」 |
| 工人日志 | `gates/diag/wb-<卡号>.jsonl` | `tools/wb_dispatch.py` | 工人跑到哪、被什么挡住 |
| 派活切片 | `gates/diag/brief-<卡号>.md` | 派活器 | 工人开工时看到的上下文 |
| 复核结论 | `gates/review/<台账号>.json` | 落地链⑧ | 这一笔的异步复核 |
| 队列 | `docs/workbacklog.toml` | 人 / 派活器 | 卡的状态与域 |
| 台账 | `docs/traceability.toml` + `docs/traceability.d/` | 落地链 | 证据指针与状态 |
| 批 / 租约 | `gates/diag/` 下的池状态 | 号池 | 谁在飞、栅栏到哪一步 |

★ `gates/` 整棵是 gitignored 的产物：**卡树里没有**，别把相对路径指给卡树里的工人。

## 2. 三个最容易读反的东西

| 看到 | 不是 | 是 |
|---|---|---|
| `not_run` | 通过 | 根本没跑（缺 node / 浏览器 / 服务） |
| `inconclusive` / 判不了 | 通过 | 空集，判不了 |
| 门在 `reused` 里 | 这轮跑过 | 输入没变、采信上一轮 |

## 3. 「结论属于哪棵树」

`gates/last.json` 里能对的三处：

- `rev` —— 被封的那笔提交；
- `branch` —— 跑门时所在分支；
- `tree` / `tree_scope` —— 封存指纹及其范围（缺省去掉 `gates/**`）。

三处里任意一处和你手上的树对不上，这份读数就**不能直接用**；它可能只是主树带过来的。

## 4. 失败链的常见形态（先看这里再翻代码）

| 形态 | 现象 | 先翻 |
|---|---|---|
| 工人空转 | 日志里反复同一条命令，退出很快 | `wb-<卡>.jsonl` 最后几个事件 + 被拒原因原文 |
| 落地半途停 | 派生物已合成、提交没成 | 队列 / 台账是否已改；用 `wb_reconcile.py` 看 stale |
| 门禁假红 | 同一条断言时红时绿 | 是否并发跑了重活；`gates/logs/` 两次读数对比 |
| 证据读不出 | 日志里出现乱码 / `UnicodeDecodeError` | 证据文件是不是被 UTF-16 重定向写的 |
