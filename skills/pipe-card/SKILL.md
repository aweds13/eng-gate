# pipe-card —— 写卡 / 派活 / 申报

一张卡 = 一份卡规格 + 一条队列条目 + 工人树里的提交 + 一条申报。
四样东西的名字与字段要能互相对上；对不上时先修名字，别急着往下走。

> 本页只写**换仓不变的动作与读法**。命令落在哪个路径、台账与队列叫什么、模型名单从哪读、
> 看守产物挂在哪、本仓读数是多少：全在 [本仓绑定](references/repo-bindings.md)（相对链接，只深一层）。
> 换一个仓用这套技能，**只换那一份**，别改本页。

## 什么时候用

- 要开一张卡：写卡规格、登记队列、建工人树。
- 要把卡派出去，或查「工人动没动」。
- 一张卡干完了，要交 `success` 申报（带证据），或显式判 `failed`。

## 什么时候别用

- 要跑门：用 `pipe-gate`；要落地：用 `pipe-land`（申报只是它的输入之一）。
- 卡规格里的 `files` 还没定就想开干：**先定域**，域是后面一切拦截的依据。
- 想替工人改他树里的文件：一写一读，工作区归他。
- 任务 / 成员还没登记就要申报：先 `register`，否则申报无处可落。

## 前置检查

1. 卡号在本仓没被用过：队列台账与既有卡规格目录里都没有这个号（两处都要查，路径见本仓绑定）。
2. 卡规格四段齐（问题 / 改法 / 判据 / 证据），且 `files` 是**你真正会碰**的文件。
3. 台账号（任务侧编号，与本仓卡号是两套）与卡号分开：`Task:` 只能有一个编号。
4. 树还没建：`git worktree list` 里没有这张卡的工人树。
5. 派活前读 [派活分工](references/dispatch.md)：谁做实现、谁只做复核、长跑归谁。

## 立卡：只走一个入口

队列台账只有一处生产写方（脚本名与参数见本仓绑定），别手编、别用临时脚本：

```bash
# 命令形状换仓不变；本仓的确切路径与参数见 references/repo-bindings.md
<立卡入口> add --id <卡号> --task <台账号> --title "<一句话>" --spec <卡规格路径>
```

- 它给的是：台账锁跨会话互斥、块级幂等（同号卡打「已在」退 0）、尾部按字节追加、原子替换（带重试）。
- 退 1 = 台账不是纯 CRLF（不写盘）；退 2 = 等不到锁 —— 两种都别手改台账对齐。
- 自己写个「往台账里插一段」的临时脚本是**禁止项**：硬编码路径 / 按全文子串判「已在」都会让卡凭空丢，
  且这类脚本往往住在 gitignore 里、不入库（历史账号与依据见本仓绑定）。

## 真命令

```bash
# 命令名换仓不变；本仓的确切路径见 references/repo-bindings.md
# ① 建树（分支名 card/<卡号>）
git worktree add <工人树> -b card/<卡号>

# ② 派活（默认 dry-run；--detach 不等它，--execute 才真派）
<派活入口> --card <卡号> --spec <卡规格路径> --cwd <工人树> --model <短名> --detach --execute
<派活入口> --card <卡号> --status

# ③ 申报（任务栅栏：先注册，再逐卡交）
<申报入口> register <预声明.toml>
<申报入口> claim <任务> <成员> --claim success \
    --evidence "<测试读数 / 门结论 / 原样输出>" --files <a.py,b.py> --why "<干了什么>"
<申报入口> status <任务>

# ④ 收口后给提交补文书（台账条目 + changelog + 交接 CHECKPOINT）
<文书入口> --tree <工人树> --id <台账号> --title "<标题>" --evidence <文件> --text-file <三段文书>
```

## 怎么读结果

- 卡排不排得出来：`python -X utf8 tools/wb_plan.py plan --concurrency 2`（只认 `status = "pending"`）。
- 队列里这张卡长什么样（`files` / `tree` / `status`）：`python -X utf8 tools/pipeline_view.py --json` 的 `cards` 块。
- 申报收没收：`python -X utf8 tools/wb_task.py status <任务>` 给「谁交了 / 还缺谁 / history」。
- 工人动没动：`python -X utf8 tools/wb_dispatch.py --card <卡号> --status`（日志落在哪见本仓绑定）。
- 队列与 git 对不上（落了没翻状态 / 翻了没落）：`python -X utf8 tools/wb_reconcile.py`。
- 长任务一律走 `python -X utf8 tools/run_logged.py --log <日志> -- <命令>` 落盘后增量读，别用管道截断。

## 常见错与处置

| 现象 | 真因 | 处置 |
|---|---|---|
| 卡排不出来 | `status` 不是 `pending`，或缺 `spec` / `files` / `depends` | 补齐字段；`depends` 指向的卡没 done 也会挡住 |
| 申报退「域不符」 | 申报里的文件清单与卡规格的 `files` 对不上 | 按**实际改动**报；确实要扩域就改卡规格并写明理由 |
| 申报退「任务/成员未登记」 | 直接 `claim` 没先 `register` | 先 `register`；成员号 = 卡号 |
| 工人日志里反复同一条命令 | 工人侧 harness 不许跑长命令（后台执行被拒） | 秒级活归工人，长跑（真机 / 分钟级）归主控，见 [派活分工](references/dispatch.md) |
| 工人说「没做」 | 上一条，或环境缺件（端口 / 进程不在） | 卡里写清降级口径：如实写「没做」+ 证据，不许假装 ✓ |
| 派活被拒「工作区不干净」 | 派活器的前置检查看的是**当前工作区** | 先提交；别人的改动用 `git stash push -- 路径` 挪开、事后精确复原，**绝不** `git reset --hard`；别顺手一起提交 |
| 树建不出来 | 同名分支 / 目录已存在 | `git worktree list` 先看；别 `-f` 硬建 |
| 派完没人管 | 看守没起来（脚本不在 / 起不来会打告警） | **默认自动挂**，派完那一屏会打 `[看 ] 看守已起（pid …）`；没看到这行才需要自己挂（命令见本仓绑定） |

## 派活走哪条道

| 道 | 用来干什么 | 不许用来干什么 |
|---|---|---|
| 实现道（本仓默认池） | 一切**实现类**卡：改代码 / 写判据 / 落地前的活 | 模型名要短名，写 `vendor/model` 会被拒 |
| 复核道 | **只做复核 / 对抗性审查**：证伪结论、审规格、审产物 | 不许当实现工人 |
| 主控 | 长跑（真机 / 全量门禁 / 落地链）、跨域决策、与用户对话 | 不许抢工人域内的活（会撞文件） |

派活前先问一句：**这张卡是实现还是复核？** 实现走默认池，复核才上复核道。
★ **模型名不许凭记忆写**：批准集是**现算**的（注册表 + 仓外开关，只做加法），写错一律被拒单并**原样列出允许集** ——
照那一屏挑，别抄本页或别人的旧笔记（本仓今天批了哪几个见本仓绑定）。

## 自查

按顺序四条，任一条不成立就**别报「这卡好了」**：

1. 卡规格、队列条目、树、分支四处的**卡号**逐字一致。
2. `files` = 我真正会碰的文件；多一个少一个都会在后面被点出来。
3. 申报里的证据是**能重跑的东西**（命令 + 读数），不是「已完成」四个字。
4. 收工前 `git status --porcelain -uno` 在我这棵树里是 0 行。

> 域怎么判、申报怎么收口、封存怎么算：判据在申报器与落地链里，本技能只讲顺序。
> 台账与队列叫什么 / 立卡退码 / 模型批准集 / 看守产物 / 攒批栅栏：见 [本仓绑定](references/repo-bindings.md)。
